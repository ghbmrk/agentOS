# The kernel's process: assumptions

`broker/kernelproc` is the kernel's half of `broker/clerk/run`, split out by KRN-2 split (#2892). Its earlier rows (MIG-4-run a to d, h, i, m, o; STO-2b-1 z, aa; LOG-anchor-tpm a, b) stay in `broker/clerk/run/ASSUMPTIONS.md`, where both processes were built. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| KRN-2-split | **The kernel's process links no clerk's code; the wire lives on the kernel's side.** `kernelproc` holds the kernel process (`OpenKernel`, `Tick`, `RunKernel`, the owner and meter sockets and their clients), the log file and its anchor, and the wire both sides speak (the call, the view, `Remote`, `ServeClerk`, `Conn`, `ServeConns`, `ServeOne`). `broker/clerk/run` keeps the clerks' processes and imports it, so a clerk's process links the kernel process's code but not the reverse: no clerk binary exists yet, and the code it gains holds no parser of outside bytes the clerk does not already read. The clerks' own errors cross a socket by their text through `WireErrors`, called from `clerk/run`'s init, since this package cannot name them. A process's private-file checks and atomic write moved to `broker/privfile`, which both use. `TestTheKernelProcessLinksNoClerkCode` holds the split: of `broker/clerk` the kernel links only `clerk/handoff`. Measured at the build: own lines 143,042 to 131,451, dependency lines 303,277 to 282,015, parsers 122 to 118. | SPEC KRN-2 | When a clerk ships as its own binary, it may want the wire in a package of its own, so it links no log or anchor code. |
