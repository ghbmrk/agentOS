# Box time check: assumptions

Built for P2-9 against SPEC v0.12 TIM-1 ("Time comes from network time when
online, with carrier network time (from the modem) as a cross-check. Large
disagreements put the broker into restricted mode for time-sensitive
checks."). Packages: `clock` (the guard) and the carrier source in
`modem/at` (`Modem.NetworkTime`, simulated in `atsim`). Each row is a
reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| K1 | "Network time" is the kernel clock as set by NTP. The broker never sets the clock; `systemd-timesyncd` does, and `clock.Synced` reads whether it has (read-only `adjtimex`: not `TIME_ERROR`, no `STA_UNSYNC`). **For P2-1:** enable `systemd-timesyncd` with Debian's default pool servers (no AgentOS-run server, DEP-2). NTP is unauthenticated, which is why the cross-check matters; one attacker who controls both sources and gives both the same false time is undetectable by design (K9). | TIM-1, DEP-2 | Small: another `Synced`. |
| K2 | Carrier time is read from the modem on demand and only compared, never used to set the box clock. Quectel: `AT+QLTS=1` (UTC as of the last network time update, `""` before one). SIMCom: `AT+CCLK?` after `AT+CTZU=1` (`NetTimeOn`, sent best effort at `Open` and never in `Init`, so a module that refuses it still texts and calls; security C3); the zone must be two digits; it has no "never set" answer, so a module clock before 2025 is treated as no carrier time. A modem error is no carrier time, never a disagreement. What S2 must confirm is C14 and C15 in [S2-CONFIRM.md](../modem/at/S2-CONFIRM.md). | TIM-1, HW-2 | Per vendor: `Profile.NetTimeCmd`/`NetTime`. |
| K3 | "Large" is more than 5 minutes (`DefaultTolerance`). The module clock runs on between network updates, and the broker's time limits (codes, request lapses, grant end dates, update metadata expiry) are minutes to days, so 5 minutes avoids false alarms while catching any shift that moves an expiry. | TIM-1 | Constant. |
| K4 | Only a disagreement restricts. With one source (`NetworkOnly`, `CarrierOnly`) or none (`Unchecked`: offline with no modem time) the box keeps running on its clock, as DEP-4 requires offline work; callers that need two sources read `Status().State`. Once restricted, only carrier time that agrees again lifts it: losing the carrier (jammed, unplugged, a network that stops sending time, a SIMCom module clock pushed below the floor by a fake cell) keeps the restriction, at the cost of staying restricted until the modem is back. The restriction, the outstanding owner text and the hold anchor are kept in `StatePath` (0600, written atomically) and survive a restart; an unreadable file restricts until carrier time agrees, with a fixed owner text (`StateLostText`) rather than a skew it cannot know (security C2, L3 F5 on #68). The temporary file and the directory are synced around the rename, and a failed save is logged (`Logf`). **For the wiring:** set `StatePath` under the broker's state directory. | TIM-1, DEP-4 | A spec diff to restrict on one source. |
| K4a | **Hold** (security C1 on #68). The box clock is held to an anchor: the last carrier-confirmed check, or this boot's first synced check before any carrier time. A wall clock that has moved from the anchor, against the monotonic clock, by more than the tolerance plus a fixed 5 s, with no carrier reading to confirm it, is `Held`: `Now` and `Latest` answer the anchor carried forward on the monotonic clock, and the owner gets one fixed text. Measuring from the anchor rather than the last check catches many small steps that add up, however long after the anchor (NTP slewing moves the wall and boot clocks together, so time since the anchor earns no allowance; L3 F6 on #68). Agreeing carrier time re-anchors and ends the hold; disagreeing carrier time restricts. A hold that ends without carrier time (the clock comes back in line) gets its own all-clear after `AgreeAfter`. The monotonic clock is `CLOCK_BOOTTIME`, so an anchor survives a broker restart within one boot (checked by `boot_id`) and is dropped across a reboot. Held rather than restricted, so a box whose network never sends time keeps working. | TIM-1, DEP-4 | Restrict instead once carrier time has been seen this boot. |
| K5 | The guard checks every 15 minutes (`Run`). `Guard.Now` and `Guard.Latest` check again before answering when the wall clock moved more than the tolerance against the monotonic clock since the last check, and, only when no `Run` loop is live, when the last check is older than the interval. Wall clocks are compared with monotonic readings stripped (`Round(0)`), since `time.Time.Sub` otherwise uses only the monotonic clock and never sees a step (L3 D1). So an NTP step, spoofed or real, is checked before the next time-sensitive answer, and a first NTP sync at boot that the carrier confirms lifts the restriction at once. Concurrent checks share one read of each source, and a carrier read is bounded by `CarrierTimeout` (5 s), so callers never queue on the modem (potency PR1 on #68). The shared check runs without the first caller's deadline, so a short one cannot turn every joined caller's answer into "no carrier" (L3 D2), and owner texts and `OnChange` run after the result is published, from one queue in check order, so a slow text or a callback that checks again holds no joined caller (L3 D3). Texts are never dropped; only an `OnChange` that a later queued change supersedes is skipped (L3 F2). `OnChange` reports each state change so the wiring can re-run lapse sweeps when a restriction lifts (PR2). | TIM-1 | Constants. |
| K6 | The owner gets fixed texts (UX-68-1, UX-68-2 on #68). When a disagreement starts: "The box clock and the phone network's time differ by about N hours, so the box is playing safe: pre-allowances with an end date ask you first, requests won't expire, and updates wait. Codes and STOP work as usual." It is two segments at most, and adds "A whole-hour difference is often a time-zone error on one side." when the skew is within a minute of a whole number of quarter hours. No new alert goes out while one is outstanding. The all-clear goes only after carrier time has agreed for an hour (`AgreeAfter`); the restriction itself lifts at once. Alerts (disagreement or hold texts) are capped at 2 sent in any 24 hours (`MaxAlertsPerDay`, L3 D4 and the security lens on #68), counted across restarts in `StatePath` (an earlier boot's alerts by their box-clock age, never placed in the future). A hold that escalates to a disagreement is texted even at the cap (L3 F3). Earlier-boot alerts are aged by the box clock clamped to between zero and this boot's uptime, so no clock setting frees the cap before a day of uptime (L3 F1). Every alert sent gets its all-clear, so the owner is never left on a stale alarm and gets at most 4 texts a day however a fake cell flaps. The all-clear that uses up the day's alerts says so ("If they disagree again today the box won't text; send STATUS to check."), so a later unsent alert is not a surprise. STATUS and the digest always show the live state. Texts go through `Config.Notify`, which the wiring points at the owner channel's broker-template sender. `Status.Line` is the STATUS line: "Time check: restricted since HH:MM (…)", agree, network only, phone network only, or not checked. | TIM-1, CH-12 | Wording. |
| K7 | **Carry-forward for the wiring package** (which consumers are restricted, and how): the owner channel's STATUS reply includes `Guard.Status().Line` in the owner's zone (UX-68-3); callers deciding an expiry call `Guard.Now` and fail closed on `ErrRestricted`. Grant, pre-allowance and update-metadata (UPD-8) expiry use the latest credible time, `Guard.Latest`, and only checks where a later time is stricter do: the later of the box clock and the last carrier reading carried forward on the monotonic clock, so something lapses if it has expired under either, and a clock moved back cannot keep authority alive; a fake cell's future time fails safe, as early lapses the owner re-grants (potency PT1 on #68; proposed, pending the security lens). Minimum-age checks use the earliest credible time, `Guard.Earliest`, and fail closed while restricted, so a clock moved forward cannot end them early (L3 C4 on #68): the grants gate's `HoldDays` (`broker/grants/gate.go`), the UPD-5 soak, quiet windows, and any "wait N" rule. While restricted, pre-allowances with an end date ask the owner first. Approval-request lapse: hold, never close as lapsed. The vault's last accepted code step (egress K7) must persist across restarts, or a clock moved back after a restart reopens old steps (security on #68). Update metadata (UPD-8): no freshness claim, so a security fix does not auto-stage, and an install says it had no freshness check. The vault process's code-generator checks (CH-4, egress K7) keep using the box clock: its shared last accepted step already refuses an older code, and refusing codes would let a spoofed cell network lock the owner out. | TIM-1, UPD-8, OP-3, CH-4 | Wiring. |
| K8 | **Carry-forward for the local UI (P2-2) and wiring** (potency PT2 on #68): an owner way out of a restriction that lasts, a code-gated "Trust the box clock" action on the local page that lifts the restriction until the skew moves by more than the tolerance from its value then. It is not built here, since it changes who can lift a restriction and needs the security lens. S2 C16 measures how far carrier time drifts across a day. | TIM-1, CH-7 | Local UI package. |
| K9 | **Residual risk** (security R2 on #68): an attacker who controls both NTP and a fake cell, and gives both the same false time, is not detected. The two paths are independent (internet vs. radio), which is the point of the cross-check, but they are not authenticated. `Latest` limits the damage for expiry: a clock moved back cannot keep authority alive past the last honest carrier reading. A second residual: spoofed NTP answers small enough that timesyncd slews rather than steps move the wall and boot clocks together, at up to 500 ppm (about 43 s a day), so they open no gap the hold sees; only carrier time catches them, or `CLOCK_MONOTONIC_RAW` (unslewed) as an optional later reference. | TIM-1 | Authenticated time (NTS) when Debian's timesyncd supports it. |
| K10 | Not built (security R3 on #68): holding a large first NTP step at boot against the RTC when no carrier time is seen. A box whose RTC is hours off and whose network never sends time would then hold the wrong time indefinitely, and the owner's code-generator codes would fail (CH-4). The first synced check of a boot is the anchor instead. Stale carrier readings (a module clock running on without network updates) cannot be told apart from fresh ones by `AT+QLTS` or `AT+CCLK?`; S2 C17 measures that drift (security R4). | TIM-1, CH-4 | If S2 shows carriers always send time, hold at boot too. |
