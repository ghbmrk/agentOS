# Box time check: assumptions

Built for P2-9 against SPEC v0.12 TIM-1 ("Time comes from network time when
online, with carrier network time (from the modem) as a cross-check. Large
disagreements put the broker into restricted mode for time-sensitive
checks."). Packages: `clock` (the guard) and the carrier source in
`modem/at` (`Modem.NetworkTime`, simulated in `atsim`). Each row is a
reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| K1 | "Network time" is the kernel clock as set by NTP. The broker never sets the clock; `systemd-timesyncd` does, and `clock.Synced` reads whether it has (read-only `adjtimex`: not `TIME_ERROR`, no `STA_UNSYNC`). **For P2-1:** enable `systemd-timesyncd` with Debian's default pool servers (no AgentOS-run server, DEP-2). NTP is unauthenticated, which is why the cross-check matters. | TIM-1, DEP-2 | Small: another `Synced`. |
| K2 | Carrier time is read from the modem on demand and only compared, never used to set the box clock. Quectel: `AT+QLTS=1` (UTC as of the last network time update, `""` before one). SIMCom: `AT+CCLK?` after `AT+CTZU=1` (`NetTimeOn`, best effort at `Open`); it has no "never set" answer, so a module clock before 2025 is treated as no carrier time. A modem error is no carrier time, never a disagreement. What S2 must confirm is C14 and C15 in [S2-CONFIRM.md](../modem/at/S2-CONFIRM.md). | TIM-1, HW-2 | Per vendor: `Profile.NetTimeCmd`/`NetTime`. |
| K3 | "Large" is more than 5 minutes (`DefaultTolerance`). The module clock runs on between network updates, and the broker's time limits (codes, request lapses, grant end dates, update metadata expiry) are minutes to days, so 5 minutes avoids false alarms while catching any shift that moves an expiry. | TIM-1 | Constant. |
| K4 | Only a disagreement restricts. With one source (`NetworkOnly`, `CarrierOnly`) or none (`Unchecked`: offline with no modem time) the box keeps running on its clock, as DEP-4 requires offline work; callers that need two sources read `Status().State`. Once restricted, only carrier time that agrees again lifts it: losing the carrier (jammed, unplugged, a network that stops sending time) keeps the restriction, at the cost of staying restricted until the modem is back. The state is not persisted: a restart checks afresh. | TIM-1, DEP-4 | A spec diff to restrict on one source. |
| K5 | The guard checks every 15 minutes (`Run`), and `Guard.Now` checks again before answering when the last check is older than that, or when the wall clock moved more than the tolerance against the monotonic clock since it. So an NTP step, spoofed or real, is checked before the next time-sensitive answer, and a first NTP sync at boot that the carrier confirms lifts the restriction at once. | TIM-1 | Constants. |
| K6 | The owner gets fixed texts: one when a disagreement starts ("The box clock and the phone network's time differ by about N hours…"), at most one per 24 hours however often the sources flap, and one all-clear for each such text. Texts go through `Config.Notify`, which the wiring points at the owner channel's broker-template sender. | TIM-1, CH-12 | Wording. |
| K7 | **Carry-forward for the wiring package** (which consumers are restricted, and how): callers deciding an expiry call `Guard.Now` and fail closed on `ErrRestricted`. Grant and pre-allowance end dates: treat a bounded grant as lapsed, so authority never outlives its window on a moved clock. Approval-request lapse: hold, never close as lapsed. Update metadata (UPD-8): no freshness claim, so a security fix does not auto-stage, and an install says it had no freshness check. The vault process's code-generator checks (CH-4, egress K7) keep using the box clock: its shared last accepted step already refuses an older code, and refusing codes would let a spoofed cell network lock the owner out. | TIM-1, UPD-8, OP-3, CH-4 | Wiring. |
