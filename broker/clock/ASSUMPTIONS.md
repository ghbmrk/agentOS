# Box time check: assumptions

Built for P2-9 against SPEC v0.12 TIM-1, moved to the interval rule of
TIM-1 as #5215 restates it ("Time is an interval from network time,
cross-checked against modem carrier time, widened by drift and
disagreement. A time-due move that widens [...] waits until the interval's
start passes it, and one that narrows fires at its end") by #5216. Packages:
`clock` (the guard) and the carrier source in `modem/at`
(`Modem.NetworkTime`, simulated in `atsim`). Each row is a
reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| K1 | "Network time" is the kernel clock as set by NTP. The broker never sets the clock; `chronyd` does (HOST-1b, superseding `systemd-timesyncd`: timesyncd clears the kernel's `STA_UNSYNC`, which arms the kernel's 11-minute copy of the clock into the host's hardware clock, HW-8). `clock.Sync` asks chronyd through `chronyc -c -n` (tracking, sources, authdata): synchronised at stratum 1-15 and the selected source NTS-authenticated (`SyncedNTS`, by its authdata mode) with the system clock within `NTSConverged` (1 s, tracking's system time) of it, since a forged plain-NTP step at boot is slewed back at 500 ppm while the NTS source is selected (security finding 1 on #5754; this also keeps K11's floor and K12's offset from learning an unconverged clock), or at least three sources combined (`SyncedPlain`) (security T4, T5, R1 and R2 on #177); any error is unsynced. chrony.conf pins `authselectmode prefer` (pool sources only when no NTS source is selectable), `makestep 1 3`, `maxslewrate 500`, and `port 0`, `cmdport 0` (no NTP server, no UDP command port). It never reads the kernel flag, which chronyd keeps set. **For P2-1:** install `chrony` with `clock/chrony/chrony.conf` as `/etc/chrony/chrony.conf` (NTS servers first, Debian pool fallback, no RTC directives, no DHCP sources), mask `systemd-timesyncd`; `agentosd` must run as root: it reaches chronyd's unix command socket in `/run/chrony`, and authdata is refused to anyone else. Plain NTP is unauthenticated, which is why the cross-check matters; one attacker who controls both sources and gives both the same false time is undetectable by design (K9). | TIM-1, DEP-2, HW-8 | Small: another `Synced`. |
| K2 | Carrier time is read from the modem on demand and only compared, never used to set the box clock. Quectel: `AT+QLTS=1` (UTC as of the last network time update, `""` before one). SIMCom: `AT+CCLK?` after `AT+CTZU=1` (`NetTimeOn`, sent best effort at `Open` and never in `Init`, so a module that refuses it still texts and calls; security C3); the zone must be two digits; it has no "never set" answer, so a module clock before 2025 is treated as no carrier time. A modem error is no carrier time, never a disagreement. What S2 must confirm is C14 and C15 in [S2-CONFIRM.md](../modem/at/S2-CONFIRM.md). | TIM-1, HW-2 | Per vendor: `Profile.NetTimeCmd`/`NetTime`. |
| K3 | "Large" is more than 5 minutes (`DefaultTolerance`). The module clock runs on between network updates, and the broker's time limits (codes, request lapses, grant end dates, update metadata expiry) are minutes to days, so 5 minutes avoids false alarms while catching any shift that moves an expiry. | TIM-1 | Constant. |
| K4 | **The interval** (#5216). `Guard.Interval` gives `Earliest` and `Latest` from one check: the box clock (the held time while held, K4a) widened by the last carrier reading carried forward on the monotonic clock, and, until this boot has verified time, by the floor (K11). A disagreement widens it; nothing stops time. The restricted mode below survives only in `Guard.Now` and `ErrRestricted`, for callers not yet on the interval (`broker/question`, sub B; release item on #5216), and only while plain sources disagree (K16). With one source (`NetworkOnly`, `CarrierOnly`) or none (`Unchecked`: offline with no modem time) the box keeps running on its clock, as DEP-4 requires offline work; callers that need two sources read `Status().State`. Once disagreeing, only carrier time that agrees again ends it: losing the carrier (jammed, unplugged, a network that stops sending time, a SIMCom module clock pushed below the floor by a fake cell) keeps the disagreement, at the cost of a wide interval until the modem is back. The disagreement, the outstanding owner text and the hold anchor are kept in `StatePath` (0600, written atomically) and survive a restart; an unreadable file counts as a disagreement until carrier time agrees, with a fixed owner text (`StateLostText`) rather than a skew it cannot know (security C2, L3 F5 on #68). The write is `privfile.WriteAtomic` (the new core's, not old-core `durable`; #5147 a): the temporary file and the directory are synced around the rename, a directory another uid can write is refused, and a failed save is logged (`Logf`). **For the wiring:** set `StatePath` under the broker's state directory. | TIM-1, DEP-4 | A spec diff to widen on one source. |
| K4a | **Hold** (security C1 on #68). The box clock is held to an anchor: the last carrier-confirmed check, or this boot's first synced check before any carrier time. A wall clock that has moved from the anchor, against the monotonic clock, by more than the tolerance plus a fixed 5 s, with no carrier reading to confirm it, is `Held`: `Now` and `Latest` answer the anchor carried forward on the monotonic clock, and the owner gets one fixed text. Measuring from the anchor rather than the last check catches many small steps that add up, however long after the anchor (NTP slewing moves the wall and boot clocks together, so time since the anchor earns no allowance; L3 F6 on #68). Agreeing carrier time re-anchors and ends the hold; disagreeing carrier time widens the interval (K4). A hold that ends without carrier time (the clock comes back in line) gets its own all-clear after `AgreeAfter`. The monotonic clock is `CLOCK_BOOTTIME`, so an anchor survives a broker restart within one boot (checked by `boot_id`) and is dropped across a reboot. Held rather than widened, so a box whose network never sends time keeps working. | TIM-1, DEP-4 | Restrict instead once carrier time has been seen this boot. |
| K5 | The guard checks every 15 minutes (`Run`). `Guard.Now` and `Guard.Latest` check again before answering when the wall clock moved more than the tolerance against the monotonic clock since the last check, and, only when no `Run` loop is live, when the last check is older than the interval. Wall clocks are compared with monotonic readings stripped (`Round(0)`), since `time.Time.Sub` otherwise uses only the monotonic clock and never sees a step (L3 D1). So an NTP step, spoofed or real, is checked before the next time-sensitive answer, and a first NTP sync at boot that the carrier confirms ends the disagreement at once. Concurrent checks share one read of each source, and a carrier read is bounded by `CarrierTimeout` (5 s), so callers never queue on the modem (potency PR1 on #68). The shared check runs without the first caller's deadline, so a short one cannot turn every joined caller's answer into "no carrier" (L3 D2), and owner texts and `OnChange` run after the result is published, from one queue in check order on a goroutine of their own, so a slow or hung text holds no caller (Run included) and a callback may check again; a notifier panic is logged and the queue goes on (L3 D3, F2). `Flush` waits for the queue. Texts are never dropped; only an `OnChange` that a later queued change supersedes is skipped (L3 F2). One exception: a broker exit while `Notify` hangs loses that text, though it still counts toward the cap, since alerts count when queued (L3 round 4). `OnChange` reports each state change so the wiring can re-run lapse sweeps when a restriction lifts (PR2). | TIM-1 | Constants. |
| K6 | The owner gets fixed texts (UX-68-1, UX-68-2 on #68). When a disagreement starts: "My clock and the phone network's time differ by about N hours, so I am playing safe: anything waiting for time to pass waits for both clocks, and anything that ends ends by either. Codes and STOP work as usual." (`DisagreeText`, the interval in owner words), or, against authenticated network time, `OutlierText` (K16). It is two segments at most, and adds "A whole-hour difference is often a time-zone error on one side." when the skew is within a minute of a whole number of quarter hours. No new alert goes out while one is outstanding. The all-clear goes only after carrier time has agreed for an hour (`AgreeAfter`); the interval itself narrows at once. Alerts (disagreement or hold texts) are capped at 2 sent in any 24 hours (`MaxAlertsPerDay`, L3 D4 and the security lens on #68), counted across restarts in `StatePath` (an earlier boot's alerts by their box-clock age, never placed in the future). A hold that escalates to a disagreement is texted even at the cap (L3 F3). Earlier-boot alerts keep the age their own boot clock measured; only the downtime between boots, which only the box clock can give, is clamped to between zero and this boot's uptime, so no clock setting frees the cap early and honest reboots still age alerts out (L3 F1). While any alert counts, every check saves the boot clock, so this holds without carrier time too (L3 F1, round 4). Alerts a day old are pruned before every save, so a saved in-boot age below zero or over a day means a corrupt file, and that alert counts as just sent (security R1 on #68). Every alert sent gets its all-clear, so the owner is never left on a stale alarm and gets at most 4 texts a day however a fake cell flaps. The all-clear that uses up the day's alerts says so ("If they disagree again today the box won't text; send STATUS to check."), so a later unsent alert is not a surprise. STATUS and the digest always show the live state. Texts go through `Config.Notify`, which the wiring points at the owner channel's broker-template sender. `Status.IntervalLine` is the STATUS line (LOG-8: the moves a wide interval delays, and its lift): "Time check: box and phone network differ by about N hours since HH:MM, so holds and timeouts end by both clocks and expiries by either, until they agree.", the K16 outlier line, a lost check's "playing safe" line, or `Status.Line`'s held, agree, network only, phone network only or not checked line. `Status.Line` keeps the restricted wording only until agentosd's STATUS line moves to `IntervalLine` (#5279), then goes. | TIM-1, CH-12 | Wording. |
| K7 | **Carry-forward for the wiring package** (which consumers read which end): the owner channel's STATUS reply includes `Guard.Status().IntervalLine` in the owner's zone (UX-68-3; #5279). A time-due move reads the interval (TIM-1): one that narrows (an expiry) fires once `Latest` passes it, one that widens (a hold's or limit's end, a default on timeout) once `Earliest` does; a clerk ending a KEY-8 hold (KEY-4, CLK-2) reads `Earliest` on its own guard. `Guard.Now` and `ErrRestricted` remain only for the question book until it moves. The rest of this row is the old wiring's reading, kept for the old core until step 5 deletes it. Grant, pre-allowance and update-metadata (UPD-8) expiry use the latest credible time, `Guard.Latest`, and only checks where a later time is stricter do: the later of the box clock and the last carrier reading carried forward on the monotonic clock, so something lapses if it has expired under either, and a clock moved back cannot keep authority alive; a fake cell's future time fails safe, as early lapses the owner re-grants (potency PT1 on #68, security signed off). Minimum-age checks use the earliest credible time, `Guard.Earliest`, and fail closed while restricted, so a clock moved forward cannot end them early (L3 C4 on #68): the grants gate's `HoldDays` (`broker/grants/gate.go`), the UPD-5 soak, quiet windows, and any "wait N" rule. While restricted, pre-allowances with an end date ask the owner first. Approval-request lapse: hold, never close as lapsed. The vault's last accepted code step (egress K7) must persist across restarts, or a clock moved back after a restart reopens old steps (security on #68). Update metadata (UPD-8): no freshness claim, so a security fix does not auto-stage, and an install says it had no freshness check. The vault process's code-generator checks (CH-4, egress K7) keep using the box clock: its shared last accepted step already refuses an older code, and refusing codes would let a spoofed cell network lock the owner out. | TIM-1, UPD-8, OP-3, CH-4 | Wiring. |
| K8 | **Carry-forward for the local UI (P2-2) and wiring** (potency PT2 on #68): an owner way out of a wide interval that lasts, a code-gated "Trust the box clock" action on the local page that ends the disagreement until the skew moves by more than the tolerance from its value then. It is not built here, since it changes who can lift a restriction and needs the security lens. S2 C16 measures how far carrier time drifts across a day. | TIM-1, CH-7 | Local UI package. |
| K9 | **Residual risk** (security R2 on #68): an attacker who controls both NTP and a fake cell, and gives both the same false time, is not detected. The two paths are independent (internet vs. radio), which is the point of the cross-check, but they are not authenticated. `Latest` limits the damage for expiry: a clock moved back cannot keep authority alive past the last honest carrier reading. A second residual: spoofed NTP answers small enough that chronyd slews rather than steps (any after its first three updates, `makestep 1 3`) move the wall and boot clocks together, at up to 500 ppm (`maxslewrate 500`, about 43 s a day), so they open no gap the hold sees; only carrier time catches them, or `CLOCK_MONOTONIC_RAW` (unslewed) as an optional later reference. | TIM-1 | Authenticated time (NTS) when Debian's timesyncd supports it. |
| K10 | Not built (security R3 on #68): holding a large first NTP step at boot against the RTC when no carrier time is seen. A box whose RTC is hours off and whose network never sends time would then hold the wrong time indefinitely, and the owner's code-generator codes would fail (CH-4). The first synced check of a boot is the anchor instead. Stale carrier readings (a module clock running on without network updates) cannot be told apart from fresh ones by `AT+QLTS` or `AT+CCLK?`; S2 C17 measures that drift (security R4). | TIM-1, CH-4 | If S2 shows carriers always send time, hold at boot too. |
| K11 | **Unverified hardware clock** (HW-8; HOST-1b, security T3, T4). Until this boot has verified time (`Status.Verified`: an NTS-authenticated sync; or a plain NTP sync or carrier time agreeing, either only with a box clock at or after the floor less the tolerance, since both can be forged on path (L3 MUST on #177); never while restricted or held), the box clock came from the host's hardware clock, which Windows keeps in local time. The **floor** is the latest verified time ever seen, kept in `StatePath`; it advances only at verified checks (so only an NTS-authenticated sync can find the floor ahead of verified time; that floor is a corrupt or tampered file and is replaced, logged; security R1 on #177; a plain sync below the floor is logged once per boot). While unverified, `Latest` is at least the floor and `Earliest` at most the floor: a clock behind keeps nothing alive past it, a clock ahead ends no wait early. The floor never steps the clock or restricts: `Now` answers the box clock (DEP-4). Verified holds for the rest of the boot, across broker restarts (by `boot_id`). **Residual (L3 on #177):** an on-path attacker who blocks NTS-KE (TCP 4460) and forges the pool's sources, or fakes a cell, can push the floor forward; it fails closed (unverified boots treat expiries as passed, waits as ended) until an NTS sync replaces it: a denial of service, not a grant. **Carry-forward:** a floor rolled back with the whole drive (an old state file restored) is caught only with the TPM NV anchor; a fake cell agreeing with a box clock after the floor can verify it (K9's residual risk, one source here). | HW-8, TIM-1 | Constants and rules in `check`. |
| K12 | **Hardware-clock offset** (potency C1, security T7). At an NTS-verified sync (not plain NTP or carrier time, which can be forged; L3 on #177) on a PC named by its firmware system UUID (`HostID`, sysfs `product_uuid`; none, all-zero or all-F names no PC) the guard reads the hardware clock (`RTC`, sysfs `since_epoch`, read-only) and keeps its offset from verified time, rounded to 15 minutes and only within ±14 hours, with a hash of that UUID (`HostKey`; the UUID is not kept). The drive moves between PCs, so the offset is used only on the PC it was learned on; boards sharing a placeholder UUID are a residual. `agentos-clock-boot` runs at boot before chronyd and sets the system clock (settimeofday) to the hardware clock less that offset (`BootEstimate`); with none learned on this PC, or a state file not root-owned 0600, it does nothing, and it never fails the boot. settimeofday leaves the kernel unsynchronised, so nothing is copied into the hardware clock. The estimate stays unverified; K11's floor bounds it. **For P2-1:** a oneshot unit `Before=chronyd.service`, `After=local-fs.target`, `-state` pointing at agentosd's `-clock-state`. | HW-8, TIM-1 | — |
| K13 | **STATUS while unverified** (UX-H1b-1): "Time check: not confirmed since start at HH:MM (waiting for network or phone-network time). Nothing to do.", the boot's start on the box clock in the owner's zone; a disagreement or hold keeps its own line. No owner text: the clock is mentioned only when asked. | HW-8, CH-11 | Wording. |
| K14 | **Carry-forward for P2-1 and HOST-1e** (security T1, T2, T6): mask `systemd-timesyncd`; refuse timedated's `SetTime` and `SetLocalRTC` (polkit rule, or mask `systemd-timedated`); leave out `util-linux-extra` (no `hwclock` binary or `85-hwclock.rules`); `/dev/rtc*` root 0600 and `DevicePolicy=closed` on root units. Image test: no `hwclock` binary or unit, chrony config as shipped, `/run/chrony` and chronyd's command socket not reachable by any uid but root and `_chrony`, agentos-clock-boot's state file root-owned 0600. VM test: QEMU `-rtc base=localtime`, sync over NTP, check `STA_UNSYNC` still set right after the sync and again after more than 11 minutes, reboot, and check through QMP that the hardware clock has not moved from the guest's view. | HW-8, A1 | P2-1, HOST-1e. |
| K15 | **HOST-1b part 2, not built here**: codes refused while unverified say "My clock isn't set yet, so codes may not work. Open my Wi-Fi page to set it." and still count toward the day's wrong codes (potency C2); phone-attested time on the Wi-Fi page for codes and waits only, never the floor or update checks (security T8-T10). | HW-8, CH-4 | HOST-1b part 2. |
| K16 | **An outlier source** (#5216 item 4). While the check's NTP sync is NTS-authenticated with the clock converged on its source (`Status.Authenticated`, K1), carrier time, which is unauthenticated, widens the interval by at most the tolerance around the box clock, so a fake base station's time hours off neither fires every expiry hours early nor delays every hold by hours. The disagreement is still a `Disagree` state: the owner gets `OutlierText` ("The phone network's time differs from my authenticated network time by about N hours, so I keep network time. A fake phone mast can do this. Nothing to do.") under K6's cap, STATUS says "network time stands", and `Restricted` is false, so `Now` answers the box clock. It stays a disagreement when the carrier goes quiet and across a restart, like any other (K4): only `Restricted` reads `Authenticated`, so when NTS then drops the full carried-forward width returns and STATUS names it (L3 blocker 1 on #5754). With plain NTP (three unauthenticated sources) or none, neither source outranks the other and the carrier widens the interval fully. Residual: an attacker holding an NTS server's key, or root on the box, is K9's case. Not built: a lost state file (Skew 0) is a disagreement of unknown width; its interval is the box clock alone (release item on #5216). | TIM-1 | A bound other than the tolerance. |
