# holder: assumptions

What `holder` and `cmd/agentos-holder` rest on (SIM-split, briefs/SIM.md; OPERATING §5).

| ID | Assumption | Source | Held by |
|---|---|---|---|
| H-1 | One holder process per account keeps that account's one login in its own memory, and nothing else does once holders are wired: egress gets only `vault.HashRedactor` (keyed hashes) and `egress.New` refuses a vault beside holders, or an adapter without a holder. This PR builds the holder and the egress route; production wiring (unlock step hands the login to the holder's keeper, egress drops the vault) is a follow-up, so until then the vault still lives in `agentos-egress`. | CRED-1, SIM-split | `TestEgressHoldsNoLoginAcrossProcesses` (memory scan of the egress process, with a control), `TestNewRequiresAHolderForEveryAdapterWithoutTheVault`; follow-up BOARD row |
| H-2 | Linux unix sockets and `SO_PEERCRED`: `request.sock` admits only the egress uid and `hand.sock` only the unlock uid, through `sockets.ListenPeers`; the binary refuses equal uids, running as either peer uid, and a run directory not 0711 or not owned by its uid, and makes itself non-dumpable (`procguard.Isolate`, #1053 R3). | ARC-1, K4 in egress | holder peer-uid tests, `TestParseRefusesWhatAHolderCannotKeep`, `TestRunRefusesItsPeerUID`, `TestIsolateRefusesItsPeerUIDAndDropsDumpable` |
| H-3 | The holder serves only the closed request shape its adapters declare (ADP-10): host picks the adapter, the op must match, no query string, only the forwarded headers, identity encoding. It does not re-apply an op's body rule; egress checks the body before forwarding. | ADP-10 | holder request-shape tests (query string: #1053 R4); body rule: SIM-split-fix (#1053 R2) |
| H-4 | The keyed-hash redactor cannot be inverted for long random logins, but its key sits beside the hashes in egress, so a short or low-entropy value can be brute-forced from egress memory. Provider API keys are long and random. | CRED-7 | review; LATER row |
| H-5 | The holder redacts its own login from every response header and body it forwards (`vault.NewRedactor`), and egress redacts every vault value again with hashes, so one missed path is caught by the other. An encoded response is refused, since neither can read it. | CRED-7 | holder redaction tests, `TestHolderRouteHoldsNoSecret` |
| H-6 | Exchange (CRED-5) swaps happen in the holder with the same `Operation.SwapResponse` the proxy uses, and a failed swap reaches egress as `Agentos-Holder-Drop`, which stops the route as the proxy's own failure would. The binary refuses exchange adapters until refreshed tokens can be persisted back through the unlock step. | CRED-5, CRED-5t | `TestHolderDropStopsTheRoute`, holder exchange tests, `TestParseRefusesWhatAHolderCannotKeep` |
| H-7 | The holder binary dials through a netguard with no compute-host pins; pins come with production wiring. Holder-side refusals (refused, no secret) reach the guest as upstream unreachable. | DEV-2 | review; follow-up |
| H-8 | A holder that restarts has no login until the keeper re-hands it (`Keeper`, every 2s by default); until then it answers 503 no-secret, so the route fails closed. | CRED-1 | `TestKeeperRehandsAfterRestart`, the restart step of `TestEgressHoldsNoLoginAcrossProcesses` |
| H-9 | A read is served on the declaration alone. An irreversible or secret verb is served only when `Config.Redeem` (the CH-4 checker's redeem socket, `-checker`) spends an approval for `checker.Act(host, method, wire path, body)` of this exact request; with no checker, and for draft, organize or an unknown verb, the holder refuses. The approval is spent before the provider is reached, so a request that then fails upstream needs a fresh owner code. | CH-4, CH-10, SIM-split | `TestHighRiskActNeedsACheckerVerifiedCode`, `TestApprovalCoversHighRiskVerbsOnly`, `TestHolderRedeemsOverTheCheckerSocket`, the non-read case of `TestShapeOutsideTheDeclarationGetsNoLogin` |
