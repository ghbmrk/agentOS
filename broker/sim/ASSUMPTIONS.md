# Broker simulation: assumptions

Built for SIM-sim (BOARD.md, briefs/SIM.md), first half: the seeded harness. It covers `broker/sim`, which drives the real `journal.Engine` on a fake disk, clock and services. Judging each run by SIM-check's predicates, the DEL-1 and stale "Cleared" mutants, and deleting the scattered crash-cut tests are the second half, after SIM-check merges. Each row is a reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| A1 | **The state machine under test is `journal.Engine`.** Only the journal is durable (SPEC §9), so the sim drives it through its public API (Submit, Authorize, Dispatch, Reconcile, Resolve, Stop, Resume, Erase, RecordQuality, Open) with real executors and policy replaced by fakes. agentosd's wiring is not simulated. | OP-4, OP-5 | When SIM-proj adds projections, the sim rebuilds them at each boot as it rebuilds the grant table now. |
| A2 | **The fake disk models one file on a POSIX file system.** A write can be cut part way (a prefix reaches the page cache); a process kill keeps the page cache; a power cut keeps what was fsynced plus any prefix of the unsynced tail of an append; a rename whose directory was not synced survives a power cut or not, by coin flip. `journal.OpenFile` syncs the directory, so a boot promotes a pending rename. | OP-4, CAP-3 | A file system that reorders appends inside one file needs a richer model; ext4 data=ordered does not. |
| A3 | **Crash points are every write, fsync, rename and directory sync the engine makes, Open's own included.** The scheduler arms a crash 1 to 8 points ahead, and also from inside a policy check or executor call. | brief: "crash cuts at every write and fsync" | none |
| A4 | **Concurrency is modelled as nesting.** The engine releases its lock around `Policy.Check` and `Executor.Execute`; the sim runs a grant revoke, a STOP or a crash arm there, one level deep. The policy reads the grant before its nested operation runs, so a nested revoke lands between that read and the dispatched record: the window the engine's `e.seq` recheck closes. This reaches the OP-3 race deterministically, without goroutines; `MutantStaleRecheck` shows the sweep catches that recheck's absence (L3 #727). | OP-3 | Real goroutine interleavings inside the engine's locked sections are not explored; the race detector covers those in `journal`'s own tests. |
| A5 | **Grants are a projection of the journal.** Grant and revoke are `meta.grant` intents on the broker account, applied when they run and rebuilt from the trail at every boot; a grant whose outcome was not journaled before a crash did not happen. | OP-5 | none |
| A6 | **Oracles the journal cannot hold are checked against the fake world**: the dispatched record is durable before an executor runs (OP-4); the grant is held when an executor runs (OP-3); no attempt runs twice and no intent takes effect twice (OP-2); an erased intent's content is on neither the live nor the durable bytes after the erase returns or the engine opens (CAP-3). Journal-only predicates belong to SIM-check and plug in as `Config.Judge`, run on the durable bytes after every boot and at the end. | OP-2, OP-3, OP-4, CAP-3 | none |
| A7 | **Determinism.** One `math/rand` source seeded by the run drives every choice, the clock moves only when the scheduler advances it, and the engine's iteration order is its own sorted or insertion order. The same seed gives the same trace and byte-identical journal. | brief acceptance | A map iteration added to the engine's write path would break this; `TestSameSeedGivesAByteIdenticalJournal` catches it. |
| A8 | **Seed budget.** CI runs 100 seeds of 200 operations under `-race` (about 45 s); `SIM_SEEDS` widens the sweep. Each mutant is found within 50 seeds. | brief acceptance | Raise the sweep if a soak job finds a seed CI missed. |
