# corpus: assumptions

Built for P3-4b-4a and P3-4b-4d (the closed checks and their guest-plane routes; their rows are loops S27 and S42–S45); this file starts with P3-4b-4c-corpus, which embeds the corpus. Requirement IDs: LOOP-7 (bullet 3), LOOP-9. No item is written or generated by a model (D-067).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| C1 | **The corpus is part of the signed binary.** `promptinject.json` holds the items of `assurance/corpora/promptinject/items.json` (`go:embed` cannot reach `assurance/`) and is embedded with `//go:embed`; `Items` parses it with `loops.ParseCorpus`. No drive file is read, so a corpus swapped on the drive is never replayed, and the binary's signature (the verity image) is the corpus's digest; no separate SHA-256 pin is kept. The copy leaves out the vendored file's provenance fields (name, URL, commit, licence): the upstream URL is a literal `tools/depaudit.py static` flags anywhere in `broker/` outside `broker/vendor/`, and its inert-literal list admits only vendored third-party files. `tests/test_corpus.py` holds the copy byte for byte to one rendering of the vendored items (as `tools/corpus.py` writes `items.json`), so a changed byte in the copy or a changed vendored item fails it; the vendored file is itself pinned to its upstream digests. | LOOP-7; #515 Security 3; brief P3-4b-4c-corpus req. 1 | Re-vendoring regenerates both files in one PR. If a corpus ever ships outside the binary, pin its SHA-256 and refuse a mismatch before parsing. |
| C2 | **No item is excluded.** LATER P3-4b-4d l8 said one vendored item does not fit one owner text (S45). With the 10 items vendored at 7739e20 none is over: the longest, carrying the code filter's payload, is 124 bytes with `owner.AgentPrefix`, under `control.MaxText` (459). So the embedded set is the whole vendored set and the in-process and plane replays cover every item. `TestEveryEmbeddedItemFitsOneOwnerText` runs the plane code filter's own bound over every embedded item and fails on a planted over-long one. | LOOP-7; loops S45 | If a re-vendored item is over one owner text, that test fails: exclude it here by item ID with the reason (the vendored file keeps it), or report it as its own finding. |
| C3 | **In-process checks need no mail code.** `InProcess` is the code filter and the commitment filter. The alert patterns and the label check run only through a guest (`PlaneChecks`), since they sit in the mail clerk's process (VRB-2); `Checks` and its `Mailbox` interface, whose only implementer was the old `*mail.Adapter`, were deleted with MIG-4-untrusted-mail (#2777). Names and payloads are shared, so a finding from either set names the same check. | LOOP-7, HLD-5, ARC-2; brief P3-4b-4c-corpus req. 3 | If an in-process copy of the alert patterns is wanted again, it takes the mail clerk's exported check, not a copy. |
