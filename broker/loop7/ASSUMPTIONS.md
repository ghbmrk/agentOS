# loop7: assumptions

Built for P3-4b-3 against LOOP-7 (bullet 2), LOOP-9 and LOOP-1. The source runs off-the-shelf checks only (D-067): Go's native fuzzer over the decoders' own targets, and the fixed `sockprobe` frames. Nothing here writes or searches for attacks.

| F1 | **One source for Loop 2.** The scheduler takes one source per loop, so `loop7.Source` wraps the passive `loops.Guard` as `Inner` and offers Inner's job first; a LOOP-7 job is offered at most once per `Every` (default 1 h), taking turns: the probe, then each fuzz target. | LOOP-1, LOOP-7 | If the scheduler takes several sources per loop, register this one beside the Guard. |
| F2 | **Bounded fuzz in spare capacity.** A fuzz job runs a prebuilt test binary for `FuzzTime` (default 30 s) with one worker, in its own process group; cancelling the job kills the group, so it returns within the preemption target (LOOP-1, 2 s) and is offered again. Jobs use no model. With `Config.Jail` (P3-4b-3r-confine) each child also starts inside the jail's cgroup leaf through `CLONE_INTO_CGROUP` (`SysProcAttr.CgroupFD`), so none runs a moment in the broker's group, as the jail's unprivileged user with no supplementary groups and no capabilities (a non-zero uid set from root clears them across exec; no ambient capability is raised), in an empty network namespace (`CLONE_NEWNET`: a loopback that is down, no routes), in an IPC namespace of its own (`CLONE_NEWIPC`, P3-4b-3r-confine-r4), whose SysV segments and POSIX queues die with its last process, which `empty()` ensures, so none stays charged to the leaf's memcg into later steps (`TestAJailedChildsSharedMemoryDiesWithItsRun`), and in a user namespace that maps only the jail's uid and gid to themselves (`CLONE_NEWUSER`), so the child keeps its ids and no capability, and the kernel refuses its project ID and `PROJINHERIT` changes (`fileattr_set_prepare` in `fs/ioctl.c`, `fs/file_attr.c` from 6.17, returns `EINVAL` for them outside the initial namespace; inside it an owner needs no capability), which would otherwise let it, as owner, retag its tree out of its quota (F15). The daemon, as root, creates the namespace, so its owner is root, not the fuzz uid, and the child holds no capability in it after exec (`TestAJailedChildsUserNamespaceMapsOnlyItsIDs`, which also checks `uid_map` and `gid_map` hold only the jail's ids). Host policy: AppArmor's `apparmor_restrict_unprivileged_userns` exempts a creator with `CAP_SYS_ADMIN`, so it does not apply; `user.max_user_namespaces` does bind root, and at 0 every child fails to start, a runner error that F14 reports, so the jail fails closed to no fuzzing, never to an unconfined child. `/dev/shm` is a file system, not IPC: the image denies it to the user (agentosd L7-6). A memory blow-up is the kernel's OOM kill in the leaf, not in `agentosd`'s group (`TestAnInputPastMemoryMaxIsKilledInTheLeafAndReported`). Every child, jailed or not, starts with `no_new_privs` (P3-4b-3r-confine-r3): `run` starts it from a goroutine locked to its thread that sets `PR_SET_NO_NEW_PRIVS` first and exits still locked, so the runtime ends that thread (or, on the process's main thread, wedges it for good with no goroutine on it: `runtime.mexit`). The flag is per thread, inherited across clone and kept across exec, and Go's `forkExec` clones from the calling thread (`syscall`'s `forkAndExecInChild` issues `clone`/`clone3` inline; hence `Pdeathsig`'s "creating thread"). So the child and all it execs can never gain privileges through a setuid or file-capability binary (`TestAJailedChildCannotGainPrivileges`, `TestEveryFuzzChildHasNoNewPrivs`), and no other daemon thread or child carries the flag (`TestNoNewPrivsStaysOffTheDaemonsOtherThreads`). | LOOP-1, ARC-2 | If Go ever forks from another thread than the caller's, the flag misses the child (the tests fail): start it through an exec shim that sets the flag, a new release binary (own BOARD row). If the box's kernel lacks `clone3` (before 5.7) every child fails to start, a runner error: move the child after start instead, accepting the window. |
| F3 | **Crash to finding.** Go writes the crashing input to the target's `testdata/fuzz/<Target>/`, which keeps it as the regression. Each round first replays that corpus; every failing input is reported as a High `fuzz` finding whose evidence is the input's SHA-256, and the input file itself stays on disk. An input whose own seed subtest passes again (an update fixed the decoder) resolves its finding; one that never ran, because an earlier seed's panic stopped the binary, does not. Restart-safe: the state is the corpus and `OpenReported`. | LOOP-7, LOOP-9 | If evidence must carry the bytes, add them to `Finding.Detail` with a size cap. |
| F4 | **Probe to finding.** A probe round's failures, plus `Journaled`'s broker-side check (a refusal note for every code in `sockprobe.Frames`, whatever the guest reports), become one High `probe` finding per machine; a clean round resolves it. A probe finding pauses nothing (`Contain` nil): A-6 allows a pause but does not need one, and a false failure provoked by a guest then costs only a notice. | LOOP-7, LOOP-9, A-6 | Pause the machine's grants when Mark wants probe failures contained. |
| F5 | **Journal window.** The daemon coalesces refusal notes per machine and code per minute, so a note up to `Window` before the round counts. | LOOP-7 | Tie `Window` to the gate's window if that changes. |
| F6 | **Fuzz targets.** sockets (`FuzzRequest`, `FuzzFrames`), browser (`FuzzParse`), modemlink (`FuzzInbound`) and guest (`FuzzMCP`) are new; each has a planted-decoder control and a seed corpus, runs 20 s per CI run and joins the soak matrix. | LOOP-7 | — |
| F7 | **Production wiring (P3-4b-3a).** `cmd/agentosd` builds this source with the targets the image lists (`Load` over `/usr/lib/agentos/fuzz/manifest.json`), `Every` 30 min, `FuzzTime` 30 s and `Probe` nil (agentosd ASSUMPTIONS L7-1 to L7-5). Each child is a `<pkg>.test` file directly in `Config.Release`, never a link (checked in `New` and again before each exec), runs with a minimal environment in a scratch directory, and in its own process group; and with the `Jail` agentosd builds (its leaf, `agentos-fuzz`, no network, its own IPC and user namespaces, the state's disk quota: agentosd ASSUMPTIONS L7-6). `Jail` nil, as in tests and dev builds, runs children as the daemon. | LOOP-7, ARC-2 | — |
| F8 | **CI's fuzz bound is a count (P1-4-flake).** CI fuzzes each target for `-fuzztime 600000x`, about what 20s ran on CI, not for a time: in Go 1.26's `internal/fuzz`, the coordinator wakes on the `-fuzztime` deadline and stops with `ctx.Err()`, which it ignores only when it equals its child context's error, and a parent's `Done` closes before its children are cancelled; so a time-bounded run can fail with a bare `context deadline exceeded` and no input (#537). A count sets no deadline. The soak's duration-bound runs keep the race (row P1-4-flake-soak). | LOOP-7 | A toolchain with the coordinator fixed lets CI return to a time bound; a slower target makes the count's run longer, inside the job's 30-minute limit. |
| F9 | **Crash inputs live in the state directory and survive updates.** `Load` runs each target in `<state>/targets/<pkg>` (`/var/lib/agentos-fuzz` on the box, beside the broker's state since P3-4b-3r-confine-r2) and copies the release's read-only seeds there only where no file of that name exists, so an input found on the box is never overwritten by an update and is never written into the image. The state directory belongs to the jail's user (P3-4b-3r-confine): `Load` creates `/var/lib/agentos-fuzz` as root and `Jail.Own` puts it under its disk quota (`Jail.Disk`) and gives `agentos-fuzz` the whole tree, including inputs from before the jail, so children can read their corpus and write new crash inputs. `Own` never follows a link and skips a file with more than one link, so nothing a child plants hands it a file from outside the tree; it runs at start-up, before any child. The release's seeds stay read-only and root's. | LOOP-7, LOOP-9 | — |

| F12 | **Every replayed failure is a finding, and every child has a deadline** (Security 4a on #560). A whole replay runs within `ReplayTime` (1 m, also passed as `-test.timeout`). One that fails with no `--- FAIL` line (a runtime fatal error such as a stack overflow, out of memory, `os.Exit`, or a stored input that hangs) is replayed input by input, each within `InputTime` (10 s), and each input that exits non-zero or runs past its bound is reported by its digest. If none fails alone, the target itself is reported ("failed before any stored input could be named") until a whole replay passes. The fuzz step runs within `FuzzTime` + `ReplayTime`; an engine that runs past that is reported ("the fuzz engine did not stop within its bound"). This catches an engine that ignores `-test.fuzztime`. When a fuzzed input hangs a worker, Go stops at `-test.fuzztime`, prints PASS, exits 0 and stores no input; a step that exits 0 while the last `fuzz: elapsed: …, execs: N` line it printed shows `N` no greater than the baseline `K` of `gathering baseline coverage: K/K completed` (or `testing seed corpus: K/K`) is reported as a stall ("a fuzzed input stopped the fuzz engine making progress"; P3-4b-3r-fuzz). So is a step that exits 0 whose last count, wherever it stands against the baseline, has stood unchanged for at least one progress period (3 s, the engine's stats ticker) by the lines' own `elapsed` fields, measured from the first line that showed it to the last line (P3-4b-3h-r1): a worker that hung after the count moved. Measuring from the first line of the count, not only the last two lines, matters because the engine's last line comes as it stops, usually one or two seconds after its last tick (a real step printed 9 s, then 11 s). Why a flat period is a hang: the step runs one worker (`-test.parallel=1`), the count moves only when a worker call returns, a fuzzing call returns after 100 ms of fuzzing, and the step bounds each minimizing call to 1 s (`-test.fuzzminimizetime`, 60 s by default); `elapsed` is rounded to whole seconds, so a 3 s gap is over 2 s. A count flat that long means one input ran for most of 2 s, against the microseconds a decoder under fuzz takes: a hang, not a slow input. A host so loaded that a worker is descheduled that long raises a false finding, never a false close. Go's coordinator can also stop at its own `-test.fuzztime` yet exit 1 with only `context deadline exceeded`: its done channel closes before its workers' context is cancelled, so the cancellation it means to suppress reads as an error (a race load widens; P3-4b-3r-confine l9, #588 and #615). A step that ran its whole `FuzzTime` and whose one failure is that line, with no stored input, is judged by its progress as a clean stop is; that text before `FuzzTime` has passed, or beside any other failure, is still a step that did not run. A child that prints it gains nothing it lacks by exiting 0. A step with fewer than two exec lines is judged by the baseline rule only, and a step that prints no baseline or no count is neither a stall nor a good step. What the parse guarantees: the progress lines are read from the child's combined output, and the regexes are line-anchored with the last match winning, so a target that prints a line shaped like the engine's can move the parse (#586 L3 point 2). A forged stall only raises a finding: a false open, never a false close. A forged good step closes a hang finding only from a release binary other than the finding's producer, which loops holds (F13), so a forged close needs a new signed release whose own target the input still compromises. `run` keeps stdout and stderr combined: splitting them would not stop a worker that writes stderr, and `run`'s output handling is P3-4b-3r-confine-r5's. The broker keeps at most 1 MiB of a child's output (`outputCap`), since the leaf's `memory.max` does not bound the broker's buffer: the first 64 KiB, where the baseline line is, and the rest of the cap from the end, where the last count and a failure's reason are; the bytes between are drained and dropped, so the child never blocks (P3-4b-3r-confine-r5, `TestAFloodOfOutputIsCappedAndTheStepStillReports`, `TestANormalStepsOutputIsUnchanged`). A target whose corpus still fails is not fuzzed (the engine stops at a failing seed). Only a child that ran counts: a refusal before exec, or a start failure, is the runner's error, never a finding. A PASS line for an input that also failed is not a pass. Each package's targets keep a fuzz cache of their own (`CacheDir/fuzz/<pkg>`), since six packages name a target `FuzzParse`. | LOOP-9, LOOP-1 | — |
| F13 | **A hang closes on a good step of a new binary, against the producer loops holds** (P3-4b-3r-fuzz, P3-4b-3h-r2). An overrun or stall finding names no input, so no replay resolves it (`Resolve` refuses it; delta L3 on #560). The runner reports one with the SHA-256 of the target binary as the finding's `Producer`; loops keeps it on the finding's record in its own state (restart-safe), and a hang reported again while open replaces it with the newer binary, so a lucky good step of a build that hung closes nothing. The finding closes only when a later fuzz step of that target stops within its bound and its exec count moves past the baseline without stalling (F12), run from a binary whose digest differs from the record's producer: the runner passes `Guard.CloseTarget` a `Closure` of kind `step` with only the step's own digest and counts, and loops compares it against the record and saves the record's producer on the closure (S30). A good step of the producing binary closes nothing. Nothing about a hang is kept in `<Dir>`, which the fuzz user owns (F16): the former `<Dir>/hang.json` let a child running injected code pick the digest a later step was compared against (#586 L3 point 2), and is gone. loop7 neither reads nor deletes a stale one; it is the user's file, harmless once nothing reads it. There is no migration: no box runs LOOP-7 yet (P3-4b-4c is queued, and the image's fuzz release first shipped with #560), and a hang record open in a dev state with no producer stays open, shown in STATUS as before, until the hang is reported again. The step's output still sits where the child writes (F12): a forged good step needs a release binary other than the producer, so the rule rests on the release being read-only and release-listed (F7). | LOOP-9, LOOP-7 | If the closing evidence must not rest on the child's output, have the broker rerun the step itself under a separate uid. |
| F14 | **STATUS says when fuzzing makes no progress** (P3-4b-3r-pass; #560 Potency, L3 point 3). With targets configured, `Digest` adds "Loop 2: my fuzz self-tests have not run for N days. I keep trying." (hours under a day) once no fuzz step has completed for longer than `Recheck()`, and "Loop 2: one of my fuzz self-tests cannot run. The fix comes with an update." once a target's step has errored on two of its turns in a row (a full cycle). Both describe one stall, so while the cannot-run line shows, the not-run line is suppressed; both keep loops' owner-text lens rule through its exported checkers (P3-4b-3r-text, #585 UX). A step completes when `Fuzz` returns with its context live and no error, a finding included; a preempted step is not progress. Neither line names a target. The clock starts when the source is built and is not saved, so a restart resets it. | LOOP-7, LOOP-9 | If boxes restart more often than `Recheck()` (10 h as wired), save the last completion time in loop7's state. |
| F15 | **The fuzz cache is bounded** (P3-4b-3r-confine). Before each fuzz step the runner prunes the target package's own cache (`CacheDir/fuzz/<pkg>/Fuzz*`, so not a nested package's such as `modem/at` under `modem`) to `CacheCap` (64 MiB), then all of `CacheDir/fuzz` to `CacheTotal` (512 MiB), removing the oldest files first by modification time. The engine regenerates what is lost by fuzzing again; 19 targets at 64 MiB would pass the box cap, which then prunes across packages. It never walks the targets' `testdata`, where crash inputs are evidence (F3, F9). One step can grow its package's cache past the cap until the next step: 30 s on one worker writes far less than the gap to the state disk's free space. The caps keep the honest engine within the state's disk quota; the quota (P3-4b-3r-confine-r4: agentosd L7-6, 1 GiB and 262,144 inodes on the state tree's own project, set by `Jail.Disk` in `Own`) bounds a hostile child during its step, which the caps cannot, and the child cannot retag its tree out of the project (F2's user namespace) nor write in `/tmp`, `/var/tmp` or `/dev/shm` (the image's ACL). The caps count apparent bytes, not blocks: an honest cache of tiny entries holds more on disk than its cap, but would need over 200,000 entries, each at least a 4 KiB block, to reach the quota. | LOOP-1, RES-4 | If a box's engine hits the quota (a runner error naming EDQUOT), prune by allocated blocks. |
| F16 | **Root never works in the fuzz user's tree by path, nor while the user has a process** (L3 1 on #588). The jail's `State` (`/var/lib/agentos-fuzz`) belongs to `agentos-fuzz`, so any path root resolves there could be a link the user planted. Every root-side file operation in it (`Load`'s seeding, the scratch directory's create, chown and removal, the corpus reads, the prune, `Own`'s chown; it keeps no hang record there, F13) goes through an `os.Root` opened at `State` (or at `/` with no jail), which refuses to resolve a link out of it. Seeds are created `O_EXCL`, so a planted name stays as it is. `New` refuses a jail whose cache or target directories lie outside `State`. Root also never works there while a process of the user lives: `Own` and every run first, and every run last, kill the leaf (freeze it, SIGKILL every process in `cgroup.procs`, thaw, and wait until the kernel reports it empty; not `cgroup.kill`, after which CI's kernel kills a child started into the group by `CLONE_INTO_CGROUP` at once), so a child that leaves its process group (`setsid`) dies with its run and cannot race root's next path or fill the disk between steps (`TestAChildThatLeavesItsGroupDiesWithItsRun`). **Emptying is bounded and survives a failed freeze** (P3-4b-3r-confine-r6; #588 Security 4a L-a and L-b). The freeze gets 500 ms (`freezeWait`) and the whole of `empty` 1.5 s (`emptyWait`). That is `empty`'s own bound, not the caller's context, which a cancel has already ended when the leaf most needs emptying; with `waitDelay` (200 ms) after a killed child, a cancelled job gives the box back within LOOP-1's 2 s (`TestEmptyingALeafThatNeverFreezesStaysWithinThePreemptionTarget`, with a freeze that never completes). A freeze that fails or does not complete still kills: `empty` SIGKILLs every pid `cgroup.procs` lists, re-reads and kills again each millisecond until the kernel reports `populated 0`, and fails only if processes remain at the deadline, naming their pids (`TestAFailedFreezeStillEmptiesTheLeaf`). A failed `empty` is the runner's error: root then does not work in the tree, and the next run's first `empty` tries again. The freeze is what empties a fork loop in one pass: frozen, the leaf forks nothing after the first pass reads it, and in none of 30 rounds does a later pass find a pid the first missed (`TestAForkLoopIsEmptiedThroughTheFreeze`). Without it, a fork loop inside `pids.max` slips newborns past the first pass in some rounds (2 of 10 on CI's machines runner, 4 of 10 in a dev container on a 6.18 kernel), which is why the test runs 30 rounds, and the later passes catch them; so the repeated passes are the fallback for a failed freeze, and the freeze is the defence. Kills go by pid, not pidfd: `pidfd_open` would need new names in agentosd's syscall allow-list (`daemon` `netOK`). A pid is signalled in the same pass that read it, microseconds to milliseconds later, and the kernel hands a freed pid out again only after its allocator has cycled through `pid_max`, which no fork rate inside the leaf's `pids.max` reaches in that window; so a signalled pid is the leaf's process, or one freed and not yet reused, never another user's. Each run gives its scratch directory and every directory above it in `State`, the cache included, to the user through the same `os.Root`, so on a fresh state the cache root creates for the first run is the user's (Security B3 on #588, `TestAJailedFuzzStepUsesItsCacheOnFirstBoot`). Inside `State`, `os.Root` still follows the user's links: root may write seeds or read inputs through a link to another target's directory, all of it the user's own tree. **Reads are bounded** (P3-4b-3r-confine-r5): a stored input is opened without blocking and refused before any read unless it is a regular file of at most 1 MiB (`inputCap`; Go's fuzz inputs are small, and the largest seed the repository ships is 543 bytes), then read through a limit of 1 MiB + 1, so one grown since the stat is refused too. A refused input is the target finding "a stored test input is too large to replay", which holds the target unfuzzed and resolves once a whole replay reads every input it names. A release seed is read within the same cap. A replay reads every input it names before reporting anything: one root cannot read in the tree (a link out of `State`, a FIFO) fails the round as the runner's error, never as a finding or a resolution. **Tests that pin each defence** (each fails with its defence reverted, P3-4b-3r-confine-r5): a link out of `State` at a target's directory, through `Load`'s seeding, a replay's reads and a fuzz step (`TestALinkOutOfTheStateIsNeverFollowed`; `input` reverted to a path read, or `seed` to `os.MkdirAll` and `os.OpenFile` on joined paths); `ownPath` through a link at or above its path (`TestOwnPathNeverChownsThroughALink`; `os.Chown` or `os.Lchown` on a joined path); the prune through a directory swapped after its walk (`TestThePruneRemovesNothingThroughALinkSwappedAfterItsWalk`, through the `pruneWalked` test seam; `os.Remove` on a joined path); the read caps (`TestAnOversizeInputIsReportedNotRead`, `TestAStoredFIFOIsNotRead`, `TestAnInputReadStopsAtTheCap`); a hang under the jail and leaf (`TestAJailedRepeatedHangRecordsTheNewerBuild`); and no `cgroup.kill` (`TestAJailedChildStartsAfterTheLeafIsEmptiedTwice`). One walk goes by path: `Jail.Disk`'s quota tag (`quota.FS.Tag`), which `Own` runs after emptying the leaf, so no process of the user can swap a directory during it, and which neither follows nor tags a link. `State`'s parent is root-owned `/var/lib`, which the user cannot write: agentosd refuses a `State` that is a link or whose parent the user owns or may write by its mode (`unswappable`, agentosd L7-6). | LOOP-7, ARC-2 | If `State`'s parent ever becomes writable by the user, `State` itself can be swapped for a link; open it from a root-owned parent with `O_NOFOLLOW`. If the image ever lowers `kernel.pid_max` below systemd's 4194304, or the allow-list admits `pidfd_open` and `pidfd_send_signal`, kill through pidfds. If CI's log shows the first pass never missing a newborn without the freeze, the fork-loop test no longer shows the freeze matters: make the loop faster. |
