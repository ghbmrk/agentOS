# loop7: assumptions

Built for P3-4b-3 against LOOP-7 (bullet 2), LOOP-9 and LOOP-1. The source runs off-the-shelf checks only (D-067): Go's native fuzzer over the decoders' own targets, and the fixed `sockprobe` frames. Nothing here writes or searches for attacks.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| F1 | **One source for Loop 2.** The scheduler takes one source per loop, so `loop7.Source` wraps the passive `loops.Guard` as `Inner` and offers Inner's job first; a LOOP-7 job is offered at most once per `Every` (default 1 h), taking turns: the probe, then each fuzz target. | LOOP-1, LOOP-7 | If the scheduler takes several sources per loop, register this one beside the Guard. |
| F2 | **Bounded fuzz in spare capacity.** A fuzz job runs a prebuilt test binary for `FuzzTime` (default 30 s) with one worker, in its own process group; cancelling the job kills the group, so it returns within the preemption target (LOOP-1, 2 s) and is offered again. Jobs use no model. | LOOP-1 | — |
| F3 | **Crash to finding.** Go writes the crashing input to the target's `testdata/fuzz/<Target>/`, which keeps it as the regression. Each round first replays that corpus; every failing input is reported as a High `fuzz` finding whose evidence is the input's SHA-256, and the input file itself stays on disk. An input that passes again (an update fixed the decoder) resolves its finding. Restart-safe: the state is the corpus and `OpenReported`. | LOOP-7, LOOP-9 | If evidence must carry the bytes, add them to `Finding.Detail` with a size cap. |
| F4 | **Probe to finding.** A probe round's failures, plus `Journaled`'s broker-side check, become one High `probe` finding per machine; a clean round resolves it. A probe finding pauses nothing (`Contain` nil): A-6 allows a pause but does not need one, and a false failure provoked by a guest then costs only a notice. | LOOP-7, LOOP-9, A-6 | Pause the machine's grants when Mark wants probe failures contained. |
| F5 | **Journal window.** The daemon coalesces refusal notes per machine and code per minute, so a note up to `Window` before the round counts. | LOOP-7 | Tie `Window` to the gate's window if that changes. |
| F6 | **Fuzz targets.** sockets (`FuzzRequest`, `FuzzFrames`), browser (`FuzzParse`), modemlink (`FuzzInbound`) and guest (`FuzzMCP`) are new; each has a planted-decoder control and a seed corpus, runs 20 s per CI run and joins the soak matrix. | LOOP-7 | — |
| F7 | **Production wiring.** `cmd/agentosd` does not yet build the test binaries into the image or construct this source; that is a release finding. | LOOP-7 | — |
