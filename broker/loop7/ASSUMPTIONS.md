# loop7: assumptions

Built for P3-4b-3 against LOOP-7 (bullet 2), LOOP-9 and LOOP-1. The source runs off-the-shelf checks only (D-067): Go's native fuzzer over the decoders' own targets, and the fixed `sockprobe` frames. Nothing here writes or searches for attacks.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| F1 | **One source for Loop 2.** The scheduler takes one source per loop, so `loop7.Source` wraps the passive `loops.Guard` as `Inner` and offers Inner's job first; a LOOP-7 job is offered at most once per `Every` (default 1 h), taking turns: the probe, then each fuzz target. | LOOP-1, LOOP-7 | If the scheduler takes several sources per loop, register this one beside the Guard. |
| F2 | **Bounded fuzz in spare capacity.** A fuzz job runs a prebuilt test binary for `FuzzTime` (default 30 s) with one worker, in its own process group; cancelling the job kills the group, so it returns within the preemption target (LOOP-1, 2 s) and is offered again. Jobs use no model. With `Config.Jail` (P3-4b-3r-confine) each child also starts inside the jail's cgroup leaf through `CLONE_INTO_CGROUP` (`SysProcAttr.CgroupFD`), so none runs a moment in the broker's group, as the jail's unprivileged user with no supplementary groups and no capabilities (a non-zero uid set from root clears them across exec; no ambient capability is raised), and in an empty network namespace (`CLONE_NEWNET`: a loopback that is down, no routes). A memory blow-up is the kernel's OOM kill in the leaf, not in `agentosd`'s group (`TestAnInputPastMemoryMaxIsKilledInTheLeafAndReported`). | LOOP-1, ARC-2 | If the box's kernel lacks `clone3` (before 5.7) every child fails to start, a runner error: move the child after start instead, accepting the window. |
| F3 | **Crash to finding.** Go writes the crashing input to the target's `testdata/fuzz/<Target>/`, which keeps it as the regression. Each round first replays that corpus; every failing input is reported as a High `fuzz` finding whose evidence is the input's SHA-256, and the input file itself stays on disk. An input whose own seed subtest passes again (an update fixed the decoder) resolves its finding; one that never ran, because an earlier seed's panic stopped the binary, does not. Restart-safe: the state is the corpus and `OpenReported`. | LOOP-7, LOOP-9 | If evidence must carry the bytes, add them to `Finding.Detail` with a size cap. |
| F4 | **Probe to finding.** A probe round's failures, plus `Journaled`'s broker-side check (a refusal note for every code in `sockprobe.Frames`, whatever the guest reports), become one High `probe` finding per machine; a clean round resolves it. A probe finding pauses nothing (`Contain` nil): A-6 allows a pause but does not need one, and a false failure provoked by a guest then costs only a notice. | LOOP-7, LOOP-9, A-6 | Pause the machine's grants when Mark wants probe failures contained. |
| F5 | **Journal window.** The daemon coalesces refusal notes per machine and code per minute, so a note up to `Window` before the round counts. | LOOP-7 | Tie `Window` to the gate's window if that changes. |
| F6 | **Fuzz targets.** sockets (`FuzzRequest`, `FuzzFrames`), browser (`FuzzParse`), modemlink (`FuzzInbound`) and guest (`FuzzMCP`) are new; each has a planted-decoder control and a seed corpus, runs 20 s per CI run and joins the soak matrix. | LOOP-7 | — |
| F7 | **Production wiring (P3-4b-3a).** `cmd/agentosd` builds this source with the targets the image lists (`Load` over `/usr/lib/agentos/fuzz/manifest.json`), `Every` 30 min, `FuzzTime` 30 s and `Probe` nil (agentosd ASSUMPTIONS L7-1 to L7-5). Each child is a `<pkg>.test` file directly in `Config.Release`, never a link (checked in `New` and again before each exec), runs with a minimal environment in a scratch directory, and in its own process group; and with the `Jail` agentosd builds (its leaf, `agentos-fuzz`, no network: agentosd ASSUMPTIONS L7-6). `Jail` nil, as in tests and dev builds, runs children as the daemon. | LOOP-7, ARC-2 | — |
| F8 | **CI's fuzz bound is a count (P1-4-flake).** CI fuzzes each target for `-fuzztime 600000x`, about what 20s ran on CI, not for a time: in Go 1.26's `internal/fuzz`, the coordinator wakes on the `-fuzztime` deadline and stops with `ctx.Err()`, which it ignores only when it equals its child context's error, and a parent's `Done` closes before its children are cancelled; so a time-bounded run can fail with a bare `context deadline exceeded` and no input (#537). A count sets no deadline. The soak's duration-bound runs keep the race (row P1-4-flake-soak). | LOOP-7 | A toolchain with the coordinator fixed lets CI return to a time bound; a slower target makes the count's run longer, inside the job's 30-minute limit. |
| F9 | **Crash inputs live in the state directory and survive updates.** `Load` runs each target in `<state>/targets/<pkg>` (`/var/lib/agentos/loop7` on the box) and copies the release's read-only seeds there only where no file of that name exists, so an input found on the box is never overwritten by an update and is never written into the image. The state directory belongs to the jail's user (P3-4b-3r-confine): `Load` creates `/var/lib/agentos/loop7` as root and `Jail.Own` gives `agentos-fuzz` the whole tree, including inputs from before the jail, so children can read their corpus and write new crash inputs. `Own` never follows a link and skips a file with more than one link, so nothing a child plants hands it a file from outside the tree; it runs at start-up, before any child. The release's seeds stay read-only and root's. | LOOP-7, LOOP-9 | — |
| F10 | **A target an update removes** leaves its open `fuzz` finding as it is: nothing replays or steps it, so nothing closes it. It stays open and STATUS shows it (LATER P3-4b-3 l8); P3-4b-3r-fuzz's close rule (F13) needs a step of the target, so it does not close it either. Likewise a finding whose crash input file is removed by hand. | LOOP-9 | LATER P3-4b-3 l8. |
| F11 | **loop7 does not import sockprobe.** sockprobe holds the in-guest dialer, which agentosd must not link (ARC-2); `ProbeRun` returns the probe's failures as strings and the wiring passes the broker's probe set as `Config.Want`, which `New` requires with `Probe` (an empty set would pass every round). | ARC-2, LOOP-9 | When P3-4b-3f wires the probe, it takes the codes from a net-free list (sockprobe's frames moved, or copied with a test that they match). |
| F12 | **Every replayed failure is a finding, and every child has a deadline** (Security 4a on #560). A whole replay runs within `ReplayTime` (1 m, also passed as `-test.timeout`). One that fails with no `--- FAIL` line (a runtime fatal error such as a stack overflow, out of memory, `os.Exit`, or a stored input that hangs) is replayed input by input, each within `InputTime` (10 s), and each input that exits non-zero or runs past its bound is reported by its digest. If none fails alone, the target itself is reported ("failed before any stored input could be named") until a whole replay passes. The fuzz step runs within `FuzzTime` + `ReplayTime`; an engine that runs past that is reported ("the fuzz engine did not stop within its bound"). This catches an engine that ignores `-test.fuzztime`. When a fuzzed input hangs a worker, Go stops at `-test.fuzztime`, prints PASS, exits 0 and stores no input; a step that exits 0 while the last `fuzz: elapsed: …, execs: N` line it printed shows `N` no greater than the baseline `K` of `gathering baseline coverage: K/K completed` (or `testing seed corpus: K/K`) is reported as a stall ("a fuzzed input stopped the fuzz engine making progress"; P3-4b-3r-fuzz). Only the last count is read: the coordinator prints it on stderr as it stops, after its workers. The broker keeps at most 1 MiB of a child's output (`outputCap`), since the leaf's `memory.max` does not bound the broker's buffer: the first 64 KiB, where the baseline line is, and the rest of the cap from the end, where the last count and a failure's reason are; the bytes between are drained and dropped, so the child never blocks (P3-4b-3r-confine-r5, `TestAFloodOfOutputIsCappedAndTheStepStillReports`, `TestANormalStepsOutputIsUnchanged`). A step that prints no baseline or no count is neither a stall nor a good step. It does not catch every hang: one that starts after the count has moved past the baseline still ends in a clean step. A target whose corpus still fails is not fuzzed (the engine stops at a failing seed). Only a child that ran counts: a refusal before exec, or a start failure, is the runner's error, never a finding. A PASS line for an input that also failed is not a pass. Each package's targets keep a fuzz cache of their own (`CacheDir/fuzz/<pkg>`), since six packages name a target `FuzzParse`. | LOOP-9, LOOP-1 | — |
| F13 | **A hang closes on a good step of a new binary** (P3-4b-3r-fuzz). An overrun or stall finding names no input, so no replay resolves it (`Resolve` refuses it; delta L3 on #560). When the runner reports one, it first records the SHA-256 of the target binary in `<Dir>/hang.json` (detail to digest; restart-safe; a hang seen again records the newer binary). The finding closes only when a later fuzz step of that target stops within its bound and its exec count moves past the baseline, run from a binary whose digest differs from the recorded one: `Guard.CloseTarget` with a `Closure` of kind `step` (both digests and the counts), saved on the finding's evidence as not a replay, with the cleared text through S39. A good step of the same binary, or one with no trusted record (missing, or not a regular file) closes nothing. The step's output and `hang.json` sit where the child can write, as its corpus does (F3, F9): a child that can run code can forge them, so the binary rule rests on the release being read-only and release-listed (F7) and on the child not rewriting `hang.json` (P3-4b-3h-r2). | LOOP-9, LOOP-7 | If the closing evidence must not rest on the child's output, have the broker rerun the step itself under a separate uid. |
| F14 | **STATUS says when fuzzing makes no progress** (P3-4b-3r-pass; #560 Potency, L3 point 3). With targets configured, `Digest` adds "Loop 2: my fuzz self-tests have not run for N days." (hours under a day) once no fuzz step has completed for longer than `Recheck()`, and "Loop 2: one of my fuzz self-tests cannot run." once a target's step has errored on two of its turns in a row (a full cycle). A step completes when `Fuzz` returns with its context live and no error, a finding included; a preempted step is not progress. Neither line names a target. The clock starts when the source is built and is not saved, so a restart resets it. | LOOP-7, LOOP-9 | If boxes restart more often than `Recheck()` (10 h as wired), save the last completion time in loop7's state. |
| F15 | **The fuzz cache is bounded** (P3-4b-3r-confine). Before each fuzz step the runner prunes the target package's own cache (`CacheDir/fuzz/<pkg>/Fuzz*`, so not a nested package's such as `modem/at` under `modem`) to `CacheCap` (64 MiB), then all of `CacheDir/fuzz` to `CacheTotal` (512 MiB), removing the oldest files first by modification time. The engine regenerates what is lost by fuzzing again; 19 targets at 64 MiB would pass the box cap, which then prunes across packages. It never walks the targets' `testdata`, where crash inputs are evidence (F3, F9). One step can grow its package's cache past the cap until the next step: 30 s on one worker writes far less than the gap to the state disk's free space. | LOOP-1 | The caps bound the honest engine, not a hostile child, which can write without limit during its step: a disk quota for the fuzz user is release row P3-4b-3r-confine-r4 (Security R2 on #588). |
| F16 | **Root never works in the fuzz user's tree by path, nor while the user has a process** (L3 1 on #588). The jail's `State` (`/var/lib/agentos/loop7`) belongs to `agentos-fuzz`, so any path root resolves there could be a link the user planted. Every root-side file operation in it (`Load`'s seeding, the scratch directory's create, chown and removal, the corpus reads, the hang record's read, write and removal, the prune, `Own`) goes through an `os.Root` opened at `State` (or at `/` with no jail), which refuses to resolve a link out of it. Seeds are created `O_EXCL`, so a planted name stays as it is. `New` refuses a jail whose cache or target directories lie outside `State`. Root also never works there while a process of the user lives: `Own` and every run first, and every run last, kill the leaf (freeze it, SIGKILL every process in `cgroup.procs`, thaw, and wait until the kernel reports it empty; not `cgroup.kill`, after which CI's kernel kills a child started into the group by `CLONE_INTO_CGROUP` at once), so a child that leaves its process group (`setsid`) dies with its run and cannot race root's next path or fill the disk between steps (`TestAChildThatLeavesItsGroupDiesWithItsRun`). Each run gives its scratch directory and every directory above it in `State`, the cache included, to the user through the same `os.Root`, so on a fresh state the cache root creates for the first run is the user's (Security B3 on #588, `TestAJailedFuzzStepUsesItsCacheOnFirstBoot`). Inside `State`, `os.Root` still follows the user's links: root may write seeds or read inputs through a link to another target's directory, all of it the user's own tree. **Reads are bounded** (P3-4b-3r-confine-r5): a stored input is opened without blocking and refused before any read unless it is a regular file of at most 1 MiB (`inputCap`; Go's fuzz inputs are small, and the largest seed the repository ships is 543 bytes), then read through a limit of 1 MiB + 1, so one grown since the stat is refused too. A refused input is the target finding "a stored test input is too large to replay", which holds the target unfuzzed and resolves once a whole replay reads every input it names. A release seed is read within the same cap. A replay reads every input it names before reporting anything: one root cannot read in the tree (a link out of `State`, a FIFO) fails the round as the runner's error, never as a finding or a resolution. **Tests that pin each defence** (each fails with its defence reverted, P3-4b-3r-confine-r5): a link out of `State` at a target's directory, through `Load`'s seeding, a replay's reads and a fuzz step (`TestALinkOutOfTheStateIsNeverFollowed`; `input` reverted to a path read, or `seed` to `os.MkdirAll` and `os.OpenFile` on joined paths); `ownPath` through a link at or above its path (`TestOwnPathNeverChownsThroughALink`; `os.Chown` or `os.Lchown` on a joined path); the prune through a directory swapped after its walk (`TestThePruneRemovesNothingThroughALinkSwappedAfterItsWalk`, through the `pruneWalked` test seam; `os.Remove` on a joined path); the read caps (`TestAnOversizeInputIsReportedNotRead`, `TestAStoredFIFOIsNotRead`, `TestAnInputReadStopsAtTheCap`); a hang under the jail and leaf (`TestAJailedRepeatedHangRecordsTheNewerBuild`); and no `cgroup.kill` (`TestAJailedChildStartsAfterTheLeafIsEmptiedTwice`). | LOOP-7, ARC-2 | If `State`'s parent ever becomes writable by the user, `State` itself can be swapped for a link; open it from a root-owned parent with `O_NOFOLLOW`. |
