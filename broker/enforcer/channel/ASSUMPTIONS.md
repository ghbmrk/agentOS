# Enforcer channel: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice d, #3660).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-d-1 | **The safety-list table keys on the secure direction the signed policy names, not on a device class.** The policy (slice a) has `Everyday` and `Secure`, and no class field. So a safety-list device takes reads, plus exactly the verb its `Secure` names from the closed list `lock`, `shut`, `off`, `close`, `return-to-dock` (`Nameable`); any other name, or none, is reads only. A lock's lock and a drone's return therefore need the name too, which is stricter than NET-2 ("needs no naming"), never looser. What the channel cannot see is the class: that a camera, microphone, alarm, siren or sensor is never named `off`, or that primary heating or a sprinkler valve is never named at all. That check belongs where the naming loosening is rendered and signed (slice b, and the device-naming rows), and is raised as a release finding on the PR: a class field in the policy. | NET-2 Safety devices, Drones; NET-4 | With a class field, `Allowed` takes the class and the table adds a row per class; the tests' rows already name one device per class. |
| ENF-d-2 | **The text on a safety command is sent for every safety-list `off` and `shut` that the radio carried out.** NET-2 says heater off and valve shut. Without a class, a plug's or relay's off texts too: over-telling in the safe direction rather than a silent heater. A command the radio did not carry out sends no text; it is logged. | NET-2 Safety devices, Texts and calls | With a class field (ENF-d-1), only heaters and valves text. |
| ENF-d-3 | **Rate limits are token buckets per kind, and an empty bucket pauses the whole channel.** NET-2: "rate-limits them; a burst pauses the channel". The bucket is the rate limit; a request past it is the burst. Refused requests and malformed frames have their own bucket, so a core that keeps trying what the table refuses pauses quickly. The numbers (`DefaultLimits`) are set well above an honest core's pace and are a checkpoint, not a measurement; slice n measures them in VMs. The engine's per-device tightening limit (ENF-a-4) applies inside them and answers `RateLimited` without a pause. | NET-2 Channel, NET-4 Tightening | Numbers change in one table. |
| ENF-d-4 | **A pause refuses everything, heads included, and outlives reconnects; a restart keeps it only if the daemon does.** Only the authenticated core counts toward it: a hello that fails (another key, another connection's exporter, a revoked key, or a frame before any hello) is dropped and counted in its own `KindPreAuth` bucket, which never pauses and past which drops go unlogged after one line saying so (#3755). Reading and verifying the hello is cheaper than the TLS handshake the daemon already completed, so the channel does not shed connections before the hello; any per-source connection limit belongs in slice l's listener. One `Channel` serves every connection, so reconnecting does not unpause, and only `Resume`, which the page calls after the owner's passkey at home (slice b, NET-6), opens it. The kernel resends its latest head and the entries it holds after a resume (slice o). `Config.Paused` is the state the daemon persisted (slice l); the core cannot restart the enforcer. | NET-2 Channel, NET-6, STO-1 | If heads must flow while paused, the gate lets `KindHead` through on its own bucket. |
| ENF-d-5 | **The channel calls the engine under its own lock, and the daemon serialises the engine with the page.** `policy.Engine` is not safe for concurrent use; the channel holds one mutex for each request, and slice l gives the page and the channel one engine behind one lock. | ENF-a (Engine) | — |
| ENF-d-6 | **Any frame that does not decode ends the connection.** The codec never resynchronises, so a malformed frame cannot be followed by a smuggled one; the refusal is logged with fixed text and counted. A request that decodes but is not allowed gets a `Result` and the connection stays open. | NET-2 Channel ("parses them strictly") | — |
| ENF-d-7 | **Sinks run outside the channel's lock; the radio does not.** `Alerts` and `Answer` are queued under the lock and run after it, so slice h may send its text back through `Channel.Alert` from inside `SafetyOff` or `Paused`. `Radio.Do` and `Radio.State` run under the lock and on the connection's read loop, so they must not wait for a device challenge's answer, which arrives on that same loop: a read that needs the core's answer sends the challenge (`Channel.Challenge`), returns, and the radio host completes it when `Answer` delivers. | NET-2 Channel, Texts and calls; DEV-withings-ble part s | A radio that must block on an answer needs the read loop and the request handling split, a change to `Serve`. |
