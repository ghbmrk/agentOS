# Enforcer channel: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice d, #3660).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-d-1 | **The safety-list table keys on the device's class and the secure direction the signed policy names.** The policy records each safety-list device's `Class` (#3748), and refuses a `Secure` its class cannot be named for (`policy.Nameable`): a camera, microphone, alarm, siren or sensor gets no name, primary heating and a valve that feeds sprinklers, heating or a medical supply get none, and a device of unknown type gets none. `Allowed` checks the class again, so a device takes reads plus exactly the verb its `Secure` names from the closed list `lock`, `shut`, `off`, `close`, `return-to-dock` only when its class allows that name. A lock's lock and a drone's return still need the name, which is stricter than NET-2 ("needs no naming"), never looser. A garage door's condition for naming (obstruction reversal and a pre-close warning) is a qualification fact the policy does not record; the owner's signed diff names the class, and the check is the device-naming rows'. | NET-2 Safety devices, Drones; NET-4 | If a lock's lock must work unnamed, `Allowed` takes it from the class alone. |
| ENF-d-2 | **The text on a safety command is sent for a heater's `off` and a valve's `shut` that the radio carried out** (by class, #3748). An oven's, plug's or relay's off sends none, as NET-2 reads. A command the radio did not carry out sends no text; it is logged. | NET-2 Safety devices, Texts and calls | If a plug's named load is a heater (DEV-4), the naming records it as class heater. |
| ENF-d-3 | **Rate limits are token buckets per kind, and a burst of a request kind past its rate trips the core** (D-255, #4174). NET-2: "a message outside that format, or a burst past the rate, is a core trip at the enforcer". The bucket is the rate; a request past it is the burst, which `Cut.Trip` turns into KRN-12's core trip. The kernel checks every message against the same rates before sending (#4373), so only a kernel defect or a compromised core reaches one. Refusals have their own bucket (`KindRefused`) and no trip: the kernel cannot know before sending that a request will be refused (a device removed a moment earlier), so a trip there could cut an honest core. Past that bucket every request is refused `RateLimited` until it refills by itself, with no owner step and no state beyond the bucket, so it is a rate, never a de-facto trip (SPEC names only a malformed message and a burst past the rate as channel trips). A `Paused` answer is not counted as a refusal, since a kernel learns of a trip only from one. The numbers (`DefaultLimits`) are set well above an honest core's pace and are a checkpoint, not a measurement; slice n measures them in VMs. The engine's per-device tightening limit (ENF-a-4) applies inside them and answers `RateLimited` with neither. | NET-2 The channel, NET-4 Tightening, D-255 | Numbers change in one table, which moves to the shared format definition with #4373. |
| ENF-d-4 | **A trip refuses everything, heads included, and outlives reconnects; the hello still connects.** After a core trip (`Cut.Stage` is `Tripped`) every request is answered `Paused` and logged, and the hello, which carries KRN-12's heartbeat, still opens a connection; at the "core reflashed" step (`Reflashed`) the traffic summaries act again, so the restore's capped backup route has a fresh count, and commands, tightenings, other reads and the core's records wait for the passkey restore, which returns the stage to `Open` (D-260, D-262). A request paused by a trip trips nothing more. The stage is the cut's (DECOY-d), never the channel's, so the page's two steps lift it in one place and it survives a restart there; the channel has no pause of its own for the owner to lift. Only the authenticated core counts toward a trip: a hello that fails (another key, another connection's exporter, a revoked key, or a frame before any hello) is dropped and counted in its own `KindPreAuth` bucket, which never trips and past which drops go unlogged after one line saying so (#3755). Reading and verifying the hello is cheaper than the TLS handshake the daemon already completed, so the channel does not shed connections before the hello; any per-source connection limit belongs in slice l's listener. The kernel resends its latest head and the entries it holds after a restore (slice o). The core cannot restart the enforcer, and a restart refills the rates. | NET-2 Channel, KRN-12 Response, NET-6, STO-1, D-260, D-262 | If heads must flow while tripped, the gate lets `KindHead` through on its own bucket. |
| ENF-d-5 | **The channel calls the engine under its own lock, and the daemon serialises the engine with the page.** `policy.Engine` is not safe for concurrent use; the channel holds one mutex for each request, and slice l gives the page and the channel one engine behind one lock. | ENF-a (Engine) | — |
| ENF-d-6 | **Any frame that does not decode ends the connection, and one from the authenticated core trips it.** The codec never resynchronises, so a malformed frame cannot be followed by a smuggled one; the refusal is logged with fixed text. A frame outside the format definition (`wire.ErrType`, `ErrLength` or `ErrPayload`: an unknown or misdirected type, a second hello, a length out of bounds, a value off a closed list, trailing bytes) is a core trip (NET-2, D-255). A stream that ends mid-frame (`wire.ErrShort`) is a lost connection, not a message, so it only ends the connection; the revoked-key refusal ends it too, counted as a refusal. A request that decodes but is not allowed gets a `Result` and the connection stays open. | NET-2 The channel ("parses them strictly", "a message outside that format ... is a core trip") | — |
| ENF-d-7 | **Sinks run outside the channel's lock; the radio does not.** `Alerts`, `Answer` and `Cut.Trip` are queued under the lock and run after it, so slice h may send its text back through `Channel.Alert` from inside `SafetyOff` or a trip; `Cut.Stage` runs under the lock and must not call the channel. `Radio.Do` and `Radio.State` run under the lock and on the connection's read loop, so they must not wait for a device challenge's answer, which arrives on that same loop: a read that needs the core's answer sends the challenge (`Channel.Challenge`), returns, and the radio host completes it when `Answer` delivers. | NET-2 Channel, Texts and calls; DEV-withings-ble part s | A radio that must block on an answer needs the read loop and the request handling split, a change to `Serve`. |
| ENF-d-8 | **The log names a device only by an ID the signed policy holds; any other name the core sends is logged as `unknown` and its SHA-256** (#3758). `wire.Name` and `policy.name` already refuse separators, every control and the format characters that reorder text (#3901), so a frame carrying one ends the connection unlogged; the hash also keeps a well-formed name the owner never signed, such as `resumed-by-the-owner`, out of the owner's record. Names are read against the policy before the request acts, so a removed device is logged by its ID. A pair's members are each named this way, each in its own field (`Device`, `Other`), since a signed ID may hold a comma or any other separator a joined string would use (#4066). The owner's log line is `Event.Line`, which shows every name through `Short`, `unknown` and 12 hex digits of its hash for an unknown one (enough to tell repeated unknown names apart), and both of a pair's members split by ` / `; `Event.Detail` is the same line with the full hash (#4185). Neither carries a time: slice l's renderer shows `Event.At` in the enforcer's configured zone, the same `Config.Zone` the page takes, so the owner's log never shows UTC (NET-4). The word `unknown` is no signed ID or channel name in any case (`policy.Unknown`), so a signed device never reads as the marker; `TestReservedWord` ties `wire.Name`'s copy of the word to it (#4249). A lookalike such as `unknоwn` (Cyrillic о) is not refused: only the owner can sign one, and it shows as itself, one token with no space, so it never takes the marker's two-part `unknown` and hex form. A core that grinds two names to the same 12 digits only makes two of its own attempts look alike on that line. Hosts and rule names are not logged. | NET-2 Channel, Texts and calls | If a host or rule name is ever logged, it goes through the same check against the policy. |
