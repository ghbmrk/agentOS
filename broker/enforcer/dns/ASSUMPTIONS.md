# Enforcer resolver: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice f, #3664).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-f-1 | **Three dnsmasq instances, split by who may resolve what.** *Listed* answers the core's segment and every Devices VLAN and resolves only names on a list; *people* answers Owner, Household, Guests and the admin port with any name and fills no set (those networks reach the internet anyway, NET-3); *DHCP* (`port=0`) serves leases only. dnsmasq has no per-client views, so one instance cannot both refuse unlisted names to devices and answer them for people. Three instances bind the same ports on different interfaces' own addresses (`bind-dynamic`); DHCP shares one wildcard socket in the DHCP instance alone. | NET-2 Hardening, The core's list, NET-3 | A per-device instance would also keep one device from resolving another's names (ENF-f-4). |
| ENF-f-2 | **A listed name matches exactly.** dnsmasq's `server=/name/` also matches every subdomain, so each name gets `local=/*.name/`, which answers its subdomains NXDOMAIN and never forwards them; a listed subdomain of a listed name still wins, since dnsmasq takes the longest match (checked in `TestOnlyResolvedAddressesAllowed` with `updates.core.example`). A subdomain therefore never fills a set and is no DNS tunnel. Names must be lower-case LDH host names (`Hostname`); any other name in a list refuses the whole version, which slice l must compile before the owner signs it, as for the ruleset (ENF-e-9). | NET-2 The core's list, NET-3 | A list that needs a wildcard needs a field in the document saying so, signed as a loosening. |
| ENF-f-3 | **Answers fill sets; they never expire on their own.** dnsmasq's `nftset=` adds every address in an answer to a query for the name, CNAME targets included, to every set whose list names it. It passes no TTL, and adding an element that is already in a set does not refresh its timeout (measured with dnsmasq 2.91 and nft 1.0.9), so a set timeout would drop a device that keeps resolving, mid-TTL. An address therefore stays until the next ruleset load empties the sets (ENF-e-3). The listed instance keeps no cache (`cache-size=0`), so every answer is fresh and refills the sets, and caps the TTL it hands out at 5 minutes (`max-ttl=300`), so after a load a device re-resolves within 5 minutes. | NET-2 The core's list ("only the addresses … that answer returns"), NET-1 | A resolver that passes TTLs (or a dnsmasq that refreshes timeouts) would let the sets expire. Slice l may re-add live entries after a load. |
| ENF-f-4 | **A device can resolve any listed name; only its own list's answers open its path.** One listed instance serves all devices and the core, so a device that asks for another list's name gets the answer, and the answer fills that list's set, never the asker's. The leak is that a device learns other lists' addresses, and its queries for listed names reach the enforcer's upstream. A device with no internet (no vendor cloud, isolated) has no set, so its list is never written and its names are REFUSED. | NET-3 Devices (default-deny per device), NET-1 | Per-device instances (ENF-f-1). |
| ENF-f-5 | **The setup is the enforcer's own.** The upstream resolvers, each network's prefix and the lease file come from the image and setup (`Setup`), like `nft.Layout`. DHCP runs only on the Owner, Household, Guests, admin and core interfaces and on device VLANs; the edge's segment, the WAN and the access point's management interface are refused, and no instance ever names them, so the edge's segment hears no DNS or DHCP even with no ruleset loaded (`TestNoServiceOnEdge`). Every instance excludes loopback and binds only its interfaces' own addresses. Upstreams must be global; `stop-dns-rebind` drops any answer into a private block. An off-path forger of upstream answers is the usual DNS risk (dnsmasq randomises port and ID); one on a served segment is dropped by the ruleset's reverse-path filter (ENF-e-11), since the upstream is routed only through the WAN. | NET-2 Segments, Hardening | — |
| ENF-f-6 | **Devices' port-53 traffic is the enforcer's.** The ruleset redirects any TCP or UDP port-53 packet from the device trunk to the enforcer (`dns_redirect`), so a device that ignores its DHCP resolver gets the listed instance anyway; DNS over TLS (853) and the known encrypted-DNS resolvers stay blocked (ENF-e-8). | NET-3 ("redirects other port-53 traffic to itself") | — |
| ENF-f-7 | **No query is logged.** No instance sets `log-queries`, so Guests' and Household's lookups are not observed. | NET-1, NET-3 | Slice i's traffic summaries read nft's log, not DNS. |
| ENF-f-8 | **The tests run dnsmasq in debug mode.** In a user namespace dnsmasq cannot change user, so the netns tests start it with `-d` (foreground, no user change); the generated files hold no user or pid-file lines, which the daemon (slice l) and image (slice m) choose. CI installs `dnsmasq-base` (the binary, no service). | — | — |
