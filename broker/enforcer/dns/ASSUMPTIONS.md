# Enforcer resolver: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice f, #3664).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-f-1 | **dnsmasq instances split by who may resolve what.** *Listed* views, one per interface: one answers the core's segment with the core's list, and one each Devices VLAN with that device's list (ENF-f-4); *people* answers Owner, Household, Guests and the admin port with any name and fills no set (those networks reach the internet anyway, NET-3); *DHCP* (`port=0`) serves leases only. dnsmasq has no per-client views, so a view is an instance. The instances bind the same ports on different interfaces' own addresses (`bind-dynamic`); DHCP shares one wildcard socket in the DHCP instance alone. A home of n devices with VLANs runs n+3 instances, each a few hundred KiB; the daemon (slice l) starts one per `Files.Listed` entry. Reuse: unbound and Knot have per-client views but no nft set fill, so dnsmasq stays. | NET-2 Hardening, The core's list, NET-3 | — |
| ENF-f-2 | **A listed name matches exactly.** dnsmasq's `server=/name/` also matches every subdomain, so each name gets `local=/*.name/`, which answers its subdomains NXDOMAIN and never forwards them; a listed subdomain of a listed name still wins, since dnsmasq takes the longest match (checked in `TestOnlyResolvedAddressesAllowed` with `updates.core.example`). A subdomain therefore never fills a set and is no DNS tunnel. Names must be lower-case LDH host names (`Hostname`); any other name in a list refuses the whole version, which slice l must compile before the owner signs it, as for the ruleset (ENF-e-9). | NET-2 The core's list, NET-3 | A list that needs a wildcard needs a field in the document saying so, signed as a loosening. |
| ENF-f-3 | **Answers fill sets; they never expire on their own.** dnsmasq's `nftset=` adds every address in an answer to a query for the name, CNAME targets included, to the view's own set. It passes no TTL, and adding an element that is already in a set does not refresh its timeout (measured with dnsmasq 2.91 and nft 1.0.9), so a set timeout would drop a device that keeps resolving, mid-TTL. An address therefore stays until the next ruleset load empties the sets (ENF-e-3). No listed view keeps a cache (`cache-size=0`), so every answer is fresh and refills the set, and each caps the TTL it hands out at 5 minutes (`max-ttl=300`), so after a load a device re-resolves within 5 minutes. | NET-2 The core's list ("only the addresses … that answer returns"), NET-1 | A resolver that passes TTLs (or a dnsmasq that refreshes timeouts) would let the sets expire. Slice l may re-add live entries after a load. |
| ENF-f-4 | **A device resolves only its own list.** Each listed view forwards only its own list's names and fills only its own set, so a device that asks for another list's name, or the core's, gets REFUSED: it never learns that list's addresses, its query never reaches the upstream, and it fills no other set (`TestViewsAreOwnLists`, `TestOnlyResolvedAddressesAllowed`). Two places hold this apart: the ruleset redirects every port-53 packet from the trunk to the arrival interface's own address (ENF-f-6), so a device asking another view's address reaches its own; and dnsmasq answers only queries that arrive on its own interface, even with no ruleset loaded (measured: the kernel delivers the packet, dnsmasq stays silent; `TestNoServiceOnEdge`). A device with no internet (no vendor cloud, isolated) has a view with no names, which refuses every query. Two lists that name the same name resolve it separately, each filling its own set. | NET-3 Devices (default-deny per device), NET-1 | — |
| ENF-f-5 | **The setup is the enforcer's own.** The upstream resolvers, each network's prefix and the lease file come from the image and setup (`Setup`), like `nft.Layout`. DHCP runs only on the Owner, Household, Guests, admin and core interfaces and on device VLANs; the edge's segment, the WAN and the access point's management interface are refused, and no instance ever names them, so the edge's segment hears no DNS or DHCP even with no ruleset loaded (`TestNoServiceOnEdge`). Every instance excludes loopback and binds only its interfaces' own addresses. Upstreams must be global and outside every served prefix (an IPv6 one included), so the upstream is never on a served segment; `stop-dns-rebind` drops any answer into a private block. An off-path forger of upstream answers is the usual DNS risk (dnsmasq randomises port and ID); one on a served segment is dropped by the ruleset's reverse-path filter (ENF-e-11), since the upstream is routed only through the WAN. | NET-2 Segments, Hardening | — |
| ENF-f-6 | **Devices' port-53 traffic is the enforcer's.** The ruleset redirects any TCP or UDP port-53 packet from the device trunk to the enforcer (`dns_redirect`), so a device that ignores its DHCP resolver gets the listed instance anyway; DNS over TLS (853) and the known encrypted-DNS resolvers stay blocked (ENF-e-8). | NET-3 ("redirects other port-53 traffic to itself") | — |
| ENF-f-7 | **No query is logged.** No instance sets `log-queries`, so Guests' and Household's lookups are not observed. | NET-1, NET-3 | Slice i's traffic summaries read nft's log, not DNS. |
| ENF-f-8 | **The tests run dnsmasq in debug mode.** In a user namespace dnsmasq cannot change user, so the netns tests start it with `-d` (foreground, no user change); the generated files hold no user or pid-file lines, which the daemon (slice l) and image (slice m) choose. CI installs `dnsmasq-base` (the binary, no service). | — | — |
