# Enforcer resolver: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice f, #3664).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-f-1 | **dnsmasq instances split by who may resolve what.** *Listed* views, one per interface: one answers the core's segment with the core's list, and one each Devices VLAN with that device's list (ENF-f-4); *people* answers Owner, Household, Guests and the admin port with any name and fills no set (those networks reach the internet anyway, NET-3); *DHCP* (`port=0`) serves leases only. dnsmasq has no per-client views, so a view is an instance. The instances bind the same ports on different interfaces' own addresses (`bind-dynamic`); DHCP shares one wildcard socket in the DHCP instance alone. A home of n devices with VLANs runs n+3 instances, each a few hundred KiB; the daemon (slice l) starts one per `Files.Listed` entry. Reuse: unbound and Knot have per-client views but no nft set fill, so dnsmasq stays. | NET-2 Hardening, The core's list, NET-3 | — |
| ENF-f-2 | **A listed name matches exactly.** dnsmasq's `server=/name/` also matches every subdomain, so each name gets `local=/*.name/`, which answers its subdomains NXDOMAIN and never forwards them; a listed subdomain of a listed name still wins, since dnsmasq takes the longest match (checked in `TestOnlyResolvedAddressesAllowed` with `updates.core.example`). A subdomain therefore never fills a set and is no DNS tunnel. Names must be lower-case LDH host names (`Hostname`); any other name in a list refuses the whole version, which slice l must compile before the owner signs it, as for the ruleset (ENF-e-9). | NET-2 The core's list, NET-3 | A list that needs a wildcard needs a field in the document saying so, signed as a loosening. |
| ENF-f-3 | **Answers fill sets; the ruleset expires them.** dnsmasq's `nftset=` adds every address in an answer to a query for the name, CNAME targets included, to the view's own allow set, to the name's own set there (nft ENF-set-keep-1) and to the view's fresh set (nft ENF-set-ttl-1). It passes no TTL, and adding an element that is already in a set does not refresh its timeout (measured with dnsmasq 2.91 and nft 1.0.9), so no set the resolver fills can hold an answer's own expiry: the daemon's `nft.Refresh` step moves each fresh answer into a recent set with a full `nft.AnswerTimeout`, which takes new connections (the fresh set's own `nft.AnswerTimeout`, counted from an answer's first add, ends one no step moves, nft ENF-set-ttl-1), so an address no answer returned for that long takes none, and a device that keeps resolving is never dropped. `nft.AnswerTimeout` is at least twice `MaxTTL` (a compile-time check), so a device that dials within its answer's TTL, or retries for as long again, connects. The allow and name sets keep an address while its name stays listed, for the connections already open to it: a ruleset load keeps it (`nft.Reload`) and drops it only with its name. No listed view keeps a cache (`cache-size=0`), so every answer is fresh, and each caps the TTL it hands out at 5 minutes (`max-ttl=300`). | NET-2 The core's list ("only the addresses … that answer returns"), NET-1 | A resolver that passes TTLs could set each answer's own expiry. |
| ENF-f-4 | **A device resolves only its own list.** Each listed view forwards only its own list's names and fills only its own set, so a device that asks for another list's name, or the core's, gets REFUSED: it never learns that list's addresses, its query never reaches the upstream, and it fills no other set (`TestViewsAreOwnLists`, `TestOnlyResolvedAddressesAllowed`). Two places hold this apart: the ruleset redirects every port-53 packet from the trunk to the arrival interface's own address (ENF-f-6), so a device asking another view's address reaches its own; and dnsmasq answers only queries that arrive on its own interface, even with no ruleset loaded (measured: the kernel delivers the packet, dnsmasq stays silent; `TestNoServiceOnEdge`). Both hold over UDP and TCP, and over IPv6 at another view's global and link-local addresses; the tests send a link-local query to the enforcer's end of the asker's own link (a pinned neighbour entry, since the enforcer answers no neighbour solicitation for another link's address), and count every query arriving there, so no expected silence is a packet never sent (#4221); the IPv6 checks run in CI, whose kernel has IPv6, and fail there without it. A device with no internet (no vendor cloud, isolated) has a view with no names, which refuses every query. Two lists that name the same name resolve it separately, each filling its own set. | NET-3 Devices (default-deny per device), NET-1 | — |
| ENF-f-5 | **The setup is the enforcer's own.** The upstream resolvers, each network's prefix and the lease file come from the image and setup (`Setup`), like `nft.Layout`. `Setup.Nets` names every interface an instance answers on, with or without DHCP, and the prefixes of every address the enforcer holds there; a setup that leaves one out is refused, so every served prefix reaches the upstream check (`TestUpstreamOnEveryServedNet`). Slice l assigns each served interface exactly its `Net`'s addresses (and the kernel its link-local one). The daemon turns router advertisements and redirects off on every served interface and checks their addresses at every load and reading, and runs no instance while one is outside its `Net` (daemon ENF-l-21, #4222), so no other prefix or route appears there even with no ruleset loaded; with one loaded, the ruleset also drops router advertisements except from the WAN (ENF-e). DHCP runs only on the networks marked, each the Owner, Household, Guests, admin or core interface or a device VLAN, and a setup that marks none is refused, since an instance with no `interface=` line would listen on every interface but loopback (`TestGenerateRefuses` "no DHCP"); the edge's segment, the WAN and the access point's management interface are refused, and no instance ever names them, so the edge's segment hears no DNS or DHCP even with no ruleset loaded (`TestNoServiceOnEdge`). Every instance excludes loopback and binds only its interfaces' own addresses. Upstreams must be global and outside every served prefix (an IPv6 one included), so the upstream is never on a served segment; `stop-dns-rebind` drops any answer into a private block. An off-path forger of upstream answers is the usual DNS risk (dnsmasq randomises port and ID); one on a served segment is dropped by the ruleset's reverse-path filter (ENF-e-11), since the upstream is routed only through the WAN. | NET-2 Segments, Hardening | An interface with several IPv6 prefixes needs `Net.Prefix6` to become a list. |
| ENF-f-6 | **Devices' port-53 traffic is the enforcer's.** The ruleset redirects any TCP or UDP port-53 packet from the device trunk to the enforcer (`dns_redirect`), so a device that ignores its DHCP resolver gets the listed instance anyway; DNS over TLS (853) and the known encrypted-DNS resolvers stay blocked (ENF-e-8). | NET-3 ("redirects other port-53 traffic to itself") | — |
| ENF-f-7 | **No query is logged.** No instance sets `log-queries`, so Guests' and Household's lookups are not observed. | NET-1, NET-3 | Slice i's traffic summaries read nft's log, not DNS. |
| ENF-f-8 | **The tests run dnsmasq in debug mode.** In a user namespace dnsmasq cannot change user, so the netns tests start it with `-d` (foreground, no user change); the generated files hold no user or pid-file lines, which the daemon (slice l) and image (slice m) choose. CI installs `dnsmasq-base` (the binary, no service). | — | — |
| ENF-f-9 | **The daemon's runner keeps the instances in step with the firewall** (`run`, slice l, #4464). Each instance is a child of the daemon: `dnsmasq --keep-in-foreground --pid-file= --conf-file=F`, an empty environment, the daemon's own user (dnsmasq changes user only when started as root, and the daemon refuses root), F a file per content in a directory only the daemon reaches. `Apply` stops every instance whose file changes and waits for it to exit (SIGTERM, then SIGKILL after 5 s), then loads the ruleset, then starts the new files; an unchanged instance keeps running, since its names' sets survive the load (nft ENF-set-keep-1). A refused load starts the stopped instances on their previous files, which match the ruleset still in force. `Apply` returns the load's error alone: an instance that fails to start, or exits on its own, is logged and started again on its file in force after 1 s, doubling to 30 s, so a start failure never reads as a refused load and the daemon's view of the loaded document stays the kernel's (L3 6655898360). A restart whose file is no longer in force never runs. An empty file is never run (`Names` leaves it out), since dnsmasq on an empty file answers and forwards every name on every interface; `dns.Files{}` stops every instance. Each instance is its own process group, and a stop signals the group and then kills what is left of it, so no TCP child of an old list outlives its parent; `Pdeathsig` kills the instances if the daemon dies, and the service manager's cgroup stops them with it. A new process-starting package, beside nft/load and radio/confine (arc2 `enforcerExec`): the daemon may not start processes itself, and confine's empty network namespace cannot serve the box's segments. | NET-2 The core's list, NET-3 | A dnsmasq that reloads its list on a signal would let the runner reconfigure in place instead of restarting. |
| ENF-f-10 | **An instance that keeps exiting is not a running one** (`Flapping`, #5164 R5 b). The runner counts each instance's exits of its own in a row on its file in force; an exit after its process ran `StayUp` (30 s, the longest wait before a restart) starts the count again, and a new file clears it. `Flapping` names every instance that has exited and not stayed up `StayUp` since, with its count, so a crash loop, which is up between its exits, never reads as running. It takes only the runner's lock, never one a load holds. | NET-2 The core's list | A shorter `StayUp` hides a loop slower than it; a longer one shows an instance that recovered as flapping for longer. |
