# Enforcer channel wire: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice d, #3660).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-d-w1 | **Mutual authentication is a signed hello inside TLS, bound to the connection's exporter.** Each end signs `DomainHello ‖ role ‖ exporter` with its Ed25519 channel key, and the other end checks it against the key it pinned, as the edge link's hello does (`broker/kernel/edge.go`). The wire takes the 32 exporter bytes (`ExporterLabel`) and does no TLS itself: `crypto/tls` is forbidden in the enforcer's links (`arc2_test.go`), so the daemon (slice l) and the kernel's client (slice o) run TLS and pass the exporter. A hello replayed on another connection, for the other role, or under another key fails. | NET-2 Channel ("share no secret"), DEV-2, KEY-7 | If either end stops running TLS, the hello still authenticates the start but not the frames after it; the transport would then need its own MAC. |
| ENF-d-w2 | **The core's records that are not requests travel on the channel too.** NET-2 names three kinds of message that act: device commands, tightenings, reads. Slices h and o also need the core to send each log head and key-change or erase entry for the enforcer to anchor (STO-1, KEY-7), to announce a proposal link it texted so the enforcer counts it (NET-2: "proposal links are rate-limited the same way"), and to answer a device challenge; the enforcer sends results, read replies, challenges and alerts back. None of them changes a rule or moves a device. An entry's body is opaque here and is parsed by the head-copy store (slice h). | NET-2 Channel, Texts and calls, STO-1 | A reading that the channel carries nothing but the three kinds moves heads and alerts to a second connection with its own schema. |
| ENF-d-w3 | **No verb exists for an unlock, disarm, arm, open or turn-on.** The verb list is NET-2's everyday commands (on, off, level, lock) and the named secure directions (shut, close, return to dock). Relock is lock again. | NET-2 Channel, Safety devices, Drones; NET-6 | A new everyday verb is a wire change both ends take, and a row in `channel.TestSafetyListTable`. |
| ENF-d-w4 | **Caps.** A name is at most 253 bytes (the policy's limit), an entry 4096 bytes, an alert 1024 bytes, a read reply 1 MiB, which bounds the policy export the core can back up through one read. The challenge frame's data area is 64 bytes, enough for the BLE challenge-response DEV-withings-ble part s describes. | NET-2 Channel ("fixed-length frame"), NET-2 Recovery | An export over 1 MiB fails its read with `Failed`; it would then need paging, a new read field. |
| ENF-d-w5 | **One summary interval, set here: a minute, and one cap edge** (`SummaryInterval`, `PastCap`, #4173). A count at its cap is not past it; the enforcer drops and trips past it and the kernel stops short of it with the same function, so the two cannot disagree by a byte. NET-2 says the format definition sets the interval between traffic summaries but gives no value. A minute keeps a summary read far inside the read rate and lets the kernel's fresh-count bound (twice the interval, `broker/kernel/capgate`) refuse capped sends for at most two minutes after the enforcer goes quiet. The kernel and the enforcer read this one constant; neither holds a copy. | NET-2 The channel, Byte caps; D-255 | A shorter interval costs more reads; a longer one keeps a stale count usable longer, so the kernel refuses later when the enforcer is down. Change it here and both sides follow. |
