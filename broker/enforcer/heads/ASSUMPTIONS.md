# Enforcer head copies and revocation set: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice h, #3666).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-h-1 | **The owner revokes the kernel's sub-key on the enforcer with the enforcer passkey, as a `key.Root{Clerk: "enforcer", Serial: "revoke/<hex key>"}` assertion.** A stolen core will not forward its own revocation, so the enforcer cannot wait for a kernel log entry; the revocation reuses brief decision 2's shape (an owner ES256 assertion over `key.RootMsg`, checked by `broker/kernel/key`), adds no verb, caveat or domain, and its serial cannot match a policy version's. The page that collects it is slice b's or l's, and the caller passes the enrolled passkey as `owner`, as `policy.Verify` takes it; slice l may pin it in `Config` when it wires enrolment. | STO-4 (stolen core), KEY-6, KEY-7 | If the kernel instead logs a sub-key revocation entry, add its type to `kept` and fold it in `apply`; the owner path stays, since it does not need the core. |
| ENF-h-2 | **Entries are the kernel's log entry JSON (`broker/kernel.Entry`), byte for byte, from a closed list of types:** `key.issued` (v2), `key.revoked`, `key.paused`, `key.resumed`, `passkey.enrolled`, `passkey.revoked`, `edge.enrolled`, `edge.revoked`, `subject.erased`, `erase.confirmed`. Any other type is refused; an entry not in its one encoding is refused. The wire entry's ID is the channel's request id, not the seq. Slice o sends exactly these. | STO-1, KEY-7, LOG-4, LOG-5 | A new key-change or erase type in the kernel is one line in `kept` (and `body`/`apply` if it changes the set). |
| ENF-h-3 | **Entries are kept as the authenticated core sends them; a head authenticates an entry only where the two meet.** The kernel signs a head at each anchoring, not each entry, so an entry is checked against a head at its seq and the entries either side of it when the store holds them, and is otherwise taken on the channel's authentication. A forged revocation can only refuse; a forged resume lifts a pause in this set only, never a revocation, which is final. | STO-1, KEY-7, NET-2 Channel | If slice o anchors after every key-change entry, require a head at each entry's seq. |
| ENF-h-4 | **Heads only rise.** A new head below the newest held, or a different head or entry at a seq held, is a fork: refused, reported through `Config.Fork` (the daemon raises alert `HeadFork`), and never kept over what is held. Resends are no change. The rollback check itself is the kernel's at boot against `Latest` (STO-1); this store's part is not forgetting. Accepting a new branch after a legitimate restore from an older backup or a replaced core, on the owner's choice, is the STO-1 recovery flow's or DECOY-d's, not this slice's. | STO-1 | If the kernel can legitimately resend an older unseen head, keep it as a gap fill only when it chains, which needs the entries between. |
| ENF-h-5 | **The journal is append-only, one JSON line per change, and is the enforcer's own disk.** Open replays it without re-verifying signatures. A last line with no newline is a torn append, never acknowledged: Open cuts it with `Truncate`, as the kernel's log does, so the next append starts clean; any other bad line refuses to open. Every head is kept forever: about 200 bytes each, and the channel rate-limits heads (slice d). | STO-1, P5 | If the disk bound bites, slice l rotates the journal into a snapshot. |
| ENF-h-6 | **`Trip` stops the store keeping anything, persisted; DECOY-d calls it on a core trip and owns lifting it.** | STO-1 ("keeps none after a core trip"), KRN-12 | DECOY-d decides whether a reflashed core's heads start a fresh store. |
| ENF-h-7 | **The revocation set answers the channel's `Revoked` for Ed25519 keys (owner-revoked sub-keys and logged edge keys), plus `RevokedPasskey`, `RevokedID` (any ID on a key's chain) and `Paused` for later enforcer key checks.** The channel pins one core key at enrolment (slice c); re-pinning a new core's sub-key is enrolment's. | KEY-7, STO-4 | |
