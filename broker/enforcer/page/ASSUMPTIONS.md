# Enforcer page: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice b, #3659).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-b-1 | **A proposal link carries the next document whole** (`/p?d=<base64url canonical JSON>`, optional `s=<summary>`). The page never shows `s` or the link's version: it draws the diff from the policy in force and the link's document (`Describe`), and the diff it signs is that text, prefixed with the consequence. Every core-chosen name is shown in printable ASCII, quoted with escapes otherwise, so a bidi override cannot reorder a line. A link that changes nothing is refused. | NET-4 Loosening ("renders the change itself"), Passkey rules | A link that carries an op instead of a document needs a parser here; the signed diff stays the page's text. |
| ENF-b-2 | **The page picks each version**: one above the policy in force, the waiting loosening and the last version it drew, and at least the clock's milliseconds. The engine does not expose `Spent`, so after a restart the clock keeps versions above any spent one; if the clock is behind, a tap fails as not rising, the page's floor climbs, and the next link works. | NET-2 Recovery (versions only rise) | If `policy.Engine` exposes `Spent`, use it as the floor and drop the clock. |
| ENF-b-3 | **A tap is refused if the policy moved after its screen was drawn** (`errMoved`): the challenge records the hash of the policy in force and `approve` compares it under the lock. Without it, approving a document drawn before a channel tightening would undo that tightening while the screen showed only the addition. | NET-4 Passkey rules ("an assertion approves only that diff") | — |
| ENF-b-4 | **Cancelling a pending loosening and resuming the channel each need a tap**, over `DomainAct ‖ action ‖ target ‖ challenge ID`, once. Being on the Owner network authorises nothing by itself. | NET-4 Passkey rules, NET-6 | — |
| ENF-b-5 | **"Synced" is the BE flag** (backup eligible) of the last verified assertion; until one arrives the page says it does not know yet. It is held in memory. | NET-4 Passkey rules ("shows the owner whether their passkey is synced") | Slice c can record it at enrolment, so it is known from the start. |
| ENF-b-6 | **Home only is three checks**: `Listen` binds only `Config.Addrs` (the Owner VLAN and admin port addresses; an unspecified address or one outside `Allow` is refused), `Serve` closes any connection from outside `Allow` before the TLS handshake, and the handler aborts any request from outside `Allow`. Interface names and VLAN binding are slice l's. | NET-6 | — |
| ENF-b-7 | **Cross-origin and framing**: every answer sets `frame-ancestors 'none'` and `X-Frame-Options: DENY`; a request the browser marks as a frame load, or a cross-site non-navigation load, is refused; a POST must carry `Origin: https://<name>`, not be marked cross-site, and be JSON; the Host must be the enforcer's name (DNS rebinding). Opening a link from a text is a cross-site navigation and is allowed. | NET-4 Owner's surface ("agentOS never renders, frames or relays that screen") | — |
| ENF-b-8 | **The certificate is a root with a critical name constraint to the enforcer's name**, and a leaf under it (`NewCert`); the phone trusts only that root. The root lasts 10 years; each leaf 397 days, inside Apple's 825-day cap that holds even under an owner-installed root, and `Cert.Renew` reissues it under the same root in its last 30 days (L3 on #3746). Keeping the root key in the sealed store, calling `Renew` daily and serving the root at enrolment are slices l and c. | NET-4 Passkey rules ("a certificate limited to the enforcer's own local name") | — |
| ENF-b-9 | **NET-1's limits are SPEC's sentences** with SPEC's markup (`[Fact]`, backticks) removed; `TestLimitsWordingAndLabels` reads SPEC.md, so a SPEC change fails it until `Limits` follows. Device labels come from `policy.Device.Label` (added here; ENF-a-8 asks the slice that adds a field to add its classify row). | NET-1 | — |
| ENF-b-10 | **Rate limits** are 10 proposal links a minute and 16 live challenges of 5 minutes each, counted for the whole page. NET-4 asks for refusal of rate-limited links but gives no number. | NET-4 | Slice d measures the core's real link rate. |
