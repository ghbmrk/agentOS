# Enforcer page: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice b, #3659).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-b-1 | **A proposal link carries the next document whole** (`/p?d=<base64url canonical JSON>`, optional `s=<summary>`). The page never shows `s` or the link's version: it draws the diff from the policy in force and the link's document (`Describe`), and the diff it signs is that text, prefixed with the consequence. Every core-chosen name is shown in printable ASCII, quoted with escapes otherwise, so a bidi override cannot reorder a line. A link that changes nothing is refused. | NET-4 Loosening ("renders the change itself"), Passkey rules | A link that carries an op instead of a document needs a parser here; the signed diff stays the page's text. |
| ENF-b-2 | **The page picks each version**: one above the policy in force, the waiting loosening and the last version it drew, and at least the clock's milliseconds. The engine does not expose `Spent`, so after a restart the clock keeps versions above any spent one; if the clock is behind, a tap fails as not rising, the page's floor climbs, and the next link works. | NET-2 Recovery (versions only rise) | If `policy.Engine` exposes `Spent`, use it as the floor and drop the clock. |
| ENF-b-3 | **A tap is refused if the policy moved after its screen was drawn** (`errMoved`): the challenge records the hash of the policy in force and `approve` compares it under the lock. Without it, approving a document drawn before a channel tightening would undo that tightening while the screen showed only the addition. | NET-4 Passkey rules ("an assertion approves only that diff") | — |
| ENF-b-4 | **Cancelling a pending loosening and resuming the channel each need a tap**, over `DomainAct ‖ action ‖ target ‖ challenge ID`, once. Being on the Owner network authorises nothing by itself. | NET-4 Passkey rules, NET-6 | — |
| ENF-b-5 | **"Synced" is the BE flag** (backup eligible) of the last verified assertion; until one arrives the page says it does not know yet. It is held in memory. | NET-4 Passkey rules ("shows the owner whether their passkey is synced") | Slice c can record it at enrolment, so it is known from the start. |
| ENF-b-6 | **Home only is three checks**: `Listen` binds only `Config.Addrs` (the Owner VLAN and admin port addresses; an unspecified address or one outside `Allow` is refused), `Serve` closes any connection from outside `Allow` before the TLS handshake, and the handler aborts any request from outside `Allow`. Interface names and VLAN binding are slice l's. | NET-6 | — |
| ENF-b-7 | **Cross-origin and framing**: every answer sets `frame-ancestors 'none'` and `X-Frame-Options: DENY`; a request the browser marks as a frame load, or a cross-site non-navigation load, is refused; a POST must carry `Origin: https://<name>`, not be marked cross-site, and be JSON; the Host must be the enforcer's name (DNS rebinding). Opening a link from a text is a cross-site navigation and is allowed. | NET-4 Owner's surface ("agentOS never renders, frames or relays that screen") | — |
| ENF-b-8 | **The certificate is a root with a critical name constraint to the enforcer's name**, and a leaf under it (`NewCert`); the phone trusts only that root. The root lasts 10 years; each leaf 397 days, inside Apple's 825-day cap that holds even under an owner-installed root, and `Cert.Renew` reissues it under the same root in its last 30 days (L3 on #3746). Keeping the root key in the sealed store, calling `Renew` daily and serving the root at enrolment are slices l and c. | NET-4 Passkey rules ("a certificate limited to the enforcer's own local name") | — |
| ENF-b-9 | **NET-1's limits are SPEC's sentences** with SPEC's markup (`[Fact]`, backticks) removed; `TestLimitsWordingAndLabels` reads SPEC.md, so a SPEC change fails it until `Limits` follows. Device labels come from `policy.Device.Label` (added here; ENF-a-8 asks the slice that adds a field to add its classify row). | NET-1 | — |
| ENF-b-10 | **Rate limits** are 10 proposal links a minute and 16 live challenges of 5 minutes each, counted for the whole page; action links (`/a`, slice s) have their own 10 a minute, so a flood of either cannot delay the other. NET-4 asks for refusal of rate-limited links but gives no number. | NET-4 | Slice d measures the core's real link rate. |
| ENF-b-11 | **Every time the page shows is in the owner's zone** (`Config.Zone`, the enforcer's configured zone, which slice l wires; a page without one is refused), to the minute with the zone's name: a pending loosening's due time, a standing rule's window, and the approval's answer. The diff a version commits to is drawn in that zone too, so a later change of zone leaves old versions' lines in the zone they name. The page never shows UTC (`TestTimesInOwnersZone`). The page is served at home only, so the enforcer's zone is the owner's. | NET-4 (the owner understands what the page asks) | — |
| ENF-r-14 | **An add-device link may carry one safety-list device's sealed secret** (slice r): the query names the device and the envelope's hash (`sd`, `sh`) and the fragment holds the envelope. The page draws the diff with `pairseal.Statement`'s line for both, only if the change adds that device to the safety list and `Config.Secrets` is wired. The tap must post the envelope hashing to that hash; after the policy takes the loosening, the store admits the secret, and if it refuses (the envelope does not open for the device) the page cancels the loosening, so no device is added without the secret the owner approved. One secret per link. | STO-3, STO-4, decision 10 | Several devices per link need a list of names and hashes, each with its line. |
| ENF-c-10 | **The enrolment screens are part of the page** (slice c): `/enrol` and its posts answer only where the page does, with the same origin, host, framing and JSON checks. With `Config.Enrol` set the page may be built with no owner; until a passkey is in force, and whenever the one it was built for is no longer (`live`), it serves only those screens and refuses every tap. The recovery-pending notice with its cancel, and the request to keep the policy (ENF-c-6), are on the home page, each a tap of the passkey in force over `DomainAct`, as cancel and resume are, except that the keep tap signs the policy's own version root. The Owner network's Wi-Fi QR is drawn by the page's script from modules `rsc.io/qr` computes, so no markup is injected. | NET-4, NET-6, HW-10 | — |
| ENF-b-12 | **The pairing screen names each mDNS name pinned or unpinned** (#4144): "Let <device> announce the name <name> ..." for a Devices-network device, "Hold the name <name> for <device> ..." for an Owner or Household one. Names compare exactly, so a change of case shows; a move onto or off the Devices network shows every kept name unpinned and pinned again in the new network's words, since its meaning changes. A link whose document pins one name on two devices is refused on the confirm screen with policy's words naming the name and both devices, and no challenge, so the owner renames one or declines (UX lens on #4145). A pair whose Devices-network side has a path (Linked) and pins no name gets one line saying that device will not show up by name across the pair (#4401), once: when the pair, its last pin's removal, its move onto Devices or its path's return is signed. A side with no path already has its own line. | NET-3, NET-4 | — |
| ENF-page-csrf-1 | **Every state-changing request carries an anti-forgery pair, checked in one place** (#4387): a screen sets a cookie, `__Host-` named, `SameSite=Strict`, `HttpOnly`, `Secure`, `Path=/`, no expiry, and carries that cookie's HMAC (under a key the page draws at start and never shows) in a `<meta>` the script posts back as `X-Enforcer-Token`. `ServeHTTP` refuses any request other than GET without a matching pair, and without ENF-b-7's origin and JSON checks, before it looks up a route; POST routes exist only in `Server.posts`, so none can skip the check and one added later starts refused. The cookie is a random nonce, the time it was drawn and an HMAC tag over both under the same key (#4428): a screen reached by a navigation the browser calls `same-origin`, `same-site` or `none` that sends a cookie whose tag checks and that was drawn at most 12 hours ago, not in the future, keeps it and shows the same token, so a second tab or a reload leaves open screens working; any other screen mints, including every link opened from a text (cross-site, so the browser withholds the cookie), and a restart's new key mints on the next screen. Open screens' taps fail with "reload it" only after a mint. | CH-9, NET-4 Owner's surface | If browsers stop sending `Sec-Fetch-Site`, every screen mints again (the old behaviour); the check stays the same. |
