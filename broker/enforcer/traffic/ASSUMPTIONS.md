# Enforcer traffic summaries: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice i, #3667).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-i-1 | **A summary is per device and short.** It names the device (from the signed policy), its bytes out and in, the `Top` (8) destinations by bytes and the `Top` refused addresses by packets, and counts the rest. It holds no port, protocol, time, source address or payload, so nothing in it is per packet (`TestSummaryShape`); a busy device's summary stays under 1 KB. Destinations are internet addresses only (nft ENF-i-2). `truncated` says a counting set or the refusal log was full, so some addresses are missing. Destinations are addresses, not names: the resolver's names are untrusted and the counting sets hold addresses. | NET-5 ("kept short, summarised rather than stored packet by packet") | Names beside addresses would come from slice f's resolver as a later row, shown as untrusted text. |
| ENF-i-2 | **The windows are the firewall's.** Bytes are since the last ruleset load (`nft` counters restart then), destinations are the last day's (the counting sets' timeout), and refusals are `Log`'s current day (`Window`, which restarts a day after it began or when the clock goes back). Nothing is written to disk. | NET-5 | — |
| ENF-i-3 | **Guests are one network.** A read for a device on the Guests network returns only the whole network's three counters, never the device's name, an address or a refusal (`TestSummaryShape`); the firewall logs nothing from Guests. Owner and Household devices are not inspected (NET-1), so a read for one is refused (`ErrNotInspected`), as is one for a device the policy does not name. A Devices-network device with no Wi-Fi identity (a radio device) has no IP path and reads as all zero. | NET-3, NET-1, A18 Segments | — |
| ENF-i-4 | **The log input is kernel messages only.** `Log.Line` counts a message only when it starts with a refusal prefix and came in on one of the trunk's VLANs; slice l feeds it the kernel's messages (the journal's kernel transport), not other processes' lines, which could imitate the format. It keeps at most `nft.TrafficSize` addresses per device; the rest add to the total. | NET-5, NET-2 | — |
| ENF-i-5 | **Served only as the channel's traffic read.** `Reader.Read` has the shape `channel.Config.Traffic` takes; slice l wires it there and to nothing else, so a planner reaches a summary only as `read` through the kernel's enforcer channel (NET-5). The page does not show summaries yet. | NET-5, NET-2 Channel | A page view of the same summary would be slice b's work. |
| ENF-cap-1 | **A cap counts what the firewall's counters count, as one reading after another** (`Counter.Add`, #4174). A `Reading` is the IP bytes the core sent to each internet address, and the edge's segment to the internet, since the ruleset load it names (`Gen`), so acknowledgements and retransmissions count like any byte (NET-2) and nothing is subtracted. Each reading adds what it holds past the last one; a new `Gen`, or a counter that falls within one, restarted, and all of it counts, since a ruleset load restarts the counters (ENF-i-2) and the day's count must not. The rules that fill the readings and drop past a cap in the kernel's own path are ENF-cap-trip-c, and the daemon that reads them, saves the state and trips is ENF-l (#3670); until then nothing links the counter. | NET-2 Byte caps | A counter that can restart and refill past its last value between two readings undercounts; the nft rules must not time out a capped address's counter within a Gen. |
| ENF-cap-2 | **The day is the enforcer's, in UTC, and only rises.** `Day` is whole days since the Unix epoch, so the day has no zone or daylight-saving change to get wrong; a clock set back keeps the later day and its count, so no step of the clock restarts a cap early (D-255 item 3). The kernel takes the day only from `Counts`. | NET-2 Byte caps ("per day on its own clock") | A local-midnight day would take the owner's zone from the signed policy, and still only rise. |
| ENF-cap-3 | **Groups are the destinations that share an address, and every capped destination is in exactly one.** An address's destinations are every one the enforcer's own resolver answered with it (`Resolved`) while the address stayed in use: a new answer adds to them and never replaces them, so a connection open across any number of midnights to an address not resolved again still counts against every destination it could be for. Each `Reading` also carries the addresses every destination's resolver set holds (`Named`, nft's per-name sets, whose union is the core's allow set), and each reading adds those destinations to their addresses, so any address the core can reach has every destination whose set holds it, however long it was idle, and after a restart too (#4377 Security release item 1). Being in a set is not being resolved that day; an address first seen in a set starts its idle clock then, so it is forgotten like any other once no set holds it. An address joins the day's groups while it was resolved that day or carried bytes that day, and is forgotten only once it has gone a full day neither resolved nor carrying bytes; the next reading gives it back the destinations whose sets still hold it, so only an address no set holds starts afresh. Destinations sharing a live address are one group whose cap is the sum of theirs and whose count is the sum of its addresses' bytes, so groups that merge mid-day add their counts. A destination with no address yet is its own group with count zero, so the kernel has a count before its first send. Bytes to an address no destination resolved to fit no cap and are an overrun with no destination (`Overrun.Dests` nil), which cuts the core. `Counts` is the shared format's `wire.Counts`, each destination with its own cap so the kernel can hold each member's own sends across a midnight split, and is read after a reading taken at the request, so it holds every byte the firewall counted before it; the kernel adds only what it sent after asking (broker/kernel/capgate). | NET-2 Byte caps, NET-1 | Grouping by an address shared on any day in the last week would merge more and loosen each cap. |
| ENF-cap-4 | **At the cap passes; one byte past trips.** An `Overrun` is a group, or the edge's segment, whose count is past its cap by `wire.PastCap`, the one edge the kernel's check (broker/kernel/capgate) stops short of, so the two cannot disagree by a byte (`TestHonestKernelNeverTripsAtTheCapEdges` runs both end to end); the caller trips the box it names (KRN-12, `Cut`). Every reading past a cap returns it again, so the caller's trip must be idempotent. Counts saturate at 2^64-1 rather than wrap back under a cap. | NET-2 Byte caps, D-255 | If the edge moves, it moves in `wire.PastCap` and both sides follow. |
| ENF-cap-5 | **A cap change applies at once; a destination taken off the list keeps its cap until the day ends.** `SetCaps` replaces the caps a newly signed version gives; the day's counts stay. A destination the version removes keeps its last cap for the rest of the day, so the bytes already sent to it, under that cap, trip nothing; its path is cut by the same version's ruleset (ENF-cut-1). A lowered cap below the day's count trips at the next reading. | NET-2 Byte caps, NET-4 | If a lowered cap should wait for the next day, `SetCaps` keeps the higher of the two until midnight. |
| ENF-cap-6 | **The day's counts survive a restart** (#4376, `Save`, `Restore`). `Save` is the whole counter but its clock and caps: the day, each address's bytes and destinations, its resolved and used days, the retired caps, the edge's bytes, and the last reading's Gen and counters. The daemon keeps it on the enforcer's own disk after every reading, and `Restore` starts from it: under the same loaded ruleset (same Gen) it counts only past the last reading, so nothing counts twice; after a ruleset load at boot (a new Gen) it counts all of the new counters on top of the day's bytes. A saved day before today's rolls over at once; one after it (a clock set back) is kept. A state that does not read back, or has no day (`null`, `{}`), is `ErrState` and the caller must not count from zero instead. What a power cut loses is the bytes since the last save, at most one reading interval's; the in-kernel drop (ENF-cap-trip-c) is loaded from the restored count, so the loss is bounded by that interval, not by the cap. | NET-2 Byte caps ("per day on its own clock"), D-255 | Saving before the firewall passes bytes, rather than after each reading, would need the counter in the kernel's own path. |
