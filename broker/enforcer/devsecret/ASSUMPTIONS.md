# Enforcer device-secret store: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice r, #3692, decision 10).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-r-6 | **A secret is admitted only with the add-device loosening it rides, while that loosening waits.** `Admit` checks the owner's assertion over the proposal (`policy.Verify`), that the proposal adds the device to the safety list and the policy in force lacks it, that the signed diff holds `pairseal.Statement` for the device and the envelope's hash as a whole line, that the proposal is the engine's pending loosening, and only then opens the envelope. Each admission raises a floor, so the same assertion admits nothing twice. Replacing a held device's secret (re-pairing) is refused: it needs its own signed change, which no slice defines yet. | STO-4, NET-4 Passkey rules | A re-pair row adds a diff line and a classify row for it. |
| ENF-r-7 | **A secret is released only after its change lands**: its device is in the policy in force at or above the admitted version and its change no longer waits. A cancelled change's secret is erased by `Prune`, which the page calls after every change it approves or cancels; slice l calls it after every change that lands and at start. Without a `Prune` between a cancel and a later add of the same device name, the later device would get the cancelled secret, so every caller of `Engine.Cancel` must prune under the same lock. | STO-4 ("erase on device removal") | If the engine reports cancels itself, `Prune` can hang off that. |
| ENF-r-8 | **A secret goes only to the process that drives its device**, named by `Config.Process` from the signed policy and the radio host's layout, and compared with the asking process's `Peer`, the user ID the kernel reports for its socket (SO_PEERCRED). Each stack and driver runs as its own user (ENF-k-1). Reading the peer credentials and the release socket are slice l's; the page and the channel get no release path at all: neither links this package (`TestReleasedOnlyToOwnDevice`), the page's `Secrets` interface only admits and prunes, and the channel's hook only returns a hash. | STO-4, NET-2 Confined radio stacks | If slice l hands secrets down the stack's command socket or a second fd at start (ENF-k-10), `Process` still decides who gets which. |
| ENF-r-9 | **The store's state is sealed by an injected `Box`**, as ENF-m seals the enforcer's state partition, and kept by an injected `Disk`; the slice ships no box. Secrets in memory are cleared when erased or replaced, best effort (Go may have copied them). | STO-4 | — |
| ENF-r-10 | **Callers hold the policy lock** (page.Config.Lock) around every `Store` call, so the store reads one consistent policy; the store also has its own mutex for its state. | ENF-d-5 | — |
