# Enforcer receive offloads: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (ENF-cap-gro, #4610; NET-2 Byte caps, D-255).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-gro-1 | **No counted port merges segments.** The byte caps count IP bytes as the kernel holds each packet (nft ENF-cap-trip-c-1); a port that merges received segments hands the firewall one IP header for several. `Off` turns `rx-gro`, `rx-lro` and `rx-gro-hw` off on the core's and the edge's ports and reads them back; the daemon refuses to start while one stays on and asks again before every reading (daemon ENF-l-16). With them off, a bulk send through the real ruleset counts exactly the IP bytes that left the sender's port, and with GRO on it counts about 2.5% short (`TestCapCountsEverySegmentHeader`). | NET-2 Byte caps, D-255 | A port that cannot turn one off cannot carry the core or the edge; a NIC that merges in a way no ethtool feature names would need its own row. |
| ENF-gro-2 | **`rx-gro` off stops every software merge.** The kernel skips GRO on a device without `NETIF_F_GRO` (`netif_elide_gro`), so `rx-gro-list` and `rx-udp-gro-forwarding`, which only shape software GRO, are left as they are. | — | A kernel that runs a GRO variant without `rx-gro` adds its name to `Merging`. |
| ENF-gro-3 | **A port's packets are received on the devices under it.** `Off` walks from each port to its parent (`IFLA_LINK`: a VLAN's, macvlan's or ipvlan's) and its members (`IFLA_MASTER`: a bond's or bridge's), down to the hardware, and turns merging off on each, since GRO runs where the hardware's packets arrive. A parent in another namespace (a veth's peer) is not walked. A core VLAN on a trunk turns merging off for the trunk's other VLANs too: they cost the enforcer CPU, not correctness. | NET-2 Segments, HW-12 | — |
| ENF-gro-4 | **The kernel's ethtool netlink, read by name.** Features are read and set as verbose bitsets by the kernel's names (`ETHTOOL_MSG_FEATURES_GET`/`SET`, Linux 5.6 and later); a compact bitset or an unnamed bit is refused rather than read as nothing set. Links are read with rtnetlink. Both go through the standard library's `syscall`: no process, no third-party code, no `unsafe`. Reading needs no privilege; a change needs `CAP_NET_ADMIN`, which the daemon's unit gives it (daemon ENF-l-3). | NET-2 Hardening, D-231 | — |
