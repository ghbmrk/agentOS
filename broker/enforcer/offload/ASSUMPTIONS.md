# Enforcer receive offloads: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (ENF-cap-gro, #4610; NET-2 Byte caps, D-255).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-gro-1 | **No counted port merges segments.** The byte caps count IP bytes as the kernel holds each packet (nft ENF-cap-trip-c-1); a port that merges received segments hands the firewall one IP header for several. `Off` turns `rx-gro`, `rx-lro` and `rx-gro-hw` off on the core's and the edge's ports and reads them back; the daemon holds a port where one stays on at its caps and asks again before every reading (daemon ENF-l-16). With them off, a bulk send through the real ruleset counts exactly the IP bytes that left the sender's port, and with GRO on it counts about 2.5% short (`TestCapCountsEverySegmentHeader`). | NET-2 Byte caps, D-255 | A port that cannot turn one off cannot carry the core or the edge; a NIC that merges in a way no ethtool feature names would need its own row. |
| ENF-gro-2 | **`rx-gro` off stops every software merge.** The kernel skips GRO on a device without `NETIF_F_GRO` (`netif_elide_gro`), so `rx-gro-list` and `rx-udp-gro-forwarding`, which only shape software GRO, are left as they are. | — | A kernel that runs a GRO variant without `rx-gro` adds its name to `Merging`. |
| ENF-gro-3 | **A port's packets are received on the devices under it.** `Off` walks from each port to its parent (`IFLA_LINK`: a VLAN's, macvlan's or ipvlan's) and its members (`IFLA_MASTER`: a bond's or bridge's), down to the hardware, and turns merging off on each, lower devices first: an upper device takes its merging features from its lower one, so set first it reads back still on. A veth's peer in another namespace is not walked (its packets are that namespace's sends, and its `IFLA_LINK` is an index there, not here). Any other parent in another namespace is an error, since it cannot be reached. A core VLAN on a trunk turns merging off for the trunk's other VLANs too: they cost the enforcer CPU, not correctness. | NET-2 Segments, HW-12 | — |
| ENF-gro-4 | **The kernel's ethtool netlink, read by name.** Features are read and set as verbose bitsets by the kernel's names (`ETHTOOL_MSG_FEATURES_GET`/`SET`, Linux 5.6 and later); a compact bitset or an unnamed bit is refused rather than read as nothing set. Links are read with rtnetlink. Both go through the standard library's `syscall`, with `golang.org/x/sys/unix`'s names for the kernel's numbers: no process, no `unsafe` of its own. Only the kernel's replies are read (sender port 0), and a bitset with bytes that are not attributes is refused. Reading needs no privilege; a change needs `CAP_NET_ADMIN` in the namespace that holds the enforcer's ports. **That holds only from ENF-m-b:** today's unit is a placeholder with `PrivateNetwork=yes` and no capability, and ENF-m-b's unit must run the daemon in the host namespace, allow `AF_NETLINK`, give `CAP_NET_ADMIN` and restart it (daemon ENF-l-3). The netns tests set features with that capability in their own namespace. | NET-2 Hardening, D-231 | ENF-m-b |
