# Enforcer texts, calls and light: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice h, #3666).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-h-a1 | **The closed list.** Texts: an unusual-time unlock or disarm, a recovery-code use, an enrolment, a paused channel (NET-2's list), a heater off or a valve shut by a channel command (slice d's hook; two kinds so the text names which), and a log fork from the head copies (STO-1: the owner must choose). Calls: an alarm triggered, a door forced, repeated failed unlocks (SPEC marks which events call as a recommendation). Logged only: routine unlocks and locks. Which unlock is unusual is the lock rules' call (slice q). | NET-2 Texts and calls | One row in `kinds`. |
| ENF-h-a2 | **An alert stays open until the owner resolves it on the enforcer's page, and every text that opens one sends the owner there unconditionally (no "if it was not you"); a paused channel resolves only when the owner resumes it there, and a trip also when its cut lifts in full (`Lifted`).** Whether the kernel took the text (`Sent`) changes nothing but the record: the core may drop or falsely confirm it, and nothing on the channel resolves anything. | NET-2 Texts and calls, P6 | |
| ENF-h-a3 | **A repeat of an open alert's kind on the same device counts on it, and tells the owner again only once its fold window has passed since they were last told: 10 minutes for calls, an hour for texts.** A burst of failed unlocks costs one call; an alarm days after one the owner could not clear while away calls again (fix-lists on #3909). The count and last time are on the page. | NET-2 ("only when the owner needs to act"; every urgent event calls) | Per-kind windows if the owner wants them. |
| ENF-h-a4 | **Light colours: red while a trip at the enforcer (`Trip`, from any box or device) is open; off otherwise.** Every other alert, a pending recovery and a silent core show only on the page (`Status`), and no text but a trip's names the light. A trip is one kind on the list, raised by the slices that detect it (decoy addresses, byte caps, channel limits); its text says the light stays red until the cut lifts or the owner clears it. `Refresh` re-shows the colour on a timer (slice l) for a bulb that was power-cycled. | NET-2 Texts and calls, KRN-12 Response, D-254 | A second known-attack kind joins `Trip`'s test in `Status`. |
| ENF-h-a5 | **A text the kernel refused is offered again when the core comes back (`Core(true)`); one it took is not, since the enforcer cannot tell a delivery from a drop.** | NET-2 Texts and calls | |
| ENF-h-a6 | **The journal is append-only, one JSON line per record state, the latest per id winning; a torn last append (no newline) is cut with `Truncate` at open, so the next append starts clean; a failed append is cut back to the last good length at once, so a short write in a running process leaves no fragment either.** | P6 | |
