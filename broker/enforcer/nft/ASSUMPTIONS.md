# Enforcer firewall: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice e, #3661).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-e-1 | **A device is its VLAN.** `Device.WiFi` is `vlan<N>` (2 to 4094, shortest form), the device's interface is `<Trunk>.<N>`, and every per-device rule matches that interface only. No rule a device's traffic reaches matches a hardware or IP address (the only hardware addresses read are a shared segment's host records and address claims, ENF-ct-bind-2, ENF-shared-src-1), so a device that copies another's MAC or address on its own VLAN gets its own list (`TestCopiedMACGetsOwnList`). Two devices on one VLAN, a VLAN on a device off the Devices network, or any other identity string fail the compile. A Devices-network device with no Wi-Fi identity (a radio device such as a Zigbee lock) gets no IP path. | NET-3, D-225 | A wired device on Devices needs a switch port mapped to its own VLAN; the layout would then name that port, not the trunk. |
| ENF-e-2 | **Paths come from the document's fields, narrowed to named ports** (ENF-e2, #3753). A device reaches the internet (its allow set) only while `VendorCloud` is on, so cutting the vendor cloud cuts its internet (NET-4's tightening, NET-2 Cameras). An everyday device with its cloud is online: the edge may start connections to its `Control` ports only. An everyday device without is offline: the core may start connections to its `Control` ports only. An everyday device with no control port is reached by neither box. A safety-list device is reached by neither box, except that the core may start connections to an offline (no vendor cloud), unisolated camera's or microphone's `Stream` ports, logged as `enf core-stream ` (the device's VLAN is the line's `OUT=`, within ENF-log-bound-1's bound) and counted in `core_stream`; a camera's control ports are never opened, since its settings go only through the enforcer. Streams must be connections the core starts: a camera that sends RTP over UDP to the core on a flow it starts itself is dropped (RTSP interleaved over TCP works). A signed pair still opens every port between its two ends. | NET-2 Device paths, Cameras and microphones, The core's list | A camera that needs its own UDP flows would need an RTSP conntrack helper here. |
| ENF-e-3 | **Allow sets hold addresses, not ports.** `DeviceSet` and `CoreSet` are filled by slice f's dnsmasq `nftset=` with what its own resolver returned; any port to such an address passes. A connection's first packet passes only to an address an answer returned within `AnswerTimeout` (ENF-set-ttl-1). A load keeps the answers of the names still listed (ENF-set-keep-1). | NET-2 The core's list ("addresses and ports that answer returns"), NET-1 | A port per destination needs a port in the document. |
| ENF-e-4 | **Owner and Household are each one network.** They share one password each (NET-3 gives per-device passwords only to Devices), so a pair from an Owner or Household device to a home device opens that path from the whole network, one way (the person's side starts it). Pairs between two Devices-network devices open both ways. A pair touching an isolated or VLAN-less device has no path; a pair with no Devices-network side, or one naming a Guests, core or edge device, fails the compile. | NET-3 Casting, NET-2 Device paths | Per-person identity on Household would need per-device passwords there too. |
| ENF-e-5 | **Owner and Household are not logged.** Their refused traffic is dropped in the `people` chain with no log line or counter, and Guests' with none but the whole-network counters (NET-1: household devices are not inspected; NET-3: guests never observed). Everything else that is refused is logged with a fixed prefix that names only a VLAN number, and counted (`counters`); slice i's summaries read the log. | NET-1, NET-3, NET-5 | — |
| ENF-e-6 | **The layout is the enforcer's own.** Interface names, the access point's and ISP router's addresses, the edge gateway and the ports come from the image and setup, never from the core or the policy, and `Layout.Check` refuses anything that would need quoting. The edge's segment is IPv4 only, with a static address: the enforcer answers no neighbour discovery there and forwards no IPv6 from it (an IPv6 edge would need neighbour discovery both ways, L3 release note on the PR). | NET-2 Segments, HW-12 | Slice l builds the layout from the box's hardware; slice g's access point config uses the same VLAN numbers. |
| ENF-e-7 | **Default deny is written twice.** Each filter chain has policy drop, and the forward chain ends in a logged drop as well; the edge's segment is dropped on input and on output, and ARP there is answered only for the gateway, because the kernel otherwise answers ARP for any of its addresses on any interface. A mutation that removes either half of the edge's input and output drops still passes the edge tests; removing both fails them. | NET-2 Segments, P4 | — |
| ENF-e-8 | **The known encrypted-DNS list is a fixed list of the large public resolvers' addresses** (`doh4`, `doh6`), and outside DNS is blocked by port (53, 853) from Devices. A resolver not on the list, or DNS over HTTPS to an address on a device's allow set, is not caught by address; it is caught only if its name never entered the allow set. | NET-3 ("blocks known outside encrypted-DNS resolvers") | Slice f may refresh the list from a signed source; a change to it is a code change reviewed here. |
| ENF-e-9 | **The loader relies on nft's transaction.** `nft -f -` applies the whole text or nothing, so a failed load leaves the previous ruleset and its set contents (`TestLoadFailureKeepsPrevious`, which also reloads under traffic and sees no window). The loader refuses a text that does not start with `flush ruleset`, which would merge instead of replace, and runs only an absolute nft path with an empty environment. A document the compiler refuses never reaches the loader, so the previous ruleset stays (P5); slice l must compile a proposed version before the owner signs it, so a signed version always compiles. | NET-2 Fails safe, decision 4 | — |
| ENF-e-10 | **The netns tests run unprivileged.** They re-run themselves as root of a new user and network namespace, which CI's Go jobs allow (`kernel.apparmor_restrict_unprivileged_userns=0`, ci.yml). In CI (`CI` set) a missing tool, IPv6 or 802.1Q support fails them; elsewhere the IPv6 probes are skipped and each device VLAN is a veth with the VLAN interface's name, which the ruleset cannot tell apart. | A18 Segments | — |
| ENF-e-11 | **Slice f's lines in the ruleset.** The ruleset exports what slice f needs so both sides agree by construction: `AllowSets` (which sets exist and which names fill each) and `Paths` (which pairs the mDNS relay carries). It also holds slice f's three rules: a device's port-53 traffic is redirected to the enforcer (`dns_redirect`, NET-3), the core alone reaches the Wake-on-LAN relay (UDP 9), and only the interfaces of a live pair, every device VLAN not isolated, and the Owner and Household networks reach the mDNS relay (224.0.0.251:5353; `Hears`), the VLANs so the relay hears which names each device proves its own (D-266), the person networks so their names are claimed and offered as holds before any pair (#4411); `Layout.Iface` is where the relay hears a device. Every interface is reverse-path filtered first (`rpf` chain, `spoofed` counter): a source not routed back out of its interface is dropped, so no segment can forge the upstream's answer to the resolver, which would fill an allow set, or pose as another segment (`TestSpoofedSourceDropped`; L3 and Security blocker on #4055). DHCP requests' (UDP 68 to 67) and IPv6 setup's unspecified sources pass to the later rules. Any other IPv4 broadcast or multicast source (`fib saddr type { broadcast, multicast }`: the limited broadcast, a subnet's broadcast, a group) is then dropped and counted on every interface, since the fib routes the WAN subnet's own broadcast back out of the WAN and the general check would pass it (#4841; IPv6 has no broadcast and its stack drops a multicast source before the hook). The fib types 0.0.0.0 as broadcast, so every other unspecified source is dropped and counted there too, by intent: nothing can answer it, though the general check passes one to the limited broadcast or a link-local group (`TestUnspecifiedSourceOnlyAsDHCP`, #4855). The later rules also receive, as they do the unspecified sources, a DHCP or DHCPv6 answer on the WAN addressed to the enforcer itself (`fib daddr . iif type` local, or broadcast for IPv4) from a source no interface routes (`fib saddr oif missing`, #4764: a core, Owner or device source is the internet posing as a segment) and that is none of the enforcer's own addresses (`fib saddr type != { local, broadcast, anycast, multicast }`, #4771: the fib reports a local source as missing too): until the WAN holds its lease no route leads back to the server, so the uplink would never get an address (`TestWANLeases`, #4078). A DHCPv6 server answering from such an address resolves the client's link-local address first, so neighbour solicitations and advertisements on the WAN, on the link (hop limit 255), to the enforcer and from an unrouted, non-local source pass too. An answer to be forwarded, or one on any other interface, is still filtered, and so is neighbour discovery in a segment's name (`TestDHCPAnswersOnlyToTheEnforcer`). The enforcer must run with the kernel's own reverse-path filter off, since this chain replaces it: on (strict or loose; Debian's systemd default is 2), it drops those answers as martians before any rule sees them. The image sets `rp_filter` to 0 on `all`, `default` and every interface, over systemd's `50-default.conf`, and its self-check fails a boot where any interface reads otherwise (image/enforcer ENF-m-11, #4810). | NET-2 The core's list, Segments, NET-3 | — |
| ENF-i-1 | **An unpatched device is isolated by losing its pairs** (slice i, #3667). A Devices-network device with any hold (`policy.Document.Unpatched`: frozen firmware or a held security fix) gets no signed-pair path to or from it, so no mDNS record of it is relayed either (`Paths`). A pair has a path exactly when both ends are `policy.Document.Linked` (`TestPathsFollowLinked`): a held Owner or Household device keeps its pairs, since that end is the whole network, and the page says which pairs a change stops or starts (page `TestHoldNamesLostPairs`). Its outbound access stays its allow set (Devices already reach nothing else), and the core's or edge's connections to its control or stream ports stay as its path rule says, since those are how agentOS drives it and the device starts none of them (`TestFrozenIsolated`). | NET-7 Freeze ("isolated and its outbound access is cut to what it needs"), A18 Locks | Cutting the boxes' control paths too would make a frozen everyday device unusable; that would be a NET-7 wording change first. |
| ENF-i-2 | **Each device's traffic is counted in the ruleset, on established connections only** (NET-5). Every unisolated VLAN device has two named byte counters (`TrafficOut`, `TrafficIn`) for all its established traffic, and a counting set per family (`TrafficSet`: dynamic, at most `TrafficSize` = 64 addresses, each dropped a day after its last packet) that records only its internet peers by address, so a box, a paired device or a person on Owner or Household never appears by address (NET-1). They are reached through one verdict map per direction before the forward chain's established accept, so the cost per packet does not grow with the number of devices. Only `established` packets count, not `related`: an address the device was refused never enters its set, either way, and a forged ICMP error (related) from another device or the internet cannot write into its summary (`TestDeviceTrafficCounted`; Security blocker on #4088). The counters restart at each ruleset load. Guests, Owner and Household have no such rules. | NET-5, NET-3, NET-1 | A longer window would need the summaries to keep their own history, which NET-5's "kept short" argues against. |
| ENF-i-3 | **Refusals are counted, never read from lines** (#4765). Every refusal ends in its prefix's logged chain (ENF-log-bound-1), which counts one from a device's VLAN on the device's `TrafficRefused` and, per destination address, in its `RefusedSet` (per family, dynamic, at most `RefusedSize` = 1024 addresses, each dropped a day after its last refused packet), before any bucket is consulted, so a device that spends its lines on decoys still has its real destination counted packet for packet (`TestRefusedWhereExact`). `load.Loader.List` reads the table as JSON for the summaries, with the same absolute-path and empty-environment rules as `Load`, and only for a plain identifier as the table name. | NET-5 | — |
| ENF-cut-1 | **A connection lives only while the ruleset in force would admit its first packet** (#4141). Every established or related forwarded packet first passes the live chains (`forward_live`, `people_live`): the forward and people rules again, written by the same code from the same list (`live.go`), but read from the connection's original tuple (`ct original`, `ct protocol`) and its direction, with the interfaces swapped for replies. So a load that removes a pair, freezes or isolates an end, drops a port, or cuts a vendor cloud ends the connections already open along that path, both ways, in the same nft transaction; the connections on kept paths go on (`TestCutPathEndsOpenConnections`). Nothing deletes conntrack entries: a cut connection's packets are dropped until its entry times out, and it flows again if a later load restores the path. A related packet (an ICMP error) passes only on the interfaces of the connection it names (ENF-ct-bind-1). The live form checks the resolver-filled allow sets (`CoreSet`, `DeviceSet`) too, so narrowing a list ends the connections to the dropped names (ENF-set-keep-1). The input chain keeps its plain established accept: its only policy-dependent accept is the mDNS relay's group address, which conntrack never sees answered, so no established connection rests on it. | NET-3, NET-7 Freeze ("isolated"), NET-2 Device paths, A18 Segments | — |
| ENF-ct-bind-1 | **A connection is bound to the interface pair its first packet crossed** (#4286). Every forward and people accept sets the connection's mark to its interface pair (egress number in the high 16 bits, ingress in the low; a device interface is its VLAN, the layout's own interfaces 0x1001 to 0x1008), and every live accept passes a later packet only on a connection with that mark, the interfaces swapped for replies. So an ICMP error that conntrack calls related to a connection, whoever forged it, passes only on that connection's own interfaces: a device, guest, person, core or edge with its own internet path cannot have one masqueraded to another segment's internet peer, nor a paired device inject one into its pair's other connections (`TestForgedRelatedDropped`, which also sees a genuine path-MTU error and the forger's error about its own connection pass). An accept that does not name one interface each way fails the compile, which is why Owner's and Household's internet are two rules (`TestEveryAcceptBound`). The numbers depend only on the interfaces, so a load keeps a kept path's mark (`TestEveryAcceptBound` also checks each live mark equals its accept's, and `TestBindAllRefuses` reaches the compile error). A connection open at the first load of this ruleset fails closed (`TestFirstLoadCutsOnce`): one conntrack tracked under an earlier ruleset that set no mark has mark 0 and its packets are dropped until its entry times out (ENF-cut-1), while new connections on the same path open; one conntrack never saw is picked up as new at its next packet and judged like any other. Hosts sharing a segment (guests, people on one network) share its pairs, so on those segments the host binding (ENF-ct-bind-2) does what the mark cannot; nothing else on the enforcer sets or reads the mark. | NET-3, NET-2 Device paths | — |
| ENF-ct-bind-2 | **On a shared segment a connection is bound to the host that started it** (#4324, #4480). Guests, Owner and Household are each one segment several hosts share, so their connections share an interface pair. Every accept from one of them goes to its segment's `learn_<segment>` chain, which, once per connection (it sets conntrack label 0 and reads it back before writing, and passes a connection already labelled without writing; a connection conntrack created while no loaded rule used labels cannot take one and is never recorded, since conntrack calls each original-direction packet new until a reply and another host could send one from the host's address and port), records the connection's conntrack ID and original source with the source address and hardware address of its first packet in its segment's `HostSet` (`host_<segment>_4`, `_6`) and then accepts. Every later packet entering from the segment in its connection's original direction (established, related, or new on a labelled connection) passes only when its connection and its own source and hardware addresses give that same record (`bound_<segment>`), and is dropped without a log line or a count (NET-1, NET-3). So another host on the segment cannot send into a host's connection, an ICMP error or a datagram from the host's address and port, from its own address, from the host's, or from its own with the host's hardware address (`TestSharedSegmentRelatedBound`: internet connections on all three, Household's pair with the printer, both families; `TestSharedSourceBound`), while the host's own packets pass. No accept leads into a shared segment (`bindAll` refuses one, `TestBindAllRefuses`), so the host that sent a connection's first packet is always its shared end. Each pass refreshes the record: for `HostTCPTimeout` (5 d, the kernel's default idle timeout for an established TCP connection) on a TCP connection both ends answered (`ct status assured`), for the set's `HostTimeout` (1 h, longer than conntrack keeps any other idle connection) otherwise. Each segment's set holds `HostSize` (65535) per family, so one segment's hosts can fill only their own. Fails closed: a connection without a record (it expired, the set was full, the connection opened while a load replaced the ruleset, or it was open at the first load of a ruleset with labels) has its later packets from the segment dropped. A load carries the records (ENF-shared-src-1). A host that copies another's hardware address as well as its address is that host to the enforcer; on Wi-Fi the access point's per-station keys stand behind the hardware address. | NET-2 Device paths, NET-3 | A wired shared segment would need port security on its switch for the hardware address to mean a host. If the kernel's TCP idle timeout is raised past 5 d, so must `HostTCPTimeout` be. |
| ENF-shared-src-1 | **On a shared segment an IPv4 address belongs to the host the enforcer's own DHCP server leased it to, an IPv6 address to the first leased hardware address that sent from it (one per hardware address), and a load keeps them** (#4480, #5294, #4703). Every packet forwarded from Guests, Owner or Household passes its segment's `claim_<segment>` chain. IPv4 passes only from an address and hardware address in `LeaseSet` (`lease_<segment>_4`); the hardware addresses are in `LeasedSet` (`leased_<segment>`). The output chain fills both from the server's DHCPACK as it leaves on the segment's interface, before the client has it, in the kernel, so no daemon races it (`snoop`): a BOOTP reply (op 2, Ethernet, length 6) with the magic cookie whose first options are, in order, message type ACK (53), server identifier (54, 4 bytes) and lease time (51), from `MinLease` (120 s, the shortest dnsmasq grants) to `LeaseTimeout`, which `dns.LeaseHours` is pinned to by a constant that does not compile otherwise. This is the order dnsmasq writes (measured with dnsmasq 2.91; `TestSnoopReadsDnsmasqACK` runs the real dnsmasq in CI and fails on another order or offset). nft cannot take a timeout from the packet, so there is one rule per band of lease times (`leaseBands`, each top under 1.5 times its floor, `LeaseTimeout` alone last), and each element lasts its band's floor from the ACK: never longer than the lease, and more than two thirds of it, so the client's renewal at half the lease refreshes it with a sixth of the lease to spare (`TestLeaseBandsCoverEveryLease`; band edges and a renewal near a band's top in `TestSharedHoldsFollowLeases`). A client whose ACK is never seen gets no lease entry and reaches nothing beyond the enforcer (fails closed); an ACK with no address (to an INFORM) leases nothing. The server can end a lease early, and dnsmasq 2.91 frees the address at once for the next client (measured, #5300): on a client's DHCPRELEASE or DHCPDECLINE, on a REQUEST that names another free address (the client moves) and on one it refuses (NAK). Neither a filter on the client's messages nor dnsmasq's `dhcp-script` closes that: a REQUEST that moves a client is an ordinary REQUEST, the message type need not come first (dnsmasq reads a RELEASE after a pad; dhcpcd writes option 50 before it in a REQUEST), and the script's `del` ran 2 ms after the server had already acknowledged the address to the next client, 340 ms with 150 events queued, which any host can queue. So the lease sets end only with their own time, and `LeaseAddrSet` (`leaseaddr_<segment>_4`) holds each address `LeaseSet` holds, filled by the same snoop rules before `LeaseSet` (a full set adds no lease, or holds an address for no one: fails closed) and written again by each load from the leases it carries or seeds: the output chain drops any answer from the server (an OFFER or ACK) whose address `LeaseAddrSet` holds and whose address and client hardware address `LeaseSet` does not, so the server cannot give an address to another host while its old holder's element lasts, and counts each such answer on `lease_held`, one total over the shared segments with no address or hardware address, like `edge_in` and `ra_dropped` (`TestEarlyEndedLeasesStayHeld` runs the real dnsmasq through a RELEASE, a forged RELEASE with a pad, and a move, and reads the count). An address the lease file lists with two hardware addresses is seeded as one `LeaseAddrSet` element for the longer time left (`TestSeedRendersLeases`), so the address stays held until the longer lease ends and answers to the shorter-lived holder are held once its own element runs out: the safe direction. The input chain also drops a DHCPRELEASE from a shared segment whose message type is its first option, before the established accept (a renewal leaves the client's unicast to the server established), so a client's own release, as dhclient, udhcpc and dhcpcd write it (measured; dhcpcd 10.0.6 sends it unicast with the message type, the server identifier and the end, padded to 300 bytes, which `TestEarlyEndedLeasesStayHeld` sends byte for byte), leaves its lease at the server for its full time, as in the sets, and frees no address for another host to wait on. A DECLINE passes: the declining host then gets another address. So no host can send from an address the server did not lease to its hardware address, nor before the server leased it (a pre-opened tuple, such as IKE's 500 to 500, which its record would then bind to it), nor into a leased host's connections (`TestSharedHoldsFollowLeases`, `TestSharedSourceBound`). Static IPv4 addressing on a shared segment reaches nothing. IPv6 (stateful DHCPv6 only on these segments, so one address per host): from the hardware address that holds the source address (`ClaimSet`, `HeldSet`) it refreshes the hold and the hardware address's mark (`MACSet`, `mac6_<segment>`); from another it is dropped; a free address is taken only by a hardware address in `LeasedSet` that holds no other (`MACSet`). A hold lasts `ClaimTimeout` (6 h) from the address's last forwarded packet, at most half the lease (a constant in nft does not compile otherwise; `TestLeaseCoversHold` reads the written leases), so a departed host's hold has run out before the server can give the address to another host. An IPv6 address whose holder was silent for 6 h can be taken; the taker still cannot send into the holder's open connections (their records name the holder's hardware address), and the holder's own packets are dropped until the taker's hold runs out: a denial of service, never an injection. The enforcer's neighbour entries keep following the holder while a host record names it, since a taken-over IPv6 hold does not mean the holder left (#4702, ENF-shared-nd-1). A load seeds the lease sets from the server's lease file (`Seed`, appended to the load's text; the daemon passes it, #5295), so a reboot does not drop every host until it renews; until #5295 merges, an upgrade from a table with the old IPv4 claims turns each into a lease for the time the claim had left (at most half a lease, so it ends before the lease it stands for while the client renews), and a reboot drops both families on the shared segments until each host renews (up to half a lease): with `LeasedSet` empty no new IPv6 hold is taken either. Every load after the first (`Reload`) carries each segment's records, leases, leased hardware addresses, holds, claims and marks from the running table, each for the time it had left (one refreshed past its set's timeout with a timeout of its own); each element is parsed field by field and written again, never copied as text, and one that does not parse is left out, which fails closed (`TestReloadCarriesSharedRecords`). Records written between `Loader.List` and the load are lost: those connections fail closed. The carried and seeded elements go only to nft's input; the loader reports nft's first error line only, a position, so a guest's or person's addresses are never logged or kept (NET-1, NET-3). Two first packets from one free IPv6 address, or from two free addresses of one hardware address, that arrive within the same moment can both take a hold. | NET-3, NET-2 Device paths | A host whose DHCPv6 address changes while its old hold lasts (a new address from the server, a second interface) is refused on the new one until the old hold runs out (up to `ClaimTimeout`). An IPv6-only host (no DHCPv4 lease, so no `LeasedSet` entry) gets no IPv6 hold on a shared segment. The identities are the server's leases, which a host multiplies only by DHCP starvation (a guest that answers with new hardware addresses until the pool, about 245 addresses a segment, is spent), an existing residual. A host whose address the server freed early waits, and may be the one the server picks for it next: the server's lease of that address to another host is answered only once the old element runs out (up to `LeaseTimeout`); the server keeps offering that host the same address meanwhile (measured), so it gets none. The enforcer's home page says so for 12 hours after `lease_held` last rose (the daemon reads it at the resolver's step and before each load; its first reading after it starts only sets where counting starts, since a table that outlived the last run counted at times it cannot tell, so a hold between the last run's final reading and the restart goes unshown, #5528), with the owner's step: wait (the address is free within 12 hours), or have the device join with its private Wi-Fi address turned off or on, so dnsmasq, which starts its search for a free address at a hash of the hardware address, most likely offers another. Neither a reload nor a reboot frees the address sooner: the carry and the seed keep `leaseaddr_*`. IPv6 has no such guard: a shared segment's IPv6 address is the first leased sender's (`claim_<segment>_6`), not bound to the DHCPv6 server's lease, so an address that server gives to another host while the old holder's hold lasts (the old holder released or declined it, or asked for a shorter lease) is answered, and the new host's packets from it are dropped until the hold runs out (up to `ClaimTimeout`), with no count and no line on home; never a send from another host's address. Whether IPv6 should be lease-bound like IPv4 is a design question for #4703's row. A host on the segment can cause this on purpose (a forged RELEASE written with a pad first, a DECLINE, or a REQUEST that moves or is refused, each with another client's hardware address): a denial of service like DHCP starvation, never a send from another host's address. A later, shorter ACK of another address to the same hardware address cuts its `LeasedSet` element to that ACK's band, while its first address keeps its own element (`TestSharedHoldsFollowLeases`): only the host's IPv6 hold can be refused early (fails closed). A host that copies another's hardware address and address is that host to the enforcer, as before. No ARP or neighbour discovery moves the enforcer's entry for a held address to another hardware address (ENF-shared-nd-1). |
| ENF-shared-nd-1 | **On a shared segment the enforcer's neighbour entry for a held address names only its holder's hardware address** (#4686). Linux sets its entry for an ARP message's sender address from any ARP that reaches it, request or reply, asked for or not, and for a neighbour discovery message's subject (a solicitation's or router solicitation's source, an advertisement's target) from its link-layer option; a host that names another's address with its own hardware address would get that host's downstream packets. IPv4: `table netdev enforcer_neigh` (`NeighTable`) has, per segment, an ingress chain on the segment's interface (`arp_<segment>`) that accepts ARP whose sender address and sender hardware address (bytes 14 and 8 of the only ARP form Linux takes on Ethernet) `LeaseSet` holds and drops ARP whose sender address `LeaseAddrSet` holds with any other; ARP for an address no lease holds passes, as before. An inet table never sees ARP, an arp table never sees DHCP, and a chain reads only its own table's sets, so `NeighTable` keeps its own `LeaseSet` and `LeaseAddrSet`: its egress chain on the interface (`ack_<segment>`) reads each ACK with `snoop`'s own matches, but only one carrying the packet mark bit `ownAck`, which `snoop`'s lease rules in the inet output chain set (after that chain has dropped one the inet sets hold for another host): the egress hook also sees forwarded packets, which never cross the output chain and are never marked, so an ACK-shaped reply a guest has the internet send it from port 67 leases nothing (#5687; `TestForwardedAckLeasesNothing`, with a ruleset without the guard under which it moves the entry), and `Seed` and `Reload` write each lease to both tables (`TestSnoopReadsDnsmasqACK`, `TestSeedRendersLeases`, `TestReloadCarriesSharedRecords`). The entry follows the lease, not the host records: a lease ends only when its holder stops renewing (the server cannot give the address away sooner, ENF-shared-src-1), and a host without one forwards nothing. IPv6: the first hardware address to hold an address (`ClaimSet`) takes its neighbour hold, which every packet `claim` passes from it keeps (`neigh_<segment>`): `NeighSet` and `NeighAddrSet` for `ClaimTimeout`, `NeighTCPSet` and `NeighTCPAddrSet` for `HostTCPTimeout` from each packet of a TCP connection both ends answered, each address before its key. So a hold outlasts its holder's claim and every record of its connections (`bound`), and a host that takes the address after its holder fell silent gets no hold while the holder's lives: its own downstream packets go to the old holder, a denial of service to the taker, never a read of another's.
