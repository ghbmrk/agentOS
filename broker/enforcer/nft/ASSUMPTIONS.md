# Enforcer firewall: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice e, #3661).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-e-1 | **A device is its VLAN.** `Device.WiFi` is `vlan<N>` (2 to 4094, shortest form), the device's interface is `<Trunk>.<N>`, and every per-device rule matches that interface only. No rule a device's traffic reaches matches a hardware or IP address (the only hardware addresses read are a shared segment's host records and address claims, ENF-ct-bind-2, ENF-shared-src-1), so a device that copies another's MAC or address on its own VLAN gets its own list (`TestCopiedMACGetsOwnList`). Two devices on one VLAN, a VLAN on a device off the Devices network, or any other identity string fail the compile. A Devices-network device with no Wi-Fi identity (a radio device such as a Zigbee lock) gets no IP path. | NET-3, D-225 | A wired device on Devices needs a switch port mapped to its own VLAN; the layout would then name that port, not the trunk. |
| ENF-e-2 | **Paths come from the document's fields, narrowed to named ports** (ENF-e2, #3753). A device reaches the internet (its allow set) only while `VendorCloud` is on, so cutting the vendor cloud cuts its internet (NET-4's tightening, NET-2 Cameras). An everyday device with its cloud is online: the edge may start connections to its `Control` ports only. An everyday device without is offline: the core may start connections to its `Control` ports only. An everyday device with no control port is reached by neither box. A safety-list device is reached by neither box, except that the core may start connections to an offline (no vendor cloud), unisolated camera's or microphone's `Stream` ports, logged as `enf core-stream ` (the device's VLAN is the line's `OUT=`, within ENF-log-bound-1's bound) and counted in `core_stream`; a camera's control ports are never opened, since its settings go only through the enforcer. Streams must be connections the core starts: a camera that sends RTP over UDP to the core on a flow it starts itself is dropped (RTSP interleaved over TCP works). A signed pair still opens every port between its two ends. | NET-2 Device paths, Cameras and microphones, The core's list | A camera that needs its own UDP flows would need an RTSP conntrack helper here. |
| ENF-e-3 | **Allow sets hold addresses, not ports.** `DeviceSet` and `CoreSet` are filled by slice f's dnsmasq `nftset=` with what its own resolver returned; any port to such an address passes. The sets carry the timeout flag so slice f can expire answers with their TTL. A load keeps the answers of the names still listed (ENF-set-keep-1). | NET-2 The core's list ("addresses and ports that answer returns"), NET-1 | A port per destination needs a port in the document. |
| ENF-e-4 | **Owner and Household are each one network.** They share one password each (NET-3 gives per-device passwords only to Devices), so a pair from an Owner or Household device to a home device opens that path from the whole network, one way (the person's side starts it). Pairs between two Devices-network devices open both ways. A pair touching an isolated or VLAN-less device has no path; a pair with no Devices-network side, or one naming a Guests, core or edge device, fails the compile. | NET-3 Casting, NET-2 Device paths | Per-person identity on Household would need per-device passwords there too. |
| ENF-e-5 | **Owner and Household are not logged.** Their refused traffic is dropped in the `people` chain with no log line or counter, and Guests' with none but the whole-network counters (NET-1: household devices are not inspected; NET-3: guests never observed). Everything else that is refused is logged with a fixed prefix that names only a VLAN number, and counted (`counters`); slice i's summaries read the log. | NET-1, NET-3, NET-5 | — |
| ENF-e-6 | **The layout is the enforcer's own.** Interface names, the access point's and ISP router's addresses, the edge gateway and the ports come from the image and setup, never from the core or the policy, and `Layout.Check` refuses anything that would need quoting. The edge's segment is IPv4 only, with a static address: the enforcer answers no neighbour discovery there and forwards no IPv6 from it (an IPv6 edge would need neighbour discovery both ways, L3 release note on the PR). | NET-2 Segments, HW-12 | Slice l builds the layout from the box's hardware; slice g's access point config uses the same VLAN numbers. |
| ENF-e-7 | **Default deny is written twice.** Each filter chain has policy drop, and the forward chain ends in a logged drop as well; the edge's segment is dropped on input and on output, and ARP there is answered only for the gateway, because the kernel otherwise answers ARP for any of its addresses on any interface. A mutation that removes either half of the edge's input and output drops still passes the edge tests; removing both fails them. | NET-2 Segments, P4 | — |
| ENF-e-8 | **The known encrypted-DNS list is a fixed list of the large public resolvers' addresses** (`doh4`, `doh6`), and outside DNS is blocked by port (53, 853) from Devices. A resolver not on the list, or DNS over HTTPS to an address on a device's allow set, is not caught by address; it is caught only if its name never entered the allow set. | NET-3 ("blocks known outside encrypted-DNS resolvers") | Slice f may refresh the list from a signed source; a change to it is a code change reviewed here. |
| ENF-e-9 | **The loader relies on nft's transaction.** `nft -f -` applies the whole text or nothing, so a failed load leaves the previous ruleset and its set contents (`TestLoadFailureKeepsPrevious`, which also reloads under traffic and sees no window). The loader refuses a text that does not start with `flush ruleset`, which would merge instead of replace, and runs only an absolute nft path with an empty environment. A document the compiler refuses never reaches the loader, so the previous ruleset stays (P5); slice l must compile a proposed version before the owner signs it, so a signed version always compiles. | NET-2 Fails safe, decision 4 | — |
| ENF-e-10 | **The netns tests run unprivileged.** They re-run themselves as root of a new user and network namespace, which CI's Go jobs allow (`kernel.apparmor_restrict_unprivileged_userns=0`, ci.yml). In CI (`CI` set) a missing tool, IPv6 or 802.1Q support fails them; elsewhere the IPv6 probes are skipped and each device VLAN is a veth with the VLAN interface's name, which the ruleset cannot tell apart. | A18 Segments | — |
| ENF-e-11 | **Slice f's lines in the ruleset.** The ruleset exports what slice f needs so both sides agree by construction: `AllowSets` (which sets exist and which names fill each) and `Paths` (which pairs the mDNS relay carries). It also holds slice f's three rules: a device's port-53 traffic is redirected to the enforcer (`dns_redirect`, NET-3), the core alone reaches the Wake-on-LAN relay (UDP 9), and only the interfaces of a live pair, every device VLAN not isolated, and the Owner and Household networks reach the mDNS relay (224.0.0.251:5353; `Hears`), the VLANs so the relay hears which names each device proves its own (D-266), the person networks so their names are claimed and offered as holds before any pair (#4411); `Layout.Iface` is where the relay hears a device. Every interface is reverse-path filtered first (`rpf` chain, `spoofed` counter): a source not routed back out of its interface is dropped, so no segment can forge the upstream's answer to the resolver, which would fill an allow set, or pose as another segment (`TestSpoofedSourceDropped`; L3 and Security blocker on #4055). DHCP requests' (UDP 68 to 67) and IPv6 setup's unspecified sources pass to the later rules. Any other IPv4 broadcast or multicast source (`fib saddr type { broadcast, multicast }`: the limited broadcast, a subnet's broadcast, a group) is then dropped and counted on every interface, since the fib routes the WAN subnet's own broadcast back out of the WAN and the general check would pass it (#4841; IPv6 has no broadcast and its stack drops a multicast source before the hook). The fib types 0.0.0.0 as broadcast, so every other unspecified source is dropped and counted there too, by intent: nothing can answer it, though the general check passes one to the limited broadcast or a link-local group (`TestUnspecifiedSourceOnlyAsDHCP`, #4855). The later rules also receive, as they do the unspecified sources, a DHCP or DHCPv6 answer on the WAN addressed to the enforcer itself (`fib daddr . iif type` local, or broadcast for IPv4) from a source no interface routes (`fib saddr oif missing`, #4764: a core, Owner or device source is the internet posing as a segment) and that is none of the enforcer's own addresses (`fib saddr type != { local, broadcast, anycast, multicast }`, #4771: the fib reports a local source as missing too): until the WAN holds its lease no route leads back to the server, so the uplink would never get an address (`TestWANLeases`, #4078). A DHCPv6 server answering from such an address resolves the client's link-local address first, so neighbour solicitations and advertisements on the WAN, on the link (hop limit 255), to the enforcer and from an unrouted, non-local source pass too. An answer to be forwarded, or one on any other interface, is still filtered, and so is neighbour discovery in a segment's name (`TestDHCPAnswersOnlyToTheEnforcer`). The enforcer must run with the kernel's own reverse-path filter off, since this chain replaces it: on (strict or loose; Debian's systemd default is 2), it drops those answers as martians before any rule sees them. Nothing sets it yet: ENF-m (#3671, comment there) must set `net.ipv4.conf.all.rp_filter` and `net.ipv4.conf.default.rp_filter` to 0, so the WAN's effective value is 0, and #4810 adds the boot check. | NET-2 The core's list, Segments, NET-3 | — |
| ENF-i-1 | **An unpatched device is isolated by losing its pairs** (slice i, #3667). A Devices-network device with any hold (`policy.Document.Unpatched`: frozen firmware or a held security fix) gets no signed-pair path to or from it, so no mDNS record of it is relayed either (`Paths`). A pair has a path exactly when both ends are `policy.Document.Linked` (`TestPathsFollowLinked`): a held Owner or Household device keeps its pairs, since that end is the whole network, and the page says which pairs a change stops or starts (page `TestHoldNamesLostPairs`). Its outbound access stays its allow set (Devices already reach nothing else), and the core's or edge's connections to its control or stream ports stay as its path rule says, since those are how agentOS drives it and the device starts none of them (`TestFrozenIsolated`). | NET-7 Freeze ("isolated and its outbound access is cut to what it needs"), A18 Locks | Cutting the boxes' control paths too would make a frozen everyday device unusable; that would be a NET-7 wording change first. |
| ENF-i-2 | **Each device's traffic is counted in the ruleset, on established connections only** (NET-5). Every unisolated VLAN device has two named byte counters (`TrafficOut`, `TrafficIn`) for all its established traffic, and a counting set per family (`TrafficSet`: dynamic, at most `TrafficSize` = 64 addresses, each dropped a day after its last packet) that records only its internet peers by address, so a box, a paired device or a person on Owner or Household never appears by address (NET-1). They are reached through one verdict map per direction before the forward chain's established accept, so the cost per packet does not grow with the number of devices. Only `established` packets count, not `related`: an address the device was refused never enters its set, either way, and a forged ICMP error (related) from another device or the internet cannot write into its summary (`TestDeviceTrafficCounted`; Security blocker on #4088). The counters restart at each ruleset load. Guests, Owner and Household have no such rules. | NET-5, NET-3, NET-1 | A longer window would need the summaries to keep their own history, which NET-5's "kept short" argues against. |
| ENF-i-3 | **Refusals are counted, never read from lines** (#4765). Every refusal ends in its prefix's logged chain (ENF-log-bound-1), which counts one from a device's VLAN on the device's `TrafficRefused` and, per destination address, in its `RefusedSet` (per family, dynamic, at most `RefusedSize` = 1024 addresses, each dropped a day after its last refused packet), before any bucket is consulted, so a device that spends its lines on decoys still has its real destination counted packet for packet (`TestRefusedWhereExact`). `load.Loader.List` reads the table as JSON for the summaries, with the same absolute-path and empty-environment rules as `Load`, and only for a plain identifier as the table name. | NET-5 | — |
| ENF-cut-1 | **A connection lives only while the ruleset in force would admit its first packet** (#4141). Every established or related forwarded packet first passes the live chains (`forward_live`, `people_live`): the forward and people rules again, written by the same code from the same list (`live.go`), but read from the connection's original tuple (`ct original`, `ct protocol`) and its direction, with the interfaces swapped for replies. So a load that removes a pair, freezes or isolates an end, drops a port, or cuts a vendor cloud ends the connections already open along that path, both ways, in the same nft transaction; the connections on kept paths go on (`TestCutPathEndsOpenConnections`). Nothing deletes conntrack entries: a cut connection's packets are dropped until its entry times out, and it flows again if a later load restores the path. A related packet (an ICMP error) passes only on the interfaces of the connection it names (ENF-ct-bind-1). The live form checks the resolver-filled allow sets (`CoreSet`, `DeviceSet`) too, so narrowing a list ends the connections to the dropped names (ENF-set-keep-1). The input chain keeps its plain established accept: its only policy-dependent accept is the mDNS relay's group address, which conntrack never sees answered, so no established connection rests on it. | NET-3, NET-7 Freeze ("isolated"), NET-2 Device paths, A18 Segments | — |
| ENF-ct-bind-1 | **A connection is bound to the interface pair its first packet crossed** (#4286). Every forward and people accept sets the connection's mark to its interface pair (egress number in the high 16 bits, ingress in the low; a device interface is its VLAN, the layout's own interfaces 0x1001 to 0x1008), and every live accept passes a later packet only on a connection with that mark, the interfaces swapped for replies. So an ICMP error that conntrack calls related to a connection, whoever forged it, passes only on that connection's own interfaces: a device, guest, person, core or edge with its own internet path cannot have one masqueraded to another segment's internet peer, nor a paired device inject one into its pair's other connections (`TestForgedRelatedDropped`, which also sees a genuine path-MTU error and the forger's error about its own connection pass). An accept that does not name one interface each way fails the compile, which is why Owner's and Household's internet are two rules (`TestEveryAcceptBound`). The numbers depend only on the interfaces, so a load keeps a kept path's mark (`TestEveryAcceptBound` also checks each live mark equals its accept's, and `TestBindAllRefuses` reaches the compile error). A connection open at the first load of this ruleset fails closed (`TestFirstLoadCutsOnce`): one conntrack tracked under an earlier ruleset that set no mark has mark 0 and its packets are dropped until its entry times out (ENF-cut-1), while new connections on the same path open; one conntrack never saw is picked up as new at its next packet and judged like any other. Hosts sharing a segment (guests, people on one network) share its pairs, so on those segments the host binding (ENF-ct-bind-2) does what the mark cannot; nothing else on the enforcer sets or reads the mark. | NET-3, NET-2 Device paths | — |
| ENF-ct-bind-2 | **On a shared segment a connection is bound to the host that started it** (#4324, #4480). Guests, Owner and Household are each one segment several hosts share, so their connections share an interface pair. Every accept from one of them goes to its segment's `learn_<segment>` chain, which, once per connection (it sets conntrack label 0 and reads it back before writing, and passes a connection already labelled without writing; a connection conntrack created while no loaded rule used labels cannot take one and is never recorded, since conntrack calls each original-direction packet new until a reply and another host could send one from the host's address and port), records the connection's conntrack ID and original source with the source address and hardware address of its first packet in its segment's `HostSet` (`host_<segment>_4`, `_6`) and then accepts. Every later packet entering from the segment in its connection's original direction (established, related, or new on a labelled connection) passes only when its connection and its own source and hardware addresses give that same record (`bound_<segment>`), and is dropped without a log line or a count (NET-1, NET-3). So another host on the segment cannot send into a host's connection, an ICMP error or a datagram from the host's address and port, from its own address, from the host's, or from its own with the host's hardware address (`TestSharedSegmentRelatedBound`: internet connections on all three, Household's pair with the printer, both families; `TestSharedSourceBound`), while the host's own packets pass. No accept leads into a shared segment (`bindAll` refuses one, `TestBindAllRefuses`), so the host that sent a connection's first packet is always its shared end. Each pass refreshes the record: for `HostTCPTimeout` (5 d, the kernel's default idle timeout for an established TCP connection) on a TCP connection both ends answered (`ct status assured`), for the set's `HostTimeout` (1 h, longer than conntrack keeps any other idle connection) otherwise. Each segment's set holds `HostSize` (65535) per family, so one segment's hosts can fill only their own. Fails closed: a connection without a record (it expired, the set was full, the connection opened while a load replaced the ruleset, or it was open at the first load of a ruleset with labels) has its later packets from the segment dropped. A load carries the records (ENF-shared-src-1). A host that copies another's hardware address as well as its address is that host to the enforcer; on Wi-Fi the access point's per-station keys stand behind the hardware address. | NET-2 Device paths, NET-3 | A wired shared segment would need port security on its switch for the hardware address to mean a host. If the kernel's TCP idle timeout is raised past 5 d, so must `HostTCPTimeout` be. |
| ENF-shared-src-1 | **On a shared segment an address belongs to the hardware address that first sent from it, and a load keeps the records** (#4480). Every packet forwarded from Guests, Owner or Household passes its segment's `claim_<segment>` chain: from the hardware address that holds its source address (`ClaimSet`, address and hardware address; `HeldSet`, the addresses held) it refreshes the hold; from another it is dropped silently; from a free address its hardware address takes it. A hold lasts `ClaimTimeout` (6 h) from the address's last forwarded packet, at most half the 12 h DHCP lease the server offers (`dns.LeaseHours`; dns does not compile when the hold exceeds half of it, and `TestLeaseCoversHold` fails when a written lease does, #4702): a host that is still present renews half a lease after its last renewal, so one that left sent its last packet at most half a lease after that renewal, and its hold has run out by the time the lease ends and the server can give the address to another host. So a host cannot open a connection first on another host's address and port (a pre-opened tuple such as IKE's 500 to 500, which its record would then bind to it) nor send into one from that address, while the address is held (`TestSharedSourceBound`). An address whose holder was silent for 6 h can be taken; the taker still cannot send into the holder's open connections (their records name the holder's hardware address), and the holder's own packets from it are dropped until the taker's hold runs out, which is a denial of service, never an injection. A silent holder may still renew its lease (input traffic, which does not refresh the hold), so a taken-over hold does not mean the holder left: anything that follows the hold, such as #4686's neighbour entries, must keep following the holder while any host record names the holder's hardware address for that address, or must not follow a hold taken over a silent holder, since otherwise the downstream of the holder's open connections (records last up to 5 d on assured TCP) would move to the taker (#4702). Every load after the first (`Reload`) carries each segment's records, holds and claims from the running table, each for the time it had left (one refreshed past its set's timeout with a timeout of its own); each element is parsed field by field and written again, never copied as text, and one that does not parse is left out, which fails closed (`TestReloadCarriesSharedRecords`). Records written between `Loader.List` and the load are lost: those connections fail closed. The carried elements go only to nft's input; the loader reports nft's first error line only, a position, so a guest's or person's addresses are never logged or kept (NET-1, NET-3). Two hosts whose first packets from one free address arrive within the same moment can both hold it. | NET-3, NET-2 Device paths | A client may request a shorter lease (dnsmasq grants down to 120 s, both families); one that did and left can keep its hold on an address the server gives again, for up to `ClaimTimeout`: a denial of service on the new host, never an injection. Addresses handed out without DHCP would need their own bound on `ClaimTimeout`. A host on a shared segment can still take another's address at layer 2 (an ARP or neighbour answer the enforcer believes), which reaches the host's downstream packets, not its connections' upstream (#4686). |
| ENF-e-related-1 | **A forged related packet is a logged refusal** (#4113). A related packet that matches no live accept (it names a connection that does not run on the interfaces it crossed, whoever sent it) is dropped at the end of `forward_live` with the `enf drop` prefix and the `blocked` counter, so a device's forged ICMP error shows in its summary as a refusal unless it touches those networks (`TestRelatedNeedsPath`, which also sees the pair's and the internet router's genuine errors pass). When it touches Guests, Owner or Household it is dropped with no line or count (ENF-e-5): sent from one (its sender is never observed), or sent to one or naming a connection with one of their ends in its inner header, either of which the log line would show (read from the connection's mark; an unbound mark-0 connection is treated as theirs); so only `forward_live` logs, as every packet `people_live` sees has an Owner or Household end. A cut connection's own established packets are dropped without a line, since one load can cut many. | A18 Segments, NET-3, NET-1 | A separate prefix for forgeries would need slice i's summaries to name it. |
| ENF-set-keep-1 | **A load keeps the answers of the names still listed, and only those** (#4237, #4080). Slice f's resolver puts each answer in its list's allow set and in the name's own set (`AllowSet.Named`: the list's set name and a hash of the holder, the core or the device's ID, and the name, so no host name reaches the ruleset and a device that takes over a VLAN starts empty). Every load after the first is `Reload(document, layout, listing)`, the listing being `load.Loader.List(Table)` of the running table: the compiled ruleset, then in the same transaction each kept name's set copied over and each allow set filled with the union of its kept names' sets. The old allow sets are never read, so an address only a dropped name answered leaves its set and the live form cuts the connections open to it, both ways, while one a kept name also answered stays (`TestNarrowedListEndsOpenConnections`, `TestReloadCarriesListedAnswersOnly`); a device that cached its answer reaches it right after a load (`TestLoadKeepsListedAnswers`; `dns::TestOnlyResolvedAddressesAllowed` with real dnsmasq). Only plain address elements carry; anything else in the listing is left out, which fails closed. An answer the resolver adds between the listing and the load is not carried: that device reaches the address again on its next query, within `dns.MaxTTL`. A listing that is not nft's JSON fails `Reload`. | NET-2 The core's list ("only the addresses … that answer returns"), NET-3, NET-4 | Slice l (the daemon, not yet built) must call `Reload`, not `Compile`, for every load after the first; a first load has nothing to carry. |
| ENF-cap-trip-c-1 | **The firewall counts every byte the core may send to the internet, and every byte the edge sends there, before any rule decides it** (#4557, NET-2 Byte caps). Right after `ct state invalid drop`, the forward chain sends the core's packets to its allow set (`CoreSet`) through `cap_4`/`cap_6` and the edge's to the WAN through `cap_edge`. What the later rules refuse anyway (the access point's admin, the ISP router, addresses that are not the internet) is not counted, so an honest box is never charged for a refused send. The core's bytes count per address in `CapSet` (`capc_4`, `capc_6`: dynamic, `CapSize` = 65535 addresses per family, no timeout, so a counter never restarts within a load), and an address the full set cannot take is dropped, so no byte goes uncounted; the edge's count in `edge_out`. IP bytes as the kernel holds them (`skb->len`), acknowledgements, retransmissions and dropped packets included: each destination's count is at least every IP byte the core's own stack sent it, retransmissions among them (`TestCapDropsTCPWithAcksAndRetransmissions`, #4614). | NET-2 Byte caps, D-255 | On an interface that merges received segments (GRO), one merged packet counts one IP header for several: a few percent under what leaves for full segments, and up to about 1.7 times under for minimum-size ones; the image keeps GRO off on the core's and the edge's ports (release item). |
| ENF-cap-trip-c-2 | **Bytes past a cap are dropped in the kernel, from the enforcer's own counts, at the trip's edge** (#4557). The drop state is `Drops(document, layout, running, traffic.Counter.Drop())`: per cap group a quota loaded with the group's count and a chain that charges it, a verdict map from each address the counter knows to its group, then one rule per listed name, in name order, that charges an address the counter has not read yet to the group of the first name whose resolver set holds it; anything else is dropped. Until a load carries it, `capd_4`, `capd_6` and `capd_edge` drop everything, so a load without it fails closed. It is appended to every load (Compile or Reload) and applied after every reading (`load.Loader.Update`, which takes only a text starting with `DropHeader`); a group that stays the same keeps its quota, so its kernel count runs on between readings, and a merged, recapped or new day's group starts from the counter's count plus what the running quotas it replaces charged between the reading's listing (`Drop.Read`) and the running one: the edge's from the old edge quota, a group's from each old group the running drop sent one of its destinations or addresses to, so bytes sent between a reading and its update count against the new quota (`TestCapMergeCarriesBytesSinceTheReading`, `TestDropsCarriesTheGap`, #4614). The kernel's groups are the counter's. An address several groups' sets hold, carrying nothing today, so the counter keeps them apart, goes to a chain that charges every one of their quotas: its first byte would merge them, and each quota then counts at least its share of the merged count, so no address raises any cap (`TestCapHeldSharedAddressRaisesNoCap`, L3 on #4611); the next reading merges them and the update gives the group one quota (`TestCapGroupSharesOneDrop`). The first byte past a cap is the first dropped and trips at the next reading, and exactly the cap passes (`TestCapDropsPastTheCapToTheByte`: core over IPv4 and IPv6, edge). A load without the drop state reaches nothing (`TestCapLoadWithoutDropFailsClosed`). A quota's N is the cap, or the cap plus one on a kernel whose quota matches on reaching N, which `load.Loader.QuotaPast` probes once (`Drop.Past`; left false, one byte more than the cap leaves). A packet past a cap goes to `log_cap`: counted in `cap_drop`, logged within its interface's `enf cap ` bucket (ENF-log-bound-1), dropped. A cap above `MaxDropCap` (2^63-2) has no quota and only trips. | NET-2 Byte caps, D-255, KRN-12 | Between a reading and the update after it, an address the counter has not read is charged to its first name's group, and a held shared address to every group's, so an honest core sending there near a cap may see drops, never a trip, until the update merges them; and a quota the update starts carries only what the old ones charged up to the running listing, so bytes sent between that listing and the update's commit pass it uncharged once (the counting set keeps them for the trip); the daemon (ENF-l, #3670) must list right before each update to keep that short. An old quota whose destinations now sit in several groups, or a shared address's gap bytes, are carried into each, and a new day's quota carries the gap's bytes from before midnight: stricter, never looser. `Drop.Read` must be the listing of the reading the update follows, with no update between. A full load restarts the counters, so the daemon takes a reading right before every load (ENF-l, #3670); the bytes between that reading and the load are not counted. A shorter reading interval narrows all three. |
| ENF-cap-trip-c-3 | **A reading's Gen is the table's handle with the boot's id** (`traffic.ReadingOf`, #4561 L3 and Security release items). The kernel numbers tables per network namespace and never reuses a number within one; the enforcer's firewall is the initial namespace's, which lives exactly as long as the boot, and the boot id (`/proc/sys/kernel/random/boot_id`) is new each boot, so a full load at boot never reuses a saved Gen, and a drop update, which keeps the table, keeps the Gen and its counters (`TestGenUniqueAcrossBoots`, `TestCapDropSurvivesRestart`). | NET-2 Byte caps, ENF-cap-6 | A firewall in a namespace that can be torn down and made again within one boot would repeat handles; it would need a Gen kept on disk. |
| ENF-log-bound-1 | **Every line is rate-bound per prefix and interface; counts and verdicts are exact** (#4432, #4762). Every refusal, and every connection the edge or the core starts to a device (`enf edge-dev `, `enf core-dev `, `enf core-stream `), goes to its prefix's `log_<prefix>` chain: counted on the prefix's counter and, a refusal from a device's VLAN, on the device's chain through the `refused` verdict map (ENF-i-3), then logged only while the interface's bucket in `lines_<prefix>` holds a token (`LineRate` 10 a minute after a burst of `LineBurst` 10; one bucket per `iif` for a refusal, per `oif`, the device's VLAN, for a box's connection; idle buckets gone after `LineIdle` 60 s), then given the prefix's verdict whether or not it logged, so an empty bucket never refuses a box's connection. `log_lines` counts the lines written. A device's refused flood and the edge's connection flood each write at most their buckets' lines while every count moves by the full flood and every connection is accepted, and another prefix or interface logs from its own bucket (`TestLinesFloodBound`, `TestLinesBound`). Lines are not keyed by source: a spoofer with many sources would then own many buckets, and nothing reads the lines but the journal. The kernel's packet logger has no rate bound of its own (`nf_log_syslog` prints every packet it is handed), so this is the only one. Only a rule's first form refuses with a line; live chains drop silently but for a forged related packet (ENF-e-related-1). | P4, NET-5, NET-3 | A bound per prefix and interface still sums over every interface and prefix: thousands of hostile VLANs at once would write thousands of lines a minute. |
