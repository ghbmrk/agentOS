# Enforcer firewall: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice e, #3661).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-e-1 | **A device is its VLAN.** `Device.WiFi` is `vlan<N>` (2 to 4094, shortest form), the device's interface is `<Trunk>.<N>`, and every per-device rule matches that interface only. No rule matches a hardware or IP address, so a device that copies another's MAC or address on its own VLAN gets its own list (`TestCopiedMACGetsOwnList`). Two devices on one VLAN, a VLAN on a device off the Devices network, or any other identity string fail the compile. A Devices-network device with no Wi-Fi identity (a radio device such as a Zigbee lock) gets no IP path. | NET-3, D-225 | A wired device on Devices needs a switch port mapped to its own VLAN; the layout would then name that port, not the trunk. |
| ENF-e-2 | **Paths come from three fields of the document**, which has no device class or port list yet (ENF-a-8, ENF-a-9). A device reaches the internet (its allow set) only while `VendorCloud` is on, so cutting the vendor cloud cuts its internet (NET-4's tightening, NET-2 Cameras). An everyday device with its cloud is online: the edge may start connections to it. An everyday device without is offline: the core may start connections to it. Both reach every port of the device, not only its control port, because the document names none. A safety-list device is reached by neither box. That is fail-closed for the one exception NET-2 makes, an offline camera's or microphone's stream port from the core: no stream reaches the core until the document can name a camera and its port (release finding on the PR). | NET-2 Device paths, Cameras, The core's list | When ENF-a's document gains a class and ports, `device.online`/`offline` and a camera stream rule read them, and the core and edge rules narrow to the named ports. |
| ENF-e-3 | **Allow sets hold addresses, not ports.** `DeviceSet` and `CoreSet` are filled by slice f's dnsmasq `nftset=` with what its own resolver returned; any port to such an address passes. The sets carry the timeout flag so slice f can expire answers with their TTL. Loading a new ruleset empties them (flush ruleset), which fails closed: a device re-resolves before it reaches anything. | NET-2 The core's list ("addresses and ports that answer returns"), NET-1 | Slice f either re-adds the live entries after each load or the loader learns to keep set contents across a replace. A port per destination needs a port in the document. |
| ENF-e-4 | **Owner and Household are each one network.** They share one password each (NET-3 gives per-device passwords only to Devices), so a pair from an Owner or Household device to a home device opens that path from the whole network, one way (the person's side starts it). Pairs between two Devices-network devices open both ways. A pair touching an isolated or VLAN-less device has no path; a pair with no Devices-network side, or one naming a Guests, core or edge device, fails the compile. | NET-3 Casting, NET-2 Device paths | Per-person identity on Household would need per-device passwords there too. |
| ENF-e-5 | **Owner and Household are not logged.** Their refused traffic is dropped in the `people` chain with no log line or counter, and Guests' with none but the whole-network counters (NET-1: household devices are not inspected; NET-3: guests never observed). Everything else that is refused is logged with a fixed prefix that names only a VLAN number, and counted (`counters`); slice i's summaries read the log. | NET-1, NET-3, NET-5 | — |
| ENF-e-6 | **The layout is the enforcer's own.** Interface names, the access point's and ISP router's addresses, the edge gateway and the ports come from the image and setup, never from the core or the policy, and `Layout.Check` refuses anything that would need quoting. The edge's segment is IPv4 with a static address; `EdgeGateway6`, if set, is the one IPv6 address the enforcer answers neighbour discovery for there. | NET-2 Segments, HW-12 | Slice l builds the layout from the box's hardware; slice g's access point config uses the same VLAN numbers. |
| ENF-e-7 | **Default deny is written twice.** Each filter chain has policy drop, and the forward chain ends in a logged drop as well; the edge's segment is dropped on input and on output, and ARP there is answered only for the gateway, because the kernel otherwise answers ARP for any of its addresses on any interface. A mutation that removes either half of the edge's input and output drops still passes the edge tests; removing both fails them. | NET-2 Segments, P4 | — |
| ENF-e-8 | **The known encrypted-DNS list is a fixed list of the large public resolvers' addresses** (`doh4`, `doh6`), and outside DNS is blocked by port (53, 853) from Devices. A resolver not on the list, or DNS over HTTPS to an address on a device's allow set, is not caught by address; it is caught only if its name never entered the allow set. | NET-3 ("blocks known outside encrypted-DNS resolvers") | Slice f may refresh the list from a signed source; a change to it is a code change reviewed here. |
| ENF-e-9 | **The loader relies on nft's transaction.** `nft -f -` applies the whole text or nothing, so a failed load leaves the previous ruleset and its set contents (`TestLoadFailureKeepsPrevious`, which also reloads under traffic and sees no window). The loader refuses a text that does not start with `flush ruleset`, which would merge instead of replace, and runs only an absolute nft path with an empty environment. A document the compiler refuses never reaches the loader, so the previous ruleset stays (P5); slice l must compile a proposed version before the owner signs it, so a signed version always compiles. | NET-2 Fails safe, decision 4 | — |
| ENF-e-10 | **The netns tests run unprivileged.** They re-run themselves as root of a new user and network namespace, which CI's Go jobs allow (`kernel.apparmor_restrict_unprivileged_userns=0`, ci.yml). In CI (`CI` set) a missing tool, IPv6 or 802.1Q support fails them; elsewhere the IPv6 probes are skipped and each device VLAN is a veth with the VLAN interface's name, which the ruleset cannot tell apart. | A18 Segments | — |
