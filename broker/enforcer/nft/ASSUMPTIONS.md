# Enforcer firewall: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice e, #3661).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-e-1 | **A device is its VLAN.** `Device.WiFi` is `vlan<N>` (2 to 4094, shortest form), the device's interface is `<Trunk>.<N>`, and every per-device rule matches that interface only. No rule matches a hardware or IP address, so a device that copies another's MAC or address on its own VLAN gets its own list (`TestCopiedMACGetsOwnList`). Two devices on one VLAN, a VLAN on a device off the Devices network, or any other identity string fail the compile. A Devices-network device with no Wi-Fi identity (a radio device such as a Zigbee lock) gets no IP path. | NET-3, D-225 | A wired device on Devices needs a switch port mapped to its own VLAN; the layout would then name that port, not the trunk. |
| ENF-e-2 | **Paths come from the document's fields, narrowed to named ports** (ENF-e2, #3753). A device reaches the internet (its allow set) only while `VendorCloud` is on, so cutting the vendor cloud cuts its internet (NET-4's tightening, NET-2 Cameras). An everyday device with its cloud is online: the edge may start connections to its `Control` ports only. An everyday device without is offline: the core may start connections to its `Control` ports only. An everyday device with no control port is reached by neither box. A safety-list device is reached by neither box, except that the core may start connections to an offline (no vendor cloud), unisolated camera's or microphone's `Stream` ports, logged as `enf core-stream <VLAN>` and counted in `core_stream`; a camera's control ports are never opened, since its settings go only through the enforcer. Streams must be connections the core starts: a camera that sends RTP over UDP to the core on a flow it starts itself is dropped (RTSP interleaved over TCP works). A signed pair still opens every port between its two ends. | NET-2 Device paths, Cameras and microphones, The core's list | A camera that needs its own UDP flows would need an RTSP conntrack helper here. |
| ENF-e-3 | **Allow sets hold addresses, not ports.** `DeviceSet` and `CoreSet` are filled by slice f's dnsmasq `nftset=` with what its own resolver returned; any port to such an address passes. The sets carry the timeout flag so slice f can expire answers with their TTL. Loading a new ruleset empties them (flush ruleset), which fails closed: a device re-resolves before it reaches anything. | NET-2 The core's list ("addresses and ports that answer returns"), NET-1 | Slice f either re-adds the live entries after each load or the loader learns to keep set contents across a replace. A port per destination needs a port in the document. |
| ENF-e-4 | **Owner and Household are each one network.** They share one password each (NET-3 gives per-device passwords only to Devices), so a pair from an Owner or Household device to a home device opens that path from the whole network, one way (the person's side starts it). Pairs between two Devices-network devices open both ways. A pair touching an isolated or VLAN-less device has no path; a pair with no Devices-network side, or one naming a Guests, core or edge device, fails the compile. | NET-3 Casting, NET-2 Device paths | Per-person identity on Household would need per-device passwords there too. |
| ENF-e-5 | **Owner and Household are not logged.** Their refused traffic is dropped in the `people` chain with no log line or counter, and Guests' with none but the whole-network counters (NET-1: household devices are not inspected; NET-3: guests never observed). Everything else that is refused is logged with a fixed prefix that names only a VLAN number, and counted (`counters`); slice i's summaries read the log. | NET-1, NET-3, NET-5 | — |
| ENF-e-6 | **The layout is the enforcer's own.** Interface names, the access point's and ISP router's addresses, the edge gateway and the ports come from the image and setup, never from the core or the policy, and `Layout.Check` refuses anything that would need quoting. The edge's segment is IPv4 only, with a static address: the enforcer answers no neighbour discovery there and forwards no IPv6 from it (an IPv6 edge would need neighbour discovery both ways, L3 release note on the PR). | NET-2 Segments, HW-12 | Slice l builds the layout from the box's hardware; slice g's access point config uses the same VLAN numbers. |
| ENF-e-7 | **Default deny is written twice.** Each filter chain has policy drop, and the forward chain ends in a logged drop as well; the edge's segment is dropped on input and on output, and ARP there is answered only for the gateway, because the kernel otherwise answers ARP for any of its addresses on any interface. A mutation that removes either half of the edge's input and output drops still passes the edge tests; removing both fails them. | NET-2 Segments, P4 | — |
| ENF-e-8 | **The known encrypted-DNS list is a fixed list of the large public resolvers' addresses** (`doh4`, `doh6`), and outside DNS is blocked by port (53, 853) from Devices. A resolver not on the list, or DNS over HTTPS to an address on a device's allow set, is not caught by address; it is caught only if its name never entered the allow set. | NET-3 ("blocks known outside encrypted-DNS resolvers") | Slice f may refresh the list from a signed source; a change to it is a code change reviewed here. |
| ENF-e-9 | **The loader relies on nft's transaction.** `nft -f -` applies the whole text or nothing, so a failed load leaves the previous ruleset and its set contents (`TestLoadFailureKeepsPrevious`, which also reloads under traffic and sees no window). The loader refuses a text that does not start with `flush ruleset`, which would merge instead of replace, and runs only an absolute nft path with an empty environment. A document the compiler refuses never reaches the loader, so the previous ruleset stays (P5); slice l must compile a proposed version before the owner signs it, so a signed version always compiles. | NET-2 Fails safe, decision 4 | — |
| ENF-e-10 | **The netns tests run unprivileged.** They re-run themselves as root of a new user and network namespace, which CI's Go jobs allow (`kernel.apparmor_restrict_unprivileged_userns=0`, ci.yml). In CI (`CI` set) a missing tool, IPv6 or 802.1Q support fails them; elsewhere the IPv6 probes are skipped and each device VLAN is a veth with the VLAN interface's name, which the ruleset cannot tell apart. | A18 Segments | — |
| ENF-e-11 | **Slice f's lines in the ruleset.** The ruleset exports what slice f needs so both sides agree by construction: `AllowSets` (which sets exist and which names fill each) and `Paths` (which pairs the mDNS relay carries). It also holds slice f's three rules: a device's port-53 traffic is redirected to the enforcer (`dns_redirect`, NET-3), the core alone reaches the Wake-on-LAN relay (UDP 9), and only the interfaces of a live pair reach the mDNS relay (224.0.0.251:5353). Every interface is reverse-path filtered first (`rpf` chain, `spoofed` counter): a source not routed back out of its interface is dropped, so no segment can forge the upstream's answer to the resolver, which would fill an allow set, or pose as another segment (`TestSpoofedSourceDropped`; L3 and Security blocker on #4055). DHCP's and IPv6 setup's unspecified sources pass to the later rules. | NET-2 The core's list, Segments, NET-3 | — |
| ENF-i-1 | **An unpatched device is isolated by losing its pairs** (slice i, #3667). A Devices-network device with any hold (`policy.Document.Unpatched`: frozen firmware or a held security fix) gets no signed-pair path to or from it, so no mDNS record of it is relayed either (`Paths`). A pair has a path exactly when both ends are `policy.Document.Linked` (`TestPathsFollowLinked`): a held Owner or Household device keeps its pairs, since that end is the whole network, and the page says which pairs a change stops or starts (page `TestHoldNamesLostPairs`). Its outbound access stays its allow set (Devices already reach nothing else), and the core's or edge's connections to its control or stream ports stay as its path rule says, since those are how agentOS drives it and the device starts none of them (`TestFrozenIsolated`). | NET-7 Freeze ("isolated and its outbound access is cut to what it needs"), A18 Locks | Cutting the boxes' control paths too would make a frozen everyday device unusable; that would be a NET-7 wording change first. |
| ENF-i-2 | **Each device's traffic is counted in the ruleset, on established connections only** (NET-5). Every unisolated VLAN device has two named byte counters (`TrafficOut`, `TrafficIn`) for all its established traffic, and a counting set per family (`TrafficSet`: dynamic, at most `TrafficSize` = 64 addresses, each dropped a day after its last packet) that records only its internet peers by address, so a box, a paired device or a person on Owner or Household never appears by address (NET-1). They are reached through one verdict map per direction before the forward chain's established accept, so the cost per packet does not grow with the number of devices. Only `established` packets count, not `related`: an address the device was refused never enters its set, either way, and a forged ICMP error (related) from another device or the internet cannot write into its summary (`TestDeviceTrafficCounted`; Security blocker on #4088). The counters restart at each ruleset load. Guests, Owner and Household have no such rules. | NET-5, NET-3, NET-1 | A longer window would need the summaries to keep their own history, which NET-5's "kept short" argues against. |
| ENF-i-3 | **Refusals are the log lines with a refusal prefix** (`BlockedPrefixes`). Every rule that logs with one drops, and every rule that logs and drops uses one (`traffic::TestPrefixesAreRefusals`); the accepted core and edge connections log with their own prefixes. `load.Loader.List` reads the table as JSON for the summaries, with the same absolute-path and empty-environment rules as `Load`, and only for a plain identifier as the table name. | NET-5 | — |
| ENF-cut-1 | **A connection lives only while the ruleset in force would admit its first packet** (#4141). Every established or related forwarded packet first passes the live chains (`forward_live`, `people_live`): the forward and people rules again, written by the same code from the same list (`live.go`), but read from the connection's original tuple (`ct original`, `ct protocol`) and its direction, with the interfaces swapped for replies. So a load that removes a pair, freezes or isolates an end, drops a port, or cuts a vendor cloud ends the connections already open along that path, both ways, in the same nft transaction; the connections on kept paths go on (`TestCutPathEndsOpenConnections`). Nothing deletes conntrack entries: a cut connection's packets are dropped until its entry times out, and it flows again if a later load restores the path. A related packet (an ICMP error) passes only on the interfaces of the connection it names (ENF-ct-bind-1). The one match the live form leaves out is a resolver-filled allow set (`CoreSet`, `DeviceSet`): a load empties them (ENF-e-3), so checking them would cut every kept internet connection at each load; the live form checks the path (the device's or core's internet) and the address family. The input chain keeps its plain established accept: its only policy-dependent accept is the mDNS relay's group address, which conntrack never sees answered, so no established connection rests on it. | NET-3, NET-7 Freeze ("isolated"), NET-2 Device paths, A18 Segments | Narrowing an allow list ends open connections to the dropped names only once the sets keep their live entries across a load (ENF-f-3 "slice l may re-add live entries"); the live form can then check the set too. |
| ENF-ct-bind-1 | **A connection is bound to the interface pair its first packet crossed** (#4286). Every forward and people accept sets the connection's mark to its interface pair (egress number in the high 16 bits, ingress in the low; a device interface is its VLAN, the layout's own interfaces 0x1001 to 0x1008), and every live accept passes a later packet only on a connection with that mark, the interfaces swapped for replies. So an ICMP error that conntrack calls related to a connection, whoever forged it, passes only on that connection's own interfaces: a device, guest, person, core or edge with its own internet path cannot have one masqueraded to another segment's internet peer, nor a paired device inject one into its pair's other connections (`TestForgedRelatedDropped`, which also sees a genuine path-MTU error and the forger's error about its own connection pass). An accept that does not name one interface each way fails the compile, which is why Owner's and Household's internet are two rules (`TestEveryAcceptBound`). The numbers depend only on the interfaces, so a load keeps a kept path's mark (`TestEveryAcceptBound` also checks each live mark equals its accept's, and `TestBindAllRefuses` reaches the compile error). A connection open at the first load of this ruleset fails closed (`TestFirstLoadCutsOnce`): one conntrack tracked under an earlier ruleset that set no mark has mark 0 and its packets are dropped until its entry times out (ENF-cut-1), while new connections on the same path open; one conntrack never saw is picked up as new at its next packet and judged like any other. Hosts sharing a segment (guests, people on one network) share its pairs, so the mark cannot stop one forging into another's connection there; nothing else on the enforcer sets or reads the mark. | NET-3, NET-2 Device paths | Finer binding than the segment needs per-host identity on that segment (ENF-e-4). |
| ENF-e-related-1 | **A forged related packet is a logged refusal** (#4113). A related packet that matches no live accept (it names a connection that does not run on the interfaces it crossed, whoever sent it) is dropped at the end of `forward_live` with the `enf drop` prefix and the `blocked` counter, so a device's forged ICMP error shows in its summary as a refusal (`TestRelatedNeedsPath`, which also sees the pair's and the internet router's genuine errors pass). To or from Guests, Owner and Household it is dropped with no line or count (ENF-e-5), since its inner header would name one of their connections; so only `forward_live` logs, as every packet `people_live` sees has an Owner or Household end. A cut connection's own established packets are dropped without a line, since one load can cut many. | A18 Segments, NET-3, NET-1 | A separate prefix for forgeries would need slice i's summaries to name it. |
