# Enforcer Thread stack: assumptions

Each row is a reading of the spec, or a property the code relies on, that a reviewer may want to change (briefs/ENF.md slice t, #3702; D-231). Covers `radio/thread/`; the confinement rows are ENF-t-1 to ENF-t-3 in `../ASSUMPTIONS.md`.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-t-4 | **Thread is OpenThread's `ot-daemon`, built by `tools/build-openthread.sh` from the one commit in `openthread.pin`** (the script sits outside `broker/` because it fetches source, and shipping code may name no undeclared endpoint) with border routing, the SRP server and advertising proxy, the DNS-SD server and discovery proxy and its own mDNS; no `otbr-agent`, Avahi or D-Bus (spike). Building it from source in the enforcer's sessions is refused by their permission check, so the build runs only in CI and in the image pipeline (slice m), which installs the result. It is linked static and position-independent (`-static-pie`), since its view holds no loader (radio ENF-k2-mnt-2). Its command socket's base name is relative (`openthread-wpan0.sock`) and both processes run in the run directory, so the socket sits there, mode 0700 and owned by the Thread user, apart from the state directory, which holds the network's keys and which the adapter's view leaves out. | D-231, decision 6 | A new pin is a change to `openthread.pin`, which also refreshes CI's build cache. |
| ENF-t-5 | **The adapter is a second confined process** (`confine.ThreadAdapter`: the Thread user, Unix sockets only, an empty network namespace), so ot-daemon's text output is parsed outside the enforcer and the enforcer reads only the radio interface's strict frames. It sends only `Commands`: bring-up (form a network once if none is stored, enable the SRP server, start) and `state`. A fault on the session (timeout, an answer past 32 lines or 1024 bytes a line, a closed socket) ends that session, so no later command reads what an earlier one left. | NET-2 Confined radio stacks | — |
| ENF-t-6 | **Thread serves one device, `thread-network`, and only its read** (`radio.Declared[StackThread]`). Thread devices (locks, the D-233 alert bulb) are Matter devices over Thread and take their commands through the Matter controller. | D-231, D-233 | — |
| ENF-t-7 | **ot-daemon forms its own network and keeps the dataset, including the network key, in its state directory**; nothing returns it through the adapter. The Matter controller needs the dataset to commission a device onto Thread; how it gets it (a declared op, or a second descriptor at start) is the Matter piece's, which waits on the BLE commissioning decision. | STO-4 (keys stay on the enforcer) | — |
| ENF-t-8 | **The daemon (slice l) starts the stack in order**: ot-daemon under `confine.Thread` (its state directory, Dir = its run directory, the RCP's device), the adapter (the enforcer's binary with `AdapterArg`) under `confine.ThreadAdapter` with Dir = the run directory, never the state directory, then the Matter controller under `confine.Matter` with `Spec.Net` set to ot-daemon's process; this package exports only its arguments and the adapter, so that `confine` stays the only radio package linking `os/exec` (arc2). `TestSrpReachesController` runs that order. | arc2, decision 1 | — |
| ENF-t-9 | **`TestSrpReachesController` uses OpenThread's simulated radio and node**: the simulated RCP runs outside the stack on a pty's master side, and ot-daemon opens the pty's other side as its serial device (`spinel+hdlc+uart://`), as it opens the RCP's on the enforcer; the RCP and an FTD node share the test's lo; the node joins with the leader's dataset and registers a service over SRP, and a Matter-profile process sends a legacy-unicast mDNS query on `infra0`. The radios and hardware timing are slice n's live work. ot-daemon logs to syslog as well as stderr (`-v` only in tests), but its view has no `/dev/log`, so without `-v` it logs nothing; how its log reaches the host's journal (stderr, say) is slice l's. | decision 11 | — |
