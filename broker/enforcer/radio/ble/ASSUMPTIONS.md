# Enforcer BLE stack: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (#3906, ENF-k2; briefs/ENF.md decision 6, slice k).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-k2-1 | **Its own D-Bus codec, not godbus.** The enforcer links no third-party package and only `nft/load` and `radio/confine` may link `os/exec` (`broker/daemon/arc2_test.go`). godbus links `os/exec` for session-bus autolaunch, and D-231 records minimal dependencies as attack surface. The codec covers the wire format only: both byte orders, no unix fds, messages at most 1 MiB, nesting at most 32, every padding byte, bool, UTF-8 string, object path and signature checked, and the header fields each type needs. A message too long, with header fields over 4 KiB, or malformed is read past and skipped, not fatal: a stock bus allows 32 MiB (`TestReadSkipsWhatDoesNotDecode`); its declared length is measured in int64, so even the largest the format allows (over 8 GiB) is skipped exactly on a 32-bit build too (`TestReadSkipsLargestDeclaredFrame`). The header is decoded first, and the body only for a reply its call still waits for or a signal the stack takes (BlueZ's PropertiesChanged, the bus driver's NameOwnerChanged), so a body it would drop is never decoded: decoding inflates one 15 to 44 times (measured; `TestReadDecodesOnlyWanted`, through `Run` against the fake bus). `FuzzDecode` round-trips whatever it accepts. `TestWireKnownBytes` holds the layout to the specification, and `TestBusPolicyRefusesUndeclaredCalls` exercises it against a real `dbus-daemon`. | ARC-2, D-231 | A later need for D-Bus features beyond method calls and signals (fd passing, serving objects) re-opens the choice. |
| ENF-k2-2 | **BlueZ is the only way to the radio.** `confine.BLE` allows only `AF_UNIX`, so the stack has no raw HCI, and `TestNoRawHCI` shows the confined process refused a raw HCI socket (EPERM) while still reaching BlueZ on the bus. The system bus socket is a path, so the stack's empty network namespace does not cut it off. | NET-2 Confined radio stacks | — |
| ENF-k2-3 | **The bus policy bounds the stack outside its process.** `BusPolicy(user)` denies every message the stack's user sends, then allows exactly Hello, GetNameOwner and AddMatch on the bus driver and `busCalls` on `org.bluez`: Device1 Connect and Disconnect, GattCharacteristic1 WriteValue and StartNotify, Properties.Get, ObjectManager.GetManagedObjects. An exploited stack cannot start discovery, pair, power the adapter, list or start services, or reach any other service on the bus, even with an encoder of its own; its broadcast signals reach no one (`TestBusPolicyRefusesUndeclaredCalls`). The policy also denies every message the user receives except from the bus driver and BlueZ, so no other peer (a compromised Thread or Matter stack) can call or signal it, unicast or broadcast (`TestBusPolicyRefusesOtherPeers`). dbus-daemon applies receive rules to the bus driver's own messages and replies too (measured: without its allow line, Hello's reply and NameAcquired are refused). A user policy beats the default and group policies, so this holds whatever the distribution's `bluetooth.conf` puts there; a `mandatory` (or deprecated `at_console`) policy is applied after it, so the image must not install one that loosens it. The policy cannot limit object paths (dbus-daemon matches `send_path` exactly, with no prefix), so it does not stop the stack from reaching another device BlueZ already knows; the stack's own configuration check does. It bounds the bus only; ENF-k2-10 bounds the other Unix sockets. Slice m installs the policy under `/etc/dbus-1/system.d/`, for the stack's user named. dbus-daemon refuses a numeric uid as an unknown user name (measured), so the image must give that user a name. | NET-2 Confined radio stacks, decision 6, A18 | A new op adds its BlueZ call to `busCalls`, and a new bus driver call to `driverCalls`, and so to the policy, in the same PR. |
| ENF-k2-4 | **Ops map one-to-one to BlueZ calls.** connect is Device1.Connect and disconnect is Device1.Disconnect. read is the device's `Connected` property, one byte (radio's `Request.Check` gives read no characteristic). write is WriteValue with no options, so BlueZ picks request or command from the characteristic's flags. subscribe is StartNotify; each PropertiesChanged `Value` on that characteristic, sent by BlueZ's unique name, becomes a notification, and anything else is dropped. There is no StopNotify: a disconnect ends notifications. A disconnect op, or BlueZ reporting the device's `Connected` false, forgets the device's subscriptions and characteristic paths (`TestDeviceDropForgets`). | NET-2 Confined radio stacks, ENF-k-2 | A device that needs a characteristic read, or an unsubscribe, adds an op to `radio.Declared` (radio's scope) and its call here. |
| ENF-k2-5 | **A device must already be known to BlueZ.** The device path comes from the configured address (`/org/bluez/<adapter>/dev_<addr>`). There is no scan op and no adapter call, so a device BlueZ has not seen answers `CodeUnreachable`. How a device first enters BlueZ (advertisement-triggered connect for the Withings scale) is DEV-withings-ble-c's (#3277). If that needs discovery, it is a new declared op and a new `busCalls` entry, each reviewed. | NET-2, briefs/DEV-withings-ble.md | — |
| ENF-k2-6 | **Characteristics are found by UUID under the device, once per connection.** BlueZ numbers characteristic objects as it discovers them, so the stack looks each configured UUID up with GetManagedObjects, caches the path until disconnect, and refuses (`CodeFailed`) when two characteristics under the device share the UUID, rather than guessing. The configuration may not give one UUID two names. | — | Configuration naming a service UUID as well, if a device repeats a characteristic UUID across services. |
| ENF-k2-7 | **BlueZ restarting ends the stack.** BlueZ's name changing owner drops every subscription, so the stack closes its bus connection and its host link. Restarting it is slice l's, as for any stack exit (ENF-k-6). | ENF-k-6 | — |
| ENF-k2-8 | **The configuration is the stack's one argument, as JSON.** It lists devices by the host's name with address and characteristic UUIDs, the adapter, and optionally a bus socket path (tests). It holds no secret: device addresses and UUIDs are what the device itself advertises. Slice l builds it from the signed policy for `confine.Spec.Args`. Slice r's secrets, if a BLE device needs one, come by another way (ENF-k-10). | STO-4 | — |
| ENF-k2-9 | **Notifications are bounded at `radio.MaxData` (512 bytes), and longer ones are dropped.** Calls wait at most 8 s, inside the host's 10 s. No reply is `CodeUnreachable`, the bus policy refusing is `CodeRefused`, and other bus errors are `CodeFailed`. The log carries one line per fault and never a device's data. | ENF-k-7, ENF-k-8 | — |
| ENF-k2-10 | **The bus socket is the only file the stack sees (#4215).** `confine.BLE`'s `View` is `/run/dbus/system_bus_socket`: Trampoline, in a user and mount namespace the enforcer creates as root (mapping only the stack's ids), makes its root a read-only tmpfs (first mounted over `/tmp` in its own namespace, so the image must have `/tmp`) holding that socket bound read-only, nosuid, nodev and noexec at its own path (opened without following a symlink and checked to be a socket, radio ENF-k2-mnt-b), pivots into it, drops CAP_SYS_ADMIN, its only capability, and execs the stack from a descriptor opened before the pivot. So an exploited stack cannot name journald's, a resolver's or a radio peer's socket, nor open any other file, and its user namespace leaves it no capability (`confine.TestViewOnlyItsEntries`, with a no-view control that reaches the other socket). Abstract sockets are per network namespace and the stack's is fresh, so none of the host's are reachable either. Landlock was checked first and cannot do this: the enforcer's kernel (6.12, Landlock ABI 6) and 6.18 (ABI 7, measured 2026-11-01) have no access right for connecting to a pathname Unix socket, only abstract-socket scoping. If dbus-daemon restarts and recreates the socket, the bound inode is stale, so the stack loses the bus and ends (ENF-k2-7) and its restart binds the new one. The stack's binary must be static, since the view holds no loader (a dynamic one fails closed: the exec fails and Trampoline exits 126); `image/build.sh` builds the core's binaries with `CGO_ENABLED=0`, and slice m's enforcer image must do the same. The cgo-linked test binaries add the loader's directories to their test views. | NET-2 Confined radio stacks, decision 6 | A stack that needs another file adds it to its profile's `View`, reviewed as a widening. |
