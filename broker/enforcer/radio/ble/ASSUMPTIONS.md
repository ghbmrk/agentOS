# Enforcer BLE stack: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (#3906, ENF-k2; briefs/ENF.md decision 6, slice k).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-k2-1 | **Its own D-Bus codec, not godbus.** The enforcer links no third-party package and only `nft/load` and `radio/confine` may link `os/exec` (`broker/daemon/arc2_test.go`). godbus links `os/exec` for session-bus autolaunch, and D-231 records minimal dependencies as attack surface. The codec covers the wire format only: both byte orders, no unix fds, messages at most 1 MiB, nesting at most 32, every padding byte, bool, UTF-8 string, object path and signature checked, and the header fields each type needs. `FuzzDecode` round-trips whatever it accepts. `TestWireKnownBytes` holds the layout to the specification, and `TestBusPolicyRefusesUndeclaredCalls` exercises it against a real `dbus-daemon`. | ARC-2, D-231 | A later need for D-Bus features beyond method calls and signals (fd passing, serving objects) re-opens the choice. |
| ENF-k2-2 | **BlueZ is the only way to the radio.** `confine.BLE` allows only `AF_UNIX`, so the stack has no raw HCI, and `TestNoRawHCI` shows the confined process refused a raw HCI socket (EPERM) while still reaching BlueZ on the bus. The system bus socket is a path, so the stack's empty network namespace does not cut it off. | NET-2 Confined radio stacks | — |
| ENF-k2-3 | **The bus policy bounds the stack outside its process.** `BusPolicy(user)` denies every message to `org.bluez`, then allows exactly `busCalls`: Device1 Connect and Disconnect, GattCharacteristic1 WriteValue and StartNotify, Properties.Get, ObjectManager.GetManagedObjects. A user policy applies after the default and group policies, so this holds whatever the distribution's `bluetooth.conf` says. An exploited stack cannot start discovery, pair, or power the adapter, even with an encoder of its own (`TestBusPolicyRefusesUndeclaredCalls`). The policy cannot limit object paths (dbus-daemon matches `send_path` exactly, with no prefix), so it does not stop the stack from reaching another device BlueZ already knows; the stack's own configuration check does. Slice m installs the policy under `/etc/dbus-1/system.d/`, for the stack's user named. dbus-daemon refuses a numeric uid as an unknown user name (measured), so the image must give that user a name. | NET-2 Confined radio stacks, decision 6 | A new op adds its BlueZ call to `busCalls`, and so to the policy, in the same PR. |
| ENF-k2-4 | **Ops map one-to-one to BlueZ calls.** connect is Device1.Connect and disconnect is Device1.Disconnect. read is the device's `Connected` property, one byte (radio's `Request.Check` gives read no characteristic). write is WriteValue with no options, so BlueZ picks request or command from the characteristic's flags. subscribe is StartNotify; each PropertiesChanged `Value` on that characteristic, sent by BlueZ's unique name, becomes a notification, and anything else is dropped. There is no StopNotify: a disconnect ends notifications. | NET-2 Confined radio stacks, ENF-k-2 | A device that needs a characteristic read, or an unsubscribe, adds an op to `radio.Declared` (radio's scope) and its call here. |
| ENF-k2-5 | **A device must already be known to BlueZ.** The device path comes from the configured address (`/org/bluez/<adapter>/dev_<addr>`). There is no scan op and no adapter call, so a device BlueZ has not seen answers `CodeUnreachable`. How a device first enters BlueZ (advertisement-triggered connect for the Withings scale) is DEV-withings-ble-c's (#3277). If that needs discovery, it is a new declared op and a new `busCalls` entry, each reviewed. | NET-2, briefs/DEV-withings-ble.md | — |
| ENF-k2-6 | **Characteristics are found by UUID under the device, once per connection.** BlueZ numbers characteristic objects as it discovers them, so the stack looks each configured UUID up with GetManagedObjects, caches the path until disconnect, and refuses (`CodeFailed`) when two characteristics under the device share the UUID, rather than guessing. | — | Configuration naming a service UUID as well, if a device repeats a characteristic UUID across services. |
| ENF-k2-7 | **BlueZ restarting ends the stack.** BlueZ's name changing owner drops every subscription, so the stack closes its bus connection and its host link. Restarting it is slice l's, as for any stack exit (ENF-k-6). | ENF-k-6 | — |
| ENF-k2-8 | **The configuration is the stack's one argument, as JSON.** It lists devices by the host's name with address and characteristic UUIDs, the adapter, and optionally a bus socket path (tests). It holds no secret: device addresses and UUIDs are what the device itself advertises. Slice l builds it from the signed policy for `confine.Spec.Args`. Slice r's secrets, if a BLE device needs one, come by another way (ENF-k-10). | STO-4 | — |
| ENF-k2-9 | **Notifications are bounded at `radio.MaxData` (512 bytes), and longer ones are dropped.** Calls wait at most 8 s, inside the host's 10 s. No reply is `CodeUnreachable`, the bus policy refusing is `CodeRefused`, and other bus errors are `CodeFailed`. The log carries one line per fault and never a device's data. | ENF-k-7, ENF-k-8 | — |
