# Enforcer access point: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice g, #3662).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-g-1 | **The access point is an OpenWrt One on OpenWrt 24.10 UCI** (D-228). Per-device passwords are `wifi-station` sections (`key`, `vid`, `iface`) with a `wifi-vlan` per device bridging it onto `<DeviceUplink>.<VLAN>`; netifd writes them into hostapd's `wpa_psk_file`, which D-225 names. The Devices interface has `dynamic_vlan 2`, so a station whose password maps to no VLAN is refused; its own `key` (`Keys.Devices`) is random and shown nowhere. The exact option set is checked by golden files only: no OpenWrt runs in CI, and the live run on the box is a later row's. | NET-3, D-225, D-228 | A live run that finds an option ignored or renamed changes the renderer and its golden files; the properties (one VLAN per password, no address off the admin VLAN) stay. |
| ENF-g-2 | **The access point holds an address only on its admin VLAN.** Every network is a bridge with `proto none` and IPv6 off on every port, VLAN and bridge, its firewall rejects input outside the admin zone, dropbear listens only there, key only, and the enforcer's key may not forward ports. Nothing on Wi-Fi has an address on the access point to reach, and its admin VLAN is one the enforcer's firewall lets only its wired admin port reach (nft `APMgmt`). The web admin is off even there (#4087): stock OpenWrt's root has no password, so LuCI or ubus over HTTP would be a root login that skips the key-only SSH, and `/etc/config/uhttpd` has uhttpd, if installed, listen on loopback alone with no HTTPS listener and no ucode, Lua or ubus handler named (`TestGoldenConfig`). The access point runs no DHCP, DNS or router advertisement service. | NET-3 ("admin reachable only from the enforcer's wired port"), NET-2 Hardening | — |
| ENF-g-3 | **Plain OpenWrt has no vendor cloud, remote access, UPnP or app pairing**, so turning them off is not shipping the packages: the config writes no such service, WPS and 802.11r are off on every network. A vendor-firmware access point would need those settings named here. | NET-3 | — |
| ENF-g-4 | **The setup network rides the Owner VLAN** and is the only network before enrolment; `Keys.Enrol` makes Owner, Household and Guests passwords and the setup network disappears from the next config. Before enrolment the enforcer serves only its enrolment page on that VLAN (slice b, HW-10). | HW-10, NET-4 | A separate setup VLAN would need its own enforcer interface in nft.Layout. |
| ENF-g-5 | **A password belongs to an id and a VLAN.** `Keys.Sync` keeps a device's password only while both stay the same; removal drops it, a VLAN move or `Rekey` makes a new one, and nothing else changes (`TestRevokeOneRepairsNoOther`). Passwords are `crypto/rand.Text()` (26 base32 characters, 130 bits), all distinct, since hostapd would put a device on the first VLAN whose password matches. | NET-3 ("revoking one device re-pairs no other") | — |
| ENF-g-6 | **Keys are held beside the policy, not in it, and storing them is slice l's.** The core and the channel never see one; the page alone shows a card (`DeviceCard`, `NetworkCard`: password, the password in groups of four for typing (`Shown`; `Keys.check` admits no space in a password, so the page can tell the owner the spaces are not typed), and a `WIFI:` QR text with the SSID and password escaped, since the setup password is the sticker's). Config reads devices only as VLAN numbers through `nft.VLAN`, so the firewall and the access point agree on every number and no core-proposed text reaches a UCI file (`TestGoldenConfig`). | NET-3 ("agentOS never holds it"), STO-4 | — |
| ENF-g-7 | **Devices join on the first radio only** (2.4 GHz on the OpenWrt One), since most home devices are 2.4 GHz only. The other networks are on every radio. The device card's `Note` names the first radio's band (`TestDeviceCardNamesBand`), so an owner pairing a device without it sees why it never joins. | NET-3 | A 5 GHz-only device needs a second Devices interface carrying the same stations. |
| ENF-g-8 | **Push is SSH with the host key pinned at setup** (`ssh.FixedHostKey`; ed25519 and ECDSA with the key's own algorithm, RSA only with `rsa-sha2-512` or `rsa-sha2-256` and never SHA-1 `ssh-rsa`, any other type refused before dialling; `TestRSAHostKeyOnlySHA2`, #4087), user root, the enforcer's key. Pinning the key on first contact over the wired admin port, and the dialer bound to that port (`Pusher.Dial`, which has no default), are slice l's. Each Sync (one at a time per pusher, and slice l runs one pusher per access point) claims the access point (ENF-g-10), reads every managed file with `cat`, writes the differing ones through temporary files on `/etc`, checks each one's SHA-256 against the config's (busybox `sha256sum` and `cut`) and only then `mv`s it into place (a stdin cut short moves nothing), tries every file even if one write fails (a write that ends without an exit status, a dropped or timed-out connection, ends the Sync, since nothing more can run on it), runs `reload_config` every time, drift or not, also after a failed write, so a reload that failed after the writes is finished by the next Sync (OpenWrt's `reload_config` applies only configs changed since its last run, so an in-sync reload does nothing), and reads them all back; content only ever goes on stdin. Drift means a managed file's bytes differ or it is gone; a runtime change nobody wrote to a file is not repaired, since `reload_config` applies only configs that changed. `Watch` re-syncs on a fixed interval. | NET-3, brief slice g | — |
| ENF-g-9 | **golang.org/x/crypto/ssh is the enforcer's first third-party package**, linked by `ap/push` alone with its exact dependency list in `broker/daemon/arc2_test.go` (`enforcerSSH`). OpenWrt's admin paths are SSH or HTTP; the enforcer links no HTTP client, and the Go project's SSH client is mature where a new one would not be. Its `NewSession` can wait for ever on a connection that ended just before it (the channel is listed after the read loop closed every listed channel, and the transport reports the failed send as success; #4441), so every session open waits only until the Sync's Timeout (`open`, `TestSessionOpenBoundedByTimeout`, `TestOpenAfterCloseReturns`) and leaves that one goroutine waiting on the closed connection. The access point chooses when its connection ends, so a hostile or broken one can aim at that window on every Sync (the #4543 Security review left 6 goroutines and about 110 KB after 5000 Syncs). So a Pusher counts the opens still waiting, `Result.Abandoned` and every `Watch` report carry the count, and from `MaxAbandoned` (16, about 320 KB) every Sync returns `ErrStalled` and dials nothing, until the waiting opens return, which in that window means until the enforcer restarts (#4554, `TestAbandonedOpensCountedAndCapped`). An open that returns after its Sync stopped waiting closes its session and stops counting (`TestLateSessionOfAbandonedOpenClosed`, `TestSilentAccessPointLeavesNoCount`), so a slow access point does not stall. | ENF decision 1, ARC-2 | An x/crypto release that ends a pending open when the connection ends lets `open` call `NewSession` directly. |
| ENF-g-10 | **A Sync claims the access point, and only the newest claim writes or reloads** (#4313). The claim takes the lock (busybox `flock -x` on `/tmp/agentos-ap.lock`, held on descriptor 9), writes a fresh 128-bit random token to `/tmp/agentos-ap.sync` and removes every `/etc/agentos-ap-*.new` temporary file. A write reads stdin into a temporary file of its own path and token and checks its hash with no lock held, so a write whose stdin never ends holds up no other Sync; only the move into place and the reload take the lock, and run only while the token file holds their own Sync's token. A Sync that times out closes the connection without waiting, and its last command can keep running on the access point; that command either moves its file before the next claim, which waits for the lock, or finds the newer token and does nothing, so a late old write cannot put back an older config such as a revoked password. A per-Sync temporary file alone would not stop that; the token check under the lock does. A claim of a Sync that timed out waiting for the lock can still land after a newer claim. The newer Sync's next write or reload then exits 75 (EX_TEMPFAIL, which no other failure of these commands returns), Sync stops and returns `ErrSuperseded`, and the next `Watch` tick claims afresh: a Sync behind a late claim is retried at the next tick, not at once. The reload runs under `timeout 20` and gets neither descriptor 9 nor the session's output, so a hung reload holds the lock, and the revocations behind it, for 20 seconds at most rather than ubus's 30-second call timeout, and nothing it leaves running holds the lock or the command open. Ending `reload_config` early loses nothing: it sends its change events before it records the configs' hashes, so a cut reload sends them again next time. Reads take no lock. The lock and token are on tmpfs, which a reboot clears along with every command; an access point without `flock` fails every claim and gets no write, and one without `timeout` fails every claim too (`command -v timeout`, exit 69, `ErrNoTimeout`), so nothing is written that no reload could apply (#4429). Only a newer claim exits 75: a `reload_config` that itself exits 75 exits 1. A write after a reboot between the claim and the write finds no token file and exits 75 too; that is right, since the reboot ended the claim, and the next tick claims afresh. `TestCommandsUnderShell` runs the commands under `sh` with util-linux `flock` and coreutils `timeout`, paths moved into a temporary directory. | NET-3, brief slice g | A late claim retried at once would need a second claim per Sync. |
| ENF-g-11 | **The live run on the OpenWrt One checks what CI cannot** (briefs/ENF.md: live runs are later rows' work). Busybox `ash`, `flock`, `timeout`, `sha256sum` and `cut` run push's commands as dash, util-linux and coreutils do in `TestCommandsUnderShell` (busybox `timeout` ends `reload_config` alone, not its children); `reload_config` applies only changed configs and sends its events before it records their hashes; uhttpd with ENF-g-2's config listens on loopback alone; and dropbear reaps the commands a Sync that timed out leaves behind, both a claim waiting behind a held lock and a `cat` whose stdin never ends and whose temporary file the next claim has unlinked, so neither holds a process or flash space for long. | NET-3, brief slice g | A failed check reopens ENF-g-10's commands. |
| ENF-g-12 | **The enforcer's key is root on the access point, with no access-point-side command allowlist** (#4087 item 3; Mark chose no allowlist and a reset step instead, on the Decisions 8 card, 2026-11-03). A `command=` forced command allowing only push's commands over `ap.Paths` would still let a stolen key write `/etc/dropbear/authorized_keys` without it, and any key that may write the UCI files can run code as root through them (an fw4 `config include` script, a dnsmasq `dhcpscript`). So the access point holds what the enforcer's key allows whatever its shell allows, and the key's protection is its storage on the enforcer (slice l). After any enforcer compromise the owner factory-resets the access point and re-pins its new host key (owner's guide, "If the enforcer was compromised"): the reset clears every file and key the old key could have written, and the re-pin is the only way past ENF-g-8's pin, which refuses the reset access point's new key. A factory reset restores the firmware's own read-only image and does not undo a firmware the key flashed over it; that residual is accepted. The re-pin is an owner step over the wired admin port, never automatic on a key change, and is slice l's to build with the first pin. The guide's hold time for the reset button (about 10 seconds; OpenWrt's button script resets on a hold of 5 or more) is checked on the OpenWrt One in ENF-g-11's live run. | NET-3 | An access point that checks what it is sent (a signed config, a fixed file set it validates) would make an allowlist worth having. |
