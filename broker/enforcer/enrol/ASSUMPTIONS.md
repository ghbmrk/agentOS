# Enforcer enrolment: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice c, #3663).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-c-1 | **The setup secret and the factory-reset code are one case code.** SPEC names a setup secret "printed inside its case" for the first passkey and a factory-reset "code printed inside its case"; the brief calls both the case code. It enrols a passkey only when none is in force (factory state, or after a reset by it), so it is never a second way in beside the passkey. It is not the setup network's Wi-Fi password, which is the sticker's (HW-10). The image's first boot stores its verifier (`Provision`); the seller or flasher prints the code. | NET-4 Enrolment and recovery, NET-2 Hardening, HW-10 | Two printed codes need two verifiers and a phase each. |
| ENF-c-2 | **Codes are stored as salted SHA-256 verifiers.** The recovery code is 20 base32 letters (100 bits), made on the enforcer, shown once in the enrolment answer, and replaced by a new one at every enrolment, so a used recovery code is spent. The case code must be at least 16 letters. At that entropy a slow hash adds nothing; misses are capped at 10 an hour per boot (in memory) all the same. | NET-4 ("kept as a verifier") | A shorter, human-chosen code would need a slow hash and a persisted miss count. |
| ENF-c-3 | **A new passkey proves it holds its key.** The page sends `getPublicKey()`'s SubjectPublicKeyInfo; the key must be ES256 on the enforcer's own name, and it must sign `DomainEnrol ‖ ticket ‖ key` with user verification before anything changes. The attestation is not checked: the owner's own phone makes the passkey, and the code, not the authenticator's maker, is what authorises it. | NET-4 Passkey rules | Requiring an attestation format would need a COSE/CBOR parser here. |
| ENF-c-4 | **The recovery code waits; the case code does not.** A replacement by the recovery code waits `Wait` (NET-4's 10 minutes), texts the owner at the start (`RecoveryCodeUsed`), shows on the page until it applies or is cancelled (`Alerts.Recovery`), and is cancelled only by a tap of the passkey in force. The case code enrols at once, as at first boot: it needs the case opened, at home, and SPEC gives the reset only "no loosening until new owner keys are enrolled". Every passkey that comes into force texts `Enrolment`. Per D-254 the light shows neither; `alert` decides that. | NET-4, NET-2 Hardening, D-254 | A wait on the case code would need the old passkey to stay live through a reset. |
| ENF-c-5 | **A factory reset keeps the policy and disarms its signer.** It cancels a waiting loosening, drops the passkey, the recovery code and any waiting replacement, and calls `policy.Engine.Disown`, so the engine takes no signed proposal from anyone while tightenings still apply. The Owner network and its password stay: the reset is for lost keys, not a lost network. | NET-2 Hardening | — |
| ENF-c-6 | **A new passkey keeps the policy by signing it.** The policy's stored versions verify under one passkey only (ENF-a-2). When a passkey comes into force over a policy that holds something, the engine is disowned and the page asks the new passkey to sign the policy in force, unchanged, at a higher version (`KeepProposal`, `Keep`, `policy.Engine.Rekey`); until then nothing loosens. An empty policy passes at once. A loosening the old passkey signed and that still waits is cancelled when the new one comes into force. The book records the passkey it is moving to before the engine saves, and `OpenPolicy` finishes a Keep cut short by a stop. | NET-4, STO-4, ENF-a-2 | Keeping old passkeys as verifiers of old versions would let a stolen old passkey forge stored history. |
| ENF-c-7 | **The setup network goes first.** With no passkey in force, `Finish` asks slice g's access point to replace the setup network (`Network.Replace`, idempotent) before it enrols anything, so an enrolment never leaves the sticker working; if the access point cannot be told, nothing enrols and the owner retries. The Owner network's card is shown once, in the enrolment answer, and the page asks for its last four characters before telling the owner to rejoin. | HW-10, D-178, CH-9 | — |
| ENF-c-8 | **The page follows the book.** The page is built for the passkey in force (`page.Config.Owner`) and takes a tap only while `Book.Owner()` still equals it; after an enrolment, a recovery applied or a reset, slice l builds it again. `Book.Tick` runs on the daemon's clock beside `policy.Engine.Tick`, without the policy lock held. | NET-6 | — |
| ENF-c-9 | **First contact over HTTPS.** The enrolment screen serves the enforcer's root certificate and the core's page authority for the phone to install (CH-9). How a phone with neither first reaches the page without a warning (risk 29, unqualified) is slice l's listener and qualification. | CH-9, risk 29 | — |
