# Clean-room builder: assumptions

Built for P4-2 (clean-room builder) against SPEC v0.12 OSS-2, OSS-3, and
OSS-5, on the hint schema and emitter (P4-1, PR #40) and the VM lifecycle
(P1-4). The leakage audit as a whole (A12), publication and its metadata
(OSS-6), attestations (OSS-8), and release signing are later packages.
Each row is a reading of the spec, or a gap left for a later package, that
a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| C1 | **Intake takes only exact canonical hints.** `Send` (the emitter's `hint.Outbox`) re-encodes each hint with the public schema's `Canonical` and refuses anything not byte-identical: another schema version, key order, spacing, escapes, extra keys, an embargo mark the schema does not give the kind. A batch is checked whole and queued by one directory rename, so it is taken whole or refused whole, and the emitter can resend it. The queue holds at most `MaxQueue` (64) jobs; past that a batch is refused (`ErrFull`). | OSS-1, OSS-2 | — |
| C2 | **A clean room is a fresh machine, never a fork.** Each job gets a new machine `cr-<job>` from the configured clean-room image, labelled public (REV-5), in the `Experiment` admission class (spare capacity, LOOP-1; preemptible). The builder checks before starting and on every poll that the machine is on that image, still public, and has no fork base; a result from a machine that fails the check is refused and the job fails. | OSS-2, REV-5, RES-1 | — |
| C3 | **What a clean room can reach is its own socket, and the socket serves three paths:** `GET /cleanroom/hint` (the canonical hint), `POST /cleanroom/result`, and `/model/...` (the model route behind the OP-8 meter, under the clean room's own machine ID). Anything else is 404: no `/mcp` (executors), no `/owner` (owner channel). The vault, journal, recall index, and workspaces are host files the sandbox never mounts; the machine has no network but its socket (V15, `--network=none`). Proved under gVisor with canaries (`TestIntegrationCleanRoomCannotReachPrivateData`). | OSS-2, ARC-6 | — |
| C4 | **The services mux keeps clean rooms off the guest plane.** `Builder.Services(plane)` is the vm manager's `Services`. An ID with the `cr-` prefix gets a clean-room socket only while a job runs it and is otherwise refused (so the machine cannot start); it is never handed to the plane, even if something else creates, forks, or resumes a `cr-` machine. Every other ID goes to the plane. | OSS-2 | `agentosd` must wire it this way (C10). |
| C5 | **Public internet (read-only) is not served yet.** OSS-2 lets a clean room see the public internet read-only; here it sees none, because uncredentialed egress by label (ARC-6 (d), guest G6) is not built. When it is, a public-labelled clean room gets it like any public machine. Until then the clean-room image must carry the public material it needs (the public repository, documentation snapshots). Potency cost: no live lookups. | OSS-2, ARC-6 | ARC-6 (d) package. |
| C6 | **The clean-room image is built from public material only:** the public repository, a toolchain, synthetic fixtures, and the guest that runs the job. That is a property of the image build (P2-1), not something the builder can check at run time; the builder only checks the image name. | OSS-2 | P2-1 builds and names it. |
| C7 | **Output rules.** A result is 1 to 256 UTF-8 text files, each at most 1 MiB, at most 8 MiB in all, with relative paths of plain segments (no `..`, no leading dot, no empty segment, no file that is also a directory), and reports its tests on the synthetic fixtures: at least one passed, none failed. A refused result can be fixed and resent until the job's time runs out; an accepted one ends the job. The fixture count is the clean room's own report; nothing re-runs it here. Independent re-running is what attestations (OSS-8) and local requalification (CHG-4) do. | OSS-2 | A verify run on a second fresh clean room if reviewers want it before publication. |
| C8 | **Artifacts are the only publishable thing.** The store keeps each result with a provenance manifest (hint, output type, image, machine, day, fixture counts, per-file SHA-256); `ReadFile` checks the hash. `Artifact` has no exported fields, so only this package makes one: a publisher that takes `Artifact`s can publish nothing else. The output type follows the hint kind (`skill_gap` → skill, `adapter_gap` → adapter, `vuln` → regression), not the guest's choice. | OSS-2, OSS-3 | Publisher package takes `Store.Publishable()`. |
| C9 | **Embargo (OSS-5, hint K2).** An artifact rebuilt from an embargo kind (`vuln`) is held: `Publishable` leaves it out and `Embargoed` lists it for the encrypted private-report path, until that path calls `ClearEmbargo`. The mark comes from the schema via the canonical hint, never from the clean room. | OSS-5 | Private-report package wires `Embargoed` and `ClearEmbargo`. |
| C10 | **Lifecycle.** One job at a time. A job has `Timeout` (2 h) of wall time per machine and `Attempts` (2) machines; a machine that cannot be created (no spare capacity) leaves the job queued without spending an attempt and is retried after `Retry` (1 min). A preempted clean room is resumed on its socket. The machine is destroyed when the job ends, however it ends. On start, `Run` destroys any `cr-` machine a previous run left; its job, still queued, starts again. An artifact stored just before a crash finishes its job on restart. Every finished job is logged (`Outcomes`, 0600) with its hint kind, result, and artifact or reason. | OSS-2, RES-1 | — |
| C11 | **Not wired into `agentosd` yet.** Nothing emits hints until Loops 1 and 2 (P3), and the clean-room image comes from P2-1. Wiring then: `vm.Config.Services = builder.Services(plane)`, the emitter's `Outbox` is the builder, `Model` is the same metered route as other machines with `vm.Manager.DataLabel`, and `Run` runs beside the vm manager. | OSS-2 | Wiring package. |
| C12 | Socket paths must fit the 108-byte Unix limit: the state directory's path should stay under about 60 bytes. | — | — |
