# Clean-room builder: assumptions

Built for P4-2 (clean-room builder) against SPEC v0.12 OSS-2, OSS-3, and
OSS-5, on the hint schema and emitter (P4-1, PR #40) and the VM lifecycle
(P1-4). The leakage audit as a whole (A12), publication and its metadata
(OSS-6), attestations (OSS-8), and release signing are later packages.
Each row is a reading of the spec, or a gap left for a later package, that
a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| C1 | **Intake takes only exact canonical hints.** `Send` (the emitter's `hint.Outbox`) re-encodes each hint with the public schema's `Canonical` and refuses anything not byte-identical: another schema version, key order, spacing, escapes, extra keys, an embargo mark the schema does not give the kind. A batch is checked whole and queued by one directory rename, so it is taken whole or refused whole, and the emitter can resend it. The queue holds at most `MaxQueue` (64) jobs; past that a batch is refused (`ErrFull`). `Send(day, batch)` is idempotent by day, as the emitter requires (it resends a day's recorded bytes after a crash): a day already taken is acknowledged and not queued again, across restarts (`days/<day>` holds the batch's hash; records older than 60 days are pruned). A batch whose bytes differ from the one taken for its day is refused (`ErrDayTaken`) and logged, never dropped silently. An empty marker (written before batch hashes) acknowledges the resend and takes its hash. Jobs carry that day, not the clock's, and so does the artifact manifest. A hint identical to one queued or already built is coalesced (logged `coalesced`, potency PR1), not built twice. | OSS-1, OSS-2 | — |
| C2 | **A clean room is a fresh machine, never a fork.** Each job gets a new machine `cr-<job>` from the configured clean-room image, labelled public (REV-5), in the `Experiment` admission class (spare capacity, LOOP-1; preemptible). The builder checks before starting and on every poll that the machine is on that image, still public, and has no fork base; a result from a machine that fails the check is refused and the job fails. | OSS-2, REV-5, RES-1 | — |
| C3 | **What a clean room can reach is its own socket, and the socket serves three paths:** `GET /cleanroom/hint` (the canonical hint), `POST /cleanroom/result`, and `/model/...` (the model route behind the OP-8 meter, under the clean room's own machine ID). Anything else is 404: no `/mcp` (executors), no `/owner` (owner channel). The vault, journal, recall index, and workspaces are host files the sandbox never mounts; the machine has no network but its socket (V15, `--network=none`). Proved under gVisor with canaries (`TestIntegrationCleanRoomCannotReachPrivateData`). | OSS-2, ARC-6 | — |
| C4 | **The services mux keeps clean rooms off the guest plane.** `Builder.Services(plane)` is the vm manager's `Services`. An ID with the `cr-` prefix gets a clean-room socket only while a job runs it and is otherwise refused (so the machine cannot start); it is never handed to the plane, even if something else creates, forks, or resumes a `cr-` machine. Every other ID goes to the plane. | OSS-2 | `agentosd` must wire it this way (C10). |
| C5 | **Public internet (read-only) is not served yet.** OSS-2 lets a clean room see the public internet read-only; here it sees none, because uncredentialed egress by label (ARC-6 (d), guest G6) is not built. When it is, a public-labelled clean room gets it like any public machine. Until then the clean-room image must carry the public material it needs (the public repository, documentation snapshots). Potency cost: no live lookups. | OSS-2, ARC-6 | ARC-6 (d) package. |
| C6 | **The clean-room image is built from public material only:** the public repository, a toolchain, synthetic fixtures, and the guest that runs the job. That is a property of the image build (P2-1), not something the builder can check at run time; the builder only checks the image name. | OSS-2 | P2-1 builds and names it. |
| C7 | **Output rules.** A result is 1 to 256 UTF-8 text files, each at most 1 MiB, at most 8 MiB in all, with relative paths of plain segments (no `..`, no leading dot, no empty segment, no file that is also a directory), and reports its tests on the synthetic fixtures: at least one passed, none failed. The manifest keeps that report as `ClaimedFixtures`: self-reported, never an attestation (review R3). A refused result can be fixed and resent until the job's time runs out; an accepted one ends the job (the guest gets its answer before the socket closes). Instead of a result a clean room may post `/cleanroom/unable` with the one fixed reason `needs_public_material`: the job is logged `parked` and kept aside, and `Requeue` runs parked jobs again once public egress exists (potency PR2), coalescing any hint already queued or built; parked `vuln` jobs stay parked, since their clean rooms stay offline (PS1). A result is first staged under a hidden name that no listing sees, then committed by one rename under the session lock only while the job is still live; a job that failed meanwhile (e.g. the machine stopped being clean), a failed commit, or a crash before the commit leaves nothing publishable, and staged leftovers are deleted at start (review R1, round 2 B3). The fixture count is the clean room's own report; nothing re-runs it here. Independent re-running is what attestations (OSS-8) and local requalification (CHG-4) do. | OSS-2 | A verify run on a second fresh clean room if reviewers want it before publication. |
| C8 | **Artifacts are the only publishable thing.** The store keeps each result with a provenance manifest (hint, output type, image, machine, day, fixture counts, per-file SHA-256); `ReadFile` checks the hash. `Artifact` has no exported fields, so only this package makes one: a publisher that takes `Artifact`s can publish nothing else. The output type follows the hint kind (`skill_gap` → skill, `adapter_gap` → adapter, `vuln` → regression), not the guest's choice. | OSS-2, OSS-3 | Publisher package takes `Store.Publishable()`. |
| C9 | **Embargo (OSS-5, hint K2).** An artifact rebuilt from an embargo kind (`vuln`) is held: `Publishable` leaves it out and `Embargoed` lists it for the encrypted private-report path, until that path calls `ClearEmbargo`. The mark comes from the schema via the canonical hint, never from the clean room. | OSS-5 | Private-report package wires `Embargoed` and `ClearEmbargo`. |
| C10 | **Lifecycle.** One job at a time. A job has `Timeout` (2 h) of wall time per machine and `Attempts` (2) machines; a machine that cannot be created for lack of capacity (admission `ErrNoRoom`, `ErrPressure`, or a revoked admission) leaves the job queued without spending an attempt and is retried after `Retry` (1 min); any other `Create` error spends an attempt, so a job that can never start leaves the queue (review R4). A preempted clean room is resumed on its socket. The machine is destroyed when the job ends, however it ends. On start, `Run` destroys any `cr-` machine a previous run left; its job, still queued, starts again. An artifact stored just before a crash finishes its job on restart. `Run` keeps running when the queue cannot be read, logging and retrying after `Retry`. Every finished job is logged (`Outcomes`, 0600) with its hint kind, result, and artifact or reason. | OSS-2, RES-1 | — |
| C11 | **Not wired into `agentosd` yet.** Nothing emits hints until Loops 1 and 2 (P3), and the clean-room image comes from P2-1. Wiring then: `vm.Config.Services = builder.Services(plane)`, the emitter's `Outbox` is the builder, `Model` is the metered route with `vm.Manager.DataLabel`, `Meter` is the loops' spare meter (`loops.Config.Spare`), not the guests', and `Run` runs beside the vm manager. `Config.Env` and `Config.Argv` are static broker configuration and never carry owner data (review R5). Clean-room model calls are metered under their own OP-8 scope on the capped evaluation budget, never the owner's task budget, and reach the owner only as one aggregate line in the weekly hint summary (UX-43-1, Security R1, Potency PR3). | OSS-2, OP-8 | Wiring package. |
| C13 | **Conditions on later packages (review of #43, auto-decided: no lens gets worse).** **K1 (P2-1):** the clean-room image is reproducible from public inputs, with a manifest the leakage audit can check; no box-local files, state, credentials or secret environment variables. **K2 (publisher, OSS-6/8):** fixture counts are shown as self-reported, never as an attestation; before OSS-8 exists the publisher either re-verifies in a second fresh clean room or publishes with no pass claim (its choice); it gets a reduced manifest view, so `frequency`, the job ID and the machine ID never leave the box. **K3 (OSS-5):** only the private-report path calls `ClearEmbargo`, enforced by an import fence. **PC1 (before P3 emits):** until ARC-6 (d) lands, the emitter holds `adapter_gap` hints with `changed_api` or `changed_layout`. **PC2:** a versioned build brief per hint kind lives in the public repository and is read from the image. **PS1 (amends C5):** `vuln` clean rooms stay offline even after ARC-6 (d). **Security R2 (relay):** model requests from public machines that reference provider-stored file IDs are refused. | OSS-2, OSS-5, OSS-6, OSS-8 | Each named package. |
| C12 | Socket paths must fit the 108-byte Unix limit: the state directory's path should stay under about 60 bytes. | — | — |
