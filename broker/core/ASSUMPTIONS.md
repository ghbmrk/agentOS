# Trusted core list: assumptions

Built for SIM-core (briefs/SIM.md, ARC-1). Each row is a reading of the brief, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| CO1 | The check is a Go test (`broker/core/core_test.go`), so CI's existing `go test ./...` in broker runs it; no workflow change. It type-checks each non-core package against the compiler's export data from `go list -export -compiled -deps`, using only the standard library (no x/tools in the module), so calls through embedded fields, method values and generic instantiations resolve to the core symbol they reach. | ARC-1 | Move to a vet analyzer if x/tools is vendored. |
| CO2 | "Write path" fails closed: every core function or method is one unless core.txt marks it `open` (the journal's Submit, reads, pure helpers, the sanctioned childproc, guesterr, verb and meter interfaces) or `allow`s one named caller with a reason. Types, constants and fields are not checked: reading a core type or building a value of it writes nothing. | ARC-1 | Add a line kind if a field write must be caught. |
| CO3 | `grants.Gate.Submit` counts as the journal's Submit: it is the same call behind the gate's refusal of broker-reserved intent IDs. | ARC-1 | Route callers to `journal.Engine.Submit` and drop the open line. |
| CO4 | Wiring packages (`daemon`, `cmd/agentosd`, `cmd/agentos-egress`, `cmd/agentos-a8scan`) build and connect the core, so they may call any write path and are rated A with the core. | ARC-1 | Shrink wiring as SIM-bound moves code out. |
| CO5 | A non-core package that declares an interface a core type satisfies (named or literal, so `x.Decide` on an interface value) reaches each core method behind it; the check counts those as calls and needs an open or allow line for them, named by the declaring package (an alias such as `loops.Journal = change.Journal` reports under `change`). **Known gap (later):** a write path handed to a non-core package as a func value, or reached by `//go:linkname` or `reflect`, is not caught. Wiring is tier A, so each func-value hand-off is reviewed at A; linkname and reflect need intent and show in a diff. | ARC-1 | A dynamic check, or a lint on func-valued Config fields. |
| CO6 | `tools/risk_tier.py` reads core.txt: a file under a core or wiring package is A, as is the list and its check (`broker/core`). Under Tier-A-narrow (#1698), `TIER_A_BROKER` lists the other packages that meet a criterion (credential, effect or approval, owner-channel input) and does not repeat core or wiring packages; `allow`-line packages that meet a criterion are listed too. `TIER_B_BROKER` lists the rest (say `broker/attention`), and a broker package in neither list is A. | ARC-1 | Classify each new broker package in one list in the PR that adds it; `test_every_broker_package_is_classed_once` fails otherwise. |
| CORE-fixture-imports-a | **Fixtures enforce their own rule.** `allow` lines for `loops/loopstest` and `kernel/sim` grant wildcards because only tests link them (#2848). Each fixture's `init` panics unless `testing.Testing()`, so any binary `go test` did not build stops at start, whatever route reached the files: a build tag, another GOOS, a symlinked, replaced or vendored copy. A static walk keyed on routes failed four review rounds on #3040, one new route each time. `TestAFixtureStopsABinaryGoTestDidNotBuild` builds and runs a binary per fixture and fails if it runs. A fixture is an allow-line package whose name ends in `test`, or `kernel/sim`, so a new one is checked as soon as it gets an allow line. `TestFixturesAreImportedOnlyByTests` is only a fast pre-filter over the host build, to name the mistake in CI; routes it does not model are the guard's. **Known gaps:** the guard is a run-time stop, not a link-time one, so a shipped binary that links a fixture fails when it starts rather than in CI. `testing.Testing()` reads a value `go test` sets with `-ldflags -X testing.testBinary=1`, so a release build that passes that flag defeats it; release build flags are in workflows reviewed at their own tier. An edited copy without the guard is new code, and `TestNoWritePathOutsideTheCore` judges its calls like any other package's (in the host build; #3043 covers build-constrained files). | ARC-1 | Mark fixtures in core.txt instead of by name (#3044). |
| CORE-buildtags-host | **Build coverage of the write-path check.** `TestNoWritePathOutsideTheCore` runs under three builds (`builds` in core_test.go): the host with cgo, linux/amd64 with `agentos_e2e`, and a partial darwin/arm64 build. Under the darwin build, 53 of 145 first-party packages are skipped (measured at 7f2fc34): 9 fail to compile, 42 depend on one that fails, and 2 are test-only. As a result, `netguard/netlink_other.go`, `localui/listen_other.go` and `cmd/agentosd/delegate_other.go` are type-checked by no build. No build covers a GOOS other than linux or darwin, or a GOARCH constraint; no first-party file uses one today. No binary ships for a non-linux GOOS, so this is a coverage gap, not a false pass. On a non-linux host, `TestEachBuildChecksItsOwnFiles` checks only that the host build finds the one `grants.Gate.Decide` call, since both cgo.go and other.go compile there. | ARC-1 | Add a build when a binary ships for another GOOS or GOARCH, or when a first-party file gains such a constraint. |
