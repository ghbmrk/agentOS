# Model router and provider adapters: assumptions

Built for PLAN P2-7 ("provider adapters: two frontier providers") against
SPEC v0.11 on main plus the v0.12 draft (PR #15: ARC-6, OP-8), on top of the
egress proxy (P1-3). Covers `broker/route`. Each row is a reading of the
spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| R1 | The two providers are OpenAI and Anthropic, the two the egress proxy already declares (P1-3 E2). Both are API-key routes. A3 also asks for a consumer route; that waits on S6 (consumer CLIs in relay mode, needs Mark's accounts), and would arrive as a third `Provider` whose `Name` is a CLI relay rather than an egress adapter. | A3, CRED-5, ADP-3 | Add a provider per qualified route. |
| R2 | The guest keeps one interface, OpenAI chat completions (ARC-6 (a)); the router translates to each provider's API. So Anthropic is reached by the broker, never by a guest speaking the Messages API, and P1-3 E2's "not qualified as a guest interface" still holds. The router serves `POST /v1/chat/completions` and `/openai/v1/chat/completions`, the path a guest configured for the raw proxy already uses, so P1-7's `/model/` mount works unchanged. Wiring (whichever of #24 and this merges second): serve `meter.Wrap(id, router.Handler(id))` where the raw proxy is served now, and stop serving the raw proxy to guests. | ARC-6, CRED-5 | — |
| R3 | The `model` a guest sends names a **task class**, not a provider model. The active `Rule` maps each class to routes (provider, model) in preference order. Class names and models are owner configuration (onboarding); no model IDs are compiled in. An unknown class is 404 `model_not_found`. | CAP-9 | A classifier that assigns classes itself would be a later Loop 1 candidate. |
| R4 | The router decodes the guest body into typed structs and each provider re-encodes from them, nested fields included: content is a string or `text` and `image_url` parts; `tool_choice` is auto, none, required, or a named function; `response_format` is text, json_object, or json_schema; roles are system, developer, user, assistant, tool, and function. Anything else is refused (400), and unknown keys inside accepted objects are dropped, so e.g. `file_id` parts, `input_audio`, `user`, `metadata`, `store`, and `web_search_options` never reach a provider. The one untyped field is a function's `parameters` (and a `json_schema` schema), the guest's own JSON schema. The proxy's body rules still apply on top. | ADP-10, REV-5 | Add a field or part type when a qualified guest needs it. |
| R5 | A route is skipped, not failed, when its provider cannot express a valid call: for Anthropic, `n` other than 1, a non-text `response_format`, the legacy `function` role, non-text system, assistant, or tool content, a non-base64 data URL, or tool arguments that are not a JSON object. Temperatures above 1 are clamped to 1 (the Messages maximum). Penalties and `seed` are dropped for Anthropic (sampling hints, no Messages equivalent). Only when no route can express the call does the guest get 400. | ADP-3 | Per provider, in `Request`. |
| R6 | Failover statuses: 429 (rate limit or quota), 401 (rejected key), 529 (overloaded), 500, 502, 503, 504, plus a stream that fails before its first byte. They apply only to responses the provider sent: the proxy marks its own answers (`egress.DeniedHeader`, which a provider cannot set because response headers are allowlisted), and those, including its per-machine 429 caps, go to that machine's guest with no cooldown and no failover, so one machine cannot cool a route for others. A failed-over route is skipped for its `Retry-After` (seconds or HTTP date, capped at 1 h) or 60 s, and a guest told every route is cooling gets `Retry-After`. A provider cooldown is keyed by route, so it falls under one credential (one per provider) and one model; it never comes from the proxy. A 401 fails over silently, and `CredentialRejected` is called at most once per provider a day so the wiring can text the owner once. A provider's other errors (a 400) are the guest's answer and are not retried. Model calls are read-verb, so a second attempt has no external effect (OP-2 concerns effects). | CAP-9, ADP-7, OP-2 | Small: `failover`. |
| R7 | A failover happens only before any byte reaches the guest: stream headers are written on the first translated byte. A stream that breaks after that ends without `[DONE]`, and the guest retries. Each call reads at most `MaxResponse` (32 MiB) from the provider, streams included. | CAP-9 | — |
| R8 | Data labels: a machine whose label is not exactly `public` is private. Private calls go only to providers in `PrivateOK` (owner-marked at connection time); the default is none, so a private machine has no model route until the owner marks one. Checked before anything is sent; `SetRule` cannot override it. | CAP-9, REV-5 | — |
| R9 | Grants come from a `Granted(machine, provider)` function so the grant store (OP-5, built in parallel) plugs in without changing this package. The egress proxy enforces the same grant again. | CAP-9, OP-5 | Pass the grant store's lookup. |
| R10 | Scores: the router measures per route calls, successes, failovers, time to headers, and bytes, counting only outcomes the provider is responsible for (served calls and failovers, not 4xx answers or proxy denials). It never reorders the active rule itself. `Candidate` proposes an order (success rate, then mean latency); only `SetRule`, called when §11 adopts the candidate, changes routing. Owner acceptance and cost per route are not scored yet: acceptance needs the journal's OP-7 outcome records, and cost needs per-provider prices (usage is now reported, R14). Measurements are in memory and reset on restart. | ADP-4, CAP-9, LOOP-4 | Feed outcomes and prices into `Stats` when Loop 1 lands. |
| R11 | Decisions go to a required `Audit` function and carry no request or response content. Like the proxy's events (P1-3 E6), they are not journal records yet. | ADP-10 | Wire with the proxy's auditor. |
| R12 | The router holds no credential and opens no connection: it calls the proxy's handler in process through a pipe. A test pins this (no vault, egress, net, or TLS imports; no HTTP client). | CRED-1, CRED-5 | — |
| R13 | Fixtures are written from the providers' documented shapes (Anthropic Messages `2023-06-01`, OpenAI Chat Completions), not captured: the build sessions have no keys and no route to the APIs. A live capture on the box should replace them (`testdata/README.md`). | — | Replace with captures. |
| R14 | Usage: every served call's `Decision` carries the provider-reported usage (input, output, cache reads, cache writes), streamed or not and whether or not the guest asked for it: OpenAI streams always request `include_usage` (the usage-only chunk is dropped again if the guest did not ask), and Anthropic usage is read from `message_start` and `message_delta`. Output is capped: every call goes upstream with `max_tokens`/`max_completion_tokens` at or below the owner's ceiling (`MaxOutputTokens`, default 32,000), so the OP-8 meter can reserve input plus that ceiling before the call. Arbitrator ruling: reported usage on a complete response is authoritative; when `Reported` is false or `Complete` is false (a cut-off stream), the meter falls back to `OutputChars` (content and tool-argument characters the provider produced), which is also the floor for a cut-off stream. Doing that charging, rather than the larger of reported usage and the meter's own byte estimate is the meter's change (P1-7). | OP-8 (v0.12), CAP-9 | Tune the default with the budget re-estimate. |
| R15 | Prompt caching: Anthropic requests carry four ephemeral cache breakpoints (last tool, end of the system prompt, last two messages), the API's limit. Agent loops resend a growing prefix, and cache reads cost about a tenth of input. Cache reads are reported to the guest as `prompt_tokens_details.cached_tokens`, with prompt tokens including cached ones as in OpenAI's usage. OpenAI caches prefixes automatically. | CAP-9 (cost) | — |
| R16 | Redaction (CRED-7) runs in the proxy over provider bytes. A vault value split across two SSE deltas is not one byte run there, so it passes the redactor; this is defense in depth (P1-3 V4), and custody does not rely on it. Running a redactor over the translated text is a later option. | CRED-7 | Inject a `Redactor` if a canary shows the gap matters. |
