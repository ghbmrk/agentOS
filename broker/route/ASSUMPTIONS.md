# Model router and provider adapters: assumptions

Built for PLAN P2-7 ("provider adapters: two frontier providers") against
SPEC v0.11 on main plus the v0.12 draft (PR #15: ARC-6, OP-8), on top of the
egress proxy (P1-3). Covers `broker/route`. Each row is a reading of the
spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| R1 | The two providers are OpenAI and Anthropic, the two the egress proxy already declares (P1-3 E2). Both are API-key routes. A3 also asks for a consumer route; that waits on S6 (consumer CLIs in relay mode, needs Mark's accounts), and would arrive as a third `Provider` whose `Name` is a CLI relay rather than an egress adapter. | A3, CRED-5, ADP-3 | Add a provider per qualified route. |
| R2 | The guest keeps one interface, OpenAI chat completions (ARC-6 (a)); the router translates to each provider's API. So Anthropic is reached by the broker, never by a guest speaking the Messages API, and P1-3 E2's "not qualified as a guest interface" still holds. The wiring package serves `Router.Handler(machine)` where it now serves the proxy's handler (P1-7's `guest.Config.Model`), behind the OP-8 meter, and stops serving the raw proxy to guests. | ARC-6, CRED-5 | — |
| R3 | The `model` a guest sends names a **task class**, not a provider model. The active `Rule` maps each class to routes (provider, model) in preference order. Class names and models are owner configuration (onboarding); no model IDs are compiled in. An unknown class is 404 `model_not_found`. | CAP-9 | A classifier that assigns classes itself would be a later Loop 1 candidate. |
| R4 | The router decodes the guest body into a fixed struct and each provider re-encodes from it, so fields outside that struct never reach a provider (e.g. `user`, `metadata`, `store`, `web_search_options`). Only `function` tools are accepted. This is stricter than the proxy alone; the proxy's body rules (REV-5 remote sources, `store:false`, denied keys) still apply on top. | ADP-10, REV-5 | Add a field when a qualified guest needs it. |
| R5 | A route is skipped, not failed, when its provider cannot express the call: for Anthropic, `n` other than 1, a non-text `response_format`, non-text/non-image content, or tool arguments that are not a JSON object. Penalties and `seed` are dropped for Anthropic (sampling hints, no Messages equivalent). | ADP-3 | Per provider, in `Request`. |
| R6 | Failover statuses: 429 (rate limit or quota), 401 (rejected key), 529 (overloaded), 500, 502, 503, 504. The route is skipped for its `Retry-After` (capped at 1 h) or 60 s. Any other status, including the proxy's own denials (403, 413), is the guest's answer: a request that is wrong or forbidden on one route is not retried on another. Model calls are read-verb, so a second attempt has no external effect (OP-2 concerns effects); its cost is spend, which the OP-8 meter counts once per guest call. | CAP-9, ADP-7, OP-2 | Small: `failover`. |
| R7 | A failover happens only before any byte reaches the guest. A stream that breaks mid-way ends without `[DONE]`, and the guest retries. | CAP-9 | — |
| R8 | Data labels: a machine whose label is not exactly `public` is private. Private calls go only to providers in `PrivateOK` (owner-marked at connection time); the default is none, so a private machine has no model route until the owner marks one. Checked before anything is sent; `SetRule` cannot override it. | CAP-9, REV-5 | — |
| R9 | Grants come from a `Granted(machine, provider)` function so the grant store (OP-5, built in parallel) plugs in without changing this package. The egress proxy enforces the same grant again. | CAP-9, OP-5 | Pass the grant store's lookup. |
| R10 | Scores: the router measures per route calls, successes, failovers, time to headers, and bytes, but never reorders the active rule itself. `Candidate` proposes an order (success rate, then mean latency); only `SetRule`, called when §11 adopts the candidate, changes routing. Owner acceptance and cost per route are not measured here yet: acceptance needs the journal's OP-7 outcome records, and cost needs per-provider prices. Measurements are in memory and reset on restart. | ADP-4, CAP-9, LOOP-4 | Feed outcomes and prices into `Stats` when Loop 1 lands. |
| R11 | Decisions go to a required `Audit` function and carry no request or response content. Like the proxy's events (P1-3 E6), they are not journal records yet. | ADP-10 | Wire with the proxy's auditor. |
| R12 | The router holds no credential and opens no connection: it calls the proxy's handler in process through a pipe. A test pins this (no vault, egress, net, or TLS imports; no HTTP client). | CRED-1, CRED-5 | — |
| R13 | Fixtures are written from the providers' documented shapes (Anthropic Messages `2023-06-01`, OpenAI Chat Completions), not captured: the build sessions have no keys and no route to the APIs. A live capture on the box should replace them (`testdata/README.md`). | — | Replace with captures. |
