# In-image end-to-end run: assumptions

Built for G1-e2e (#1688). `box-e2e` drives first-boot setup inside the booted image as an owner's
phone would; `image/ci_boot.sh` injects it on a fourth QEMU boot. Each row is a reading a reviewer
may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| E1 | The run never changes the image. Its unit and two drop-ins (`image/e2e/`) arrive as SMBIOS type 11 credentials (`systemd.extra-unit.*`, `systemd.unit-dropin.*`), which systemd imports only in a VM, and the driver on a read-only 9p share. A shipped box has neither, so the run adds no path into a production box. | HW-1, HW-5 | If systemd ever honoured SMBIOS credentials on bare metal, gate the image on `ImportCredential=` instead. |
| E2 | QEMU has no radio, so a veth pair stands in for the access point: the box end is named `wlan0` at 10.42.0.1/24, the phone end sits in its own network namespace at 10.42.0.23, and `wlan0` joins `agentos_inbound`'s `exempt` set as `ap-exempt` would add it. `agentos-ap` is stopped. The setup page's own interface binding, address checks and same-origin checks are exercised; hostapd, the radio and DHCP on the AP are not (M6 Ultra session). | ONB-1, HW-1 | Use mac80211_hwsim if the kernel ships it, to cover hostapd too. |
| E3 | The claim is sealed after the first boot (`claim.Seal` with localui stopped, then started): `localui-claim` moves it into localui's state because the destination is still absent. This takes the same route as a claim written at first boot. | ONB-3 | If the move ever requires a first-boot marker, seal before localui's first start instead. |
| E4 | The modem is the AT simulator (`modem/atsim`, a SIMCom SIM7600G-H profile) behind a pseudo-terminal. A fake sysfs tree under `/run/agentos-e2e/sysroot` gives discovery its vendor and interface files, and its `ttyUSB2` node links to the pty slave, owned by `agentos-modem` as the udev rule would make it. A drop-in adds `-sys-root` and `DeviceAllow=char-pts rw`; a test keeps its command line equal to the shipped unit's plus `-sys-root`. Real USB enumeration, the udev rule and the radio are not exercised (M6 Ultra session). | CH-1, CH-12, HW-2 | If discovery reads more of sysfs, extend `buildSysroot`. |
| E5 | The phone's code generator is computed from the enrolment link's seed with the broker's own `owner.TOTP`; the card's prompt is answered from the saved sheet. Both prove the server's round trip, not an independent RFC 6238 or card implementation (those have their own package tests). | CH-10, ONB-3 | — |
| E6 | Steps run in the box's setup order (claim, network if offline, number and pairing, codes, card, recovery, this PC, AI), not the order #1688 lists them. After the first failure later steps print BLOCKED and do not run; a step on the expected-failure list prints XFAIL with its issue, and a listed step that passes fails the run (XPASS) so the list shrinks. | ONB-3 | — |
| E7 | The model-backed guest task is on the expected-failure list (#1701) until a model stub at the provider boundary exists; CI has no model secret. | ONB-3 | Remove the entry when #1701 lands. |
| E8 | Output is one console line per step. It never carries the claim code, card words, recovery key, vault passphrase, code-generator seed or a page body: a failure names the step, status codes, the location, the page's step heading and its sanitized error line. | ONB-3 | — |
