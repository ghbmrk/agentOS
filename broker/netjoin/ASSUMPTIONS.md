# Home Wi-Fi helper: assumptions

Built for P2-2w c3 (briefs/P2-2w-c3.md) against Security L8 in
[the L6-L8 note](../../reviews/security/2026-10-08-p2-2w-l6-l8.md), for ONB-1,
ONB-3, CRED-1 and ARC-2. Covers `broker/netjoin` and `broker/cmd/agentos-netjoin`.
Each row is a reading of the note or the spec, or a gap left for a later
package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| N1 | **The image installs and wires the helper (P2-1/c4; done in #1388, image I17).** This package ships the unit (`agentos-netjoin.service`), the polkit rule (`50-agentos-netjoin.rules`) and the binary's flags; the image creates the `agentos-netjoin` system user, installs all three, and passes agentosd `-netjoin-sock /run/agentos-netjoin/netjoin.sock`. Until it does, agentosd has no helper and the page's network step answers its one error. agentosd's unit sets no `User=`, so the helper serves uid 0 (`-agentosd-uid 0`). | L8.1, L8.2 | `agentos-netjoin.service`, agentosd's unit, the image. |
| N2 | **Release rows recorded, not built here:** #935 (c3 r3: NetworkManager's store must not leave the PSK in plaintext on the drive; encrypted volume or in-memory connections re-added after unlock, which would amend L8.7; its canary half is built: the A5 harness mints a `wifi_psk` kind, a WPA passphrase per N9, that every target is planted with and the scan fails on, while the store half waits on the sealed store, which SPEC v1.0 picks for the home Wi-Fi password (§6.1 custody exceptions, STO-2), #936 (c3 r4: a station device beside the access point, no seat or console session, `auth-polkit=true`, polkit 0.106+ for JS rules) and #926 (P2-1-roles: the image's writable paths for agentosd and the modem user, folded into the same P2-1 image work that installs this helper). Without #936's station device the helper answers `failed` (N13). | L8.6, L8 "What the radio does", CRED-8 | Rows #935, #936, #926; `test_wifi_psk_kind_is_a_valid_wpa_passphrase` and the A5 leaky controls in tests/test_canary.py. |
| N3 | **No busconfig narrowing (c3 r1).** The helper's D-Bus calls are limited by its code (`nmBus` makes three Settings calls and three property reads, tested against a recording bus) and by polkit to `settings.modify.system`; a compromised helper can still rewrite or delete any connection and read stored secrets. This is the note's accepted residual. | L8.2, L8.3 | A busconfig file and its parse test (row c3 r1). |
| N4 | **NetworkManager 1.22 or later.** `AddConnection2` and `Update2` (with `TO_DISK`, flag 0x1) and the error name `org.freedesktop.NetworkManager.Settings.InvalidConnection` for an unknown UUID are NetworkManager's D-Bus API from 1.22. Any other lookup error is `failed`, never "create a new one", so the one connection is not duplicated. | L8.3 | `cmd/agentos-netjoin/main.go` constants. |
| N5 | **The outcome is read, never caused.** The helper snapshots the active connections carrying the fixed UUID before its write and watches only new ones: `ACTIVATED` is `joined`, `DEACTIVATED` or vanishing is `not_joined`, nothing within `Wait` (25 s) is `saved`. A re-join while the old connection stays active is therefore `saved`, which the page also shows as success. It activates nothing, holds no `network-control`, and takes no device or the access point down. | L8.4 | `netjoin/join.go`. |
| N6 | **One join at a time.** A second request while one runs answers `busy` at once rather than queueing, so a stuck NetworkManager cannot pile up callers; the socket admits two connections. | L8.4 | `Joiner.Join`. |
| N7 | **Timeouts nest.** The helper's wait (25 s) ends before agentosd's call (`CallTimeout`, 30 s), which ends before the page's (`localapi.JoinTimeout`, 34 s), which ends before the bridge's outbox wait plus slack (35 s). Each caller waits longer than the one it calls, so an answer is never lost to an outer timeout. | L8.4 | `netjoin.Wait`, `netjoin.CallTimeout`, `localapi.JoinTimeout`. |
| N8 | **godbus's `os/exec` is unreached.** godbus runs `dbus-launch` only for session-bus autolaunch and `launchctl` only on macOS; the helper calls `ConnectSystemBus` alone and its unit sets no environment (D-108). | L8.5, DEP-1 | `main.go`, D-108. |
| N9 | **SSID and PSK rules.** An SSID is 1-32 bytes, any value (NetworkManager takes `ay`); a PSK is 8-63 printable ASCII characters or exactly 64 hex digits. agentosd checks only the shape (1-32, 8-64 bytes) and leaves the exact rule to the helper. SAE-only and hidden networks are LATER f2 and f3; changing the Wi-Fi after setup is LATER f1. | L8.4, L8.5, L8.8 | `netjoin.Valid`. |
| N10 | **The scan is read-only and needs no polkit action (c4b).** It reads `Devices`, `DeviceType`, `Ssid` and `Strength` and calls `Device.Wireless.GetAllAccessPoints`, all of which NetworkManager answers to any system-bus client; it never calls `RequestScan` (polkit `wifi.scan`), so it lists only what NetworkManager has already seen. A radio serving the setup access point may have seen nothing until #936's station device; the page then takes a typed name, as before. The box's own setup access point may appear in the list (LATER). | L8.2, L8.3, ONB-3 | `cmd/agentos-netjoin/main.go`, `50-agentos-netjoin.rules`. |
| N11 | **Names only, and only showable ones.** The scan answers at most 20 SSIDs, strongest first, each once; no BSSID, frequency or strength leaves the helper. A name is shown only if it is 1-32 bytes of UTF-8 with no control or format (Cf) character, so a name using a zero-width joiner is not listed but can still be typed. agentosd's client re-checks count and names. | CRED-1, L8.6 | `netjoin.Showable`, `netjoin.MaxNetworks`. |
| N12 | **The box's own networks are never listed (#1281).** The scan drops every name starting `apnet.Prefix` ("AgentOS-"), which covers the setup network (`claim.SetupSSIDPrefix`, "AgentOS-Setup-") and the card's, so the strongest network in range, usually the box's own, is never offered as the home Wi-Fi; the page's list also opens on a disabled "Choose your network" placeholder, so nothing is preselected. A home network whose name starts "AgentOS-" is not listed but can still be typed. A prefix rather than the box's exact SSID keeps the scan free of agentosd's state. | ONB-3 | `Scanner.Scan`, `TestTheScanLeavesOutTheBoxsOwnNetworks`. |
| N13 | **The join never takes the access point's interface (S-R4, #1428; DEV-2, CH-7; amends L8.4's list by one key).** `agentosd → agentos-netjoin → NetworkManager` does not pass through `localui.APLoader.Station`: the loader lives in `agentos-ap`, and NetworkManager autoconnects whenever it likes after a join returns, so wrapping the call could not cover later activations. So the helper refuses instead, and pins the connection: it takes `-station <if>` (the one interface the home connection may use, #936's station device) and `-ap-iface <if>` (repeatable, `agentos-ap`'s `-iface`), and `Join` answers `failed` before any D-Bus call unless `StationOK`: the station is a plain interface name (`^[a-zA-Z0-9_.-]{1,15}$`, not `.`, `..` or `lo`), at least one access point interface is given, each one plain, and none equals the station. `failed` is what agentosd maps to "use Ethernet" (#1429, localui L48), which is the right answer for a box with no usable station device, and nothing is written. `ConnectionSettings` adds `connection.interface-name` = the station, the helper's own flag and never the request's, so NetworkManager activates the home connection on no other device now or at a later autoconnect. The unit passes `-ap-iface wlan0` and no `-station` until #936 ships one, and `TestTheUnitRefusesTheAccessPointInterface` holds every `-iface` in `agentos-ap.service` inside its `-ap-iface` list. Rests on: `agentos_ap` only ever holding `agentos-ap`'s `-iface` (`agentos-ap` calls `APLoader.Up` with nothing else; a table left by an older image's other interface is cleared by `APLoader.Start` before any join, localui L34, DEV-net-i); the exempt set holding no other wireless interface (its other members are agent-machine links); NetworkManager honouring `interface-name` for autoconnect and manual activation; no home connection saved by an earlier image without the key (none shipped: NetworkManager is not in the image yet). netjoin cannot read `agentos_ap` itself: it has no `CAP_NET_ADMIN` and only `AF_UNIX`, by design (L8.1). The station on the same radio as the access point (a station virtual interface beside it, #1495) is #936's to build and name. | S-R4, L8.4, DEV-2, CH-7 | `join.go` `StationOK`, `netjoin.go` `ConnectionSettings`, `cmd/agentos-netjoin` flags and unit; #936 sets `-station`. |
