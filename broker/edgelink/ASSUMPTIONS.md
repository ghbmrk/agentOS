# edgelink: assumptions

Built for EDGE-link-core slice c1 (#3296, `briefs/EDGE-link-core.md` decisions 4 to 6) against HW-15, HW-17 and PLN-3. `broker/edgelink` is the wire of the edge link: the frame codec, the kind table, the hello and the TLS configurations. It holds no key and opens no socket; `agentos-link` (c2) does. Each row is a reading a later change could overturn.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| EDGE-link-c1-1 | **The header is big-endian.** Decision 6 fixes the fields and their widths but not the byte order; network order is used, and the edge-side row reads it from `AppendFrame`. | HW-15 | A different order is a version 2 frame, never a silent change. |
| EDGE-link-c1-2 | **Every kind but the hello names an origin.** Decision 6 bounds the origin at 1024 bytes and the hello's is empty; the other kinds' origin column is always something (a URL, a number, a device name), so an empty origin on them refuses (`ErrOriginLength`). | HW-15 | If a kind needs no origin, its table row says so. |
| EDGE-link-c1-3 | **The streams are three: `ToEdge`, `FromEdge` and `Hello`.** "Direction" in decision 6 and the two connection modes of decision 5 are one choice at the reader: a served connection reads `FromEdge` (no hello), a hello-mode connection reads `Hello` (only a hello). A hello on a served connection is `ErrDirection`. | HW-15, decision 5 | — |
| EDGE-link-c1-4 | **The core's certificate is not self-signed by the core's key.** Decision 4 lets `linksign` sign only a server CertificateVerify input, so the core's key cannot sign its own certificate. `ServerConfig` signs it with a throwaway key; the edge pins the core's key, not the certificate, and the CertificateVerify proves the core holds it. The edge's certificate is self-signed, as decision 5 checks. | Decisions 4 and 5 | If the edge-side row needs a self-signed core certificate, enrollment (b) makes one once while the link key is in its hands, and `ServerConfig` takes it. |
| EDGE-link-c1-5 | **TLS's signer calls are guarded here too.** TLS reaches the signer only through a guard that refuses anything but a TLS 1.3 CertificateVerify input for its side's context (RFC 8446 §4.4.3) and any prehashed request, the check `linksign` will make in the kernel. Go's TLS 1.3 asks an Ed25519 signer for exactly that input, once per full handshake. | Decision 4 | A Go release that signs anything else fails the handshake, not the check. |
| EDGE-link-c1-6 | **No resumption.** Session tickets are off on the server and the client keeps no cache, so every connection runs a full handshake with a fresh client CertificateVerify and the core asks the kernel about the key each time (decision 5 "never cached across one"). | Decision 5 | — |
| EDGE-link-c1-7 | **The edge's client configuration requires a pin.** `ClientConfig` refuses an empty pin. Decision 5's pre-store exchange, where the edge cannot yet know the core's ephemeral key, is the edge-side row's to define (Unowned gaps); this package offers no unpinned client. | Decision 5, Unowned gaps | The edge-side row adds an explicitly named first-contact configuration. |
| EDGE-link-c1-8 | **Key exchange is X25519MLKEM768 only** (D-149's hybrid rule), and `PeerKey` refuses a state that negotiated anything else. It needs Go 1.24 or later; `go.mod` is on 1.26. A `GODEBUG` that turns the group off makes every handshake fail, never fall back. | D-149, decision 5 | — |
