# Home-network address policy: assumptions

Built for BOARD row DEV-net-a (tier A, egress) against SPEC DEV-2, REV-5, ARC-6, CAP-2 and CAP-13. Each row is a reading of the spec, or a gap left for DEV-net-b, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| N1 | Resolve, then check every answer, then connect to a literal address through a `net.Dialer` whose `ControlContext` runs the same check. One refused answer refuses the whole dial (strict), so a name cannot mix a public and a private answer. Nothing is cached: a name that rebinds is checked again at its next dial. A connection already open stays in the transport's pool; it was verified when made. | DEV-2, REV-5 | A caching resolver needs a TTL cap of zero or a re-check on reuse. |
| N2 | The refused set is the IANA IPv4 and IPv6 special-purpose registries plus multicast and `::/8`, including the entries the registry marks globally reachable (192.0.0.9, 192.31.196/24, 192.52.193/24, 192.175.48/24): a broader table is simpler to state and the home network gains nothing from them. 64:ff9b::/96 (NAT64) is not refused as such; the IPv4 it embeds decides, as for 6to4 (refused whole) and ISATAP. IPv4-mapped addresses are unmapped first. The table is a snapshot of the registries and is not fetched at run time. | DEV-2 | A registry change is a table edit. |
| N3 | Learned, not configured: the uplink and access-point prefixes (a global IPv6 prefix longer than /56 is widened to its /56, the unit a residential ISP delegates; an IPv4-mapped prefix of /96 or longer is the IPv4 prefix it carries, and an IPv6 prefix that as learned, before that widening, holds the whole `::ffff:0:0/96` mapped range also adds `0.0.0.0/0`, since a mapped destination is unmapped before the check), the gateway, the router's external address, and the assigned resolver. `Learn` replaces the whole set; `Watch` refreshes on each address or route event. A failed read keeps the last set. The learning source (netlink, DHCP, RA) is the caller's: it is not in this package. | DEV-2 | A source that fails closed would need a startup state with no network. |
| N4 | The router's external address comes from one NAT-PMP opcode-0 request (`ExternalAddr`); a PCP gateway answers it through RFC 6887 Appendix A. No MAP or PEER request, no UPnP, no SSDP. It is a datagram to the gateway, not a connection under the guard, and is the one place this package dials outside the hook. | DEV-2 | A gateway that answers neither leaves the external address unlearned; the rest of the policy still applies. |
| N5 | Exactly four exceptions, each scoped by a `Purpose` in the context, never by the destination alone: (1) the assigned resolver on port 53, `PurposeDNS`; (2) a compute host's pinned endpoint, `PurposeModelCall`; (3) a device executor's pinned device, `PurposeDevice`; (4) an owner-pinned backup target (`PurposeBackup`) or private hosted route (`PurposeModelCall`). The zero purpose, which every agent request and ordinary dial carries, gets none, and the learned resolver is refused to it. Device and backup are hooks only: no executor or backup exists yet. | DEV-2, CAP-13, DEV-1, BAK-1 | A fifth exception is a SPEC change. |
| N6 | A pin matches on its address and port or on the name dialed, and always carries the SHA-256 of the server's SubjectPublicKeyInfo. `TLSConfig` verifies a pinned name by that key alone (a home device's certificate is usually self-signed) and fails the handshake with `ErrPinMismatch` on any other key, before any request byte. An unpinned name gets ordinary chain and name verification against the base config's roots. Pins are set by the caller; where an owner enters them is not here. | DEV-2, CAP-13 | A device with a rotating key needs a re-pin flow (DEV-net-b or later). |
| N7 | The package does not install, scan or probe anything on a compute host or any other machine; it only refuses or allows dials the broker itself makes. | CAP-13 | none |
| N8 | `tools/netguardcheck.py` is a per-file regex check, not a type check: a file that imports `broker/netguard` is trusted to use it for every dial in the file. Unix-socket dials and `testdata/` are exempt. The only file listed in `tools/netguard_allow.txt` is the guest bridge (ARC-7), which runs inside the agent machine, not on the box. | DEV-2 | A per-call check needs the Go type checker (a vet analyzer). |
| N9 | The egress process learns the home network on each kernel address, route or link event, or change to the IPv4 default gateway's neighbour entry (netlink `RTMGRP_*` with `RTMGRP_NEIGH`, `WatchNetlink`) and every 10 s as the backstop (`netWatchEvery`): interface addresses, `/proc/net/route` and `/proc/net/ipv6_route`, and `resolv.conf` (systemd-resolved's file first). Each event applies the quick local read at once (`Sources.ReadLocal`, no NAT-PMP wait, takes the external address last read on that gateway; `Policy.quickLearn` keeps the learned resolver when the quick read has none, while the gateway is unchanged); the full read runs single-flight on its own goroutine, so a later event is never queued behind a slow router lookup. The event feed and the poll tick feed one worker (`WatchEventsEvery`), so two full reads never run at once and a stale one cannot put back an old external address after a newer read (#1439). A full read that began before a later learn is stale: it never replaces the newer set and only its external address is kept while the gateway is unchanged (`Policy.gen`). While the gateway is unchanged, a quick read keeps the policy's learned external address and ignores its own copy (`ReadLocal`'s copy can predate a newer full read); the merge and the store run under one write lock, so a full read cannot store a newer external address between them (#1492). In the mirrored order, a quick read that lands after a full read has asked the router but before it stores, the full read is stale and its newer external address is stored through that stale-read rule. When the gateway changes, a quick read takes its own external address, never the previous network's. `Sources` keeps the last external address per gateway, the 8 most recently read gateways (`maxGatewayExternals`), so a return to a known gateway refuses that gateway's own external address from the quick read on (#1517); a full read on a gateway whose router does not answer keeps that gateway's entry. On a gateway with no known external address, a quick read starts a hold: a destination every other rule allows, which may be the router's not-yet-learned external address, waits until that gateway's full read stores (fresh, or stale on the same gateway, answered or not) and is then decided against the new set. The hold fails closed: after 7 s (`externalHold`) or when the dial's context ends, the destination is refused. While that gateway's full reads keep failing (no interface address, an unreadable route table), every public dial waits the full bound before it is refused. The bound is past one full read's two router requests (`externalReadTimeout`, `natpmpDeadline`); a read the gateway moves under twice and the read after it can together pass it, which refuses (fail closed). DNS to the resolver and pinned endpoints are not held. The hold applies only where the policy has a full-read source (`Config.Source`). A gateway is its address, its default route's interface and its MAC (#1536): the MAC is the complete neighbour entry (`/proc/net/arp`, flag `ATF_COM`, not all zeros) for the gateway address on that interface, and an absent entry counts as its own value, so a different router behind the same address, or one whose entry a link flap flushed, has no known external address and starts the hold; the interface keeps a point-to-point gateway with no entry apart from the same address on another link. A router swapped with no link event at the box is noticed through the neighbour event for the gateway's address (other hosts' entries are ignored), else by the next poll (10 s). A full read reads the host again after each NAT-PMP request, answered or timed out. If the gateway is unchanged (address, interface and MAC), the answer is filed under that gateway and returned. A MAC unknown at the start and known after the request counts as a change: the request may have reached another router behind the same address, so its answer is filed under no gateway, and a known router's stored address stays (#1725); a read that starts with no entry therefore asks twice, and one whose second request also starts with no entry ends in `ErrGatewayMoved`. If it changed, the answer is dropped and the read asks the gateway it ended on once more, so a full read that succeeds always asked the router of the network it returns, and a silent end router stores none, as on any silent router. A second change returns `ErrGatewayMoved` with the end network and files nothing; the policy then applies that network as a quick read does (a gateway with no known external address starts the hold) and the worker runs another full read at once. A read whose host read fails after the request returns that failure and files nothing. IPv6 gateways carry their interface but no MAC (there is no IPv6 neighbour table file), and store no external address: NAT-PMP to a link-local gateway is dialled without a zone and fails (`EINVAL`), so on an IPv6-only uplink a gateway change holds public destinations only until that gateway's full read, whose router request fails at once; that read ends the hold and public destinations are then allowed. Recheck if PCP over IPv6 is added. A burst of events coalesces into one pending refresh; the netlink goroutine logs if it ends on an error; a netlink overflow counts as an event. Where netlink cannot be opened the poll alone applies and the failure is logged. A read that finds no non-loopback interface address fails, so the last learned set stays. | DEV-2 | Test: a prefix added at one event is refused with the poll an hour away; `TestRefreshInQuickGapKeepsNewerExternal` (a real `Sources` whose router address changes between a quick read and its store keeps and refuses the newer address, and the merge holds the write lock); `TestQuickInRefreshGapKeepsNewerExternal` (a quick read in a full read's gap while the router address changes: the newer address is learned and refused); `TestQuickLearnGatewayChangeDropsOldExternal` (a flip-back G1, G2, G1 takes G1's external address from the quick read and refuses it at once); `TestSourcesKeepExternalPerGateway`; `TestNeverSeenGatewayHoldsPublicUntilFullRead`; `TestNeverSeenGatewayHoldFailsClosed`; `TestStaleFullReadOnNewGatewayEndsHold`; `TestExternalHoldOutlastsTwoRouterReads`; `TestHoldSparesDNSAndPins`; `TestNoHoldWithoutFullReadSource`; `TestHoldEndsThroughTheWatchWorker`; `TestEgressProcessGuardReadsWithOneWorker`; `TestSameGatewayNewRouterHoldsPublicUntilFullRead`; `TestSourcesTellRoutersApartBehindOneGatewayAddress`; `TestGatewayChangeDuringNATPMPAsksTheEndGateway`; `TestTimedOutNATPMPAcrossAMoveAsksTheEndGateway`; `TestFailedReadAfterNATPMPFilesNothing`; `TestTwoAnsweringRoutersAtOneAddressKeepTheirOwn`; `TestGatewayKeyedByInterface`; `TestPolicyGatewayKeyedByInterface` (ppp0 with no entry, then wlan0 with no entry at the same address: the hold opens, ppp0's router address is not carried over, and wlan0's is refused after its full read); `TestInterfaceMoveDuringNATPMPAsksTheEndGateway`; `TestGateway4InterfaceIsTheChosenRoutes`; `TestMovedFullReadDoesNotOverwriteNewerLearn`; `TestIPv6OnlyGatewayChangeHoldEndsAtFailedRead`; `TestNetlinkSocketSubscribesToNeighbourEvents` (the kernel reports the socket's groups, `RTMGRP_NEIGH` among them); `TestFullReadAcrossGatewayChangeAsksTheEndRouter` (an address move, the same address with a new MAC, and a flushed entry, each with and without an event); `TestFullReadMovedTwiceHoldsUntilNextRead`; `TestWatchRereadsAfterGatewayMoved`; `TestStaleFullReadOfOldRouterKeepsNewRoutersHold`; `TestNetlinkEventsAreAddressRouteLinkAndGatewayNeighbourChanges`; `TestGatewayMAC`; `TestUnknownStartMACThenRouterSwapKeepsTheEndRoutersAddress` (no entry at the start, router A answers and B replaces it, B's request times out: B's stored address is returned and stays refused). |
| N10 | With no resolver learned, names do not resolve (fail closed), and `PurposeDNS` reaches only the learned resolver on port 53 over tcp or udp. A loopback or link-local nameserver is never learned (a loopback resolver is also dropped by `Learn`), and the next entry is tried. A host whose resolver is DNS-over-TLS (port 853), or whose `resolv.conf` lists only a loopback stub, does not resolve until that is changed. | DEV-2 | Learn the stub's upstream, or allow the encrypted-DNS port for the learned resolver. |
| N11 | Plain IMAP or SMTP to a literal loopback address (the box-local mail bridge) dials without the guard; any other host, TLS or not, goes through it. `skill.MCPEffects` has no default client and refuses without one. | DEV-2 | none |
| N12 | Owner pins are vault entries named `netpin:<label>` of kind `netguard-pin`, holding `{kind: backup/hosted/compute, name, addr, key}` with the SHA-256 of the endpoint's TLS public key. They are read when the vault opens (`custody.serve`) and cleared on lock or expiry (`discard`), so a locked box reaches no pinned endpoint. A bad record is skipped and logged by label, never by value. Only the owner pin command writes them: `agentos-egress pin` over the unlock socket, tier 4 (an approval code, used once, plus local confirmation), with `unpin` and `pins` beside it. Pinning a label again replaces it: that is the re-pin when an endpoint's key or address changes, and until then the endpoint's handshake is refused. The guard takes the new list before the command returns. A refusal names the problem, never a value, and is checked before the code is spent. `custody.put` still refuses these entries from the local page. With no entry the pin list is empty. Device pins (`PinDevice`) are not owner-entered here. | DEV-2, BAK-1, CAP-13 | Tests: no pin by default; a pin reaches only its address, port, purpose and key; the pin ends with the unlock; pinning needs an open vault and a fresh code; a pinned backup and hosted endpoint are reachable and a compute host with a wrong key is refused; re-pin replaces the key and unpin removes it; `custody.put` refuses a pin. |
| N13 | The inbound rule set (`netguard.InboundRules`) renders the `agentos_inbound` nftables table (input hook). Every interface is dropped by default except those in its `exempt` set: loopback at boot, and the access point's interface, which P2-1's `agentos_ap` loader adds (`nft add element inet agentos_inbound exempt { "<ap>" }`) because a drop in this table is final and `agentos_ap` could not override it. Agent machines run without host network links (gVisor `--network=none`), so none is exempt. Admitted from any other interface: replies, router advertisements from a link-local source and neighbour solicitations and advertisements from any source, all with hop limit 255 (RFC 4861), DHCP and DHCPv6 replies, and the listed device sources, ports and discovery ports. The image ships the default rendering as `/usr/lib/agentos/inbound.nft` (a test keeps it equal to `InboundRules(Inbound{})`), loaded at boot as described in image I11. | DEV-2 | Tests evaluate the rendered rules for an unlisted source, port and interface and for neighbour discovery, run `nft -c` where permitted, and run the shipped file in network namespaces (tests/test_inbound_netns.py). |
| N14 | `netguard.InboundExemptRemove(<if>)` renders the removal of one interface from the `exempt` set as `add element …; delete element …` in one `nft -f` transaction, so it succeeds whether or not the element is still there and never flushes the set (which may hold other links). It refuses `lo` and any name `ifaceRe` refuses. Removing an element closes that interface; it never opens the drop (DEV-net-g). `localui.BringUp`/`BringDown` run it when the access point stops or fails. | DEV-2 | Test renders it and refuses bad names; tests/test_inbound_netns.py loads the same script. |
