# Home-network address policy: assumptions

Built for BOARD row DEV-net-a (tier A, egress) against SPEC DEV-2, REV-5, ARC-6, CAP-2 and CAP-13. Each row is a reading of the spec, or a gap left for DEV-net-b, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| N1 | Resolve, then check every answer, then connect to a literal address through a `net.Dialer` whose `ControlContext` runs the same check. One refused answer refuses the whole dial (strict), so a name cannot mix a public and a private answer. Nothing is cached: a name that rebinds is checked again at its next dial. A connection already open stays in the transport's pool; it was verified when made. | DEV-2, REV-5 | A caching resolver needs a TTL cap of zero or a re-check on reuse. |
| N2 | The refused set is the IANA IPv4 and IPv6 special-purpose registries plus multicast and `::/8`, including the entries the registry marks globally reachable (192.0.0.9, 192.31.196/24, 192.52.193/24, 192.175.48/24): a broader table is simpler to state and the home network gains nothing from them. 64:ff9b::/96 (NAT64) is not refused as such; the IPv4 it embeds decides, as for 6to4 (refused whole) and ISATAP. IPv4-mapped addresses are unmapped first. The table is a snapshot of the registries and is not fetched at run time. | DEV-2 | A registry change is a table edit. |
| N3 | Learned, not configured: the uplink and access-point prefixes (a global IPv6 prefix longer than /56 is widened to its /56, the unit a residential ISP delegates), the gateway, the router's external address, and the assigned resolver. `Learn` replaces the whole set; `Watch` refreshes on each address or route event. A failed read keeps the last set. The learning source (netlink, DHCP, RA) is the caller's: it is not in this package. | DEV-2 | A source that fails closed would need a startup state with no network. |
| N4 | The router's external address comes from one NAT-PMP opcode-0 request (`ExternalAddr`); a PCP gateway answers it through RFC 6887 Appendix A. No MAP or PEER request, no UPnP, no SSDP. It is a datagram to the gateway, not a connection under the guard, and is the one place this package dials outside the hook. | DEV-2 | A gateway that answers neither leaves the external address unlearned; the rest of the policy still applies. |
| N5 | Exactly four exceptions, each scoped by a `Purpose` in the context, never by the destination alone: (1) the assigned resolver on port 53, `PurposeDNS`; (2) a compute host's pinned endpoint, `PurposeModelCall`; (3) a device executor's pinned device, `PurposeDevice`; (4) an owner-pinned backup target (`PurposeBackup`) or private hosted route (`PurposeModelCall`). The zero purpose, which every agent request and ordinary dial carries, gets none, and the learned resolver is refused to it. Device and backup are hooks only: no executor or backup exists yet. | DEV-2, CAP-13, DEV-1, BAK-1 | A fifth exception is a SPEC change. |
| N6 | A pin matches on its address and port or on the name dialed, and always carries the SHA-256 of the server's SubjectPublicKeyInfo. `TLSConfig` verifies a pinned name by that key alone (a home device's certificate is usually self-signed) and fails the handshake with `ErrPinMismatch` on any other key, before any request byte. An unpinned name gets ordinary chain and name verification against the base config's roots. Pins are set by the caller; where an owner enters them is not here. | DEV-2, CAP-13 | A device with a rotating key needs a re-pin flow (DEV-net-b or later). |
| N7 | The package does not install, scan or probe anything on a compute host or any other machine; it only refuses or allows dials the broker itself makes. | CAP-13 | none |
| N8 | `tools/netguardcheck.py` is a per-file regex check, not a type check: a file that imports `broker/netguard` is trusted to use it for every dial in the file. Unix-socket dials and `testdata/` are exempt. Three files carry unhooked dialers today and are listed in `tools/netguard_allow.txt` with a reason (the SMS provider client, the IMAP and SMTP client, the skill webhook step); DEV-net-b hooks them and empties the list. | DEV-2 | A per-call check needs the Go type checker (a vet analyzer). |
