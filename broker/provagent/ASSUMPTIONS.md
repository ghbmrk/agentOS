# Provider-agent route: assumptions

Built for BOARD CAP-11-plan (#1314) on the plan-login chain (#807, #1015, #1014). The route is wired deny-by-default in agentosd: it stays closed until #809 fills the Codex qualification record and CRED-5c, #1264 and #1380 land.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| P1 | The Codex declaration is verdict `allowed` (#1377, D-117) with an empty qualification record, so every run refuses `unqualified` until #809 records the pinned CLI version, evidence pointer, terms URL and date. A record whose CLI version differs from the image's, or `not-allowed`, refuses the same way. | CAP-11, D-114 | #809 changes the built-in under tier A review. |
| P2 | Claude Code is worker-held, verdict `unclear`, and always refuses `opt-in-required` here; #1380 builds the opt-in. `unconfirmed` runs only with the owner's recorded consent (CRED-5c), which agentosd does not yet supply (Consent is false). | CAP-11, CRED-5 | #1380 and CRED-5c provide the grant sources. |
| P3 | The brief reaches the CLI on stdin only, never argv, so `/login` and `!cmd` text is data. Deviation from the brief's "declared result file": stdout is redirected inside the worker to a result file and stderr to /dev/null, so the CLI's own output is the result and no raw stderr is ever journaled. `TestCommandUnderARealShellKeepsOnlyStdout` runs `Command` under a real `/bin/sh` with a fake CLI that writes a canary to stderr: the result holds stdout only, in the declared cwd, with only the declared env. The journal holds metadata only. Whether the result should be the CLI's last-message file instead of the `--json` stream is open (security finding 6, L3 finding 13). | CAP-11, CRED-7 | A CLI that writes its own result file needs a declared path. |
| P4 | The command is `env -i` with exactly the launch.json env, then `wrap`, then `argv` (#1850). No login is handled here; the seed is a placeholder via `RouteControl.Seed`. | CRED-5, #1015 | Env or wrap form changes in #1850. |
| P5 | A refused login and a credit draw are read on the broker's own upstream connection, never in the result file the agent can write (#1856). agentos-egress reads a refused refresh by its codex-rs codes (`refresh_token_expired`, `refresh_token_reused`, `refresh_token_invalidated`; `invalid_grant` is excluded because the guest's request controls client and scope), and a credit draw or reached limit as an `Exhausted` reading from the `X-Codex-Credits-*` headers. After a run, `Usage` is read again: a refusal at or after the run's start is `login-refused`, and an exhausted reading at or after it is `used-up`, so no run draws credits unmetered. The codes and headers are unmeasured until #809. A guest cannot forge a refusal: at worst a real refresh it triggers fails, which only stops the route. `UsedUp` stays matched only inside the CLI's own JSON error events (`ErrorEvents`), never in the agent's messages. A refused login stops that provider's route: later runs refuse `login-refused` without seeding or starting a worker, and `SignIn` is called once, until `Runner.SignedIn` lifts it. The stop is held in the Runner, so a broker restart clears it; journaling it is CRED-5b's. | CAP-9, CRED-5, CRED-5b, OP-8 | #809 measurement confirms or replaces the codes and headers; CRED-5b persists the stop. |
| P6 | The result is scanned for provider credential formats (CRED-7) and withheld on a match. The scan is a tripwire only; the worker holds placeholders. | CRED-7 | Encodings beyond the tripwire's formats are not detected. |
| P7 | Admission (RES-5) fails closed on the broker's readings, aggregated per provider across every worker (`Usage`). No source or no reserve, a NaN reading or reserve refuses `pool-at-reserve`; an unreachable source refuses `route-busy`. A reading is current when it is under `MaxAge` old (default 10 minutes) and its reset, if stated, is still ahead. A pool at or below the owner's reserve refuses until its reset passes (the reset is its cooldown); with no reset stated it refuses while current. **Probe rule:** a pool with no current reading (never read, stale, or past its reset) makes the run a probe, since the only way the broker reads a plan is a call on its own connection. A probe runs alone (no other run of that provider in flight) and at most once per `MaxAge`; a probe that failed before the CLI ran is forgotten. At most `PerPool` (default 2) runs of a provider are in flight. Decision boundary: with a nonzero reserve, one probe may draw a pool past the reserve before its first reading; an active read that spends nothing is a release follow-up once #809 shows the endpoint. | RES-5, OP-5 | #809 shows a free usage read; a per-provider cap other than 2. |
| P8 | A wall-clock cap wraps the Execs; the worker is destroyed on every exit path, and a Destroy error goes to the broker's log. The Seeder's errors are provagent's own sentinels, which agentosd maps from `modelroute`: a locked vault is `vault-locked`, a stalled or contended route (any other 503) is `route-busy` (#1857), both fallbacks; a missing plan login is `unsigned` and sets the sign-in line once (#1858). Only a broker-held declaration is seeded, and agentosd seeds Codex only (the control socket mints Codex placeholders); a create that fails after the seed closes the route, so the placeholders are forgotten. | CAP-9, CRED-5b | |
| P9 | ARC-2: `provagent` imports only `admission` and `vm` (guest plane, `forbiddenStd`). The worker tools name the run through `workers.ProviderRunner` and its own request and reason types; agentosd adapts the Runner to it and `modelroute.RouteControl` to the Seeder, so neither `workers` nor `provagent` links the model route's HTTP client. | ARC-2 | |
| P10 | agentosd inputs and who wires them: `Usage` reads agentos-egress's `/usage` through `RouteControl.Usage` (#1856, wired). `Reserve` is 0 for every pool (`ownerReserve`, RES-5/ONB-9 "Kept for your own use: 0%"); the ONB-9 owner setting (OP-5 budget row) replaces it. Still unwired: `ImageVersion` returns "" (the image's pinned `CODEX_VERSION`, with #809), `Journal` is nil (OP-8 run metering and charge, to be filed), `SignIn` is nil and nothing calls `SignedIn` (#1264 sign-in, CRED-5b resume), `Granted`, `PrivateOK` and `Consent` are false (CRED-5c, #1264). #1701's end-to-end step needs each of these. | CAP-11, OP-8, ONB-9, RES-5 | The owner-setting row wires `Reserve`. |
