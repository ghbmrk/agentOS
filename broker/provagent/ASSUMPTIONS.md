| P5 | A refused login and a credit draw are read on the broker's own upstream connection, never in the result file the agent can write (#1856). agentos-egress reads a refused refresh by its codex-rs codes (`refresh_token_expired`, `refresh_token_reused`, `refresh_token_invalidated`; `invalid_grant` is excluded because the guest's request controls client and scope), and a reached limit or a credit draw (a pool at 100%, `X-Codex-Rate-Limit-Reached-Type`, or a lower `X-Codex-Credits-Balance` than the route last read) as an `Exhausted` reading. After a run, `Usage` is read again: a refusal at or after the run's start is `login-refused`, and an exhausted reading at or after it is `used-up`; if `Usage` cannot be read after the run, the run fails `route-busy` rather than pass unchecked. A run that times out, or whose Exec or result read fails, still reads `Usage` for a refusal since its start and stops the route on one, keeping its own outcome; an unreadable `Usage` there is logged and stops nothing, which rests on egress still recording the refusal after the run's context ends (#1891 item 2). The credit rule covers less than every draw: a lower balance is seen only between two calls of one route (each run has a fresh worker and route), so a draw on a run's first call, in a one-call run, or between runs is seen only when a reached-limit type or a pool at 100% comes with it, and an unparseable balance reads as no draw (#1891 item 3). The codes and headers are unmeasured until #809. A guest cannot forge a refusal: at worst a real refresh it triggers fails, which only stops the route. `UsedUp` stays matched only inside the CLI's own JSON error events (`ErrorEvents`), never in the agent's messages. A refused login stops that provider's route: later runs refuse `login-refused` without seeding or starting a worker, and `SignIn` is called once, until `Runner.SignedIn` lifts it. The stop is held in the Runner, so a broker restart clears it; journaling it is CRED-5b's. | CAP-9, CRED-5, CRED-5b, OP-8 | #809 measurement confirms or replaces the codes and headers; CRED-5b persists the stop. |
| P6 | The result is scanned for provider credential formats (CRED-7) and withheld on a match; CAP-11-plan-fu4-P17 says which formats. The scan is a tripwire only; the worker holds placeholders. | CRED-7 | Encodings beyond the tripwire's formats are not detected. |
| P7 | Admission (RES-5) fails closed on the broker's readings, aggregated per provider across every worker (`Usage`). No source or no reserve, a NaN reading or reserve refuses `pool-at-reserve`; an unreachable source refuses `route-busy`. A reading is current when it is under `MaxAge` old (default 10 minutes) and its reset, if stated, is still ahead. A pool at or below the owner's reserve refuses until its reset passes (the reset is its cooldown); with no reset stated it refuses while current. **Probe rule:** a pool with no current reading (never read, stale, or past its reset) makes the run a probe, since the only way the broker reads a plan is a call on its own connection. A probe runs alone (no other run of that provider in flight) and at most once per `MaxAge`; a probe that failed before the CLI ran is forgotten. At most `PerPool` (default 2) runs of a provider are in flight. Decision boundary: with a nonzero reserve, one probe may draw a pool past the reserve before its first reading; an active read that spends nothing is a release follow-up once #809 shows the endpoint. The cap is per provider, where RES-5 says per pool: every Codex run draws both its pools, so the two agree; a provider with disjoint pools (Claude's model-specific weeks) revisits it (#1856 review L3, later). | RES-5, OP-5 | #809 shows a free usage read; a per-provider cap other than 2. |

Only a broker-held declaration is seeded, and agentosd seeds Codex only (the control socket mints Codex placeholders); a create that fails after the seed closes the route, so the placeholders are forgotten. | CAP-9, CRED-5b | |

| P11 | **Sign-in runs the provider's own CLI flow (ONB-3 step 6, CRED-5, #1264).** `StartSignIn` runs the declared `SignInArgv` (`codex login --device-auth`) in a fresh private provider worker whose route `SignInFor` marked, so the vault process opens it on the sign-in endpoints only and stores the login the owner approves there (egress `ForSignIn`); no run worker can store a login. `SignInArgv` points the CLI's issuer at the worker's forwarder with `--experimental_issuer http://127.0.0.1:18432` (#1701: no image config ever set it, so the CLI dialled `auth.openai.com` from a worker with no network and exited without a code), so the CLI asks the forwarder for its code, prints the forwarder's device page, and sends the `redirect_uri` egress's code check expects (`TestONB3CodexSignInIssuerIsTheForwarder`); CLI 0.162.1 run against a fake issuer on that port printed `http://127.0.0.1:18432/codex/device` and the code; `SignInPrompt` accepts only a declared `SignInLinks` entry and always shows the declared `SignInPage` (`https://auth.openai.com/codex/device`), the same pair egress `PlanRoute.SignInLink` accepts (`TestONB3CodexSignInMatchesTheEgressCheck`). | ONB-3, CRED-5 | The CLI's device page changes, or a CLI bump drops the hidden `--experimental_issuer` flag (the sign-in then fails `failed`, never signs in elsewhere). |
| P12 | **The prompt's shape is assumed, not measured.** The CLI prints the device page link and then a code shaped `[A-Z0-9-]{4,16}` on its output; ANSI escapes are stripped and the first code-shaped token after the first declared link is taken. A look-alike link, no code, or a CLI that exits before printing one refuses `failed`; no prompt within `SignInTimes.Link` (1 min) refuses `timed-out`. Only the link and the user code leave the worker: the user code is the feature (the owner types it on the provider's page). | ONB-3, CRED-7 | #809's live run measures the output; a changed shape refuses rather than guessing. |
| P13 | **The CLI keeps running after its Exec returns.** `SignInCommand` starts the CLI in the background with its output and exit status in files under the worker's cwd, and exits 0, so the Exec returns while the owner approves (up to `SignInTimes.Wall`, 15 min). This rests on the worker runtime keeping a command's children alive until the worker is destroyed (vm Exec's gVisor note); `TestONB3SignInCommandUnderARealShellRunsInTheBackground` checks the shell half. The sign-in counts only when the vault process reports that this worker's own sign-in stored the login (`SignInStored`, egress K29's `/signedin`): a login already stored (the refused one a re-sign-in replaces) and the CLI's exit status are not signals, so a CLI that exits 0 without a code exchange signs nothing in, and one that cannot write its own auth file after the vault stored the login still signs the owner in. The CLI's exit, `SignInTimes.Wall` or the runner's `Background` context ends the wait; every path destroys the worker, which closes its route. One sign-in per provider runs at a time (`ErrSignInBusy`); `SigningIn` reports it from the claim until the wait ends, and the Wi-Fi page keeps a started sign-in's code only while it holds (#1945). `SignIn` and `OnSignedIn` run under the runner's lock, in the same hold that sets or lifts the stop, so a refusal racing a sign-in cannot leave the route stopped with the line off. | ONB-3, CRED-5 | A runtime that reaps an Exec's children breaks the flow; it then times out and signs nothing in. |
| P14 | **Nothing of the sign-in is logged or shown beyond the link and code.** The CLI's output and status files are read only for the prompt and the exit status; tokens, the authorization code and `device_auth_id` pass only between the CLI and the vault process's route. The runner's log lines carry the provider, worker ID and a fixed outcome; a refused start (#1701) also logs the step that refused it with the machine plane's error, the start Exec's exit status, or the CLI's exit status, which is quoted only when the status file holds a number, since the CLI can write that file (signin_test.go checks a canary in the CLI output or status file never reaches a log or the result). vm's errors name machine ids, images and paths, never a command's output. | CRED-7, OP-8 | |

| P16 | **A worker starts on the declaration's idle command (#1721).** runsc refuses a container whose process has no args, so `Run` and `StartSignIn` create the worker with `Argv: Idle`; the CLI, and its sign-in, run beside it by Exec, which P13 already rests on. `Idle` is absolute (`/bin/sleep infinity`) so it does not depend on the runtime's PATH, the Codex image copies `/bin/sleep` (tests/test_codex_rootfs.py runs it in the built tree), and `TestCodexBuiltinMatchesLaunchJSON` pins it to `guest/codex/launch.json`'s `idle`. `Validate` refuses a declaration with none. | CAP-11, ONB-3 | If a runtime gains an init that waits on its own, drop `Idle`. |
| CAP-11-plan-fu4-P17 | **Each declaration carries its credential formats (CAP-11-plan-fu4, #1879).** `CredFormats` are Go regular expressions; `Validate` and `Run` refuse a declaration with none, one that does not compile, or one that matches the empty string (FMT-4, outcome `unqualified`). `Run` withholds a result that matches the default scan or any declared format. The Codex JWT and refresh-token shapes are measured from a supervised live sign-in with CLI 0.162.1 (#2313, spikes/S8-live/RESULTS.md); the refresh token is 196 characters in dot segments 2.1.191 over `[A-Za-z0-9_]` with no prefix. Its format (#2352) needs both short segments and a tail of at least 160 characters over base64url (`-` allowed), since one sample fixes neither the alphabet nor the length, and it has no leading word boundary, so a JSON escape, percent-encoding or a joined character before the token does not hide it; ordinary text still does not match. The public `rt_` refresh shape stays declared alongside it, narrowed to case-sensitive `rt_` plus at least 40 characters over `[A-Za-z0-9._-]` (main's alphabet, dot kept) so code identifiers such as `rt_sigprocmask_…` do not match: the issuer is server-side, so one measurement does not show the old shape is gone. In place of a plain leading word boundary it also accepts, and consumes, a JSON escape (`\n`, `\t`, `\u0022`) or a percent-encoded byte (`%22`, `%3D`) before `rt_`, so an escaped or percent-encoded token is redacted whole (#2354 Security); an `rt_` token joined to a word character (`x`, `_`) is not matched, the price of keeping `rt_` inside identifiers out. The Codex API-key shape and the Claude shapes are still the public ones, since a plan sign-in issues no API key and Claude is not measured. A token in a shape the measurement missed (a tail under 160 characters, another alphabet), or an `rt_` token under 40 characters or joined to a word character, passes this tripwire; the worker still holds only placeholders (P6) and egress holds the refresh (P5). `vault.Redactor.WithFormats` scrubs the same formats, leftmost-longest. A `Writer` for a redactor with formats holds back the last `FormatMaxLen`-1 (4095) bytes of every write, match or not, and holds a format match running to the end of what it has seen until it ends, if shorter than `FormatMaxLen` (4096 bytes); of a longer match only the first 4096 or more bytes are redacted and its tail may be emitted, since the built-in formats are start-anchored (a prefix, or the Codex refresh token's two short dot segments). `TestFormatStreamHoldBounds` pins both bounds. agentosd's main.go is unchanged: the scan is per declaration inside `Runner`. Wiring the formats into the vault process (agentos-egress) is a follow-up release issue; that wiring must bound the `Writer`'s cost, since it rescans its 4095-byte hold-back on every write (O(n·4096/w) for writes of w bytes; Security on #2354). | CRED-7, CAP-11 | A new CLI version is re-measured with `run.sh shapes`; the vault-process wiring lands. |
| CAP-11-plan-fu1-P18 | **OP-8 journal is wired (#1876); this supersedes P10's `Journal` clause.** agentosd's `journalProviderRuns` (providerjournal.go) sets `Journal` to one egress note per admitted run (machine from `Request.Machine` or `unattributed`, `provider-<name>`, task class, outcome, result size and elapsed time; never the brief or result). That entry is the plan run's metering: a plan run is not charged to or refused by the spend meter, since OP-8 as #2291 wrote it meters a plan run as runs, wall time and plan quota with zero spend, bounded by wall clock and machine limits (RES-2) and the pool's reserve (RES-5). Refusals before admission are not journaled. With no `Journal` the runner logs once that runs are unmetered. | OP-8 | Token counts per run, when the provider CLI reports them. |
