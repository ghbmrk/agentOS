# Provider-agent route: assumptions

Built for BOARD CAP-11-plan (#1314) on the plan-login chain (#807, #1015, #1014). The route is wired deny-by-default in agentosd: it stays closed until #809 fills the Codex qualification record and CRED-5c, #1264 and #1380 land.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| P1 | The Codex declaration is verdict `allowed` (#1377, D-117) with an empty qualification record, so every run refuses `unqualified` until #809 records the pinned CLI version, evidence pointer, terms URL and date. A record whose CLI version differs from the image's, or `not-allowed`, refuses the same way. | CAP-11, D-114 | #809 changes the built-in under tier A review. |
| P2 | Claude Code is worker-held, verdict `unclear`, and always refuses `opt-in-required` here; #1380 builds the opt-in. `unconfirmed` runs only with the owner's recorded consent (CRED-5c), which agentosd does not yet supply (Consent is false). | CAP-11, CRED-5 | #1380 and CRED-5c provide the grant sources. |
| P3 | The brief reaches the CLI on stdin only, never argv, so `/login` and `!cmd` text is data. Deviation from the brief's "declared result file": stdout is redirected inside the worker to a result file and stderr to /dev/null, so the CLI's own output is the result and no raw stderr is ever journaled. `TestCommandUnderARealShellKeepsOnlyStdout` runs `Command` under a real `/bin/sh` with a fake CLI that writes a canary to stderr: the result holds stdout only, in the declared cwd, with only the declared env. The journal holds metadata only. Whether the result should be the CLI's last-message file instead of the `--json` stream is open (security finding 6, L3 finding 13). | CAP-11, CRED-7 | A CLI that writes its own result file needs a declared path. |
| P4 | The command is `env -i` with exactly the launch.json env, then `wrap`, then `argv` (#1850). No login is handled here; the seed is a placeholder via `RouteControl.Seed`. | CRED-5, #1015 | Env or wrap form changes in #1850. |
| P5 | Codex `CreditDraw` and `LoginRefused` signals are provisional; #809 measures them. Signals are matched only inside the CLI's own JSON error events (`ErrorEvents`: `error`, `turn.failed` for Codex), never in the agent's messages, which the brief steers; a signal taken from the broker's own upstream connection (#1856) is still needed before the route ships. A credit-draw signal is treated as used-up so no run draws credits unmetered. A refused login stops that provider's route: later runs refuse `login-refused` without seeding or starting a worker, and `SignIn` is called once, until `Runner.SignedIn` (the owner's sign-in or resume) lifts it. The stop is held in the Runner, so a broker restart clears it and the next run may start the CLI once more; journaling it is CRED-5b's. | CAP-9, CRED-5, CRED-5b, OP-8 | #809 measurement picks the signal or a credits-off check; CRED-5b persists the stop. |
| P6 | The result is scanned for provider credential formats (CRED-7) and withheld on a match. The scan is a tripwire only; the worker holds placeholders. | CRED-7 | Encodings beyond the tripwire's formats are not detected. |
| P7 | Admission (RES-5) fails closed: it refuses `pool-at-reserve` unless every declared pool has a reading and every reading is above the owner's reserve. No readings source, no reserve, an unread pool or a NaN reading refuses. agentosd wires no readings yet (#1856: a control verb carrying quota readings to agentosd is not built), so the route stays closed even after #809 fills the record (`TestProviderRunnerRefusesUnreadPoolsAfterTheRecordIsFilled`); #1856 is a precondition of enabling the route. | RES-5 | #1856 supplies readings. |
| P8 | A wall-clock cap wraps the Execs; the worker is destroyed on every exit path, and a Destroy error goes to the broker's log. The Seeder's errors are provagent's own sentinels, which agentosd maps from `modelroute`: a locked vault is `vault-locked`, a stalled or contended route (any other 503) is `route-busy` (#1857), both fallbacks; a missing plan login is `unsigned` and sets the sign-in line once (#1858). Only a broker-held declaration is seeded, and agentosd seeds Codex only (the control socket mints Codex placeholders); a create that fails after the seed closes the route, so the placeholders are forgotten. | CAP-9, CRED-5b | |
| P9 | ARC-2: `provagent` imports only `admission` and `vm` (guest plane, `forbiddenStd`). The worker tools name the run through `workers.ProviderRunner` and its own request and reason types; agentosd adapts the Runner to it and `modelroute.RouteControl` to the Seeder, so neither `workers` nor `provagent` links the model route's HTTP client. | ARC-2 | |
| P10 | agentosd inputs still unwired, and who wires them: `ImageVersion` returns "" (the image's pinned `CODEX_VERSION`, with #809), `Readings` is nil (#1856), `Journal` is nil (OP-8 run metering and charge, to be filed), `SignIn` is nil and nothing calls `SignedIn` (#1264 sign-in, CRED-5b resume), `Granted`, `PrivateOK` and `Consent` are false (CRED-5c, #1264). #1701's end-to-end step needs each of these. | CAP-11, OP-8, ONB-9 | |
