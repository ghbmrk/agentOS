# Provider-agent route: assumptions

Built for BOARD CAP-11-plan (#1314) on the plan-login chain (#807, #1015, #1014). The route is wired deny-by-default in agentosd: it stays closed until #809 fills the Codex qualification record and CRED-5c, #1264 and #1380 land.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| P1 | The Codex declaration is verdict `allowed` (#1377, D-117) with an otherwise empty qualification record, so every run refuses `unqualified` until #809 records the pinned CLI version, evidence pointer, terms URL and date. `Validate` refuses a record for a CLI version other than the declaration's, and `TestCodexBuiltinMatchesThePinnedImageVersion` ties both to guest/codex/build-rootfs.sh `CODEX_VERSION` and checks the evidence file exists, so the finish is a data change under the existing tests. A record whose CLI version differs from the image's, or `not-allowed`, refuses the same way. | CAP-11, D-114 | #809 changes the built-in under tier A review. |
| P2 | Claude Code is worker-held, verdict `unclear`, and always refuses `opt-in-required` here; #1380 builds the opt-in. `unconfirmed` runs only with the owner's recorded consent (CRED-5c), which agentosd does not yet supply (Consent is false). | CAP-11, CRED-5 | #1380 and CRED-5c provide the grant sources. |
| P3 | The brief reaches the CLI on stdin only, never argv, so `/login` and `!cmd` text is data. Deviation from the brief's "declared result file": stdout is redirected inside the worker to a result file and stderr to /dev/null, so the CLI's own output is the result and no raw stderr is ever journaled. `TestCommandUnderARealShellKeepsOnlyStdout` runs `Command` under a real `/bin/sh` with a fake CLI that writes a canary to stderr: the result holds stdout only, in the declared cwd, with only the declared env. The journal holds metadata only. Whether the result should be the CLI's last-message file instead of the `--json` stream is open (security finding 6, L3 finding 13). | CAP-11, CRED-7 | A CLI that writes its own result file needs a declared path. |
| P4 | The command is `env -i` with exactly the launch.json env, then `wrap`, then `argv` (#1850). No login is handled here; the seed is a placeholder via `RouteControl.Seed`. | CRED-5, #1015 | Env or wrap form changes in #1850. |
| P5 | A refused login and a credit draw are read on the broker's own upstream connection, never in the result file the agent can write (#1856). agentos-egress reads a refused refresh by its codex-rs codes (`refresh_token_expired`, `refresh_token_reused`, `refresh_token_invalidated`; `invalid_grant` is excluded because the guest's request controls client and scope), and a reached limit or a credit draw (a pool at 100%, `X-Codex-Rate-Limit-Reached-Type`, or a lower `X-Codex-Credits-Balance` than the route last read) as an `Exhausted` reading. After a run, `Usage` is read again: a refusal at or after the run's start is `login-refused`, and an exhausted reading at or after it is `used-up`, so no run draws credits unmetered; if `Usage` cannot be read after the run, the run fails `route-busy` rather than pass unchecked. The codes and headers are unmeasured until #809. A guest cannot forge a refusal: at worst a real refresh it triggers fails, which only stops the route. `UsedUp` stays matched only inside the CLI's own JSON error events (`ErrorEvents`), never in the agent's messages. A refused login stops that provider's route: later runs refuse `login-refused` without seeding or starting a worker, and `SignIn` is called once, until `Runner.SignedIn` lifts it. The stop is held in the Runner, so a broker restart clears it; journaling it is CRED-5b's. | CAP-9, CRED-5, CRED-5b, OP-8 | #809 measurement confirms or replaces the codes and headers; CRED-5b persists the stop. |
| P6 | The result is scanned for provider credential formats (CRED-7) and withheld on a match. The scan is a tripwire only; the worker holds placeholders. | CRED-7 | Encodings beyond the tripwire's formats are not detected. |
| P7 | Admission (RES-5) fails closed on the broker's readings, aggregated per provider across every worker (`Usage`). No source or no reserve, a NaN reading or reserve refuses `pool-at-reserve`; an unreachable source refuses `route-busy`. A reading is current when it is under `MaxAge` old (default 10 minutes) and its reset, if stated, is still ahead. A pool at or below the owner's reserve refuses until its reset passes (the reset is its cooldown); with no reset stated it refuses while current. **Probe rule:** a pool with no current reading (never read, stale, or past its reset) makes the run a probe, since the only way the broker reads a plan is a call on its own connection. A probe runs alone (no other run of that provider in flight) and at most once per `MaxAge`; a probe that failed before the CLI ran is forgotten. At most `PerPool` (default 2) runs of a provider are in flight. Decision boundary: with a nonzero reserve, one probe may draw a pool past the reserve before its first reading; an active read that spends nothing is a release follow-up once #809 shows the endpoint. The cap is per provider, where RES-5 says per pool: every Codex run draws both its pools, so the two agree; a provider with disjoint pools (Claude's model-specific weeks) revisits it (#1856 review L3, later). | RES-5, OP-5 | #809 shows a free usage read; a per-provider cap other than 2. |
| P8 | A wall-clock cap wraps the Execs; the worker is destroyed on every exit path, and a Destroy error goes to the broker's log. The Seeder's errors are provagent's own sentinels, which agentosd maps from `modelroute`: a locked vault is `vault-locked`, a stalled or contended route (any other 503) is `route-busy` (#1857), both fallbacks; a missing plan login is `unsigned` and sets the sign-in line once (#1858). Only a broker-held declaration is seeded, and agentosd seeds Codex only (the control socket mints Codex placeholders); a create that fails after the seed closes the route, so the placeholders are forgotten. | CAP-9, CRED-5b | |
| P9 | ARC-2: `provagent` imports only `admission` and `vm` (guest plane, `forbiddenStd`). The worker tools name the run through `workers.ProviderRunner` and its own request and reason types; agentosd adapts the Runner to it and `modelroute.RouteControl` to the Seeder, so neither `workers` nor `provagent` links the model route's HTTP client. | ARC-2 | |
| P10 | agentosd inputs still unwired, and who wires them: `Readings` is nil (#1856), `Journal` is nil (OP-8 run metering and charge, to be filed), `Consent` is false (CRED-5c), and the resume half of `SignedIn` (CRED-5b). #1877 wires `ImageVersion` to the CLI version the registered image pins (agentosd imagepin.go, `cmd/agentosd` ASSUMPTIONS IP1): "" when the image is unregistered or pins nothing, so the gate stays closed. #1264 c4e2a wires `Granted`, `PrivateOK`, `SignInStored`, `SignInFor`, `SignIn`, `OnSignedIn` and `Background` from the vault process's `/plan` and `/signedin` answers and agentosd's shutdown context (agentosd planwire.go): a locked vault reads as granted so a run falls back on the seed's `vault-locked` (CAP-9), and the private mark and `SignInStored` are false whenever the vault cannot say. Nothing calls `StartSignIn` until the setup page does (#1264 c4e2b). #1701's end-to-end step needs each of these. | CAP-11, OP-8, ONB-9 | |
| P11 | **Sign-in runs the provider's own CLI flow (ONB-3 step 6, CRED-5, #1264).** `StartSignIn` runs the declared `SignInArgv` (`codex login --device-auth`) in a fresh private provider worker whose route `SignInFor` marked, so the vault process opens it on the sign-in endpoints only and stores the login the owner approves there (egress `ForSignIn`); no run worker can store a login. The Codex image's config points the CLI's issuer at the worker's forwarder (`http://127.0.0.1:18432`), so the CLI prints the forwarder's device page; `SignInPrompt` accepts only a declared `SignInLinks` entry and always shows the declared `SignInPage` (`https://auth.openai.com/codex/device`), the same pair egress `PlanRoute.SignInLink` accepts (`TestONB3CodexSignInMatchesTheEgressCheck`). The image config is #809's to pin. | ONB-3, CRED-5 | The CLI's device page or issuer override changes. |
| P12 | **The prompt's shape is assumed, not measured.** The CLI prints the device page link and then a code shaped `[A-Z0-9-]{4,16}` on its output; ANSI escapes are stripped and the first code-shaped token after the first declared link is taken. A look-alike link, no code, or a CLI that exits before printing one refuses `failed`; no prompt within `SignInTimes.Link` (1 min) refuses `timed-out`. Only the link and the user code leave the worker: the user code is the feature (the owner types it on the provider's page). | ONB-3, CRED-7 | #809's live run measures the output; a changed shape refuses rather than guessing. |
| P13 | **The CLI keeps running after its Exec returns.** `SignInCommand` starts the CLI in the background with its output and exit status in files under the worker's cwd, and exits 0, so the Exec returns while the owner approves (up to `SignInTimes.Wall`, 15 min). This rests on the worker runtime keeping a command's children alive until the worker is destroyed (vm Exec's gVisor note); `TestONB3SignInCommandUnderARealShellRunsInTheBackground` checks the shell half. The sign-in counts only when the vault process reports that this worker's own sign-in stored the login (`SignInStored`, egress K29's `/signedin`): a login already stored (the refused one a re-sign-in replaces) and the CLI's exit status are not signals, so a CLI that exits 0 without a code exchange signs nothing in, and one that cannot write its own auth file after the vault stored the login still signs the owner in. The CLI's exit, `SignInTimes.Wall` or the runner's `Background` context ends the wait; every path destroys the worker, which closes its route. One sign-in per provider runs at a time (`ErrSignInBusy`). `SignIn` and `OnSignedIn` run under the runner's lock, in the same hold that sets or lifts the stop, so a refusal racing a sign-in cannot leave the route stopped with the line off. | ONB-3, CRED-5 | A runtime that reaps an Exec's children breaks the flow; it then times out and signs nothing in. |
| P14 | **Nothing of the sign-in is logged or shown beyond the link and code.** The CLI's output and status files are read only for the prompt and the exit status; tokens, the authorization code and `device_auth_id` pass only between the CLI and the vault process's route. The runner's log lines carry the provider, worker ID and a fixed outcome; a refused start (#1701) also logs the step that refused it with the machine plane's error, the start Exec's exit status, or the CLI's exit status, which is quoted only when the status file holds a number, since the CLI can write that file (signin_test.go checks a canary in the CLI output or status file never reaches a log or the result). vm's errors name machine ids, images and paths, never a command's output. | CRED-7, OP-8 | |
| P15 | **Plan readings and the reserve are wired (#1856); this supersedes P10's `Readings` clause.** `Usage` reads agentos-egress's `/usage` through `RouteControl.Usage` (#1856, wired). `Reserve` is 0 for every pool (`ownerReserve`, RES-5/ONB-9 "Kept for your own use: 0%"); the ONB-9 owner setting (OP-5 budget row) replaces it. P10 lists the inputs still unwired. | RES-5, ONB-9 | The owner-setting row wires `Reserve`. |
| P16 | **A worker starts on the declaration's idle command (#1721).** runsc refuses a container whose process has no args, so `Run` and `StartSignIn` create the worker with `Argv: Idle`; the CLI, and its sign-in, run beside it by Exec, which P13 already rests on. `Idle` is absolute (`/bin/sleep infinity`) so it does not depend on the runtime's PATH, the Codex image copies `/bin/sleep` (tests/test_codex_rootfs.py runs it in the built tree), and `TestCodexBuiltinMatchesLaunchJSON` pins it to `guest/codex/launch.json`'s `idle`. `Validate` refuses a declaration with none. | CAP-11, ONB-3 | If a runtime gains an init that waits on its own, drop `Idle`. |
