# Host disks left untouched: assumptions

Built for HOST-1a part 1 against SPEC v0.12 HW-8 ("internal disks are not
auto-mounted, not swapped to, and not used by any service, agent machine,
or executor. Reading the partition table and volume signatures read-only
is allowed, only to describe disks for HW-8a … no file system on a host
disk is opened") and the HW-8a disk list, with the lens conditions on the
design (security H1-H7, potency C1, R1, R2). Packages: `hostdisk` (probe,
classification, disk list, udev rules) and `cmd/agentos-hostdisk` (the
root-only udev helper and JSON list). Each row is a reading a reviewer may
want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| H1 | "Partition table and volume signatures" means: the MBR sector, the GPT header and entry array (the backup copy only when the primary fails), MBR extended-partition boot records, and the first 4 KiB of each partition (`WindowSize`), or of the disk when it has no table. Every recognized signature (NTFS, BitLocker `-FVE-FS-`, FAT, exFAT, ReFS, ext, LUKS, swap, LVM, APFS) lies in that window; a test checks every read offset. x86 swap only: a 64 KiB-page swap header lies outside the window and reads as no signature. | HW-8 | Constant. |
| H2 | **Hostile table** (security H3): GPT at most 128 entries of 128-512 bytes (multiple of 8), array at most 32 KiB, header CRC, entry CRC and own-LBA checked; every LBA checked against the disk with overflow-checked multiplication; a partition reaching past the end is described as far as the disk goes, one starting past it (or ending before its start) is left out, and either way, or when a partition's first bytes cannot be read, the disk gets `Problem` `partly-unreadable` (L3 on #172); two readings of the disk's start (a volume boot record whose boot code also parses as an MBR, or a valid primary GPT without a protective MBR) give `ambiguous-table`, describing what the kernel reads (the MBR or volume; the GPT only when nothing else is there); extended-partition chains capped at 64 with loop detection; total reads per disk capped (`readBudget`). A hybrid MBR is read as its GPT; without a valid GPT copy the disk is unreadable, never described from the hybrid entries. `FuzzProbe` checks no panic, no read outside the disk and the budget (3.2 M executions locally). | HW-8 | Constants. |
| H3 | **Output** (security H4): booleans, enums and sizes. No volume label, GPT partition name, GUID or serial is decoded, kept or logged; partition GUIDs are compared against systemd-boot's in place and dropped; tests with canary labels and GUIDs check the JSON and `%+v`/`%#v` output. One exception, flagged for Security: the disk's `Model` from sysfs, which HW-8a requires the page to show; it is the drive's own model string, not anything the owner wrote, and is cut to printable ASCII, 64 bytes. | HW-8a | Drop `Model` if Security rules the spec's "model" must come another way. |
| H4 | **Read-only by construction** (security H5): devices are opened `os.O_RDONLY`, to which Go adds `O_CLOEXEC` (a test reads the fd's flags: no write access, no `O_EXCL`), with `O_NOFOLLOW` (no link is followed) and `O_NONBLOCK` (no wait on a FIFO; block reads ignore it), and kept only when the open file is a block node (#3950); the fence admits `syscall` for those two flags alone and `os.OpenFile` with `os.O_RDONLY` alone or with exactly those two; the opener and the open device are unexported and no exported function returns a file or reader; a source test fails on any write, create, sync, ioctl, raw syscall, `Fd`, mount, swap, exec, discard, `syscall` name but those two flags, `unix`/`unsafe` or network use in the package or its command. | HW-8 | — |
| H5 | **Second confirmation** (`NeedsSecondConfirm`): BitLocker anywhere on the disk, Windows (an MSR or Windows recovery partition, or NTFS/BitLocker next to a boot partition), a boot loader (an ESP, a BIOS boot partition, or an MBR active flag), or a disk that could not be read whole or reads two ways (`Problem`: unreadable, partly unreadable, ambiguous, cannot open, size unknown; potency R1). A plain NTFS data disk needs only the erase confirmation, as in the UX walkthrough. "The host's running boot loader" is read as "a boot partition is on this disk", since telling which loader firmware starts would mean opening the ESP's file system. | HW-8a | `summarize`. |
| H6 | **The drive** (security H1, F2 on #172): the one physical disk the running system is on: the disk backing `/` (through `/sys/dev/block`, partitions to their disk, dm and md through their slaves, an overlay through its upper and lower directories), or for a device-less root (tmpfs) the disk backing `/usr`. If neither resolves, it is the disk holding systemd-boot's `LoaderDevicePartUUID` partition, only if exactly one disk does (every AgentOS drive carries the same GUIDs: #41 fixes mkosi's seed). When the root resolved from mounts, the loader variable, if present, is a cross-check: a root disk without that partition means no drive and `HealthMismatch`; with no single disk, `HealthNoRoot`. Mount state of any other disk never makes it the drive. Tested on #41's layout (`/` on the root partition, `/usr` on dm-verity over the A slot and its hash partition, `/efi` on the ESP), a tmpfs root and an overlay root. | HW-8 | `rootDisk`, `findDrive`. |
| H7 | **Classes** (security H2, H7): the helper prints `AGENTOS_DISK=drive`, `host` or `unknown`. dm and md devices take the class of the disks they are built on (a mix, or any host disk, is `host`; no slaves yet is `unknown`); removable media other than the drive are `host`; only loop, ram, zram and nbd devices are the box's own and skipped. Kernel names with `!` (`cciss!c0d0`) are accepted, as is udev's `/` spelling, and opened under `/dev` with `/`; every segment must start with a letter or digit. With no single root disk every device is `unknown`. On a mismatch every disk is `host` except the one under the running root, which is `unknown`: hiding it cannot unmount the root, only stop the box booting, and the health item reports it (a reading of "all disks are treated as host" together with H2's "so the box still boots"). | HW-8 | `Classify`. |
| H8 | **udev rules** (`udev/`, three files around the stock ones; L3 on #172; order checked by L3 against Ubuntu noble's packages). `59-agentos-host-disks.rules` runs the helper; `host` gets `UDEV_DISABLE_PERSISTENT_STORAGE_RULES_FLAG=1` (systemd's 60-persistent-storage skips it: no blkid probe, so no label, partition label, UUID or member type in the udev database and no `/dev/disk/by-*` link, by-partuuid and by-partlabel included), for a dm device also `DM_UDEV_DISABLE_DISK_RULES_FLAG` and `DM_UDEV_DISABLE_OTHER_RULES_FLAG` (60-persistent-storage-dm, 69-lvm and 69-bcache skip it), `SYSTEMD_READY=0` (no `.mount`/`.swap` unit can use it), `UDISKS_IGNORE`/`UDISKS_AUTO=0`/`UDISKS_SYSTEM` and node `root:root 0600` with `:=`; `unknown`, a failed helper or any other output gets only `UDISKS_IGNORE=1`, `UDISKS_AUTO=0`. `64-agentos-host-disks-assembly.rules` (after every blkid probe, mdadm's 63-md-raid-arrays included, and before 64-md-raid-assembly, 69-lvm and bcache-tools' 69-bcache) sets `ID_FS_TYPE` to the sentinel `agentos_held` on every host device (dropping its usage, label and UUID) and, on every other device but the drive's, on a RAID, LVM, bcache or ZFS member type **or an empty type**. Each assembly rule acts only on its own type, and 69-bcache also probes and registers (journal replay, writeback: a write) a device with no type, which blkid leaves empty on an ambiguous probe or an unprobed boot partition; so the type is held, never left empty (L3 MUSTs on #172). Any other type on an unknown device, and its usage, stay, so 99-systemd keeps the box's own dm-verity or dm-crypt device ready and routes it as before. `72-agentos-host-disks-late.rules` (after 70-uaccess, before 73-seat-late) takes the `uaccess` tag from every block device but the drive's, and makes every SCSI and NVMe generic node (`sg*`, `ng*`), block SCSI generic node (`/dev/bsg/*`) and NVMe controller node (`nvme0`), which can send writing commands to any disk (SG_IO, NVMe admin and I/O passthrough), `root:root 0600` with no `uaccess` (bsg and controller nodes: Security, optional, on #172; HOST-1a part 2). A test runs the three files in order between models of 60-persistent-storage (skipping dm and md), 60-persistent-storage-dm, 63-md-raid-arrays, 64-md-raid-assembly, 69-lvm, 69-bcache, 70-uaccess and 99-systemd. **Inferred, for the P2-1 VM test:** that the image's systemd and dmsetup honor the flags and the stock files behave as modelled. **Residual, needing a root action first:** a host md array keeps the by-label/by-uuid links 63-md-raid-arrays gives it (its type is held). **Reads by stock rules:** 60-cdrom_id opens a host optical drive read-only (`--lock-media`); an unknown disk is probed read-only by blkid. | HW-8 | Rule files. |
| H9 | **Root only** (security H6): the helper reads disks only as root and otherwise answers `unknown` (classify) or refuses (list); it prints only the H3 output. No machine gets a host device: `vm/gvisor`'s bundle test (now also `REQ: HW-8`) fails on any declared device, `/dev` mount or bind other than the machine's services directory. | HW-8 | — |
| H10 | **The listing** (`HostDisks`): every physical disk but the one under the running root, with bus (`nvme`, `sata`, `usb`, `mmc`, `virtio`, `scsi`, `other`) and removable flag (potency R2); dm and md devices are left out, being built on listed disks; optical drives are left out and never opened (an open can close an ejected tray), though udev hides them. | HW-8a | — |
| H11 | **Installed by the image** (HOST-1a part 2, from the P2-1 carry-forward; security ruling (c) and R1 on #172). `image/build.sh` builds `agentos-hostdisk` into `/usr/lib/agentos/` (static, root-owned 0755, on the verity `/usr`) and installs the three rule files to `/usr/lib/udev/rules.d/` in the main system only; `exec.allow` pins each to its source's hash, so an edit here fails the image build until it is reviewed there, and the initrd carries neither. The initrd's udev, having none of the rules, still probes a host disk read-only with blkid and links it by label, partition label and disk sequence before the switch to the main system, and udev there never removes links it did not make, so the 59 rule runs `/usr/lib/agentos/host-disk-unlink` (a shell script in the image, outside this package's no-write fence) on each device it hides, which removes only the `/dev/disk/by-*` links that point at it (#3306's CI boot found them). `/etc/fstab` mounts only API file systems, the command line has no `root=` (gpt-auto takes root from the loader's partition) and `systemd.swap=0`, and no unit mounts a block device. No `lvm2`, `mdadm`, `bcache-tools`, `zfsutils`, `multipath-tools`, `dmraid`, `udisks2` or automounter ships: `exec.allow` admits none of their udev rules and `mkosi.finalize` refuses their commands; in the initrd, mkosi-initrd's `lvm2` commands, rules and units are removed and `initrd/mkosi.finalize` refuses the same commands and rules. Every root unit sets `PrivateDevices=yes` or `DevicePolicy=closed` with `DeviceAllow=` only for what it needs, and `tests/test_image.py` lists every agentOS unit's user and policy; **except** `agentosd.service`, the old core's broker frozen under D-139, whose hardening is IMG-4 (#917). The health item is `agentos-hostdisk health` (`System.DriveHealth`, equal to `HostDisks().Health` and opening only the root's disk): any answer but `hostdisk=ok` fails the boot's health check, so a boot with no drive is never blessed. CI's first boot (`image/ci_boot.sh`) attaches a second internal virtio disk and a USB disk on xHCI, each with labelled file systems and named partitions, and requires: the root's disk classed `drive`; every node of both disks `host`, `SYSTEMD_READY=0`, `root:root 0600`, with no `ID_FS_LABEL`, `ID_FS_UUID` or partition name or UUID recorded and no `/dev/disk` link to it; the helper listing them as `usb` and `virtio`; every `sg`, `bsg`, `ng` and NVMe controller node root-only; both disks byte-identical afterwards and `foreign=none`. **Residual:** for the initrd's few seconds, a host disk's links and blkid record exist in the initrd's udev; and (later, #3305) the kernel's own uevent for a partition carries its GPT name (`PARTNAME`), which sysfs shows to any uid and udev records; no rule can take it out of sysfs. | HW-8, ONB-2 | P2-1. |
| H12 | **Carry-forward for update and restore** (potency C1 as ruled by Security): removable drives stay `host`, hidden and never automounted. Offline update (UPD, A14) and restore (REC-1 `RestoreDrive`) read the owner's USB drive through a root-only, read-only broker path of their own, never through udev exposure or a guest; the VM test above includes the USB disk. | HW-8, UPD, REC-1 | Those packages. |
| H13 | **Carry-forward for HOST-1d**: the Settings > Storage list comes from `System.HostDisks()`; the page shows model, size, bus and partitions, never kernel names; it refuses the opt-in unless `Health` is OK. Whether volume labels may be read at display time on the owner's page only, never stored or logged, is HOST-1d's own lens question (UX ask, deferred by Security's H4 ruling). | HW-8a | HOST-1d. |
| HOST-1a-drive-id | **The drive check counts hidden disks** (HOST-1a part 2): `image/mkosi/mkosi.extra/usr/lib/agentos/drive-id` (UPD-1, L3 MUST on #41) found a second agentOS drive by the PARTUUIDs `lsblk` reads from udev, which the 59 rule now withholds for a host disk. So for every partition `lsblk` shows without one, it reads that disk's table with `sfdisk -d`, read-only (a partition table, as HW-8a allows), and a copy attached beside the drive still fails the health check. A table `sfdisk` cannot read adds nothing, as an unprobed device did before. | HW-1, HW-8 | `drive-id`. |
