# Host disks left untouched: assumptions

Built for HOST-1a part 1 against SPEC v0.12 HW-8 ("internal disks are not
auto-mounted, not swapped to, and not used by any service, agent machine,
or executor. Reading the partition table and volume signatures read-only
is allowed, only to describe disks for HW-8a … no file system on a host
disk is opened") and the HW-8a disk list, with the lens conditions on the
design (security H1-H7, potency C1, R1, R2). Packages: `hostdisk` (probe,
classification, disk list, udev rule) and `cmd/agentos-hostdisk` (the
root-only udev helper and JSON list). Each row is a reading a reviewer may
want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| H1 | "Partition table and volume signatures" means: the MBR sector, the GPT header and entry array (the backup copy only when the primary fails), MBR extended-partition boot records, and the first 4 KiB of each partition (`WindowSize`), or of the disk when it has no table. Every recognized signature (NTFS, BitLocker `-FVE-FS-`, FAT, exFAT, ReFS, ext, LUKS, swap, LVM, APFS) lies in that window; a test checks every read offset. x86 swap only: a 64 KiB-page swap header lies outside the window and reads as no signature. | HW-8 | Constant. |
| H2 | **Hostile table** (security H3): GPT at most 128 entries of 128-512 bytes (multiple of 8), array at most 32 KiB, header CRC, entry CRC and own-LBA checked; every LBA checked against the disk with overflow-checked multiplication; a partition past the end is not described; extended-partition chains capped at 64 with loop detection; total reads per disk capped (`readBudget`). A hybrid MBR is read as its GPT; without a valid GPT copy the disk is unreadable, never described from the hybrid entries. `FuzzProbe` checks no panic, no read outside the disk and the budget (2.2 M executions locally). | HW-8 | Constants. |
| H3 | **Output** (security H4): booleans, enums and sizes. No volume label, GPT partition name, GUID or serial is decoded, kept or logged; partition GUIDs are compared against systemd-boot's in place and dropped; tests with canary labels and GUIDs check the JSON and `%+v`/`%#v` output. One exception, flagged for Security: the disk's `Model` from sysfs, which HW-8a requires the page to show; it is the drive's own model string, not anything the owner wrote, and is cut to printable ASCII, 64 bytes. | HW-8a | Drop `Model` if Security rules the spec's "model" must come another way. |
| H4 | **Read-only by construction** (security H5): devices are opened `os.O_RDONLY`, to which Go adds `O_CLOEXEC` (a test reads the fd's flags: no write access, no `O_EXCL`); the opener and the open device are unexported and no exported function returns a file or reader; a source test fails on any write, create, sync, ioctl, raw syscall, `Fd`, mount, swap, exec, discard, `syscall`/`unix`/`unsafe` or network use in the package or its command. | HW-8 | — |
| H5 | **Second confirmation** (`NeedsSecondConfirm`): BitLocker anywhere on the disk, Windows (an MSR or Windows recovery partition, or NTFS/BitLocker next to a boot partition), a boot loader (an ESP, a BIOS boot partition, or an MBR active flag), or a disk that could not be read (`Problem`, potency R1). A plain NTFS data disk needs only the erase confirmation, as in the UX walkthrough. "The host's running boot loader" is read as "a boot partition is on this disk", since telling which loader firmware starts would mean opening the ESP's file system. | HW-8a | `summarize`. |
| H6 | **The drive** (security H1): the one physical disk under the running root (`/` in mountinfo, through `/sys/dev/block`, partitions to their disk, dm and md through their slaves). systemd-boot's `LoaderDevicePartUUID`, when present, is a cross-check: if the root's disk does not list that partition there is no drive and the listing carries `HealthMismatch`; with no single root disk it carries `HealthNoRoot`. Mount state of any other disk never makes it the drive. | HW-8 | `findDrive`. |
| H7 | **Classes** (security H2, H7): the helper prints `AGENTOS_DISK=drive`, `host` or `unknown`. dm and md devices take the class of the disks they are built on (a mix, or any host disk, is `host`; no slaves yet is `unknown`); removable media other than the drive are `host`; only loop, ram, zram and nbd devices are the box's own and skipped. With no single root disk every device is `unknown`. On a mismatch every disk is `host` except the one under the running root, which is `unknown`: hiding it cannot unmount the root, only stop the box booting, and the health item reports it (a reading of "all disks are treated as host" together with H2's "so the box still boots"). | HW-8 | `Classify`. |
| H8 | **udev rule** (`udev/61-agentos-host-disks.rules`): `host` gets `SYSTEMD_READY=0` (no `.mount`/`.swap` unit can use it), `UDISKS_IGNORE`/`UDISKS_AUTO=0`, `ID_FS_TYPE`/`ID_FS_USAGE` cleared (no LVM, MD-RAID or other blkid-keyed assembly) and node `root:root 0600` with `:=`; `unknown`, a failed helper or any other output gets `UDISKS_IGNORE=1` and `UDISKS_AUTO=0` only. A test runs the rule through a small udev evaluator. | HW-8 | Rule file. |
| H9 | **Root only** (security H6): the helper reads disks only as root and otherwise answers `unknown` (classify) or refuses (list); it prints only the H3 output. No machine gets a host device: `vm/gvisor`'s bundle test (now also `REQ: HW-8`) fails on any declared device, `/dev` mount or bind other than the machine's services directory. | HW-8 | — |
| H10 | **The listing** (`HostDisks`): every physical disk but the one under the running root, with bus (`nvme`, `sata`, `usb`, `mmc`, `virtio`, `scsi`, `other`) and removable flag (potency R2); dm and md devices are left out, being built on listed disks. | HW-8a | — |
| H11 | **Carry-forward for P2-1** (#41 or its follow-up): install the rule to `/usr/lib/udev/rules.d/` and `agentos-hostdisk` to `/usr/lib/agentos/agentos-hostdisk` (root-owned, 0755) in the main system, not the initrd; keep `/etc/fstab` and `systemd-gpt-auto-generator` to the drive's own partitions; leave out `lvm2`, `mdadm`, `udisks2` and any automounter, or keep them only with this rule in place; give root units that need no disk `PrivateDevices=yes` or `DevicePolicy=closed`, since root can open a 0600 node; raise a health item from `HostDisks().Health`; add the VM boot test with a second internal virtual disk plus a USB disk, checking both stay hidden and untouched (shared with IMG-1 and HOST-1e). | HW-8, ONB-2 | P2-1. |
| H12 | **Carry-forward for update and restore** (potency C1 as ruled by Security): removable drives stay `host`, hidden and never automounted. Offline update (UPD, A14) and restore (REC-1 `RestoreDrive`) read the owner's USB drive through a root-only, read-only broker path of their own, never through udev exposure or a guest; the VM test above includes the USB disk. | HW-8, UPD, REC-1 | Those packages. |
| H13 | **Carry-forward for HOST-1d**: the Settings > Storage list comes from `System.HostDisks()`; the page shows model, size, bus and partitions, never kernel names; it refuses the opt-in unless `Health` is OK. Whether volume labels may be read at display time on the owner's page only, never stored or logged, is HOST-1d's own lens question (UX ask, deferred by Security's H4 ruling). | HW-8a | HOST-1d. |
