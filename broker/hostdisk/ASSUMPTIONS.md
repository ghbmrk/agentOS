# Host disks left untouched: assumptions

Built for HOST-1a part 1 against SPEC v0.12 HW-8 ("internal disks are not
auto-mounted, not swapped to, and not used by any service, agent machine,
or executor. Reading the partition table and volume signatures read-only
is allowed, only to describe disks for HW-8a … no file system on a host
disk is opened") and the HW-8a disk list. Packages: `hostdisk` (probe,
disk list, udev rule) and `cmd/agentos-hostdisk` (udev helper, JSON list).
Each row is a reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| H1 | "Partition table and volume signatures" means: the MBR sector, the GPT header and entry array (the backup copy only when the primary fails its CRCs), MBR extended-partition boot records, and the first 4 KiB of each partition (`WindowSize`), or of the disk when it has no table. Every recognized signature (NTFS, BitLocker `-FVE-FS-`, FAT, exFAT, ReFS, ext, LUKS, swap, LVM, APFS) lies in that window; nothing past it is read, which a test checks offset by offset. x86 swap only: a 64 KiB-page swap header lies outside the window and reads as no signature. | HW-8 | Constant. |
| H2 | Read-only by construction: devices are opened `O_RDONLY` (`OpenReadOnly`), the probe takes an `io.ReaderAt`, and a source test fails on any write, create, mount, swap, exec, `syscall`/`unix` or network import in the package or its command. | HW-8 | — |
| H3 | **Second confirmation** (`NeedsSecondConfirm`): BitLocker anywhere on the disk, Windows (an MSR or Windows recovery partition, or NTFS/BitLocker next to a boot partition), a boot loader (an ESP, a BIOS boot partition, or an MBR active flag), or a disk that could not be read. A plain NTFS data disk needs only the erase confirmation, as in the UX walkthrough's "WD Blue, 1 partition, Data". "The host's running boot loader" is read as "a boot partition is on this disk", since telling which loader firmware starts would mean opening the ESP's file system. | HW-8a | Flags in `summarize`. |
| H4 | **Which disk is the AgentOS Drive**: the disk whose GPT lists the partition named by systemd-boot's `LoaderDevicePartUUID` EFI variable. If the variable is missing or matches no disk, every disk the running system uses (a mounted partition, or one held by device-mapper such as dm-verity `/usr`) is the drive. So a mismatch never hides the drive the box runs on, and a host disk is only exposed if something already mounted or assembled it, which H6 prevents and HOST-1e detects. | HW-8 | `drive`. |
| H5 | **udev rule** (`udev/61-agentos-host-disks.rules`): for every block disk and partition not on the drive (virtual devices skipped): `SYSTEMD_READY=0` (no `.mount`/`.swap` unit can use it), `UDISKS_IGNORE`/`UDISKS_AUTO=0` (no automount or desktop exposure), `ID_FS_TYPE`/`ID_FS_USAGE` cleared (no LVM, MD-RAID or other blkid-keyed assembly), node `root:root 0600` with `:=` (no disk-group service, agent machine or executor can open it). A helper failure sets nothing and the disk is hidden. A root process can still open a 0600 node, so the P2-1 carry-forward (H6) gives every unit that runs as root and needs no disk `PrivateDevices=yes` or `DevicePolicy=closed`. | HW-8 | Rule file. |
| H6 | **Carry-forward for P2-1** (#41 or its follow-up): install the rule to `/usr/lib/udev/rules.d/` and `agentos-hostdisk` to `/usr/lib/agentos/agentos-hostdisk` (root-owned, 0755) in the main system, not the initrd; keep `/etc/fstab` and `systemd-gpt-auto-generator` to the drive's own partitions (gpt-auto only ever looks at the boot disk); leave out `lvm2`, `mdadm`, `udisks2` and any automounter, or keep them only with this rule in place; give root units that need no disk `PrivateDevices=yes` or `DevicePolicy=closed`; add the boot test with a second virtual disk (HOST-1a's VM test, shared with IMG-1 and HOST-1e). | HW-8, ONB-2 | P2-1. |
| H7 | **Carry-forward for HOST-1d**: the local page's Settings > Storage list comes from `System.HostDisks()` (model, size, partitions, the H3 flags). Disk names are the kernel's; the page shows model and size, not `nvme0n1`. | HW-8a | HOST-1d. |
