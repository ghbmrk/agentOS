# graph: assumptions

Built for TN-graph (#2857, brief `briefs/TN-graph.md`) against KRN-11, CLK-10, CH-11, CH-12, CLK-11 and D-149, D-151, D-152. The package is advisory: nothing imports it yet, and wiring STATUS, `STOP <name>` and proposals to it is later rows' work. Each row is a reading a reviewer may want to change.

| TN-graph-A8 | A STATUS line names a failure domain by the names of the nodes that carry it, never by its label, and words it as one failure: "lost to one failure shared by Key 1 and Key 2", "of Ana's phone", or "of its own maker or provider" when the domain is the asset's own, labelled or not, carried by no other node (UX on #3193). | TN-graph-A15 | Missing data is weak, and every node but the owner can fail. `New` gives any node with no failure domain a domain of its own (`SelfDomain`, `self:<ID>`), a person (such as a recovery contact) or a brake included, except the owner's own person node, the one node not modelled as failing. So that no node without a failure domain can stand in for a credential or a witness, `New` refuses a reset, copy, act, cutoff or watch edge from a brake (a brake is a setting that only brakes), an AND edge or a watch edge that includes the owner (what proves the owner, or tells them, can fail), and an owner node that is not a person. The owner acting alone is still a control source: that is how reach is measured (A1). Because nothing can fail it, `Apply` refuses a proposal's new owner-only control edge unless its To is a node the same proposal adds (such as a new key): onto a node already there it would be free reach that masks a lock-out (Security on #3200). (Security on #3193, rework of the reject at `5a0b304`.) | KRN-11, CLK-10 | Drop the default or a refusal in `New`, and `naiveDomains` and the generators in the test. |
| TN-graph-A16 | **Non-regression invariant.** A proposal is offered (by `Next`, or as a STATUS `Fix:`) only if (1) it adds no owner node, so reach is always measured from the same owner; (2) for every asset and class in the after state, new ones included, measured against its before state: the owner still reaches it if they did before, it gains no cut-off provider, and every thief cut it gains (a single domain or a pair) is larger than its old smallest cut; and (3) no class on the board scores worse (ThiefNeed does not fall, CutOff does not rise), so the gain is at least zero. A new asset's before state is its floor: one failure of a domain only it carries (its own maker or provider), no other cut, smallest cut taken as 1, no cut-off provider. (2) is `Effect.Weakens`, (3) is `Effect.Lowers`, (1) is refused by `Apply`. Under (2) a second pair beside a pair, or a swapped single, is refused; a pair beside a single is not, since the smallest cut does not shrink. `TestWeakensInvariantOverFixtureMutations` restates (2) from brute-force cuts and checks it over every one-step mutation of Ana: each edge dropped; single, AND and cut-off edges added onto each asset; new money accounts under each kind of label; and, for every node kind (its list is asserted equal to the engine's, so a new kind fails until covered), a new node labelled or not as a control source onto each asset, as one member of an AND on each control edge, as a witness and as a cut-off provider. The restatement applies its own default-domain rule and also checks each mutation's cut sets against brute force. A brake in any of those roles, the owner in an AND or as a witness, a new owner-only control edge onto each existing node, and an added owner of any kind are refused by `Apply`. `TestClassFloorOverNewAssets` checks (3) from brute-force class floors: from Ana with money held at 3, a new asset that weakens nothing still lowers its class and is refused. The invariant rests on every node a thief could use carrying a failure domain, which A15 enforces. Among proposals that pass, `Next` takes one with gain or `Steps` above zero (`Steps` is the fall in single cuts across every asset and class plus the fall in cut-off assets, leaving out any lock-out). It ranks them structural first, then by gain per minute, then by steps per minute. (Security, L3 and Potency on #3193.) | KRN-11, D-152, CH-12 | Change `Apply`, `Effect`, `weakens`, `Lowers`, `rank` and `Next` in board.go, and the restatement in the test. |
| KEY-9-reach-writer-1 | **The writer reads the log's declarations and sends the difference** (#5814, `reach.go`). `WriteReach` maps the graph (`Decl`), reads what the log declared over the owner socket and sends `Additions` as one entry, nothing when it adds nothing, so a restart resends nothing and the writer holds no state. A node the graph drops stays declared: the log only adds. | KEY-9, CLK-10 | Keep a sent set in the writer instead of reading the log. |
| KEY-9-reach-writer-2 | **Classes map one to one, and a device's safety is its Safety class** (CLK-14): money, identity, safety and data become `key.AssetMoney`, `AssetIdentity`, `AssetSafety` and `AssetData`. The graph has no separate access class, so a device the owner or the table marks safety or access carries `Safety` in its `Assets`; no kind implies it. Only reset, copy and act edges are sent; cutoff, brake and watch carry no control. | CLK-14, KEY-9 | Add an access class to the graph and map it to `AssetSafety`. |
| KEY-9-reach-writer-3 | **The caller names which clerk roots on which node** (`clerks`, clerk to node ID): the graph has no clerk field. A clerk on a node the graph lacks, or two clerks on one node, is an error rather than skipped or one kept, since its keys would price on direct reach alone. A binding the log already holds (a clerk to a node, a node to a clerk) is kept even if the graph's differs: a move could lower a price, which the kernel refuses whole with every other addition. Such a move then needs a fresh log's declaration, not this writer. `Additions` also holds back a first declaration of a node an earlier logged edge named (the kernel would refuse it whole). It names everything it holds, and `WriteReach` sends the rest, then returns `ErrHeld` naming each, so the agentosd caller (step 2) can alert on a clerk priced on a stale root (L3 and Security on #5978). | KEY-9 | Send moves through a signed entry if rebinding becomes an owner action. |
| KEY-9-reach-writer-4 | **The package imports the kernel's declaration types in `reach.go` only** (`kernel`, `kernel/key`), the brief's pre-approved exception to TN-graph-i; `TestImportsOnlyStdlib` allows exactly those two there. | Brief guard files | Mirror the types locally and convert in agentosd. |
