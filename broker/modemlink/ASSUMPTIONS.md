# modemlink: assumptions

Started for P2-2w-d2b-s2 (#927) against CH-1 and CH-19. Each row is a reading a later change could overturn.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| ML1 | **An adoption under way lasts only while the bridge reports the same swapped or unbound SIM (#927, M7).** `setState` clears `adopted` on any report whose SIM differs or that carries none (ok, down), so the page offers the SIM the bridge now reports, never "setting up" one no longer in the modem. `Adopt` checks the tag against the SIM reported now, so a stale page cannot record a SIM pulled since. | CH-19 | If the bridge reported the adopted SIM under another state while it reopens, the clear would re-offer a SIM the owner just confirmed; the clear would then need to key on the SIM alone. |
| ML2 | **The bridge reports a SIM's serial only while the line is swapped or unbound (#927, M12), and modemlink keeps it only then.** Both ends hold the rule: the bridge's `open` returns no serial with `StateOK`, and `setState` drops an ICCID that comes with any other state. | CH-1, CH-19 | A state that needs the serial while ok (say, to show which SIM is in use) must add it to both ends and to this row. |
| ML3 | **A picture notice (CH12-mms) is counted, never inboxed, and journaled within two separate budgets: the owner's at most `InboundPerMinute` a minute, others' at most `OtherPicturesPerHour` an hour.** It is taken after the paused and second-line checks, so an owner's picture while paused is refused and retried like a text. Owner means `From` equals the owner's number and is not alphanumeric. Counts are since start and exact; past a budget only the hook call is skipped, so a stranger's flood neither keeps the owner's pictures out of the journal nor writes more than 24 records a day. | CH-12, OP-5 | The photo-input package fetches the picture: it adds its own path from here, and the bound and the note change with it. |
| G1-1688-f1-ML4 | **A text counted as missed is logged with its kind and callers, never its words (#2170).** `deliver` calls `Config.Logf` with `MissedLog`, `kind=text` or `kind=request`, and up to `missedFrames` ` via <func>` for the first calls outside the `Link`'s own methods, the runtime's and the owner channel's (`/broker/owner.` frames, skipped so the names reach agentosd's sender, #2349; a send the channel started itself names its outermost owner frame), outside the lock. Function names carry no owner data; the journal adds its own time. The box e2e driver reads the line to name the send a recovery text counts. | CH-1, UX U-B1 | If a caller's function name ever carried data (a generated name), or the log moved to a store the owner reads, the line would need a fixed tag per caller instead. If the owner channel moved out of `broker/owner` or agentosd called the Link through another wrapper package, `ownerFuncs` would need that package too or the names stop at its wrappers again. |
| MODEM-notice-slots-ML6 | **A handed-out item nobody waits for (the recovery text) is forgotten once its result is `SendWait` overdue (#1445).** `expireLocked` runs before each send's capacity check and in `Bridged`; a waiter's item is cleared only by its result or its own timeout, as before. A late result for a forgotten item is stray. The recovery text is never re-sent, so one the bridge took and never answered may not have reached the owner. | CH-2, UX U-B1 | If a second kind of waiterless item came that must be retried until answered, it would need its own waiter or a re-queue instead of this expiry. |
| P2-2w-c4c-l1-ML7 | **While setup runs, the SIM in the box is the one to bind: a SIM reported unbound, or swapped from the one this setup recorded, is recorded, each once (#1295).** A swap from a SIM some earlier run recorded is not recorded by setup. There is no owner yet, so no trust rests on the SIM setup binds; after setup, a swap goes through the confirm-with-a-code path (P2-2w d2b). | CH-1, CH-12 | If setup ever ran with an owner already trusted (a re-pairing that keeps the owner), a swap during it would need the code path instead of this rebind. |
