# The kernel's process: assumptions

`broker/kernel/proc` is the kernel's half of `broker/clerk/run`, split out by KRN-2 split (#2892). Its earlier rows (MIG-4-run a to d, h, i, m, o; STO-2b-1 z, aa; LOG-anchor-tpm a, b) stay in `broker/clerk/run/ASSUMPTIONS.md`, where both processes were built. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| KRN-2-split | **The kernel's process links no clerk's code; the wire lives on the kernel's side.** `kernel/proc` holds the kernel process (`OpenKernel`, `Tick`, `RunKernel`, the owner and meter sockets and their clients), the log file and its anchor, and the wire both sides speak (the call, the view, `Remote`, `ServeClerk`, `Conn`, `ServeConns`, `ServeOne`). `broker/clerk/run` keeps the clerks' processes and imports it, so a clerk's process links the kernel process's code but not the reverse: no clerk binary exists yet, and the code it gains holds no parser of outside bytes the clerk does not already read. The clerks' own errors cross a socket by their text through `WireErrors`, called from `clerk/run`'s init, since this package cannot name them. A process's private-file checks and atomic write moved to `broker/kernel/privfile`, which both use. `TestTheKernelProcessLinksNoClerkCode` holds the split: of `broker/clerk` the kernel links only `clerk/handoff`. Measured at the build: own lines 143,042 to 131,451, dependency lines 303,277 to 282,015, parsers 122 to 118. | SPEC KRN-2 | When a clerk ships as its own binary, it may want the wire in a package of its own, so it links no log or anchor code. |
| STO-2c-restart | **A kernel that came up and then failed reboots the box; one refused at its start does not** (#2998). After the unlock cap (#2977, tpmseal STO-2c-cap) no restart in the same boot unlocks, so `Restart=on-failure` cannot bring the kernel back. `RunKernel` makes `MainConfig.Up` (`-up`, empty, `O_EXCL` and no link followed) once both sockets listen, after every start check (the log key, the anchor, the owner's hardware keys in the unlock step). `agentos-keeper-kernel.service` makes it in `/run/agentos-kernel`, which systemd makes afresh for each start and a reboot empties, and its `ExecStopPost=` asks for a reboot only when the kernel made it and the unit's result is not success: `systemd-run --on-boot=30min`, so the reboot comes no sooner than 30 minutes into the boot (a boot timer past its time elapses at once). A refusal at the start repeats on every boot, so it stays down as before; a kernel that comes up and fails on every boot reboots the box at most twice an hour, spending at most four of the counter's increments an hour (#2897). `mkosi.finalize` admits only that one reboot line in the unlock unit (`KERNEL_REBOOT`), and no `OnFailure=` or `OnSuccess=`. A failure to make the file is said on stderr and the kernel runs on: the file only lets a later failure reboot the box. **Limits:** a failure after the cap but before the sockets that a reboot would cure (a TPM glitch at the anchor) stays down until the weekly reboot (UPD-10); the reboot does not wait out a call (UPD-6), since nothing reaches the kernel while it is down; the kernel's uid can make or remove the file, which lets a compromised kernel only reboot or keep down its own box, a denial of service it already has. | STO-2, CLK-1 | If the kernel ever survives its own crash without a second unlock (#2998 option 2), this reboot goes. |
