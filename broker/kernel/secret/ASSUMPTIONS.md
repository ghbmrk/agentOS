# Keys that print as addresses (KRN-keys-print-core): assumptions

Built for KRN-keys-print-core (#4833), the release row of #4759's sweep, across `kernel/secret`, `clerk/handoff`, `clerk/clerkkey`, `clerk/seal`, `tpmseal`, `pageca` and `cmd/agentos-unlock`. Each row below is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| KRN-keys-print-core-1 | **`Secret` lives in its own package, which links nothing.** `handoff.Secret` (#4759) could not serve the rest of the core: `clerkkey` is linked by every clerk process and must not link the hand-off, and `handoff` imports `pageca`, so `pageca` importing it would be a cycle. `kernel/secret` imports no package at all, so any holder of a key can use it without linking more. Every caller of `handoff.Secret` and `handoff.Hide` moved to it, and `handoff`'s private `drop` is `secret.Drop`; no alias is kept. | CLK-1, DECOY-b-8, KRN-2 | none |
| KRN-keys-print-core-2 | **A `Secret` is not comparable.** A zero-length `[0]func()` field makes `==` a compile error, because once a key sits behind a pointer, `==` compares two holders' addresses and is false for equal keys. Moving `clerkkey.Key.Key` into a `Secret` turned three test comparisons (`got != want`) into always-unequal ones, and the compiler now names every such site; they compare with `reflect.DeepEqual`, which reads through the pointer. | CLK-1 | none |
| KRN-keys-print-core-3 | **Each core holder keeps its key in a `Secret`, or behind its own `**` where JSON must read it.** `clerkkey.Key.Key`, `seal.Store`'s key and entries, `tpmseal.Counter.Auth` and the unlock step's test-only `config.passphrase` are `Secret`s. `pageca`'s sealed form and the unlock step's `counterRec` are JSON structs, which cannot see a `Secret`'s unexported field, so their key is a `**[]byte`: fmt prints it as an address and `encoding/json` reads and writes through it, so the encoded form is unchanged. A missing or `null` key decodes to nil and is refused as before. `Secret` itself gets no JSON methods, so `json.Marshal` of a holder writes no key either. | CLK-1, DECOY-b-8 | none |
| KRN-keys-print-core-4 | **The unlock step clears its array copies of the log key and the clerk root** (the #4835 L3 finding). `seal.Store.LogKey` and `ClerkRoot` return `[32]byte`, so the step's locals are copies that `KernelKeys.Wipe` never reaches; each is cleared once its `Secret` holds it. No test reads a dead stack slot, so this is best-effort, as STO-2a-e says every wipe is. | STO-2a-e | If `seal` hands keys out by pointer, the locals go. |
| KRN-keys-print-core-5 | **`secrettest` is the one print probe.** Sixteen verbs (`%w` and `%p` included), raw, hex, decimal-byte and JSON-escaped forms, the value bare and by pointer and in a holder with unexported pointer, value and interface fields, after a plain-field control that must show each secret. Only `_test.go` files import it, so it links into no binary. With `Secret` reduced to a single pointer, `TestSecretPrintsNoKey` fails. | CLK-1, DECOY-b-8 | none |
| KRN-keys-print-core-6 | **The seal factors' fields are a row of their own** (#4833's `seal.Passphrase.Phrase`, `seal.Recovery.Key`, `seal.TPM.PIN`). They are exported fields every caller sets in a literal, about 120 sites in twelve packages, two of them in sub B's `localui` tests (docs/LANES.md: nobody else writes there) and one in a file open PR #4845 changes (D-111). Changing their type would break sub B's tests in the same merge, so the factor change and sub B's two call sites must land together; the follow-up row #4860 says how. A factor is a call argument, built from bytes its caller already holds and dropped when `Unlock` or `AddSlot` returns; no core holder keeps one. | CLK-1, DECOY-b-8 | #4860 lands it. |
