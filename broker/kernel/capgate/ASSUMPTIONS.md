# Kernel byte-cap check: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (issue #4173, KRN-cap-first; D-255, D-260, D-262).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| KRN-cap-1 | **A count is fresh by the kernel's own clock, from when its summary was asked for.** The age is `now - ask` on the monotonic clock, never the enforcer's timestamp, so neither clock's drift nor the answer's travel time makes an old count look new; fresh means no older than `Fresh`, twice `wire.SummaryInterval`, and exactly `Fresh` is still fresh. | NET-2 Byte caps ("no older than twice the summary interval") | Measuring from the answer instead would let a slow answer extend a count's life. |
| KRN-cap-2 | **"What the kernel sent since the count" is every send the count may not hold.** A send is held by a count only if it ended before that count was asked for; every other reservation (reserved after the ask, or still in flight at it) is added in full. This counts some bytes twice and never one zero times, so it errs toward asking. | NET-2 Byte caps ("adds what it has sent to that group since the time that count covers ... plus its bytes in flight") | A per-byte sent figure from the transport would let the kernel subtract what the enforcer has already seen. |
| KRN-cap-3 | **The retry margin is one full re-send.** Each reservation is its size times `1 + Retries` (`Retries = 1`), so a send the transport retries once still lands inside the cap; a second retry needs a fresh `Reserve`. Sizes are IP bytes, headers and acknowledgements included, as the enforcer counts them; the caller estimates them. | NET-2 Byte caps ("a retry margin"); A18 ("with bytes in flight, a retry") | A smaller margin uses more of the cap and needs the transport to bound its retransmissions in bytes. |
| KRN-cap-4 | **At the cap is allowed; past it is refused.** The gate and the enforcer share one edge, `wire.PastCap` (count > cap), so they cannot disagree by a byte. A refusal is `*PastCap`, carrying the raise the owner is asked for (`Raise`). | NET-2 Byte caps ("traffic past a cap is dropped"); D-255 item 3 | If the enforcer's edge moves, both sides move with `wire.PastCap`. |
| KRN-cap-5 | **The enforcer's day and groups come only from its summary.** A summary replaces every group held, so groups that merged mid-day count as one; a summary on an earlier day, or answering a request asked before the one held, is refused (`ErrSummary`); a destination in no group of the latest summary has no count. | NET-2 Byte caps ("on the enforcer's day", groups) | A day held by the kernel would let a clock difference reset a cap early (D-255 item 3). |
| KRN-cap-6 | **A paused summary is no count.** After a core trip the enforcer answers summary requests Paused until the "core reflashed" step (D-260, D-262); `Paused` drops the count and moves the pause epoch, so an answer to a request asked before the pause is refused and only a summary asked for after it counts. Reservations are kept across the pause. | KRN-12 Response, NET-2 The channel (as #4347 words it) | If summaries resumed on the passkey instead of the reflash step, nothing here changes: the gate only waits for a summary asked after the pause. |
| KRN-cap-7 | **This package is the check only.** Reading summaries off the channel, not asking while paused, refusing the step and texting the raise, ending an edge fetch before its acknowledgements pass a cap, and checking each channel message against the shared format and rate before it is sent are the follow-up rows filed from #4173. Until they land nothing links the gate, so it adds no trusted-core lines. | #4173 | Wiring it into the kernel grows the trusted core and needs its D-159 row. |
