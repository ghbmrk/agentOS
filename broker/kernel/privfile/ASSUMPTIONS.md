# kernel/privfile root-side lint: assumptions

Rows added by REV-CHK-links-egress, REV-CHK-links-localui, KRN-2-std-files, KRN-2-manager-opens and REV-CHK-links-ns7 (#4623, #4636, #4641, #6143, #6033; D-271). Each is a reading a later change could overturn. The lint itself is `pathops_lint_test.go`; its header says what it holds and what it leaves out.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| REV-CHK-links-localui-1 | **Every unit the image ships from `broker/` is a regular file outside `testdata` and `node_modules`, and `image/build.sh` installs it under its own name.** `rootBinaries` reads those files beside `image/`'s units, so a root step such as `agentos-localui.service`'s `ExecStartPre=+/usr/lib/agentos/agentos-port1` makes its binary root-side. The lint does not parse build.sh's `install` lines: a unit build.sh installs under another name would be read under its file name, and its drop-ins under `image/` would not reach it. | build.sh lines 128-131 (four units, each installed under its file name) | If build.sh renames a unit on install or takes one from another tree, the lint reads build.sh's install lines instead. |
| REV-CHK-links-egress-1 | **`egress-setup` runs no broker binary as root.** It runs `agentos-egress init -setup` under `setpriv --reuid=agentos-egress --regid=agentos-egress --clear-groups`, and the setuid from root clears its capabilities (no keep-caps, no ambient set), so `agentos-egress` is not root-side; #4623's premise (it ran as root) no longer holds on main. `tests/test_image.py` pins the setpriv line. | egress-setup; `agentos-egress-setup.service`; test_image.py | If egress-setup runs `agentos-egress` without that drop, the binary's packages must join the root side (a `root_programs.txt`-style line or a unit of its own), and its build-tagged `upstream_e2e.go` must be readable by the lint first (#4623's fix). |
| KRN-2-std-files-1 | **The manager opens a unit's `StandardInput=`, `StandardOutput=` and `StandardError=` files (`file:`, `append:`, `truncate:`), its `EnvironmentFile=`, `LoadCredential=`/`LoadCredentialEncrypted=` and `TTYPath=` as root before the command drops to `User=` or `DynamicUser=`**, following a link, so the lint holds them on every unit to rootTrees as on a root unit (KRN-2-std-files). `OpenFile=` and the mount and namespace keys are KRN-2-manager-opens-1's. | systemd.exec(5); systemd's exec child opens these before `setresuid` | A systemd release that opens any of them after the drop could relax that key; a new key the manager opens as root joins `managerOpens`. |
| KRN-2-manager-opens-1 | **On a unit with no root command, the manager opens, mounts or joins as root, following links, the paths of `OpenFile=`, `BindPaths=`/`BindReadOnlyPaths=` (the source), `RootDirectory=`, `RootImage=`, `MountImages=`, `Extension*`, `NetworkNamespacePath=`, `IPCNamespacePath=`, `BPFProgram=` and `IP*FilterPath=`, and another uid can plant a link only in a world tree or at or below a grant**: a `*Directory=` a unit gives its user or opens by mode, or a tmpfiles line (`userOpens`, `opensHeld`). A bind's destination is inside the unit's own view and is not held. | systemd.exec(5); the exec child sets these up before `setresuid`. The keepers' `/run/agentos-kernel` is made `agentos-kernel`'s by the kernel unit's own root `ExecStartPre=install -o`, which no grant records: the kernel serves those sockets and is trusted core (KRN-2). | A directory another uid owns made by any other route (a root command's `chown` or `install -o`, a package's maintainer script, a daemon's runtime `mkdir`) is not seen; a path below one would pass. A new key the manager resolves as root joins `userOpens`. |
| KRN-2-manager-opens-2 | **`PermissionsStartOnly=` makes a unit root unless every assignment is one of `parse_boolean`'s false words, and `AmbientCapabilities=` makes it root unless every word is on `userCapNames`** (`CAP_NET_BIND_SERVICE`, `CAP_NET_RAW`, `CAP_WAKE_ALARM`, `CAP_BLOCK_SUSPEND`), none of which reads, writes or changes another uid's files, sets an id or runs code as root; `CAP_NET_RAW` does see another uid's plaintext on loopback, so a service of ours speaks to another uid over loopback only with its own authentication. `CAP_SYS_BOOT` counts only on a line under `image/camnode/`: elsewhere it grants `kexec_file_load`, which boots the signed kernel with any initramfs as PID 1, with no firmware MOR wipe between and the boot PCRs unchanged; the camera node's kernel has neither `CONFIG_KEXEC` nor `CONFIG_KEXEC_FILE` (`tests/test_image_camnode.py`). | systemd's `parse_boolean` and `capability_from_name` (names in any case, numbers too); capabilities(7). A package's own `AmbientCapabilities=` is not read: its commands are its own (#4677). | A capability added to `userCapNames` is a reviewed edit against that test. |
| REV-CHK-links-ns7 | **An image built from overlays is one merge per build, and each build of camnode merges only `common` with one board** (`cm4` or `qemu`), so a link in an overlay is answered only by a copy in each merge that holds it. **systemd reads an instance's `pre@inst.type.d` drop-ins whatever starts the instance** (a link, a `.timer`'s `Unit=`, a `Wants=`, a socket instance), so the source lint reads each such directory against every same-image copy of `pre@.type`, linked or not. | `image/camnode/external/configs/*.config` `BR2_ROOTFS_OVERLAY` (held to `imageOverlays` by `TestImageOverlaysAreListed`); systemd.unit(5) "drop-in" search order. | A new board, or a build merging more overlays, is a listed merge or that test fails. |
