# Release signing and update verification: assumptions

Built for P4-3 (BOARD.md) against SPEC v0.12. Covers `broker/update` and
`cmd/agentos-release`. Each row is a reading of the spec, or a gap left for a
later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| U1 | TUF is go-tuf v2.4.2, the reference Go implementation, vendored and hash-pinned. Versions before 2.3.1 accept a role threshold of 0 (GHSA-fphv-w9fq-2525) and panic on malformed metadata (GHSA-846p-jg2w-w324), and 2.3.1 needs Go 1.25, so the broker module moved from go 1.22 (out of support) to `go 1.25.0` with `toolchain go1.26.8`. go-tuf brings sigstore's signature package, go-securesystemslib's canonical JSON, and protobuf; none runs at boot or contacts anything (A9 static scan passes; the vendored doc-comment and error-message URLs are listed in `inert_literals`). Only `update` and `cmd/agentos-release` import it; `agentosd` stays third-party-free (ARC-2). | UPD-8, DEP-1, ARC-2 | Bump go-tuf with each advisory. |
| U2 | Roles: root and targets are offline, held by maintainers, each with a k-of-n threshold; snapshot and timestamp are single online keys used by a scheduled `refresh`, which cannot add or change a release. Defaults: root and targets expire after 365 days, snapshot 7 days, timestamp 1 day. Root rotation needs the old root threshold and the new one. A check that accepts a rotation reports the new root version (`Result.RootRotatedTo`) so the digest can log it (Security R3). All keys are Ed25519. | UPD-2, UPD-8 | Expiries are constants in `repo.go`. |
| U3 | The box refuses a root or targets threshold below 2 (`Options.MinThreshold`; a lower setting counts as 2), so one stolen key cannot sign a release even if a root said 1. One key listed under two key IDs counts once, and a threshold of 0 for any role is refused (both go-tuf behaviour, pinned by tests). Every root in the rotation chain must meet it, and the box saves no root past a weak one. A single maintainer meets this with several keys held apart (SPEC open question 6, key custody, is still open). | UPD-8, §16 q6 | Mark decides custody. |
| U4 | Offline (`Options.Offline`, a drive): signatures, thresholds, root rotation, metadata version rollback, and "newer than installed" are all checked; no expiry is, including root and targets, since a drive can be months old. The release is `Fresh() == false`; `Commit` records the manifest path and SHA-256 and leaves the freshness check pending, and the owner sees `OfflineNotice`. The next online `Check` settles it only after the whole check succeeds: `FreshnessConfirmed` if the fresh targets list that exact manifest, otherwise `FreshnessFailed` (the check stays pending; the owner sees `NotConfirmedNotice`). Online, expired timestamp, snapshot, targets or root metadata is refused. **Limits.** Offline, a revoked key stays usable for drives signed before its revocation until the box next sees a newer root: a drive carries its own metadata, and nothing offline says the key was revoked. A box's local saved metadata blocks rollback below what it has seen, but a box restored from an older disk image loses that; P2-4b's TPM NV monotonic counter (egress V6) is the anchor the updater should bind the installed version to. A default refusal of drives whose root expired more than 180 days ago is a pending K line on BOARD (arbitrator; spec substance, waits on Mark). **Clock.** Online expiry trusts the box's clock (`Options.Now`); a clock set back lets a frozen mirror's expired metadata pass. A floor (never earlier than the newest accepted timestamp's signing time, or a TPM-backed time) belongs to the updater. A clock far in the future refuses everything as expired (tested). | UPD-8, DEP-4, A14, HW-5a | Checking root or targets expiry offline would refuse old drives. |
| U5 | A release is one target, `releases/<version>.json`, holding the `/usr` verity root hash and the target paths of its boot files and images; every named file must be a signed target or the box refuses the release. Versions are positive integers and only go up, in the tool and on the box. `*Verified` is only made by `Check` (sealed; a zero or hand-built value is refused by every method with `ErrNotChecked`), so activation and the PCR-policy signing in P2-4b (its T4) can require one. `Fetch` writes a file only after its signed length and SHA-256 match, and syncs the file and its directory, as every metadata write does. | UPD-1a, UPD-8, HW-5a | — |
| U11 | One type: `change.Pipeline.ProposeRelease` takes the `*update.Verified` that `Store.Check` makes, and refuses nil or a zero value. `Version()` is the version as a decimal string and `Images()` every release file with its signed SHA-256, so release files live under `host-image/` or `guest-image/`, the pipeline's namespaces. `Security()` is false unless `WithAttestations(atts, own)` found `SecurityAutoStage` satisfied; the manifest flag alone never sets it. #34's stand-in `Verify` is gone; its tests are ported (threshold, images only, one key once, strict decoding). | CHG-3, UPD-8 | — |
| U6 | Channels: a stable box takes only stable releases, a fast box takes both, a pinned box does not check for automatic updates. Soak and cadence (UPD-5), quiet windows (UPD-6) and the journaled update intent belong to the updater, not here. | UPD-4 | The updater package. |
| U7 | Attestations are DSSE v1 envelopes (written out in `attest.go`; the go-securesystemslib `dsse` package would also vendor `x/crypto/ssh`) over a statement naming the release's manifest path and SHA-256, the result, channel, hardware class and versions, the attestor's Ed25519 key, and an optional operator label. A security fix auto-stages only with one valid passing fast-channel attestation from an independent key (D6, arbitrator ruling): not listed by any root this box has accepted, for any role (the box keeps every such key in `seen_keys.json`, so rotating a key out does not make it independent), not in the signed maintainer-operated attestor list (`attestors/maintainer.json`, staged with `agentos-release attestors`), not self-labelled `operator: maintainer`, and not the box's own. A maintainer-run CI attestor runs from day one; `MaintainerPasses` counts its passes as evidence for the digest, labelled maintainer-operated, never as independent. **Residual:** anyone can mint a key, so a signing threshold that is itself malicious can also mint an "independent" attestor and stage a forged security fix; D6 guards against a maintainer mistake, not a compromised quorum. The security lens (#53, B1) asks instead for an allow-list of attestor keys pinned in the image or owner configuration, changed only by an update the old list attested; that conflicts with the arbitrator's definition and is with the coordinator as a decision. Until it lands, Loop 3 keeps attestations unwired. Weighting by reproducibility (OSS-9), where the box's attestation key lives, and how attestations are fetched are later. | OSS-8, OSS-9, UPD-8 | — | OSS-8, OSS-9, UPD-8 | — |
| U12 | `Check` and `Commit` hold an exclusive `flock` on `<Dir>/.lock`, so two checks (two mirrors, or the updater beside Loop 3) cannot interleave saved metadata and lower the rollback floor (security lens C3). `Result.SecurityFix` names the highest release above the installed one on the box's channel marked as a security fix, so a newer ordinary release does not hide it (C2). | UPD-5, UPD-8 | — |
| U8 | `DirSource` reads a repository directory (a drive or a synced mirror) and refuses any path with `..`, empty or hidden segments. An HTTP mirror source, with owner-configured mirrors declared as endpoints, is the updater's. Metadata reads are capped at 4 MiB and manifests at 64 KiB. Metadata holding a JSON `null` anywhere is refused before go-tuf parses it, and any other panic during `Check` fails closed as `ErrBadRepository`: go-tuf 2.4.2 dereferences a null targets entry while parsing, after the snapshot's hash check but before signatures, so a thief with only the online snapshot and timestamp keys could otherwise crash every checking box (`TestOnlineKeysCannotServeNullTargets`; worth reporting upstream). Manifests, the attestor list and attestations decode strictly: no unknown, duplicate or case-variant key, nothing trailing. | DEP-4, UPD-2 | The updater package. |
| U9 | Private key files are plain PKCS #8 PEM, mode 0600, meant for offline media; `LoadPrivateKey` refuses a file its group or others can read or write, and `keygen` prints an offline-media reminder. No real keys exist yet (K3). The custody and rotation procedure, any passphrase or hardware-token storage, and the scheduled `refresh` job on the publication repository (OSS-11; it needs the online keys as secrets) wait on Mark's key-custody decision. | UPD-2, §16 q6 | — |
| U10 | Moving to Go 1.26 changed three things outside this package: `e2e/a14_test.go` records the guest socket's redirect of an unclean path as 300 (Go now answers 307 where it answered 301; the path is never served either way); CI's format check skips `vendor/` (go-digest's upstream files are not gofmt-clean); the A9 audit job installs the module's Go before its offline build. Every CI job, the root-run test steps, and `broker/test/a9-scenario.sh` set `GOTOOLCHAIN=local`, so no build downloads a toolchain; box image builds must do the same (lens condition). | A14, A9 | — |
