# Enforcer daemon: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice l, ENF-l-a, #3670).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-l-1 | **One policy lock.** The page (`page.Config.Lock`), the book (`enrol.Config.Lock`), the channel (through `lockedPolicy`) and the clock's `Engine.Tick` share `Enforcer.mu`; the page and the book take it themselves, so `pagePolicy` takes none. `Book.Tick` runs without it held (ENF-c-8). | ENF-d-5, ENF-c-8 | A second engine caller wires through `lockedPolicy`. |
| ENF-l-2 | **The firewall follows the policy in force, never a request.** After a tightening (channel or page) the run loop is kicked; every tick also compares the hash of `Engine.Current()` with the last loaded and reloads (`nft.Reload` with the running table) only on a change. A refused load leaves the previous ruleset (nft's transaction) and is retried next tick; each load has 30 s (`fireTimeout`), so a hung nft cannot stall the clock. Every start, first boot included, must load the policy in force before anything is served: a refused first load fails `open` and the service manager restarts the daemon, since the box may have booted with any ruleset (#4755 item 3). First boot loads the empty document's ruleset: default deny. | P4, P5, decision 4 | Byte-cap drops (`nft.Drops`) are ENF-l-b's, with the traffic counter. |
| ENF-l-3 | **State is files in one directory the daemon alone can read.** The directory must be owned by the running user with no group or other bits and not be a symlink; stores are replaced atomically (temp file, fsync, rename, fsync of the directory) and journals are appended with fsync. "The enforcer's sealed store" (ENF-a-7) is this directory on the image's encrypted, verity-backed data partition (slice m); no TPM sealing here. The daemon refuses to run as root. | STO-4, NET-2 Hardening | Slice m names the partition and the unit's user and capabilities (CAP_NET_ADMIN, CAP_NET_BIND_SERVICE). |
| ENF-l-4 | **The page is rebuilt, not mutated.** When the passkey in force changes (enrolment, recovery applied, factory reset) or the leaf certificate renews, a new `page.Server` is built and the listeners move to it; the old page already refuses taps from the moment the book's passkey changed (`live`), so the gap refuses rather than accepts. Challenges and anti-forgery tokens drawn by the old page do not carry over. | ENF-c-8, NET-4 | — |
| ENF-l-5 | **The core trip here is the minimal cut DECOY-d builds on.** A frame outside the format or a burst trips it (`channel.Cut`), it is saved before the alerts and survives a restart; a trip whose `cut.json` write fails stays in force, is retried each tick and at `Close`, and the channel listener takes no connection until it lands, so only a power loss before any retry succeeds loses it (#4755 item 1), a repeat trip writes nothing (#4606), and only the page's passkey resume lifts it (`page.Channel`, ActResume), which also resolves the channel-paused alert and the core's trip. A trip raises `ChannelPaused` and `Trip` (device `core`; the light goes red, ENF-h-a4). The firewall's cut of the core's segment, the "core reflashed" stage, `heads.Store.Trip` and the modem and edge plugs are DECOY-d's (#3765). | KRN-12 Response, NET-2 Channel, ENF-d-4 | DECOY-d replaces `cut` with its own and keeps `cut.json`'s meaning. |
| ENF-l-6 | **The core's channel sub-key is a pinned file.** `core.pub` (base64) is written when the core is set up beside the enforcer; with none, the daemon runs no channel and no head store, and alerts reach only the page, log and light. The enforcer's own channel key is made on first start (`channel.key`, mode 0600) and printed with `-channel-pub` for the kernel to pin. Pairing both keys through the page is not built. | DEV-2, KEY-7 | A pairing step on the enforcer's page writes `core.pub`. |
| ENF-l-7 | **The core counts as up while it spoke within `Silence`, two summary intervals; every session it authenticates is offered the alerts no session took.** Every channel log line but a failed hello's is the authenticated core's and refreshes it, on the rate clock. SPEC KRN-12 Silence names a heartbeat "at a fixed interval" that the format definition does not yet set; one beat per `wire.SummaryInterval` is assumed. A cut core whose lines pass `KindPaused`'s bucket goes unlogged and can read as silent. A hello's re-offer marks the core told up under the same lock as `Tick`, so the next tick that finds the core silent shows it down (#4755 item 8). | KRN-12 Silence, NET-2 | The interval moves into `wire` and both ends read it. |
| ENF-l-8 | **The channel listener is the per-source limit.** Only `core_allow` addresses get a TLS handshake (others are closed unanswered), at most `MaxCoreConns` connections are open at once, the TLS handshake and the core's hello together have 10 s from accept, an authenticated session ends after `Silence` plus 10 s with no read (each read and write has that deadline), and an idle end is a close, not a refused frame or a line that counts the core as up (#4755 items 2 and 4); a temporary `Accept` error is retried with backoff to 1 s, and any other stops the daemon for the service manager to restart (item 5), and TLS 1.3 runs under a certificate made for each run that nothing trusts: the hellos bound to the exporter authenticate both ends. | ENF-d-4, ENF-d-w1 | Slice o's client must dial TLS 1.3 without verifying the certificate and send the hello. |
| ENF-l-9 | **The rate clock is CLOCK_BOOTTIME** (`bootTime`, x/sys/unix), which never steps back and counts through suspend; a failed read returns the last reading. The wall clock is for the log and the policy's times only. | #4507, ENF-d-10 | — |
| ENF-l-10 | **Until ENF-l-b2, the box's device pieces fail closed.** The access point refuses (`unwiredNetwork`), so enrolment enrols nothing and the setup network stays; every radio command and state read is refused (`noRadio`); each change of the light's colour goes to the log until its driver lands (#4305), and `Tick` tells the alerts the core's and the recovery's state only when it changes, so the light is re-shown on a change and at the minute's `Refresh` only; the page has no action, sealed-secret or heard-names inputs, so it refuses those links. | P1, P5, ENF-c-7 | ENF-l-b2 wires `ap/push`, `radio`, `devsecret`, `pairseal`, `action` and `locks`; ENF-l-b1 wired the resolver, `mdns`, `wol` and `traffic` (ENF-l-11 to ENF-l-15). |
| ENF-l-11 | **A document the resolver cannot serve still loads.** `dns.Generate` refuses a document whose names are not host names or whose device VLAN the setup does not name (dns ENF-f-2, ENF-f-5). The firewall loads it anyway, so a tightening is never held back by the resolver, and every dnsmasq instance stops (DHCP included, whose clients keep their 12-hour leases), so no list resolves until one can be served; the log says why each load. | NET-2 The core's list, P5 | A page check that refuses to sign such a document (ENF-f-2) would make this path unreachable. |
| ENF-l-12 | **The resolver moves in step with every load** (#4464, `dns/run`, dns ENF-f-9). Each load is `run.Set.Apply(files, load)`: the instances whose files change are stopped and have exited before the running table is read and the new ruleset loads, and start on their new files after; a refused load restarts them on their old files. The running table is read on every load, the first after a restart included (#4754 Potency point 1), so a restart keeps the answers of names still listed; an absent or unreadable table is logged and the load starts with none. | NET-2 The core's list, NET-3 | — |
| ENF-l-13 | **One pair relay at a time, on one filter.** Every load rebuilds the plan from the same document in one step, `mdns.NewPlan(nft.Paths, nft.Announces).Hearing(nft.Hears)` (#4397), stops the relay before it and starts it on the new plan. The filter is made once per process and given to both the relay and the page (`page.Config.Heard = mdns.HeardBy`), so the page offers only names the relay heard (#4531 comment 6568595938); a restart forgets what was heard. A relay that ends on its own is started again at the next tick. The Wake-on-LAN relay runs for the process's life on the configuration's machines (`wake`); a failure is logged and the relay starts again after a second, without stopping the daemon. | NET-3 Casting, HW-11 | A filter kept on disk would let a restart keep the names heard. |
| ENF-l-14 | **The byte caps are read every 10 seconds** (`readEvery`; #4376 wiring note). Each reading adds to the day (`Counter.Add`), saves the day to `traffic.json` before the drop moves, loads the in-kernel drop from the new counts (`load.Loader.Update`), and trips the core for each core cap passed (`cut.Trip`, idempotent). Every full load first reads the table it replaces into the day (a load starts new counters, nft ENF-cap-trip-c-2) and carries the drop for its caps in the same transaction; a clean stop takes a last reading. The document each load compiled is saved (`loaded.json`), so the first load after a crash reads the dead process's table against it: on the same boot the table keeps its Gen, so only the bytes since the last reading count, and a clean stop's table counts nothing twice. The channel's counts read takes a reading first. A saved day that does not read back (`traffic.ErrState`) is never counted from zero: every cap is loaded spent, so every capped send is dropped, the file is not overwritten, the counts read is refused, and the log says so; replacing the file and restarting is the only way out until the page has an owner step for it (release #5013). Only a power cut loses bytes: at most one interval's, which the drop already counted in the kernel. | NET-2 Byte caps, D-255 | A shorter interval costs one `nft -j list` per reading. |
| ENF-l-15 | **The edge's cap is held by the drop alone.** The in-kernel drop stops the edge's bytes at its cap, and an edge overrun is logged once a day. It raises no alert: no edge cut is built here (release #5014), so a `Trip` would name steps the edge does not have, and nothing would clear it (UX 6656586767). | NET-2 Byte caps | The edge cut (#5014) raises its own trip and lifts it. |
