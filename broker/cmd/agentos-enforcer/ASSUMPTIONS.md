# Enforcer daemon: assumptions

Each row is a reading of the spec, or a property the code relies on, that a
reviewer may want to change (briefs/ENF.md slice l, ENF-l-a, #3670).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| ENF-l-1 | **One policy lock.** The page (`page.Config.Lock`), the book (`enrol.Config.Lock`), the channel (through `lockedPolicy`) and the clock's `Engine.Tick` share `Enforcer.mu`; the page and the book take it themselves, so `pagePolicy` takes none. `Book.Tick` runs without it held (ENF-c-8). | ENF-d-5, ENF-c-8 | A second engine caller wires through `lockedPolicy`. |
| ENF-l-2 | **The firewall follows the policy in force, never a request.** After a tightening (channel or page) the run loop is kicked; every tick also compares the hash of `Engine.Current()` with the last loaded and reloads (`nft.Reload` with the running table) only on a change. A refused load leaves the previous ruleset (nft's transaction) and is retried next tick; each load has 30 s (`fireTimeout`), so a hung nft cannot stall the clock. Every start, first boot included, must load the policy in force before anything is served: a refused first load fails `open` and the service manager restarts the daemon, since the box may have booted with any ruleset (#4755 item 3). First boot loads the empty document's ruleset: default deny. | P4, P5, decision 4 | Byte-cap drops (`nft.Drops`) are ENF-l-b's, with the traffic counter. |
| ENF-l-3 | **State is files in one directory the daemon alone can read.** The directory must be owned by the running user with no group or other bits and not be a symlink; stores are replaced atomically (temp file, fsync, rename, fsync of the directory) and journals are appended with fsync. "The enforcer's sealed store" (ENF-a-7) is this directory on the image's encrypted, verity-backed data partition (slice m); no TPM sealing here. The daemon refuses to run as root. | STO-4, NET-2 Hardening | Slice m names the partition and the unit's user and capabilities (CAP_NET_ADMIN, CAP_NET_BIND_SERVICE). |
| ENF-l-4 | **The page is rebuilt, not mutated.** When the passkey in force changes (enrolment, recovery applied, factory reset) or the leaf certificate renews, a new `page.Server` is built and the listeners move to it; the old page already refuses taps from the moment the book's passkey changed (`live`), so the gap refuses rather than accepts. Challenges and anti-forgery tokens drawn by the old page do not carry over. | ENF-c-8, NET-4 | — |
| ENF-l-5 | **The core trip here is the minimal cut DECOY-d builds on.** A frame outside the format or a burst trips it (`channel.Cut`), it is saved before the alerts and survives a restart; a trip whose `cut.json` write fails stays in force, is retried each tick and at `Close`, and the channel listener takes no connection until it lands, so only a power loss before any retry succeeds loses it (#4755 item 1), a repeat trip writes nothing (#4606), a missing `cut.json` starts the core cut, logged, with `RecordMissing` (device `core`, light red, ENF-h-a4) and a reason that says to check the enforcer before resuming, since provisioning writes it uncut and nothing removes it, so its loss means root on the enforcer or lost state (#5282, #5399, `TestCutRecordsMissing`). ENF-m-b owes the image's first boot a `-provision` run (`provisionState`): without it the box starts with the core and the edge both cut, which fails closed but is wrong. Only the page's passkey resume lifts it (`page.Channel`, ActResume), which also resolves the channel-paused alert and the core's trip. A trip raises `ChannelPaused` and `Trip` (device `core`; the light goes red, ENF-h-a4). The firewall's cut of the core's segment, the "core reflashed" stage, `heads.Store.Trip` and the modem and edge plugs are DECOY-d's (#3765). | KRN-12 Response, NET-2 Channel, ENF-d-4 | DECOY-d replaces `cut` with its own and keeps `cut.json`'s meaning. |
| ENF-l-6 | **The core's channel sub-key is a pinned file.** `core.pub` (base64) is written when the core is set up beside the enforcer; with none, the daemon runs no channel and no head store, and alerts reach only the page, log and light. The enforcer's own channel key is made on first start (`channel.key`, mode 0600) and printed with `-channel-pub` for the kernel to pin. Pairing both keys through the page is not built. | DEV-2, KEY-7 | A pairing step on the enforcer's page writes `core.pub`. |
| ENF-l-7 | **The core counts as up while it spoke within `Silence`, two heartbeat intervals; every session it authenticates is offered the alerts no session took.** Every channel log line but a failed hello's is the authenticated core's and refreshes it, on the rate clock, and so does every hello the channel accepts, through its `Connected` hook, which also makes the re-offer, so neither waits on the hello's log line (#4903). SPEC KRN-12 Silence names a heartbeat "at a fixed interval"; the format definition sets it (`wire.HeartbeatInterval`, wire ENF-d-w8), and `Silence` is twice it. A cut core whose other lines pass `KindPaused`'s bucket goes unlogged, but each reconnect still counts it up and is offered the unsent alerts. A hello's re-offer marks the core told up under the same lock as `Tick`, so the next tick that finds the core silent shows it down (#4755 item 8). | KRN-12 Silence, NET-2 | Slice o's client (ENF-o, #3673) must send at least one message each `wire.HeartbeatInterval`, with a test that fails on any other interval. |
| ENF-l-8 | **The channel listener is the per-source limit.** Only `core_allow` addresses get a TLS handshake (others are closed unanswered), at most `MaxCoreConns` connections are open at once, the TLS handshake and the core's hello together have 10 s from accept, an authenticated session ends after `Silence` plus 10 s with no read (each read and write has that deadline), and an idle end is a close, not a refused frame or a line that counts the core as up (#4755 items 2 and 4); a temporary `Accept` error is retried with backoff to 1 s, and any other stops the daemon for the service manager to restart (item 5), and TLS 1.3 runs under a certificate made for each run that nothing trusts: the hellos bound to the exporter authenticate both ends. | ENF-d-4, ENF-d-w1 | Slice o's client must dial TLS 1.3 without verifying the certificate and send the hello. |
| ENF-l-9 | **The rate clock is CLOCK_BOOTTIME** (`bootTime`, x/sys/unix), which never steps back and counts through suspend; a failed read returns the last reading. The wall clock is for the log and the policy's times only. | #4507, ENF-d-10 | — |
| ENF-l-10 | **Until ENF-l-b2, the box's device pieces fail closed.** The access point refuses (`unwiredNetwork`), so enrolment enrols nothing and the setup network stays; every radio command and state read is refused (`noRadio`); each change of the light's colour goes to the log until its driver lands (#4305), and `Tick` tells the alerts the core's state only when it changes, so the light is re-shown on a change and at the minute's `Refresh` only; the page has no action, sealed-secret or heard-names inputs, so it refuses those links. | P1, P5, ENF-c-7 | ENF-l-b2 wires `ap/push`, `radio`, `devsecret`, `pairseal`, `action` and `locks`; ENF-l-b1 wired the resolver, `mdns`, `wol` and `traffic` (ENF-l-11 to ENF-l-15). |
| ENF-l-11 | **A document the resolver cannot serve still loads.** `dns.Generate` refuses a document whose names are not host names or whose device VLAN the setup does not name (dns ENF-f-2, ENF-f-5). The firewall loads it anyway, so a tightening is never held back by the resolver, and every dnsmasq instance stops (DHCP included, whose clients keep their 12-hour leases), so no list resolves until one can be served; the log says why each load, and home shows why for the policy in force once its load is taken (`pageResolver`, #5164 R1). | NET-2 The core's list, P5 | A page check that refuses to sign such a document (ENF-f-2) would make this path unreachable. |
| ENF-l-12 | **The resolver moves in step with every load** (#4464, `dns/run`, dns ENF-f-9). Each load is `run.Set.Apply(files, load)`: the instances whose files change are stopped and have exited before the running table is read and the new ruleset loads, and start on their new files after; a refused load restarts them on their old files. The running table is read on every load, the first after a restart included (#4754 Potency point 1), so a restart keeps the answers of names still listed; an absent or unreadable table is logged and the load starts with none. | NET-2 The core's list, NET-3 | — |
| ENF-l-13 | **One pair relay at a time, on one filter.** Every load rebuilds the plan from the same document in one step, `mdns.NewPlan(nft.Paths, nft.Announces).Hearing(nft.Hears)` (#4397), stops the relay before it and starts it on the new plan. The filter is made once per process and given to both the relay and the page (`page.Config.Heard = mdns.HeardBy`), so the page offers only names the relay heard (#4531 comment 6568595938); a restart forgets what was heard. A relay that ends on its own is started again at the next tick. The Wake-on-LAN relay runs for the process's life on the configuration's machines (`wake`); a failure is logged and the relay starts again after a second, without stopping the daemon. | NET-3 Casting, HW-11 | A filter kept on disk would let a restart keep the names heard. |
| ENF-l-14 | **The byte caps are read every 10 seconds** (`readEvery`; #4376 wiring note). Each reading adds to the day (`Counter.Add`), saves the day to `traffic.json` before the drop moves, loads the in-kernel drop from the new counts (`load.Loader.Update`), and trips the core for each core cap passed (`cut.Trip`, idempotent). Every full load first reads the table it replaces into the day (a load starts new counters, nft ENF-cap-trip-c-2) and carries the drop for its caps in the same transaction; a clean stop takes a last reading. The document each load compiled is saved (`loaded.json`), so the first load after a crash reads the dead process's table against it: on the same boot the table keeps its Gen, so only the bytes since the last reading count, and a clean stop's table counts nothing twice. The channel's counts read takes a reading first. A saved day that does not read back (`traffic.ErrState`) is never counted from zero: every cap is loaded spent, so every capped send is dropped, the file is not overwritten, the counts read is refused, and the log says so, until the owner's fresh day on the page is saved (ENF-l-19) or the file is replaced and the daemon restarted. Only a power cut loses bytes: at most one interval's, which the drop already counted in the kernel. | NET-2 Byte caps, D-255 | A shorter interval costs one `nft -j list` per reading. |
| ENF-l-15 | **The edge past its cap is cut until the owner lifts it on the page** (#5014, `edgecut.go`). An edge overrun cuts the edge's record (`edgecut.json`: why, and the day) and raises a `Trip` naming the edge, which turns the light red, then writes the drop again at once with the cut (`nft.Drop.EdgeCut`, nft ENF-edge-cut-1); every later drop and full load carries the record's cut, so a restart's first load is already cut. The core's channel is untouched. A trip whose write fails is in force, retried each tick and at close, as the core's (ENF-l-5). The kernel itself cuts the edge at the first byte past its cap (nft ENF-edge-cut-2), before the reading that trips the record, so a firewall write that fails after a trip leaves the edge cut; it asks for a full load at the next tick, whose refusal the page names. The kernel's cut is held off (`nft.Drop.EdgeHold`, `holdDrop`) while the edge's quota is spent rather than counted (its port merges segments, ENF-l-16, or the day is unreadable, ENF-l-14), so an edge within its cap is never cut, and on the day the owner lifted a cut; while the edge's port merges segments, a trip's cut is the record's write alone. The merge's hold lasts until a full load the firewall takes starts the quota and `edge_trip` afresh, since a refused one leaves the spent quota running (#5399 item 5, `TestMergeHoldOutlivesARefusedLoad`). A reading whose running table has `edge_trip` holding the edge, under a drop that keeps it, trips the record even with the count within the cap, so the kernel's cut always has a card and a lift (`nft.EdgeTripped`, #5399 item 2, `TestKernelCutRecorded`). A full load over a table this process loaded that does not read is refused and the running table stays, since replacing it would lose its bytes since the last reading and `edge_trip`; the first load after a start reads none (a reboot leaves no table), so a crash's unreadable table loses them (#5399 item 6). A record that is missing or does not read back starts the edge cut, logged, raises `RecordMissing` naming the edge (light red), and its card says to check the enforcer before the lift; the owner's lift writes it whole again (fails closed): provisioning writes it uncut (`provisionState`, which ENF-m-b's first boot owes, ENF-l-5) and nothing removes it, so its loss means root on the enforcer or lost state (#5282, #5399). Such a cut has no day, so its lift holds for the rest of the lift's day, as a lift on an overrun's day does (#5399 item 4). The edge's `Trip` text reaches the core as an owner-line text, so a compromised edge can signal the core with one event per lift, whose timing it chooses (it decides when to cross its cap), so each event carries as many bits as the core can tell instants apart, and it must wait for the owner's lift before signalling again; the uplink the edge and the core share already offers a far larger channel (the edge's own traffic, which the core sees as load on the uplink), so the text is left as it is (#5282 item 3). Only the owner's passkey on the page lifts it (`page.ActLiftEdge`, after the tap, as `ActResume` lifts the core's channel): the record first, then the drop without the cut, and the edge's trips resolve. A lift on the day of the overrun holds for the rest of that day, since the edge stays past its cap all day and its internet bytes stay held there by the drop; the next day's overrun cuts again (`TestByteCapTripsTheEdge`, `TestEdgeCutRecordUnreadable`, `TestCutRecordsMissing`). | NET-2 Byte caps, KRN-12, P5 | DECOY-d (#3765) can trip the same record for an edge decoy. |
| ENF-l-16 | **A counted port that merges segments has its caps held spent** (#4610, #5088, offload ENF-gro-1). `open` asks `offload.Off` for the core's and the edge's ports, one at a time, before the byte caps are restored. A port that is missing, unreadable or still merging does not stop the start: its caps are loaded spent (the core's groups and the edge's cap, as ENF-l-14 loads them all), so every capped send it carries is dropped, and the other port and the rest of the daemon run on. Before every reading it asks again, since a port whose device is made again starts with its driver's defaults; a port that starts or stops merging there brings a full load, since a running quota keeps its own count, so its caps are spent or count again from the next load. Each start and end is logged once, and a full load the firewall refuses is asked for again at every tick until one is taken, a reading with no change included (`TestMergingReloadRetried`). The residual is a device made again between readings: its bytes count short until the next one (at most `readEvery`, 10 s). | NET-2 Byte caps, D-255 | A cut of the core on a merging port, instead of its caps' drop, would go through KRN-12. |
| ENF-l-17 | **The page shows the alerts as the alert log holds them** (#4750, `pageAlerts`). Every open alert with its fixed wording, when it began, its count and whether the core took its text; the core down after `Silence`; and the light red only while a trip is open. The owner clears an alert there after a passkey tap (`alert.Resolve`); a paused channel's alert clears only by resuming it. A clear whose journal append fails is cut back from the journal and left open, so the answer, the run and the disk agree (alert ENF-h-a journal rule); only a failed cut-back as well can leave it cleared on disk, which is the clear the owner asked for. The page links no alert type: the daemon maps `alert.Status` to `page.Status`. | NET-2 Texts and calls (P6), KRN-12 Silence, D-254 | If an alert kind needs a step other than clear, give `page.Alert` that step, as `Fixed` does for a paused channel. |
| ENF-l-18 | **The owner revokes the pinned core's sub-key on the page** (#4751, `pageCore`). The challenge is `key.RootMsg(heads.SubKeyRoot(owner, core))` for the passkey in force, and the tap goes to `RevokeCore`, which checks it again. The revocation closes the core's channel only (hello and every frame): the firewall, the cut and the core's allow list are unchanged, and the page says so rather than "cut off". A revocation the head journal could not save is in force for the run (and cut back from the journal, as heads does), and the page says so and offers it again until a tap saves it: `pageCore.Revoked` answers in force and saved apart, so home shows a third state after a reload, "revoked only until the enforcer restarts", with the button again (#5106); were the cut-back to fail too, the journal ends in a torn line a restart drops (or, after a failed sync, the whole revocation, which only errs toward refusing the core), and the head store appends nothing until a cut-back succeeds (heads ENF-h-5), so a revocation the page calls saved is a whole line no later failure removes. Only the core's one pinned key is offered (ENF-l-6). A forked-log alert's card names the choice (keep the core, or revoke its key) and links to the step. | KEY-7, STO-4 (stolen core), STO-1, heads ENF-h-1 | If revocation should also cut the core's network, add the cut here and change the page's words with it. |
| ENF-l-19 | **An unreadable byte-cap day starts afresh only on the owner's tap, after `policy.Wait`, and the record of it is the spent day itself** (#5013, D-255, `pageCaps`, state.go). While `traffic.json` does not read back, each step writes it whole, once (`fileStore.Save`): the approval `{"fresh_day":{"due":T}}`, the cancel `{"fresh_day":{}}`, and at T the start, a day from zero whose last reading is the running table as it is then, so nothing the spent drop dropped counts against it. Neither record reads back as a day, so every cap stays spent while one is on disk; an approval exists only inside the spent day it was approved for, and any day that reads back (the start, or a file replaced by hand) has none, so no approval outlives its day and no second file can disagree with the first. The run never takes the start up in place: once its save returns nil the daemon stops (`errFreshDay`) and the service manager starts it again, and `openNetwork` reads the day like any saved one. Only a Save that returns nil (written, synced, renamed, directory synced) confirms a step. An approval or cancel whose Save errs, whatever the file then holds, is in force for the run, answered `"saved":false` and shown on the page as not confirmed, and saved again every second and at a clean stop. Once T passes the start is committed for the run: a cancel is refused ("the fresh day is starting"), every cap stays spent, and the start is read and saved again every second until a Save returns nil; a crash meanwhile leaves the approval, already tapped and waited, which starts at the first tick. `fwMu`, then the fresh day's lock, are held across the start's check, reading, save and commit, so a cancel wins before it or is refused. Limits: a power cut can still roll back a rename whose directory sync failed (the limit every state file here shares), which for a cancel answered `"saved":false` can bring back the approval; the bytes the core sends between the start's save and the restart count against the fresh day, which errs toward spent. | NET-2 Byte caps, NET-4 Loosening, ENF-l-14 | If the wait should be the policy's own pending loosening, move the step into `policy.Engine`. If the restart is too coarse, take the day up in place under `fwMu` once `counts` reads the counter under it. |
| ENF-l-21 | **The resolver runs only on served interfaces as set up** (#4222, dns ENF-f-5). At every load and every reading the daemon (`hold`) writes 0 to `accept_redirects` (IPv4 and IPv6) and `accept_ra` under `/proc/sys/net/*/conf/` for `default` and for each `DNS.Nets` interface that exists, and to `ipv4/conf/all/accept_redirects` (the kernel combines it with each interface's), reads each back as the value written, and checks every address the kernel holds there (one `RTM_GETADDR` dump, taken once more if the kernel marks it interrupted and failing if the second is too, or if its end carries an error or is missing: #5164 item 8; the interface's index is looked up before the dump and again after it, and one made again or gone in between fails, since the kernel numbers each new interface past the last: #5188) lies in that `Net`'s prefixes with a prefix no wider, or is its `fe80::/64` link-local one. While that fails, every load runs no instance (`dns.Files{}`, as ENF-l-11; the firewall still loads), stopped before the load so a refused load starts none of them again (#5164 item 7), the failure is logged once and its end once, home shows the resolver stopped while no instance runs (each address outside its `Net` with its interface, every other failure by its typed cause, which the page words without reading its text (#5284; an IPv6 tree whose presence cannot be read is `UnsetIPv6`, #5307), the policy in force's refusal by the typed cause `dns.Generate`'s error carries, the name or device it refused (`refusedCause`, #5307, #5352), and with no such cause the step that refused the last load, compile (`compileErr`) or the firewall (`fireErr`), never its error's text, since a check that passes starts nothing until a load is taken; `pageResolver`, #5164 R1, R5 d; while the instances run, home shows each that keeps exiting from dns/run's `Flapping`, R5 b), and a change either way brings a full load at that reading. No other interface's own keys are written. **The uplink:** NET-2's one enforcer uplink is the WAN to the ISP router (the modems are on the core and the edge, HW-2); a WAN made after the daemon starts, like any later interface, starts from `default`, so with `accept_ra=0` it takes no router advertisement until its link configuration says so. ENF-m-b's WAN configuration must therefore set it explicitly on the WAN: networkd's `IPv6AcceptRA=` (networkd reads advertisements itself and keeps the kernel's off), or `net.ipv6.conf.<wan>.accept_ra=2` in `sysctl.d` (2, since forwarding ignores 1; udev applies it again to a WAN made later). The daemon never writes the WAN's keys (#5164 R2, item 6). An interface not there yet passes: it is made from `default` and set and checked at the next reading, so the residual is at most `readEvery` (10 s) of a new interface with an address set by hand before the check sees it. A kernel booted without IPv6 has only the IPv4 key. Writing these needs `CAP_NET_ADMIN` in the host namespace and a writable `/proc/sys/net`: ENF-m-b's unit must not set `ProtectKernelTunables=` (or must make `/proc/sys/net/ipv4/conf` and `/proc/sys/net/ipv6/conf` writable); until then the check fails and no instance runs. | NET-2 Segments, NET-2 Fails safe | ENF-m-b |
| ENF-l-20 | **The resolver's answers are refreshed every 10 seconds** (#4453, nft ENF-set-ttl-1). Each tick that reads the byte caps then lists the running table and applies `nft.Refresh` of the document in force through `load.Loader.Update`, under the firewall lock, so never between a load's reading of the table and the load; nothing is applied when no answer is fresh. A failing step is logged when it starts or changes and its end once; while it fails, the answers since the last step keep taking new connections until one succeeds, each for at most `nft.AnswerTimeout` from its first answer (the fresh set's own timeout, #5116). | NET-2 The core's list | A longer interval lets an answer take new connections for up to that much longer than `nft.AnswerTimeout`. |
| ENF-l-22 | **No stack step runs on the main thread** (#5159, #5286). The runtime never ends the main thread, so a step left there in a stack's network namespace would keep that namespace alive past the stack. confine moves any step it finds on the main thread to another (`step` in confine.go, `TestStepLeavesTheMainThread`), in any binary; main.go's `init` lock on the main thread (`TestNoStackStepRunsOnTheMainThread`) is a second guard. | NET-2 Confined radio stacks | A step that must run on the main thread would go through the main goroutine. |
| ENF-l-23 | **Every full load seeds the shared segments' leases from the DHCP server's lease file** (#5295, nft ENF-shared-src-1). In the load step, after the running table is read, the daemon reads `dns.Setup.LeaseFile` and appends `nft.Seed` of its IPv4 leases to the ruleset, before the byte caps' drop, in the one transaction, so a restart or reboot does not cut every leased IPv4 host on Guests, Owner or Household off until its next renewal (up to 6 h). A line (`expiry mac ip hostname clientid`) seeds its address on the one shared segment whose DHCP subnet in `dns.Setup.Nets` holds it, for `expiry` minus the wall clock; it seeds nothing when the address is in no subnet, in two, in one that is not a DHCP-served shared segment's, or outside that subnet's lease range (`dns.Hosts4`, the range dnsmasq serves, which the network, broadcast and enforcer's own addresses are outside), nor when the line is not exactly five fields, its hardware address is not Ethernet, or its lease is infinite (expiry 0), run out or longer than `nft.LeaseTimeout`. A missing file (first boot) seeds nothing; an unreadable one seeds nothing and is logged; neither refuses the load (`TestLoadSeedsLeases`, `TestLeasesOf`, `TestLeaseFileUnreadable`). | NET-1, NET-3 | A lease file another DHCP server writes, or a lease time over `LeaseTimeout`, would need the parse and Seed's bound to change together. Residual: a wall clock ahead after a reboot drops leases (fails closed), but one behind by less than `LeaseTimeout` minus a lease's time left seeds that lease for the lag longer than it has; if the clock then steps forward, dnsmasq can lease the address to another host while the old holder's element lasts, the same window as a lease ended early (#5300). No code can tell a wrong clock from a right one at boot. |
