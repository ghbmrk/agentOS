# Assumptions: the camera clerk's process (CAM-clerk part d, #3514)

What the process rests on. Brief: `briefs/CAM-clerk.md` (part d, CAM-clerk-host); the library's rows are `broker/clerk/camera/ASSUMPTIONS.md` (CAM-clerk-1 to -16).

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| CAM-host-1 | **The owner side checks tier 4; the clerk trusts its socket's peer.** The owner socket admits only the owner side's uid (agentosd's, `sockets.ListenPeers`), as the mail clerk's owner socket does. agentosd checks the approval code a tier-4 step carries (`localapi.OpCameraChange`, `localapi.CameraTier4`) before it relays the step. agentosd's handler for the camera page ops, its relay of STOP and RESUME, and its read of the enforcer's listed nodes are the agentosd chain's follow-up (no `cmd/agentosd` edit here, D-111). Until it lands, no step reaches the clerk and no camera connects. | DEV-10, CH-3, KRN-7 | A clerk that checked the code itself would need the code generator's seed, which only the kernel holds. |
| CAM-host-2 | **Every connected camera is in the capture store before the first sweep** (#3625). `Store.Sweep` erases every camera directory the store has not taken, and is also each camera's retention expiry. At start the host adds every camera in its file to the store, then sweeps, then connects each to the clerk and its decoder and opens streams. A camera the clerk or decoder refuses stays in the store, so its retained capture is kept and still expires on time, and every other camera's sweep goes on. A camera the store itself refuses (its sealed key slot failing) refuses the start, since no sweep could then run safely. The cameras file is refused whole on any malformed record, so a torn edit cannot drop a camera that a sweep would then erase. Disconnect removes the camera from the file before erasing, so a crash between the two leaves a directory the next start's sweep erases. | DEV-7 | A store whose `Sweep` takes the connected set would make the store's membership and the clerk's independent. |
| CAM-host-10 | **An owner change is saved before it is applied.** `update` writes the new record first and applies nothing if the save fails, so no stream opens on a setting the file does not hold. A failed apply restores, saves and re-applies the old record; apply reads only its record arguments, so the rollback closes what the change opened. A re-pin carries the listed node's address with its key, so a node that came back at a new address is pinned there. | DEV-3, DEV-7 | — |
| CAM-host-3 | **Tamper events are logged until the kernel's device-report entry exists.** DEVSLOT b3 (DEVSLOT-kernel) is not merged, so `eventSink` writes one fixed line per event: the camera's ID, the kind and the count, never a byte the node sent (design point 6). The rate limit (DEV-8) applies before the sink, and the clerk flushes its windows every minute. | DEV-8 | When b3 merges, the sink becomes the kernel's device-report call; nothing else changes. |
| CAM-host-4 | **RES-2 admission is a fixed cap of 8 cameras**, checked at connect. The clerk's own `Admit` passes every camera the host has admitted. | RES-2, design point 8 | A memory-admission service would replace the cap. |
| CAM-host-5 | **The decoded frames' consumers are later rows.** Each camera's frames go to the capture store (retention and the memory ring) and to its decoder sandbox; the decoder's checked output is dropped until VIS-core (#3515) and live view consume it. A store fault ends the connection, so capture the owner's retention cannot keep is not taken. | DEV-7, NET-2 | — |
| CAM-host-6 | **On-request capture opens no stream here yet.** An on-request camera streams only within a kernel-admitted read step (`Clerk.Capture`, CAM-clerk-9); serving that step on the kernel's socket is a follow-up. Until then an on-request camera is connected and idle. | DEV-7 | — |
| CAM-host-7 | **The client key is made at first start**, in the clerk's own sealed slot `device/camera-client`, and lent per signature (CAM-clerk-2). Its public key is in the STATUS answer (`client`, hex), for the enforcer to put in the nodes' bundles. A node turned off by a key mismatch is off only in memory: after a restart the clerk dials it again, is refused again before any frame, and raises the event again. | CLK-1, DEV-3 | — |
| CAM-host-8 | **STOP is kept in the cameras file** (`stopped`), so a restart during a STOP opens no stream until RESUME. | KRN-7 | — |
| CAM-host-9 | **The image runs it as `agentos-keeper-camera.service`, a keeper unit** (CAM-clerk-image, #3867), as the mail clerk is (image/ASSUMPTIONS.md MAIL-unit-1 to -4): its own user `agentos-camera` (sysusers), its key through `OpenFile=/run/agentos-kernel/key-camera.sock:clerk-key` and the kernel's `-clerk-key camera=...,/agentos.slice/agentos-keeper.slice/agentos-keeper-camera.service`, its sealed store and retained capture in `/var/lib/agentos-camera` (0700, tmpfiles.d, a `KEEPER_PATHS` entry, so every main-side unit has it masked), and its socket and runsc's state in `/run/agentos-camera`. The issue named the unit `agentos-camera.service`; a keeper name is what puts it in the keeper's slice and lifts the main side's mask from its own state. It reaches only the home ranges the device-driver host does (`IPAddressAllow=`, DEV-2), and the guard checks each pin again. No kernel socket yet (CAM-host-6), so the kernel's `-clerk` line names only the mail clerk. The end-to-end test runs in this package against a synthetic node with a fake decoder feed, rather than in `broker/e2e`, which has no key on descriptor 3 and no gVisor. | brief part d, CLK-1, NET-2 | — |
| CAM-host-11 | **runsc runs rootless, as the clerk's uid, beside the clerk's leaf of its unit's delegated group.** A plain runsc as a non-root uid fails at its gofer (`newuidmap`, a setuid helper that `NoNewPrivileges=` stops), so `gvisor.Runtime.Rootless` passes `--rootless` and runsc makes its own user and mount namespaces, mapping only the clerk's uid; each sandbox keeps `--network=none`, its read-only root and its unprivileged in-sandbox user. cgroup v2 lets a group that holds a process give its children no controller, so the clerk moves itself into `<-cgroup>/clerk` before anything else, and each sandbox's group, with its memory and task caps, is made in the unit's group beside it (`Delegate=cpu io memory pids`). The kernel matches the key's peer by the unit's whole cgroup, so the move happens after the hand-off and no `DelegateSubgroup=` is set. The unit therefore allows what the mail clerk's refuses: any namespace (no `RestrictNamespaces=`: systemd's namespace filter answers every `clone3` with `ENOSYS`, since it cannot read `clone3`'s flags, and the clerk starts runsc with `clone3` so it begins in its sandbox's group; runsc makes the user, mount, pid, network, IPC and UTS ones), any system call but the CPU-emulation, raw-I/O, swap, reboot, clock, module and obsolete groups (the sentry and gofer filter their own), write-and-execute memory, and a writable cgroup tree where only its own group is its user's. **Limit:** a sandbox escape lands as the clerk's uid (in runsc's user namespace), not as `nobody` under root's runsc as agentosd's machines do: it could read the sealed store's files (sealed by a key only the clerk's memory holds) and the retained capture, and dial the home ranges. CI's camera unit step runs a real sandbox inside the shipped unit file (`TestDecoderStartsInTheUnitsSandbox`); its runner lifts Ubuntu's AppArmor bar on unprivileged user namespaces, which Debian does not set. | CLK-1, NET-2, RES-2 | A decoder per camera under a uid of its own (a template unit, as `agentos-imapconn@.service`) would take the escape off the clerk's uid. |
