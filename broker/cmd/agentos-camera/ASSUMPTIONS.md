# Assumptions: the camera clerk's process (CAM-clerk part d, #3514)

What the process rests on. Brief: `briefs/CAM-clerk.md` (part d, CAM-clerk-host); the library's rows are `broker/clerk/camera/ASSUMPTIONS.md` (CAM-clerk-1 to -16).

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| CAM-host-1 | **The owner side checks tier 4; the clerk trusts its socket's peer.** The owner socket admits only the owner side's uid (agentosd's, `sockets.ListenPeers`), as the mail clerk's owner socket does. agentosd checks the approval code a tier-4 step carries (`localapi.OpCameraChange`, `localapi.CameraTier4`) before it relays the step. agentosd's handler for the camera page ops, its relay of STOP and RESUME, and its read of the enforcer's listed nodes are the agentosd chain's follow-up (no `cmd/agentosd` edit here, D-111). Until it lands, no step reaches the clerk and no camera connects. | DEV-10, CH-3, KRN-7 | A clerk that checked the code itself would need the code generator's seed, which only the kernel holds. |
| CAM-host-2 | **Every connected camera is in the capture store before the first sweep** (#3625). `Store.Sweep` erases every camera directory the store has not taken, and is also each camera's retention expiry. At start the host adds every camera in its file to the store, then sweeps, then connects each to the clerk and its decoder and opens streams. A camera the clerk or decoder refuses stays in the store, so its retained capture is kept and still expires on time, and every other camera's sweep goes on. A camera the store itself refuses (its sealed key slot failing) is kept (`Store.Keep` with its retention): each sweep still deletes its segments past that retention by name, but its directory and key stay (#4064). It is not pinned or connected, STATUS shows it refused with what it keeps and that a disconnect erases that capture, owner changes to it are refused, and the owner's disconnect erases it. Each periodic sweep first retries it (`retry`): once the store takes it, it is pinned, connected and started as at start, so a slot that failed only briefly needs neither a restart nor a disconnect (#4065). Every other camera starts (#3968). The cameras file is refused whole on any malformed record, so a torn edit cannot drop a camera that a sweep would then erase. Disconnect removes the camera from the file before erasing, so a crash between the two leaves a directory the next start's sweep erases. | DEV-7 | A store whose `Sweep` takes the connected set would make the store's membership and the clerk's independent. |
| CAM-host-10 | **An owner change is saved before it is applied.** `update` writes the new record first and applies nothing if the save fails, so no stream opens on a setting the file does not hold. A failed apply restores, saves and re-applies the old record; apply reads only its record arguments, so the rollback closes what the change opened. Tests pin it for a re-pin the clerk refuses, at the same address and at a new one (#3967); a capture change's only failing call is its first, so there the rollback restores the record and the file, starts no runner, and the clerk was never changed. A re-pin carries the listed node's address with its key, so a node that came back at a new address is pinned there. | DEV-3, DEV-7 | — |
| CAM-host-3 | **Tamper events are logged until the kernel's device-report entry exists.** DEVSLOT b3 (DEVSLOT-kernel) is not merged, so `eventSink` writes one fixed line per event: the camera's ID, the kind and the count, never a byte the node sent (design point 6). The rate limit (DEV-8) applies before the sink, and the clerk flushes its windows every minute. | DEV-8 | When b3 merges, the sink becomes the kernel's device-report call; nothing else changes. |
| CAM-host-4 | **RES-2 admission is a fixed cap of 8 cameras**, checked at connect. The clerk's own `Admit` passes every camera the host has admitted. | RES-2, design point 8 | A memory-admission service would replace the cap. |
| CAM-host-5 | **The decoded frames' consumers are later rows.** Each camera's frames go to the capture store (retention and the memory ring) and to its decoder sandbox; the decoder's checked output is dropped until VIS-core (#3515) and live view consume it. A store fault ends the connection, so capture the owner's retention cannot keep is not taken. | DEV-7, NET-2 | — |
| CAM-host-6 | **On-request capture opens no stream here yet.** An on-request camera streams only within a kernel-admitted read step (`Clerk.Capture`, CAM-clerk-9); serving that step on the kernel's socket is a follow-up. Until then an on-request camera is connected and idle. | DEV-7 | — |
| CAM-host-7 | **The client key is made at first start**, in the clerk's own sealed slot `device/camera-client`, and lent per signature (CAM-clerk-2). Its public key is in the STATUS answer (`client`, hex), for the enforcer to put in the nodes' bundles. A node turned off by a key mismatch is off only in memory: after a restart the clerk dials it again, is refused again before any frame, and raises the event again. | CLK-1, DEV-3 | — |
| CAM-host-8 | **STOP is kept in the cameras file** (`stopped`), so a restart during a STOP opens no stream until RESUME. | KRN-7 | — |
| CAM-host-9 | **The image runs it as `agentos-keeper-camera.service`, a keeper unit** (CAM-clerk-image, #3867), as the mail clerk is (image/ASSUMPTIONS.md MAIL-unit-1 to -4): its own user `agentos-camera` (sysusers), its key through `OpenFile=/run/agentos-kernel/key-camera.sock:clerk-key` and the kernel's `-clerk-key camera=...,/agentos.slice/agentos-keeper.slice/agentos-keeper-camera.service`, its sealed store and retained capture in `/var/lib/agentos-camera` (0700, tmpfiles.d, a `KEEPER_PATHS` entry, so every main-side unit has it masked), and its owner socket in `/run/agentos-camera`; its decoder sessions run in `agentos-camdecode@.service` (CAM-host-11). The issue named the unit `agentos-camera.service`; a keeper name is what puts it in the keeper's slice and lifts the main side's mask from its own state. It reaches only the home ranges the device-driver host does (`IPAddressAllow=`, DEV-2), and the guard checks each pin again. No kernel socket yet (CAM-host-6), so the kernel's `-clerk` line names only the mail clerk. The end-to-end test runs in this package against a synthetic node with a fake decoder feed, rather than in `broker/e2e`, which has no key on descriptor 3 and no gVisor. | brief part d, CLK-1, NET-2 | — |
| CAM-host-11 | **Each decoder session runs in a unit of its own, under a user of its own, never the clerk's** (CAM-decoder-uid, #4134). The clerk starts no sandbox: each camera's decoder session is a connection to `agentos-camdecode.socket` (`-decoder`, `camera.DialDecoder`), which only the clerk's user can open (`SocketMode=0600`) and which starts a fresh `agentos-camdecode@.service` per connection (`Accept=yes`, at most 8, one per admitted camera, CAM-host-4). That unit runs `agentos-camdecode-host` under `DynamicUser=yes` with `User=camdec-%i`: systemd makes one dynamic user per name, and `Accept=` names each instance by its count, pid and uid, so every session's uid is its own and is freed when it ends. The process reads the session's two shapes (`camera.ReadSpec`, held to the bounds `Decoder.Add` uses), moves into its leaf `host` of its unit's delegated group (`Delegate=cpu io memory pids`; cgroup v2 lets a group that holds a process give its children no controller) and starts the decoder's gVisor sandbox rootless beside it (`gvisor.Runtime.Rootless`: a plain runsc as a non-root uid fails at its gofer, since `NoNewPrivileges=` stops `newuidmap`), held to 512 MiB by its own group, with `--network=none`, a read-only root and an unprivileged in-sandbox user, then copies frames between the connection and the sandbox. Everything the sandbox writes back is checked by the clerk as before (`Decoder.read`). A sandbox escape therefore lands as a dynamic uid that owns no file on the box: it cannot read the clerk's sealed store or capture (0700, the clerk's, and masked by the main side's `InaccessiblePaths=`), write `/run/agentos-camera` (0755, the clerk's) and so replace `owner.sock`, signal or trace the clerk, or open a session of its own; it has no network (`PrivateNetwork=yes`, `IPAddressDeny=any`, `AF_UNIX` only), its own `/tmp` (runsc's state) and its own pid namespace (`PrivatePIDs=yes`), so it sees no other session, whose uid is another. The decoder unit keeps what runsc needs and the mail clerk's unit refuses: any namespace (no `RestrictNamespaces=`: systemd's filter answers every `clone3` with `ENOSYS`, and the process starts runsc with `clone3` straight into its sandbox's group), any system call but the CPU-emulation, raw-I/O, swap, reboot, clock, module and obsolete groups (the sentry and gofer filter their own), write-and-execute memory, and a writable cgroup tree where only its own unit's group is its user's. The clerk's unit has none of these: it has the mail clerk's profile (`RestrictNamespaces=yes`, `MemoryDenyWriteExecute=yes`, `@system-service`, `ProtectControlGroups=yes`), no delegated group, and the kernel's key goes to it in its unit's own group as before. The owner side's dial of `owner.sock` (none exists yet; agentosd's camera relay is a later row) checks the server's uid, which only the clerk now holds; `RuntimeDirectoryMode=0755` leaves that directory writable by no other uid. A session's `Stop` (`camera.DialDecoder`) waits up to 10 s for the unit to close the connection, so a restart does not overlap its predecessor past `MaxConnections=`. CI's camera decoder step runs the shipped socket and unit with the main side's mask on the runner's systemd, connects twice at once as the clerk's user, and checks from inside each session that its uid is neither root, the clerk's nor the other's, that it cannot write the clerk's directories or open a session, and that a real sandbox starts in its group with no network (`TestDecoderStartsInItsUnit`); its runner lifts Ubuntu's AppArmor bar on unprivileged user namespaces, which Debian does not set. **Limit:** an escape holds its own session's stream and can stall or end it (the clerk's stall check stops it and counts a fault), and it can hold its unit's slot until systemd stops it; it cannot reach another camera's. | CLK-1, NET-2, RES-2 | If systemd ever gave two instance names one dynamic uid, two sessions would share a user; CI's step fails on that. The runner's systemd (255) ignores `PrivatePIDs=` (257), which the image's trixie systemd applies. |
