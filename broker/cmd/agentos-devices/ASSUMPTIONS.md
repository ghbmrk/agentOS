# Assumptions: the device-driver host's process (DEVSLOT-drivers part b2b-1, #3473)

What the process rests on. Brief: `briefs/DEVSLOT-drivers.md` ("Part (b), settled", b2b); decision D-189. The host library is `broker/clerk/devhost` (DEVSLOT-host-lib-4 to -9).

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| DEVSLOT-host-unit-1 | **Only image drivers run, as the image built them.** The host reads `drivers.json` (part b1) once, refuses the whole file on any malformed entry, and builds a host only for a pin whose driver it lists, from the image's declaration. A pin for any other driver starts nothing and is logged. Before each operation it hashes the driver's binary and refuses one whose SHA-256 is not the listed one before it connects, so no instance starts. The binary is under `/usr` (verity), so the file systemd then executes is the one hashed. | DEV-1, KRN-2 | A binary outside verity: check the hash at exec, not at dial. |
| DEVSLOT-host-unit-2 | **A TCP device's key is the SHA-256 of its certificate's public key.** `Pin.Key` (DEV-3) is checked in TLS's `VerifyConnection` against the leaf certificate's `SubjectPublicKeyInfo`. Names, issuer and dates are ignored, so the pin is the device's whole identity. The stream is dialled only through `broker/netguard` (DEV-2), as a device executor's dial (`PurposeDevice`) to a `PinDevice` pin of that device's address, port and key, and the process's guard refuses any address and port no pin names before netguard is asked, public ones included, so the host reaches nothing but the image drivers' pinned TCP devices. The host learns no home network, since it dials nothing else. A wrong key fails the handshake before any frame is written. A frame for another pin or port is refused before the stream. A call whose context ends drops the stream, and the next call connects again. A frame read is what one read of the stream gives, at most `MaxRead` bytes. | DEV-3, DEV-2 | A device whose identity key is not a TLS key: a second transport kind, declared in the link. |
| DEVSLOT-host-unit-3 | **The host's uid is fixed at 900.** The driver's process checks that its peer's uid is `AGENTOS_DEVHOST_UID` (`devslot/proc`). A unit's `Environment=` cannot resolve a user name, so the host's sysusers line fixes the uid, the template names it, and the process refuses to run under any other uid. If sysusers ever has to give the name another uid, the host does not start and every driver refuses its peer, so the system fails closed. | CLK-1 | none |
| DEVSLOT-host-unit-4 | **Staged until b2b-2 and b3.** The unit ships disabled and has no `-pins` yet, so no device is paired and nothing runs. Events go to a sink that drops them and logs only a fixed line, never a reading, until the kernel's device-report side (b3). The drivers' key lines, the kernel's key hand-off to a driver instance and the CI boot probe are b2b-2's. | DEV-8, KRN-7 | none |
