# cmd/agentos-clerk-model assumptions

Built for MIG-4-untrusted-exit-b2b (#2780(b), briefs/MIG-4-untrusted-exit-b.md). Each row is a reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-untrusted-exit-b2b-1 | **Every refusal of the process comes before the key is read.** The main refuses root, then runs `procguard.Isolate` with agentosd's uid (refused as that peer, then non-dumpable), then checks `-dir` is this uid's own directory, closed to every other uid (`privfile.Check`); only then does it read descriptor 3 (`clerkkey.Read`, naming `model`). A refused start leaves the key in its pipe (`TestARefusedClerkLeavesItsKeyUnread`). | CLK-1 | none |
| MIG-4-untrusted-exit-b2b-2 | **The plan login lives in one sealed slot. A slot whose value does not open starts the clerk signed out, and a slot whose file is wrong refuses the start.** `-dir/plan-codex` holds `plan.Store`'s at-rest form, sealed under the sealer derived from this clerk's key and bound to the plan's name. Writes go through `privfile.WriteAtomic` and are capped at 64 KiB, so this process never writes a form it would not read back. A file that is a link, or not this uid's alone (`CheckFile`), refuses the start, because that means the directory was tampered with. A slot whose value does not open, whether sealed under another key, sealed for another plan, damaged or over 64 KiB, is never opened. The clerk logs one fixed line and starts on an empty store. The owner then sees "not signed in" (`planstate`), and their next sign-in or `planremove` replaces the slot, as with the mail clerk (MAIL-main-a-4). Refusing the start instead would leave `planremove`, the owner's only remedy, unreachable (#3568 UX 1). Whoever could plant such a blob (this uid or root) could already delete the file (`TestThePlanLoginIsSealedInTheClerksOwnSlot`, `TestAnUnopenableSlotStartsSignedOut`). | CLK-1, STO-2, CLK-7, OWN-17 | A second plan route gets a slot of its own, named for it. |
| MIG-4-untrusted-exit-b2b-3 | **This slice hosts the owner's plan sign-in only.** The process serves `ServePlanOwner` (`planbegin`, `planstate`, `planresume`, `planremove`) to agentosd's uid, and each sign-in's CLI runs through `run.SignInSock` on agentosd's `-signin-sock`, where the endpoint it serves in agentosd's route admits agentosd's uid, the sandbox host (clerk/run MIG-4-untrusted-exit-b1-1). A guest's plan model endpoint (`ServePlan` per guest) is not served yet: it needs what only the guest host knows, the kernel plan a run is charged to, the route's price and pool, and the provider's context window and output limit (clerk/run MIG-4-plan-login-b6). Serving it with invented values would meter wrongly. `ServeModel` is served since MIG-4-exit m1 (MIG-4-exit-m1-c1). | PLN-5, CLK-7, LOG-7 | The guest host's slice (#2780(b3) or the row that restores `providerTask`) adds per-guest flags. |
| MIG-4-untrusted-exit-b2b-4 | **One uid, agentosd's, is every peer.** agentosd is the plan owner socket's caller (b3's `accountsock.Plan`), the sign-in socket's server and the sign-in machines' host, so `-agentosd-uid` names all three. It may be root, as agentosd is on the box; the clerk never is. | CLK-1 | If the pages' caller moves out of agentosd, the owner socket gets its own uid flag. |
| MIG-4-untrusted-exit-b2b-5 | **Its address policy is the mail clerk's, copied** (`netguard.go`, D-154 rule 4): the plan login's dials go only through the learned home-network resolver and the policy (DEV-2), with the system's roots, since the provider's hosts are public. | DEV-2 | none |
| MIG-4-untrusted-exit-b2b-6 | **A sign-in in flight at shutdown is ended by agentosd.** The process closes its owner socket and exits; agentosd destroys a sign-in machine when its caller's end goes (cmd/agentosd MIG-4-untrusted-exit-b1, `TestSignInStopDestroysTheMachine`), and the sign-in guest's placeholders die with this process's memory. | PLN-6 | none |

## MIG-4-exit-m1 (#3680)

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-exit-m1-c1 | **The model socket is served only with all four of its flags.** `-model-sock`, `-planner-uid`, `-meter-sock` and `-kernel-uid` go together; with none the process serves no model call, as on the image today, since the unit flags wait for b2b-unit (#2780). The planner's and the kernel's uids are never root, and the clerk refuses to run as the planner's uid. `ServeModel` admits the planner's uid only (`TestServesModelCallsToThePlannerOnly`) and meters every call through the kernel's meter socket (`proc.Meter`); the key, the task and every cap come from the kernel plan and the route's declaration (clerk/model MIG-4-exit-m1-3). | CLK-1, CLK-7, LOG-7 | The unit sets the flags in b2b-unit. |
| MIG-4-exit-m1-c2 | **The API keys have their own sealed slot, opened like the plan login's.** `-dir/api-keys` holds `model.Keys`' at-rest form under the same sealer, written through `privfile.WriteAtomic` and capped at 64 KiB. A file that is a link or not this uid's alone refuses the start; a value that does not open, or one over the cap, starts the clerk with no key and one fixed log line, so the owner's next `apikeyset` replaces it (as MIG-4-untrusted-exit-b2b-2). The providers are `model.Shipped`, dialled through the process's one address policy with the system's roots. | CLK-1, STO-2, DEV-2 | none |
