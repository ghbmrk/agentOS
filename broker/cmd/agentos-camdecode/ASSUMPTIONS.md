# cmd/agentos-camdecode: assumptions

Built for CAM-clerk part (b2), CAM-decode H.264 (#3514, `briefs/CAM-clerk.md` design point 4), against NET-2 (Cameras), KRN-2 and DEV-7. `agentos-camdecode` is the program inside a camera's decoder sandbox; part (b1) built its thermal path and the clerk side (`broker/clerk/camera` decode.go, whose rows are CAM-clerk-N there). This part adds video: libavcodec's H.264 decoder, pinned and linked statically.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| CAM-decode-b2-1 | **libavcodec is FFmpeg 9.0.2's release tarball, pinned by SHA-256** in `image/libavcodec.sh` (a build input, outside the shipping code `tools/depaudit.py` scans; agentos-camdecode itself has no network) and checked against the FFmpeg release signing key (FCF9 86EA ... D676 58D8) when the pin was set; the Ubuntu archive's `orig` tarball is the same file. It is configured with `--disable-everything --enable-decoder=h264` and no programs, formats, filters, devices, hardware paths, threads, network, autodetected libraries or assembly, static and LGPL. | Brief design point 4 ("built with only the H.264 decoder (mature; OSS-Fuzz covers it)"); reuse over a new decoder | A security release of FFmpeg is a pin bump in `image/libavcodec.sh`, re-checked against the signing key. |
| CAM-decode-b2-2 | **No assembly at all (`--disable-x86asm --disable-inline-asm`)**: the build needs no `nasm`, and the decoder is FFmpeg's plain C path, CABAC included (inline assembly would otherwise remain there), which OSS-Fuzz also covers. One 1080p30 stream is expected (not measured) to fit one core in C. | Fewer build inputs; containment does not depend on speed | If a box decodes several 1080p cameras and the sandbox's CPU cap stalls them (the clerk kills a stalled sandbox), enable assembly (inline, then a pinned `nasm`). |
| CAM-decode-b2-3 | **The decoder runs on one thread, logs nothing, and refuses a coded size over the declared shape** (rounded to macroblocks, plus 64 pixels a side for buffer alignment) before it allocates for it (`max_pixels`). A picture of any other size or pixel format than 8-bit 4:2:0, a decoder error, or more pictures than access units fed, ends the run with `ErrVideo` (exit 11); the clerk restarts the sandbox with a backoff and a DEV-8 event. | Design point 4: output shapes come from the bundle, never the stream; stderr carries one word | A camera that sends 4:2:2, 10-bit or a resolution change mid-stream would need its bundle to declare it. |
| CAM-decode-b2-4 | **A node opens each stream with its parameter sets and an IDR picture**: a slice before any SPS/PPS is a decoder error, so a stream that starts mid-GOP ends the sandbox once and decodes after the restart only if the node then resends them. | H.264 needs the parameter sets to decode anything; CAM-node sends one access unit per frame (`camwire.TypeVideo`) | If CAM-node starts streams mid-GOP, skip non-IDR units until the first IDR instead of refusing. |
| CAM-decode-b2-5 | **Video output frames are counted from 1 by the decoder**: an access unit carries no counter, unlike a thermal frame. | `camwire.TypeVideo` payload is Annex B only | If the wire gains a per-unit counter, carry it as thermal does. |
| CAM-decode-b2-6 | **Default builds have no H.264 decoder (`HasH264` false)**: `go test ./...` and the race shards have no libavcodec, so the cgo file builds only under the `libavcodec` tag. `image/build.sh` builds the shipped binary with the tag, statically (it fails on a dynamic one), and CI's fuzz job runs the tagged tests and `FuzzH264Feed` against the same pinned build. An untagged binary refuses every video frame, failing closed. | No cgo elsewhere in the broker; one pinned build for image and CI | If the broker's main test job gains libavcodec, drop the tag. |
| CAM-decode-b2-7 | **Static linking of LGPL-2.1 libavcodec into an Apache-2.0 program** meets the LGPL's relinking term because this repository publishes the program's whole source and `image/libavcodec.sh` rebuilds the library; `NOTICE` names it, its licence and its source, and the image carries the licence text at `/usr/share/licenses/libavcodec/COPYING.LGPLv2.1`. | LGPL-2.1 §6 | An image that ships closed code linked to it would need object files for relinking. |
