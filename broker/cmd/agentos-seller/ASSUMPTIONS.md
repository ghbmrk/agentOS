# Seller prep for one box: assumptions

Built for SELLER-prep-1 (BOARD.md, D-105) against SPEC HW-10, HW-1 and A1, on `broker/claim` (`NewCode`, `Seal`, `Open`), `broker/hostdisk.Probe` and `card.QRSVG`. Covers `broker/cmd/agentos-seller`. One box only (D-104).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| A1 | **Image layout.** The image's root file system is its only ext4 volume and its last partition, at 512-byte sectors (`image/mkosi/mkosi.repart/30-root.conf`; the ESP and the `/usr` verity pairs come first and are not ext4). `/var/lib` exists in it and `/var/lib/agentos` does not (tmpfiles makes it at boot; mkosi.finalize allows it only empty). `prep` refuses any other layout rather than guessing. | HW-10 | A change to the repart files changes `rootOffset`; a 4K-sector image needs `Probe` at 4096. |
| A2 | **Where the box reads it.** The box opens its claim state at `claim.StatePath` with `change.FileStore`, as root (agentosd runs as root), so the file is root:root 0600 under a root:root 0700 directory. `firstboot.Begin` sets the preloaded latch itself. Beside the state the seller writes only the setup network at `claim.SetupNetPath`, with the same owner and mode (A9). The reader is CTRL-card-sock's wiring, not yet merged. | HW-10, HW-1 | If the wiring opens another path or runs as another user, `StatePath` and the owner set here move with it. |
| A3 | **debugfs.** e2fsprogs' `debugfs` writes into the unmounted image, so `prep` needs no root and no loop device. It exits 0 when a command fails, so `prep` trusts none of its writes: it reads back the mode, owner and bytes, runs `e2fsck -fn`, and opens the state with `claim.Open` and claims a copy with the code. | HW-10 | — |
| A4 | **Image trust.** The input is a CI image built from a push to main and checked against its `SHA256SUMS` (I8, C3). There is no signature over the raw image file itself (the `/usr` verity root hash is signed into the UKI; the root partition is not covered). `prep` only checks the checksum; a signature check belongs to FLASH-1 (after G1). | I8, C3 | When the release pipeline signs the raw image, `prep` and `write` check that signature. |
| A5 | **Code only on the sticker.** The code is generated in memory, sealed as a salted Argon2id verifier (`claim.Seal`, production cost), and written only to `sticker.txt` and `sticker.html` (0600, in a 0700 directory). Logs carry paths and steps, never the code. The owner deletes the directory once the sticker is on the box. | HW-1 | — |
| A6 | **Write target.** `write` takes a whole disk the owner names. It refuses a target that is not a block device, is mounted or used as swap (it or a partition by the kernel's naming: `sda2`, `nvme0n1p2`), that the kernel holds (`O_EXCL`), or that is smaller than the image, before writing. It does not judge what the disk holds: in the owner checklist the disk is the M6 Ultra's own SSD, not a host disk (HW-8a's checks are for the box installing itself). | A1, HW-10 | A general flasher (FLASH-1) adds HW-8a-style disk descriptions and confirmations. |
| A7 | **Read-back.** After `fsync`, `write` drops the device's buffer cache (`BLKFLSBUF`) and the page cache for the range (`FADV_DONTNEED`) and hashes the first image-size bytes against the checksum, so the check reads the disk, not what was just written. A USB enclosure's own cache is outside this. | A1 | — |
| A8 | **Pre-claim network (CTRL-claim-ap).** The QR opens `http://10.42.0.1/claim?code=…` on the box's own Wi-Fi, which before the claim is the setup network the seller seals (A9), not the card's: the sticker prints its name, its password and a Wi-Fi QR (`card.WiFiQR`, the encoder the card uses) as step 1, and the claim QR and code as step 2. The two codes share one format and style, so each has its own label above it, "Wi-Fi password" and "Claim code" (CTRL-claim-ap-2), so an owner does not type the password into `/claim` and spend a shared try (K9). | HW-10, CH-7 | If Mark picks an open setup network instead, the sticker loses step 1 and the box serves an open network that reaches only the claim page. |
| A9 | **Setup network on disk.** `prep` draws the setup network with `claim.NewSetupNet` (its own 80-bit password, drawn apart from the code) and writes it at `claim.SetupNetPath`, root:root 0600, in the same debugfs run as the state, reads it back, and checks it parses. It refuses an image that already holds one. The password is in the clear on the box (WPA3-SAE needs it, claim K10) and on the sticker; unlike the code, it is meant to be read by whoever holds the sticker, so the canary scan covers the code only. | HW-10, CH-7 | — |
