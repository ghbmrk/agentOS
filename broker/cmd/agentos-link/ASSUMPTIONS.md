# agentos-link: assumptions

Built for EDGE-link-core slice c2a (#3297, `briefs/EDGE-link-core.md` decisions 3 to 8) against HW-15, HW-16 and HW-17. `agentos-link` is the core's process on the link port: the pre-store capture and the served mode. The kernel's side of its calls is c2b's; its units, user and input rule are c2c's (rows EDGE-link-c2c-*). Each row is a reading a later change could overturn.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| EDGE-link-c2-1 | **Before the store, a root parent writes and an unprivileged child reads.** Enrollment takes the capture only when root owns it (b2 decision 2), but a root process should not parse another box's bytes. So the parent binds the port as root and starts itself again (`-hello-child`) through `childproc`, with no environment, under `-uid`/`-gid` with no supplementary groups, killed with its parent, and with the listener on descriptor 3. The child runs TLS and the hello and writes 128 bytes on its stdout. The parent checks them again (`validCapture`: no small-order key, a signature over `kernel.HelloMsg`) and writes them. It never parses TLS or a frame. | Decision 3, b2 decision 2 | If the capture moves to a file the link's uid owns, enrollment's owner check changes with it. |
| EDGE-link-c2-2 | **The first capture is final.** `writeCapture` refuses when the store or the capture exists. It writes a new 0600 file in the same directory and links it into place, so a second capture never replaces the first and enrollment never reads part of one. The parent then exits, so later hellos find nothing listening. A capture linked just after enrollment made the store is inert: enrollment never runs again over a store, and a restore's enrollment removes the file. c2c's unit also stops the capture before enrollment starts, and makes the capture's directory root-only (0700): a directory the link's uid could write would let it swap the temporary file before the link. | Decision 3 | — |
| EDGE-link-c2-3 | **The kernel client lives in this command.** It is not in `owner/kernelsock`, which is the owner side's client (it takes the owner's uid per call) and is held by an open PR (D-111). The wire is kernel/proc's (`{op, args}` answered `{result}` or `{error}`). c2b serves these calls on a link socket that admits the link's uid alone: `linkkey` (none) answers the link public key; `linksign {msg}` answers a signature; `edgekey {key}` answers `{live, revoked}`; `edgecandidate {key, nonce, sig}` answers nothing. `linkkey` is one call more than the brief names: the server's certificate needs the public half before any handshake. | Decisions 4, 5 and 8 | c2b's test serves the real link side to this client, so the two cannot drift. |
| EDGE-link-c2-4 | **The ticker asks about the key, not the log length.** A served connection asks `edgekey` every 250 ms and closes when the key is no longer live or the kernel has not answered within 500 ms, so a revoke or cut closes it within a second even while the kernel is slow. Decision 5's "answer carries the log length" is a way to make that check cheaper; one small call per open connection four times a second is cheap enough for the one live edge. | Decision 5 | If many connections are served, `edgekey` answers a change count and the ticker compares it. |
| EDGE-link-c2-5 | **The newest live connection is served.** One edge key is live, but it can reconnect before its old connection times out. A new served connection closes the older one, and outbound frames go to the newest. | HW-15 (one edge) | — |
| EDGE-link-c2-6 | **A hello connection is watched briefly for a second frame.** After the hello verifies, the core reads for 200 ms more. Any byte is a fault and the hello is not reported, so "exactly one hello" is enforced rather than assumed. An edge that closes or waits after its hello is not delayed past that. | Decision 5 | — |
| EDGE-link-c2-7 | **The consumer socket carries JSON lines, one consumer at a time.** Items go out as `{kind, origin, body, label}`. The label is set here from the kind, and the consumer's own label field is ignored on frames coming in. Frames come in as `{kind, origin, body}`, at most 128 KiB a line, and are checked by `edgelink.AppendFrame` on the `ToEdge` stream. The item channel is unbuffered: with no consumer, the live edge's reader waits, which slows the edge. The one item taken just as the consumer's connection fails is lost, and the loss is said on stderr. An outbound frame with no live edge is dropped, and the drop is said on stderr. | Decision 7 | The consumer rows (PLN-3, CLK-8, NET-2) may want a richer wire. They change it here and in their client together. |
| EDGE-link-c2-8 | **The log carries counts and fixed text only.** A fault logs its running count. A kernel refusal logs the kernel's text, which names no content from the edge. Nothing the edge sent (origin, body, key) is written. | Decision 6, CLAUDE.md | — |
| EDGE-link-c2-9 | **Served mode never runs as root; the pre-store parent always does.** The served process holds no key, and the kernel's link socket admits its uid alone (c2b). | HW-16, decision 4 | — |
| EDGE-link-cap-1 | **At most 16 handshakes are in flight per listener; the next connection is closed at accept and counted.** Both accept loops (`server.serve`, `firstHello`) take a slot before the handshake. In served mode the slot covers the handshake, the `edgekey` call and a hello read, and is given back once the connection is served live or closed, so the live edge never holds one. Before the store it covers the handshake and the hello read. 16 is far above one edge reconnecting and bounds a hostile edge to 16 `linksign` and `edgekey` calls at a time, each held at most `handshakeFor` plus `helloFor`, so the revoke recheck's 500 ms limit is not starved. A refusal logs its running count, never the peer's address. | #3462 (from #3460's Security and L3 point 3), HW-16 | If more than one edge is ever served on one link, the cap is per edge or raised with it. |
| EDGE-link-c2c-1 | **The link interface is the core's USB Ethernet adapter, named `agentos-link`.** HW-15 puts the link on a core port used for nothing else, a USB Ethernet adapter where ports 1 and 2 are taken; the first-release core has two fixed ports, and `localui.Port1` already leaves USB adapters out as the link's. `10-agentos-link.link` names any USB Ethernet adapter (`Type=ether`, no virtual kind, `ID_BUS=usb`) `agentos-link`; a second one fails the rename, keeps its kernel name and gets neither the link's name nor its port, though `10-agentos-link.network` matches it too, so it never takes the uplink's DHCP. A phone tethered over USB is such an adapter and gets no address from the phone; the edge image, built from the same tree, would name its own USB adapter the same way (a later row). One fixed name lets the units, the `.network` file and the inbound link set agree without a lookup at start. Before the confirm, whatever is on that adapter is the first edge (Residual risk 1). | HW-12, HW-15 | A core whose link is a third fixed port gets a `.link` matching that port's path instead; nothing else changes. |
| EDGE-link-c2c-2 | **The core's link address is fixed, `fe80::1/64`, and nothing is learned from the edge.** `10-agentos-link.network` (matching every USB Ethernet adapter, as the `.link` does, and sorted before the uplink's, so the uplink's DHCP never runs on one) sets no DHCP, router advertisement or LLDP either way, so the edge cannot give the core an address, a route or a resolver; DHCPv4 replies reach networkd through a packet socket the inbound drop never sees, so the file, not the drop, is what stops them. The edge connects to `[fe80::1%<its port>]:7443`. The link never counts towards being online. `mkosi.finalize` holds the file to exactly its keys (`LINK_KEYS`). | HW-15, HW-16 | The edge-side row (Unowned gaps) builds against this address; a change moves both. |
| EDGE-link-c2c-3 | **The capture runs as a keeper unit, root with three capabilities.** `agentos-keeper-link-capture.service` must see whether the store exists, which the main side's mask hides (a masked directory reads as empty, which would keep the window open), and its capture directory `/run/agentos-link-capture` (0700 root, made at boot) is keeper state, so no main-side unit can plant a first key. Its bounding set is `CAP_SETUID CAP_SETGID CAP_KILL` (start and kill the reader under the link's ids); the link set is loaded by its `+` steps, as the served unit's are; without `CAP_DAC_OVERRIDE` the kernel's and the mail clerk's directories stay closed, and the setup factors' directory, root's, is mounted over. It ends by itself within a second of the store existing (`-store`, looked for every second), freeing the port for the served unit; no unit stops it, since the Owner Card flow's units run no `systemctl`, and enrollment's unit cannot `Conflicts=` it, which would delete its start job from every boot's transaction (tests/test_image.py runs systemd's own transaction). A hello taken while enrollment runs is either read, or never read: written after enrollment looked, it is removed with the capture once the store is in place, or left in `/run` for no enrollment to read, as none reruns over a store. Like the served unit, it is bound to the link interface's device (`BindsTo=`, `WantedBy=` `sys-subsystem-net-devices-agentos\x2dlink.device`): it starts when the adapter appears, at boot or plugged in later, and stops when it goes, because the listener's `SO_BINDTODEVICE` holds the interface's index, which a replugged or reset adapter changes; a listener outliving its device would refuse the edge with no error (#3834 Potency). | Decision 3, b2 decision 2 | — |
| EDGE-link-c2c-4 | **The served link runs on every boot with a store and at the kernel's first start.** `agentos-link.service` is main side, under `agentos-link` with no capability (Linux 5.7 and later let any user set `SO_BINDTODEVICE` on a socket not yet bound to a device), and talks only to link-local addresses (`IPAddressAllow=link-local`). It is bound to the link interface's device and wanted by it, so it starts whenever the adapter appears and stops when it goes (EDGE-link-c2c-3), and it is wanted by the kernel's unit, so the Owner Card confirm's boot serves the first edge without a reboot; not by `multi-user.target`, where with no adapter it would only wait out the device. A start that fails (the kernel not yet listening) retries with a backoff and is never left failed. The consumer socket admits `agentos-link-items`, a user no process runs as yet: the consumers are rows of their own (Unowned gaps), and until one runs, the live edge's items wait (EDGE-link-c2-7). | HW-15, HW-16, decision 7 | A consumer row gives its process that user, or changes `-consumer-uid` to its own. |
| EDGE-link-c2c-5 | **The link's port is open only while a link unit listens.** Both units put `agentos-link` in the inbound drop's `link` set before they start (one nft transaction, flush then add) and empty it on stopping, as the page's unit does for its set, except that the capture, once the store exists, leaves the set to the served unit, so its exit never races the served unit's admit; with the set empty, the link's port is dropped and so is everything else on the link but neighbour discovery (netguard EDGE-link-core-c2c-1); both do it as root (`+`, listed exactly in `FULL_PRIVILEGE_COMMANDS`), so neither process holds `CAP_NET_ADMIN`. The port is `netguard.LinkPort`, 7443, the units' `-port`. | HW-16, netguard WIFI-del-a3-1 | — |
