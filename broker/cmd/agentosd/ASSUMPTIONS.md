# agentosd wiring: assumptions

## Owed take-backs (W3-forget-b2c)

Started by W3-forget-b2c (owed take-backs for FORGET's item 2, the UX
release finding R-1/R-2 on #327). Each row is a reading of the spec, or a
gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| 1 | An approved item 2 that cannot be taken back now (no agent machine, recall off, or the take-back not saved) is owed: its journal outcome is Succeeded, and `resumeAgent` takes it back at a later open of recall once recall has not recorded it (`Handled`). The journal never prunes Succeeded intents. | CAP-3 (the owner's approved deletion is carried out), CH-12 | If the journal ever prunes Succeeded intents, owed take-backs need their own durable record. |
| 2 | A take-back error that is not `ErrCarried` or `ErrNotOpen` means recall recorded nothing and reset nothing (`Reach.TakeBack` wraps every failure after `MarkTakeBack` in `ErrCarried`), so trying it again cannot repeat a take-back (#327 L3 blocker 1). | CAP-3 | If `Reach.TakeBack` can fail unwrapped after resetting, `carryAgent` must stop retrying on that error. |
| 3 | STATUS's agent line says why the agent is not running, so "Send STATUS to see why." is a real step for the no-agent text. ~~Recall off (no recall directory or vault verifier) has no STATUS line and no step the owner can reach, so that text names none and says what remains.~~ Recall off now has a STATUS line, "Memory across tasks: off on this box; …" (OP9-status-a, C7). It names no step the owner can take (a later box version adds it), so the recall-off text still names none and says what remains. | CH-12 (a problem text says what the owner can do; never a step that cannot fix the cause), OP-9 | If recall off gains an owner step, that text can name STATUS. |
| 4 | A not-saved take-back is tried again in this boot with the forget's backoff (2 s doubling to `forgetRetryMax`) until it is saved or the box shuts down; the owner is told once at the start and once when done, matching item 1's not-saved promise. | CH-12, UX-182-3 (a promised text comes) | If retries should be bounded, the text must stop saying "I keep trying". |
| 5 | Every approved take-back is in the forget log before the owner is told, owed or done, so a restore replays it (`resumeRestored`); one logged twice is taken back once, as recall reports it handled. | W3-forget-b1 (forget log), security 4a on #427 | `TestForgetItem2OwedSurvivesARestore` fails. |

## Owed done texts (W3-forget-b3)

Built for W3-forget-b3 ("Promised done text survives a restart") against CAP-3, UX-182-3 and SHOULD 4 of L3 on #182. Covers the owed done texts in `broker/cmd/agentosd` (`forget.go`, `learn.go`). Each row is a reading of the spec or the brief that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| F1 | **Owed done texts are their own store, not the forget log.** `forget-owed.json` in the learn dir maps goal ID to the task's time and the undone count. It is written before the tombstone and cleared once the owner is told. The forget log (W3-forget-b1) is an authenticated append-only record of what was forgotten, not of what the owner was told, and it is nil until W3-forget-b1-5. "Rides the forget log" is read as: the done text after a restart appends to the forget log like any other done forget, and its tail follows that append. | CAP-3; SHOULD 4 on #182 | Move the owed state into the forget log once it carries an entry per told text. |
| F2 | **Told after the replay, at attach.** The start-up replay (`replayForgotten`) runs in `openLearning`. If it fails, learning does not open and nothing is told. The owner channel exists only from `attach`, so the owed goals are snapshotted after a successful replay and texted at attach. | UX-182-3; CAP-3 (told only after the save) | Send them from the replay itself if the owner channel opens earlier. |
| F3 | **No tombstone, no text.** An owed goal whose tombstone did not hold at start was not forgotten, so it is dropped untold. This covers a crash before the tombstone saved, and a "Not forgotten" no later save wrote. | CAP-3 | Text "not forgotten" at start for these too. |
| F4 | **A repeated text over a missing one.** If clearing a told text fails to save, the next start tells it again. | CAP-3 | Clear before telling, accepting a lost text. Class: later (L3 on #425). |
| F5 | **Named by its time, never its text.** The text says "Your task from <date> is forgotten now." because the owner may have texted since. Without the ID's time it says "A task you asked me to forget". The store holds goal IDs, times and counts only. | security C2 on W3-forget | None expected. |
| F6 | **Uncapped.** One entry per forget not yet told. Entries exist only between a YES and its done text, so the store stays small. | — | Cap it if forgets can be owed in bulk. Class: later (L3 on #425). |
| F7 | **A restored backup's owed file is replayed like the live one.** Its goals that the restored tombstone or forget log hold are told again, as "forgotten now". | REC-2 | Drop the owed file on restore. Class: later (L3 on #425). |
| F8 | **The local Wi-Fi page's task list (potency R2) is not built here.** `broker/localui` has no task page. Listing older tasks needs a new page, a socket route and a forget path, all outside this brief's files. It is classed release (agreed with L3 on #425; the coordinator adds the BOARD row). | brief W3-forget-b3 (carried) | — |
| F9 | **A done text is owed until it sends.** The owner channel's send reports failure (`loop2Notify.try`), for example modemlink's ErrDown just after boot. A text that does not send stays in the owed file, with whether it was logged and the agent taken back, and is sent again with backoff (2s doubling to a minute). At a shutdown it is left to the next start. | CAP-3; L3 B1 on #425 | None expected. |
| F10 | **An unreadable owed file fails safe.** It is renamed to `forget-owed.json.bad`, a fresh file starts, and the owner is owed one fixed notice: "After a restart I couldn't read which forget texts I still owed you. Send FORGET to see your recent tasks." Entries that read but no forget wrote are sanitized: a goal with no tombstone gets no text, a negative count reads as none, and a future time reads as "A task you asked me to forget". No text repeats words from the file. | security C2; L3 B2 on #425 | Text each recoverable goal from the `.bad` file instead. |

## Held restore (W3-forget-b1-7)

Built for W3-forget-b1-7 (#409 UX U2 and U6; #436 L3 points 4, 5 and 8, and UX points 1 and 2) against security C3, CAP-3, A8 and CH-12. Covers `held.go`, the held-mode block in `main.go`, and the text changes in `restoreconfirm.go`.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| H1 | **Held mode serves only owner.sock.** It uses the daemon's peer checks: the bridge's uid and group, at most 8 connections, a 60 s idle timeout. It serves the bridge's ops, and "message" where the daemon would (no `-modem-bridge`, or `-owner-message`). localui.sock is not served, so the local page shows nothing while the box is held. | security C3 (a held restore opens nothing restored) | Serve a held-state page on localui.sock if the UX lens asks for one. |
| H2 | **The owner comes from `-owner`, else from setup's finished record**, the same source setup mode reads. The record is read before setup mode would run. With neither, agentosd exits as before b1-7, since no one can be texted. | CAP-3 | Have held mode run setup first, if a held box can be one that was never set up. |
| H3 | **Only the owner's number answers.** The link's inbox already drops other senders and named senders (modemlink `inbound`); held mode checks again. "message" answers other senders with no replies. Held mode sends no other prompt, so a single letter can only answer the question. | CAP-3, CH-21; #436 L3 point 4 | A held mode that sends another prompt needs to tell the replies apart. |
| H4 | **One reply at a time** (`heldReplies` mutex), across the inbox and "message". answerHeld reads the question, then writes it. | #436 L3 point 5 | None. |
| H5 | **A reply over 64 bytes is no choice**, and is asked again. modemlink already bounds a text to `bridgeproto.MaxText`. | #436 L3 point 8 | None. |
| H6 | **Fail closed on a failed save.** An answer whose write fails leaves the restore held. For the rest of that start, every reply gets the notice and no answer counts, so a failing disk cannot give more than one guess per start. | security C3 | None. |
| H7 | **STOP, STATUS and any other word get the held text back.** The agent is not running, so the held text is what STATUS would say, and STOP has nothing to stop. | CH-2 (STOP and STATUS work with every model down) | Give STOP and STATUS their own held replies if the UX lens wants them. |
| H8 | **The first text waits for the bridge to report the owner line OK.** It is sent again after 10 s and the next report if it did not go. Sending earlier fails as down and counts as a missed text, which the link would report to the owner as a text that didn't reach them. | CH-12 (no false text) | None. |
| H9 | **A hold with no question texts the marker's notice** (recovery.PendingNotice), checked as GSM-7 and at most three segments, with a fixed fallback. This covers rolled-back, forged and an unreadable question. agentosd does not import recovery, so the marker carries the text. | CH-12, A8 | None. |
| H10 | **"Restore this backup again" works**, because a restore writes its question afresh, open and with the same dates (recovery `writeQuestion`, deterministic decoys). The restore command itself is wired by W3-forget-b1-6. | #436 UX point 2 | If a re-restore keeps a closed question, the wrong-answer text must stop naming it. |
| H11 | **Release reuses nothing.** The released text's Send returns once the bridge reports it sent. Held mode then stops serving and `restoreHold` is checked again. The normal start opens its own link, and the bridge reconnects to the new owner.sock. | — | None. |
| H12 | **Releasing ends serving only after the releasing reply is written** (#487 L3 point 1). A release from inside a handler ("message", or "sent" ending the confirmation's Send) cancels the server while its reply is still being encoded. sockets now closes a connection only between requests, and gives a reply in flight at most 1 s to be written. | CH-12 (the owner hears the restore was released) | If sockets gains a graceful drain of its own, drop this reliance. |

## Capability lines (OP9-status)

Built for OP9-status-a against OP-9 and A11. Covers the capability-off registry in `capoff.go` and its wiring in `main.go`, `agent.go` (no change: `lateStatus` lives in `main.go`) and `questions.go`. Q1–Q3 are open with Mark; the brief's defaults (Q1a, Q2a, Q3a) are built, with the fix clauses as two constants (`fixUpdate`, `fixRestart`) so a ruling is one edit.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| 1 | "The digest repeats it while it lasts" is met by a live `Digest()` the digest sender reads each day. No sender exists until DIG-1. Until then the evidence is the `Digest()` tests, not a sent text. | OP-9, CH-15 | If DIG-1 dedupes repeated lines, OP-9 lines must be exempt, with a test there. |
| 2 | Accelerators, PSI, the modem bridge flag and the local page flag aren't OP-9 capabilities: nothing the owner uses is lost (RES-3, admission), or the shipped image always sets them. | OP-9, RES-3 | If the image can ship without the bridge or the page, add a line. |
| 3 | One line per cause, naming each capability that cause turns off, meets "names it in one line" (Q2). `-runsc` empty and the machine plane failing give "Agent and worker tools: …". | OP-9 | If Mark rules one line per capability, split the cause lines. |
| 4 | Listing an owner choice in STATUS's loop line is not "repeating it as an alert": STATUS is pulled by the owner. | OP-9, CH-15 | Drop it from STATUS. |
| 5 | Update checks (C11), a held security fix (D3) and PINNED/ASK (O2) depend on W5b constructing `maintain.Loop3`. Nothing calls `capState.updateChecks` yet, so C11's line stands on every box. W5b calls it with Loop 3's source (removing the line), registers D3 and O2, with a test, if -b has not. | OP-9, UPD-9 | — |
| 6 | Route withdrawal and declined classes (D4) are CRED-5f's. Their line enters through this registry when CRED-5f wires it. | OP-9, CAP-9 | — |
| 7 | Build gaps the owner can't fix say "nothing to do; a later box version adds it" (Q1). | OP-9 ("what would fix it") | Reword per Mark's answer. |
| 8 | **C2 cannot tell "no model grant" from "unreachable".** agentosd sees only whether the vault process's model socket accepts a connection (`modelProbe`, cached a minute); `modelroute` exposes no grant state and the brief adds no vault call. A box with no AI plan or key connected therefore reads "Model: not reachable, …; restart the box.", not "no AI plan or key is connected; connect one on the box's Wi-Fi page". Release finding against CRED-5f. | OP-9, A11, CRED-5f | When the vault process reports grant state, C2 gets the no-grant wording, with a test. |
| 9 | **Lines avoid apostrophes.** STATUS's `plainLine` (control/text.go) keeps only letters, digits and ` .,;:()-`; "can't" would read "cant". `ownerWorded` rejects any other character, which also rules out paths and `%v` text. The brief's sample wording ("can't think") is built as "cannot think". Existing notes with apostrophes (`noRoomNote`, `agentNoLimits`) are -b's. | OP-9 | If plainLine keeps apostrophes, the check can allow them. |
| 10 | **One agent line.** When a boot-time agent line is set (`mem.AgentOff`, `agentNoLimits`), it is STATUS's agent line and the registry adds no C1 line, even if the machine plane fails after. Otherwise a C1 cause blanks `lateStatus` (the daemon then shows the admission summary) and the registry's line names the agent. | OP-9 (one line), brief item 1 | If a later failure must be named beside H1/H2, add it as a worker-tools line. |
| 11 | **Main's paths are tested through their state, not by running main.** `main()` is one function; the tests drive `capState` the way each path does (`agentSpec` and `workerTools` are called for real; the questions book is failed for real), and the wiring calls are one line each at the logging sites. | OP-9 | If main is split, test the paths end to end. |
| 12 | The model probe dials with a 300 ms timeout at most once a minute, from STATUS or the digest; a STATUS during a slow dial waits for it. | OP-9 | If STATUS must never block, probe on a timer instead. |
