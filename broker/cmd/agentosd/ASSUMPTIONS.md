release finding R-1/R-2 on #327). Each row is a reading of the spec, or a
gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|

## Owed done texts (W3-forget-b3)

Built for W3-forget-b3 ("Promised done text survives a restart") against CAP-3, UX-182-3 and SHOULD 4 of L3 on #182. Covers the owed done texts in `broker/cmd/agentosd` (`forget.go`, `learn.go`). Each row is a reading of the spec or the brief that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| F1 | **Owed done texts are their own store, not the forget log.** `forget-owed.json` in the learn dir maps goal ID to the task's time and the undone count. It is written before the tombstone and cleared once the owner is told. The forget log (W3-forget-b1) is an authenticated append-only record of what was forgotten, not of what the owner was told, and it is nil until W3-forget-b1-5. "Rides the forget log" is read as: the done text after a restart appends to the forget log like any other done forget, and its tail follows that append. | CAP-3; SHOULD 4 on #182 | Move the owed state into the forget log once it carries an entry per told text. |
| F2 | **Told after the replay, at attach.** The start-up replay (`replayForgotten`) runs in `openLearning`. If it fails, learning does not open and nothing is told. The owner channel exists only from `attach`, so the owed goals are snapshotted after a successful replay and texted at attach. | UX-182-3; CAP-3 (told only after the save) | Send them from the replay itself if the owner channel opens earlier. |
| F3 | **No tombstone, no text.** An owed goal whose tombstone did not hold at start was not forgotten, so it is dropped untold. This covers a crash before the tombstone saved, and a "Not forgotten" no later save wrote. | CAP-3 | Text "not forgotten" at start for these too. |
| F4 | **A repeated text over a missing one.** The owner is told while the entry is on disk, and it is dropped only after (`TestTheDoneTextIsToldBeforeItIsDropped`, security S3 on #425). If clearing a told text fails to save, the next start tells it again. | CAP-3 | Clear before telling, accepting a lost text. Class: later (L3 on #425). |
| F5 | **Named by its time, never its text.** The text says "Your task from <date> is forgotten now." because the owner may have texted since. Without the ID's time it says "A task you asked me to forget". The store holds goal IDs, times and counts only. | security C2 on W3-forget | None expected. |
| F6 | **Uncapped.** One entry per forget not yet told. Entries exist only between a YES and its done text, so the store stays small. | — | Cap it if forgets can be owed in bulk. Class: later (L3 on #425). |
| F7 | **A restored backup's owed file is replayed like the live one.** Its goals that the restored tombstone or forget log hold are told again, as "forgotten now". | REC-2 | Drop the owed file on restore. Class: later (L3 on #425). |
| F8 | **The local Wi-Fi page's task list (potency R2) is not built here.** `broker/localui` has no task page. Listing older tasks needs a new page, a socket route and a forget path, all outside this brief's files. It is classed release (agreed with L3 on #425; the coordinator adds the BOARD row). Built by W3-forget-b3r (P1–P4). | brief W3-forget-b3 (carried) | — |
| F9 | **A done text is owed until it sends.** The owner channel's send reports failure (`loop2Notify.try`), for example modemlink's ErrDown just after boot. A text that does not send stays in the owed file, with whether it was logged and the agent taken back, and is sent again with backoff (2s doubling to a minute). At a shutdown it is left to the next start. | CAP-3; L3 B1 on #425 | None expected. |
| F10 | **An unreadable owed file fails safe.** It is kept aside as `forget-owed.json.bad` by a hard link (same inode, so its 0600 mode holds), then the fresh file is saved over it (atomic rename), so the path holds the bad file or the fresh one, never nothing; a crash before the save repeats both at the next start (security S1 on #425). If the aside fails, the fresh file still replaces the bad one and that is logged. A fresh file starts, and the owner is owed one fixed notice: "After a restart I couldn't read which forget texts I still owed you. Send FORGET to see your recent tasks." Entries that read but no forget wrote are sanitized: a goal with no tombstone gets no text, a negative count reads as none, and a future time reads as "A task you asked me to forget". No text repeats words from the file. | security C2; L3 B2 on #425 | Text each recoverable goal from the `.bad` file instead. |
| F11 | **A failed owed save is saved again before the forget can finish.** If `Execute`'s owed save fails and the forget goes to `retry`, each pass saves it again before forgetting, until it holds; it stops at shutdown like the forget. What is still lost: a text whose owed save fails on every pass up to the one where the forget holds, plus a crash before that text sends; or an owed save that fails when the forget finishes at once in `Execute`, plus a crash before the send. In the first case the owner may have been told `forgetNotSaved` ("I'll text you when it's done") and never is. Both need a failing disk and a crash; `done` keeps the text owed in memory, so without a crash it is still told. Logs carry store errors only. | CAP-3; UX-182-3; security S2 on #425 | Block the forget until the owed save holds, if the owner's promise must survive a failing disk. |

## Held restore (W3-forget-b1-7)

Built for W3-forget-b1-7 (#409 UX U2 and U6; #436 L3 points 4, 5 and 8, and UX points 1 and 2) against security C3, CAP-3, A8 and CH-12. Covers `held.go`, the held-mode block in `main.go`, and the text changes in `restoreconfirm.go`.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| H1 | **Held mode serves only owner.sock.** It uses the daemon's peer checks: the bridge's uid and group, at most 8 connections, a 60 s idle timeout. It serves the bridge's ops, and "message" where the daemon would (no `-modem-bridge`, or `-owner-message`). localui.sock is not served, so the local page shows nothing while the box is held. | security C3 (a held restore opens nothing restored) | Serve a held-state page on localui.sock if the UX lens asks for one. |
| H2 | **The owner comes from `-owner`, else from setup's finished record**, the same source setup mode reads. The record is read before setup mode would run. With neither, agentosd exits as before b1-7, since no one can be texted. | CAP-3 | Have held mode run setup first, if a held box can be one that was never set up. |
| H3 | **Only the owner's number answers.** The link's inbox already drops other senders and named senders (modemlink `inbound`); held mode checks again. "message" answers other senders with no replies. Held mode sends no other prompt, so a single letter can only answer the question. | CAP-3, CH-21; #436 L3 point 4 | A held mode that sends another prompt needs to tell the replies apart. |
| H4 | **One reply at a time** (`heldReplies` mutex), across the inbox and "message". answerHeld reads the question, then writes it. | #436 L3 point 5 | None. |
| H5 | **A reply over 64 bytes is no choice**, and is asked again. modemlink already bounds a text to `bridgeproto.MaxText`. | #436 L3 point 8 | None. |
| H6 | **Fail closed on a failed save.** An answer whose write fails leaves the restore held. For the rest of that start, every reply gets the notice and no answer counts, so a failing disk cannot give more than one guess per start. | security C3 | None. |
| H7 | **STOP, STATUS and any other word get the held text back.** The agent is not running, so the held text is what STATUS would say, and STOP has nothing to stop. | CH-2 (STOP and STATUS work with every model down) | Give STOP and STATUS their own held replies if the UX lens wants them. |
| H8 | **The first text waits for the bridge to report the owner line OK.** It is sent again after 10 s and the next report if it did not go. Sending earlier fails as down and counts as a missed text, which the link would report to the owner as a text that didn't reach them. | CH-12 (no false text) | None. |
| H9 | **A hold with no question texts the marker's notice** (recovery.PendingNotice), checked as GSM-7 and at most three segments, with a fixed fallback. This covers rolled-back, forged and an unreadable question. agentosd does not import recovery, so the marker carries the text. | CH-12, A8 | None. |
| H10 | **"Restore this backup again" works**, because a restore writes its question afresh, open and with the same dates (recovery `writeQuestion`, deterministic decoys). The restore command itself is wired by W3-forget-b1-6. | #436 UX point 2 | If a re-restore keeps a closed question, the wrong-answer text must stop naming it. |
| H11 | **Release reuses nothing.** The released text's Send returns once the bridge reports it sent. Held mode then stops serving and `restoreHold` is checked again. The normal start opens its own link, and the bridge reconnects to the new owner.sock. | — | None. |
| H12 | **Releasing ends serving only after the releasing reply is written** (#487 L3 point 1). A release from inside a handler ("message", or "sent" ending the confirmation's Send) cancels the server while its reply is still being encoded. sockets now closes a connection only between requests, and gives a reply in flight at most 1 s to be written. | CH-12 (the owner hears the restore was released) | If sockets gains a graceful drain of its own, drop this reliance. |
