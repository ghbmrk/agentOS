# Local inference service: assumptions

What `broker/infer`, `broker/infer/supervise`, `broker/cmd/agentos-infer` and the
agentosd wiring rest on (briefs/INFER-SVC.md). Each row is a reading of the spec, or
a property the code relies on, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| INFER-A1 | The package ships in two PRs at the brief's split. The first carries the protocol, client, supervisor, service and agentosd wiring against a fake runtime, with `-infer` off by default; no runtime adapter is linked, so `agentos-infer` built from it answers every call unavailable. The second adds the llama.cpp adapter (`runtime_llamacpp.go`, `real_test.go`), the image build, the service user and the `-infer-uid` flag in `agentosd.service` (INF-3), and the N95 step (INF-7). | INF-3, INF-7; brief "split at the checkpoint" | Turning `-infer` on before the second PR merges starts a service that only ever answers unavailable; nothing else changes. |
| INFER-A2 | The model file is image-owned and read-only to the service, so a change between the service's hash check and the runtime's read is not defended against. The image installs it root-owned, mode 0644, at `/usr/lib/agentos/infer/` on the dm-verity `/usr` (image/infer.sh), where no process on the box can change it. | INF-1, INF-6 | A model file the service user, or any non-root user, can write needs the runtime to load from the fd that was hashed instead. |
| INFER-A3 | The runtime serves embeddings without a TCP port (stdio or in-process); if it needs one, it binds 127.0.0.1 inside the child's own network namespace after bringing loopback up, which reaches nothing outside. | INF-6; brief assumption | The INF-6 test stays as it is; the supervisor's jail is unchanged. |
| INFER-A4 | The model ships under Apache-2.0 (D-230, Mark's Q2 answer), so the image carries only its licence text. image/infer.sh reads `general.license` from the exact file's own GGUF header (image/gguf_licence.py) and stops the build unless it is `apache-2.0`. The model's repository ships no licence file (its card names Apache-2.0), so the text installed at `/usr/share/licenses/Qwen3-Embedding-0.6B/LICENSE` is the Apache License 2.0 from this repository's own `LICENSE`. | INF-3 | A model under other terms needs its own decision before it ships. |
| INFER-A5 | A user namespace with a one-uid map is available to agentosd on the target kernel. Where it is not, every start fails and the service reports unavailable, never stopping the broker. | INF-1, INF-4 | A kernel without unprivileged user namespaces needs a jail built another way. |
| INFER-A6 | The model is an embedding model only (D-230), by default Qwen3-Embedding-0.6B at Q8_0: about 0.64 GB of weights and about 112 KiB of f16 cache a token (28 layers, 8 KV heads of 128). With the runtime at two slots of 2048 tokens (one per `Config.Concurrent` call; 8 KiB of text is at most about 2048 tokens), the cache is about 0.45 GB and peak RSS about 1.1 to 1.4 GB, inside the 2.0 GB leaf. [Inference from model-size arithmetic; INF-7 on the N95 (#3656) measures it or the cap drops to 1.] | INF-1, RES-2 | Lower the default `Concurrent`; the leaf's OOM kill reports `oom` and restarts meanwhile. |
| INFER-A7 | The leaf is the `inference` group `budget.Memory.Apply` creates beside the machine pool; agentosd finds it through the machine group it already opens, even when no runsc is configured, and starts nothing unless its `memory.max` equals the budget. It is not opened with `cgroup.Open`, whose subtree controllers would stop it holding a process. | INF-1, RES-2 | A budget layout that moves the component changes `inferenceLeaf` alone. |
| INFER-A8 | The supervisor's jail, leaf and OOM tests skip off root or without a delegated cgroup. CI's machines job runs `./infer/...` as root with no_new_privs and `AGENTOS_CGROUP_PARENT`, and fails the step on any skip, so they run on every PR that touches the package. | INF-1, INF-6 | If the machines job loses root or cgroup delegation, its skip check fails the step. |
| INFER-A11 | The llama.cpp adapter (`runtime_llamacpp.go`, build tag `infer_llamacpp`; the default build keeps `runtime_none.go`) runs one `llama-server` child at a time, started through `childproc` with `PATH` alone in its environment, in its own process group, with its log discarded (INF-8). It listens on a unix socket in an `os.MkdirTemp` directory (0700, removed on stop), so the service needs no network and no loopback (INFER-A3). The server is untrusted like the service: every reply is read under a byte bound and decoded, vectors are placed by their `index`, and the service checks count, dim and finiteness again; no error carries a server body. `Load` reads the GGUF header (arrays nest at most 4 deep): a model whose `<arch>.pooling_type` is 1 to 3 is an embedding model and runs with `--embedding` and the pooling its header names (Qwen3-Embedding: last token); a generative model (no pooling type or 0), a ranking model (4) and a file that is not a GGUF are `ErrRefused`, reported as corrupt (D-230). The dim is what the server returns for a probe text. | INF-1, INF-6, INF-8, CAP-13 | A generative route (a later row) needs a second adapter mode and its own memory budget; the header read is the only place that decides the mode. |
| INFER-A12 | The server runs with two slots of 2048 tokens (`--parallel 2 --ctx-size 4096`, INFER-A6), CPU only, no web UI, no slots endpoint and no network fetch (`--offline`). A text over a slot's context fails the call (the protocol's 8 KiB per text is about 2048 tokens, at the edge), and the service reloads the server on any failed call. The adapter relies on `--host PATH.sock`, `/health` and `/v1/embeddings` as in the pinned release; a release that changes them fails the real test. | INF-6, RES-2 | A larger context is `slotTokens` plus a cache figure from INF-7. Moving the pin runs infer-real. |
| INFER-A13 | The real-runtime test runs in `.github/workflows/infer-real.yml` on llama-server built from the pinned llama.cpp source (b11900) by `image/llamaserver.sh`, the same script the image build runs, and on the default model, Qwen3-Embedding-0.6B at Q8_0 (Apache-2.0), all in `broker/cmd/agentos-infer/llama.pins` with their SHA-256; each file whose hash differs is refused before anything builds or runs. The source hash was taken from a CI download (the build session cannot reach github.com archives; GitHub publishes no hash for them, and a regenerated archive fails the build rather than changing what ships); the model hash is Hugging Face's own LFS object id and equals the hash of the file downloaded in the build session. `ci.yml` compiles the real test and runs the fake-server tests on every change. The image's boot test (image/ci_boot.sh, INFER) runs it again on the installed files as `agentos-infer`. | INF-3, CAP-13 | A new release or model changes `llama.pins` (and the model's name and hash in `agentosd.service` and `boot-report`) and nothing else; infer-real and the image run show it works. |
| INFER-A14 | The service's user can create a directory under `TMPDIR` (default `/tmp`) and a unix socket in it, and the path stays under the 108-byte socket limit. The supervisor's jail leaves the host filesystem visible, so `/tmp` is the host's; the image's boot test runs the real test as `agentos-infer` with `/tmp` as the box has it, and an image that mounts `/tmp` read-only needs a `RuntimeDirectory` for the service instead. | INF-1, INF-6 | A service that cannot make its socket directory fails every load as unavailable, never stopping the broker. |
| INFER-A15 | llama-server is built static (glibc and libstdc++ linked in; the build fails on an interpreter or a NEEDED entry), CPU only, with no network client (`LLAMA_CURL`, `LLAMA_OPENSSL` off) and no dynamically loaded backends, for a fixed instruction set: x86-64 with SSE4.2, AVX, AVX2, FMA, F16C and BMI2 (the N95 floor has them all), never the build machine's (`GGML_NATIVE` off), with ggml's own thread pool instead of OpenMP. A CPU without AVX2 cannot run it: every load fails and the service answers unavailable (RES-3 holds on the floor and up). The source path is mapped out of the binary, so two builds of one commit match (IMG-2). | RES-3, HW-4, IMG-2 | A target without AVX2 needs a second build or ggml's per-CPU variants (`GGML_CPU_ALL_VARIANTS`, which needs dynamic backends). |
| INFER-A16 | The image carries the model with the service off (D-230): 639,150,592 bytes of the 6 GiB `/usr` slot, plus llama-server, on every release until a retrieve row turns `-infer` on, and no memory at boot. The default model is kept (the brief allows a smaller Apache-2.0 embedder only if this one fails INF-7 on the N95, #3656). | RES-2, D-230 | A model swap changes the pins, the unit and the boot report together (INFER-A13). |
