# Local inference service: assumptions

What `broker/infer`, `broker/infer/supervise`, `broker/cmd/agentos-infer` and the
agentosd wiring rest on (briefs/INFER-SVC.md). Each row is a reading of the spec, or
a property the code relies on, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| INFER-A1 | The package ships in two PRs at the brief's split. The first carries the protocol, client, supervisor, service and agentosd wiring against a fake runtime, with `-infer` off by default; no runtime adapter is linked, so `agentos-infer` built from it answers every call unavailable. The second adds the llama.cpp adapter (`runtime_llamacpp.go`, `real_test.go`), the image build, the service user and the `-infer-uid` flag in `agentosd.service` (INF-3), and the N95 step (INF-7). | INF-3, INF-7; brief "split at the checkpoint" | Turning `-infer` on before the second PR merges starts a service that only ever answers unavailable; nothing else changes. |
| INFER-A2 | The model file is image-owned and read-only to the service, so a change between the service's hash check and the runtime's read is not defended against. | INF-1, INF-6 | A model file the service user, or any non-root user, can write needs the runtime to load from the fd that was hashed instead. |
| INFER-A3 | The runtime serves embeddings without a TCP port (stdio or in-process); if it needs one, it binds 127.0.0.1 inside the child's own network namespace after bringing loopback up, which reaches nothing outside. | INF-6; brief assumption | The INF-6 test stays as it is; the supervisor's jail is unchanged. |
| INFER-A4 | The model's licence permits shipping it in the image (RECALL-EMB's assumption); the second PR verifies it before building, else stops and escalates. | INF-3 | No model in the image: the service stays off. |
| INFER-A5 | A user namespace with a one-uid map is available to agentosd on the target kernel. Where it is not, every start fails and the service reports unavailable, never stopping the broker. | INF-1, INF-4 | A kernel without unprivileged user namespaces needs a jail built another way. |
| INFER-A6 | Two concurrent requests at batch 64 fit the 2.0 GB inference leaf with the 1.0 GB embedder figure. A generate model does not leave room for two calls at once (about 1.1 GB of weights plus about 0.5 GB of cache at a 4096-token context), so with `Config.Concurrent` unset the service runs two calls at once of which at most one is a generate, leaving a slot for hello; `-concurrent N` lets any N calls be generates. [Inference from model-size arithmetic; INF-7 and G6 on the N95 confirm it or the cap drops.] | INF-1, RES-2, PLN-7 | Lower the default `Concurrent`; the leaf's OOM kill reports `oom` and restarts meanwhile. |
| INFER-A9 | A generate call is bounded by 120 s on both sides (`Client.GenerateTimeout`, `-generate-timeout`) and by `MaxOut` 1024 tokens. At G6's floor of 5 tokens/s, a full 1024-token reply after a 512-token prompt takes about 205 s, past the deadline, so such a call is `unavailable`. The model clerk's local route asks for fewer tokens until G6 measures the box. [Inference: from G6's limits, not measured.] | PLN-7, HW-4 | Raise both deadlines together, or lower `MaxOut`, from G6's figures. |
| INFER-A10 | `hello` names the ops the loaded model serves (`embed`, `generate` or both), with `dim` exactly when `embed` is served, and the client sends a prompt only after a `hello` on the same connection names `generate`. The generate reply's `sha256` must equal that `hello`'s, so a service cannot pass off text from another model within one call. Which model ships, and whether it serves embed, generate or both, is the brief's Q1 and Q2; this protocol carries any of the answers. | PLN-7, INF-2 | A model that serves an op the protocol does not name needs a new op and a new `hello` value, not a reuse of these. |
| INFER-A7 | The leaf is the `inference` group `budget.Memory.Apply` creates beside the machine pool; agentosd finds it through the machine group it already opens, even when no runsc is configured, and starts nothing unless its `memory.max` equals the budget. It is not opened with `cgroup.Open`, whose subtree controllers would stop it holding a process. | INF-1, RES-2 | A budget layout that moves the component changes `inferenceLeaf` alone. |
| INFER-A8 | The supervisor's jail, leaf and OOM tests skip off root or without a delegated cgroup. CI's machines job runs `./infer/...` as root with no_new_privs and `AGENTOS_CGROUP_PARENT`, and fails the step on any skip, so they run on every PR that touches the package. | INF-1, INF-6 | If the machines job loses root or cgroup delegation, its skip check fails the step. |
| INFER-A11 | The llama.cpp adapter (`runtime_llamacpp.go`, build tag `infer_llamacpp`; the default build keeps `runtime_none.go`) runs one `llama-server` child at a time, started through `childproc` with `PATH` alone in its environment, in its own process group, with its log discarded (INF-8). It listens on a unix socket in a `os.MkdirTemp` directory (0700, removed on stop), so the service needs no network and no loopback (INFER-A3). The server is untrusted like the service: every reply is read under a byte bound, decoded, and checked again by the service as before; no error carries a server body. One server serves one mode: a GGUF whose `<arch>.pooling_type` is 1 to 3 runs with `--embedding` and serves embed with `dim` as the server returns it; any other runs without it and serves generate; pooling 4 (ranking) and a file that is not a GGUF are `ErrRefused`. A model that serves both needs two servers, which the one-leaf budget (INFER-A6) does not allow, so it is not built. | INF-1, INF-6, INF-8, PLN-7 | A model that serves both ops from one file needs a second child and a budget for it. The header read is the only place that decides the mode. |
| INFER-A12 | The server runs with a 4096-token context, one slot, no prompt cache (`--cache-ram 0`, `cache_prompt` false: no call's text stays in the server for the next), CPU only, no web UI, no slots endpoint and no network fetch (`--offline`); `temperature` 0 and `seed` 0 make a generate call repeat. A prompt that does not fit the context fails the call (the 32 KiB protocol bound is about 8k tokens, over it), and the service reloads the server on any failed call, so a caller that sends one costs a reload; the model clerk's local route keeps prompts under the context (G2). Child exit between calls shows as a failed call, then a reload. The adapter relies on `--host PATH.sock`, `/health`, `/completion` and `/v1/embeddings` as in the pinned release; a release that changes them fails the real test. | INF-6, RES-2, PLN-7 | A larger context is a `contextTokens` change plus a cache figure from G6. Moving the pin runs infer-real. |
| INFER-A13 | The real-runtime test runs in `.github/workflows/infer-real.yml` on the pinned llama.cpp release and two Apache-2.0 test models (Qwen3 0.6B and Qwen3-Embedding 0.6B at Q8_0), all in `broker/cmd/agentos-infer/llama.pins` with their SHA-256; the workflow refuses any file whose hash differs. The release hash was taken from a CI download (the build session cannot reach github.com releases), the model hashes are Hugging Face's own LFS object ids. The test models exercise the adapter; the model the image ships is G5's, with INFER-A4. `ci.yml` compiles the real tests and runs the fake-server tests on every change. The image machine test runs the real test again against the installed files after G5. [The llama.cpp release's asset name and layout are from the project's release convention, confirmed by the first workflow run.] | INF-3, PLN-7 | A new release or model changes `llama.pins` and nothing else; infer-real shows it works. |
| INFER-A14 | The service's user can create a directory under `TMPDIR` (default `/tmp`) and a unix socket in it, and the path stays under the 108-byte socket limit. The supervisor's jail leaves the host filesystem visible, so `/tmp` is the host's; G5's machine test confirms it with the real service user, and an image that mounts `/tmp` read-only needs a `RuntimeDirectory` for the service instead. | INF-1, INF-6 | A service that cannot make its socket directory fails every load as unavailable, never stopping the broker. |
