# Decoy table and matcher: assumptions

Built for DECOY-a (#3762, `briefs/DECOY.md`, D-232): the table, its sealed storage and first-boot event, and the matcher (`match/`). Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| DECOY-a-1 | **Built-in kinds follow a published or widely-validated format.** GitHub classic token: `ghp_`, 30 base62 (0-9A-Za-z), and the CRC32 of those 30 as six zero-padded base62 digits, as GitHub described it in 2021. AWS key ID: `AKIA` and 16 base32 symbols, the first from the upper half (the encoded account's top bit, set in every key AWS issues now); secret: 40 base64 symbols. Anthropic and OpenAI keys: gitleaks' `anthropic-api-key` and `openai-api-key` shapes. Recovery codes: GitHub's `xxxxx-xxxxx` lower hex. SSH: an unencrypted OpenSSH ed25519 key with an empty comment, lines of 70, as `ssh-keygen -C ""` writes it. No issuer publishes its full validity rule, so a decoy differs from a real value only in that no issuer accepts it, which an intruder can learn only by using it. | KRN-12 One table | A format an issuer changes gets a new kind; the corpus (`testdata/corpus.py`) is regenerated with it. |
| DECOY-a-2 | **The box's own kinds come from the caller.** Honey keys (KEY-1 shape, no root) and sealed-store root or recovery entries are made by the code that makes the real ones, which this package does not link (the kernel imports it in DECOY-b, so it stays standard-library plus `match`). The caller passes them as `Own` generators to `Generate` at first boot; this slice makes none. | KRN-12 One table, Placement | DECOY-b and DECOY-e pass their generators to `FirstBoot`. |
| DECOY-a-3 | **One sealed-store entry.** The table's stored form is one entry, `decoy/table`, at most 4 KiB (seal's `MaxEntry`); the built-in plan takes about 3 KiB (3.5 KiB with four short own entries), leaving room for a few own entries. A larger table fails first boot with `ErrTooBig` rather than splitting across entries, which seal does not commit atomically. | STO-2 | Splitting needs a header written last with the parts' digest. |
| DECOY-a-4 | **First boot is idempotent; the log is the authority after it.** The kernel (DECOY-b) reads `decoy/table` first and generates only if the store holds none, so a boot cut short between the save and the log write logs the same table. This package returns bytes and does not call the store itself, so it is handed no core write path (`core.txt`). Replay rebuilds the table from the event body only, never from the store or a generator, so a generator change in a later release changes no past trip. | KRN-1, KRN-6 | none |
| DECOY-a-5 | **Values match raw and in the common encodings.** JSON string, with `/` as written and as `\/`, URL query, with spaces as `+` and as `%20`, URL path, lower and upper hex, and base64 in the standard and URL-safe alphabets at each of the three byte offsets a value can start at inside a longer run, padded or not: at each offset the form is the characters whose six bits all come from the value (#3876). A PEM's text forms are also matched for its body alone, the lines between its first and last, if that is `match.MinJoined` bytes or more (#4853). Every form is also matched in the text joined: CR, LF, `%0a` and `%0d` (either case) and the JSON escapes `\r`, `\n`, `\u000a` and `\u000d` at any depth removed, so base64 or hex broken into lines at any width (76 in base64(1) and MIME, 64 in PEM, 60 in `xxd -p`), raw, URL-escaped or JSON-escaped in a plan step, matches (#4500, #4582). Each removed break is kept, so a form whose first characters could end one (base64 `n` after a literal `\`, hex `0a` after `%`) also matches with them read back; a break begins after the last one, so one split by another (`%0` + JSON `\n` + `A`) is not removed, a run of `\`s counts as one in the joined text, and a break is let go once the longest form's rest has come and no later break's head is still open in it (#4582). Since joined text counts a run of `\`s as one, a form holding a run is also matched with each run as one `\`, and a form's `\` may end the run a JSON break removes, so it is also read back there: a value holding a `\` matches with its JSON form, other escapes and all, split anywhere, right after the escaped `\` too, and so does the value with a JSON break in its `\`'s place, a near-copy as telling as the value; a `%0a` or `%0d` inside a `\` run, at any depth and however many split it, is read as the run it splits: the `\` after one joins the run as it comes, unless it begins a JSON break, so a break is held for no more than the longest form and costs nothing more per byte; and a form's rest after a break is matched with each later break read back the same way, so a form split many times, or begun inside a break and split again, matches (#4622, #4681). A `\` is read back only where the bytes beside the break are those beside it in its form, so a break costs one lookup and, for each of the table's `\`s with those neighbours, a check of the bytes before it and a walk over its form's rest, where each later `\` is that byte or a held JSON break: for the built-in kinds, a few dozen `\`s, the SSH decoy's JSON forms' (a `\n` for each line and a `\/` for each `/`) and the AWS secret's `\/` form's, and for a value whose JSON form repeats one escape (a MaxValue value of `<`s: 1,024 `\`s in 6,144 bytes), which only the box's table can hold, up to that value's `\`s times its form's length per break, bounded by the table, not the stream (#4681). The rest is compared whole between `\`s with the held breaks walked in order (#4743), and a held break is walked once, when it is let go or the result is read, not again at each scan, so the joined text keeps the longest form before the first held break (#4853). On that table alone (256 KiB in 512-byte writes, no trip) plain text runs at about 1.1 MB/s, `c\nu` repeated at about 0.6 MB/s, and the near-copy stream (the `<`s' JSON form with a JSON break for each `\`, one `<` short, repeated) at about 0.35 MB/s, a third of plain text. The worst value measured, `\x` 512 times, a `\` in every other byte (Security on #4845): its near-copy (its raw form with a JSON break for each `\`) runs at about 0.19 MB/s, 6 to 8 times plain text (about 21 times before #4853). `TestBreakStreamCost` holds the `<`s' near-copy within 9 times plain text and the `\z`s' within 12, timed best of three rounds against plain text (#4853). A value that holds break text itself (a CR, LF or one of those escapes in its bytes, as the SSH decoy's PEM does) is also matched in its text forms as the joined text holds it when the byte after it begins no break (so a `\` that a `%0a` split off a run joins it, #4853), its own breaks removed, so it trips with its breaks changed (CRLF, JSON `\r\n`, `%0a`), dropped, trimmed or added to, or rewrapped at another width; not with a break put inside one of its own, as one split by another is not removed; and no joined form, this or a run-collapsed one, under `match.MinJoined` (10 bytes, `decoy.MinValue`) is matched, as ordinary text could hold it (#4743). A value broken by other characters (spaces, tabs, `%250A`, `%5Cn`), split into fields, or encrypted does not match; the enforcer's fixed addresses and the destinations are the backstop for those. A stream carries back the longest encoded form and 4 KiB for CLK-4's patterns, as written and joined, and the joined text never past the longest form before a break still held, whatever the forms' length (#4622, #4853), so a value or token split across writes still matches, and scans once 4 KiB is pending or its result is read, so small writes cost each byte about two scans. | KRN-12 Trips, CLK-4 | More encodings are one line each in `match.encodings`, with a test. |
| DECOY-a-6 | **Destinations trip at connect time, not in text.** `Matcher.Dest` takes the address a connection reaches (plain, IPv4-mapped, or NAT64's well-known prefix, with any zone dropped); an address named in bytes is not a trip, so a page that names 169.254.169.254 is refused at connect time and stops only its session (DECOY-b, DECOY-c). | KRN-12 Trips | A local-use NAT64 prefix (RFC 8215) is added when the box uses one. |
| DECOY-a-7 | **Printing never shows a value.** `Table` and `Entry` print kind, place and destination only (`%v`, `%+v`, `%#v`, and an `Entry` in JSON), so a log line or error that formats one leaks nothing; the event body and the stored form are the only places a value is encoded, and both are sealed. | KRN-12, CLK-1 | none |
| DECOY-a-8 | **The corpus is hex.** `testdata/corpus.json` stores each synthetic example hex-encoded, so secret scanners do not read a checksum-valid synthetic token as a leak. | CLAUDE.md (synthetic canaries) | none |
| DECOY-a-9 | **Bounded sampling.** Every uniform draw, symbols and destinations alike, rejects over one byte when the set fits one and two bytes otherwise, so no accepted range is empty; more than `MaxRange` (65,536) decoy addresses is refused. A value shorter than `MinValue` (10 bytes, a recovery code) is refused, so no value is short enough to trip on ordinary traffic. | KRN-12 One table | none |
