# Decoy table and matcher: assumptions

Built for DECOY-a (#3762, `briefs/DECOY.md`, D-232): the table, its sealed storage and first-boot event, and the matcher (`match/`). Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| DECOY-a-1 | **Built-in kinds follow a published or widely-validated format.** GitHub classic token: `ghp_`, 30 base62 (0-9A-Za-z), and the CRC32 of those 30 as six zero-padded base62 digits, as GitHub described it in 2021. AWS key ID: `AKIA` and 16 base32 symbols, the first from the upper half (the encoded account's top bit, set in every key AWS issues now); secret: 40 base64 symbols. Anthropic and OpenAI keys: gitleaks' `anthropic-api-key` and `openai-api-key` shapes. Recovery codes: GitHub's `xxxxx-xxxxx` lower hex. SSH: an unencrypted OpenSSH ed25519 key with an empty comment, lines of 70, as `ssh-keygen -C ""` writes it. No issuer publishes its full validity rule, so a decoy differs from a real value only in that no issuer accepts it, which an intruder can learn only by using it. | KRN-12 One table | A format an issuer changes gets a new kind; the corpus (`testdata/corpus.py`) is regenerated with it. |
| DECOY-a-2 | **The box's own kinds come from the caller.** Honey keys (KEY-1 shape, no root) and sealed-store root or recovery entries are made by the code that makes the real ones, which this package does not link (the kernel imports it in DECOY-b, so it stays standard-library plus `match`). The caller passes them as `Own` generators to `Generate` at first boot; this slice makes none. | KRN-12 One table, Placement | DECOY-b and DECOY-e pass their generators to `FirstBoot`. |
| DECOY-a-3 | **One sealed-store entry.** The table's stored form is one entry, `decoy/table`, at most 4 KiB (seal's `MaxEntry`); the built-in plan takes about 3 KiB (3.5 KiB with four short own entries), leaving room for a few own entries. A larger table fails first boot with `ErrTooBig` rather than splitting across entries, which seal does not commit atomically. | STO-2 | Splitting needs a header written last with the parts' digest. |
| DECOY-a-4 | **First boot is idempotent; the log is the authority after it.** The kernel (DECOY-b) reads `decoy/table` first and generates only if the store holds none, so a boot cut short between the save and the log write logs the same table. This package returns bytes and does not call the store itself, so it is handed no core write path (`core.txt`). Replay rebuilds the table from the event body only, never from the store or a generator, so a generator change in a later release changes no past trip. | KRN-1, KRN-6 | none |
| DECOY-a-5 | **Values match raw and in the common encodings.** JSON string, URL query, lower and upper hex, and base64 in the standard and URL-safe alphabets at each of the three byte offsets a value can start at inside a longer run, padded or not: at each offset the form is the characters whose six bits all come from the value (#3876). A value re-wrapped (PEM lines joined, base64 broken into lines, a key split into fields) or encrypted does not match; the enforcer's fixed addresses and the destinations are the backstop for those. A stream carries back the longest encoded form and 4 KiB for CLK-4's patterns, so a value or token split across writes still matches, and scans once 4 KiB is pending or its result is read, so small writes cost each byte about two scans. | KRN-12 Trips, CLK-4 | More encodings are one line each in `match.encodings`, with a test. |
| DECOY-a-6 | **Destinations trip at connect time, not in text.** `Matcher.Dest` takes the address a connection reaches (plain, IPv4-mapped, or NAT64's well-known prefix, with any zone dropped); an address named in bytes is not a trip, so a page that names 169.254.169.254 is refused at connect time and stops only its session (DECOY-b, DECOY-c). | KRN-12 Trips | A local-use NAT64 prefix (RFC 8215) is added when the box uses one. |
| DECOY-a-7 | **Printing never shows a value.** `Table` and `Entry` print kind, place and destination only (`%v`, `%+v`, `%#v`, and an `Entry` in JSON), so a log line or error that formats one leaks nothing; the event body and the stored form are the only places a value is encoded, and both are sealed. | KRN-12, CLK-1 | none |
| DECOY-a-8 | **The corpus is hex.** `testdata/corpus.json` stores each synthetic example hex-encoded, so secret scanners do not read a checksum-valid synthetic token as a leak. | CLAUDE.md (synthetic canaries) | none |
| DECOY-a-9 | **Bounded sampling.** Every uniform draw, symbols and destinations alike, rejects over one byte when the set fits one and two bytes otherwise, so no accepted range is empty; more than `MaxRange` (65,536) decoy addresses is refused. A value shorter than `MinValue` (10 bytes, a recovery code) is refused, so no value is short enough to trip on ordinary traffic. | KRN-12 One table | none |
