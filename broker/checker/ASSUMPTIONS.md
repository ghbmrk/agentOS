# checker: assumptions

What `checker` and `checkersock` rest on (SIM-split, briefs/SIM.md; OPERATING §5). The checker process is `cmd/agentos-checker` on `clerk/codecheck` (D-244), whose ASSUMPTIONS.md covers the seed, the verify buckets and the spent step; MIG-5-checker-server (#5012) deleted this package's own server, which no binary ran. What stays is the clients the key holders and `agentos-egress -checker` link. Since D-244 nothing serves the redeem socket or `hand.sock` (`agentos-checker` listens only on `verify.sock`, and codecheck redeems nothing), so `-checker` on agentos-holder and agentos-egress fails closed: no approval is redeemed and no unlock code passes.

| ID | Assumption | Source | Held by |
|---|---|---|---|
| C-4 | An act is the SHA-256 of the length-prefixed account (the credential name), host, method, wire path and body, so it binds the whole request a holder sends and the login that sends it (#1057 S1). The approval's issuer must compute it over the exact bytes the holder sends: the body rule's encoding, which equals what egress forwards because the rule is idempotent. Every holder shares one redeem socket and the socket does not map uid to account, so a compromised holder can spend, and so deny, another account's approval, but never use it with that account's login. | CH-10, ADP-10 | `TestActBindsTheWholeRequest`, `TestHighRiskActNeedsACheckerVerifiedCode`, `TestApprovalIsBoundToTheAccount` |
| MIG-5-checker-server-1 | The clients trust only the closed answers: `Redeemer` reads 204 as a spent approval and 403 as none, and every other answer or a failed dial as an error the holder refuses; `VerifyClient` reads 200 as the match, 429 as a pause with its end, 503 as no seed and a failed dial as `ErrDown`. These clients have no live server: their callers' tests run against small fakes of the socket protocol, and a failed dial, which is what they get today, is refused. | CH-4, CH-10 | `TestRedeemerTrustsOnly204`, `TestVerifyTOTPReadsEachAnswer`, `TestHolderRedeemsOverTheCheckerSocket` |
