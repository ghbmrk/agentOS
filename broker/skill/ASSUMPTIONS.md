# Compiled skills (format and runner): assumptions

Built for PLAN P3 ("compiled skills", CAP-5) against SPEC v0.12. These rows covered `broker/skill` in `broker/compile/ASSUMPTIONS.md` (K1, K2, K9, K11 there); they moved here when MIG-4-untrusted-change (a) (#2785) deleted the compiler, with their text unchanged. Whether this package stays under v1.0 is #2784's call.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-untrusted-change-K1 | **Where a skill runs.** In the guest, not the broker. `agentos-guest-bridge` serves each valid file under the tree's `skills/` and `procedures/` as an MCP tool `skill_<id>` on `/skills/mcp`, and runs it by sending each step to the broker's own `effect_request`. A skill therefore holds no authority of its own: every step is journaled, rate-limited, routed, label-stamped, checked against grants and approved exactly as a request the model made (ARC-7), and the broker never interprets a skill (ARC-2). The guest is root and can change or ignore the runner; nothing in the broker trusts it. The same holds in replay, which seeds the tree into the replay machine, so held-out evaluation exercises the skill as it would run live. | CAP-5, ARC-2, ARC-7, LOOP-5 | — |
| MIG-4-untrusted-change-K2 | **Where the model is consulted.** Once, to fill the skill's inputs; then only where an assumption fails. The assumptions are: every input is present, of its slot's type (text, email, number, bool, list or object), and no longer than twice the longest value any source run used (at least 64 bytes); and every step succeeds. A failed input stops the run before any effect. A step in any state but `succeeded` (waiting for the owner, denied, held, refused) stops it there, and the tool returns the remaining steps with their bound values for the model to finish. The runner never retries, skips or reorders a step. Step request IDs are `skill-<id>-<run_id>-<n>`, so a retried run repeats its requests and each effect runs at most once (OP-1). | CAP-5, OP-1 | Add value assumptions (enumerations, patterns) when Loop 1 data shows inputs that pass the type check but fail the step. |
| MIG-4-untrusted-change-K9 | **Format.** Skill files (package `skill/format`, standard library only, ARC-2) are decoded strictly: anything but the canonical encoding (duplicate keys, spacing, trailing data), unknown fields, an ID that is not `k`/`p` plus 12 hex of the shape its own steps give or not the file's name, a param or object key compile would not walk, an empty object, more than 32 steps or slots, an unused or unknown slot, a node that is not exactly one of literal, slot or object, a procedure with a literal, the `broker` account, or a `meta.*` action each refuse the file, and the bridge does not offer it. Account and action names follow the guest plane's lowercase rule. | CAP-5, OP-5 | — |
| MIG-4-untrusted-change-K11 | **Time bounds.** A whole skill run is bounded by `RunTimeout` (10 min) and each step's request by `StepTimeout` (3 min); a step past its time stops the run like any failed step. | CAP-5 | — |
