# Verb list and demo mismatch check: assumptions

Built for ADP-8 (PR #208) and wired into §11 adoption by ADP-8b (#895). Each row is a reading of the spec, or a gap left
for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| V1 | The mismatch rule keys on verb classes, not names: any effect other than read or the mapped verb itself exceeds a Reversible verb, so read, draft, organize and any reversible verb added later are covered alike. | ADP-8, ADP-2 (organize changes only what the owner sees) | A new class between Reversible and Irreversible would need its own case in `Exceeds`. |
| V2 | A verb off the list, mapped or observed, blocks. An irreversible or secret effect exceeds every verb but itself, so a payment mapped to send blocks even though both are irreversible (the owner may pre-allow send, ADP-9). A reversible effect under an irreversible verb does not (a send that keeps a sent copy). | ADP-8, ADP-9; ADP-8b brief item 6 | If the spec ranks irreversible verbs, `Exceeds` could allow a weaker effect under a stronger verb. |
| V3 | `DemoRun.Effects` is trusted as given: the demo harness's own observation, never the adapter's claim. The `adapters` target implements `change.DemoHarness`; the adapter file has no field for effects or a class, and a file that tries does not parse. | ADP-8, A13 | The harness is the trust base for ADP-8; a harness that echoes the adapter's mapping would pass any mislabelled adapter. |
| V4 | Every declared operation needs at least one demo run, a run of an undeclared operation blocks, and an empty mapping blocks. | ADP-8b brief item 5 | None expected. |
| V5 | An operation mapped to "" (owner has not chosen) is held to Draft in the check. Runtime draft-only enforcement of such an operation is ADP-10 and egress, not this package. | ADP-2 | If unmapped operations may not be adopted at all, `checkAdapter` should forbid them instead. |
| V6 | The check fails closed: with no demo harness, or a harness error (including a tool with no demo environment), nothing is adopted. ADP-8 says "where one exists"; the path for a tool with no demo environment (ADP-14 first live runs) is left for a later package. | ADP-8, ADP-14 | A later package adds the no-demo-environment path; until then such a tool cannot get an adapter. |
| V7 | The demo runs inside classify, under the pipeline lock. A slow harness stalls other proposals (liveness, not safety). Moving it outside the lock needs a `pipeline.go` edit, which waits for #2023. | ADP-8 | Move the demo before the lock once #2023 merges. |
| V8 | An adapter is never authority-neutral: adoption and removal go to the owner, on an item that names the tool, its grants, and its irreversible and unmapped operations (V10). Adoption creates no grant; `grants` is a request the owner reads. Adapters are private-derived: a shared source cannot carry one and Export refuses one (CHG-5, OSS-3). | ADP-6, OSS-3, CHG-5 | If adoption should create grants, that is a grant-store change, not this file. |
| V9 | Revert mutant, by hand: replacing the `checkAdapter` call with `cl.neutral = false` makes `TestA13MislabelledDraftThatSendsBlocksAdoption` and four other ADP tests fail; disabling only the `Mismatch` result fails the A13, unexercised-operation, payment and mapping-rules tests. | ADP-8b brief item 4 | Rerun after any change to `checkAdapter`. |
| V10 | The owner's item for an adapter (`adapterItem` in `change/digest.go`) is always GrantChange (high tier), never a learned change. Its object names the tool, its detail (cut at 40 characters on the text) names the irreversible and secret verbs first (anything not Reversible, so an unknown verb too; Security delta on #2049), then the grants and the count of draft-only operations, and its terms, which the gate now forwards to the local page and the item's sum, list every grant and every operation, with the unmapped ones marked draft only. Tool, operation and grant names come from the agent-drafted file and pass through `safe` (a blank name shows as "(unnamed)"). Mutant, by hand: without the adapter branch, `TestADP6AdapterOwnerItemNamesToolGrantsAndOperations` fails with "a learned procedure"; with `c == verb.Irreversible` in place of `c != verb.Reversible`, `TestADP6AdapterSecretOperationIsNamedToTheOwner` fails. | ADP-6, ADP-2 | If the texted line must list every grant, the owner channel needs a multi-line item; today the full list is on the local page. |
