# Follow clerk: assumptions

Built for MIG-4-adapters-f1 (#3429, slice f1 of #2579, brief `briefs/MIG-4-adapters.md`): `broker/follow` keeps the switch, the page's `Describe` and the alert, and the follow clerk is `broker/follow/followclerk`. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-adapters-f1-a | **A switch of update root is `change-account`.** VRB-2's list is closed and has no `follow` verb; the switch is box configuration nobody can undo for the owner, the same reading DEV-4 gives a device's configuration and firmware. So the step is `change-account` on the clerk `follow` (irreversible, high tier), its object (`target`) the digest of the root summary the page showed and its value the owner's name for the source. The kernel refuses an empty argument (`key.ArgsDeclared`), so the switch back carries `followclerk.ArgProject` (the project's own line, `follow.ProjectName`), which `NameOK` refuses as a look-alike, so no named follow can carry it (security 2 on #3444). | VRB-2, KRN-4, DEV-4 | A verb of its own is an L1 spec change plus a `kernel/key` verb; the clerk changes one constant. |
| MIG-4-adapters-f1-b | **Only the owner's own approval of the exact switch runs it.** The clerk takes a plan only under a bare root, which only an owner passkey can sign a use of (KEY-4): the tap on the page signs the plan that names the digest and the name. A plan under any key derived from the root, a clerk or standing key, is refused (`owner`), so KEY-5 never covers a switch here. The root itself is a grant in the log and waits its hold (`kernel.Live`), so it is made at setup or well before the first switch. | KRN-4, CH-10, KEY-4 | If Mark wants a standing key to cover a switch back to the project, the check admits it for the empty name only. |
| MIG-4-adapters-f1-c | **One clock.** The clerk checks the key and judges root expiry on the HOST-1b clock guard's `Latest`. Before the guard runs, `Latest` is the far future (agentosd's `guardClock`), so every key and root reads as expired and nothing is followed. | WF2, CLK-2 | A clerk clock apart from the guard would need its own fail-closed answer before the guard runs. |
| MIG-4-adapters-f1-d | **Probe answers only done or unknown, and alerts again on done.** The kernel fences only an identical step, so a later switch with other args runs while an earlier one is unresolved (security 1 on #3444); the journal's broker-account fence used to hold it. So no reading of the box proves an earlier switch never landed: it may have landed and been replaced, or switched back, or a later approval may already hold (three review rounds on #3444 each found an order a "not landed" rule got wrong). Probe answers done when the box follows the step's root under its name (and re-sends the owner's alert, the at-least-once rule the journal executor's Reconcile kept), and unknown otherwise. A switch that truly never landed and lost its answer parks for the owner's RETRY (KRN-8) instead of being sent again on the clerk's word; that needs a crash mid-switch plus an unreadable store. Nothing runs the clerk and the journal executor in one box: f1 wires neither into the kernel, and f2 deletes the executor when it wires the clerk. | KRN-8, OWN-4 | Recording the idempotency key inside the update store, atomically with the switch, would let Probe prove notdone; that is `broker/update`'s change (#3449). |
| MIG-4-adapters-f1-e | **Look-alike names fold through CH-12.** A name is refused if any `owner.CheckFolds` fold, or its plain lower case, with every character that is not a letter or a digit dropped, matches `owner.FoldPattern("agentosproject")`, so no space, punctuation or split word hides it ("Agent OS-Project"): case, accents, confusable skeletons (Cyrillic and Greek letters, 0 for o) and ignorable characters. A name that merely contains the product name passes ("agentOS Community"). The length, digit and printable rules are the gate's, unchanged. | CH-10, CH-12, #957 | A stricter rule (any "agentos") is one pattern. |
| MIG-4-adapters-f1-f | **The journal executor is gone (f2b1, #3430).** f1 kept `executor.go` (`Execute`, `Reconcile`, `Route`) while agentosd still routed the page's `grants.FollowIntent` through the journal. f2b1 deleted it, ported the journal-driven tests in `follow_test.go` and `rotation_test.go` to `Switch` and `Settled`, and agentosd now hosts the clerk and retires the journal's `update` executor. `TestFollowLinksNoOldCore` holds `go list -deps ./...` free of `journal` and `grants`. | D-111, #2578 | None. |
| MIG-4-adapters-f1-g | **The clerk is its own package.** `followclerk` imports `broker/clerk` for `clerk.Check`, and `broker/clerk` links the network exit (`net/http`, `crypto/tls`). agentosd imports `follow` for the page's `Describe`, and `TestAgentosdLinksNoInference` holds agentosd's graph free of network clients. So the clerk lives apart and `follow` imports no `broker/clerk` (`TestFollowLinksNoOldCore`). f2 hosts the clerk where linking `broker/clerk` is allowed, or moves `Check` to a net-free package, rather than linking it into agentosd. | KRN-2, ARC-2 | f2a (#3430) moves the check path to the net-free `broker/clerk/check`, so `followclerk` now links no network code and agentosd may host it; f2b1 (#3430) hosts it in agentosd; it stays its own package so `follow` itself imports no `broker/clerk`. |
| REV-CHK-names-e | **A source's name refuses invisible text** (#3901). `NameOK` also refuses invalid UTF-8 (which ranged as a printable U+FFFD), default-ignorable characters (Hangul and Khmer fillers, the grapheme joiner) and variation selectors, which `unicode.IsPrint` lets through; `TestNameCheckRefusesHostileText` runs the shared corpus (`broker/internal/hostiletext`). | CH-10 | A name script that needs one of those characters would need an exception at the test. |
