# Follow clerk: assumptions

Built for MIG-4-adapters-f1 (#3429, slice f1 of #2579, brief `briefs/MIG-4-adapters.md`): `broker/follow` keeps the switch, the page's `Describe` and the alert, and the follow clerk is `broker/follow/followclerk`. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-adapters-f1-a | **A switch of update root is `change-account`.** VRB-2's list is closed and has no `follow` verb; the switch is box configuration nobody can undo for the owner, the same reading DEV-4 gives a device's configuration and firmware. So the step is `change-account` on the clerk `follow` (irreversible, high tier), its object (`target`) the digest of the root summary the page showed and its value the owner's name for the source, "" to switch back to the project's own root. | VRB-2, KRN-4, DEV-4 | A verb of its own is an L1 spec change plus a `kernel/key` verb; the clerk changes one constant. |
| MIG-4-adapters-f1-b | **Only the owner's own approval of the exact switch runs it.** The clerk takes a plan only under a bare root, which only an owner passkey can sign a use of (KEY-4): the tap on the page signs the plan that names the digest and the name. A plan under any key derived from the root, a clerk or standing key, is refused (`owner`), so KEY-5 never covers a switch here. The root itself is a grant in the log and waits its hold (`kernel.Live`), so it is made at setup or well before the first switch. | KRN-4, CH-10, KEY-4 | If Mark wants a standing key to cover a switch back to the project, the check admits it for the empty name only. |
| MIG-4-adapters-f1-c | **One clock.** The clerk checks the key and judges root expiry on the HOST-1b clock guard's `Latest`. Before the guard runs, `Latest` is the far future (agentosd's `guardClock`), so every key and root reads as expired and nothing is followed. | WF2, CLK-2 | A clerk clock apart from the guard would need its own fail-closed answer before the guard runs. |
| MIG-4-adapters-f1-d | **Probe reads the box, and alerts again on done.** Probe answers from the update store's trusted root and source, not from what the process held, so it answers the same after any restart (#1372's reading: neither matches means the switch never landed). A done probe re-sends the owner's alert, the at-least-once rule the journal executor's Reconcile kept, because the alert of a switch whose answer was lost may never have gone out; the only cost is a duplicate alert. A `Do` that finds the switch already made answers ok without switching again. | KRN-8, OWN-4 | If a probe must have no side effect, the alert moves to a pending-before-switch write in `Do`, at the cost of an alert for a switch that then fails. |
| MIG-4-adapters-f1-e | **Look-alike names fold through CH-12.** A name is refused if any `owner.CheckFolds` fold, or its plain lower case, matches `owner.FoldPattern` of "agentos project" with or without the space: case, accents, confusable skeletons (Cyrillic and Greek letters, 0 for o) and ignorable characters. A name that merely contains the product name passes ("agentOS Community"). The length, digit and printable rules are the gate's, unchanged. | CH-10, CH-12, #957 | A stricter rule (any "agentos") is one pattern. |
| MIG-4-adapters-f1-f | **The journal executor stays until f2.** `cmd/agentosd/follow.go` registers `follow.Route` as the journal's "update" executor, and agentosd edits run in the serial slot (D-111), which #3403 holds. So `executor.go` keeps `Execute`, `Reconcile` and `Route` over the same switch code the clerk uses (`Executor.Switch`, `Settled`), and is the only file in the package importing `journal` or `grants` (`TestOnlyTheExecutorImportsTheOldCore`). f2 (#3430) wires the clerk, deletes `executor.go` and the journal-driven tests in `follow_test.go` and `rotation_test.go` (porting their rig), and then `go list -deps ./follow/...` lists neither. | D-111, #2578 | If f1 and f2 merge as one PR, the deletion moves here. |
| MIG-4-adapters-f1-g | **The clerk is its own package.** `followclerk` imports `broker/clerk` for `clerk.Check`, and `broker/clerk` links the network exit (`net/http`, `crypto/tls`). agentosd imports `follow` for the page's `Describe`, and `TestAgentosdLinksNoInference` holds agentosd's graph free of network clients. So the clerk lives apart and `follow` imports no `broker/clerk` (`TestOnlyTheExecutorImportsTheOldCore`). f2 hosts the clerk where linking `broker/clerk` is allowed, or moves `Check` to a net-free package, rather than linking it into agentosd. | KRN-2, ARC-2 | If `clerk.Check` moves to a net-free package, `followclerk` can fold back into `follow`. |
