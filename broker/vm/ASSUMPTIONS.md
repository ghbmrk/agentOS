# Agent-machine lifecycle: assumptions

Built for PLAN P1-4 against SPEC v0.12 (PR #15) on the broker skeleton
(PR #19). Each row is a reading of the spec, or a gap left for a later
package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| V1 | A machine is a read-only image plus a host overlayfs upper layer, served to gVisor with gVisor's own overlay off (`--overlay2=none`). gVisor's internal overlay keeps writes in an opaque file, so the broker could not snapshot files without a full checkpoint. | REV-1, ARC-5, S3 | Firecracker (if it wins on the N95) needs a block-device layer instead; only `vm/gvisor` and `vm/overlay` change. |
| V2 | Per-step snapshot = pause, copy the upper layer (reflink where the file system has it, otherwise extent by extent so holes stay holes, hardlinks kept), resume. Full checkpoint = the same plus `runsc checkpoint` while paused, so files and memory match. `runsc pause` does not flush the sentry's dirty pages of files the guest has mmapped, so a file-system snapshot can miss mmapped writes not yet synced; a full checkpoint holds them in memory. | REV-1 | Sync before copying if a guest workload depends on it. |
| V3 | "Step" is whatever calls `Manager.Step`. The guest plane (P1-7) calls it after each broker tool call, on the machine that made it; a failed Step is logged and does not fail the tool call (G4). | REV-1 | — |
| V4 | Rollback is allowed to the machine's own snapshots and to the snapshot it was forked from, nothing else, so a machine cannot load another machine's data. | REV-4, REV-5 | `inLineage`. |
| V5 | `fork(n)` is all or nothing: every fork is admitted on its own full budget (forks share no memory, S3) before the source is checkpointed. Forks keep the source's class. | REV-4, CAP-1, RES-2 | `Manager.Fork`. |
| V6 | `merge` is a three-way file merge of a fork back into the machine it came from, against the fork point. Any path both sides changed differently is a conflict and nothing merges. A directory one side removed or retyped while the other side changed something beneath it is a conflict too. Before merging, the destination gets a full checkpoint, so the owner can undo the merge with memory intact. Ownership and guest xattrs (e.g. file capabilities) count as changes. The merged machine restarts on the merged files (a file-system rollback), so its memory is not kept. Keep-the-winner (CAP-1) needs no merge: keep the fork, destroy the rest. | REV-4 | A live in-guest merge would need guest cooperation (P1-7). |
| V7 | Data labels (REV-5) are tracked here because snapshots carry data: a label only rises; rollback, rebuild and merge never lower it; forks inherit it; reading a diff raises the reader to the snapshots' label. Egress enforcement is not here. | REV-5 | REV-5 package. |
| V8 | Preemption (RES-1) pauses the guest, kills it, and returns once its cgroup is empty, which is what `admission.Preempter` requires (memory released). Nothing is copied on that path, so its time does not depend on what the guest wrote. The machine's layer stays on disk and `Resume` restarts the machine on it (cold). In-memory state since the last full checkpoint is lost. Checkpointing memory first would cost 2–4.5 s for an OpenClaw-sized guest (S3), too slow for a call. Preemption does not wait for an operation holding the machine; target and measurement: P2-5 (budget/ASSUMPTIONS.md R5, R6). | RES-1, LOOP-1 | Checkpoint-then-kill as an option once the target is frozen. |
| V9 | A preemption that lands between a machine's admission and its start withdraws the admission; the machine does not start (`ErrRevoked`). | RES-1 | — |
| V10 | Every machine runs in its own cgroup v2 group: `memory.max` is the declared budget, `memory.high` is 1/16 below it (throttle before the stall S3 measured), swap is 0. The manager refuses to open without a cgroup parent unless told it is a test. | RES-2 | `cgroup.Child`. The 1/16 margin is unmeasured. |
| V11 | PSI comes from the machine parent group's `memory.pressure` (else `/proc/pressure/memory`). If PSI worked and then fails, it reads as +Inf, so only foreground is admitted. A host with no PSI at start-up admits on the budget alone. `-max-pressure` defaults to 10 % (unmeasured; size on the N95). | RES-2 | Flag. |
| V12 | ARC-2: the control-path packages still cannot start processes. `agentosd` (the composition root) opens the machine plane and hands it to admission as a `Preempter`. Only `vm/gvisor` starts a process, and only the configured runsc (`TestOnlyRunscIsExecuted`). | ARC-2 | `daemon/arc2_test.go`. |
| V13 | Broker restart: machines come back `stopped` with layers and snapshots intact; leftover sandboxes are killed. `Resume` restarts from the newest snapshot. | ARC-4 | — |
| V14 | Destroy keeps a machine's snapshots until pruned by policy (`prune.go`, budget R10). | RES-4 | `PrunePolicy`. |
| V15 | Each machine gets its own broker services directory, `Config.Services`, mounted read-only at `/run/agentos` with gVisor's `--host-uds=open`; the sandbox has no other network. The directory is opened before every start or restore and closed on destroy. A fork gets its own directory; a connection it inherits from its source reads EOF after restore and never speaks for the source (integration tests). `--host-uds=open` is sandbox-wide, but a host socket file planted in the image is not reachable from the guest (`TestIntegrationHostSocketInImageIsUnreachable`); P2-1's image build should still assert the image holds no socket files. Each machine's lineage (OP-1) is its root's ID plus a creation nonce, so a reused ID gets a new one; `DataLabel` gives egress a fail-closed label. | ARC-6, REV-5, OP-1 | — |
| V16 | Layer paths are resolved beneath the layer root without following any symlink; a path under a symlink or other non-directory is absent, as for the kernel overlay. An image symlink to a host path (Debian's `/var/run -> /run`) never leads a diff, merge, or copy into the host. | REV-1, REV-4 | — |
| V17 | Layer copies keep only regular files, directories, symlinks, and 0/0 whiteouts; anything else (device nodes, FIFOs, sockets) fails the snapshot with the path named. Of overlayfs's xattrs only a valid opaque marker is kept; redirect, metacopy, and origin are dropped, and machine roots mount with `redirect_dir=off,metacopy=off,index=off`. Setuid bits and owners are kept because guests need them (REV-1), and are inert on the host because of V18. | REV-1, ARC-5 | — |
| V18 | Machine roots mount `nosuid,nodev` and are made private right after mounting. That cannot stop the mount event itself from reaching peers when the state directory sits on a shared mount, so `agentosd` must run in its own mount namespace (systemd `PrivateMounts=yes`), where mounts do not propagate to the host. The broker's state directory (layers and snapshots) must be on a file system mounted `nosuid,nodev` (P2 image build). | ARC-5, CRED-2 | P2 host image: unit file. |
| V19 | Snapshots are admitted against measured disk, as memory is (arbitrator ruling on #23): a snapshot is taken only if copying the machine's layer (allocated bytes; holes and hardlinks cost nothing extra) leaves the state disk's RES-4 reserve free (`-disk-reserve-mb`, default 2 GiB, unmeasured), with an optional per-machine byte cap and a 200,000-inode cap. Otherwise the step is refused with a "disk budget" error the guest can act on (delete files, roll back) and nothing is truncated or dropped. The guest is not stopped from writing; a host file-system quota would do that. | RES-4, REV-1 | Size the reserve on the N95 (P2). |
| V19a | Every copy is reserved against the same budget before it starts, not only snapshots: a full checkpoint counts its layer plus the machine's whole memory budget; fork(n) reserves n copies of the layer before checkpointing and holds them until every fork has started; a merge reserves the merged layer and dst's restart before checkpointing dst; a rollback reserves its restore before stopping the machine. Reservations are serialized and held ones count against later checks, so concurrent copies cannot together eat the reserve. A refusal leaves machines running as they were. While a copy runs its bytes count twice (used and held), an overestimate. | RES-4 | — |
| V20 | CI's gVisor is pinned by SHA-512, trust on first use from the same origin; it is not a signature check. | DEP-1 | Verify the release signature when the P2 image vendors runsc. |
| V21 | Known gaps: a `Preempt` whose kill fails leaves the machine stopped while admission still counts it, until it is destroyed; `Manager.Diff` with an empty requester (broker or owner callers only) raises no label. | RES-1, REV-5 | Small. |
| V22 | Every machine's cgroup has `memory.oom.group=1`: an OOM kill takes the whole machine, never part of it. | RES-2 | — |
| V23 | runsc writes each machine's `console.log` directly, so the broker rotates it only when the machine starts (above 4 MiB, one old copy kept). A guest that floods the console while running grows it until its next start; the V19 reserve and the state disk's monitoring cover that. | RES-4 | Pipe the console through the broker with a cap, with the P1-7 guest. |
| V24 | `CreateSeeded` writes broker-chosen files into a fresh machine's layer before its guest first runs (root-owned 0644, local clean paths only), admitted against the disk budget and the layer byte cap like any copy. This is how a replay hands its guest the tree under evaluation. The seed is held in memory: a rebuild writes it again, but a broker restart forgets it. IDs starting `eval-` are kept for replay machines: `Create` refuses them, `Fork` neither forks nor makes one, and `Rollback` and `Merge` refuse them. Every write of a seed (create, rebuild) reserves the disk first. A non-empty seed needs a private machine (`ErrSeedLabel`): the managed tree is derived from owner tasks and no file carries a public mark yet (compile K7); forks inherit the label. | LOOP-5, RES-4, ARC-6, REV-5 | A public mark on seed files lets a public machine take a seed whose every file came from a public candidate. |
| V25 | A snapshot taken while a preemption begins is discarded with `ErrPreempted`: Preempt marks the machine before it kills the sandbox, and `capture` checks the mark after the copy and checkpoint return, before it writes `meta.json`. A runtime that reports success on a killed sandbox therefore never publishes a truncated image, and a mark not seen means the kill came after the image was whole (Security R2 on #124). A snapshot whose resume then fails is withdrawn as well, so a snapshot operation that returns an error never leaves a published snapshot (#134 CI). | RES-1, REV-4 | `Manager.capture`, `takeLocked`. |
| V26 | **Deletion reach (CAP-3).** `ForgetSince(lineage, T)` takes back from a fork lineage what it may hold since T: each machine goes back to its newest usable snapshot taken before T (memory too from a full checkpoint; a stopped or preempted machine gets the layer on disk and stays stopped), or to a fresh layer from its image when none exists; then every snapshot of the lineage taken at or after T is deleted, those of destroyed machines and fork points included (metadata first, so a crash part-way leaves an unpublished directory `Open` drops). Snapshots now record their lineage; an older one whose machine is gone is deleted when taken at or after T, whatever its lineage. Labels do not fall. Known gap: a machine of another lineage that read a lineage snapshot through `Diff` is not reached. A repeat after success rolls back work done since; recall's reach records the reset and does not repeat it. A snapshot is dated when its capture completes, not when it starts, so a record handed to the machine during the capture cannot land in a snapshot dated before it (#59 L3 3). `ResetPlan` measures, without changing anything, the oldest restore point and the files changed since it (overlay `Diff`; memory not measured), which recall counts as work to ask about (recalltool W10). A running machine restarts on reset, opening its services again, so its unanswered owner messages are handed out again (guest G5). While `Config.Contained` reports a lineage (it holds a record the owner deleted, asked or unanswered), its machines are not forked or merged (`ErrContained`). | CAP-3, REV-4, REV-5 | — |
