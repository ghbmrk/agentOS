# clerk/codecheck: assumptions

Built for MIG-4-exit-c2 (#3683, `briefs/MIG-4-exit.md` section c2, D-226), with `cmd/agentos-checker`. This package carries the old `checker`'s rows C-2 and C-6 into the new core. C-1, C-3, C-4 and C-7 fall with the redeem side. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-exit-c2-lib-1 | **A new path, not `broker/checker` rewritten in place.** `tools/trace.py --ratchet` lets `broker/checker` leave `tools/old_core.txt` only in the PR that deletes its old files, and `holder`, `cmd/agentos-holder` and `cmd/agentos-egress` (old core, deleted by d1 and d2) still link `checker` and `checkersock`. So the process D-226 keeps (`cmd/agentos-checker`) moves onto this package, and the old package stays frozen until d2 deletes it with `holder` (settled on #3683). | D-226, D-139 | If d2 lands first, nothing here changes, and the old package goes. |
| MIG-4-exit-c2-lib-2 | **The seed comes only from the unlock step's sealed hand-off.** `Open` takes `handoff.OpenCodeSeed`'s file, opened under the sealer of the clerk key the kernel hands the checker, plus that key's signer. A checker never opened verifies nothing (`ErrNoSeed`, HTTP 503), so the owner channel can tell "codes are off" from a wrong code. A failed open leaves no seed and no key. | CLK-1, STO-2 | — |
| MIG-4-exit-c2-lib-3 | **A verified code signs one approval of exactly the steps it was given, and keeps nothing.** The approval is `kernel.SignCode` under the clerk key's signer, which the kernel pins from the same derivation (`proc.CheckerPin`). The kernel checks each step is held, named once, of the plan bytes named, and not a secret one (c1). The checker sees no plan, so the old C-5 gap stands: an agentosd taken over that gets a fresh owner code can name other held steps within the code's step. The kernel still admits only held, non-secret steps under keys that cover them (KEY-4, VRB-1). A code with no steps (a session's, CH-14) approves nothing. | CH-4, CH-10, KEY-4 | A content-bound code (the paper grid, CH-18) closes the gap for its cells. |
| MIG-4-exit-c2-lib-4 | **Lockout and spent steps as before.** Codes are checked by `totp.Match`, which is RFC 6238 and is tested equal to the owner channel's check over a day of steps without linking `owner`'s text parsers. Counted and silent buckets hold 20 and 10 wrong codes per 10 minutes and pause per bucket. The step is on disk (`privfile.WriteAtomic`) before the answer. The step setup's confirming code spent comes with the seed and is spent here too. | CH-4, O6 | — |
| MIG-4-exit-c2-lib-5 | **One socket, one caller.** `verify.sock` serves `POST /verify` alone, for the owner channel's uid (`sockets.ListenPeers`). The binary refuses to run as that uid, makes itself non-dumpable, and refuses a key that is not from a pipe or socket naming `checker`. It refuses a seed file read through a link, or one that is not a regular file. | ARC-1, CLK-1 | — |
