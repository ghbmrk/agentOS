# clerk/readerwire assumptions

Built for MAIL-reader-sock-a (#3421, briefs/MAIL-reader-sock.md). Each row is a reading a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MAIL-reader-sock-a-1 | **Only the canonical encoding of a call or an answer is read.** Each end decodes a line and refuses it unless `encoding/json` encodes the value back to exactly the same bytes, so another key case, an unknown or duplicate key, other spacing or another escaping is refused rather than read. Both ends are this package, so the canonical form is the only one either sends. Any byte after the line's newline is refused too. | D-154 rule 1 | A reader in another language would need the same encoder, or a stricter decoder here. |
| MAIL-reader-sock-a-2 | **A reply past the bound fails only that mail; a reader failure pauses every mail for a minute.** The mail can steer the model's reply, so the reader answers a reply over 64 bytes, or one that escaping grows past the 256-byte answer, as `too-large`, which the mail clerk does not count as the reader's failure; a lying reader's over-long or malformed answer is refused the same way. A dial error, a wrong uid, the reader's own deadline, a lost answer, `unavailable` or `refused` pause the next calls for 60 s, with nothing dialled. A deadline or cancel of the caller's own context does not pause. | PLN-2, brief item 2 | If a mail can make the model clerk itself fail (a provider refusing its text), that mail pauses the read each time it is asked: slice b's model function should answer such a refusal per call, not as `unavailable`. |
| MAIL-reader-sock-a-3 | **The model function ends at the connection's deadline.** `Serve` gives each call a context with the connection's 60 s deadline and runs at most eight at once (row RES-5-readerwire-maxconns-1); a model that ignores its context holds its slot until it returns, though the mail clerk's own deadline ends the call on its side. Slice b's model function is one socket call under that context. | brief item 4 | Run the model in its own goroutine if a model function cannot honour its context. |
| MAIL-reader-sock-a-4 | **`Serve` checks no uid itself; `Listen` does.** The peer check is `sockets.ListenPeers`, so `Serve` on a listener from anywhere else admits any peer. `cmd/agentos-reader` (slice b) uses `Listen`. | D-154 rule 2 | none |
| RES-5-readerwire-maxconns-1 | **`maxConns` = 8 calls at once; the ninth is answered `busy` at once, unread, and never queued.** The basis is the caller's demand, not the box: `Listen` admits only the mail clerk's uid, and the mail clerk asks one call at a time (`inbox.Read` loops over the mails in order, and `MailHost.refresh` runs one read at a time), so a working mail clerk holds one slot. The other seven hold only calls whose caller went away while the model still runs: `Serve` does not see a hang-up, so such a call keeps its slot until the model returns, at most `serveTimeout`. A caller's own deadline pauses its dialer for `pause` (= `serveTimeout`), so its orphan is gone before it calls again; only a caller whose context ended (a mail clerk stopping) leaves one without a pause, so 8 absorbs seven mail-clerk restarts within one `serveTimeout` (its unit restarts no faster than every 2 s, `agentos-keeper-mail.service`). A slot costs one goroutine, a 4 KiB read buffer, the call line (at most `maxCall`, about 32 KiB) and its decoded prompt (at most `MaxPrompt`), so eight cost under 1 MiB: memory does not bind, and the cap bounds only the model calls a looping mail clerk can hold open. Spend is not bounded here: the model clerk meters and admits each call (LOG-7, RES-5). A full reader pauses the dialer like a failed one, because with one caller only orphans can fill it, and they end within `pause`. | RES-5, D-154 rule 4 | If the mail clerk ever reads in parallel (more accounts per clerk, or a parallel `inbox.Read`), the cap becomes that parallelism plus the orphan headroom, and busy should stop pausing. If `Serve` learns to end a model call when its caller hangs up, orphans vanish and the cap can fall to the caller's parallelism. |
| RES-5-readerwire-maxconns-2 | **Every other fixed bound in the package, and its basis.** `MaxPrompt` (24 KiB) is at least `inbox.MaxPrompt` (the question plus 16 KiB of mail), which `agentos-clerk-mail`'s test checks. `MaxReply` (64 bytes) holds the longest class word (`phishing`, 8 bytes) eight times over. `maxCall` and `maxAnswer` follow from those: the base64 prompt plus the frame, and a 64-byte reply's encoding with room to spare (an escape that grows past it is refused, row MAIL-reader-sock-a-2). `DefaultTimeout` and `serveTimeout` (60 s) are one model call's deadline, and `pause` (60 s) equals `serveTimeout` so a pause outlasts any call still running. `acceptBackoffMin` (5 ms) and `acceptBackoffMax` (1 s) pace the accept loop's retries after a failed accept (out of descriptors), doubling from one to the other, as `net/http` does. None is a concurrency cap but `maxConns`. `TestEveryBoundIsRecorded` reads every non-test file in the package and fails on a constant not named in this row or the last (a mention elsewhere does not count), and on any number but 0 or 1, any rune but the frame's newline, any time unit, or `time` imported under another name, written outside a const. Only the frame's own names, version and opRead at the top of `readerwire.go`, are exempt (unquoted here, so they never count as recorded bounds). `TestAcceptBackoff` pins the backoff's doubling, cap and reset. | RES-5, PLN-2 | Raise `MaxPrompt` with `inbox.MaxPrompt`; the rest change only with the frame. |
