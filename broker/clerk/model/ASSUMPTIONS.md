# Model clerk: assumptions

Built for MIG-4-spend (#2572, D-139 step 4). Covers `broker/clerk/model` and the metering in `broker/kernel` (`model.reserved`, `model.used`, `Kernel.AdmitSpend`, `Kernel.Meter`, `key.Verified.Spend`). Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-spend-a | **A model call is metered usage, not a plan step.** The verb list is closed and a model call is not an effect, so it is charged to the key the plan cites by a `model.used` entry. The plan must be active; the caller names only the plan, and the key and the task (the plan ID) come from it or its latest extension, never from the caller. | VRB-2, HLD-2, LOG-7 | A plan-step model call would add a verb, which the spec forbids. |
| MIG-4-spend-b | **One check, one mechanism.** `Verified.Spend` (live, spend caps hold for `amount` more) runs in `AdmitSpend` before a call. `Meter` records what happened and does not re-run it. Rate and use caps count steps, not metered usage, so `caps` skips them for `Spend` (`spendOnly`); no flag rides on `Use`. | KEY-2, LOG-7 | Counting calls would be a `rate` cap read over `Meter` uses. |
| MIG-4-spend-c | **Usage that happened is always recorded**, even past a cap, after the plan ended or after its key was revoked mid-call, so the next admission sees it: `Meter` charges the key and scopes the call was admitted under, from its reservation. Only a Meter that cites no open admission of that plan (`ErrNotAdmitted`) records nothing, so an admission settles once. | LOG-7 | Refusing the record would hide spend from the caps. |
| MIG-4-spend-d | **Admission uses the worst case** (the prompt's tokens plus `maxOut`); the record uses the provider's figure, else the clerk's own count at four bytes a token. Cost rounds up. | LOG-7 | A real tokenizer replaces `tokens`. |
| MIG-4-spend-e | **Calls run at once; the kernel's reservations keep them inside the caps** (#2613 item 1). `AdmitSpend` logs the call's worst case (`model.reserved`), which counts against every cap until `Meter` settles it with what was used (`model.used` cites it). The clerk's lock covers only its owed log writes, never the provider call. A call refused only because calls still in flight fill a cap is `in-flight` and holds nothing; one that cannot fit even once they settle is refused by the cap and holds the plan (MIG-4-spend-b1). A request that never left settles at 0. An admission never settled (a crash mid-call, or an `admitspend` answer lost on the socket) stays charged at its worst case. If it alone fills a cap, later calls are refused `in-flight` and nothing holds the plan, so the owner cannot extend it: the plan fails closed, with no overspend, and makes no further call that cap would carry. A pool route admits on its last reading with no reservation, so calls admitted at once can each pass before any reading lands: the reserve can be overshot by the calls in flight, not by more. | KRN-1, LOG-7, RES-5 | A settlement of stale admissions at their worst case, which makes such a plan holdable and extendable, is #2731. |
| MIG-4-spend-f | **A model key is issued for clerk `model` with the verb `read`.** Roots need a verb; `Spend` ignores verbs. | KEY-2 | A verbless root would be a key-format change. |
| MIG-4-spend-g | **Spend never goes unmetered and is never negative.** `Meter` and `Spend` refuse a negative amount; `Price.cost` uses checked arithmetic and refuses negative tokens or prices and overflow, so no call is admitted or metered below its cost. Usage a provider reports is metered as reported (source `provider`), whatever error comes with it, `ErrNotSent` included; a request that provably never left (`ErrNotSent` with no figure) meters 0; any other error, an unusable figure or a failed cost meters the admitted worst case (source `admitted`). If `Meter` fails, the unrecorded spend is kept in memory as one owed write per call, the reply is withheld and the clerk makes no further call until the log records it. A restart loses the pending entries; the next call is admitted against the log as it stands. | LOG-7, CLK-7 | A provider that reports failed-call usage could meter less than the worst case. |
| MIG-4-spend-h | **Not here:** paid API calls and purchases through other clerks, and spare-class draw (HLD-4). They build on `Spend` and `Meter`. | LOG-7, HLD-4 | Each is its own row. |

## MIG-4-spend-b: holds, extensions, pools

Adds `spend.held`, `spend.extended`, `pool.read`, `pool.reset`, `pool.reserve.raised` and `pool.reserve.lowered` to the log, and `Hold`, `Extend`, `ReadPool`, `Reserve`, `AdmitPool` to the kernel.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-spend-b1 | **A refused spend cap holds the plan**, not only a fully used one. A call whose worst case does not fit means the plan needs more budget; the owner extends it, and a smaller retry is not a way around the hold. | LOG-7 | Holding only at zero left would need a minimum-call rule per route. |
| MIG-4-spend-b2 | **An extension is a derivation of the owner's envelope, not a new caveat kind, and a held key cannot release itself.** `spend.held` records the cited key's root and the key that was funding the plan; `Extend` refuses any extension under that root or whose chain contains that key (so a key funded by an earlier extension cannot release itself either), one with no per-task cap in its chain, or without room left. The envelope's caps sit in a shared chain prefix, so every extension is charged to them and none passes them. | KEY-4, LOG-7 | A per-extension ceiling would be a new cap kind. |
| MIG-4-spend-b3 | **Equal caveats derive the same key**, so two extensions with the same cap are one key and share its cap. Distinct caps give distinct keys. | KEY-4 | Per-grant serials would be a key-format change. |
| MIG-4-spend-b4 | **Owner authentication is outside the kernel**, as for every owner action: the channel authenticates the passkey or text, the kernel records. `Extend` of a held task is itself the grant. | KEY-4, KEY-6 | The kernel would verify an owner signature over the extension. |
| MIG-4-spend-b5 | **A pool is per mille, and the reserve defaults to 0.** `pool.read` records the provider's utilization and reset time. A pool admits while `used + reserve < 1000`. A reading can only narrow: it never reopens a closed pool. Reopening past the reset time (the cooldown) is the logged widening `pool.reset`. A full reading with no reset time, or one already past, falls back to the pool's declared window `PoolWindowMS` (5 hours, the shortest window RES-5 names), so a pool is never closed for good by a missing figure. | RES-5, CLK-7 | Percent, or a forecast-based draw, changes `PoolOpen` only. |
| MIG-4-spend-b6 | **Raising a reserve narrows (a text), lowering widens (the passkey).** Two entry types let `Widening` stay typed by entry type, so a restart honours a lowering only when an anchor covers it. | KEY-4, KEY-6, KRN-7 | One entry type needs `Widening` to read the body. |
| MIG-4-spend-b7 | **A held plan is refused by `AdmitSpend` itself** (`held`), so a clerk never makes a call for it and never re-holds. | LOG-7 | A clerk-side check would duplicate the kernel's. |
| MIG-4-spend-b8 | **`Widening` lists `spend.extended`, `pool.reset` and the reserve lowering**: each loosens a limit, so a restart keeps one only when an anchor covers it (KRN-7). | KEY-4, KEY-6, KRN-7 | A narrowing-only extension would not need the anchor. |
| MIG-4-spend-b9 | **One pool per route; a model-specific pool is its own route.** A provider meters one subscription per credential, so a route draws on one pool. RES-5's model-specific weekly pool (one model on a plan) is a second route for that model, drawing on its own pool; the clerk checks the route's one pool, and the owner's route order (PLN-3) sends the call to the first route whose pool is open. | RES-5 | A `Pool` list on `Price` and an admit over all of them; revisit if a run must draw on two pools at once. |
| MIG-4-spend-b10 | **Spend is authorized by the funding key's spend caveat, whatever clerk the key was issued for.** A key with no spend cap funds nothing. A plan under a mail key with a cap makes a capped model call. | LOG-7, KEY-2 | Requiring the key's clerk to be `model` would make mail plans unable to call a model. |
| MIG-4-spend-b11 | **Spend is charged to a key the log already vouches for.** `AdmitSpend`, `Meter`, `Hold` and `Extend` take the plan's key (held when `VerifyPlan` admitted the plan) or an owner-granted extension through `key.Chain`, which checks the chain without a holder signature. A `Verified` from `Chain` can be charged but `Authorize` refuses it, so it moves no step. | LOG-7, KEY-1 | A model clerk holds no holder secret; asking it to sign would put the planner's secret in the exit. |
| MIG-4-spend-b12 | **A plan is spent under its own key as well as its funding key.** After an extension `AdmitSpend` and `Extend` still require the cited key to be live (not paused, revoked or expired, no stop), so an owner who pauses a key stops its plan. A rejected plan is metered and held under nothing. `Extend` and `Reserve` go through `owner`, so a widening is anchored at once and a failed anchor refuses it. | KEY-6, LOG-7, KRN-7 | Without it a pause reached only unextended plans, and an extension or lowered reserve was lost on restart. |

## #2613: paid replies and unbilled errors

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-spend-p1 | **A paid reply is kept when only its pool reading fails.** Once the call is metered, a reading the log refuses (a figure outside 0..1000, or a closed pool refusing a lower reading after the owner raised the reserve mid-call) is recorded as a full pool at its reset time, since a reading can only narrow. A reading the log cannot write is an owed write like unrecorded spend: the reply is returned, no further call is made until the log records it, and the retry writes the provider's figure (full only if refused). A missing or past reset time becomes the declared window from the call, and an owed reading whose reset time has passed is dropped, so the pool never closes for a fresh window after it has reset. A failed meter still applies the call's reading. Like owed spend, an owed reading is kept in memory only: after a restart, calls are admitted against the pool as the log stands until the next reading. | RES-5, LOG-7, CLK-7 | Withholding the reply loses work the owner paid for; dropping the reading leaves a pool open past the reserve. |
| MIG-4-spend-p2 | **Provider adapters decide what an error costs.** An adapter returns `ErrNotSent` only when no byte of the request was written (a refused connection, a failed lookup), and an error the provider does not bill (an unbilled overload or server error) with a `Reported` zero; any other error is charged the admitted worst case, so an outage would hold plans. No adapter exists in this package yet: each one, and its test per case, comes with the wiring step that replaces `broker/meter` (#2613 items 3 and 10). | LOG-7, RES-5 | An adapter that cannot tell would leave the worst case, which fails safe for the caps. |
