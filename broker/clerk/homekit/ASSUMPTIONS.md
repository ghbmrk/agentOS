# Assumptions: HomeKit (HAP) controller and clerk (DEV-homekit parts a and b1, #3291, #3331)

What the package rests on. Brief: `briefs/DEV-homekit.md`; decision D-182.

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| HK-1 | **No Go HAP controller is reusable.** `github.com/AlexxIT/go2rtc/pkg/hap` (MIT, active) takes the controller key as raw bytes (`ClientPrivate []byte`), so the key could not stay behind a holder, and it ships inside a large application module; `github.com/MrEhbr/hc` (Apache-2.0) was last published in 2020 as a fork of the archived `brutella/hc`; `brutella/hap` is accessory-side only. The controller here uses the standard library (`crypto/ed25519`, `crypto/ecdh`, `crypto/hkdf`, `crypto/sha512`) and the vendored `golang.org/x/crypto/chacha20poly1305`. | DEV-1, CLK-1 | A maintained controller that takes a signer: replace `pair.go` and `frame.go` with it and keep the tests. |
| HK-2 | **SRP-6a is the one hand-written primitive.** RFC 5054's 3072-bit group, g = 5, SHA-512, user "Pair-Setup"; k = H(N ‖ PAD(g)), x = H(s ‖ H(I ":" P)), u = H(PAD(A) ‖ PAD(B)), K = H(PAD(S)), M1 = H(H(N) xor H(g) ‖ H(I) ‖ s ‖ PAD(A) ‖ PAD(B) ‖ K), M2 = H(PAD(A) ‖ M1 ‖ K), with PAD = 384 bytes. B with B mod N = 0, a B longer than the group, u = 0 and a salt that is not 16 bytes are refused. | DEV-3, DEV-10 | A real accessory that hashes unpadded values fails pair-setup with a proof error; part c shows it, and the encoding changes here with a new vector. |
| HK-3 | **The SRP vectors come from an independent second implementation, not aiohomekit (deviation from the brief).** Executing the downloaded aiohomekit package was refused, so `testdata/gen_srp_vectors.py` (Python standard library only, run with `python3 -I`) computes them; each formula in it was checked against aiohomekit 4.0.1 `aiohomekit/crypto/srp.py` read as text only, and agrees, including aiohomekit's fixed k constant. Two implementations in two languages agree; neither is an accessory. | DEV-3 | If aiohomekit's output differs, regenerate with it and fix whichever formula disagrees. |
| HK-4 | **The key holder signs; this package never sees the private key.** `KeyHolder` gives a pairing ID, the public key and signatures. The clerk uses `SealedKey` (HK-13). `MemoryKeyHolder` is for tests; it prints and marshals no field and keeps the key inside a signing function, not a field, so no `fmt` verb on any struct holding it reaches the key (#3325 item 4). | CLK-1, DEV-4, A16 | A holder that cannot sign in-process: the interface stays, the signer moves. |
| HK-5 | **One attempt per call.** `PairSetup` never retries, so the accessory's own try counter (HAP: 100, then MaxTries until reset) counts only the owner's attempts. A wrong code returns `ErrAuthentication` and the zero `Pin`. | DEV-10 | None known. |
| HK-6 | **Identity is the pinned key and ID.** pair-verify checks the accessory's signature over both ephemeral keys with the pinned LTPK and the pinned pairing ID; either differing is `ErrIdentity`, the connection is closed and nothing else is sent. Part b turns that into the KRN-7 line and the owner re-pin. | DEV-3 | None known. |
| HK-7 | **Every target heating/cooling state write is `actuate-physical`, by choice.** DEV-5 would let turning heat off be a secure direction; the brief makes every value (off, heat, cool, auto) need the code-generator code (CH-10), because any change can stop heating (frozen pipes, an occupant at risk) or start a heat or cool source, so neither direction is safe to cover with a standing key. This is stricter than DEV-5 on purpose. | DEV-4, DEV-5, CH-10 | If the owner wants "off" covered by a key, that needs the kernel table to name a secure direction for this row, and a decision. |
| HK-8 | **Rows are data.** `ThermostatRows`, `AdminRows` and `ClassFor` are the HomeKit Thermostat rows for the kernel-shipped table (DEV-4); the session does not consult them. Setpoints inside the owner's confirmed bounds are `actuate` with the prior value as inverse; outside, or with unconfirmed bounds, `actuate-physical`; display units are `change-account`; anything unmapped reads as `read` and writes as `actuate-physical`. | DEV-4, DEV-5 | The kernel table takes a different shape: convert the rows, keep the test. |
| HK-9 | **Writes keep to the resolved shape.** A write names a resolved `aid`/`iid` with `pw`, a bool or number in the characteristic's format, inside `minValue`/`maxValue`, on `minStep` from `minValue`, and in `valid-values` when given; anything else is `ErrRefused` before a byte is framed. String, data and TLV8 writes are refused. `c#` changing re-resolves `/accessories`. | DEV-4, CLK-3 | A thermostat needing another format: add it to `checkValue` with a test. |
| HK-10 | **Bounds on accessory input.** A 1xx interim reply is refused (#3325 item 7). TLV8 at most 4 KiB and 16 items, fragments joined only after a full 255-byte fragment, repeated types refused; HTTP lines at most 1,024 bytes, 32 headers, bodies at most 256 KiB by length or chunks, no body without a length, no redirects; frames 1 to 1,024 bytes; `/accessories` at most 150 accessories, 64 services and 64 characteristics each; at most 1,024 events while waiting for one response. The first framing or transport error ends the session. | RES-1, KRN-2 | A larger bridge: raise the caps with a fuzz run. |
| HK-11 | **Timeouts and reach.** The package works on an `io.ReadWriter`. `Options.Timeout` sets a deadline on each session round trip when the connection takes deadlines, and the clerk sets one on each pairing step (`DefaultTimeout`, 30 s); an accessory that misses it ends the session. `Close` closes the connection before taking the session lock, so a blocked read ends at once with `ErrClosed` (#3325 item 3). The host (part b2) dials only the pinned address and port; the enforcer drops the vendor-cloud traffic (enforcer rules row). | DEV-1, NET-2, RES-1 | A real accessory slower than 30 s at pair-setup: raise `Clerk.Timeout`. |
| HK-12 | **The synthetic accessory is in-test.** `accessory_test.go` builds a thermostat from this package's codec and an SRP server written there, instead of vendoring `brutella/hap` and its dependency tree (`brutella/dnssd`, `go-chi`, `xiam/to` and more) for tests. It shows the controller against the protocol notes, not against a real thermostat; part c does that. | DEV-1, HLD-3 | A disagreement on a real thermostat: record the exchange (keys replaced by canaries) as a test here. |
| HK-13 | **The controller key is lent, not held** (part b1). Its 32-byte seed is sealed in the static slot `device/homekit/controller`; `NewControllerKey` draws it and wipes it once the host's `Secrets.Put` returns. `SealedKey.Open` is `clerk.Secrets.DeviceKey(ControllerSlot)`, unchanged from #3299: each `Sign` opens the seed for one call, expands it, signs, and wipes both, so the key is in core memory only while one signature is made (short of copies the Go runtime and `crypto/ed25519` make). Only the public half is cached. `SealedKey` has no field holding key bytes. | CLK-1, STO-2, A16 | A TPM-backed sealer replaces the AES one behind the same `Secrets`. |
| HK-14 | **The pin store, and who changes it.** The clerk keeps each device by the owner's name: its pin, an off flag and its setpoint bounds. Only `Pair`, the owner's tier-4 connect step (part b2), pins or re-pins and turns a device on; a failed `Pair` leaves the old pin. `Connect` never pins: an accessory that does not prove the pinned key turns the device off, logs one line (the KRN-7 line once b2 wires the log), and any later `Connect` is refused before a byte is written. The host keeps the store across restarts (`Snapshot`, `Restore`); it holds public keys only. The library cannot tell the owner's call from another; b2 must reach `Pair`, `ConfirmBounds` and `Restore` only from the owner's page and the host's own state. | DEV-3, DEV-10, KRN-7 | If a non-owner path can reach `Pair`, the pin is only as strong as that path: b2's review checks it. |
| HK-15 | **Bounds are confirmed, not set.** `ProposeBounds` records a setpoint's bounds as unconfirmed (only the three setpoints, finite, min at most max), and any new proposal unconfirms the old. `ConfirmBounds` confirms only the values proposed, as the owner saw them. `WriteVerb` reads the class rows (HK-8) with the device's bounds, so a setpoint write is `actuate` only inside confirmed bounds. Bounds are per device, which is one accessory (`aid`) for a T10 Pro. | DEV-4, DEV-5 | A bridge exposing several thermostats under one pairing: key bounds by `aid` too. |
| HK-16 | **Events are private, unverified numbers.** Session events go to `OnEvent` after the session lock is released (#3325 item 1), so the clerk's callback may ask the session for the characteristic. Each value becomes one `Event` (owner's device name, `private`, unverified, `aid`/`iid`, service and type, a bool or number); text values are counted, never emitted. Events reach the accessory's controller only while a request is in flight; an idle session reads nothing until the host's next call. Per characteristic at most one event per `Gap` (1 min), the latest value held for `Flush`; at most `MaxEvents` (64) per gap over all devices. A value the bus refuses is held again for the next `Flush`, unless a newer one is held: thermostat values are current states, so the latest wins. | DEV-8, DEV-3, PLN-3, RES-1 | If an idle session must surface events, the host polls or b2 adds a reader that holds no lock while it waits. |
| HK-17 | **The bus is a function for now.** `Clerk.Emit` takes one `Event`. The kernel has no device-report entry yet (KRN-1) and no host runs the clerk; both are part b2, with the device-clerk host shared with #3321. The package is linked into no trusted process until then, so it needs no `trusted_base_parsers.txt` line yet; b2 adds one for `clerk/homekit`. | DEV-8, KRN-1, KRN-2 | b2 maps `Event` to the kernel's entry and wires the host. |
| HK-18 | **SRP side channel, rechecked at part c.** `big.Int.Exp` with the code-derived exponent is not constant-time (#3325 item 6). Exposure is a LAN timing observer during the single owner-run pairing; part c rechecks it on the box. `testdata` now pins a vector whose B starts with a zero byte, and one whose A does (#3325 item 8). | DEV-10 | A measurable leak on the box: move the exponentiation to a constant-time implementation. |
