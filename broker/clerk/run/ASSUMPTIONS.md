# Kernel and clerk processes: assumptions

Built for MIG-4-run (#2682), slice 1: the kernel's process and the exit clerk's process, in `broker/clerk/run`. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-run-a | **Option A: one process per credentialed clerk, and the kernel in its own process.** Each credentialed clerk (exit, mail, browser) runs under its own uid with its own Secrets directory, and the kernel runs in a separate process. One process holding every clerk's Secrets (option B) is ruled out by CLK-1. A clerk that holds no secret (the sim, the slice runner) may share the kernel's process. Decided by the coordinator on 2026-10-21 and recorded on #2682. | CLK-1, STO-3 | A clerk sharing a process gets a row of its own here. |
| MIG-4-run-b | **One call per connection, and the view travels with it.** The kernel sends `{op, request, view}`, and the clerk answers `{outcome, detail}`. The view is the log's answer for this request only: the dispatch record, the chain's grants, the enrollments, the revocation and stop state, the ledger uses before the dispatch for every scope the chain charges, and the one-off line for the chain's root (D-146). The one-off line is computed on the kernel's clock at the call, not the clerk's, because it folds every grant under the root; the two clocks are on one box within one call. A root the view does not name has line 0, so any spend asks for a second passkey. The clerk runs its own `Check` against that view and does no I/O to the kernel while it acts, so a kernel that dies mid-call cannot half-answer a check. The clerk sees the log only through the kernel. Before calling the clerk, the clerk's process refuses (`view`) a view that leaves out a charged scope's ledger, because that scope would read as unspent. | CLK-2, STO-3 | A View method added to `kernel.View` is one field of the view. |
| MIG-4-run-c | **Each side admits only the other's uid.** The clerk's socket admits only the kernel's uid (`sockets.ListenPeers`). The kernel sends nothing to a socket whose peer is not the clerk's configured uid. A kernel that cannot reach its clerk, or finds the wrong uid, has sent nothing, so the step fails `unreachable`, as at a clerk the kernel does not have. Once any byte of the call is written, a missing answer is `unknown` (`lost`), and the step is probed through the clerk (KRN-8). | CLK-1, KRN-8 | none |
| MIG-4-run-d | **The kernel logs only a bounded answer.** An outcome outside the op's closed list (`ok`/`failed` for a call, `done`/`notdone` for a probe) is read as `unknown`. A detail over 256 bytes, invalid UTF-8 or holding a control character is logged as `malformed`. The exit's details are typed codes (clerk MIG-4-exit-c), so honest details pass unchanged. | CLK-4, KRN-8 | none |
| MIG-4-run-e | **The Secrets file is replaced atomically, in the clerk's own directory.** The steps are: write `secrets.tmp` (O_EXCL, O_NOFOLLOW, 0600), fsync it, rename it over `secrets`, fsync the directory. A crash leaves the old form or the new one, each whole, and a leftover temporary is never read and is replaced by the next write. The directory and the file must belong to the process's uid, be closed to every other uid, and not be symlinks; anything else is refused, never repaired. The path is the clerk's own directory, so no configuration names another clerk's file. | CLK-1, STO-2 | The setup flow (after STO-2) creates the directory with the clerk's uid. |
| MIG-4-run-f | **The old slot-to-blob form is refused, not migrated.** A Secrets file in which any slot is a bare string is refused with `ErrOldFormat` and left as it was. No store in that form was ever written outside tests (clerk MIG-4-exit-e). | CLK-1 | none |
| MIG-4-run-g | **Nothing here holds a real secret before STO-2.** The sealer is `clerk.NewAESSealer` under a test key, and the log key and head key are supplied by the caller. No `cmd/` main, unit file or setup flow is shipped yet. The production `Sealer` (the store key released by the TPM or passphrase slot), the boot unlock, and the mains and units under `image/` wait for STO-2, per Mark's #936 answer. Until then only tests start these processes, by re-running the test binary. Hardening a clerk's process (`procguard.Isolate`, which refuses the kernel's uid and sets it non-dumpable) belongs in that main. | STO-2, CLK-1 | The STO-2 slice adds the mains, the units and the Sealer. |
| MIG-4-run-h | **One lock around the kernel.** Every call into the kernel goes through `Kernel.With`, including `Tick` and the clerk calls inside it. A slow clerk therefore delays the owner side until its call ends or times out (5 minutes by default). This is correct but not concurrent. Running clerk calls outside the lock needs the kernel to split dispatch from result, which is a kernel-lane change. | KRN-5 | A kernel API that logs the dispatch and the result in separate calls lets the host drop the lock while a clerk works. |
| MIG-4-run-i | **The log file is locked, not anchored, by this package.** `FileStore` takes an exclusive `flock` so a second kernel process cannot open the same log. The anchor (LOG-2: the phone, a TPM counter or the enforcer) is supplied by the caller. No anchor that lives on the log's own disk ships, so the tests use the in-memory anchor. | LOG-1, LOG-2 | The anchor's slice supplies a real `kernel.Anchor`. |
