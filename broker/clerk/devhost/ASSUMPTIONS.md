# Assumptions: the device-driver host library (DEVSLOT-drivers part b2a, #3472)

What the package rests on. Brief: `briefs/DEVSLOT-drivers.md` ("Part (b), settled"); decision D-189. The wire and the process entry are in `broker/clerk/devslot` (DEVSLOT-host-lib-1 to -3).

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| DEVSLOT-host-lib-4 | **The host re-checks everything, outside the driver's address space.** It holds the image's declaration (from `drivers.json`, part b1), never the driver's, and compares the declaration the driver's process sends with that one's `Canonical` bytes; it never parses the driver's. It refuses an operation the image lacks before any process starts. Every write must be one of the running operation's shapes on its declared channel (`Declaration.Writes`), so an undeclared, oversize or wrong-channel frame never reaches the transport. At most the operation's `MaxWrites` frames reach the transport in one connection; the next write fails it with `ErrWrites` (DEVSLOT-writes-1, #3506). Every frame the device sends must come from the pin on a declared channel and be at most `MaxRead`. A refusal fails the operation, closes its connection and emits nothing. The slot's own checks in the driver's process are a second layer (DEVSLOT-a-7). | DEV-1, DEV-4, CLK-1 | none |
| DEVSLOT-host-lib-5 | **The host owns the transport.** `Config.Transport` is the slot's `Transport` interface, called only by the host: the key-checked TCP stream is b2b's, the enforcer's GATT relay is part c's, and until then GATT is a fixed "no relay" error (b2b). A transport error crosses the wire only as `failed`, and the driver may go on; no device or transport text reaches the driver or the log. | DEV-2, DEV-3, NET-2 | none |
| DEVSLOT-host-lib-6 | **Each operation is one connection and one deadline.** `Do` dials the driver's socket unit (`Dialer`), which starts a fresh instance (Accept=yes), and closes the connection at done, refusal or deadline; `Config.Deadline` bounds dial to done, and the unit's `RuntimeMaxSec` kills a process past it (part b1). One operation runs at a time per driver; a subscription gives way to it (DEVSLOT-subscribe-2). | CLK-1, RES-2 | none |
| DEVSLOT-host-lib-7 | **Readings are checked and held until done.** A reading must be a kind the image declares, with an exponent in [-18, 18] and a time in canonical RFC 3339 form in UTC (`Z`, no offset, zone name or trailing zeros), at most `MaxReadings` per operation. Readings are emitted only after a clean `done`, so a refused one emits none. Events carry the image's device and operation names, the `private` label, and `Unverified` unless the link is TCP (DEV-3). | DEV-8, PLN-3 | none |
| DEVSLOT-host-lib-8 | **One host is one source for DEV-8, with a window per reading kind (Potency 6450899341 point 1 on #3480).** A host serves one driver for one pinned device. For each reading kind, its first `Limit.Burst` events of a window (from that kind's first event in the window) go to the sink; the rest are counted, and the count goes out as one `Coalesced` event of that kind carrying its last reading once the window has ended, on the next event or on `Flush`, which b2b's process calls on a timer. So a flood of one kind never hides another: a smoke reading in a flood of temperatures goes out at once. A source then sends at most `Burst + 1` events per kind per window, and a declaration has at most `CapKinds` (32) kinds, so a source's rate stays bounded. The limit's values are b2b's configuration. | DEV-8, RES-1 | A source floods across many kinds: lower `CapKinds`, or add a per-source cap over the kinds' windows. |
| DEVSLOT-host-lib-9 | **The host is a parser of hostile bytes.** It decodes the driver's wire messages (through `devslot.ReadMsg`) and checks the device's frames, so it has a `parser` line in `tools/trusted_base_parsers.txt`. Nothing links it into a binary before b2b (`cmd/agentos-devices`). | KRN-2 | none |
| DEVSLOT-subscribe-1 | **A subscription is an instance that stays up and emits each reading as it arrives (part b4, #3475).** `Subscribe` runs a declared subscription operation (DEVSLOT-subscribe-3 in `devslot`): each instance is one connection, held for `Config.Subscription`, and each reading it sends is checked as in DEVSLOT-host-lib-7 and emitted at once, under DEVSLOT-host-lib-8's limit, not held until done; `MaxReadings` does not bound it, the limit does. When the instance reaches that deadline, the host closes it and subscribes again with a fresh instance. Each instance has its own `MaxWrites` count (DEVSLOT-writes-1), so `New` refuses a `Config.Subscription` below `MinSubscription` (30 s): instances start at most once per period plus once after each preempting `Do` (DEVSLOT-subscribe-2), whose own caller bounds how often it runs, so the host's config alone cannot raise the write rate (#4515). Any other end (a refusal, a failed dial, a failed `done`) ends `Subscribe` with its error, and a clean `done` ends it with none, so the library never re-dials in a loop on a failing or quitting driver; b2b decides when to subscribe again. A refusal stops the instance's later readings, not the ones already out, since each was checked alone. `Do` refuses a subscription and `Subscribe` refuses a one-shot operation. The unit's `RuntimeMaxSec` for a subscription instance must be at least `Config.Subscription`; that line is b1's template and b2b's config, not this package's. | DEV-8, DEV-4, RES-2 | none |
| DEVSLOT-subscribe-2 | **A subscription gives way to an operation.** One subscription runs per host. `Do` ends the running subscription instance (the readings already out stay out), runs on the driver alone, and the subscription resumes with a fresh instance after it, so an actuation never waits for a subscription's deadline. A reading the device pushes in that gap is not seen. The one transport is never read by two instances at once. | DEV-4, RES-1 | Readings lost in the gap matter: demultiplex the transport, which is part c's relay and b2b's stream. |
