# Clerk exit: assumptions

Built for MIG-4-exit (#2571, D-139 step 4), slice 1: the declaration-driven exit in `broker/clerk` (`exit.go`, `secrets.go`). Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-exit-a | **A declared request shape fixes everything but argument values.** URL is https with a fixed host. A path slot is a whole segment, and the path holds no escapes, so the path checked at declare time is the path sent. A constant query may follow. `Query` maps a parameter to an argument, `Body` maps a field to an argument under a closed `Type` (JSON or form), and `Headers` are constants. Each value is encoded by `url.Values` or `encoding/json` for its one place. A value that is empty, `.`, `..` or holds `/` is refused in a path slot. No declared header may be a credential header, one the clerk sets itself, or the secret's own header. One op per verb per clerk. A GraphQL-style constant body and a read-back probe op are later items. | CLK-3 | A new place for a value is a new `Op` field with a test. |
| MIG-4-exit-b | **The exit gives back only an outcome and "http N".** Response bodies are drained, never returned, so a hostile page cannot reach the log or the planner. Reads that need a body go through the model clerk (CLK-7), a later slice. | CLK-4, CLK-7 | A body-returning op needs a quarantined reader. |
| MIG-4-exit-c | **Outcome from status, as a typed detail.** 2xx: ok. 401/403 auth, 402 declined, 404/410 notfound and other 4xx rejected are failed, because the remote refused before acting. 3xx (never followed), 408, 409, 5xx and no answer are unknown, left to the probe. 429 is unknown with phase notsent, so the probe answers notdone once Retry-After (seconds form only; a date form counts as 0) has passed and the kernel sends again under the same key. A detail is a code plus "http N", the host or an argument name. It never holds a value, a transport error or a secret, so nothing needs redacting. | KRN-8, CLK-2, CLK-4 | A remote with its own status semantics gets its own op field. |
| MIG-4-exit-d | **Probe is the clerk's own memory.** It answers `done`, `unknown` or `notdone` per idempotency key, held in memory, and the key is sent as `Idempotency-Key`. It answers `notdone` only when a resend is safe: a 429 after Retry-After, or an op declared `Idempotent` (the remote dedupes on the key, and the declaration asserts it). Any other key it has no record of is `unknown`, because a restart forgets. At most `kernel.MaxChecks` sends per key, then `unknown` until the kernel parks the step. Retrying a parked step is the owner's RETRY, tracked by #2620 (kernel side), which does not exist yet. The lock covers only the state table, never a request. | KRN-8 | Persisting the table is one store write. |
| MIG-4-exit-e | **One clerk, one sealed secret slot.** NewExit refuses two slots across ops, and a store that holds any slot other than the one the clerk uses. AES-256-GCM with the slot name as AAD, and no method returns plaintext. The opened bytes are wiped after the request, but the header string copied from them is not (Go strings are immutable), so that wipe is best-effort. The sealing key is supplied by the caller; binding it to the TPM is the `tpmseal` side. OAuth refresh for the slot is a separate PR. | CLK-1, STO-2..4 | A `Sealer` backed by the TPM replaces `AESSealer`. |
| MIG-4-exit-f | **Slice 1 is additive.** `broker/{egress,holder,checker,vault}` and their `cmd/` binaries stay until their slices port and delete them, in that order; `tools/old_core.txt` loses a line per deletion. | D-139 | none |
| MIG-4-exit-g | **The exit owns its transport and dials only through the home-network address policy.** No proxy from the environment, no cookie jar, no redirects, TLS 1.2 minimum. Every dial goes through `netguard.Policy.DialContext` (DEV-2), which checks each resolved address after DNS, so rebinding is caught. A nil `Declaration.Guard` is netguard's IANA-only policy. A home device is reached only through a pin on the policy the caller passes. A refused dial fails as `blocked`, with nothing sent. | CLK-3, CLK-4, DEV-2 | The broker passes its one shared policy, so learned home prefixes are refused too. |
| MIG-4-exit-h | **A step's recipient is its object argument.** Check refuses (RClaim) a step whose `Recipient` differs from the verb's first argument, so key caveats judge what is actually sent. | KEY-2 | none |
