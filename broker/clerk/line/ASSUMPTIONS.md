# Assumptions: the second-line clerk, part a (CLK-8-line-a, #3735)

What the library rests on. Brief: `briefs/CLK-8-line.md`. Part b wires it into `agentos-clerk-line` (keeper) and `agentos-line` (main side); part c adds the owner page and STATUS.

| ID | Assumption | If wrong |
|---|---|---|
| CLK8-1 | **Recipient sources.** The kernel marks every plan argument as the planner's (`kernel.Normalize`), so no step reaches a clerk with `Source` owner or clerk today. The clerk resolves the source of `to` itself from its own owner-given records: an owner-created contact's exact number is `Source` clerk, a number on the owner's fixed list is `Source` owner, anything else is the planner's and refused (KEY-2). `Admit` re-reads those records whatever a `Source` says, so a mislabelled argument passes nothing. A key's `to` bound (`KArg`) is not used: `Authorize` refuses a bounded argument from the planner, which every plan argument is. | If the kernel later carries argument sources, `Source` becomes a check of the step's own and the fixed list may move into the key. |
| CLK8-2 | **Who may be texted.** A recipient is E.164 (`+` and 3 to 15 digits) or a digits-only short code of 3 to 8 digits; any other form, a contact saved with separators or in national form included, is refused (CLK-8). A contact passes in that form, short and premium-rate codes included; a fixed number passes only as E.164 of at least 8 digits outside `sendrules.Premium`. The owner's number, the box's owner-channel number and the line's own never pass, also in a national, international-prefix or separated form (digits compared by `sendrules.SameNumber`), even as a contact (CH-1, CH-19; L3 6503790799). A short code passes the clerk, but `sipline` dials only `+` and 3 to 15 digits (SL6), so the line refuses it as not taken: nothing is sent. | A provider that texts short codes over SIP would need sipline's number rule widened. |
| CLK8-3 | **Custody.** The password and the account record are two static slots under `clerk.DeviceSlots + "second-line/"`, opened only through `Secrets.DeviceKey`, which lends a slot for one call and wipes it after; the clerk returns only a digest answer made with it (CLK-1). `DeviceKey` is reused rather than a new lend added to `clerk/secrets.go`, which is in the trusted core (`tools/trusted_core.txt`) and would grow it. The clerk runs in its own process with its own store (part b), so no device clerk shares these slots. `sipsign.Account` takes the password as a string, a copy the wipe does not reach; it lives for one signature in the clerk's process, as `Secrets.Login`'s does. | If a lend of its own is wanted, it is a trusted-core change under D-159. |
| CLK8-4 | **One budget.** The line's budget is the key's rate caveats (`KRateDay`, `KRateRecipient`), charged by the kernel's ledger for every `send` on this clerk; the clerk re-checks them through `check.Check` and keeps no count of its own. `sendrules.Budget` is not used. | None for texts; calls (part d) spend the same caveats. |
| CLK8-5 | **At most once.** A step is handed to the line once per idempotency key. A cancel before the hand-off, or a line that took nothing (`ErrNotTaken`), sends nothing and leaves the step notdone; a provider refusal (`ErrRefused`) is final. Any other answer, a lost one included, is "may have been sent": logged as such, unknown to `Probe` for good so the kernel parks it, and never handed or signed again. State is in memory, so `Probe` answers notdone only for a step this clerk saw go nowhere and unknown for any step it has no record of: after a restart the kernel parks every unfinished text rather than send it again (KRN-8, as `clerk.Exit` does for a request that is not idempotent; security fix-list 6503740548). | Part b must map sipline's errors onto `ErrNotTaken` and `ErrRefused` only where nothing reached the provider or it refused finally. |
| CLK8-6 | **The signing binding (D-154 option A).** `sign.go` signs REGISTER only for `sip:<domain>`, at most once per 30 s, and MESSAGE only for an admitted send: once, with the Request-URI's number equal to that send's recipient and its host the account's domain. INVITE, BYE and CANCEL are refused until calls (part d). Every refusal is counted in `Status`. The realm is learned from the first REGISTER challenge the account can answer within 30 minutes of setup, and texts are refused before the line until the owner confirms it (SL3). Residuals, as the brief names them: a taken-over line process can keep the account registered, and since `qop=auth` does not cover a body it can change an admitted text's words to the admitted recipient, or replay the signed request where the provider tolerates nonce reuse (`qop=auth-int` is a later item; part b checks whether the provider offers it, security 6503740548); a provider that accepts MESSAGE without a challenge never asks the clerk to sign. | Under option B, `sign.go` and `sign_test.go` drop; no other file names them (`TestTheSigningBindingIsOneFile`). |
| CLK8-7 | **Inbound.** A text to the line becomes an item labelled `untrusted-second-line` (`edgelink.LabelSecondLine`), its sender a number only when the provider vouched for it, else "named sender <name>" (SL5), and is logged as that item. The owner texting the line gets `MainNumberText` at most once an hour and reaches no planner and no log. | None. |
| CLK8-8 | **Tests use a fake line.** `sipline`'s loopback seam for `sipsim` is in its own `export_test.go`, so a test outside that package cannot reach the simulated provider through the network guard. Part a's tests drive the clerk with a fake line that asks the signer for its MESSAGE signature as sipline does, and check each answer with the provider's digest arithmetic; the run against `sipsim` through `sipline` is part b's lifecycle matrix (`broker/e2e/secondline_test.go`). | None; part b's matrix covers the wire. |
