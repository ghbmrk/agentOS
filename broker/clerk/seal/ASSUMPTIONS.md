# Sealed store (STO-2a): assumptions

Built for STO-2a (#2828), the first of the four STO-2 rows (triage 2026-10-23): the store file, its slots and its derived keys, in `broker/clerk/seal`. Boot wiring and the mains are STO-2b, image units and first-boot enrollment STO-2c, unknown-host unlock with the approval code STO-2d. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| STO-2a-a | **One store key, wrapped by independent slots, never on the drive.** The key is 32 random bytes. A slot is `tpm` (a random 32-byte slot key sealed by `tpmseal.Seal` under the box's policy key, with the optional boot PIN), `passphrase` (Argon2id of the Owner Card's passphrase, at least 256 MiB, its cost stored in the slot) or `recovery` (HKDF of the 32-byte recovery key; it is random, so it needs no slow hash). Each slot holds AES-256-GCM of the store key under its slot key, with the store's ID and the rest of the slot as associated data, so a wrap moved to another store or slot does not open and a passphrase slot's cost cannot be lowered in place. A tpm slot's boot paths are left out of that data so an update can add one (`SetPolicies`); the file's MAC covers them, and the TPM checks each signature at unseal. So nothing on the SSD alone opens the store (`TestCanaryKeyIsNotOnTheDrive` looks for the store key, the derived keys, the recovery key, the passphrase and an entry, raw, hex and base64). | STO-2, A8, HW-5a | none |
| STO-2a-b | **The whole file is MAC'd under the store key, and only its canonical encoding parses.** HMAC-SHA256 under a derived key covers the version, the ID, every slot and the sealed entries. After a slot opens, Unlock checks the MAC and refuses the store (`ErrTampered`) if it fails, so a slot forged by someone with the drive but not the key (one that wraps a key of their own for this store's ID) makes the store refuse to open for everyone, rather than open a store they chose; a dropped slot is refused the same way. The parser accepts only the bytes `encoding/json` would write for what it read (no spacing, duplicate keys or base64 padding bits the MAC would not see), so any changed byte is refused. The cost: a tampered file is a denial of service until the owner restores it; nothing opens wrongly. | STO-2, KRN-2 | none |
| STO-2a-c | **Bounds are checked before any key work.** The file is at most 1 MiB, holds 1 to 16 slots, a tpm slot at most 16 boot paths, a passphrase slot an Argon2id cost between 256 MiB and 4 GiB and time 1 to 64, and the entries at most 64 of 4 KiB each. A hostile drive cannot make the unlock step allocate or hash past them. The 1 s tuning of the default cost (time 1, 4 threads) is #826; each slot keeps its own cost, so a retune needs no migration. A passphrase under 16 bytes is refused at enrollment; the Owner Card's is seven words. | STO-2, HW-4 | #826 changes `DefaultArgon` only. |
| STO-2a-d | **Per-purpose keys come from one HKDF, each under its own label.** `agentos-store/v1/` plus `log` (the log's AES-256-GCM key, `run.KernelConfig.Key`), `head` (the ed25519 seed of the kernel's head-signing key, KEY-3's head domain, `run.KernelConfig.Sign`), `sealer/<clerk>` (each clerk's `clerk.Sealer`, AES-256-GCM through `clerk.NewAESSealer`), `entries` and `mac`, with the store's ID as salt. A clerk name is lower-case letters, digits and hyphens, so `sealer/` names never meet another label. The store key is never rotated: that would change every derived key and orphan the log. "Rekey" is `Replace`, which puts a new slot in place of one in a single write (a new passphrase or recovery key, REC-4, or a TPM slot sealed again with a PIN). | STO-2, KEY-3, CLK-1, REC-4 | A store-key rotation would need a log re-encryption step of its own. |
| STO-2a-e | **The store key stays with whoever unlocked.** `Store` holds the key until `Close` wipes it; `LogKey`, `HeadKey` and `Sealer` hand out derived keys only. SPEC puts the store key with the unlock step, which hands each process only its own keys (credential exceptions, CLK-1); that step and its hand-off over inherited descriptors are STO-2b. Go cannot pin memory or stop the runtime copying it, so the wipe is best-effort, as in `broker/clerk`'s Secrets. | CLK-1, STO-3 | none |
| STO-2a-f | **Entries hold what the kernel reads after unlock, as opaque bytes.** The approval-code verifiers (the CH-4 seed, the grid) and the box's policy key (HW-5a: its private half lives only inside the store) are entries under names the caller picks. The store seals them as one blob under the entries key. Checking a code belongs to the rows that read them. | STO-2, CH-4, HW-5a | none |
| STO-2a-g | **Every change is one atomic write.** Add, remove, replace, boot-path and entry changes encode the whole file, write a temporary file beside it (mode 0600), fsync, rename over the store and fsync the directory; a failed write leaves the file and the in-memory store as they were. `Create` links into place and refuses an existing path. Removing the last slot is refused. All of them need the open store, and so the key. One process opens the store at a time (the unlock step, STO-2b); this package takes no file lock. The rename is `durable:exempt` (broker/durable is old core, D-139) and the package is listed in `broker/durable/stores.txt` as `content`: the store is key material, not a lifecycle. | STO-2 | STO-2b adds a lock if a second writer appears. |
| STO-2a-h | **A tpm slot is tried only on its own TPM.** Unlock reads the TPM's storage-root name (`tpmseal.Identity`) and tries only slots sealed to it, so another PC's TPM gets `ErrNoSlot` and spends no dictionary-attack count. A TPM refusal (a boot path no policy signed, a wrong or missing PIN, lockout) comes back joined with `ErrWrongFactor`, so the caller can say why. The policies must be signed by the slot's policy key at enrollment and at `SetPolicies`. | HW-5a, STO-2 | none |
| STO-2a-i | **A core package of its own.** `broker/core/core.txt` lists `core clerk/seal`, so its write paths (`Create`, `Unlock`, `AddSlot`, `Replace`, `Put`, `Sealer`, …) are refused to any non-core, non-wiring caller unless an `open` or `allow` line names it; its first callers (the unlock main and `clerk/run`, wiring) come in STO-2b. It calls `clerk.NewAESSealer`, a core-to-core call. Its `FuzzParse` is on the CI fuzz list. | KRN-2, ARC-1 | none |
| STO-2a-j | **The store file is not anchored against rollback here.** A copy of an older store file opens with the older slots (for example a passphrase since replaced). REC-4 already says a rotation protects only against copies made afterwards; the log's own rollback is caught by its anchors (STO-1). | STO-1, REC-4 | A TPM-counter binding of the store file would be its own row. |
