# Assumptions: the device-driver slot (DEVSLOT-drivers part a, #3321)

What the package rests on. Brief: `briefs/DEVSLOT-drivers.md`; decision D-189.

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| DEVSLOT-a-1 | **A driver is code behind an interface, run in its own clerk process.** `Driver` has two methods, `Declare` and `Run`; `Run` gets only a `Link`, a `Secrets` handle and the operation's name. Part a gives `New`, `Slot.Do` and `Serve` over an `Env` the host fills. The process main, the host's `Transport` (the enforcer's GATT relay or a key-checked TCP stream), its uid, its non-dumpable flag, the manifest check and the wiring of `Emit` to the kernel's entry are part b (and the relay is part c). Until then nothing links the slot into a running process. | CLK-1, DEV-1, NET-2 | Part b finds the process boundary needs more than an `Env` (for example a cancel or a status call): add it to `Env`, a tier A change to the public contract. |
| DEVSLOT-a-2 | **The declaration is data, checked before the driver runs.** `Check` refuses any verb outside DEV-4's list (`read`, `actuate`, `actuate-physical`, `present`, `change-account`, `delete-remote`, `reveal-or-create-secret`), a link or shape kind off the closed lists (`gatt` with `gatt-write`, `tcp` with `tcp-frame`), names outside `[a-z][a-z0-9-]{0,39}`, undeclared references and frame bounds past the caps (read 65,540, write 4,096, 1,024 readings). The class of each operation still comes from the kernel's table, never from this declaration (DEV-4). The slot keeps its own copy, so a driver that edits its declaration later changes nothing. | DEV-4, DEV-1 | A device needs another link kind (USB, serial): a new kind and shape kind here, tier A, with its own link test. |
| DEVSLOT-a-3 | **The host pins the device, not the driver.** A `Pin` is a Bluetooth address for GATT, or a home-network address (private or link-local unicast, not loopback, multicast or the internet) with the SHA-256 of the device's identity key for TCP. The driver names only declared channels, and the slot turns each into the pinned target, so it cannot name an address. A frame read from another address, another characteristic or an undeclared channel, or longer than `MaxRead`, is refused and fails the operation. A GATT device has no key identity here, so its events are `Unverified`; a TCP device pinned by key is verified. Checking the key on the wire is the host transport's job (part b). | DEV-2, DEV-3 | A GATT device with a cryptographic identity (LE Secure Connections bonding the relay can attest): add that to `Pin` and mark it verified. |
| DEVSLOT-a-4 | **Writes are declared shapes: a channel, a prefix and a length range.** That is coarser than a whole-frame allowlist: a shape with a short prefix and a wide range admits any bytes after it. The slot enforces the shape; the private repo's review judges whether a shape is narrow enough (point 5), and the conformance suite fails any shape that leaves more than `MaxFreeTail` (8) bytes free after its prefix until the driver's tests name it in `Config.Wide`, so the diff that widens a shape is the one the review reads (#3363). `Check` still accepts an empty prefix: length-prefixed TCP framing needs a variable first byte. A refused write is not sent, and the operation fails with `ErrUndeclared` even if the driver ignores the error. | DEV-4, CLK-3 | Shapes need fields inside the frame (an enumeration at an offset): add typed field checks to `Shape`. |
| DEVSLOT-a-5 | **The key is lent, never named.** `Env.Lend` is `clerk.Secrets.DeviceKey` for the `device/` slot pinned at pairing (D-184): it opens a static slot under `device/` only, for one call, and wipes the bytes after. `Secrets` holds no slot name and prints no field. The slot imports no `clerk` package, so a driver binary links no HTTP or TLS client through it. | CLK-1, D-184 | none |
| DEVSLOT-a-6 | **Nothing from the driver leaves as text.** Every error `Do` returns and every log line the slot writes is a fixed message naming only the declared device and operation; a driver error becomes `ErrDriver` and a panic `ErrPanic`. Events carry the declared device and operation names, the `private` label, and readings of a declared kind with an integer value, an exponent in [-18, 18] and a time, emitted in UTC so the driver's zone name (free text) never reaches an event. A driver can still encode its key into frames or reading values; the suite catches the raw and hex forms and base64 at each of its three alignments, in any frame and across the written stream with and without the shapes' prefixes, and the review catches the rest (XOR, reading values). Rate limits and coalescing of events (DEV-8) are the host's (part b). | DEV-8, PLN-3, CLK-1 | A leak the suite cannot see: the private review is the check, as for any trusted-base code. |
| DEVSLOT-a-7 | **The conformance suite is a test library and a lint; the boundary is the process.** `conformance.Check` runs each operation once against the driver's fake device with a canary key and fails an undeclared write, a failed clean run, a canary leak or a panic; then it fuzzes each operation 300 times (seeded) with flipped, truncated, extended and random replies bounded by `MaxRead`; then it reads `Config.Listing`, the `go list -deps -json` output the driver repository's CI makes for the image's target (the suite starts no process; a listing that is empty, lacks the driver type's own package, has an entry with no import path, or has one go list could not load fails; a forged or partial listing passes, so the private review checks the CI command that makes it), and, for each non-standard package outside the slot (`devslot`, `kernel/key`), fails any source but plain Go files (assembly, syso, C and the other cgo kinds, files the build skipped), any `//go:` directive but `//go:build` (`linkname` reaches runtime internals, `norace` hides races from the race detector, `cgo_import_dynamic` loads a system library at exec), any standard import off an allowlist (`allowedStd`: framing, encoding, hashing, crypto primitives without `crypto/tls` or `crypto/x509`, and the language's helpers), and any other import from this repository, `conformance` included (test tooling; drivers use it from `_test.go` files only). This is a lint over source, not a sandbox: Go code with no forbidden import can still corrupt memory through a data race and reach the kernel, `time.LoadLocation` can test whether a zoneinfo file exists, and `fmt` can print to standard output and read standard input. The boundary that holds a hostile driver is its sealed process: its own uid, non-dumpable, a seccomp filter that allows no socket, no file open and no exec, no standard input, and no standard output or error that leaves it, and only the host's link and lend channel (CLK-1, STO-3). That process is part b's (#3321): no driver runs on the box before it. | DEV-1, KRN-2, CLK-1, point 5 | A driver needs a third-party library that imports something off the list: the private repo raises a finding, and the allowlist gains a reviewed entry here. |
| DEVSLOT-a-8 | **No parser of device bytes is in the slot.** The slot compares prefixes and lengths and copies frames; the parsers are in the drivers, counted in the private repo's own `trusted_base_parsers.txt` and the image manifest (point 5). The fixture driver under `testdata/` is test code, not linked into any binary. So this package adds no line to `tools/trusted_base_parsers.txt`. | KRN-2 | none |
| DEVSLOT-a-9 | **Handles end with their operation.** The `Link` and `Secrets` given to `Run` are revoked when `Run` returns: every later `Write`, `Read` or `Open` gets `ErrClosed`, calls still in flight are cancelled through their context and waited for, so a kept handle or a goroutine the driver left cannot replay the operation's frames without an operation running, open the key again, or touch the transport during the next operation. The host's `Transport` must return once its context ends (part b). A driver that ignores its own context still holds its operation, so part b's host gives each operation a deadline and kills the process past it. | CLK-1, DEV-4, DEV-8 | none |
