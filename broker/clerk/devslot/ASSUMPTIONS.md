# Assumptions: the device-driver slot (DEVSLOT-drivers part a, #3321)

What the package rests on. Brief: `briefs/DEVSLOT-drivers.md`; decision D-189.

| ID | Assumption | Serves | If wrong |
|---|---|---|---|
| DEVSLOT-a-1 | **A driver is code behind an interface, run in its own clerk process.** `Driver` has two methods, `Declare` and `Run`; `Run` gets only a `Link`, a `Secrets` handle and the operation's name. Part a gives `New`, `Slot.Do` and `Serve` over an `Env` the host fills. The process main, the host's `Transport` (the enforcer's GATT relay or a key-checked TCP stream), its uid, its non-dumpable flag, the manifest check and the wiring of `Emit` to the kernel's entry are part b (and the relay is part c). Part b2a adds the process entry `proc.Main`, the wire and the host library `broker/clerk/devhost` (DEVSLOT-host-lib-1, -2); nothing links them into a running process before b2b. | CLK-1, DEV-1, NET-2 | Part b finds the process boundary needs more than an `Env` (for example a cancel or a status call): add it to `Env`, a tier A change to the public contract. |
| DEVSLOT-a-2 | **The declaration is data, checked before the driver runs.** `Check` refuses any verb outside DEV-4's list (`read`, `actuate`, `actuate-physical`, `present`, `change-account`, `delete-remote`, `reveal-or-create-secret`), a link or shape kind off the closed lists (`gatt` with `gatt-write`, `tcp` with `tcp-frame`), names outside `[a-z][a-z0-9-]{0,39}`, undeclared references and frame bounds past the caps (read 65,540, write 4,096, 1,024 readings). The class of each operation comes from the driver's reviewed class row in the release manifest, never from this declaration; the declared verb must equal it, and an operation with no row is refused (DEV-4). The slot keeps its own copy, so a driver that edits its declaration later changes nothing. | DEV-4, DEV-1 | A device needs another link kind (USB, serial): a new kind and shape kind here, tier A, with its own link test. |
| DEVSLOT-a-3 | **The host pins the device, not the driver.** A `Pin` is a Bluetooth address for GATT, or a home-network address (DEVSLOT-host-lib-3) with the SHA-256 of the device's identity key for TCP. The driver names only declared channels, and the slot turns each into the pinned target, so it cannot name an address. A frame read from another address, another characteristic or an undeclared channel, or longer than `MaxRead`, is refused and fails the operation. A GATT device has no key identity here, so its events are `Unverified`; a TCP device pinned by key is verified. Checking the key on the wire is the host transport's job (part b). | DEV-2, DEV-3 | A GATT device with a cryptographic identity (LE Secure Connections bonding the relay can attest): add that to `Pin` and mark it verified. |
| DEVSLOT-a-4 | **Writes are declared shapes: a channel, a prefix and a length range.** That is coarser than a whole-frame allowlist: a shape with a short prefix and a wide range admits any bytes after it. The slot enforces the shape; the private repo's review judges whether a shape is narrow enough (point 5), and the conformance suite fails any shape that has no prefix, or leaves more than `MaxFreeTail` (8) bytes free after its prefix, until the driver's tests name it in `Config.Wide`, so the diff that widens a shape is the one the review reads (#3363, #3375). The limit is per write, not per stream: on TCP, writes of a narrow shape still join into a longer sequence. `Check` still accepts an empty prefix: length-prefixed TCP framing needs a variable first byte, and names its shape in `Wide`. A refused write is not sent, and the operation fails with `ErrUndeclared` even if the driver ignores the error. | DEV-4, CLK-3 | Shapes need fields inside the frame (an enumeration at an offset): add typed field checks to `Shape`. |
| DEVSLOT-a-5 | **The key is lent, never named.** `Env.Lend` is `clerk.Secrets.DeviceKey` for the `device/` slot pinned at pairing (D-184): it opens a static slot under `device/` only, for one call, and wipes the bytes after. `Secrets` holds no slot name and prints no field. The slot imports no `clerk` package, so a driver binary links no HTTP or TLS client through it. | CLK-1, D-184 | none |
| DEVSLOT-a-6 | **Nothing from the driver leaves as text.** Every error `Do` returns and every log line the slot writes is a fixed message naming only the declared device and operation; a driver error becomes `ErrDriver` and a panic `ErrPanic`. Events carry the declared device and operation names, the `private` label, and readings of a declared kind with an integer value, an exponent in [-18, 18] and a time, emitted in UTC so the driver's zone name (free text) never reaches an event. A driver can still encode its key into frames or reading values; the suite catches the raw and hex forms and base64 at each of its three alignments, in any frame and across the written stream with and without the shapes' prefixes, and the review catches the rest (XOR, reading values). Rate limits and coalescing of events (DEV-8) are the host's (part b). | DEV-8, PLN-3, CLK-1 | A leak the suite cannot see: the private review is the check, as for any trusted-base code. |
| DEVSLOT-a-7 | **The conformance suite is a test library and a lint; the boundary is the process.** `conformance.Check` runs each operation once against the driver's fake device with a canary key and fails an undeclared write, a failed clean run, a canary leak or a panic; then it fuzzes each operation 300 times (seeded) with flipped, truncated, extended and random replies bounded by `MaxRead`; then it reads `Config.Listing`, the `go list -deps -json` output the driver repository's CI makes for the image's target (the suite starts no process; a listing that is empty, lacks the driver type's own package or an import of a listed driver package (made without `-deps`), has an entry with no import path, or has one go list could not load fails; a forged listing passes, so the private review checks the CI command that makes it), and, for each non-standard package outside the slot (`devslot`, `kernel/key`), fails any source but plain Go files (assembly, syso, C and the other cgo kinds, files the build skipped), any `//go:` directive but `//go:build` (`linkname` reaches runtime internals, `norace` hides races from the race detector, `cgo_import_dynamic` loads a system library at exec), any standard import off an allowlist (`allowedStd`: framing, encoding, hashing, crypto primitives without `crypto/tls` or `crypto/x509`, and the language's helpers), and any other import from this repository, `conformance` included (test tooling; drivers use it from `_test.go` files only). This is a lint over source, not a sandbox: Go code with no forbidden import can still corrupt memory through a data race and reach the kernel, `time.LoadLocation` can test whether a zoneinfo file exists, and `fmt` can print to standard output and read standard input. The boundary that holds a hostile driver is its sealed process: its own uid, non-dumpable, a seccomp filter that allows no socket, no file open and no exec, no standard input, and no standard output or error that leaves it, and only the host's link and lend channel (CLK-1, STO-3). That process is part b's (#3321): no driver runs on the box before it. | DEV-1, KRN-2, CLK-1, point 5 | A driver needs a third-party library that imports something off the list: the private repo raises a finding, and the allowlist gains a reviewed entry here. |
| DEVSLOT-a-8 | **No parser of device bytes is in the slot.** The slot compares prefixes and lengths and copies frames; the parsers are in the drivers, counted in the private repo's own `trusted_base_parsers.txt` and the image manifest (point 5). The fixture driver under `testdata/` is test code, not linked into any binary. The wire codec (DEVSLOT-host-lib-1) does decode messages, from the host in a driver's process and from a driver's process in the host, so since part b2a the package has a `parser` line in `tools/trusted_base_parsers.txt`. | KRN-2 | none |
| DEVSLOT-a-9 | **Handles end with their operation.** The `Link` and `Secrets` given to `Run` are revoked when `Run` returns: every later `Write`, `Read` or `Open` gets `ErrClosed`, calls still in flight are cancelled through their context and waited for, so a kept handle or a goroutine the driver left cannot replay the operation's frames without an operation running, open the key again, or touch the transport during the next operation. The host's `Transport` must return once its context ends (part b). A driver that ignores its own context still holds its operation, so part b's host gives each operation a deadline and kills the process past it. | CLK-1, DEV-4, DEV-8 | none |
| DEVSLOT-host-lib-1 | **The wire is one operation per connection, in bounded messages.** Each message is a 4-byte big-endian length and a JSON body of at most `MaxMsg` (128 KiB), one object with only `Msg`'s fields; anything else is `ErrWire`. The driver's process speaks first: its declaration in `Canonical` form (JSON with every empty list and prefix as null), which is the form the image's `drivers.json` must hold (part b1), then the host's `op` message with the pin and the uplink's /56, then writes, reads and readings, then `done`. The only error text on the wire is `failed`. In the driver's process the wire is the slot's `Transport` and `Emit`, one round trip at a time; a call its context interrupted leaves the wire out of step, so every later call of that operation fails. It lends no key: `Env.Lend` is nil until b2b adds the key reader (brief part b point 3). | DEV-1, DEV-4, CLK-1 | A driver needs to read and write at once (subscriptions, b4): give device frames their own unsolicited message, so a read does not hold the wire. |
| DEVSLOT-host-lib-2 | **The process entry is its own package, and the sandbox is the unit's.** `proc.Main` is apart from the slot so the slot imports no process or file package (TestLinkReachesOnlyPinnedDevice); `slotSide` in the suite gains it. It makes the process non-dumpable, then refuses a peer on descriptor 3 whose `SO_PEERCRED` uid is not `AGENTOS_DEVHOST_UID`, before `Declare`, serves one operation and exits 0 or 1 with no output. Package initialisers run before `Main`, so everything that holds a hostile driver (no socket, no file, no exec, no standard input, the deadline) is applied by systemd before exec (brief part b point 1). The variable comes from the driver's unit: sysusers fixes no uid, so b1 or b2b must give the unit the host's uid (a fixed uid for the host's user, or a drop-in the setup writes). A driver's own initialiser can change its environment, but that only weakens the check that protects the driver from a wrong caller; the socket's mode 0600 under the host's user is the first such check. | CLK-1, DEV-1 | The unit cannot be given the host's uid: check the peer's gid against the socket's group instead. |
| DEVSLOT-host-lib-3 | **Home addresses (Security 6433469158 point 8).** A TCP pin is a private, shared (100.64.0.0/10) or link-local IPv4 address whose last octet is not 255, a unique-local or link-local IPv6 address, or a global IPv6 address inside the uplink's enclosing /56, which the host passes to `Check` (and `Env.Home`, and the `op` message). A v4-mapped address is judged as its IPv4 address. The home /56 must lie in 2000::/3, judged by its first bits whatever host bits are set, and must not overlap 6to4 (2002::/16) or Teredo (2001::/32); so NAT64 (64:ff9b::/96, 64:ff9b:1::/48), IPv4-compatible (::/96) and IPv4-translated (::ffff:0:0:0/96) homes are refused too. Such an address reaches the IPv4 internet, and b2b will learn the /56 from the home network, which DEV-2 does not trust (L3 6450413836 point 1 on #3480; Security 6455038688 point 1 on #3509). Every directed broadcast of a /24 or wider subnet ends in .255; a narrower subnet's broadcast is not caught. | DEV-2, DEV-3 | A home uses a subnet narrower than /24: the host passes its IPv4 subnet too, and the check refuses that subnet's broadcast. |
| DEVSLOT-subscribe-3 | **A subscription is a declared read that reports as it goes (part b4, #3475).** An `Operation` with `Subscribe` set must have the verb `read`, so a long-lived instance writes only read-class shapes, however many times. In it, the driver reports each reading through `Link.Report`, which the slot checks (a declared kind, an exponent in [-18, 18]) and emits at once, in UTC, one at a time; its `Run` returns no readings, and should return nil once `Read` fails because the host ended the instance. `Report` in a one-shot operation, readings returned by a subscription's `Run`, or an undeclared reading fails the operation; readings already reported stand. `Report` on a kept link after the operation ended gets `ErrClosed` (DEVSLOT-a-9). The field is `omitempty`, so a declaration with no subscription keeps its canonical bytes and `drivers.json` (DEVSLOT-image-2). | DEV-8, DEV-4 | none |
| DEVSLOT-subscribe-4 | **A declaration has at most `CapKinds` (32) reading kinds.** The host's DEV-8 windows are per kind (DEVSLOT-host-lib-8), so this bounds a source's event rate. | DEV-8, RES-1 | none |
