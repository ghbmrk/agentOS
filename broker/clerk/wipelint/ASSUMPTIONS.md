# Sealer key-wipe lint: assumptions

Built for LINT-sealer-key-wipe-fu (#6349). Each row is a reading a reviewer may want to change.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| LINT-sealer-key-wipe-fu-1 | A sealer is anything whose method set, as a type or through its pointer, satisfies `clerk.Sealer` (`types.Implements`); a constructor is a function whose results hold one anywhere inside (a field, pointer, slice, map, channel or func result), found by type alone, so a package need not import clerk to be held. Any receiver or parameter that can hold or produce bytes (an interface, func, channel, uintptr or unsafe.Pointer included) is a possible key, so such a constructor is listed, its keys named or the reason none are. | CLK-1, STO-2 | A sealer of another shape (a second interface, a func pair) gets its own interface in the rule. |
| LINT-sealer-key-wipe-fu-2 | Only linux binaries ship, so a file that only another platform compiles holds no key on a box; the files lintload.Unread reports (another tag set, cgo, non-Go) are listed one by one in `unreadOK` with why each holds no sealer. | HW-8, REV-CHK-lintload-2 | A second shipped platform adds a load for it. |
| LINT-sealer-key-wipe-fu-3 | A listed key is a byte slice, wiped by the builtin `clear(k)` or `defer clear(k)` as the statement right after the call. `clear(k)` wipes before anything can return; `defer clear(k)` wipes when the function returns, on every path, so the key stays in memory until that return. A string cannot be wiped, a byte array passes by value and leaves the callee an unwiped copy, and a key behind a pointer, in a struct or map, or of a type the lint cannot read (any, a type set without terms) cannot be wiped by one statement at the call, so a listed key of those forms fails. | STO-2 | A rule that a key must not outlive the call refuses `defer`; a key form a statement can wipe at the call, with no copy left in the callee, gets its own wipe shape. |
| LINT-sealer-key-wipe-fu-4 | `vendor/` and nested modules are other modules: their declarations are not read, so a use in broker of one of their functions that makes a sealer from a possible key fails unlisted. | CLK-1 | Vendored code that must itself wipe a key is held where broker calls it. |
