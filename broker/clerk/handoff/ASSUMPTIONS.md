# The unlock step's hand-off: the backup recipient (MIG-4-recovery-e1): assumptions

Built for MIG-4-recovery-e1 (#3191) from `briefs/MIG-4-recovery-e.md` (Shared decision 1 and section e1), across `clerk/handoff`, `cmd/agentos-enroll`, `cmd/agentos-unlock` and `kernel/proc/kernelmain.go`. The hand-off's earlier rows are rows v to ab of `broker/clerk/run/ASSUMPTIONS.md`. Each row below is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| MIG-4-recovery-e1-1 | **The recipient's store entry and wire form are defined here, not in `broker/backup`.** `handoff` links neither the store nor the kernel, and `broker/backup` imports `broker/kernel`, so `handoff` carries the recipient as bytes: its X25519 public key then its ML-KEM-768 encapsulation key (`RecipientLen`, 1216 bytes), the order of `backup.Recipient`'s `X` and `EK`. `RecipientEntry` (`kernel/backup-recipient`) holds that behind a version tag (`agentos-backup-recipient/v1`), so a later form can be told apart, as `kernel/anchors` had to be after the fact. Both ends parse both keys (`crypto/ecdh`, `crypto/mlkem`), so a recipient no backup can be sealed to is refused at enrollment, at unlock and at the kernel's read. e3 rebuilds a `backup.Recipient` with `SplitRecipient`. | BAK-1 | If `broker/backup` gains its own encoding, the entry keeps this one or takes a new tag. |
| MIG-4-recovery-e1-2 | **The hand-off goes to v4, the recipient after the counter.** A uint16 length, 0 or `RecipientLen`, then the bytes, before the anchors' count, so the anchors stay last and their parsing is unchanged. A v3 hand-off is refused whole: the unlock step and the kernel ship in one image, so no box pairs them across versions. `maxHandoff` grows by 1218 bytes to under 8 KiB, still far below a pipe's 64 KiB buffer, so the unlock step's write never waits for a reader. | BAK-1, STO-2a-e | — |
| MIG-4-recovery-e1-3 | **A store enrolled before e1 hands no recipient and its kernel still starts.** The unlock step treats a missing entry as none (an entry that is there must read, as for anchors); the kernel says `ErrNoRecipient` on stderr and runs on. Backups for such a box start after a recovery-key rotation (REC-4) writes the entry; e3 refuses each `backup` call with a fixed reason, and e4's notice names the fix. | BAK-1, REC-4 | If old boxes must back up without a rotation, the recovery key would have to be asked for at a boot, which the store's design keeps out of the kernel. |
| MIG-4-recovery-e1-4 | **Enrollment writes the recipient with the slots, before the "slots" step.** It derives it from the same recovery key the recovery slot wraps, and stores only the public half (`TestEnrollStoresTheBackupRecipient`: no 8-byte run of the key is in the entry). A crash before the rename leaves a staged store the next run deletes, so no store holds slots without the recipient. `rotate` (the TPM policy key) does not touch it; the recovery-key rotation that must rewrite it is REC-4's row. | BAK-1, STO-2 | — |
| MIG-4-recovery-e1-5 | **The kernel holds the recipient and uses it for nothing yet.** `RunKernel` reads `KernelKeys.Recipient` only to say when it is missing; e3 passes it to the backup calls. The kernel's row for this belongs in `broker/kernel/proc/ASSUMPTIONS.md`, which #3259 holds (D-111); it is carried here until e3, which owns that file's backup rows. | BAK-1 | — |
| MIG-4-recovery-f1-2 | **The hand-off carries the page authority (v5).** `KernelKeys.PageCA` is `pageca.Marshal`'s form, length-prefixed after the recipient; none crosses as none, and a value `pageca.Unmarshal` refuses is refused at both ends and as a store entry (`ParsePageCA`). `Wipe` clears it. `handoff` now links `pageca` (standard library and `kernel/privfile`), which `kernel/proc` links anyway; a v4 hand-off is refused, as each earlier version was, since the unlock step and the kernel ship in one image. | CH-9, BAK-1, D-186 | If the two binaries can ever ship apart, the reader keeps the older version. |
| MIG-4-recovery-f1-3 | **Enrollment makes the authority, dated from the build.** `cmd/agentos-enroll` makes it with `pageca.New` and puts it in the staged store with the recipient, so a store is never committed without one. Its NotBefore comes from the binary's `vcs.time` (go build stamps it from image/build.sh's checkout, the commit `SOURCE_DATE_EPOCH` also comes from), else the binary's modification time; never the first boot's clock. With neither, enrollment refuses. A rerun after a crash starts a new store and so a new authority, which is safe: no Owner Card prints a fingerprint before enrollment ends. A store enrolled before f1 has no entry and hands none; that box was never shipped wired (#3166 was queued, no production sealer existed). | CH-9, HW-1, D-186 | If the image strips VCS stamps and does not clamp mtimes, enrollment takes a `-built` flag from the unit instead. |
| EDGE-link-core-b-1 | **The hand-off carries the link key, the first edge key and the slot (v6).** After the page authority: the link key's seed and the first edge key, each a one-byte length of 0 or the exact size; then the slot that opened the store, a one-byte length and 1 to `MaxSlot` printable bytes, always named. The anchors stay last. A v5 hand-off is refused, as each earlier version was. `Wipe` clears the link key. | HW-15, STO-2 | If the slot must name a slot ID rather than its kind, `seal.Unlock` has to report which slot opened. |
| EDGE-link-core-b-2 | **Enrollment makes the link key and takes the first edge from the link port's capture.** The capture file (`-first-edge`) is 128 bytes: the edge key, the hello's 32-byte nonce, and the key's signature over `kernel.HelloMsg(nonce)`, as agentos-link's pre-store mode (c2) will write it. Enrollment takes it only from a regular file of its own euid that no group or other can write, opened without following a link, and only when the hello verifies from a key not of small order (`kernel.SmallOrder`, b2); the owner uid is `readCapture`'s parameter so a plain-user test reaches the check, and enrollment passes its euid; anything else stores no first key, is said on stderr, and enrollment finishes. It removes the file once the store is in place, so a crash before that rereads it. `-restore` (a restore's enrollment, REC-2) stores none and only removes the file; no unit passes `-first-edge` or `-restore` yet (c2 and #3186 do). The link key is a fresh 32-byte seed per store, never backed up (BAK-1). | HW-15, REC-2, BAK-1 | If c2 writes another form, `readCapture` and `captureLen` change with it. c2 must write the capture file as root, enrollment's euid, mode 0600 or tighter, or enrollment takes no first key. |
| EDGE-link-core-b-3 | **The unlock step names the slot by its kind; only `tpm` is this PC's.** Today it opens the store only through the tpm slot. Its `passphrase` field opens it by the passphrase slot and names `passphrase`, but only tests set it: the unknown-host unlock of §12.2, which would take a passphrase on the local page, is not built in the new core, and no flag takes one, so no root path that skips the store anchor's check is added here. An entry for the link key or first edge that is there must read; a missing one hands none, so older stores still start. | HW-15, STO-2, §12.2 | When the unknown-host unlock is built, it sets the slot so, and the kernel cuts the edge at that start. |
| MIG-4-recovery-r1 | **The rotation approval is a fixed binary form under the head key, shared by the kernel and the root steps** (#3391, D-201). `agentos-recovery-rotate/v1\n`, version byte 1, route byte (`a` card, `b` lost), `old` and `next` each as a length byte and 0 or 32 lowercase-hex bytes, the expiry in milliseconds as a big-endian uint64, then the Ed25519 signature over everything before it; at most `MaxApproval` (167) bytes, with no trailing bytes. `VerifyApproval` checks shape, then the signature, then `now < expires`; the caller checks the route and that `old` is the recipient it holds, which makes the approval single-use once the recipient changes. Times are the caller's clock: route B's verify at boot reads an unsynchronised clock (brief residual risk 3). | REC-4, BAK-1, STO-2 | A field added to the approval is a v2 tag and body; v1 readers refuse it. |
