# Resource admission, preemption and budgets: assumptions

Built for PLAN P2-5 (RES-1 to RES-4) on SPEC v0.12 (PR #15), ported from draft #31 as P2-5r and reconciled with PE2 and PE6, on the
admission controller (P1-2, #19) and the machine lifecycle (P1-4, #23).
Each row is a reading of the spec, or a gap left for a later package,
that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| R1 | The floor budget is RES-2's table with GB read as GiB: host 1024, inference 2048, browser 512, headroom 600 MiB, the figures `agentosd` (PE6) and the S1 test kit's `floor_fit` use too; the pool is what is left of `MemTotal`. An 8 GB N95 reports about 7680 MiB, which leaves a 3496 MiB pool: two OpenClaw machines (1552 MiB each), not three. A host whose pool cannot hold the agent machine runs agentosd with the agent off and says so on STATUS (PE6, daemon B15). | RES-2, HW-4, S3, S4 | `budget.Floor`, `budget.OpenClawMB`. |
| R2 | A larger host keeps every component's budget (HW-4). Its capacity (pool plus headroom) is capped at `CapMB(cores, headroom)`: headroom plus one OpenClaw machine per two cores, at least 4500 MiB (RES-2c). Cores bound how many machines run well; memory past that stays with the host. At five cores or fewer the cap is 4500 MiB, as under PE6, so the N95 (4 cores, about 7.5 GiB, capacity 4096) is unchanged. Cores are logical CPUs, `runtime.NumCPU()` (the broker's CPU affinity at start), not a cgroup CPU quota; on an SMT box that is two per physical core, so the cap is doubled there (potency R1 on #140), which A2's large-host run checks on an SMT box. One machine per two cores is a judgment from S3/S4 (an OpenClaw machine busy on one core, with a core for the host), unmeasured above the floor: check it on A2's large-host run, on an SMT box. | HW-4, RES-2 | `budget.CapMB`, `budget.ForHost`, agentosd `capacityFor`. |
| R3 | Each component has its own cgroup under one root (`-cgroup-root`, default the broker's own group from `/proc/self/cgroup`; it must be that group or below it, and delegated: systemd's `trusted.delegate`/`user.delegate` mark on the broker's group, or `-cgroup-delegated` with an explicit root. Without that proof the broker writes nothing to the cgroupfs, runs no machines, and STATUS says the memory controls are not set up): `inference`, `browser` and `machines` have hard limits; `broker` has its budget as `memory.min` and no hard limit, so it is never OOM-killed by its own group and its pages are not reclaimed for others. With every other component capped and the headroom left over, the host OOM killer has nothing to choose. The pool's `memory.high` equals its limit; per-machine groups carry the 1/16 throttle (V10). The broker moves itself into `broker` before enabling controllers (cgroup v2 refuses controllers below a group that holds a process). | RES-2 | `budget.Apply`, `agentosd` `openPool`. The P2 unit file sets `Delegate=yes`. |
| R4 | Host processes outside the broker (systemd, the modem bridge) are not under the root and are covered only by the 1000 MiB host figure; nothing caps them. | RES-2 | Host image (P2-1). |
| R5 | Preemption never waits for an operation already holding the experiment. `vm.Manager.Preempt` sets a flag, tries the machine's lock, and if a checkpoint, fork, rollback or prune holds it, empties the machine's cgroup (`cgroup.kill`) under that operation; the operation then fails, and the machine is recorded `preempted` once it lets go. While the flag is set, `startFrom` refuses to start the machine, before and after the runtime starts it. Residual window: a sandbox whose start was already inside `runsc` when the kill landed lives until that start returns and its caller stops it, so for up to one start's duration its memory is not counted. | RES-1 | `vm/vm.go` `Preempt`, `startFrom`. |
| R6 | The preemption target (1 s) is provisional: no DECISIONS.md row freezes it yet. It is measured on CI in a 7680 MiB group with every component loaded (`floor` test): from the foreground request to the experiment's memory being released, idle and mid-checkpoint. Propose freezing it in DECISIONS.md after the N95 run confirms it. CI's cores are faster than the N95's: re-run `floor` on the N95 (A2). | RES-1, A2 | `floor.PreemptTarget`. |
| R7 | Accelerators are found from sysfs only: `class/accel/accel*` is an NPU, `class/drm/renderD*` a GPU, integrated when it sits on PCI bus 0 (Intel iGPUs at 0000:00:02.0, AMD APUs). Display nodes (`card*`) are not compute devices. | RES-3 | `accel.Discover`. |
| R8 | An accelerator is an admission resource as a lease, one holder per device. A lease never blocks or fails: with no free device it is a CPU lease, the same service on the CPU. Foreground takes a device from an experiment (the experiment's lease reports `Lost` and its next unit runs on the CPU); nothing else is taken from. `-accel off` makes every lease a CPU lease (A2: identical behavior when disabled). No local inference service exists yet; it takes its leases from this pool. Until it does, `agentosd` builds the pool only to log what it found and keeps no handle: a pool with no lease holders would be dead state on the daemon (L3 on #124). | RES-1, RES-3 | `accel.Pool`; P3 inference. |
| R9 | The RES-4 reserve is declared per item: a staged release 1280 MiB (S7: 1.0 GiB erofs + 69 MiB verity), journal growth 512 MiB and recall-index growth 1024 MiB (both placeholders until P3 sizes them), 2816 MiB in all. It is the default of `-disk-reserve-mb`, which every snapshot, fork, merge and rollback copy is admitted against (V19). No discretionary download path exists yet; when one does (UPD-3, model downloads) it must pass the same check. | RES-4 | `budget.FloorDisk`. |
| R10 | Snapshots are pruned by policy every minute: each live machine keeps its newest snapshot, its oldest full checkpoint (the warm template, REV-1), its newest full checkpoint, its 50 newest file-system snapshots and 2 newest full checkpoints. Any snapshot a live machine was forked from is kept (merge needs it), and nothing younger than 10 minutes is pruned (so a fork or merge between taking a snapshot and recording its use never loses it). While free space is below the reserve plus 1 GiB, a machine keeps only the protected ones. A destroyed machine's snapshots are pruned unless a live fork needs one. | RES-4, REV-1, REV-4 | `vm.PrunePolicy`. |
| R11 | Pruning unpublishes each snapshot (record, then `meta.json`) under the machine's lock, so no rollback, fork or merge of it can pick the snapshot up afterwards, then deletes the files after the locks are released, so a slow delete never holds up a rollback (L3 on #124). A crash mid-delete leaves a directory the next start drops. **Gap:** `Diff` takes no machine lock, and one that resolved a snapshot just before it was unpublished can fail mid-read with not-found; it never reads another snapshot's files, and only snapshots past `MinAge` (10 min) outside every protection are pruned. A per-snapshot reader count that defers deletion would close it. | RES-4 | `vm/prune.go`. |
| R12 | **Gap: CPU is not budgeted.** Components get memory limits only; no `cpu.weight` is set, so a busy machine pool can starve the broker's CPU and slow STOP and the preemption target (R6) on the N95's four cores. The floor test loads memory, not CPU. Close it by giving `broker` a high `cpu.weight` and `machines` a low one in `Apply`, measured on the N95 run (A2). | RES-1, RES-2 | `budget.Apply`; `floor` test. |
| R13 | The broker manages cgroups only with proof they are its own: its own group (from `/proc/self/cgroup`) or below, carrying systemd's delegate mark, or an explicit `-cgroup-root` vouched for by `-cgroup-delegated`. Otherwise it writes nothing to the cgroupfs, starts no machines, and STATUS reads "Agent: off, the box's memory controls are not set up; it needs an update." The legacy `-cgroup` flag is gone. | RES-2 | `agentosd` `delegatedRoot`, `openMachines`. |
