# childproc: assumptions

What `childproc` rests on (P3-4b-3r-env-r8a, r8b; OPERATING §5).

| ID | Assumption | Source | Held by |
|---|---|---|---|
| CP-1 | Linux, and the stdlib `os/exec` semantics `childproc` wraps: a non-nil `exec.Cmd.Env` is the child's whole environment, and `Cancel` and `WaitDelay` behave as documented for Go 1.25 and later. | Go `os/exec` docs | `TestTheChildSeesExactlyTheBuiltEnvironment`, `TestAnEmptyEnvIsEmpty`, `TestOnCancelRunsBeforeTheKill`, and each caller's exact-environment test (r8b) |
| CP-2 | No code outside `childproc` reaches `os/exec` or names a launcher selector in the non-test graph, apart from the gate's `exempt` map. The gate's graph is the union of `CGO_ENABLED=0` (how shipped binaries are built) and `CGO_ENABLED=1` (CI's race tests). Test files are outside the gate because agentosd links none. The fuzz binaries built with `go test -c` run only as `childproc` children, so whatever they start inherits only the checked pairs. A file neither setting builds for linux/amd64 (another GOOS or GOARCH, a tag) is held to both rules by its own imports, and what those import that the graph lacks is listed too; a package that lists only under another GOOS is not followed (r8b). | brief D3 | `TestOnlyChildprocStartsAProcess`, `TestGateCatchesAChildStartedOutsideChildproc` |
| CP-3 | Nothing reaches the handle's unexported `*exec.Cmd` through reflection plus `unsafe`, and nothing starts a child through a raw `SYS_EXECVE`. Both are held by review for now. | LATER P3-4b-3r-env-r8 l1, l2 | review |
| CP-4 | The secrets a child must not see are agentosd's `AGENTOS_*` variables and variables whose names mark a credential (`credentialWords`). A secret under another name is caught only by the key allowlist, which refuses every key not listed. | brief D2 | `TestTheEnvironmentIsDeniedByDefault` |
| CP-5 | `childproc` checks a child's environment only. Nothing checks what else a caller hands it: argv (`sh -c "X=<secret> …"`), `ExtraFiles`, or a secret whose value starts with `/` (`ownSecrets` skips such values, so a base64 secret beginning with `/` is not matched). A secret under a name outside `credentialWords` is caught only by the key allowlist (CP-4). Callers pass no secret in argv or files. | #651 Security 4a 6; D2's text covers the environment only | review; LATER P3-4b-3r-env-r8a l1 |
| CP-6 | The key allowlist is one list for every child, so a key added for one caller is allowed for all. The guest runtime's keys (`OPENCLAW_*`, `DO_NOT_TRACK`) are on it because the guest bridge runs in the guest, where no `AGENTOS_*` variable exists; a broker child given one would still have its value checked against the process's own secrets. | brief r8b | `TestRuntimeGetsExactlyTheNamedVariables`, review of each new key |
