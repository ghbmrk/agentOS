# apnet: assumptions

Built for CTRL-claim-ap u1 (#1185) against HW-1, CH-7, HW-10 and ARC-1. `broker/apnet` is the card's Wi-Fi network as the page reports it and as agentos-ap serves it. It imports only the standard library, so agentosd can take it without linking the card or the claim (ARC-2). Each row is a reading a later change could overturn.

| # | Assumption | Basis | If it changes |
|---|---|---|---|
| N1 | **The page reports the card's network before the confirm latches.** The card step's provision (`localui.ServeCardNet`) first sends the card's Wi-Fi name and password to agentosd (`page_setup_ap_net`), which writes them root-only (0600, durable rename) to `/var/lib/agentos/ap-net.json`; only then does it provision, and the latch saves after that. So agentos-ap, which serves this file once it sees the latch or the owner state, always has the network when the confirm appears. A report that fails fails the provision: nothing latches and the card stays shown for a retry. A later report replaces the last, since a reset card is a new card. The op is served for the whole setup session until finish, whenever the page runs the card step, not only while the card is shown; a report after the confirm replaces the network, and agentos-ap serves the new one (Down then Up). | HW-1, CH-7, ARC-1 | If the confirm moves out of the page, whatever confirms must write the file first. |
| N2 | **Only a network a card prints is taken.** `Validate` accepts exactly `AgentOS-` plus four card symbols and a password of 16 card symbols in four groups, the shape `card.Generate` makes; `Parse` also refuses unknown fields and trailing data. So the page cannot make the root loader serve the setup network's name, an open network, or anything hostapd would read as more than a name and a key. The alphabet is a copy of `card.Alphabet`, pinned by a test. | CH-7, ARC-2 | A new card format changes `Validate` and its test together. |
| N3 | **A forged latch serves only the page's own network.** The latch is the page's file, so a compromised page can mark the card confirmed early. agentos-ap then burns the setup network and serves the network the page itself reported; it gains nothing it could not get by confirming, and the claim code still guards the claim. This does not widen #1385 (the page can forge "claimed"), which stays open as filed. | HW-10, HW-1 | If the latch moves to a root-owned file, the loader can trust it and this row goes. |
| N5 | **A Wi-Fi rotation rewrites the file from the vault process's commit (REC-4, #1191, #1522; replaces N4).** When the vault process commits a card whose Wi-Fi part is rotated, or stops after a slot write (409, where the owner keeps the new card), it holds that card's network as a one-shot permit for 5 minutes; a new begin, a lock, a take or the lapse drops it. The page's `page_rotate_ap_net` carries only the confirming session's token, and names no network. agentosd then takes the permit over the verify socket (`POST /rotate/wifi`), and only with it writes: the file must exist and keep its SSID, the network must pass `Validate` (through `Marshal`), and the write is a durable rename at 0600; a directory sync that fails after the rename counts as written, since the new network is on the air. Nothing logs the password. agentos-ap sees the change at its next poll (2 s) and brings the access point Down then Up, so the old password is off the air from then on, including after restarts. A failed hand-off leaves the old password served, and the page says so: the done page after a clean commit, the in-effect text after a 409 or no answer (#1523). `APLoader.Rekey` stays unwired (localui L40). Residuals: (tier) any live page session, not only the confirming one, can spend the permit, but it writes only the network the owner's code just committed; (persistence) a crash or power cut between the commit and the take leaves the old password on the air after reboot, and nothing reconciles the file with the vault's card (P-1, later); (flapping) a compromised page writes at most once per Wi-Fi commit, and each commit needs the owner's proof; (who takes) any process that reaches the verify socket as the broker uid, or root, can take the permit first and so suppress the switch, which is #1426's (A1) to narrow. | REC-4, CH-7, ARC-1 | If agentosd reconciles the file with the vault process's card at start, the persistence residual goes; if the verify socket narrows to agentosd alone, so does the last. |
| N6 | **An access point that keeps failing on the card's network is told to the owner once per rotation (CH-12, #1525).** agentos-ap counts each failed `Up` of the card's network, and each child that dies before the network has served 15 looks (30 s at the 2 s poll), in `ap-up-failures.json` beside the network file, root-only 0600 by durable rename; the record names the file's version (inode and modification time, never the password) and starts again at one for a new version; a network that settles clears it. A failure only ends the run: systemd restarts agentos-ap after 5 s, which again serves what the file holds or nothing, so the previous password is never brought back. agentosd looks every 10 s, and once the count reaches 3 for the file's current version it sends the owner one fixed text through `Inform` ("Restart the box, then join my Wi-Fi with your newest Owner Card"), noting that version in `ap-up-noticed` only after the send, so a failed send is tried again and a restart of agentosd does not repeat it. The setup network's failures are not counted. Residuals: `Inform` is paced as an update (CH-15), so a quiet setting holds the text; the text names the step, but a radio that never comes up still needs the box's other channels to fix. | CH-12, REC-4, CH-7 | If the access point gains a health signal of its own (hostapd's control socket), it replaces the settle window. |
