# broker/browser: assumptions and carry-forward (CRED-4b part 1)

Part 1 is the broker-side gate in front of S5's driver: the closed v0 action protocol (CRED-4), declared-origin checks, and the CRED-10 output filter, all applied outside the driver, which is treated as untrusted because it renders pages written by strangers.

## What the gate guarantees
- **G1** Only the seven v0 verbs exist. Requests with unknown verbs or arguments, wrong JSON types, duplicate keys, oversized fields (`url` 4096, `ref` 32, `option` 1024, `text` 2000 bytes) or anything but whitespace after the object are refused and never reach the driver. The driver receives a canonical re-encoding, never the agent's bytes, so the two sides cannot parse one line differently.
- **G2** `navigate` to an undeclared origin is refused at the gate, in addition to the driver's own routing checks. Hosts must be ASCII: a Unicode host is refused, not mapped, in requests, replies and declared origins alike, because Go's lowercasing and the browser's IDNA (UTS46) can name different hosts (`gİthub.com`). Declare IDN origins in punycode (`xn--`).
- **G3** Every string the driver returns passes the vault's exact-value redactor first, then the CRED-10 detector (ported from S5 `protocol.py`). The gate's detector also redacts a value of 16 or more token characters with a digit after a secret label (key, token, secret, password, api key), which makes it stricter than S5's `protocol.py`. Output file names are filtered too; a match withholds and removes the file. Fields outside `Result` are dropped.
- **G4** A reply whose page URL is off the declared origins, or an `ok` reply with no page URL, means confinement failed. The driver puts `page.url` on every reply. The gate stops the executor (kills its process group) and relays nothing from that page.
- **G5** Before a screenshot, the gate snapshots the page itself; any match from the driver or the gate withholds the screenshot without taking it. After the shot it scans the file's bytes and snapshots again; a match in either removes the file and withholds it.
- **G6** A download whose text carries a vault value or a detector match is removed from the workspace and withheld. Only screenshot and download may name an output file, and it must be a flat name of a regular, singly linked file in the workspace (no symlinks, no hard links); the gate reads it through an `O_NOFOLLOW` descriptor.
- **G7** The driver starts with a fixed environment (PATH, HOME=workspace, LANG, plus `Config.Env`), never the broker's. A missed reply deadline, malformed output or driver exit stops the executor.
- **G8** `OmitValues` replaces the value of a snapshot line whose ref is a password field with `[password omitted]`; the line and its ref stay. The ref is the first `[ref=…]` after the quoted accessible name, at any indentation, because the name is page-controlled and can hold a decoy token. Only the canonical shapes `- role "name"` and `- role` followed by nothing, `:`, ` [` or a closing `'` are parsed. Any other line (unterminated or unquoted name, extra spaces, a YAML double-quoted key) cannot be parsed: if any ref on it is a password field, everything after the role is replaced (fail closed). Lines nested deeper under a password line are its children (a field with a placeholder renders its value as `- text: <value>`): every child but `/placeholder` loses its value. Each removed value is then replaced everywhere else in the snapshot, as is, whitespace-collapsed, JSON-escaped, and each of those with `'` doubled to `''` (Playwright single-quotes a key that needs YAML quoting, such as a name holding `: `), because a row, cell, link or button holding the field, or an element labelled by it, carries the value in its accessible name (measured on Playwright 1.56.1, Security 4a on #683). A short value can over-redact other text, which fails closed. A transformed copy of the value (split across nodes, reversed, encoded) is outside what a snapshot filter can catch (#683 L3, later). Moved here from #211's `broker/browseract`.
- **G9** A credentialed GET that reads as a state change is held for the owner, not sent (ADP-14, ADP-14-get). A `navigate` URL, or the target of a link a `click` or `download` follows, matches when a path, query or hash-route word (split on punctuation, letter-digit and camelCase boundaries, adjacent pairs joined so `opt-out` reads `optout`) is an action word or contains an action stem, or a query key names a token. A click inside a clickable element (a link, a button, a checkbox, an element with a pointer cursor) is also held when the whole subtree text of the element it activates names an action (`[icon] Unsubscribe`): the nearest click-role element or an enclosing link, or a pointer-cursor ancestor with no click-role element in between, so a link in a clickable card keeps its own name; a text field is not judged by name, an unparseable href is held raw, and an un-unquotable name counts as written, except a dialog's "Cancel", "Close" or "Not now" with no target; a form field or container outside one is not judged by name; `Config.StateLinks` adds the recipe's own path prefixes on the declared origins. A held request gets an id and is sent only by `Gate.Release` with the exact held URL, once; a held click or download is sent only if a fresh snapshot shows the same ref with the same role, name and target. A `click` or `download` on a ref not in the last snapshot the gate saw is refused (`unknown_ref`). Over-matching (a search for "cancel") fails closed. Holds live in memory, at most 32 per gate, oldest dropped first.
- **G10** The gate omits password values from every snapshot itself, before the CRED-10 filter, and never takes the driver's word for which fields are passwords (CRED-4, #1111). The refs come from the snapshot alone: every `textbox` or `searchbox` line (the roles Playwright gives an `<input>` or `<textarea>` that can hold a password) that shows a value on its own line or in a child other than `/placeholder`. A line with one of those roles that G8 cannot parse gives every ref on it (fail closed). The one exemption is a field whose value is exactly the text the agent typed into that ref, by `type`, on the page the driver named in its reply: nothing leaks, and keying it to the ref and page stops a guess typed elsewhere from telling the agent whether it matches a password. A value the agent typed on any page is also not scrubbed from the rest of a snapshot, so a search does not hide its own results; the field itself is still omitted. The gate remembers at most 64 typed refs and 64 texts, then starts over. `password_fields` in a result is the gate's count of fields omitted; the driver's figure is discarded. G8 changes with it: a value shorter than 4 characters is omitted only from its own field, not scrubbed from the rest of the page (a quantity of `1` would wipe every price), and the scrub never rewrites a `[ref=…]` token, so clicks keep working. Cost, which fails closed: a pre-filled value the agent did not type (a saved address, a username) is hidden, and the agent must not be relied on to read one.

## Known limits (carried to part 2)
- **K1 Sandbox.** The driver is a child process in its own process group, not yet in a broker-owned VM. Part 2 places it in its own sandbox, one account each (CRED-4), through `vm.Manager` (call, not change).
- **K2 Sessions.** There is no session handling yet. Part 2 adds vault-held sessions and the A5 canary sessions. If `broker/vault` cannot hold a browser session in the vault process as it stands, that goes to primary as a `lane:primary` issue before part 2 starts.
- **K3 Driver packaging.** `Config.Driver` points at S5's `executor.py`. Part 2 packages it into the sandbox image with Playwright AI-mode snapshots (S5 measured 1.63) and Chromium's headless shell (S5 finding 5: full Chromium connects to Google on launch).
- **K4 Real-driver test.** `TestFixtureThroughTheGate` skips where Playwright lacks AI-mode snapshots. This build environment has 1.56 and the broker CI job has none, so the real-driver path ran in neither. Part 2's acceptance includes a CI job that runs it together with `tests/test_s5_executor.py`.
- **K5 CRED-6.** Actions that reveal or create secrets are not yet classed as irreversible intents. That needs the adapter's operation map (verb, grants); part 2 or ADP-8.
- **K6 Images.** Screenshots and binary downloads are not inspected as images. A secret drawn in a canvas or image is not detected (same limit as S5).
- **K7 Restart.** After a stop, the caller decides whether to start a fresh executor. The gate never restarts itself.
- **K8 Stuck-driver write** (L3 #6). `stdin.Write` runs before the reply timer, so a driver that stops reading can block `Do` while it holds the lock. Request fields are now bounded (G1), so one request fits the pipe buffer, but part 2 puts the write under the same deadline.
- **K9 Request/reply id** (L3 #7). Replies are not matched to requests; a stray driver line answers the next request. Part 2 adds an id the driver echoes.
- **K10 Containers and scan TOCTOU** (L3 #8, widens K6). Compressed containers (zip, gzip, PDF streams) are not inspected, and the driver can rewrite a file after the gate's scan. Part 2 moves the scanned bytes out of the driver's reach (copy to a gate-owned file) and unpacks known containers or withholds them.
- **K11 Label in a neighbouring node** (re-review R3/R1). The label rule needs the label and the value in one line with a separator between them. A label in a neighbouring node (`cell "API token"` then `cell "<hex>"`, `generic: API key` then `code: <hex>`), in prose (`Your API key is <hex>`), with a dash separator, with more words after the label in the same node (`textbox "API Key (read-only)"`, `textbox "Token value"`), or with the value split into groups is not detected, and hex never reaches the entropy bar. Part 1 holds no sessions (K2), so nothing can leak before part 2. Part 2's acceptance adds a node-adjacent rule, an A14 canary in each of these layouts, and one shared positive/negative corpus for the label rule (this PR's canaries and ordinary-text cases, camelCase, initialisms and all-caps included, plus the known misses `accessTOKEN: <hex>`, `accessTokenValue: <hex>` and `access_token_value: <hex>`) that both the gate and S5's protocol.py must pass.
- **K12 Unanchored secret parameter names** (re-review R4, inherited from S5). `secretParam` matches anywhere in a query key, so `?author=` or `?postcode=` is redacted, and a page that links one loses its screenshots (G5). Anchoring it to whole names or `_`/`-` parts would also drop camelCase keys such as `authToken` and `apikey`, so that trade goes with K11's detector work rather than this fix round. The label rule has a similar availability cost in prose: a label word followed by a digit-bearing run (`See the secret 2024-holiday-party-photos album`) is redacted. So does the camelCase branch when an identifier ending in a label word is followed by one (`hotKey 2024-10-08-release-notes`, `useToken 2024-10-08-changelog-entry`, `?sortKey=created_at_2024_desc`). All of these fail closed, are recorded as later, and join part 2's negative corpus.
- **K13 HOME is the output workspace** (re-review R5). Chromium and Playwright per-user state (`.pki`, `.cache`, crash dumps) lands in the directory that holds agent-facing outputs. Hidden names are refused as outputs, but an agent that reads the workspace directly would see that state. Part 2 gives the gate its own output directory (with K10) and puts HOME outside the agent's reach.
- **K14 Password refs** (#211 combined lens, release; closed by #1111, G10). The gate derives the password refs from the snapshot and calls `OmitValues` on every snapshot, so a mislabelled field or a driver that reports none no longer passes a value. What remains: a password input the page gives another role (`role="spinbutton"`, `combobox`) is not omitted, and combobox stays out because omitting a select's option children breaks `select` (#1111, later); a screenshot is judged by the snapshot's CRED-10 matches only, so a mislabelled field's value can show in its pixels (#1111, later); a compromised driver can place text anywhere, and only the vault scrub (G3) and the detector stand behind that. A driver that splits lines on a bare `\r` defeats `OmitValues` (#683 Security 4a, later). A value with C1 control characters is emitted as `\xNN`, which `yamlValue` decodes as a raw byte, so that copy is not matched (#683 Security re-sign, later).
- **K15 GETs the gate cannot see** (ADP-14-get, release). G9 is a pattern heuristic in front of the driver: a state-changing GET with no action word, a redirect, a script-initiated request, a GET form submitted by `type` with `submit` or by `select`, a page that rewrites a link after the snapshot, a button or `role="button"` anchor with a neutral name ("Stop these emails") whose href or form the snapshot does not show, a click handler on an element with no pointer cursor, and a dialog whose "Cancel" button itself acts all reach the site unheld, and the ref map comes from the untrusted driver. A follow-up has the executor report each click target's href and form method so the gate can judge the real URL. Part 2's network egress gate binds submits at the network (CRED-12) and is the boundary for these.
