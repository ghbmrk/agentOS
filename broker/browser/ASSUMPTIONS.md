# broker/browser: assumptions and carry-forward (CRED-4b part 1)

Part 1 is the broker-side gate in front of S5's driver: the closed v0 action protocol (CRED-4), declared-origin checks, and the CRED-10 output filter, all applied outside the driver, which is treated as untrusted because it renders pages written by strangers.

## What the gate guarantees
- **G1** Only the seven v0 verbs exist. Requests with unknown verbs or arguments, wrong JSON types, duplicate keys, oversized fields (`url` 4096, `ref` 32, `option` 1024, `text` 2000 bytes) or anything but whitespace after the object are refused and never reach the driver. The driver receives a canonical re-encoding, never the agent's bytes, so the two sides cannot parse one line differently.
- **G2** `navigate` to an undeclared origin is refused at the gate, in addition to the driver's own routing checks. Hosts must be ASCII: a Unicode host is refused, not mapped, in requests, replies and declared origins alike, because Go's lowercasing and the browser's IDNA (UTS46) can name different hosts (`gİthub.com`). Declare IDN origins in punycode (`xn--`).
- **G3** Every string the driver returns passes the vault's exact-value redactor first, then the CRED-10 detector (ported from S5 `protocol.py`). The gate's detector also redacts a value of 16 or more token characters with a digit after a secret label (key, token, secret, password, api key), which makes it stricter than S5's `protocol.py`. Output file names are filtered too; a match withholds and removes the file. Fields outside `Result` are dropped.
- **G4** A reply whose page URL is off the declared origins, or an `ok` reply with no page URL, means confinement failed. The driver puts `page.url` on every reply. The gate stops the executor (kills its process group) and relays nothing from that page.
- **G5** Before a screenshot, the gate snapshots the page itself; any match from the driver or the gate withholds the screenshot without taking it. After the shot it scans the file's bytes and snapshots again; a match in either removes the file and withholds it.
- **G6** A download whose text carries a vault value or a detector match is removed from the workspace and withheld. Only screenshot and download may name an output file, and it must be a flat name of a regular, singly linked file in the workspace (no symlinks, no hard links); the gate reads it through an `O_NOFOLLOW` descriptor.
- **G7** The driver starts with a fixed environment (PATH, HOME=workspace, LANG, plus `Config.Env`), never the broker's. A missed reply deadline, malformed output or driver exit stops the executor.
- **G8** `OmitValues` replaces the value of a snapshot line whose ref is a password field with `[password omitted]`; the line and its ref stay. The ref is taken only from the attribute run right after the role and quoted name (`[ref=…]` among the bracketed attributes), at any indentation, because the name and the value are page-controlled and can hold a decoy token (#2245 comment 6239829840). Only the canonical shapes `- role "name"` and `- role` followed by nothing, `:`, ` [` or a closing `'` are parsed. Any other line (unterminated or unquoted name, extra spaces, a YAML double-quoted key) cannot be parsed: if any ref on it is a password field, everything after the role is replaced (fail closed). Lines nested deeper under a password line are its children (a field with a placeholder renders its value as `- text: <value>`): every child but `/placeholder` loses its value. A child that is itself a node with another role (`paragraph`, `generic`, a rich-text editor's structure) is not a value; `text` and `/prop` children are, and a child line that cannot be parsed is (fail closed). If a removed value, or a piece of it between `[ref=…]` tokens, of 4 characters or more shows on any line outside the field, its children and its ancestors, the whole snapshot is replaced by `[snapshot withheld: …]` and the verb's outcome stays (#2245). Text the agent put on pages (G10) is handled the same way whether or not it equals a value, once any field on the page is omitted: on an omitted field's lines and ancestors it is scrubbed at any length like the value, and 4 characters or more of it on any other line, a kept typed field's own value aside, withholds the snapshot (PR #2273 reviews). Otherwise the value is replaced on the field's ancestors at any length, after the role, and every other copy in the snapshot, as is, whitespace-collapsed, JSON-escaped, and each of those with `'` doubled to `''` (Playwright single-quotes a key that needs YAML quoting, such as a name holding `: `), because a row, cell, link or button holding the field, or an element labelled by it, carries the value in its accessible name (measured on Playwright 1.56.1, Security 4a on #683). A short value can over-redact other text, which fails closed. A transformed copy of the value (split across nodes, reversed, encoded) is outside what a snapshot filter can catch (#683 L3, later). Moved here from #211's `broker/browseract`.
- **G9** An action that may change state at the site is refused unsent (`approval_required`) and waits for the owner's approval of the exact request (CLK-3, ADP-14-get). With `Config.LoggedOut` set, declaring that the clerk supplies the session no cookies, password or card, only a `navigate`, `click` or `download` to a target the patterns below match needs approval, and clicks, typing and selects are free (D-147). Left unset, identity is unknown and the gate judges fail closed: only `snapshot`, `screenshot`, `type` without `submit`, a `click` into a text field (`textbox`, `searchbox`, `combobox`, `spinbutton`), and a `navigate`, `click` or `download` that follows a `link` to a target G9's patterns do not match are reads. A button, a select, a submit, a container and any element that is not itself a link show the gate no request, so they need approval whatever their name ("Place order"). A URL matches the patterns when a path, query or hash-route word (split on punctuation, letter-digit and camelCase boundaries, adjacent pairs joined so `opt-out` reads `optout`) is an action word or contains an action stem, or a query key names a token; a link also matches when the whole subtree text of the element it activates names an action (`[icon] Unsubscribe`), an unparseable href counts raw, and `Config.StateLinks` adds the recipe's own path prefixes on the declared origins. The refusal carries `to`: the role, quoted name and target of the ref (or the URL of a navigate) after the output filter, so a token the filter redacts shows as `[REDACTED]`. A `click` or `download` on a ref not in the last snapshot the gate saw is refused (`unknown_ref`). Over-matching (a search for "cancel") fails closed.
- **G10** The gate omits password values from every snapshot itself, before the CRED-10 filter, and never takes the driver's word for which fields are passwords (CRED-4, #1111). The refs come from the snapshot alone: every `textbox` or `searchbox` line (the roles Playwright gives an `<input>` or `<textarea>` that can hold a password) that shows a value on its own line or in a child other than `/placeholder`, with or without a ref (a field the page made inert has none, and every such line is omitted). A line with one of those roles that G8 cannot parse gives every ref on it (fail closed). The one exemption is a field whose value is exactly the text the agent typed into that ref, by `type`, on the page the driver named in its reply: nothing leaks, and keying it to the ref and page stops a guess typed elsewhere from telling the agent whether it matches a password. That field's value is never scrubbed, so it reads the same whether or not the text matches a password on the page; every copy elsewhere of an omitted value is scrubbed, typed or not (#2246 reviews 6239557715, 6239610403). A typed record is forgotten once a snapshot shows that field with other text, or empty while the typed text was not, so a value the page refills later is omitted even when it equals the old text (#2245). `spinbutton` is an entry role too (#2245). The gate also keeps the text the agent put on pages, on any page and across stale records: every `type` text, and the query values and fragment of every `navigate` URL (the parts a results page echoes; path segments and query keys name pages such as `account` and would withhold most of them). G8 treats a whole echo of it the same whether or not it matches a password, so a heading that echoes a whole guess, a row holding it beside the field, or a whole query value echoed by a results page does not tell the agent whether the guess was right (#2245, PR #2273 reviews 6240595360, 6240595981). A page that echoes only part of a text (a truncated query, its words listed separately) is matched by the value rule alone, so that echo can still answer a guess; matching every 4-character window of agent text would withhold most pages (release, #2282). Costs: a page that shows an omitted value outside its field is withheld whole, so the agent cannot read it at all; so is a page with any omitted field that shows 4 or more characters of text the agent put on any page outside an omitted field's ancestors and the typed field itself (a search for `shoes` on a page with a pre-filled field withholds it if `shoes` shows anywhere else), and shorter agent text is scrubbed from omitted fields' ancestors; withholding tells the agent one bit per snapshot, whether some field value or some text it put on a page shows elsewhere, and that bit is the same for a right and a wrong guess; text reaching a page by other routes (a path segment, a `select` option, a click, or text the site stored before this gate existed, such as an earlier session's recent searches) is not tracked, but those copies are scrubbed or withheld only when they equal a value, which can still answer a guess placed that way (release, #2282); a value shorter than 4 characters is scrubbed only from its field and ancestors; a plain-text contenteditable rendered `- textbox "M": text` is still omitted; a stale record is forgotten only when a snapshot shows the change. The gate remembers at most 1024 typed refs and 1024 texts. Past either, it forgets nothing and withholds every snapshot with an omitted field for the rest of its life, because a forgotten text's echo would again depend on the guess (PR #2273 security delta 6240743036). `password_fields` in a result is the gate's count of fields omitted; the driver's figure is discarded. G8 follows these rules: a value shorter than 4 characters is omitted only from its own field, not scrubbed from the rest of the page (a quantity of `1` would wipe every price), and the scrub never rewrites a `[ref=…]` token, so clicks keep working. Cost, which fails closed: a pre-filled value the agent did not type (a saved address, a username) is hidden, and the agent must not be relied on to read one.

## The clerk (D-139, CLK-2, CLK-3)
- **C1** `Clerk` is the browser's only exit. Each step passes `clerk.Check` (clerk name, facts, key chain, logged root, limits, hold window), then its `read{query}` line goes to the gate, which sends it only if G9 judges it a read. A `post` step is refused unsent (`approval_required`): no recipe covers any page yet, so no standing key may cover a submit before the owner approves the exact request (CLK-3 unknown submits and first live runs). That approval path is the next row (#2661); until it lands the browser cannot submit forms or press buttons, which main could only hold and never release.
- **C2** The clerk sends only reads, which are safe to run again, so it keeps no memory of what it ran: Probe says `notdone` for every step, in this process or after a restart, and the kernel never parks a browser step (KRN-8).
- **C3** The clerk's result detail is the gate's filtered result, which goes into the log.
- **C4** The clerk's facts give every step no content class, flow label or amount: a read of a page moves no money, and the clerk cannot vouch for a label. A step claiming one, as one typing private-labelled data must, is refused (`claim`), which is D-147's fail-closed case for private data until #2661.
- **K2 Sessions.** There is no session handling yet. Part 2 adds vault-held sessions and the A5 canary sessions. A vault fill into a field must clear the gate's typed record for that ref (G10), or the filled value would read as typed. If `broker/vault` cannot hold a browser session in the vault process as it stands, that goes to primary as a `lane:primary` issue before part 2 starts.
- **K8 Stuck-driver write** (L3 #6). `stdin.Write` runs before the reply timer, so a driver that stops reading can block a step while the gate holds its lock. Request fields are bounded (G1), so one request fits the pipe buffer, but the write still needs the same deadline (#2609).
- **K9 Request/reply id** (L3 #7). Replies are not matched to requests; a stray driver line answers the next request, so a read can return another line's answer. The approval row needs the fix before a submit is ever sent: an id the driver echoes (#2609, #2661).

## Known limits (carried to part 2)
- **K1 Sandbox.** The driver is a child process in its own process group, not yet in a broker-owned VM. Part 2 places it in its own sandbox, one account each (CRED-4), through `vm.Manager` (call, not change).
- **K3 Driver packaging.** `Config.Driver` points at S5's `executor.py`. Part 2 packages it into the sandbox image with Playwright AI-mode snapshots (S5 measured 1.63) and Chromium's headless shell (S5 finding 5: full Chromium connects to Google on launch).
- **K4 Real-driver test.** `TestFixtureThroughTheGate` skips where Playwright lacks AI-mode snapshots. This build environment has 1.56 and the broker CI job has none, so the real-driver path ran in neither. Part 2's acceptance includes a CI job that runs it together with `tests/test_s5_executor.py`.
- **K5 CRED-6.** Actions that reveal or create secrets are not yet classed as irreversible intents. That needs the adapter's operation map (verb, grants); part 2 or ADP-8.
- **K6 Images.** Screenshots and binary downloads are not inspected as images. A secret drawn in a canvas or image is not detected (same limit as S5).
- **K7 Restart.** After a stop, the caller decides whether to start a fresh executor. The gate never restarts itself.
- **K10 Containers and scan TOCTOU** (L3 #8, widens K6). Compressed containers (zip, gzip, PDF streams) are not inspected, and the driver can rewrite a file after the gate's scan. Part 2 moves the scanned bytes out of the driver's reach (copy to a gate-owned file) and unpacks known containers or withholds them.
- **K11 Label in a neighbouring node** (re-review R3/R1). The label rule needs the label and the value in one line with a separator between them. A label in a neighbouring node (`cell "API token"` then `cell "<hex>"`, `generic: API key` then `code: <hex>`), in prose (`Your API key is <hex>`), with a dash separator, with more words after the label in the same node (`textbox "API Key (read-only)"`, `textbox "Token value"`), or with the value split into groups is not detected, and hex never reaches the entropy bar. Part 1 holds no sessions (K2), so nothing can leak before part 2. Part 2's acceptance adds a node-adjacent rule, an A14 canary in each of these layouts, and one shared positive/negative corpus for the label rule (this PR's canaries and ordinary-text cases, camelCase, initialisms and all-caps included, plus the known misses `accessTOKEN: <hex>`, `accessTokenValue: <hex>` and `access_token_value: <hex>`) that both the gate and S5's protocol.py must pass.
- **K12 Unanchored secret parameter names** (re-review R4, inherited from S5). `secretParam` matches anywhere in a query key, so `?author=` or `?postcode=` is redacted, and a page that links one loses its screenshots (G5). Anchoring it to whole names or `_`/`-` parts would also drop camelCase keys such as `authToken` and `apikey`, so that trade goes with K11's detector work rather than this fix round. The label rule has a similar availability cost in prose: a label word followed by a digit-bearing run (`See the secret 2024-holiday-party-photos album`) is redacted. So does the camelCase branch when an identifier ending in a label word is followed by one (`hotKey 2024-10-08-release-notes`, `useToken 2024-10-08-changelog-entry`, `?sortKey=created_at_2024_desc`). All of these fail closed, are recorded as later, and join part 2's negative corpus.
- **K13 HOME is the output workspace** (re-review R5). Chromium and Playwright per-user state (`.pki`, `.cache`, crash dumps) lands in the directory that holds agent-facing outputs. Hidden names are refused as outputs, but an agent that reads the workspace directly would see that state. Part 2 gives the gate its own output directory (with K10) and puts HOME outside the agent's reach.
- **K14 Password refs** (#211 combined lens, release; closed by #1111, G10). The gate derives the password refs from the snapshot and calls `OmitValues` on every snapshot, so a mislabelled field or a driver that reports none no longer passes a value. `spinbutton` and screenshots were closed by #2245: the gate does not take, or discards, a screenshot of a page showing a field value the agent did not type, before or during the shot, so a page with a pre-filled value cannot be shot. What remains: a password input given `role="combobox"` is not omitted, because omitting a select's option children breaks `select`; a compromised driver can place text anywhere, and only the vault scrub (G3) and the detector stand behind that. A driver that splits lines on a bare `\r` defeats `OmitValues` (#683 Security 4a, later). A value with C1 control characters is emitted as `\xNN`, which `yamlValue` decodes as a raw byte, so that copy is not matched (#683 Security re-sign, later).
- **K15 GETs the gate cannot see** (ADP-14-get, release). G9 judges a link or navigate by its URL and name, so a state-changing GET with no action word, a redirect, a script-initiated request on a link click, a page that rewrites a link after the snapshot, and an href the untrusted driver misreports all reach the site as reads; buttons, selects and submits no longer do (G9 fails closed for them). A follow-up has the executor report each click target's href and form method so the gate can judge the real URL. Part 2's network egress gate binds requests at the network (CRED-12) and is the boundary for these.
