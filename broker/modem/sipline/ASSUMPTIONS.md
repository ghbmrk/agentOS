# SIP second line: assumptions

Built for P2-3b against SPEC v0.12 (ADP-12, CRED-1, CH-1, DEP-3): ADP-12's
"owner-held calling account" as a `secondline.Line`, so an owner gets
third-party texts and calls without a second modem. Packages: `sipline`
(the line), `sipsim` (a simulated provider for tests). The `secondline`
tool is unchanged in what it guards: owner-number refusals, the disclosure
that opens every call, untrusted inbound, roles. Each row is a reading of
the spec, or a gap left for a later package, that a reviewer may want to
change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| SL1 | The account is a SIP account at a VoIP provider (registrar plus outbound proxy at one `host:port`), reached only over TLS with the provider's certificate verified against the system roots. A config that turns verification off (`InsecureSkipVerify`, or its own `VerifyConnection` or `VerifyPeerCertificate`) is refused, and TLS is at least 1.2. Plain UDP or TCP SIP is not offered: it would send the account's caller ID, the numbers it texts, and the texts themselves in clear. | ADP-12, CRED-1 | Small: a provider without SIP over TLS is not supported. |
| SL2 | The account password never enters the line's process. Digest challenges go to a `Signer`; the vault side is `sipsign.Account`, which signs only for the realm recorded at setup, only `REGISTER`, `MESSAGE`, `INVITE`, `BYE` and `CANCEL`, and only `qop=auth` challenges (an RFC 2069 challenge has no client nonce), so a process that can ask it to sign cannot use it as a digest oracle for another service sharing the password. `agentos-egress` serves it on `sign.sock` to the modem bridge's uid only, and the bridge signs with `sipsign.Client` (P2-3c, egress K13). `sipsign` links no SIP or SRTP stack, and an import test keeps sipgo, pion and this package out of `agentos-egress` and `agentosd` (#102 security R5, CRED-1). A digest response is still offline-guessable for a weak password, so setup takes only a provider-generated password of at least 12 characters. | CRED-1, ARC-2 | Wiring only. |
| SL3 | The realm is recorded at setup from the first registration over verified TLS, which is trust on first use but only after the certificate check of SL1. The vault process records it from the first `REGISTER` challenge it can answer, within 30 minutes of setup. Texts and calls are signed only once the owner confirms that realm on the local page (egress K13). | CRED-1 | Setup step. |
| SL4 | The line never listens for signaling (each call binds one UDP socket for its own audio). Requests reach it only on its own TLS connection to the provider (the provider's flow back to a registered contact, as every NAT-facing provider does over TLS), so a text or call cannot come from anyone else on the network. Before registering, an `OPTIONS` request learns the connection's local address for the contact; registration is renewed at half the granted lifetime and retried sooner after a failure; `Registered` reports the last outcome, and `Done` closes only on `Close`. | ADP-12 | Small. |
| SL5 | Third-party texts are SIP `MESSAGE` (RFC 3428) with `text/plain`, both ways. Incoming texts must be valid UTF-8 (else 415) and at most 1,600 bytes, ten SMS segments (else 413); any other content type is refused (415). A sender's number is believed only as the provider vouches for it: its `P-Asserted-Identity` (`tel:` or `sip:`), or a `From` in the provider's own domain. Any other sender, or one that is not a phone number, is delivered as `alpha:<name>` (at most 32 printable ASCII characters) with `Alphanumeric` set, as for an alphanumeric SMS sender (at M15), so it can never pass for the owner. Whether real providers put their domain in `From`, and strip a peer's inbound `P-Asserted-Identity`, are P2-3c real-provider checks. The owner texting the second line gets `MainNumberText` and reaches no agent, as on a SIM. | ADP-12, CH-1 | Provider support: an HTTP-API-only SMS provider would need its own `Line`. |
| SL6 | A number reaches a Request-URI only as an optional leading `+` and 3 to 15 digits (separators stripped); anything else is `ErrNumber`, so a "number" cannot name another host or carry URI parameters. `NoPlus` dials without the `+` for providers that want it. | ADP-12 | Small. |
| SL7 | Calls offer G.711 (PCMU, then PCMA) over SRTP with SDES keys (`AES_CM_128_HMAC_SHA1_80`, RFC 4568), which travel only inside the verified TLS. An answer without SRTP under the offer's crypto tag, without an offered codec, or with an audio address that is not public unicast is hung up before anything is said (`ErrNoSRTP`, `ErrMediaAddress`). Loopback and private audio addresses are allowed only when the provider's own signaling address is one, so an answer cannot aim the call's packets at the box's network or its local UI. RTP starts at a random sequence number and timestamp (RFC 3550). Audio is paced in 20 ms frames from the same 8 kHz, 16-bit mono PCM the modem path uses (at M7), so the disclosure audio is shared. | ADP-12 | Medium: a provider without SRTP is not supported; allowing plain RTP would need a ruling. |
| SL8 | One call at a time (`ErrBusy`), as on the modem (at M5). An unanswered call is cancelled with `CANCEL` when the tool's answer wait runs out; one answered is ended with `BYE`; the far end's `BYE` ends it. The far end's audio is read and dropped: speech recognition is a later package (at M13). | ADP-12, CH-5 | Call handler. |
| SL9 | Calls to the line are declined (603). Answering third-party calls, like on the modem, waits on the call handler (at M13); until then they are never picked up. | ADP-12 | Call handler. |
| SL10 | The second line's role is bound to the account's address of record (`Roles.SecondAccount`), recorded at setup, the way a second SIM's role is bound to its ICCID (at M12). The domain compares case-insensitively and the user part case-sensitively (RFC 3261 19.1.4). Roles recorded for both a second SIM and an account, or for neither, are refused (`ErrUnbound`), and an account whose number is the owner line's is refused (`ErrOwnerLine`). | ADP-12, CH-1 | Small. |
| SL11 | Reused: `emiago/sipgo` (SIP parser, transactions, TLS transport, dialogs), `pion/srtp` and `pion/rtp` (SRTP and RTP, as in pion/webrtc), `pion/sdp` (answer parsing) and `icholy/digest` (digest arithmetic, via sipgo). G.711 is 40 lines here, pinned to known values: no maintained Go G.711 module was worth a dependency. | — | — |
| SL13 | Nothing the SIP stack handles reaches a log: sipgo's transport, transaction, client and server loggers, and its process-wide default, all discard, because sipgo logs a whole message it cannot parse (a third party's text, or an SRTP key in SDP). Errors carry status codes, never the provider's reason text. `Account` prints without its password. | CRED-1 | — |
| SL12 | Measured only against `sipsim`. A run against a real provider (registration through NAT, SRTP interop, MESSAGE delivery to a phone) is a check in the wiring row, with the owner's account. | ADP-12 | Findings feed SL1, SL4, SL5, SL7. |
