# SIP second line: assumptions

Built for P2-3b against SPEC v0.12 (ADP-12, CRED-1, CH-1, DEP-3): ADP-12's
"owner-held calling account" as a `secondline.Line`, so an owner gets
third-party texts and calls without a second modem. Packages: `sipline`
(the line), `sipsim` (a simulated provider for tests). The `secondline`
tool is unchanged in what it guards: owner-number refusals, the disclosure
that opens every call, untrusted inbound, roles. Each row is a reading of
the spec, or a gap left for a later package, that a reviewer may want to
change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| SL1 | The account is a SIP account at a VoIP provider (registrar plus outbound proxy at one `host:port`), reached only over TLS with the provider's certificate verified against the system roots. A config that turns verification off (`InsecureSkipVerify`, or its own `VerifyConnection` or `VerifyPeerCertificate`) is refused, and TLS is at least 1.2. Plain UDP or TCP SIP is not offered: it would send the account's caller ID, the numbers it texts, and the texts themselves in clear. | ADP-12, CRED-1 | Small: a provider without SIP over TLS is not supported. |
| SL2 | The account password never enters the line's process. Digest challenges go to a `Signer`; the vault side is `Account`, which signs only for the realm recorded at setup and only `REGISTER`, `MESSAGE`, `INVITE`, `BYE` and `CANCEL`, so a process that can ask it to sign cannot use it as a digest oracle for another service sharing the password. The `Signer` crosses into `agentos-egress` in the wiring row (P2-3c), as `verify.sock` does for code-generator codes (P2-4c). A digest response is still offline-guessable for a weak password; so the setup step (P2-3c) asks for a provider-generated SIP password, not one the owner chose. | CRED-1 | Wiring only. |
| SL3 | The realm is recorded at setup from the first registration over verified TLS (trust on first use, but only after the certificate check of SL1). | CRED-1 | Setup step. |
| SL4 | The line never listens. Requests reach it only on its own TLS connection to the provider (the provider's flow back to a registered contact, as every NAT-facing provider does over TLS), so a text or call cannot come from anyone else on the network. Before registering, an `OPTIONS` request learns the connection's local address for the contact; registration is renewed at half the granted lifetime and retried sooner after a failure. | ADP-12 | Small. |
| SL5 | Third-party texts are SIP `MESSAGE` (RFC 3428) with `text/plain`, both ways. Incoming texts with any other content type are refused (415). A sender whose user part is not a phone number is delivered as `alpha:<name>` with `Alphanumeric` set, as for an alphanumeric SMS sender (at M15), so it can never pass for the owner. The owner texting the second line gets `MainNumberText` and reaches no agent, as on a SIM. | ADP-12, CH-1 | Provider support: an HTTP-API-only SMS provider would need its own `Line`. |
| SL6 | A number reaches a Request-URI only as an optional leading `+` and 3 to 15 digits (separators stripped); anything else is `ErrNumber`, so a "number" cannot name another host or carry URI parameters. `NoPlus` dials without the `+` for providers that want it. | ADP-12 | Small. |
| SL7 | Calls offer G.711 (PCMU, then PCMA) over SRTP with SDES keys (`AES_CM_128_HMAC_SHA1_80`, RFC 4568), which travel only inside the verified TLS. An answer without SRTP, without an offered codec, or without a usable address is hung up (`ErrNoSRTP` for SRTP) before anything is said. Audio is paced in 20 ms frames from the same 8 kHz, 16-bit mono PCM the modem path uses (at M7), so the disclosure audio is shared. | ADP-12 | Medium: a provider without SRTP is not supported; allowing plain RTP would need a ruling. |
| SL8 | One call at a time (`ErrBusy`), as on the modem (at M5). An unanswered call is cancelled with `CANCEL` when the tool's answer wait runs out; one answered is ended with `BYE`; the far end's `BYE` ends it. The far end's audio is read and dropped: speech recognition is a later package (at M13). | ADP-12, CH-5 | Call handler. |
| SL9 | Calls to the line are declined (603). Answering third-party calls, like on the modem, waits on the call handler (at M13); until then they are never picked up. | ADP-12 | Call handler. |
| SL10 | The second line's role is bound to the account's address of record (`Roles.SecondAccount`), recorded at setup, the way a second SIM's role is bound to its ICCID (at M12). The domain compares case-insensitively and the user part case-sensitively (RFC 3261 19.1.4). Roles recorded for both a second SIM and an account, or for neither, are refused (`ErrUnbound`), and an account whose number is the owner line's is refused (`ErrOwnerLine`). | ADP-12, CH-1 | Small. |
| SL11 | Reused: `emiago/sipgo` (SIP parser, transactions, TLS transport, dialogs), `pion/srtp` and `pion/rtp` (SRTP and RTP, as in pion/webrtc), `pion/sdp` (answer parsing) and `icholy/digest` (digest arithmetic, via sipgo). G.711 is 40 lines here, pinned to known values: no maintained Go G.711 module was worth a dependency. | — | — |
| SL12 | Measured only against `sipsim`. A run against a real provider (registration through NAT, SRTP interop, MESSAGE delivery to a phone) is a check in the wiring row, with the owner's account. | ADP-12 | Findings feed SL1, SL4, SL5, SL7. |
