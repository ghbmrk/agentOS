# Modem bridge: assumptions

These were built for P2-3w part 1 against SPEC v0.12 (CH-1, CH-2, CH-10, ADP-12, ARC-2). Each row is either a reading of the spec or a gap left for a later part. A reviewer may want to change any of them.

The pieces are:

- `agentos-modem` (`cmd/agentos-modem`, core in `modem/bridge`), which drives the modems as its own user;
- `bridgeproto`, the owner.sock contract;
- `bridgeclient`, the bridge's side of that socket;
- `modemlink`, agentosd's side: the owner channel's `modem.Modem`.

The design read is [DESIGN.md](DESIGN.md). All three lenses cleared it with conditions (S-B*, U-B*, potency C1/R1/R2).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| B1 | **The bridge is always the client, and nothing it says widens authority.** It reaches agentosd's `owner.sock` (`/run/agentos/owner.sock`) over a socket that admits its uid only: that socket is 0660 and the bridge user's group's, and the directory is widened to 0711 (traversable, not listable) only after every socket has its mode, narrowed to 0700 first on a restart. The SO_PEERCRED check refuses every uid but the bridge's, and the other sockets stay 0600 (security F2, F3, R3 on #170). With the bridge on, agentosd does not serve the raw `message` op, which skips the bridge's checks; `-owner-message` restores it for simulator and test builds only (security F1 on #170). A compromised bridge is an attacker on the cellular path (security S-B1): it reads every text to the owner and can forge any text from the owner's number. Nothing that widens authority rests on SMS alone. A high-tier item needs the code generator or the paper grid, which no text carries. `TestAForgedOwnerTextCannotApproveAHighTierItem` replays every code the bridge saw, plus guesses, against a grant change and shows it stays unapproved, while the owner's code-generator code still approves it through the same path. A low-tier item stays approvable by its texted code, which is CH-10's accepted SMS trust. | CH-1, CH-10, ARC-2 | Low tier would need a second factor. |
| B2 | **agentosd addresses every owner text and stamps every arrival.** `modemlink.Link.Send` texts only the owner's number (`ErrRecipient` otherwise). Inbound texts are at most 1600 bytes of UTF-8, from at most 32 characters (a number is `+` and digits; a named sender is printable ASCII and is never the owner). Texts from anyone but the owner (a named sender, or another number) are set aside and counted before the rate limit and the inbox, so no one else's texts can crowd out the owner's STOP (L3 on #170). The owner's are limited to 20 a minute, with one "dropped" flag past that. agentosd stamps its own receive time and takes no time from the bridge (S-B4).<br><br>**No owner text is lost (L3 on #170).** The modem keeps each text stored until agentosd has taken it (`at.Config.KeepUntilAck`; the bridge acks), so a text survives the bridge, the modem or agentosd going away and is read again at the next open. The bridge checks the SIM serial before any stored text is listed or read (`at.Config.CheckSIM`: a wrong SIM keeps its texts), and tells agentosd the line is ok before reading any. A refused text is offered again for as long as the modem answers while the refusal can pass (paused, limited, or a lost connection), with the line reported ok again before each offer, since agentosd may have restarted and read it as down; waits double up to the reopen interval. While it retries, the bridge reads no further text, so the modem, SIM and SMSC hold the backlog. Each text's ID is derived from its PDUs, the same on every read, and agentosd takes an ID once within `IDTTL` (10 minutes), so a text read again is not taken twice (a repeated approval code would count as a wrong one). Residual: an ID agentosd took before it restarted is forgotten, so a text taken and not yet deleted when both stop at once can be taken twice. A flood with the owner's number spoofed is retried one text at a time and can hold a real STOP behind it; STOP first is a part 2 carry (security R1 at bc36b57).<br><br>Results are fixed codes. `Send` waits `SendWait` for a result from when the bridge takes the text (a poll's wait plus three segments at the modem's 60 s each, plus a margin), and for the texts ahead of it before that, so a text still going out is not reported down; one that still times out is counted (`TimedOut`). The outbox's long poll ends when the bridge hangs up (`sockets.Endpoint.HangupOps`), so no text is handed to a dead bridge. Item IDs are 128-bit random and single-use while outstanding; a result for an unknown or finished ID is ignored and counted (S-B3). | CH-1, CH-2 | — |
| B3 | **The line decides trust (S-B8).** A text on the second line never reaches the owner channel, whatever it claims to be from. In part 1 those texts are refused, and part 2 hands them to the agent as `Untrusted`. The owner line carries texts only while its SIM is the one recorded at setup. The bridge reports `swapped` for a different SIM and `unbound` when none is recorded or the modem has no usable SIM, and agentosd then refuses inbound texts and hands nothing out. | CH-1, ADP-12 | — |
| B4 | **An unusable line fails fast, and nothing is replayed (UX U-B1, U-B2, and UX on #170).** `Send` returns `modem.ErrDown` at once in these cases, and the owner channel's existing handling applies:<br>• the owner line is down, swapped or unbound;<br>• the bridge has been silent for over 2.5 minutes.<br><br>An approval request that fails this way is dropped, so its code is never valid. The agent is told, in fixed words, that the request was not sent: "not sent: the owner's phone line is down; ask again later" (`grants.LineDown`). Asking again reaches the owner once the line is back.<br><br>Each such text is counted, approval requests apart (`owner.RequestSender`). When the line recovers, the owner gets one text ahead of anything queued. For example: "I couldn't text you from 13:05 to 15:20. 2 approval requests and 1 other text didn't reach you; your agent can ask again." The text says the agent can ask again only when a request was lost, and it says "can", not "will", because asking again is the agent's choice. An outage that cost nothing sends nothing.<br><br>A poll that began before the line last recovered is handed nothing, since it may belong to a dead bridge. | CH-2, CH-15 | **Carry, before real hardware (S1/S2; UX on #170):** the channel re-texts still-valid open requests on recovery, as `Reissue` does after a restart. |
| B5 | **The owner line's state shows on the local page only (U-B1, U-B3, U-B4).** `Link.OwnerLineNote` gives the fixed line for the local UI's home page: down "I can't reach my phone modem. Check it's plugged in.", swapped "The SIM in my phone modem changed. Texts to and from you are paused until you confirm it on my Wi-Fi page.", unbound "My phone modem has no SIM, or its number isn't set up. Set it up on my Wi-Fi page.". Nothing shows while the line is fine. STATUS does not carry it, since STATUS cannot reach the owner over a broken line. The local UI runs in its own process and is not wired yet (P2-2), so showing the note is the wiring package's job. | CH-2 | — |
| B6 | **The roles file.** The owner line's SIM serial is read from `-roles` (`/var/lib/agentos/modem/roles.json`, `{"owner_iccid": ...}`) at each open, so a SIM the owner confirms on the local page is taken without a restart. Writing it at setup, and the swap confirmation, belong to the local UI's setup step (P2-2), which already records roles for the second line. The bridge picks the first qualified modem it finds. Telling two modems apart by serial is part 2. | ADP-12, HW-2 | Part 2. |
| B7 | **The unit (S-B7).** `cmd/agentos-modem/agentos-modem.service` sets: own user, `NoNewPrivileges`, an empty capability set, `ProtectSystem=strict`, seccomp `@system-service` minus `@privileged @resources`, `MemoryDenyWriteExecute`, `DevicePolicy=closed` with only the `char-ttyUSB` and `char-alsa` classes, no IP (`IPAddressDeny=any`, Unix sockets only), no view of AgentOS's state but the roles directory, read-only (`TemporaryFileSystem=/var/lib/agentos:ro`, `BindReadOnlyPaths=-/var/lib/agentos/modem`, so a roles file replaced by rename is seen and a missing one reads as unbound; L3 on #170), no number on its command line (read from the environment file), and no view of other processes or System V IPC (`ProtectProc=invisible`, `PrivateIPC`, `RemoveIPC`; security R1 on #170). `ProcSubset=pid` is left off because discovery pairs each modem with its sound card through `/proc/asound`. A static unit cannot name the modems' nodes, which appear under changing names. The udev rule makes only qualified modems' nodes this user's (0600), so the classes allow no more. Part 2's SIP account reaches only its provider, through the egress allow-list. | ARC-2, HW-2 | — |
| B8 | **Residual (S-B6).** Premium-rate and international barring with the carrier is the owner's to set. The second line's setup page and the docs advise it (part 2). Until then, the shared budget is the bound (egress K16). | ADP-12 | Part 2. |
