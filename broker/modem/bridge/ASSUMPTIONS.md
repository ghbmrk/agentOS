# Modem bridge: assumptions

These were built for P2-3w part 1 against SPEC v0.12 (CH-1, CH-2, CH-10, ADP-12, ARC-2). Each row is either a reading of the spec or a gap left for a later part. A reviewer may want to change any of them.

The pieces are:

- `agentos-modem` (`cmd/agentos-modem`, core in `modem/bridge`), which drives the modems as its own user;
- `bridgeproto`, the owner.sock contract;
- `bridgeclient`, the bridge's side of that socket;
- `modemlink`, agentosd's side: the owner channel's `modem.Modem`.

The design read is [DESIGN.md](DESIGN.md). All three lenses cleared it with conditions (S-B*, U-B*, potency C1/R1/R2).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| B1 | **The bridge is always the client, and nothing it says widens authority.** It reaches agentosd's `owner.sock` over a socket that admits its uid only. A compromised bridge is an attacker on the cellular path (security S-B1): it reads every text to the owner and can forge any text from the owner's number. Nothing that widens authority rests on SMS alone. A high-tier item needs the code generator or the paper grid, which no text carries. `TestAForgedOwnerTextCannotApproveAHighTierItem` replays every code the bridge saw, plus guesses, against a grant change and shows it stays unapproved, while the owner's code-generator code still approves it through the same path. A low-tier item stays approvable by its texted code, which is CH-10's accepted SMS trust. | CH-1, CH-10, ARC-2 | Low tier would need a second factor. |
| B2 | **agentosd addresses every owner text and stamps every arrival.** `modemlink.Link.Send` texts only the owner's number (`ErrRecipient` otherwise). Inbound texts are at most 1600 bytes of UTF-8, from at most 32 characters (a number is `+` and digits; a named sender is printable ASCII and is never the owner). They are limited to 20 a minute, with one "dropped" flag past that. agentosd stamps its own receive time and takes no time from the bridge (S-B4). Results are fixed codes. Item IDs are 128-bit random and single-use while outstanding; a result for an unknown or finished ID is ignored and counted (S-B3). | CH-1, CH-2 | — |
| B3 | **The line decides trust (S-B8).** A text on the second line never reaches the owner channel, whatever it claims to be from. In part 1 those texts are refused, and part 2 hands them to the agent as `Untrusted`. The owner line carries texts only while its SIM is the one recorded at setup. The bridge reports `swapped` for a different SIM and `unbound` when none is recorded or the modem has no usable SIM, and agentosd then refuses inbound texts and hands nothing out. | CH-1, ADP-12 | — |
| B4 | **An unusable line fails fast, and nothing is replayed (UX U-B1, U-B2).** While the owner line is down, swapped or unbound, or the bridge has been silent for over 2.5 minutes, `Send` returns `modem.ErrDown` at once, and the owner channel's existing handling applies (an approval request is dropped, so its code is never valid). Each such text is counted. When the line recovers, the owner gets one text ahead of anything queued: "I couldn't text you from 13:05 to 15:20. 3 texts weren't sent; see my Wi-Fi page." An outage that cost nothing sends nothing. A text that is still valid is not resent, because no caller retries and the channel has no queue of its own. The re-send half of U-B2 needs the channel to re-text its open requests on recovery, as `Reissue` does after a restart; that is carried to the wiring package. A poll that began before the line last recovered is handed nothing, since it may belong to a dead bridge. | CH-2, CH-15 | Re-text valid open requests on recovery. |
| B5 | **The owner line's state shows on the local page only (U-B1, U-B3, U-B4).** `Link.OwnerLineNote` gives the fixed line for the local UI's home page: down "I can't reach my phone modem. Check it's plugged in.", swapped "The SIM in my phone modem changed. Texts to and from you are paused until you confirm it on my Wi-Fi page.", unbound "My phone modem has no SIM, or its number isn't set up. Set it up on my Wi-Fi page.". Nothing shows while the line is fine. STATUS does not carry it, since STATUS cannot reach the owner over a broken line. The local UI runs in its own process and is not wired yet (P2-2), so showing the note is the wiring package's job. | CH-2 | — |
| B6 | **The roles file.** The owner line's SIM serial is read from `-roles` (`{"owner_iccid": ...}`) at each open, so a SIM the owner confirms on the local page is taken without a restart. Writing it at setup, and the swap confirmation, belong to the local UI's setup step (P2-2), which already records roles for the second line. The bridge picks the first qualified modem it finds. Telling two modems apart by serial is part 2. | ADP-12, HW-2 | Part 2. |
| B7 | **The unit (S-B7).** `cmd/agentos-modem/agentos-modem.service` sets: own user, `NoNewPrivileges`, an empty capability set, `ProtectSystem=strict`, seccomp `@system-service` minus `@privileged @resources`, `MemoryDenyWriteExecute`, `DevicePolicy=closed` with only the `char-ttyUSB` and `char-alsa` classes, and no IP (`IPAddressDeny=any`, Unix sockets only). A static unit cannot name the modems' nodes, which appear under changing names. The udev rule makes only qualified modems' nodes this user's (0600), so the classes allow no more. Part 2's SIP account reaches only its provider, through the egress allow-list. | ARC-2, HW-2 | — |
| B8 | **Residual (S-B6).** Premium-rate and international barring with the carrier is the owner's to set. The second line's setup page and the docs advise it (part 2). Until then, the shared budget is the bound (egress K16). | ADP-12 | Part 2. |
