# Modem driver: assumptions

Built for PLAN P2-3 against SPEC v0.12 (HW-2, CH-1, CH-5, CH-17, ADP-12) on
top of the P1-5 owner channel and its carrier simulator (`broker/modem`).
Packages: `at` (driver), `atsim` (AT-level simulator on the P1-5 carrier),
`secondline` (ADP-12). Each row is a reading of the spec, or a gap left for
a later package, that a reviewer may want to change. What only real
hardware can settle is in [S2-CONFIRM.md](S2-CONFIRM.md).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| M1 | The broker drives the modem's AT port itself rather than through ModemManager. ModemManager runs AT commands only in debug mode, has no call-audio path, and would make a D-Bus client the broker's first external module; the S2 test kit uses it only to test the modem. The production image (P2-1) must keep ModemManager off the modem's ports (`ID_MM_DEVICE_IGNORE` or not installed). | HW-2, DEP-1 | Medium: a ModemManager backend behind the same `modem.Modem`. |
| M2 | Both vendors run in PDU mode (`AT+CMGF=0`), so the character set never depends on firmware. The codec is checked against published 3GPP vectors and fuzzed. GSM-7 and UCS-2 are read; 8-bit and compressed texts are dropped. | CH-1, CH-12 | Small. |
| M3 | A received text is deleted from the modem before it is delivered: a crash loses it rather than replaying it, since a replayed approval code would count as a wrong code (CH-18). The owner resends a lost text. Texts stored while the broker was down, or whose `+CMTI` notice was lost, are found by a sweep at start and every 30 s. | CH-1, CH-18 | Small: `receive`. |
| M4 | A concatenated text is delivered only whole. Parts wait at most 10 minutes; at most 32 texts are being reassembled, the oldest dropped first, so forged parts cannot grow memory. Drops are counted (`Dropped`). | CH-1 | Constants. |
| M5 | One call at a time. Waiting and held calls are ignored, so they ring out. `Calls` offers an incoming call while it rings; whether to answer is the caller's decision. The broker's call handler, not built here, answers only the owner's number on the owner line and treats any other caller as untrusted (ADP-12). | CH-5, ADP-12 | Call handler in integration. |
| M6 | Keypad presses are decoded in the broker from the call audio by default (the S2 kit's Goertzel decoder, ported), or from the modem's own DTMF reports (`KeysModem`) if S2 shows VoLTE keeps tones out of the audio. Either way the uplink passes a gate that holds audio back 60 ms and zeroes every frame near a tone, using a looser test than decoding, so the speech service never receives a tone it could decode. `Speech` carries only gated audio; `Keys` carries the keys. Wiring `Keys` into the owner channel's code checks needs a call input on `owner.Channel`, which is integration work. | CH-5, CH-17 | `KeySource` per S2; gate constants. |
| M7 | Call audio is 8 kHz, 16-bit, mono on both vendors, in 20 ms frames. Downlink is paced at real time. A slow speech reader loses audio frames, never keys and never the modem's responses. | CH-5 | S2 latency results. |
| M8 | The Quectel UAC flag persists in the modem. `Open` never changes it; `EnsureUAC` sets it once (the setup step), the modem restarts, and the caller reopens it. Without it, calls connect with no audio (`ErrNoAudio`). | HW-2 | Small. |
| M9 | Only qualified models are driven: `Open` refuses a modem whose `AT+CGMM` does not match its profile before any vendor command is sent. | HW-2 | Add a `Profile`. |
| M10 | After a command times out, the next one first resynchronizes with a bare `AT`, so a late `OK` is not taken as the answer to a later command. Numbers reach `ATD` only as `+` and digits. | — | — |
| M11 | When the modem disappears, `Done` closes, `Send` returns `modem.ErrDown`, and calls end. Re-discovering and reopening it is the daemon's job (integration), as is telling the owner. | CH-1 | Supervisor in integration. |
| M12 | ADP-12's second line is a second modem with its own SIM (the S2 pair qualifies). `secondline` refuses a second line that is the owner's modem or has the owner line's number, refuses one whose number is unknown, and with no second line reports itself unavailable and sends nothing. Every call plays the broker's disclosure audio in full before `Call` returns. Inbound texts come out as `Untrusted`, a type the owner channel cannot take; inbound calls to the second line are not answered. Dual-SIM or eSIM modems and owner-held calling accounts are not built. Recipient verification, the default businesses-and-contacts rule, third-party rate limits and transcript journaling belong to the adapter that maps `send` onto this tool. | ADP-12, DEP-3, CH-1 | Adapter package. |
| M14 | Wiring for integration (from P2-2, PR #32): until setup has an owner, the daemon's modem loop passes texts from this driver's `Inbox` to `localui.Server.OfferText`; whoever calls `Hooks.Finish` then starts `owner.Channel` on the same `at.Modem`, calls `SetOwner`, and sends `AllSetText`. Only one reader may drain `Inbox` at a time. | ONB-1, CH-1 | Integration. |
| M13 | Out of scope here: speech recognition and synthesis (local by default, CH-5), the call handler and its preemption of experiments (RES-1), and CH-17's "text the pending batch when the keypad can't be used". | — | Later packages. |
