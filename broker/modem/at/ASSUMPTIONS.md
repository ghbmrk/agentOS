# Modem driver: assumptions

Built for PLAN P2-3 against SPEC v0.12 (HW-2, CH-1, CH-5, CH-17, ADP-12) on
top of the P1-5 owner channel and its carrier simulator (`broker/modem`).
Packages: `at` (driver), `atsim` (AT-level simulator on the P1-5 carrier),
`secondline` (ADP-12). Each row is a reading of the spec, or a gap left for
a later package, that a reviewer may want to change. What only real
hardware can settle is in [S2-CONFIRM.md](S2-CONFIRM.md).

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| M1 | The broker drives the modem's AT port itself rather than through ModemManager. ModemManager runs AT commands only in debug mode, has no call-audio path, and would make a D-Bus client the broker's first external module; the S2 test kit uses it only to test the modem. The production image (P2-1) must keep ModemManager off the modem's ports (`ID_MM_DEVICE_IGNORE` or not installed), and installs [udev/71-agentos-modem.rules](udev/71-agentos-modem.rules) to `/usr/lib/udev/rules.d/`: every serial node of both vendors and the Quectel sound card are mode 0600, owned by the `agentos-modem` user and group (never `dialout` or `audio`), the `uaccess` tag is removed so a desktop seat, if the image ever gets one, gains no ACL on them, and ModemManager is told to ignore the modems. The image must create that user and run the broker's modem process as it. No image tree exists yet, so P2-1's brief carries this (arbitrator ruling on #33). | HW-2, DEP-1 | Medium: a ModemManager backend behind the same `modem.Modem`. |
| M2 | Both vendors run in PDU mode (`AT+CMGF=0`), so the character set never depends on firmware. The codec is checked against published 3GPP vectors and fuzzed. GSM-7 and UCS-2 are read; 8-bit and compressed texts, silent Type-0 (TP-PID 0x40) and replace-message (0x41–0x47) texts are dropped. A Go PDU library (e.g. warthog618/sms) was not reused: the broker has no external modules, so one would be its first dependency and add an audit surface (A9), for about 400 lines of code that are pinned to published vectors. | CH-1, CH-12 | Small. |
| M3 | A received text is deleted from the modem before it is delivered: a crash loses it rather than replaying it, since a replayed approval code would count as a wrong code (CH-18). The owner resends a lost text. Texts stored while the broker was down, or whose `+CMTI` notice was lost, are found by a sweep at start and every 30 s. A stored line whose length disagrees with its header (a stray boot line) is left for the next sweep, never deleted unread. A PDU already delivered in the last 10 minutes is dropped, so a delete the modem did not perform cannot replay a code. | CH-1, CH-18 | Small: `receive`. |
| M4 | A concatenated text is delivered only whole. Parts wait at most 10 minutes; at most 32 texts are being reassembled, so forged parts cannot grow memory. 4 of the 32 slots are the owner's number's alone (an alphanumeric sender spelling it is a stranger), and any one sender keeps at most 4 texts pending; a new text drops the oldest of its own sender's, then of its own class's (owner or strangers), never another class's, so a flood of first parts cannot push the owner's long text out before its last part arrives (SR2-7, security review 2 finding 7). Strangers can still evict each other's partial texts, and a sender who spoofs the owner's number can evict the owner's own; carrier sender spoofing is outside what the modem can check. Two different bodies for the same part (a spoofer who guessed the reference) drop the whole text; on the owner line (`Config.Owner`) the owner gets the fixed "Message garbled, please resend.", at most once an hour. Drops are counted (`Dropped`). | CH-1 | Constants. |
| M5 | One call at a time. Waiting and held calls are ignored, so they ring out. `Calls` offers an incoming call while it rings; whether to answer is the caller's decision. The broker's call handler, not built here, answers only the owner's number on the owner line and treats any other caller as untrusted (ADP-12). | CH-5, ADP-12 | Call handler in integration. |
| M6 | Keypad presses are decoded in the broker from the call audio by default (the S2 kit's Goertzel decoder, ported), or from the modem's own DTMF reports (`KeysModem`) if S2 shows VoLTE keeps tones out of the audio. Downlink audio, which comes from the untrusted speech service, has any frame holding a keypad tone zeroed before it reaches the call. Either way the uplink passes a gate that holds audio back 60 ms and zeroes every frame near a tone, using a looser test than decoding, so the speech service never receives a tone it could decode. `Speech` carries only gated audio; `Keys` carries the keys. Wiring `Keys` into the owner channel's code checks needs a call input on `owner.Channel`, which is integration work. | CH-5, CH-17 | `KeySource` per S2; gate constants. |
| M7 | Call audio is 8 kHz, 16-bit, mono on both vendors, in 20 ms frames. Downlink is paced at real time. A slow speech reader loses audio frames, never keys and never the modem's responses. | CH-5 | S2 latency results. |
| M8 | The Quectel UAC flag persists in the modem. `Open` never changes it; `EnsureUAC` sets it once (the setup step), the modem restarts, and the caller reopens it. Without it, calls connect with no audio (`ErrNoAudio`). | HW-2 | Small. |
| M9 | Only qualified models are driven: `Open` refuses a modem whose `AT+CGMM` does not match its profile before any vendor command is sent. | HW-2 | Add a `Profile`. |
| M10 | After a command times out, the next one first resynchronizes with a bare `AT`, so a late `OK` is not taken as the answer to a later command. Numbers reach `ATD` only as `+` and digits. | — | — |
| M11 | When the modem disappears, `Done` closes, `Send` returns `modem.ErrDown`, and calls end. Re-discovering and reopening it is the daemon's job (integration), as is telling the owner. That supervisor runs `Roles.Check` again after every reopen, before either line is used, and arrives in the same package as M14. The digest gets "Texting was down HH:MM–HH:MM" after a modem outage, and second-line missed calls and texts. | CH-1 | Supervisor in integration. |
| M12 | ADP-12's second line is a second modem with its own SIM (the S2 pair qualifies), or an owner-held SIP account (P2-3b, [sipline](../sipline/ASSUMPTIONS.md), bound by `Roles.SecondAccount`). Roles are bound to each SIM's serial (ICCID), recorded when the owner assigns the lines at setup, not to USB order or the SIM's stored number: `Roles.Check` fails closed when an ICCID is unknown or unrecorded, when one SIM holds both roles, or when the owner line is missing, and names a swap (`ErrSwapped`) when the modems trade ports. It also refuses a second line with the owner line's number. Third-party texts and calls never go to the owner's phone or either box number, so the agent cannot ask the owner for a code over the second line (CH-19). A text arriving on the second line from the owner's number, real or forged, reaches neither an agent nor the owner channel; the owner gets a fixed pointer to the main number, at most once an hour. With no second line the tool reports itself unavailable and sends nothing; with one, `New` refuses a configuration without the owner's number and home country code, since the guards above would otherwise pass everything. Every call plays the broker's disclosure audio in full before `Call` returns. Inbound texts come out as `Untrusted`, a type the owner channel cannot take; inbound calls to the second line are not answered (the adapter should answer them with a fixed "This number can't take calls. Please text it."). Dual-SIM or eSIM modems and owner-held calling accounts are not built. Recipients are full international numbers (E.164, at least 8 digits) outside the premium-rate ranges on `smsapi.Premium`'s list, unless `Config.Contact` says the owner made the number a contact; the owner's own and the box's numbers stay refused even as contacts (SR2-5). A second SIM's texts and calls spend one budget held by the tool (`smsapi.Budget`: 30 an hour, 200 a day, 10 an hour per recipient, calls also at most 10 an hour and 50 a day); a calling account's budget is the vault process's, which INVITE signing spends too (egress K16), and the vault process knows no contacts, so a short-code contact can be texted or called only from a second SIM. It is in memory, so a restart of the modem bridge starts it again. `Config.Contact` must answer yes only for contacts the owner created, by exact number (security R1 on #164). Carry to the call-handling row: a per-call maximum, such as 60 minutes, so one call cannot run unbounded (security R2 on #164). `dialable` and `encodeAddr` stay a syntax gate only: the owner channel uses the same driver, and an owner's short-code contact must pass it. Recipient verification against owner contacts or a source, the default businesses-and-contacts rule, and transcript journaling belong to the adapter that maps `send` onto this tool. | ADP-12, DEP-3, CH-1 | Adapter package. |
| M13 | Out of scope here: speech recognition and synthesis (local by default, CH-5), the call handler and its preemption of experiments (RES-1), and CH-17's "text the pending batch when the keypad can't be used". | — | Later packages. |
| M14 | Wiring for integration (from P2-2, PR #32): until setup has an owner, the daemon's modem loop passes texts from this driver's `Inbox` to `localui.Server.OfferText`; whoever calls `Hooks.Finish` then starts `owner.Channel` on the same `at.Modem`, calls `SetOwner`, and sends `AllSetText`. Only one reader may drain `Inbox` at a time. | ONB-1, CH-1 | Integration. |
| M15 | A sender given as an alphanumeric ID (TP-OA type 101) can spell any 11 characters, including an owner number. It is delivered with `Alphanumeric` set and `From` prefixed `alpha:`; the owner channel skips such texts before matching numbers, and `SameNumber` never matches an `alpha:` address. Numeric senders and callers are written as E.164 using the home country code from setup (`Config.CountryCode`), so the owner's texts match their number whether the network sends it international, national, or with a trunk or exit prefix, including an exit prefix or trunk 0 written after `+` (`+0044…`, `+4407…`). Italy, San Marino and the Vatican keep the 0 after the country code. | CH-1, CH-18 | Small. |
| M16 | SIM, registration and signal are read at `Open` (which waits up to 10 s for a SIM still starting, `+CME ERROR: 14` or `NOT READY`, as after the `AT+CFUN=1,1` restart), on every `+CPIN`, `+CEREG` or `+CREG` notice, and at each 30 s sweep (`Status`). `Open` returns a `SIMError` when the SIM is missing or locked. `Status.Line` is one plain sentence for the local UI (P2-2): no SIM, PIN-locked, SIM not readable yet, refused by the carrier (including LTE emergency-only, `+CEREG` 8), no signal, searching, or connected with 0–4 bars (SMS-only and CSFB-not-preferred registrations, 6, 7, 9 and 10, count as connected). The box never asks for a PIN by text or voice (CH-6). The ICCID identifies the SIM and is kept only in the broker's configuration, never logged. | §8.1, CH-1, CH-6 | P2-2 shows `Line`. |
| M17 | Carrier network time (`NetworkTime`, TIM-1) is read on demand for the box's clock check and never sets the box clock: Quectel `AT+QLTS=1`, SIMCom `AT+CCLK?` after a best-effort `AT+CTZU=1`; a SIMCom clock before 2025 counts as never set. Readings are confirmed by S2 C14 and C15; the guard is `broker/clock` (K2). | TIM-1 | Per vendor profile. |
