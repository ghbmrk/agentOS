# Vault and credentialed egress: assumptions

Built for PLAN P1-3 against SPEC v0.12 (PR #15) on top of the broker
skeleton (PR #19). Covers `broker/vault` and `broker/egress`; the K rows
are P2-4a (key slots and the vault process `cmd/agentos-egress`). Each row is a
reading of the spec, or a gap left for a later package, that a reviewer may
want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| V1 | The vault is one AES-256-GCM sealed file, names and values both sealed, replaced atomically, mode 0600. Its 32-byte data key is random and never on the drive in the clear: it is wrapped under key slots in a keys file beside it (K1, P2-4a). `Create`/`Open` with a raw key remain for tests and the slot code. | CRED-1, CRED-8, DEP-1 | The file format is versioned. |
| V2 | Only `egress` and the vault process `cmd/agentos-egress` (P2-4a) may import `vault`; `vault/imports_test.go` enforces it. The daemon `cmd/agentosd` may not: it is on the ARC-2 control path. Inside the trusted broker process Go cannot hide memory, so custody rests on this import rule plus `Secret` formatting as a placeholder under every `fmt` verb, JSON, and text marshaling, including inside unexported struct fields (the bytes sit behind a pointer). `Close` zeroes the vault's own copies only; `Reveal` strings and redactor patterns are immutable Go strings. The vault's one third-party import is `golang.org/x/crypto/argon2` (K2). | CRED-1, ARC-1, ARC-2 | Add an importer only with a reviewed reason. |
| V3 | Values shorter than 12 bytes are refused, so CRED-7 redaction cannot shred innocent text. Passwords for credentialed browsers (P2-6) may need a different redaction rule. | CRED-7 | P2-6. |
| V4 | Redaction matches each value verbatim; as base64 (standard and URL-safe) at all three byte alignments, so a value inside a larger blob such as `base64("Bearer "+key)` is caught; as hex in any letter case; URL query and path escaping; and JSON string escaping. A value fully rewritten with arbitrary `\u` escapes, or split by a transform the redactor does not know, is not caught: redaction is defense in depth, custody does not rely on it. Streams hold back at most the longest pattern minus one byte. | CRED-7 | Add encodings in `NewRedactor`. |
| V5 | After `Close` every call fails (`ErrClosed`), so a late `Put` cannot rewrite the file with only the new entry. | CRED-1 | — |
| V6 | Rollback: an older sealed vault file still opens with the same key, so an attacker with the drive could restore a revoked credential. P2-4b binds a TPM NV monotonic counter into the AAD (or the sealed key slot); the passphrase slot alone cannot, since nothing on the drive is trustworthy against a drive copy. | CRED-8, REC-2 | P2-4b, on hardware. |
| E1 | Guest path is `/<adapter>/<upstream path>`. A request is forwarded only if the path is clean (no `.`/`..`/empty segments, nothing percent-escaped), has no query, and matches a declared operation's method and path template exactly. Everything else is denied with 403 and reported. No normalization: ambiguous means denied. | ADP-10 | Declared query parameters, and GraphQL/JSON-RPC body schemas, arrive with the first adapter that needs them. |
| E2 | Built-in relays declare inference only. OpenAI: `POST /v1/chat/completions`, the one route ARC-6 (a) qualifies. Anthropic: `POST /v1/messages`, declared but **not qualified** as a guest interface until a guest needs it (ARC-6 (a)); no grant should name it before then. `/v1/responses`, model listing, files, batches, key management, and billing are undeclared, so denied. | CRED-5, ADP-10, ARC-6 | Add an operation per qualified need. |
| E3 | Request headers are an allowlist (`Content-Type`, `Accept`, `User-Agent`, plus adapter-declared). An adapter may not declare `Location`, `Accept-Encoding`, `Content-Encoding`, `OpenAI-Organization`, `OpenAI-Project`, `Anthropic-Beta` (betas switch on server tools), or any name containing auth, key, token, session, cookie, secret, or password. So a guest's own key, cookie, org, or project header is dropped, and the vault credential is the only one sent. | CRED-5, A14 | Small: `credentialHeaders`. |
| E4 | The proxy sends `Accept-Encoding: identity` and refuses (502) any response with any other `Content-Encoding` value, in any header line or list, and sets `Content-Type: application/json` itself on rule-checked bodies, since compressed bytes would pass the redactor unread. Responses keep only allowlisted headers (`Location`, `Set-Cookie` never), redirects are returned rather than followed (the key is never re-sent elsewhere), and headers and body pass the redactor. | CRED-1, CRED-7 | Small: `baseResponseHeaders`. |
| E5 | Grants are a static machine → adapter table given at construction. The grant store and grant-change intents (OP-5) are a later package. Model access itself is ARC-6 (a) for any granted machine; the REV-5 data label, read from `Config.Label`, gates what the provider may fetch on the machine's behalf (E10). | OP-5, REV-5 | Swap `Config.Grants` for a lookup. |
| E6 | Decisions go to an `Auditor`, which `New` requires; events carry no header or body content. `JournalAuditor` (P1-7) journals denials as `egress` records (`journal.RecordEgress`: machine, adapter, operation, method, status, a redacted reason), outside any intent and never held by STOP. Per machine and reason, the first denial in a minute is journaled and the rest are counted into the next record's `suppressed`, so a looping guest cannot fill the journal. Allowed calls are not journaled one by one; the OP-8 meter counts them. | ADP-10 | — |
| E7 | Not linked into `agentosd` (V2). The vault process `cmd/agentos-egress` holds the unlocked vault and serves the proxy behind every machine's model route: `agentosd` meters the route (E8) and forwards it there (`broker/modelroute`, K4). `Proxy.HandlerFor` takes each request's machine, REV-5 label, and auditor from the forwarding broker. Until the vault is unlocked (K5) the route answers 503. `e2e/a14_test.go` still composes the chain in one process as the A5 canary target; `cmd/agentos-egress` `TestUnknownHostUnlockThenModelRoute` runs it across the two sockets. | ARC-2, ARC-6, CRED-1 | — |
| E8 | OP-8 spend metering lives in `broker/meter`, applied by the guest plane in front of the model route, so every model call is counted by machine identity at the socket before this proxy sees it, and settled to the usage the provider reports (G7). The OpenAI relay forces `stream_options.include_usage` on streamed calls for that. The meter runs this handler on a context the guest cannot cancel and keeps accepting writes after the guest hangs up, so the upstream read finishes. `Config.Cap` stays as a second, hard per-machine ceiling, and `MaxConcurrent` (default 4) bounds one machine's requests in flight (each buffers up to 8 MiB). The default transport bounds connect (30 s), TLS handshake (10 s), and wait for response headers (10 min). | OP-8 | — |
| E9 | Every `Operation` declares an ADP-2 verb class from a closed list; `New` refuses an unlisted one. Only `read` operations are forwarded without an intent: any other verb is denied 403 until proxied effects submit a journal intent per call. Model inference is declared `read` (no effect on an external account). | ADP-10, ADP-2 | Submit an intent per call when the first effectful adapter arrives. |
| E10 | Relay bodies must be one JSON object. The proxy re-encodes what it checked, so no duplicate keys or trailing data reach the provider. `background` is always denied, and OpenAI bodies always get `store:false`. Provider-side fetches follow the calling machine's REV-5 label (arbitrator ruling). `BodyRule.PublicMayFetch` opts in, so a rule that leaves it unset is strict for every machine. Provider-side fetches are remote content sources (a non-`data:` string under `url`, `image_url`, `file_url`, `document_url`, `audio_url`, `video_url`, or `server_url`, anywhere outside JSON schemas and client `tool_use` input; e.g. OpenAI `image_url`, Anthropic `image`/`document` `source:{type:"url"}`), plus a `tools[]` entry whose `type` is not absent, `function`, or `custom`, plus `mcp_servers`, `container`, and OpenAI `web_search_options`. They are admitted only when `Config.Label` returns exactly `public`. A private or unknown label is denied. On the box `Label` is `vm.Manager.DataLabel`, which answers `public` only for a known machine labelled public and `private` for an unknown machine or any lookup error; `agentosd` sends that answer as `Agentos-Label` to the vault process, which passes it to `Proxy.HandlerFor` per request (K4); `e2e/a14_test.go` uses the same contract. A nil `Label` makes every machine unknown, so all of them are denied. Anthropic client tools with schema-less types (`bash_*`, `text_editor_*`, `computer_*`) count as provider-side, which is stricter than needed. `Anthropic-Beta` is dropped for every label (an empty allowlist), so Anthropic server tools that need a beta flag do not work even for public machines yet. | ADP-10, REV-5, A14 | Admit a tool type or beta value only with a reviewed reason. |
| K1 | Key slots (P2-4a): `vault.keys` beside the vault, JSON, mode 0600, replaced atomically. Each slot wraps the data key (AES-256-GCM) under a key-encryption key from its factor, with the slot's kind, KDF parameters, and any sealed blob bound in as associated data, so an edited or relabelled slot opens nothing. Kinds are a closed list: `passphrase` (this build), `tpm` (P2-4b), `recovery` (REC-1). A known kind this build cannot open still loads and survives `Rekey`; an unknown kind or version fails the whole file closed. `Factor` (Kind, Enroll, KEK) is the seam the TPM factor implements. `Rekey` proves one factor and replaces every slot of the other's kind, which is passphrase replacement (CRED-8, REC-4); a copy of the keys file taken earlier still opens with the old passphrase, as CRED-8 says. | CRED-8 | P2-4b adds the TPM factor. |
| K2 | Argon2id is `golang.org/x/crypto/argon2` at v0.33.0, the last x/crypto release that builds with the module's go 1.22, pinned in `go.sum` and vendored under `broker/vendor` so the broker builds offline (DEP-1; the A9 offline scenario compiles from source with no module cache). It is the Go project's own implementation; hand-rolling Argon2 and BLAKE2b in the custody path would be the riskier choice. Only the vault imports it (not `agentosd`, which stays third-party-free under ARC-2). New slots get 256 MiB, 3 passes, 4 lanes: about 1 s on a 4-core cloud host. Tuning to about 1 s on the N95 (HW-4) waits for the hardware. Before deriving, a slot below 256 MiB or 1 pass, or with a salt under 16 bytes, is refused, so a keys file cannot make a guess cheap; one above 2 GiB, 20 passes, or 16 lanes is refused, so it cannot exhaust the box either.  DEP-1 reading (accepted in the #29 review): DEP-1 governs what boot, owner control, the journal and recovery need at run time, and a vendored, hash-pinned library compiled into the binary needs nothing at run time; DECISIONS.md allows near-zero external dependencies, and the build stays offline. | CRED-8, HW-4, DEP-1 | Raise the x/crypto pin with the module's Go version. |
| K3 | Passphrase normalization: lowercase, and runs of whitespace become one space, so a scan and a typed copy agree. This is exactly `card.NormalizePassphrase` (P2-2, #32), whose seven EFF words the card prints and whose QR code holds the plain passphrase; hyphens stay, since some word-list entries contain one. Enrollment refuses fewer than 20 normalized characters; strength comes from the generator. `agentos-egress init` generates 100 bits as five space-separated groups of four base32 characters and prints it once with the code-generator `otpauth` URI (label `AgentOS`). It builds both files under temporary names and renames the keys file last, so a crash leaves nothing openable or a complete vault; a vault left without its keys file is reported for removal. The normalized passphrase bytes are wiped after each slot call. This stands in for the Owner Card until P2-2 prints the real one (with words, CRED-8's example). | CRED-8, §8.1 | P2-2. |
| K4 | Process split: `agentos-egress` runs as its own uid and alone reads the vault and keys files. Its run directory is 0711 (reachable, not listable); `model.sock` admits only `agentosd`'s uid and `unlock.sock` only the local UI's uid, by SO_PEERCRED, and `serve` refuses an unlock uid equal to the broker's, so the passphrase never passes through `agentosd`. `agentosd` forwards each machine's metered model route there and sets `Agentos-Machine` and `Agentos-Label` from its own state, dropping any `Agentos-*` header the guest sent; an unknown label is sent as private. The vault process returns a denial in an `Agentos-Egress-Denial` response header, which `agentosd` strips and journals under the machine it forwarded for (E6). The vault process down, or the vault not open, is 503. | ARC-1, ARC-6, CRED-1, REV-5 | — |
| K5 | Unknown-host unlock: the passphrase decrypts the vault into a pending state that serves nothing, and returns a ticket that the confirm must carry, so no other client of the unlock socket can answer or spoil it. A code-generator code (O6: current or previous 30 s step, each step once), checked against the seed inside the vault after decryption, opens it. A wrong code counts but keeps the unlock pending until its 15-minute expiry (the owner channel's code TTL), so the owner can retype it; no right code by then, or a lock, discards the key. Three wrong codes in 24 h discard it (CRED-8 as amended in #28: the key is discarded "if the code attempts are exhausted or no valid code arrives within the request's expiry") and refuse unlocks until the oldest ages out, with the time given ("Unlock again after Tue 14:05"). The wrong-code times and the last accepted step live in `unlock.json` (0600, written atomically and fsynced before the reply, loaded at start; unreadable fails closed), so neither a crash nor a restart resets the cap or replays a code. A code one or two steps outside the window is refused without counting and reports the clock difference. One Argon2id derivation runs at a time: a lock cancels an unlock in flight, but the phase stays `opening` until the derivation returns. Passphrase attempts are spaced 2 s apart and the refusals do not count. Wrong passphrases are not counted, so nobody without the card can lock the owner out. A vault without a seed is refused. The paper-grid fallback is not offered: it needs a challenge shown on the local page (P2-2). | CRED-8, CH-4, CH-18 | P2-2 adds the grid challenge. |
| K6 | Gaps until hardware and the local UI: the owner is not yet texted that an unlock is pending; the vault process logs it (`custody.notify` is the seam), since no modem driver exists before P2-3. The unlock page is P2-2's `localui` `Config.VaultUnlock` at `/unlock/vault` (#32): a handler on the local UI's uid that decodes the QR from a photo upload (plain-HTTP pages get no camera) and talks to `unlock.sock`; it is a follow-up once #29 and #32 merge. Until then `agentos-egress unlock` on a terminal is the client. The trusted-host TPM slot (unattended restart, optional PIN) and the V6 counter are P2-4b, so on the cloud box every boot is an unknown host and needs the owner. Carried to P2-3 and the local UI (from the #29 review): owner texts for unlock pending, unlocked, wrong code with tries left, and lockout with the retry time; and a broker reply while the vault is locked: "Box locked after restart; unlock on the local page." | CRED-8, CRED-9 | P2-2, P2-3, P2-4b. |
| K7 | The owner channel's high-tier verifiers (the seed and grid seed) stay in the vault process; `agentosd` still holds none, so the channel keeps refusing high-tier codes. The follow-up is a verify operation on the vault process, so the seed never leaves custody, rather than handing seeds to `agentosd` as `daemon.Config.OwnerSecrets` anticipated. The two verifiers must share one last accepted step before the channel accepts any high-tier code, so a code used for an unlock cannot be accepted again by the channel; the channel accepts none today, so nothing is open. | CRED-8, CH-4, O6 | Follow-up package. |
| K8 | The proxy sees only `api_key` entries (`apiKeysOnly`), so no adapter declaration can send the seed or any other kind upstream; the redactor still covers every value (CRED-7). Provider keys are stored through the unlock socket's `credential` operation, only while the vault is open, under the adapter's name (`openai`, `anthropic`), and never over the seed. Grants come from `-grant machine=adapter` flags (E5) until the grants package replaces them. | CRED-1, CRED-5, CRED-7 | Grants package. |
| K9 | The vault process serves the egress proxy on `model.sock`, not yet the model router (P2-7, #25), whose `Handler` calls the proxy in process and so belongs in this process too. Wiring it needs a per-request label and auditor in `route` (as `Proxy.HandlerFor` has) and a way back for `Decision.Usage` (a response trailer that `modelroute` hands to the OP-8 meter), which changes the meter (P1-7). That is a follow-up package; until it lands, guests call the provider-named raw routes (`/openai/...`), metered by bytes. | CAP-9, OP-8, ARC-6 | Follow-up: router in the vault process. |
