# Vault and credentialed egress: assumptions

Built for PLAN P1-3 against SPEC v0.12 (PR #15) on top of the broker
skeleton (PR #19). Covers `broker/vault` and `broker/egress`; the K rows
are P2-4a (key slots and the vault process `cmd/agentos-egress`). Each row is a
reading of the spec, or a gap left for a later package, that a reviewer may
want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| V1 | The vault is one AES-256-GCM sealed file, names and values both sealed, replaced atomically, mode 0600. Its 32-byte data key is random and never on the drive in the clear: it is wrapped under key slots in a keys file beside it (K1, P2-4a). `Create`/`Open` with a raw key remain for tests and the slot code. | CRED-1, CRED-8, DEP-1 | The file format is versioned. |
| V2 | Only `egress` and the vault process `cmd/agentos-egress` (P2-4a) may import `vault`; `vault/imports_test.go` enforces it. The daemon `cmd/agentosd` may not: it is on the ARC-2 control path. Inside the trusted broker process Go cannot hide memory, so custody rests on this import rule plus `Secret` formatting as a placeholder under every `fmt` verb, JSON, and text marshaling, including inside unexported struct fields (the bytes sit behind a pointer). `Close` zeroes the vault's own copies only; `Reveal` strings and redactor patterns are immutable Go strings. The vault's one third-party import is `golang.org/x/crypto/argon2` (K2). | CRED-1, ARC-1, ARC-2 | Add an importer only with a reviewed reason. |
| V3 | Values shorter than 12 bytes are refused, so CRED-7 redaction cannot shred innocent text. Passwords for credentialed browsers (P2-6) may need a different redaction rule. | CRED-7 | P2-6. |
| V4 | Redaction matches each value verbatim; as base64 (standard and URL-safe) at all three byte alignments, so a value inside a larger blob such as `base64("Bearer "+key)` is caught; as hex in any letter case; URL query and path escaping; and JSON string escaping. A value fully rewritten with arbitrary `\u` escapes, or split by a transform the redactor does not know, is not caught: redaction is defense in depth, custody does not rely on it. Streams hold back at most the longest pattern minus one byte. | CRED-7 | Add encodings in `NewRedactor`. |
| V5 | After `Close` every call fails (`ErrClosed`), so a late `Put` cannot rewrite the file with only the new entry. | CRED-1 | — |
| V6 | Rollback: an older vault file still opens with the same key, so someone who copied the drive once could put the copy back and revive a revoked credential or an old code-generator seed. P2-4d binds the file to a TPM NV counter on each trusted PC: the vault ID and per-PC anchors are sealed inside the file (format 2, `vault/rollback.go`), and the vault process refuses a file behind that PC's counter (`vault.ErrRolledBack`) before trusting anything in it. Details and limits are T11 in `tpmseal/ASSUMPTIONS.md`: an unknown host without a counter checks nothing, which leaves the owner-present unlock of CRED-8. | CRED-8, REC-2 | — |
| V7 | **Re-encryption** (recovery R10a, P2-4d; `vault/reencrypt.go`, `cmd/agentos-egress` `tpmHost.reencrypt`). `Rekey` replaces a slot but keeps the data key, so a lost card plus an earlier keys file or backup keeps opening later copies. `Vault.Reencrypt(factors...)` seals the open vault under a fresh random data key and rewraps each owner slot under its existing key-encryption key, proven by a given factor against the current key. A passphrase or recovery slot nobody proves refuses the call with nothing changed (`ErrSlotNotProven`), so the card is never locked out. In the vault process (review of #45, B5, and the arbitrator's ruling) every trusted-host slot is dropped with the old key, because whoever kept the old data key may also hold the old policy key and each slot's old key-encryption key: the vault then gets a new policy key, the approved boot paths are re-signed under it (`tpmseal.Resign`), this PC is sealed again on its TPM with a fresh key-encryption key (its boot PIN proved first and kept), and every other trusted PC is sealed from the SRK public area its slot recorded (`tpmseal.SealTo`, a TPM duplication blob the PC imports on its next unseal), so it needs no visit. A PC with a boot PIN cannot be sealed while away and is counted for the owner to trust again. An imported object cannot be `fixedTPM`; moving it again needs a policy the new policy key signs. A crash part way leaves fewer trusted PCs, never a slot under an old key. Lost factors must be replaced with `Rekey` first, or the new key is wrapped under them again. Slots and the vault envelope carry a key ID (a hash of the key, bound into each wrap and the file's associated data; empty until the first re-encryption). Writes: keys file with old and new slots, then the vault under the new key (advancing a bound counter), then the new slots only; `OpenSealed` after a crash uses the slots for the key the file is under and drops the rest, and `Rekey`/`AddSlot` refuse until then (`ErrReencryptPending`). **When it runs** (arbitrator ruling): a lost card or a removed trusted host re-encrypts; an ordinary passphrase change with the card in hand gets only the keys-file binding and the counter (T11). **Required steps of the same tier-4 action** (P2-8 wires them): rotate the code-generator seed and recovery's backup MAC key, which `Reencrypt` carries over unchanged and which an old copy holds. Copies taken before stay readable with the old key (CRED-8). | CRED-8, CRED-9 | P2-8 calls it in the lost-card and removed-host commits, with the seed and MAC key rotation. |
| E1 | Guest path is `/<adapter>/<upstream path>`. A request is forwarded only if the path is clean (no `.`/`..`/empty segments, nothing percent-escaped), has no query, and matches a declared operation's method and path template exactly. Everything else is denied with 403 and reported. No normalization: ambiguous means denied. | ADP-10 | Declared query parameters, and GraphQL/JSON-RPC body schemas, arrive with the first adapter that needs them. |
| E2 | Built-in relays declare inference only. OpenAI: `POST /v1/chat/completions`, the one route ARC-6 (a) qualifies. Anthropic: `POST /v1/messages`, declared but **not qualified** as a guest interface until a guest needs it (ARC-6 (a)); no grant should name it before then. `/v1/responses`, model listing, files, batches, key management, and billing are undeclared, so denied. | CRED-5, ADP-10, ARC-6 | Add an operation per qualified need. |
| E3 | Request headers are an allowlist (`Content-Type`, `Accept`, `User-Agent`, plus adapter-declared). An adapter may not declare `Location`, `Accept-Encoding`, `Content-Encoding`, `OpenAI-Organization`, `OpenAI-Project`, `Anthropic-Beta` (betas switch on server tools), or any name containing auth, key, token, session, cookie, secret, or password. So a guest's own key, cookie, org, or project header is dropped, and the vault credential is the only one sent. | CRED-5, A14 | Small: `credentialHeaders`. |
| E4 | The proxy sends `Accept-Encoding: identity` and refuses (502) any response with any other `Content-Encoding` value, in any header line or list, and sets `Content-Type: application/json` itself on rule-checked bodies, since compressed bytes would pass the redactor unread. Responses keep only allowlisted headers (`Location`, `Set-Cookie` never), redirects are returned rather than followed (the key is never re-sent elsewhere), and headers and body pass the redactor. | CRED-1, CRED-7 | Small: `baseResponseHeaders`. |
| E5 | Grants are a static machine → adapter table given at construction. The grant store and grant-change intents (OP-5) are a later package. Model access itself is ARC-6 (a) for any granted machine; the REV-5 data label, read from `Config.Label`, gates what the provider may fetch on the machine's behalf (E10). | OP-5, REV-5 | Swap `Config.Grants` for a lookup. |
| E6 | Decisions go to an `Auditor`, which `New` requires; events carry no header or body content. `JournalAuditor` (P1-7) journals denials as `egress` records (`journal.RecordEgress`: machine, adapter, operation, method, status, a redacted reason), outside any intent and never held by STOP. Per machine and reason class (the reason up to any quoted part, so a guest varying a key name opens no new entry), the first denial in a minute is journaled and the rest are counted into the next record's `suppressed`, so a looping guest cannot fill the journal; the key is machine and reason class only (method, status and adapter are not part of it, so the first record of a window stands for all of them); past 4096 live classes, new ones share one overflow entry per machine, never journaled untracked (`journal.EgressGate`; the broker applies the same gate to the denials the vault process reports, `modelroute.Journal`). Allowed calls are not journaled one by one; the OP-8 meter counts them. | ADP-10 | — |
| E7 | Not linked into `agentosd` (V2). The vault process `cmd/agentos-egress` holds the unlocked vault and serves the model router (P2-7) and, behind it, the proxy for every machine's model route (K9): `agentosd` meters the route (E8) and forwards it there (`broker/modelroute`, K4). `Proxy.HandlerFor` takes each request's machine, REV-5 label, and auditor from the forwarding broker. Until the vault is unlocked (K5) the route answers 503. `e2e/a14_test.go` still composes the chain in one process as the A5 canary target; `cmd/agentos-egress` `TestUnknownHostUnlockThenModelRoute` runs it across the two sockets. | ARC-2, ARC-6, CRED-1 | — |
| E8 | OP-8 spend metering lives in `broker/meter`, applied by the guest plane in front of the model route, so every model call is counted by machine identity at the socket before this proxy sees it, and settled to the usage the provider reports (G7). The meter forwards every call with an output limit no larger than its reservation (clamped or inserted). Behind the model router, each served call's provider-reported usage reaches the meter from the vault process in the `Agentos-Usage` trailer (K9). The OpenAI relay forces `stream_options.include_usage` on streamed calls for that. The meter runs this handler on a context the guest cannot cancel and keeps accepting writes after the guest hangs up, so the upstream read finishes. `Config.Cap` stays as a second, hard per-machine ceiling, and `MaxConcurrent` (default 4) bounds one machine's requests in flight (each buffers up to 8 MiB). The default transport bounds connect (30 s), TLS handshake (10 s), and wait for response headers (10 min). | OP-8 | — |
| E9 | Every `Operation` declares an ADP-2 verb class from a closed list; `New` refuses an unlisted one. Only `read` operations are forwarded without an intent: any other verb is denied 403 until proxied effects submit a journal intent per call. Model inference is declared `read` (no effect on an external account). | ADP-10, ADP-2 | Submit an intent per call when the first effectful adapter arrives. |
| E10 | Relay bodies must be one JSON object. The proxy re-encodes what it checked, so no duplicate keys or trailing data reach the provider. `background` is always denied, and OpenAI bodies always get `store:false`. Provider-side fetches follow the calling machine's REV-5 label (arbitrator ruling). `BodyRule.PublicMayFetch` opts in, so a rule that leaves it unset is strict for every machine. Provider-side fetches are remote content sources (a non-`data:` string under `url`, `image_url`, `file_url`, `document_url`, `audio_url`, `video_url`, or `server_url`, anywhere outside JSON schemas and client `tool_use` input; e.g. OpenAI `image_url`, Anthropic `image`/`document` `source:{type:"url"}`), plus a `tools[]` entry whose `type` is not absent, `function`, or `custom`, plus `mcp_servers`, `container`, and OpenAI `web_search_options`. They are admitted only when `Config.Label` returns exactly `public`. A private or unknown label is denied. On the box `Label` is `vm.Manager.DataLabel`, which answers `public` only for a known machine labelled public and `private` for an unknown machine or any lookup error; `agentosd` sends that answer as `Agentos-Label` to the vault process, which passes it to `Proxy.HandlerFor` per request (K4); `e2e/a14_test.go` uses the same contract. A nil `Label` makes every machine unknown, so all of them are denied. Anthropic client tools with schema-less types (`bash_*`, `text_editor_*`, `computer_*`) count as provider-side, which is stricter than needed. `Anthropic-Beta` is dropped for every label (an empty allowlist), so Anthropic server tools that need a beta flag do not work even for public machines yet. | ADP-10, REV-5, A14 | Admit a tool type or beta value only with a reviewed reason. |
| E11 | **Broker-held route failure (CRED-5t).** An operation with a `ResponseRule` is a credential exchange (a plan CLI's token refresh). Its response is forwarded only as status 200, `application/json`, one JSON object of at most 64 KiB whose top-level fields are exactly the declared ones: `credential` (non-empty string, swapped for a placeholder that must not contain any of the response's credentials), `number` (at most 20 characters), `bool`, or `text` (at most 256 bytes, matching the declared anchored pattern). Nothing is swapped unless the whole response matches, and the CLI gets the proxy's re-encoding. The `Swapper` gets all of one response's credentials in one call, stages them and returns placeholders; the proxy checks the placeholders and commits only then, so the vault stores all of a refresh or none of it (never a new access token beside an old refresh token). A commit that fails drops the response like an unswappable one. Any other response below 400 is dropped and stops the route (trigger a, `ReasonUnswappable`); an error status is dropped without stopping it, since an outage is not the login failing. A status in an operation's `Refused` list, on any operation, stops the route unforwarded (trigger b, `ReasonLoginRefused`). A stopped route is per adapter (one login per provider), not per machine: every request on it is denied without reaching the provider, and `RouteFailed` is called once per stop. A refused-login stop reopens through `Resume`, the owner's path only: its caller checks the owner's low-tier code (CH-10). An unswappable stop stays fallen back until a release requalifies the declaration (a new `Proxy`); `Resume` refuses it (`ErrRequalify`), per the CRED-5 wording in #421. Stops live in memory only, so a restart of the egress process reopens every stopped route; persisting them is CRED-5b. `New` refuses an exchange without a `Swapper`, and an exchange or refusal list without `RouteFailed`. The CLI's guest-controlled request can provoke a declared refusal status (e.g. 400 on a malformed refresh), which stops the route: a denial of service the owner is told about, never a credential reaching the guest. Exchanges are classed read (ADP-2): rotating the login has no owner-visible effect. Not yet built (release findings on the CRED-5t PR): injecting the vault's refresh token into the exchange request body, the vault `Swapper`, a built-in plan adapter, and wiring `RouteFailed` to the owner's notice and the router's fallback (CAP-9). | CRED-5, CRED-1, ADP-10 | Per provider, in its declaration. |
| E12 | **Home-network address policy (DEV-net-a; DEV-2, CAP-13).** The default transport dials and verifies TLS through a `netguard.Policy` (`Config.Guard`; nil means the IANA registries only), so a provider name that rebinds into the home network is refused, journaled with the denied header, and never dialed. A caller-supplied `Transport` must do the same; `tools/netguardcheck.py` checks the repo's own dialers. Only an operation declared `Inference` (the OpenAI and Anthropic relays, or an adapter for a compute host or private hosted route) carries the model-call purpose; any other operation to the same host gets no exception. The default transport therefore keeps two connection pools, so a connection made under the exception is never reused by a request without it. The proxy answers `CONNECT` with a journaled denial and never follows a redirect, so no request can name an address of its own. | DEV-2, CAP-13, REV-5 | A shared pool would need the purpose in the pool key. |

| K1 | Key slots (P2-4a): `vault.keys` beside the vault, JSON, mode 0600, replaced atomically. Each slot wraps the data key (AES-256-GCM) under a key-encryption key from its factor, with the slot's kind, KDF parameters, and any sealed blob bound in as associated data, so an edited or relabelled slot opens nothing. Kinds are a closed list: `passphrase` (this build), `tpm` (P2-4b), `recovery` (REC-1). A known kind this build cannot open still loads and survives `Rekey`; an unknown kind or version fails the whole file closed. `Factor` (Kind, Enroll, KEK) is the seam the TPM factor implements. `Rekey` proves one factor and replaces every slot of the other's kind, which is passphrase replacement (CRED-8, REC-4); a copy of the keys file taken earlier still opens with the old passphrase, as CRED-8 says. | CRED-8 | P2-4b adds the TPM factor. |
| K2 | Argon2id is `golang.org/x/crypto/argon2` at v0.50.0 (raised from v0.33.0 when the module moved to go 1.25 for a patched go-tuf, P4-3), pinned in `go.sum` and vendored under `broker/vendor` so the broker builds offline (DEP-1; the A9 offline scenario compiles from source with no module cache). It is the Go project's own implementation; hand-rolling Argon2 and BLAKE2b in the custody path would be the riskier choice. Only the vault imports it (not `agentosd`, which stays third-party-free under ARC-2). New slots get 256 MiB, 3 passes, 4 lanes: about 1 s on a 4-core cloud host. Tuning to about 1 s on the N95 (HW-4) waits for the hardware. Before deriving, a slot below 256 MiB or 1 pass, or with a salt under 16 bytes, is refused, so a keys file cannot make a guess cheap; one above 2 GiB, 20 passes, or 16 lanes is refused, so it cannot exhaust the box either.  DEP-1 reading (accepted in the #29 review): DEP-1 governs what boot, owner control, the journal and recovery need at run time, and a vendored, hash-pinned library compiled into the binary needs nothing at run time; DECISIONS.md allows near-zero external dependencies, and the build stays offline. | CRED-8, HW-4, DEP-1 | Raise the x/crypto pin with the module's Go version. |
| K3 | Passphrase normalization: lowercase, and runs of whitespace become one space, so a scan and a typed copy agree. Enrollment refuses fewer than 20 normalized characters; strength comes from the generator. `agentos-egress init` generates 100 bits as five space-separated groups of four base32 characters and prints it once with the code-generator `otpauth` URI (label `AgentOS`). It builds both files under temporary names and renames the keys file last, so a crash leaves nothing openable or a complete vault; a vault left without its keys file is reported for removal. The normalized passphrase bytes are wiped after each slot call. This stands in for the Owner Card until P2-2 prints the real one (with words, CRED-8's example). | CRED-8, §8.1 | P2-2. |
| K4 | Process split: `agentos-egress` runs as its own uid and alone reads the vault and keys files. Its run directory is 0711 (reachable, not listable); `model.sock` admits only `agentosd`'s uid and `unlock.sock` only the local UI's uid, by SO_PEERCRED, and `serve` refuses an unlock uid equal to the broker's, so the passphrase never passes through `agentosd`. `agentosd` forwards each machine's metered model route there and sets `Agentos-Machine` and `Agentos-Label` from its own state, dropping any `Agentos-*` header the guest sent; an unknown label is sent as private. The vault process down, or the vault not open, is 503. | ARC-1, ARC-6, CRED-1, REV-5 | — |
| K5 | Unknown-host unlock: the passphrase decrypts the vault into a pending state that serves nothing, and returns a ticket that the confirm must carry, so no other client of the unlock socket can answer or spoil it. A code-generator code (O6: current or previous 30 s step, each step once), checked against the seed inside the vault after decryption, opens it. A wrong code counts but keeps the unlock pending until its 15-minute expiry (the owner channel's code TTL), so the owner can retype it; no right code by then, or a lock, discards the key. Three wrong codes in 24 h discard it (CRED-8 as amended in #28: the key is discarded "if the code attempts are exhausted or no valid code arrives within the request's expiry") and refuse unlocks until the oldest ages out, with the time given ("Unlock again after Tue 14:05"). The wrong-code times and the last accepted step live in `unlock.json` beside the keys file (0600; written by `init` before the keys, then atomically and fsynced before each reply; loaded at start; unreadable, or missing while the keys file exists, fails closed), so neither a crash nor a restart resets the cap or replays a code. A code one or two steps outside the window is refused without counting and reports the clock difference. One Argon2id derivation runs at a time: a lock cancels an unlock in flight, but the phase stays `opening` until the derivation returns. A correct passphrase while an unlock is pending supersedes it (P2-4f): the pending unlock keeps serving its ticket during the derivation, then is discarded and replaced in one step, and the owner is told, at most once per 10 minutes with a count (a burst that stopped reports its total at the unlock), so a card holder on the Wi-Fi cannot turn restarts into a stream of texts; if a confirm opened the vault during the derivation, the new key is discarded and the unlock refused as busy.
