# Hostile-text corpus: assumptions

Built for REV-CHK-names (#3901, brief `briefs/REV-CHK.md`). `broker/hostiletext` is a test-only corpus that every name or label check runs, and a lint that each check does. The rules the four checked packages now apply are recorded here too, rather than in `broker/kernel` and `broker/enforcer/policy`'s own files, which open PRs (#3855, #3873, #3874) are editing. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| REV-CHK-names-a | **What the corpus holds.** `Blank`: empty, spaces, a tab, NBSP, ideographic space, a Hangul filler, each fed alone. `Hidden`: zero-width and word joiners, BOM, soft hyphen, grapheme joiner, Mongolian vowel separator, variation selectors (BMP and supplementary), the Hangul and Khmer fillers, every bidi embedding, override, isolate and mark, tag characters, CR, LF, CRLF, NEL, U+2028, U+2029, NUL, C0 and C1 controls, DEL, and invalid UTF-8 (a stray byte, an overlong slash, an encoded surrogate, a cut sequence), each fed alone and at the start, middle and end of `name`. `name` must pass (positive control). The source is ASCII, so each entry reads as its escape. | KRN-2 | An entry added here reaches every check at once; a check it breaks is fixed or excepted with its reason. |
| REV-CHK-names-b | **An exception is named and argued at the call.** `Except` names a `Hidden` entry and a reason; one naming no entry, or with no reason, fails. Only the kernel's `Named` uses it: a label query keeps every character a STATUS line shows (`unseen` keeps it), so the joiners (#2740), the variation selectors an emoji or an ideographic variant needs, NBSP, the grapheme joiner and the fillers are excepted. Its match is exact (`sameLabel`), so none of them widens one; a query with nothing to see is still refused (UX on #3957). | KRN-2, LOG-4 | Refusing them would make a subject whose label holds one unfindable. |
| REV-CHK-names-c | **The lint finds checks by name and result.** A non-test function in `broker/` (outside vendor, third_party, testdata and `tools/old_core.txt`'s directories) named `shape`, `Shape`, `name`, `*Name`, `*NameOK` or `valid*Name*` whose last result is a bool or an error is a check. It is covered when a test in its directory calls `hostiletext.Run` with its name (and, for a method, its receiver's type) in the arguments; otherwise it needs an `allow.txt` line with a reason, and a stale line fails. A check under another name, or one whose Run wrapper hides the hostile part, is held by review. | KRN-2 | A type-checked lint (go/types) could follow calls instead of names; it would need the module loaded. |
| REV-CHK-names-d | **The rules the checks now apply.** A token in the enforcer policy and on the enforcer channel (`policy.name`, `wire.Name`, so a Wi-Fi identity too, #3871) and a follow source's name (`follow.NameOK`) are valid UTF-8 with no space (ASCII space allowed in a follow name), slash (the tokens), control, format, line or paragraph separator, non-ASCII space, default-ignorable or variation selector character; non-ASCII letters stay. A new backup destination's locator also refuses a path element led or trailed by a space (`BackupTarget.addable`), which the signer's page shows without it (#3284); replay does not re-check it, so a target logged before the rule still folds, and so does every later add signed over the count it made (`TestATighterTargetRuleKeepsLoggedTargets`). `kernel.Named` refuses invalid UTF-8, any character `unseen` refuses (so a tab no longer reads as a space there), and a label with no visible character (#3438). | NET-2, NET-4, CH-10, BAK-1, LOG-4 | A device or host name that needs a default-ignorable character (none known) would need an exception at the check. |
