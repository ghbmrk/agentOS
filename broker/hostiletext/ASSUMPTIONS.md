# Hostile-text corpus: assumptions

Built for REV-CHK-names (#3901, brief `briefs/REV-CHK.md`). `broker/hostiletext` is a test-only corpus that every name or label check runs, and a lint that each check does. The rules the four checked packages now apply are recorded here too, rather than in `broker/kernel` and `broker/enforcer/policy`'s own files, which open PRs (#3855, #3873, #3874) are editing. Each row is a reading a reviewer may want to change.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| REV-CHK-names-a | **What the corpus holds.** `Blank`: empty, spaces, a tab, NBSP, ideographic space, a Hangul filler, each fed alone. `Hidden`: zero-width and word joiners, BOM, soft hyphen, grapheme joiner, Mongolian vowel separator, variation selectors (BMP and supplementary), the Hangul and Khmer fillers, every bidi embedding, override, isolate and mark, tag characters, CR, LF, CRLF, NEL, U+2028, U+2029, NUL, C0 and C1 controls, DEL, and invalid UTF-8 (a stray byte, an overlong slash, an encoded surrogate, a cut sequence), each fed alone and at the start, middle and end of `name`. `name` must pass (positive control). The source is ASCII, so each entry reads as its escape. | KRN-2 | An entry added here reaches every check at once; a check it breaks is fixed or excepted with its reason. |
| REV-CHK-names-b | **An exception is named and argued at the call.** `Except` names a `Hidden` entry and a reason; one naming no entry, or with no reason, fails. Only the kernel's `Named` uses it: a label query keeps every character a STATUS line shows (`unseen` keeps it), so the joiners (#2740), the variation selectors an emoji or an ideographic variant needs, NBSP, the grapheme joiner and the fillers are excepted. Its match is exact (`sameLabel`), so none of them widens one; a query with nothing to see is still refused (UX on #3957). | KRN-2, LOG-4 | Refusing them would make a subject whose label holds one unfindable. |
| REV-CHK-names-c | **The lint finds checks by name and result.** A non-test function in `broker/` (outside vendor, third_party, testdata and `tools/old_core.txt`'s directories) named `shape`, `Shape`, `name`, `*Name`, `*NameOK` or `valid*Name*` whose last result is a bool or an error is a check. It is covered when a test in its directory calls `hostiletext.Run` with its name (and, for a method, its receiver's type) in the arguments; otherwise it needs an `allow.txt` line with a reason, and a stale line fails. A check under another name, or one whose Run wrapper hides the hostile part, is held by review. | KRN-2 | A type-checked lint (go/types) could follow calls instead of names; it would need the module loaded. |
| REV-CHK-names-d | **The rules the checks now apply.** A token in the enforcer policy and on the enforcer channel (`policy.name`, `wire.Name`, so a Wi-Fi identity too, #3871) and a follow source's name (`follow.NameOK`) are valid UTF-8 with no space (ASCII space allowed in a follow name), slash (the tokens), control, format, line or paragraph separator, non-ASCII space, default-ignorable or variation selector character; non-ASCII letters stay. A new backup destination's locator also refuses a path element led or trailed by a space (`BackupTarget.addable`), which the signer's page shows without it (#3284); replay does not re-check it, so a target logged before the rule still folds, and so does every later add signed over the count it made (`TestATighterTargetRuleKeepsLoggedTargets`). `kernel.Named` refuses invalid UTF-8, any character `unseen` refuses (so a tab no longer reads as a space there), and a label with no visible character (#3438). | NET-2, NET-4, CH-10, BAK-1, LOG-4 | A device or host name that needs a default-ignorable character (none known) would need an exception at the check. |

## REV-PROOF-corpus (#4910, part a)

Headers and address forms join the corpus; the ISO 4217 pin lives beside the code it pins (`broker/daemon/minordigits_test.go`) but is recorded here. Part b (the systemd differential) is #4916.

| ID | Assumption | Spec basis | If it changes |
|---|---|---|---|
| REV-PROOF-corpus-a | **What the header corpus holds.** `HeaderNames`: each credential word (key, token, auth, secret, session, csrf, xsrf, signature, password, cookie, credential) alone, with `X-`, as `X-Api-<word>` and `<word>-Id`; named credential headers (Authorization, Cookie, X-Api-Key, X-Amz-Security-Token, …); request-reshaping headers (`*-Method-Override`, `X-Forwarded-*`, `Forwarded`, `X-Original-*`, `X-Rewrite-*`, `X-Real-Ip`, `X-Host`, client-IP headers, Host, Content-*, Expect, Max-Forwards); hop-by-hop headers (RFC 9110 §7.6.1, plus Proxy-Connection and HTTP2-Settings); each in its given, canonical, lower and upper case; and broken names (empty, CR/LF, colon, space, tab, NUL, non-ASCII). A check passes only if it refuses every entry its caller does not name exactly, byte for byte, and accepts every name it does (positive control). `HeaderValues`: CR, LF, CRLF, an injected line, an obsolete fold, NUL, DEL and ESC. | CLK-3, CLK-1 | An entry added here reaches every header check at once. |
| REV-PROOF-corpus-b | **What the address corpus holds.** `Addrs(target)` is built from the target's bytes, not from `ipform`: every form `ipform.Forms` documents, SIIT's IPv4-translated `::ffff:0:0:0/96` (the #4037 release item; `::ffff:0:0/96` is the mapped prefix, also covered), mapped written four ways, ISATAP inside 6to4 and a global prefix, the inverted Teredo client, then 15 near misses (a neighbour with its first octet's high bit flipped, each prefix one off, an un-inverted Teredo client); every IPv6 entry also zoned. The neighbour is chosen so no test decoy, range or table entry shares it. | KRN-12, DEV-2 | A new embedding prefix needs an entry here and in `ipform.Forms`. |
| REV-PROOF-corpus-c | **The differential.** `kernel/addrcorpus_test.go` runs one logged decoy table through `ipform.Forms`, netguard `Policy.Check` (its `Config.Decoy` is the table's `Matcher.Dest`) and the kernel's plan check (`destOf` on a bare address, an address and port, and a URL), and fails each that disagrees with the corpus or with the others. `Kernel.CallTrip` is not a view yet: it reads only mapped and well-known NAT64 forms (#4915), and has no production caller. netguard's `Config.Decoy` has no production caller either; the test covers the logic it will run. | KRN-12 | Adding CallTrip as a view is #4915's acceptance. |
| REV-PROOF-corpus-d | **The lint finds checks by shape.** A package-level variable named `...Headers`; a function whose name holds "header", whose first parameter is a string and whose last result is a bool or error; and a function with a `netip.Addr` parameter whose last result is a bool or error. It is covered when a test in its directory names it in a `RunHeaders`, `RunHeaderValues` or `RunAddrs` call (a method by its name alone); otherwise it needs an `allow-corpus.txt` line with a reason, and a stale line fails. The model and plan clerks' header denylists fail the corpus today and are allowed against #4914. | KRN-2, CLK-3 | A check of another shape is held by review. |
| REV-PROOF-corpus-e | **The currency pin.** `minorDigits` must equal ISO 4217 List One published 2026-01-01 (`broker/daemon/testdata/iso4217-list-one-2026-01-01.xml`, SIX's list-one.xml as vendored unchanged in the `iso4217` 1.16.20260101 PyPI wheel; SIX's own host is not reachable from the build sandbox): every non-fund code with a 0, 2 or 3 digit minor unit, less `notHeld` (XAD, the Arab Monetary Fund's unit of account), at its digits. A loosened copy (a wrong scale, ANG or BGN kept, XCG missing, a fund or 4-digit code held) fails. | CH-10 | A new list is vendored under its own date and `minorDigits` updated in the same change. |
