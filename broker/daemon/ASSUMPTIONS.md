# Broker skeleton: assumptions

Built for PLAN P1-2 against SPEC v0.12 (PR #15) on top of the P1-1 journal
(PR #18). Each row is a reading of the spec, or a gap left for a later package,
that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| B1 | Messages from any number other than the owner's get no reply and no effect. A reply would let anyone probe the box or make it spend texts. | CH-3 | Small: `Handler.Handle`. |
| B2 | STATUS and task chat need a session unlock (CH-3 table). The default `Auth` knows the owner's number but keeps sessions locked until the owner channel (P1-5) can verify code-generator codes, so until then the running daemon answers STATUS with the unlock prompt. STOP, RESUME, and HELP need only the owner's number. | CH-3, CH-14 | P1-5 supplies the real `Auth`. |
| B3 | RESUME: a bare `RESUME` texts a 6-digit code from `crypto/rand`, or re-sends the live one; `RESUME <code>` within 15 minutes lifts STOP. A code is single use, void after 3 wrong replies, and voided by a new STOP. Wrong codes are also counted per day across codes: 5 in 24 hours lock RESUME by texted code, and the owner is told once. The broker sends at most 3 RESUME texts per hour and is silent beyond that, so a spoofer cannot make it text the owner without limit. In the skeleton the lock clears when the 24-hour window passes; P1-5 adds the code-generator path that lets the owner unlock (CH-18) and extends the count to every texted-code kind. | CH-10, CH-11, CH-18 | Small: `resumeCmd`. |
| B4 | Control words are strict whole-message matches with a per-word argument grammar, so "stop the newsletter" goes to the agent. A task message whose first or last word is STOP also gets the fixed reply "To pause everything, reply STOP.", whether or not the agent is up, at most once per hour, so spoofed near-misses cannot make the box text the owner repeatedly (CH-15). A message that starts with RESUME, YES, or NO and has digits but fits no grammar gets a fixed "not understood" reply and is not forwarded, since it may carry a code (CH-10). | CH-11 | Small: `Parse`, `StopNearMiss`. |
| B5 | YES and NO answer "No open requests." and UNDO/MORE "No request <id>." until approvals exist (P1-5). Pause/revoke words for pre-allowances and loops are not parsed yet: the spec names no exact words. | CH-11, CH-13 | P1-5 and the ADP-9/LOOP-0 packages. |
| B6 | STOP and STATUS replies are fixed templates. STATUS shows at most three unresolved intents as `action/account`, each passed through a fixed alphabet with no digits or spaces, so no field can carry a code or a control word into a text. The machines line is a broker template carrying counts; it is filtered to letters, digits, spaces, and `.,;:` with no line breaks. | CH-12, CH-19 | Small: `status`, `safeToken`, `plainLine`. |
| B7 | Admission: config needs capacity > headroom >= 0, and a request larger than capacity minus headroom is refused. A class may preempt only experiments, and only when it outranks them; newest first; only as many as needed; nothing is preempted if that cannot make room. Preemption runs outside the controller lock with the request's memory reserved; if some victims fail, the request is admitted when the ones that yielded made room, and refused otherwise. Foreground and accepted work are never preempted. A PSI reading above the threshold, NaN, or negative (-Inf included) refuses experiments, admits accepted work only by replacing experiments of at least its size, and leaves foreground alone. STATUS never shows negative free memory. `agentosd` supplies the VM manager as the preempter and PSI as the pressure input (P1-4, see `broker/vm/ASSUMPTIONS.md`); without `-runsc` there are no machines and preemption is refused. | RES-1, RES-2 | — |
| B8 | Socket identity is fixed by which socket a request arrives on: socket directory 0700, a real directory owned by the broker's uid (never a symlink), held with a lock file so a second broker cannot take it over; sockets 0600. The owner socket admits only the modem bridge's uid (`SO_PEERCRED`), which `agentosd` requires to differ from the broker's own, so another process running as the broker cannot inject owner texts. Guest sockets: one per machine, at most 4 connections each, closed after 30 s idle. Owner socket connections close after 60 s idle, so a stuck bridge cannot hold all 8 slots. The accept loop retries temporary errors (EMFILE) with backoff, so a flood cannot stop it. Every socket has a closed op set and a 64 KiB request cap, and peers see only fixed error codes. | CH-1, CH-2, ARC-6, OP-8 | Small. |
| B9 | ARC-2 is enforced structurally. `daemon/arc2_test.go` fails if a control-path package imports a network client, a process launcher, `unsafe`, cgo, a third-party module, or a broker package outside the control path (`net` and `syscall` only where listed: sockets, signals). It also checks `go list -deps` for HTTP, RPC, TLS, and process launching anywhere in the transitive dependencies. | ARC-2 | Extend the list when new control-path packages appear. |
| B10 | The sockets here are control sockets with JSON-lines framing. Model access and MCP (ARC-6 a, b) carry large and streamed bodies, so they will be separate per-machine HTTP listeners, under the same rule that the socket fixes the peer's identity. The 64 KiB cap applies to control ops only. | ARC-6, OP-8 | Documentation only. |
| B11 | Requests on one connection are handled one at a time, and task chat waits up to 5 s for the agent. STOP on a separate connection is never blocked by it. The modem bridge (P1-5) must use a connection per message, or delivery must become asynchronous, so a slow agent can never delay a STOP (CH-2). | CH-2 | P1-5. |
| B12 | The journal needs a redactor (P1-1). Until the vault (P1-3) supplies one that knows vault values and the CH-19 patterns, the daemon journals no free text: every evidence, reason, and param string becomes `[redacted]`. Nothing can submit intents yet anyway. | CRED-1, CRED-7 | P1-3 replaces `redactAll`. |
| B13 | **Broker executors (W3).** `BrokerExecutors` are the broker's own setting executors, the change pipeline (`change`) and the loop scheduler (`loops`). They declare no operations, so no grant can name them; the gate reaches them only for `meta.change.*` and `meta.loops.*` intents its `Changes` and `Loops` policies allow, and those check account, executor, and origin themselves (change C8, loops L2). A name that is reserved or also an adapter's is refused at start. `Settings`, `HelpExtra`, and `Narrows` pass the scheduler's settings texts to the control handler and the owner channel (owner O17). | OP-3, OP-5, LOOP-0 | — |
| B14 | **Replay machine budget (PE2).** A replay machine's memory is `-replay-mem-mb` (default 1024 MB), set apart from the agent's `-agent-mem-mb` (1536 MB). `agentosd` opens replay evaluation only if the agent machine and one replay machine fit in the pool at once (`-capacity-mb` less `-headroom-mb`, 3900 MB by default); otherwise it logs "replay evaluation disabled" with the three figures, because admission would refuse or preempt every evaluation while the agent runs (replay R6) and learning would stall unseen. The owner sees it (UX-114-1, potency C1): STATUS adds "Learning: paused, the box's memory is too small to test changes." after the time check, and a LEARNING ON or LOOPS ON that takes effect says "Learning is on, but the box's memory is too small to test changes, so nothing new will be adopted.", keeping its "Reply ... OFF if this wasn't you." line (security C1 on #49). No owner text or digest line yet (W5). The S1 test kit records `agent_and_replay_fit` on each PC from `MemTotal` less the RES-2 floor budget (host 1.0 GB, inference 2.0 GB, browser 0.5 GB, headroom 0.6 GB), with the `-capacity-mb` that PC supports; the N95 reading is the check (risk 15). | RES-2, LOOP-5, HW-4 | If the N95 pool is short, lower `-replay-mem-mb` or measure a smaller replay guest |
| B15 | **Admission capacity from the box (PE6, R1 on #114).** Unless `-capacity-mb` is given, `agentosd` sets admission's capacity at start to MemTotal less the RES-2 floor budget outside the agent-machine pool (host 1024, inference 2048, browser 512 MB), at most 4500 MB, and logs the figure and how it was reached. On the N95 (about 7680 MB MemTotal) that is 4096 MB, a 3496 MB pool after headroom, which still holds the agent and one replay machine (B14); before, the fixed 4500 MB let admission promise 400 MB the box does not have. An unreadable MemTotal takes the N95 floor's 4096 MB and says so. A box too small for the agent machine (capacity less headroom below `-agent-mem-mb`, under about 5.6 GB of memory with the defaults) keeps `agentosd` up with no agent machine and no replay machine: capacity is kept above headroom so admission opens, and STATUS's agent line reads "Agent: off, this box has 4.9 GB of memory and running the agent needs about 5.6 GB." (potency C1 on #118), in place of "not set up", whose advice to update or restart would be wrong. The S1 test kit's `agent_and_replay_fit` line reports the same figure. | RES-2, HW-4 | When the floor budget is measured on the N95 (risk 15), change the three constants with the test kit's |
| B16 | **Managed tree to the live agent (W4).** The tree's `procedures/`, `skills/` and `context/` reach the agent through the broker tool `managed_tree` on the guest socket (ARC-6 (b); guest G15), never a new path. `agentosd` makes its in-memory copy (`liveTree`) the change pipeline's target for those three namespaces, so an adoption, an UNDO, and the restore at start all land there; nothing with authority or governance is a target or ever sent. The tool answers only a machine labelled private when it asks (REV-5, compile K7): a public machine, an unknown one, and every machine before the machine plane opens are refused with a fixed reason, and none is raised, so a PUBLIC task stays public; the agent gets the tree once owner data has made it private. The answer is the whole tree with its hash as version; a caller holding that version gets `unchanged` and no files; a tree over 4 MiB is not sent at all. Until the pipeline has opened and applied its state (and with no learning plane at all) the tool answers "not ready", since an empty copy is not the box's tree (L3 on #120). A target applies only paths in its own namespace. The guest bridge fetches it every 30 s (`-tree-sync`) and mirrors it into its tree directory (`/etc/agentos/tree`): paths outside the three namespaces refuse the whole answer; new and changed files are written first (aside, then renamed) and gone ones removed last, all through an `os.Root`, so a symlink cannot reach outside the directory; an `unchanged` answer for another version is an error; and a failed fetch changes nothing, so a replay machine (whose plane serves no such tool) keeps the tree it was seeded with. The bridge is guest code (ARC-7): what it does with the tree binds nothing, and the label check is the boundary. **Retention (security C2 on #120):** literals the compiler bakes into an adopted skill live in the tree, which only private machines get, and they outlive the 30-day window that bounds kept task values (W3-values); they go when the skill is undone or replaced, or when forget removes it (BOARD W3-tasks). | CAP-5, REV-5, ARC-6 | The public-mark exception (compile K7): send public-derived files to public machines once files carry the mark. |
| B17 | **The agent sleeps while the box learns (PE7 part 2).** Where B14 finds no room for the agent and a replay machine together, `agentosd` no longer leaves evaluation off: it opens the evaluator with a sleeper. An evaluating unit of work first puts the agent to sleep (vm V27, `CheckpointAndStop`); if the agent may not sleep, the unit is not run and is offered again as an interruption. The agent may sleep only inside `-sleep-hours` (default 01:00-06:00 box time, wrapping past midnight) and not within 10 minutes of their end, when the owner has sent it nothing for 30 minutes, with STOP not in force, while the box clock check does not restrict time checks (TIM-1; the hours read the box clock, security R1 on #149), and with no work in hand: no guest intent authorized or in flight, no undo open, no agent effect held anywhere in the gate, no open question, no owner message handed to it and unanswered, and no worker tool call in flight (CAP-8, L3 on #149). A worker machine left running between calls does not count: it is the guest's, admission weighs its memory, and the reaper parks it after an hour idle. Work that arrives while the checkpoint is taken wakes the agent again at once. It wakes when the unit ends, when an owner message reaches its inbox (the message waits there and is handed over on the wake, warm or cold alike), on STOP, 10 minutes before the hours end, or after 5 hours asleep; after a 5-hour wake it stays awake 30 minutes before it may sleep again. A wake cuts the running evaluation at once as the owner's (`change.ErrOwnerWork`, or `ErrOwnerStop` for STOP), so the cut is exempt under PE5 within PE5b's bound. One restore is bounded to 2 minutes; if it and its cold fallback fail, the agent is marked awake and the keeper starts it again. In this mode a preempted evaluation's pairs and candidates are kept 36 h rather than 12 h, so work cut when one night's hours end resumes the next night (change C22). Each sleep and wake is a `sleep` journal record with its cause and, for a cold wake, vm's reason (journal A13). Being asleep is held in memory only: at start `agentosd` restores an agent a restart left on its sleep checkpoint, or the checkpoint is deleted (security R1 on #147), on a box that no longer sleeps its agent too (security R2 on #149). The keeper does not restart a sleeping agent; STATUS says "Agent: asleep while the box learns. Any task message wakes it." and, in place of B14's line, "Learning: at night only, while the agent sleeps (the box's memory is too small to run both)." Outside the hours the sleeper keeps the agent awake for the owner, so `busy()` holds all loop work during the day on such a box, not only evaluation. An owner message whose wake has not finished 15 s after its delivery gets "One moment, your agent is waking up.", at most once per sleep however many messages arrive and never once the agent is awake, through the owner channel, which reaches the owner only once a modem is wired (P2-3). The S1 test kit's `agent_warm_wake` line checks the disk and hash part of a warm wake against those 15 s on each PC (UX P2-a); gVisor's restore time, and condition 13's 10 s p95 from wake to delivery, are measured on the box (S1 hardware). The owner's quiet hours, once the gate's `Quiet` is set from an owner setting, should become the sleep hours (UX note on #149); nothing sets it yet. | RES-1, RES-2, LOOP-5, REV-1, TIM-1 | If the N95's warm wake runs past 15 s, the holding line goes out sooner or the checkpoint shrinks; events-bus and call wakes are PE7-bus and PE7-call |

## Left for P1-5 (from the PR #19 review)

- STATUS must keep working with models down once the session is unlocked.
- One CH-15 rate limit over every reply to a message that proves only the owner's number (the unlock prompt, "agent not running", "not understood", the STOP hint and RESUME texts). The skeleton caps the STOP hint at one per hour and RESUME texts at 3 per hour; the other fixed replies are not capped yet.
- "Resumed." should report how many held items were released; a held item whose approval went stale goes back to needs-approval.
- YES/NO grammar: request IDs are letters, item numbers digits, codes 6 digits, so `YES <id> <code>` is never ambiguous. A bare "yes" while requests are open gets the fixed usage reply.

## W5-D58 shutdown custody

Daemon.Wait now joins the owned owner loop (including its existing modem Run
join), Gate.Run and outstanding Gate settlements after socket Wait, then closes
the journal and publishes completion. Owned producers return before Gate.Wait,
so their later settlement admission cannot escape the join. An owner restart
send or settlement callback may remain stuck forever, retaining journal custody;
cancellation is not I/O interruption or a shutdown deadline. This truthful
availability tradeoff is intentional, not a timeout/replacement writer policy.

Caller-owned Gate/Owner/Engine handles, spawned work, executor subwork and other
consumers must independently cease admission and complete downstream handoff.
The daemon does not enforce those scopes, revoke permissions, guarantee all-user
quiescence or qualify current-main/runtime/custody/media/latency. Joining while
an owned callback awaits Daemon.Wait deadlocks; callbacks must not do that.
The existing close error is still not reported by Wait; media qualification is
external. No activation/default/config/policy/reset/authority change supplied.

## W5-D59 journal close outcome

WaitError joins the same shutdown/done as Wait and returns one immutable fixed
ErrShutdownRecovery if the actual journal Close failed, nil on its observed
success. Assignment precedes done publication; observers never repeat Close or
launch a new operation. The raw error/path is withheld. Existing Wait callers
still discard the result; command/daemon startup routing must adopt it separately.
A failed result is uncertain recovery requiring trusted external determination
before reuse, not proof of retained/released lock, an enforced/persistent restart
hold, all-user quiescence, media durability or revocation of escaped permissions.
Synchronous producer/settlement/close work may hang forever. Callback code must
not await its own daemon shutdown. No automatic repair/retry/default activation.
