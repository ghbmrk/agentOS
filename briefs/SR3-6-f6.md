# SR3-6-f6: a narrowing retires ordinary-release claims too, and W5b binds the copy it stages

Board section: Security and architecture review (2026-10-08). Source: #620 reviews (Security 6083934362 points 1-3, L3 6083942942 points 1-2). Class release, tier A. Must land before W5b (`needs` includes SR3-6-f4, merged).

**Requirements:** OSS-9, UPD-5, UPD-8, CH-12. Fails closed in every part: only text or an unused path is stale today.

**Re-verify first.** SR3-6f-4 changed this area (`Stage` now binds when `v.security || v.attested`, `store.go:1152`). Confirm each part below still holds on main before writing its test; drop a part that no longer does and say so in the PR.

**(a) Ordinary-release claims survive a narrowing.** `retireClaims` (`maintain.go:403`) walks only `l.st.TestedBy`, the security claims. A version proposed on an ordinary pass keeps `State.Evidence[v]` and, if adopted, the digest line "Update N is ready and installs at the next quiet time", while `Stage` refuses it. Hold the proposed `Verified` for every proposal with `Evidence[v][0] > 0` (today `l.held[v]` is set only when `o.tested != ""`, `maintain.go:648-656`) and retire it the way `TestedBy` claims are retired, under the same `l.held[v] == held[v]` guard.

**(b) The staged copy is the bound one.** The binding is a flag on the `WithAttestations` copy only. `Stage(res.Release)`, the raw `Check` result `decide` admitted on the same pass, returns nil after a narrowing. Make W5b's staging path take the held copy (or have `Stage` re-derive the binding), pinned by a test. `Applier.Schedule` (`apply.go:354`) has no non-test caller today, so no live path is wrong yet; the test fixes the contract for W5b.

**(c) Restart path.** Rebuild `Loop3` from saved state with a `TestedBy` entry (nil `held`), call `AttestorsChanged`, assert the claim is gone. This kills the mutant `if h != nil && !h.Security()` (a guard that fails open on a missing value; recurring kind: #587, #584, #599).
