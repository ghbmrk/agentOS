# P2-2w c4e4 s2: vault-process notices reach the owner by text

Work item #1421 (release; Security S-2 / UX U-2 on #1367). Serves OP-9, CH-3, CAP-9.

**State on main (2026-10-17).** #1592 landed the stopgap and the check: the providers and second-line pages no longer say "I text you", and `TestEveryTextPromisedOnALocalPageHasASender` (`broker/localui/owedtext_test.go`) fails on any "I text you" without a named sender. What remains is the wiring: `custody.notify` in the vault process is still `log.Print` (`broker/cmd/agentos-egress/main.go`), so an allow the owner did not make, or a changed second line, is never texted (egress K6, K25).

**Requirements:**
- CAP-9 / CH-3: when a provider is allowed or withdrawn private data, or the second line's account is replaced or removed, the owner is texted.
- OP-9: a wrong code-generator code typed on the box reaches the owner, so use from someone else's signed-in phone is noticed.
- Fixed texts only: the vault process hands over a notice code (and, for provider notices, a provider name checked against a fixed shape); the owner text is rendered from one table, never from free text.

**Acceptance tests:**
- CH-3, CAP-9: `broker/owner/notice/notice_test.go::TestEachCodeRendersAFixedText`, `TestOnlyKnownCodesAndShapedNamesRender`, `TestFromLogMapsOnlyTheOwnerNoticeLines` — fixed texts only; a bad name or unknown code renders nothing. Catches free text reaching the owner.
- OP-9, CAP-9: `broker/cmd/agentos-egress/noticesock_test.go::TestCustodyNoticesReachTheQueue`, `TestEveryOwnerNoticeLineMapsToANotice` — a wrong code and an allow through the real custody queue their notices; every notice constant maps. Catches a reworded line going quiet.
- OP-9, CH-3: `noticesock_test.go::TestTheNoticeSocketAnswersAcksAndWaits`, `TestAFullQueueReportsWhatWasMissed`, `TestTheNoticeSocketAdmitsOnlyAgentosd`, `TestAWaitingPullEndsWithItsCaller` — ack, wait, boot reset, overflow and peer checks. Catches a lost or unbounded queue.

**Implementation risk:** tier A. **Gate:** lenses (security: strongest tier).

## Sizing

Two parts, because agentosd's `main.go` is in open PR #2015 (D-111):

- **s2a (this PR).** A new `broker/owner/notice` package (codes, the owner texts, and `FromLog`, which maps the vault process's existing notice lines to codes) and the vault process's side: a bounded notice queue fed by `custody.notify`, served on a new `notice.sock` that admits agentosd's uid only, as a long poll. Nothing reaches the owner yet, so the pages keep their current wording.
- **s2b (follow-up row, after #2015).** agentosd pulls `notice.sock` (a new flag and a new file) and sends each notice through `owner.Channel.Inform`; the providers and second-line pages get back their "I text you" lines, with `promiseSenders` entries naming the sender; egress K6/K25 and localui L47 are updated. s2b closes #1421.

## Scope (files, s2a)

- New `broker/owner/notice/notice.go`, `notice_test.go`, `ASSUMPTIONS.md`.
- `broker/cmd/agentos-egress/main.go` (the queue, the notify wiring, serving `notice.sock`) and a new `noticesock.go` and `noticesock_test.go`.

No other egress or localui file. Egress K6 is updated in s2b, since `broker/egress/ASSUMPTIONS.md` is in open PRs #2015 and #2025; until then `broker/owner/notice/ASSUMPTIONS.md` N1–N3 record the seam.

## What to build (s2a)

1. `notice.Notice{Code, Name}`; `notice.Text(n)` gives the owner's text or false for an unknown code or a bad name; `notice.FromLog(line)` maps the vault process's notice lines for mail and second-line account changes, missed second-line texts, provider private-data changes, wrong codes and too many wrong codes. Every other line stays log-only.
2. The vault process keeps the last 64 owner notices in memory, numbered, with a boot id. `GET /notices?boot=B&after=N` on `notice.sock` drops what the caller has seen (`after`, same boot), answers what is left, or waits up to 25s for one. A different boot means the caller has seen nothing. Overflow drops the oldest and reports the count as `missed` until the caller has seen past it.
3. `notify` still logs every line; it never blocks and never calls back into custody (it runs under `custody.mu`).

## Acceptance tests (s2a)

1. Each code renders a fixed text; an unknown code, or a name outside the fixed shape, renders none.
2. `FromLog` maps each of the egress constants and inline lines named in item 1 of What to build, and nothing else.
3. Through the real custody: a wrong code and an allow on `/providers/private` each queue the matching notice.
4. `notice.sock`: answers queued notices; drops seen ones; waits and wakes on a new one; a new boot id resends; overflow reports `missed` and then clears; a peer other than agentosd's uid is refused by the existing listener.

Run tests with `-race`.

## Out of scope

agentosd's puller, the page lines, the remaining log-only notices (unlock, trusted host, card rotation): those stay logged until a row routes them.
