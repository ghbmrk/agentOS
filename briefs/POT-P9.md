# POT-P9: Carry a typed prior result through a compiled skill

**Owner:** primary, unclaimed. **Class:** later; promote only for a demonstrated recurring-workload blocker. **Tier:** A for effect/result binding.
**Requirements if promoted:** CAP-5, CHG-1/2/6, REV-2/5, OP-3, ARC-7.
**Needs:** POT-P1 measured workload; L1 acceptance of a versioned skill-format extension; compare a narrow composite adapter verb before changing the format.

Current skill nodes are literals, slots and objects filled before execution. If a real workflow needs a server-assigned object ID from an earlier step, propose one allowlisted typed handle from an earlier successful step in the same run. No arbitrary expressions, body extraction, loops, credentials or authority-bearing tokens.

Scope after promotion: `broker/skill/`, `broker/compile/`, targeted result binding and adoption tests. Bind handle to account, task, object type/version, run and source step. Recheck effect gates at use; a successful read is not permission for a later mutation. Failed, cancelled, rolled-back, stale, foreign or deleted results cannot be referenced.

Acceptance: compile one observed recurring trajectory, execute against a changing synthetic service-assigned ID, reject each foreign/stale/type-confused reference, and prove source content cannot generate a privileged expression. Existing literal skills retain behavior. Requalification/version migration and FORGET must be tested. No generic automation language. Tests first plus tier-A reviews. Initial checkpoint after promotion: 20k tokens for one handle type.
