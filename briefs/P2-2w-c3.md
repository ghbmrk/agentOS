## Boundary with P2-2w c4

c3 owns the helper and agentosd's `JoinNetwork` wiring, end to end: the page's `AgentosdSetup.JoinNetwork`, a `localapi` setup op, `localsrv.Setup` serving it, and agentosd calling the helper.

c4 keeps every other setup hook: `Networks` (the list in range), box number, host info, texts, host trust, providers, and real progress (including `Online`). c4 also gives `cmd/agentos-localui` its `AgentosdSetup`. Until c4 lands, the network step works through `InProcess` and in tests, as pairing does today (L28).

## Scope (files)

- `broker/netjoin/` (new): request validation, the fixed `agentos-home` connection settings, the NetworkManager seam (an interface whose test fake records the D-Bus calls), the socket server, tests and ASSUMPTIONS.md.
- `broker/cmd/agentos-netjoin/` (new): `main.go`, `agentos-netjoin.service`, the polkit rule file, and tests.
- `broker/localapi/`: one setup op (`page_setup_join`) and its fixed refusals.
- `broker/localsrv/`: `Setup` serves the join op under L6, with at most 6 tries a minute.
- `broker/localui/setuphooks.go` and its tests: `AgentosdSetup.JoinNetwork`. Also a localui ASSUMPTIONS row, or an amendment to L28.
- `broker/cmd/agentosd/`: a flag naming the helper's socket. Setup mode dials it.
- If D-Bus needs a library: `broker/go.mod`, `broker/vendor/`, `assurance/dependencies.json`, and one DECISIONS.md dependency row, in the form of the `rsc.io/qr` row.

## What to build

Build exactly the note's L8 conditions 1-7. Fixed points for the builder:

- **D-Bus client.** Reuse a mature, vendored client, preferably `github.com/godbus/dbus/v5`: BSD-2, no dependencies of its own. The PR says why if it chooses otherwise. Running `nmcli` with the PSK on its command line is not allowed (L8.5).
- **Join outcome.** The helper reports the result from NetworkManager's state for `agentos-home` after autoconnect, within a fixed wait. It must not depend on holding `network-control`.
- **Page wording.** The page's wording and its one "Could not join that Wi-Fi" error stay as they are.

## Acceptance tests

1. A peer whose uid is not agentosd's is refused before its request is read. Oversized, malformed or extra-field requests are refused with fixed codes.
2. Bounds are checked before any NetworkManager call. Test each SSID and PSK edge: 0, 1, 32 and 33 bytes; 7, 8, 63 and 64 characters; 64 hex vs 64 non-hex; non-printable characters. A refused request makes zero D-Bus calls on the fake.
3. The first join creates `agentos-home`, and a second join updates it in place. No call names another connection, a device, or an activate or delete method. The settings sent are exactly the fixed set, plus the SSID and PSK.
4. Once setup is closed, the join op is refused at `localsrv.Setup` and the helper is never called. The 7th try in a minute is refused.
5. A synthetic canary PSK appears in no log line, error, journal entry, setup record or agentosd state written during the tests, and only in the request to the fake.
6. The unit file and polkit rule match L8.1 and L8.2: a test parses them and checks the user, the missing capabilities, `NoNewPrivileges`, the address families, and the one granted action.

Run tests with `-race` on Linux. A mutation that drops the peer check or the bounds check must fail a test.

## Out of scope

- Listing networks in range.
- Ethernet detection.
- Changing the home Wi-Fi after setup (LATER P2-2w c3 f1).
- Concurrent access point and station on one radio: hardware, P2-1.
- Whether NetworkManager's store is encrypted at rest (L8.6, P2-1).
