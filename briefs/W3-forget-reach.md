# W3-forget-reach: Recall says when a take-back is done, and item 2 owes its text from the ask

Board section: Integration: wiring merged packages into the box. Follows W3-forget-b2c-2 (#541); SPEC CAP-3. Second of three packages that edit `broker/cmd/agentosd/forget.go` in turn (see Order).

**Sources:**
- L3 delta on #520, R1 ([record](../reviews/l3/2026-10-09-pr520-delta.md)): b2c-2's two residuals (ASSUMPTIONS of `broker/cmd/agentosd`, recorded by #541): (a) a crash after `takeBack` returns nil and before the owed entry is saved leaves item 2 done and the owner untold; (b) the `TakenBack` text recall's `Retry` sends on `ErrCarried` is sent once and forgotten, so a failed send or a crash loses it. A done-or-owed signal exists inside recalltool and is not exposed.
- Security 4a on #541, P2 ([record](../reviews/security/2026-10-09-pr541.md)): `Reach.TakeBack` returns nil when the machines are back but the reset's reach is unfinished (an unfinished `Reset`; `Retry` finishes it), and on `errUnrecorded`, where the reset was not recorded, the take-back is marked done and "its reach is left undone (logged)" (reach.go:319-330). Nothing then finishes that reach, and the owner is told "no longer holds it". The signal this row exposes must count a take-back done **only once its reach is finished too**, not merely "in `TakenBackFrom` and not in `TakeBacksOwed`".

**Requirement IDs** (the builder confirms each against SPEC.md and writes the failing test first):
- **CAP-3** (SPEC): "an agent that read it is rolled back to before the read … Actions already taken stay done." The owner is told the agent no longer holds the task only when that is true.
- **UX-182-3** (UX lens on #182; not a SPEC ID): a text promised or owed is sent after a restart; a lost send is not lost for good.
- **RCH-1** (this package, `broker/recalltool`): `Reach` gains one exported method that reports a take-back's state from `since`: not recorded; owed (recorded, or machines back with an unfinished reset: something will carry it); done (machines back, reset recorded **and** finished); and not known (recall not open, as `Handled`'s `ok`). Names are the builder's. Test each state on a real `Provenance` with fake machines, including an unfinished `Reset` (owed, not done) and the `errUnrecorded` path (not done).
- **RCH-2** (`broker/recalltool`): a take-back whose machines went back but whose reset was not recorded (`errUnrecorded`) is carried to done: a later `Retry` records the reset and finishes its reach **without running `ForgetSince` again** (a repeat rolls back later work; #327 L3 1). Until then RCH-1 reports it owed. Test: `MarkReset` fails once, then `Retry` records and finishes it; the fake machines see exactly one `ForgetSince`. What the record needs to survive a restart (the reset's `At`/`Until`) is the builder's design; persist it in `Provenance`, as owed take-backs are now.
- **RCH-3** (`broker/recalltool`): the caller can own the `TakenBack` text. When the owner-forget path sets it (a hook, or an option the builder names), `Retry` reports a take-back it finished to the caller instead of calling `tell(…, TakenBack)`; when unset, behavior is as today. Test both. Exactly one done text per approved take-back across `TakeBack` and `Retry`.
- **RCH-4** (`broker/cmd/agentosd`): item 2 saves its owed entry (the `Agent` entry of #541, keyed by item 2's ID) **before** `takeBack`, marked not yet done, and it is told done only when RCH-1 reports done: at once after `takeBack`, from the RCH-3 hook when `Retry` finishes it, or after a restart once recall opens (`resumeAgent`). An entry not done at restart is judged then; one marked done is told at attach as now (`finishOwed`). This closes residual (a) and (b). Tests: a crash after `takeBack` and before the send (entry on disk, not told) is told once after restart; a `Retry`-finished take-back whose send fails is told after restart; `ErrCarried` then `Retry` gives one text, not two; an unfinished reset is not told done until finished.
- **RCH-5** (`broker/cmd/agentosd`): `agentBackWithoutAsking`'s `back` flag (which picks the done text's tail `forgetBackupsOnly`/`forgetLoggedOnly`) is true only when RCH-1 reports done. Test with an unfinished reset: the tail keeps "your agent's own files may still hold it".
- **CH-12** (SPEC): no text changes wording. If the builder finds a case that needs a new text (say, a take-back carried for a long time), raise it as a finding; do not add it here.

**Design notes from the coordinator:**
- `Handled` keeps its meaning ("recorded, owed or done") and its one use: `resumeAgent` and `resumeRestored` skip a take-back recall already holds. It is never used to say done.
- `TakenBackFrom` is lineage-blind by design (a task's time names one take-back, whichever lineage the agent has now); keep RCH-1 lineage-blind the same way.
- The owner-forget path is the only caller of `TakeBack` today (W3-forget-b2b), so `Retry`'s `TakenBack` texts are all item 2's. Confirm with `grep` before relying on it, and say so in the PR.
- b2c-2's mutant set (M1-M8 in the #541 Security record) must still be killed after the change; add a mutant for "told done on an unfinished reset" and one for "`Retry` tells and the hook tells".
