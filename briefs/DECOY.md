# DECOY: breach decoys, heartbeats and drills (KRN-12)

Board section: Migration to the capability kernel (D-139) for slices a, b, e and f; Devices, hardware and image (SPEC §13-14) for c and d. SPEC KRN-12, KRN-10 (its limits; a trip gets KRN-12's own response), CLK-4 (the detector), KEY-3, KEY-4, KEY-6 (narrowing and resume), CH-15 (security class), NET-2 (channel, texts and calls), NET-4 (tightenings), DEP-3, KRN-6 (the simulator). Decision D-232. Six slices, one session each, tests first (CLAUDE.md), every touched package's `ASSUMPTIONS.md`.

## The gap

Canaries exist only in tests. A running box that is breached raises no alarm: an intruder who reads a sandbox's environment, opens the sealed store's entries, scans the home network or kills the core's process is never seen, and the enforcer's alerts ride the core's owner line, so a rooted core can swallow them.

- **Failure path:** an injected planner or a rooted sandbox, host or edge finds a credential-shaped value, uses it, and nothing trips; or a rooted core stops sending and nothing notices.

## Decisions (the brief's; a builder who finds one wrong stops and comments on the work item)

1. **One table, one matcher.** `broker/decoy/` holds the table type, the generator calls and the matcher. The matcher is CLK-4's fixed-pattern detector (`broker/browser/filter.go`'s patterns, moved into `broker/decoy/match/` and imported back by the browser clerk) with the table's values and destinations added. It runs on the core only: the enforcer trips on its fixed addresses (decision 4) and imports nothing from `broker/decoy/`.
2. **No new grant kind.** A honey key is a key-shaped value signed by no root. The key check already refuses it (KEY-1); the kernel looks a refused key up in the table and, on a hit, logs a trip instead of a plain refusal.
3. **The table is sealed and logged.** It is stored in the sealed store (STO-2), so neither the image nor the repository shows a decoy, and it reaches the kernel as one logged event at first boot (KRN-1), so a replay gives the same trips (KRN-6). The wallet seeds are not in it (decision 5).
4. **The enforcer's decoy addresses are fixed.** They are 169.254.169.254 and a never-assigned range of each segment, shipped in the enforcer's image; DHCP never hands them out, nothing is read over the channel, and placements that name a host (an SSH `known_hosts` entry for "core-admin", a "Backups" share path) point into the range. Drop-and-trip rules on them are part of the enforcer's own ruleset; no listener runs, and a trip cuts only the box it came from (KRN-12 Response), changing no other rule.
5. **Wallets use a mature library.** BIP39 seeds and BIP84 receive addresses through an existing Go library (for example `btcsuite/btcd/btcutil/hdkeychain`); the PR names why if it picks another. The box never broadcasts a transaction and holds no code that spends. Seeds are made at setup, outside the table, and never logged.
6. **No own line for now.** Mark chose the light only (2026-10-29 00:48:58Z): a trip or core silence at the enforcer shows on its light and page, and a tripped core stops answering once its modem plug is off. An own send-only line for the enforcer stays a later option, not a row.

## Slices

### DECOY-a (#3762): the table and the matcher (KRN-12 One table, Trips)

**Scope:** `broker/decoy/` (new), `broker/decoy/match/` (new), `broker/browser/filter.go` (imports the moved patterns), `tools/risk_tier.py` (one line; a gate file, so this PR also owes a separate Security accept, OPERATING §7).
**Builds:** the table (value, kind, destination, placement), its generation at first boot from the same generators that make real entries, its sealed storage and its first-boot log event (decision 3), and the matcher over bytes and destinations.
**Acceptance tests:**
1. KRN-12: `decoy::TestDecoyIndistinguishable`: for each kind, generated decoys pass an independent validator of the kind's published format (checksums included) and a two-sample test on length and character classes against a fixed corpus of synthetic, format-valid examples finds no difference. It covers values only: destinations point into the enforcer's public range by design (SPEC KRN-12 Limit). Catches a decoy value an intruder can skip.
2. KRN-12: `decoy::TestTableSealedAndReplayed`: the table is readable only through the sealed store, and replaying the log gives the same table and the same trips. Catches a public table or a nondeterministic trip.
3. CLK-4: `match::TestTableAndPatterns`: every table value and every existing CLK-4 pattern matches, split across two writes too; random high-entropy text without a table entry does not trip. Catches a lost CLK-4 case or a false trip.
**Size:** about 90k, tier A, strongest model. **Depends on:** #3761 and the D-232 row merged.

### DECOY-b (#3763): kernel trips and the response (KRN-12 Trips, Response)

**Scope:** `broker/kernel/` (trip entry, refusal lookup, outbound-path match, response, resume), `broker/egress/` (the connect-time decoy-address check), `broker/kernel/key/` only if the refusal needs a typed reason, and `tools/trusted_core.txt` (the `known` lines for the kernel's import of `broker/decoy/`). Trusted-core growth, here and in any slice that touches a core root (DECOY-e's `broker/clerk/seal/` included): a one-row DECISIONS PR naming this slice's PR and citing D-232 merges first, then the PR body carries `Trusted-core: <that row>` (D-159; `tools/trusted_base.py` accepts only a row naming the PR itself).
**Builds:** a `trip` log entry; a refused key that is in the table logs a trip; the kernel's outbound path runs the matcher, and the core's egress (`broker/egress/`) refuses and trips on a connection whose address at connect time, after any redirect, is a decoy address, stopping only that call; a trip pauses the keys of its scope (KEY-6's pause), stops planning, and queues one fixed-template security text; a honey-key trip, and a decoy value placed in the planner sandbox or its view that a planner session sends outbound, refuse that step and stop only that session, logged and texted like a honey-key trip; a resume of a trip's pause needs a passkey assertion (KEY-4), a texted RESUME is refused with fixed wording.
**Acceptance tests:**
1. KRN-12: `kernel::TestHoneyKeyTripsSessionOnly`, and `kernel::TestHostilePageDecoyDestinationStopsSessionOnly`: a fetched page that makes a planner request 169.254.169.254 or the decoy range refuses that step and stops only that session. Catches a careless planner stopping the box, or a honey key that authorizes.
2. KRN-12: `kernel::TestOutboundDecoyPausesScope`: a host-placed decoy value (or one with no planner session behind it) in an outbound request pauses that scope's keys before the request leaves, logs one trip and queues one security text. Catches a decoy that leaves.
   `kernel::TestSandboxDecoyFromInjectionStopsSessionOnly`: a sandbox- or view-placed decoy value that a planner session sends outbound, as injected content can make it, is refused before it leaves and stops only that session, with one trip logged and one text queued; planning goes on. Catches an injected page stopping planning box-wide.
3. KRN-12: `kernel::TestTripResumeNeedsPasskey`. Catches an intruder holding the owner's number undoing the pause.
4. KRN-6: `sim::TestTripDeterministic`: same log and events, same trip entries. Catches a nondeterministic matcher in the kernel.
5. KRN-12: `egress::TestRedirectToDecoyStopsCallOnly`: a core service with no planner session whose connection resolves or redirects to a decoy address, in plain, IPv4-mapped or NAT64 form, or that probes 169.254.169.254, has that call refused and logged as a trip, and nothing else stops. Catches untrusted DNS or a redirect stopping the box.
**Size:** about 110k, tier A, strongest model. **Depends on:** DECOY-a (#3762).

### DECOY-c (#3764): the edge (KRN-12 Placement, Trips, Silence)

**Scope:** `broker/edgelink/` (matcher on the core side of the link, heartbeat kind), `broker/edgelink/fetch/` (new: the edge's fetcher and its decoy-address check), the edge's image profile under `image/` (placements as data).
**Builds:** the matcher on everything the core sends to the edge except one placement kind that only the kernel sends, at enrolment; the edge's dotfiles and jackpot files written from the table through that kind, and the edge wallet seed, which the kernel's effect names only by its sealed-store handle and the sealed-store clerk fills in at send, so the log holds the handle, never the seed (KRN-1, KRN-12 Outside canaries); the edge's check of the address each fetch and every redirect connects to, at connect time, against the decoy addresses in its image, refused and reported on the link; a replaced edge gets a fresh wallet, never a re-sent seed; a signed heartbeat from the edge each interval, a missed one alarmed on the core.
**Acceptance tests:**
1. KRN-12: `edgelink::TestDecoyToEdgeTrips`: a decoy in any kind but the kernel's placement kind trips; enrolment and re-enrolment after a restore trip nothing. Catches a guest's query smuggling a decoy out, or a false trip at every enrolment.
2. KRN-12: `edgelink::TestHeartbeatSilenceAlarms`: two missed beats raise one alarm, a late beat clears nothing without the log saying so. Catches a killed edge going unseen.
3. KRN-12: the image test that the edge image adds no listener for any placement. Catches a fake service.
4. KRN-12: `edgelink::TestResolvedDecoyStopsSessionOnly`: a public name that resolves to 169.254.169.254 or the decoy range, and a redirect to one, are refused at the edge and stop only that session, as are a name that rebinds there between lookup and connect and the IPv4-mapped and NAT64 forms of each address; the enforcer sees no traffic. Catches DNS or a redirect turning a page into a box-wide stop.
**Size:** about 80k, tier A (the link), strongest model. **Depends on:** DECOY-b (#3763).

### DECOY-d (#3765): the enforcer (KRN-12 Placement, Trips, Silence; NET-2)

**Scope:** `broker/enforcer/decoy/` (new: the fixed addresses, decision 4), `broker/enforcer/nft/` (drop-and-trip rules), `broker/enforcer/channel/` and `broker/enforcer/wire/` (the heartbeat kind), `broker/enforcer/cut/` (new: the cut on a trip, the modem plug and the light bulb, paired and driven with ENF-h's radio stack), `broker/enforcer/alert/` (trip and silence alerts), `broker/kernel/enforcer/` (sending the heartbeat).
**Builds:** the fixed decoy addresses, kept out of DHCP; drop-and-trip rules; a trip lights the light, shows on the page and sends an alert through the kernel like NET-2's other alerts, and cuts the box it came from as KRN-12 Response says (a core trip: the core's internet, every core-segment path but the channel, and both plugs, the owner-line modem's and the edge box's; an edge trip: the edge's plug; a Devices trip: that device, attributed by its Wi-Fi password, unless it is on the safety list); the enforcer keeps no head from a tripped core, and its page tells the owner to reflash the core; after a core trip a passkey-signed "core reflashed" loosening, accepted only with a TPM quote of the core's measured boot (HW-5a) that matches the pinned release digest, reopens only the owner page and a fetch-only route from the core to the configured backup host's fixed address; the edge box and its second-line modem stay unpowered, and the passkey ending REC-5's visit lifts the rest; a cut survives a restart, no channel message lifts it, and only a passkey-signed loosening does; the core's signed heartbeat on the channel, silence alarmed with no cut.
**Acceptance tests:**
1. KRN-12: `nft::TestDecoyAddressDropsAndTrips` (network namespace). Catches a scan that goes unseen or reaches a listener.
2. KRN-12: `alert::TestCoreSilenceAlarmsNoCut`, and `alert::TestNoHeadFromTrippedCore`. Catches a dead core unseen, or a reboot that locks the owner out.
3. NET-2: `channel::TestHeartbeatStrictFrame`: the heartbeat frame carries only its fields and signature. Catches a heartbeat kind that smuggles anything else.
4. KRN-12: `cut::TestTripCutsOnlyItsBox`: a core trip drops the core's internet and every core-segment path but the channel, and switches off the owner-line modem's plug and the edge box's plug; an edge trip switches off only the edge's plug; no channel command reaches either plug or the bulb; a Devices trip isolates only the device whose Wi-Fi password sent it, and a safety-list device's trip only alerts; no other rule changes; the cut survives an enforcer restart, no channel message lifts it, and only a passkey-signed loosening does. After a core trip, the "core reflashed" loosening is refused without a matching TPM quote (a bare tap, or a core on an unmeasured image, opens nothing) and, with one, reopens only the owner page and the fetch-only backup route; the edge stays unpowered, and the core's other internet stays cut until REC-5's closing passkey. Catches a cut that misses its box, spreads, lifts without the owner, or reopens a way out through a tap, the edge or its second line. Also catches a recovery that deadlocks behind its own cut.
**Size:** about 120k, tier A, strongest model. **Depends on:** ENF-d (#3660), ENF-e (#3661), ENF-h (#3666).

### DECOY-e (#3766): placements and the wallets (KRN-12 Placement, Outside canaries)

**Scope:** `broker/decoy/place/` (new), the planner sandbox and host image placements under `image/`, the sealed store's decoy entries (`broker/clerk/seal/`), the planner's key view (honey keys), `broker/decoy/wallet/` (new), the edge seed copy through DECOY-c's placement path, the owner-page step (`broker/localui/`, sub B's directory: coordinate on the issue first).
**Builds:** environment variables, dotfiles and jackpot files in the sandbox and host, with core and edge services started under a clean environment and a HOME outside every placement, so no SDK credential chain or metadata client reads a decoy; decoy root and recovery entries in the sealed store; honey keys in the planner's view; three wallets made at setup, each seed planted at one boundary (the host's jackpot files, never the planner sandbox; the edge's; the sealed store, which every backup carries), receive addresses shown as QR codes in one optional owner-page step, never the seeds; after a core trip, only the reflashed core's owner page offers REC-5's restore with the switch set, to the enforcer's last head kept before the trip or a backup head that is it or an ancestor, which the reflashed core reads from the enforcer as an anchor together with the trip record (STO-1), and the restore makes fresh wallets; its cloud backup fetch runs in the first step over the fetch-only route, and its provider revokes and re-consents and CA-fingerprint text run after the closing passkey lifts the cut.
**Acceptance tests:**
1. KRN-12: `place::TestEveryPlacementFromTable`: each placement's bytes are a table entry, wallet seeds aside, each credential-shaped decoy names a destination in the enforcer's decoy range, and each kind on the list is placed. Catches code at a place or a missed place.
2. KRN-12: `wallet::TestSeedNeverLeaves`: the seed appears only in its decoy copies; logs, texts, the owner page, STATUS, the core's stores outside the three decoy copies, and a backup's contents beyond the sealed-store copy carry the address only; a restored host gets a fresh wallet, and no seed is in the planner sandbox. Catches a seed leak the owner pays for.
3. DEP-3: `wallet::TestSkippedStepCostsNothing`. Catches a required optional step.
4. REC-5: `restore::TestOfferOnlyAfterReflash`: a core that logged a trip never offers the restore; a reflashed core does, to the enforcer's last pre-trip head or an ancestor, and a restore past that head is refused. Catches a restore that ignores the trip or brings back the breach's own entries.
**Size:** about 110k, tier A, strongest model. **Depends on:** DECOY-a (#3762), DECOY-b (#3763), DECOY-c (#3764, the edge's placement path).

### DECOY-f (#3767): drills (KRN-12 Drills)

**Scope:** `broker/kernel/sim/` (drill scenario), the image test under `tests/image/`, `tests/` or `evals/` (the intruder playbook script), STATUS's broken line in the kernel's STATUS view.
**Builds:** a scripted intruder search over the sim box in the order KRN-12 lists; per tripwire, time to detect and false trips recorded in the log; a scheduled run (default weekly); STATUS lists a tripwire whose last drill is missing or failed as broken.
**Acceptance tests:**
1. KRN-12: `sim::TestDrillTripsEveryPlacement`: every table placement and enforcer decoy address trips within one minute of simulated time at its exit; the wallets are watched by the owner's phone and are not drilled. Catches a dead tripwire.
2. KRN-12: `sim::TestDrillNoFalseTrips`: an ordinary week of sim tasks, including a fetched public page that names 169.254.169.254 and the decoy range directly, by a name that resolves there, and by a redirect, trips nothing beyond refusing that step and stopping its one session, and planning goes on. Catches an alarm that cries wolf.
3. KRN-12: `kernel::TestStaleDrillShowsBroken`. Catches a tripwire trusted without proof.
4. KRN-12: `image::TestRealImagesNoFalseTrips` (QEMU): boot the core and edge images with a decoy table placed, run a scripted day of ordinary tasks, and assert that no packet reaches 169.254.169.254 or the decoy range and that no binary in either image is a metadata client. Catches a service, SDK credential chain or OS client that dials a decoy and cuts the box, which the sim box cannot show.
**Size:** about 80k, tier A (`broker/kernel/sim/`), strongest model. **Depends on:** DECOY-b to DECOY-e.
