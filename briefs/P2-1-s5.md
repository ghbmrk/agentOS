# P2-1 s5: the home Wi-Fi join never takes the access point's interface

Work item #1428 (Security S-R4, from the #1407 Security review). It lands with or before #936 (the station device), and before NetworkManager ships in the image.

**Requirements:**
- DEV-2: the home network is untrusted. The interface `agentos_ap` holds, or that the inbound exempt set names for the access point, never joins it.
- CH-7: the broker's own access point stays up on its interface while setup joins the home network; the join cannot move that radio into station mode.
- Binding conditions: Security S-R4 (#1407: "the join must go through the loader, or netjoin must refuse while agentos_ap holds the interface"), L8.3 and L8.4 (the helper's reach into NetworkManager), localui L34 (`APLoader.Station`).

**Acceptance:** A1 (setup on hardware, with P2-1 and #936).
**Acceptance tests:** DEV-2, CH-7 `broker/netjoin/netjoin_test.go::TestJoinRefusesTheAccessPointInterface`, `TestTheConnectionIsPinnedToTheStation`; `broker/cmd/agentos-netjoin/main_test.go::TestTheUnitRefusesTheAccessPointInterface`, `TestTheFlagsReachTheJoiner`.
**Implementation risk:** tier A. **Needs:** P2-2w c3/c4 (merged). **Gate:** lenses (security: strongest tier).

## Design (the issue's second option)

`agentosd → agentos-netjoin → NetworkManager` cannot run through `APLoader.Station`: the loader lives in `agentos-ap` (root), the join in the unprivileged helper, and NetworkManager autoconnects whenever it likes after the join returns, so wrapping the call would not cover the connection's later activations. So the helper refuses, and the connection it writes can only ever activate on the station interface:

1. **Configured interfaces.** `agentos-netjoin` takes `-station <if>` (the one interface the home connection may use; default none) and `-ap-iface <if>` (repeatable; the interfaces `agentos-ap` may run the access point on, its `-iface`). The unit passes `-ap-iface wlan0` and no `-station`, since the image has no station device until #936.
2. **Refusal.** `Joiner.Join` answers `failed` before any D-Bus call when no station is configured, the station is not a plain interface name, is `lo`, or is one of the access point interfaces, or no access point interface is configured. `failed` is what agentosd already maps to "I cannot join Wi-Fi yet, use Ethernet" (#1429), and nothing is written.
3. **Pinning.** `ConnectionSettings` sets `connection.interface-name` to the station, so NetworkManager never activates the home connection on any other device, the access point's included, now or at a later autoconnect.
4. **#936** states this design (a comment on the issue): its station device is the interface netjoin's unit names in `-station`, never agentos-ap's `-iface`.

## Acceptance tests

1. `Joiner`: with no station, an invalid one, `lo`, a station equal to an access point interface, or no access point interface, `Join` answers `failed` and makes no D-Bus call. With a valid station distinct from the access point interfaces, the existing join tests pass unchanged.
2. `ConnectionSettings` names the station in `connection.interface-name`; the connection written by a join carries it.
3. `agentos-netjoin`: the flags reach the `Joiner` (a join with the unit's flags is refused before any bus call); the unit's `ExecStart` passes `-ap-iface wlan0` and no `-station`; `nmBus`'s call test writes the pinned settings.
4. `grep -n "agentos_ap\|APLoader\|ap-iface" broker/netjoin broker/cmd/agentos-netjoin` finds the refusal.

Run tests with `-race`.
