# S8-W1 s7: A tool cannot read auth.json after the Codex CLI rewrites it

Board section: Phase 0: harness and risk spikes. Issue: [#1504](https://github.com/ghbmrk/agentOS/issues/1504) (release finding from the #1451-#1455 PR).

Codex CLI expands requirements.toml's `deny_read` into bwrap masks when each tool starts (guest/codex/ASSUMPTIONS.md C12). A file the CLI creates afterwards, or an auth.json it replaces by rename, is readable to the running tool. If a token refresh did that, a long-running tool could read the refreshed login.

**Requirements:** CRED-5, A14.

**Scope:** `guest/codex/ASSUMPTIONS.md` (C12). Widened to the Codex worker harness the test needs: `tests/test_codex_worker.py`, `tests/codex_worker/fake_endpoint.py`, `tests/codex_worker/stub_tool.py`. Not `guest/codex/build-rootfs.sh` (#1720), and none of #1951's qualification files.

**Approach:** the issue's second option. Pin, under the real CLI, that a refresh rewrites auth.json in place (so the mask set at tool start still covers it), that it writes only the route's placeholders, and that a dropped refresh (502, as `broker/egress` answers) leaves auth.json unchanged.

**Acceptance tests:** `tests/test_codex_worker.py` `CliSandboxTest.test_a_tool_cannot_read_auth_json_after_the_cli_rewrites_it` and `CliSandboxTest.test_a_dropped_refresh_leaves_auth_json_as_it_was` (opt-in: they need `AGENTOS_CODEX_CLI`). C12 cites both. doclint clean.

**Needs:** S8-W1 (#1419), #1749.
