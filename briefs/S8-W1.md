# S8-W1: Codex provider worker image

Board section: Phase 0: harness and risk spikes.

**Re-scoped 2026-10-13 (D-114).** Codex (ChatGPT plan) is the default plan route and runs broker-held (D-061): the CLI holds only placeholders, and the broker's egress proxy injects the real login (CRED-5). This row was the image fix for worker-held custody, written for Claude Code. Worker-held custody is now dropped for every provider (D-140).

**Owns for the plan chain:** the provider worker image with the pinned official Codex CLI. It also owns the CLI's managed configuration and the tool-subprocess sandbox. The configuration has five parts:
- A model provider with `requires_openai_auth = true` and a `base_url` at the in-worker forwarder (#1014). S8 completed a run this way: `spikes/S8-provider-workers/codex_provider.toml`.
- `CODEX_REFRESH_TOKEN_URL_OVERRIDE` pointing at the forwarder, so the CLI's token refresh reaches the broker's swap (ADP-10).
- Plugins, MCP, analytics and auto-update off.
- **Hosted tools off** (CRED-5 W4's "provider-side fetch tools … off", carried over for Codex). Web search and every other hosted tool, meaning a tool OpenAI runs on its side when the request asks for it, are off by managed configuration. These ride inside the body of the one declared responses request, so the declared-endpoint list cannot stop them: a model-directed run on a private-labelled caller could otherwise have OpenAI fetch an attacker URL carrying private data. The builder records the config keys used in `image/ASSUMPTIONS.md`. #1014's request-body check is the enforcement; this setting keeps a correct CLI from tripping it. #809 measures which hosted tool types the pinned CLI still sends.
- `codex exec --json` as the headless command.

The image has no `auth.json`. #1015 writes the placeholder `auth.json` into the worker's scratch at create.

**Tool sandbox (the defensive half kept from the worker-held design).** Codex's tool subprocesses have no network: they cannot reach the forwarder, loopback or the egress socket. A tool holding the placeholder could otherwise spend the owner's plan through the proxy, which injects the real login. The sandbox is the bwrap prefix for the tool shell, plus managed-policy denies on the forwarder's socket path. It is tested with stub CLIs and synthetic canaries only.

**Image test.** The image test fails if the managed configuration leaves web search or any other hosted tool on, alongside the `base_url` and refresh-override checks #1014 adds.

**Simpler than the worker-held design:** this row has no launcher, no token fetch, no `CLAUDE_CODE_OAUTH_TOKEN`, and no `/proc` containment of a real login, since the CLI never holds one.
