# INFER-SVC: The local inference service, with an embedding call

Board row: issue #2217 (section Phase 3: compounding). Class: release. Tier: A (`tools/risk_tier.py` prints A for the planned paths: `broker/cmd/...` is wiring, `image/` builds what ships, and a new broker package is A until classed; this brief itself is docs-only). Builder: strongest model. Usage estimate: 110k tokens, checkpoint at 80k; split at the checkpoint if the runtime build (INF-3) is not green by then (INF-1, INF-2, INF-4, INF-5 against the fake runtime as one PR; INF-3 and INF-7 as the second). Needs: the runtime decision below (Q1; the builder proceeds on the recommended default if no answer has landed), and the G2 freeze: `tools/g1_scope.py` reports `broker/infer/` and `broker/cmd/agentos-infer/` outside `tools/g1_scope_g2.txt`, so the build starts only after a separate Mark-merged PR adds them to that list (or G2 passes); its first line cites this brief. Unblocks RECALL-EMB (#1134). Brief only for INF-7: the N95 step needs the hardware, so a builder with no N95 ships the code and CI tests, leaves the row `state:building` with that step open, and says so in the PR (OPERATING §5 hand-off).

**Why (facts, verified at main 912250c).** SPEC §4 lists Local inference as an untrusted service ("small model, speech, embeddings, leverage passes for the main route (CAP-13); uses accelerators when present"), but nothing runs one: `broker/cmd/agentosd/main.go:586` says "No local inference service exists yet to take leases (budget R8)". `broker/budget/budget.go:141` already creates the `inference` cgroup component at `InferenceMB` (default 2048, RES-2) with nothing placed in it. `broker/daemon/inference_test.go` (`TestAgentosdLinksNoInference`, ARC-2) forbids agentosd from linking `route`, `egress`, `cmd/agentos-egress`, any provider SDK, any HTTP client but `modelroute`'s, and any non-unix socket. RECALL-EMB (#2216) needs a service that takes texts and returns vectors with the model file hash, reporting `missing`, `corrupt` or `unavailable`, and must not reach it through `modelroute` (the vault process's credentialed egress, REV-6).

## Requirements (from SPEC.md)

- **ARC-2** the broker's control path never invokes inference: the model runs in its own process, agentosd holds only a client. **RES-2** per-component cgroup budget, local inference 2.0 GB. **RES-3** the identical service runs on CPU with no accelerator; nothing in the broker depends on one. **REV-6** private content, embeddings included, stays off hosted routes. **CAP-13** the retrieve pass is local. **HW-4** every acceptance test passes at the floor (N95, 8 GB, no accelerator). **DEP-1** boot, owner control and recovery never need inference.

Package IDs:
- **INF-1** Process and budget. agentosd starts `agentos-infer` through `broker/childproc` (the only broker code that starts a process) into the existing `inference` cgroup leaf (`UseCgroupFD`, the `vm/gvisor/gvisor.go:176` precedent), as a dedicated user (`-infer-uid @uid:agentos-infer`, the `with-uids` pattern in `agentosd.service`), in new user, network and IPC namespaces (the `loop7.go:1223` jail pattern, reimplemented, not imported: loop7 is frozen), with no_new_privs and `KillGroup`. CPU only: it takes no accelerator lease (RES-3; leases are a later row, budget R8 stays open). The leaf's `memory.max` is the `InferenceMB` budget.
- **INF-2** Socket and protocol. agentosd creates the listener at a configured path (default `/run/agentos/infer/infer.sock`, directory 0700 owned by agentosd) and passes it to the child as fd 3, so the child neither creates nor names sockets. Protocol: one JSON object per line. Requests `{"op":"hello"}` and `{"op":"embed","texts":[...]}`; replies `{"model":NAME,"sha256":HEX,"dim":N,"state":"ready"}`, `{"sha256":HEX,"dim":N,"vectors":[[...],...]}` or `{"error":"missing|corrupt|unavailable|bad_request","detail":TEXT}`. Bounds, enforced by both sides: 64 texts per request, 8 KiB per text, request line 1 MiB, reply line 4 MiB. The client in `broker/infer` sets a per-call deadline (default 2 s, config), and treats a reply with the wrong vector count, a wrong `dim`, a non-finite float, an over-long line or a closed connection as `unavailable`, never as data.
- **INF-3** The embed call with a real runtime. `agentos-infer` loads the model file named in config (EmbeddingGemma 2 270M, the RECALL-EMB model), computes its SHA-256 while loading, and reports it in every reply; embed returns `dim` (768 for that model) floats per text, the same vector for the same text. The runtime is the one Q1 settles; the service is a small Go program that owns the socket, the bounds and the error causes, and drives the runtime as its child or library, so the protocol does not change with the runtime.
- **INF-4** Failure without crashing. Model file absent: the service stays up and answers `missing`. File present but its hash differs from the pin (`-model-sha256`, from config), or the runtime refuses it: `corrupt`. Runtime crashed, hung past its deadline or out of memory: `unavailable` for that call, and the service restarts the runtime. The service process exiting (any cause, including an OOM kill in the leaf): agentosd restarts it with backoff (1 s doubling to 60 s, reset after 5 minutes up), and the client sees `unavailable` meanwhile. agentosd starts, serves owner control and recovers with the service absent, disabled or crash-looping (DEP-1). `Supervisor.State()` gives state, cause and restart count for STATUS; the owner-visible line is RECALL-EMB's (EMB-3), not this package's.
- **INF-5** ARC-2 link graph. `cmd/agentos-infer` is added to `forbidden` in `inference_test.go` (and to its self-check beside `route` and `egress`), so agentosd can never link the runtime side. `broker/infer` (protocol and client) imports the standard library only, dials `unix` only, and has no `net/http`, `os/exec`, `plugin`, `unsafe` or `C`; the supervisor lives in `broker/infer/supervise`, which may import `childproc`, `cgroup` and `budget` and is not imported by `broker/infer`. `netOK` in `inference_test.go` is a per-package allowlist, so both packages get an entry, each by review with its reason: `infer` ("dials only the inference service's unix socket", `net.Conn` and `net.Dialer`, as `modelroute`) and `infer/supervise` ("creates the service's unix listener and its child's namespaces", only the `net` listener names and `syscall` namespace and credential names it uses, listed in the entry). Every dial and `Listen` still names `"unix"` (`sourceUse`). No other exception to `TestAgentosdLinksNoInference` is needed; `os/exec` stays in `childproc` alone.
- **INF-6** No network, no credentials (REV-6). The child has only a down loopback in its network namespace, so it can reach no address; its user cannot open `/run/agentos-egress/` (the vault process's sockets) or any other broker socket directory; its environment is `childproc`'s allowlist with nothing added; it gets no file descriptor but the listener, stdout and stderr. The model file is read-only to it.
- **INF-7** Floor figures (HW-4), recorded in the PR and in `broker/infer/ASSUMPTIONS.md`: service RSS at idle and at peak over a batch of 64 texts of 512 tokens, cold start (spawn to `ready`), single-text embed p50 and p95, and batch-of-32 throughput. Limits: RSS peak <= 1.0 GB (RECALL-EMB EMB-5's embedder limit, half the inference budget), cold start <= 15 s, single-text embed p95 <= 200 ms at the socket (EMB-5 allows 250 ms end to end). The builder may tighten them from the first measurement, never loosen without a PR note.
- **INF-8** Synthetic data only. Fixtures are synthetic text and a synthetic model stand-in; no log line of the service or the supervisor carries request text or vectors (counts, sizes, durations and causes only).

## Design

- `broker/infer`: `proto.go` (wire types, bounds, causes), `client.go` (`Dial(path)`, `Hello(ctx)`, `Embed(ctx, texts) ([][]float32, Info, error)` where the error carries one of the four causes). RECALL-EMB's `ServiceEmbedder` uses this client; its arc2 entry allows `infer` besides `recall` (amended in `briefs/RECALL-EMB.md` by this brief's PR).
- `broker/infer/supervise`: `Start(ctx, Options)` creates the socket directory and listener, builds the `childproc.Options` (cgroup FD, namespaces, uid and gid, `ExtraFiles: [listener]`, `KillGroup`), runs the restart loop, and exposes `State()`. agentosd calls it after the budget groups exist and never waits on it.
- `broker/cmd/agentos-infer`: `main.go` takes the listener from fd 3, the model path, the pin and the runtime path from flags; hashes and loads; serves one connection per goroutine with a small concurrency cap (2, config) so a burst queues rather than multiplying memory. The runtime adapter is one file (`runtime_<name>.go`) behind a two-method interface (`Load(path) (dim, error)`, `Embed(texts) ([][]float32, error)`), so Q1 changes one file.
- Image: `image/build.sh` builds or installs the runtime and the model at pinned versions and hashes (default per Q1 and Q2), installs `agentos-infer`, and adds the `agentos-infer` user to `agentos-setup.conf`; `agentosd.service` gains `-infer-uid @uid:agentos-infer`. Go stays `CGO_ENABLED=0`: with the default runtime the C++ code is a separate executable, not linked.

## Open questions for Mark (the coordinator posts them as a Decisions card)

- **Q1 Model runtime.** Recommended: **llama.cpp** (`llama-server` in embedding mode, built from a pinned upstream release in the image, driven by `agentos-infer` over a private unix socket or stdio). MIT, runs EmbeddingGemma from GGUF at q8 on CPU, and has a Vulkan backend for a later iGPU lease (RES-3) with the same service. Alternative: **ONNX Runtime** (MIT, also strong on CPU, but its Go use needs cgo or a C++ shim of our own, and its accelerator story on Intel iGPU is OpenVINO, a second large dependency). Rejected: pure-Go inference (no maintained implementation of this model; a new component where reuse works). Answer: llama.cpp or onnx.
- **Q2 Model delivery.** Recommended: **in the image**, pinned by hash (about 300 MB at q8; no first-boot fetch, no new egress path, updates ride the signed image). Alternative: fetched on first use through the update channel (smaller image, but a fetch path and a "not yet downloaded" state). Answer: image or fetch.

## Assumptions (recorded in `broker/infer/ASSUMPTIONS.md`, new)

- [Inference] The chosen runtime can serve embeddings without opening a TCP port (unix socket or stdio); if only TCP works, it binds 127.0.0.1 inside the child's own network namespace after the service brings loopback up, which still reaches nothing outside (INF-6 test unchanged).
- The model's licence permits shipping it in the image (RECALL-EMB's assumption; verify before building, else stop and escalate).
- A user namespace with a one-uid map is available to agentosd on the target kernel, as loop7's jail already requires.
- 2 concurrent requests at batch 64 fit the 2.0 GB leaf with the 1.0 GB embedder figure; INF-7 confirms or the cap drops.
