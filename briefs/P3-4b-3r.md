## P3-4b-3r-env

**Goal:** no broker child inherits the daemon's environment, and the owed check catches every way of starting one.

**IDs:** ARC-2 (the child-process path is reviewed), LOOP-7. Tests carry `REQ: ARC-2`.

**Sources:** #560 L3 point 5 (comment 6076986110: `envExempt` children still inherit, and agentosd's environment carries `AGENTOS_OWNER`) and point 4 (`execWithoutEnv` accepts `cmd.Env = append(os.Environ(), …)`; `cmd/agentos-guest-bridge/main.go:76` does this); #560 Security 4 (comment 6076971513: chronyc inherits `AGENTOS_OWNER`, the owner's number, from `EnvironmentFile`); #548 Security 4a point 4 (comment 6075894827: `machprobe.Press("processes")` calls `os.StartProcess` with a nil `Env`, a third shape the check misses); `reviews/security/README.md` row "A broker child process inherits the daemon's whole environment"; agentosd ASSUMPTIONS L7-2.

### Requirements (each with a failing test first)
1. **Production children get an explicit environment** (3a-r1, 3a-r2). `envExempt` (`daemon/inference_test.go:608`) exempts `clock/chrony.go:runChronyc`, `vm/gvisor/gvisor.go:cmd` (runsc), `modem/at/audio.go:Record` and `Play` (arecord, aplay). Give each an explicit minimal `Env`: `PATH` set to a fixed value, plus only what the tool needs by name (the builder lists each in the call site's comment; runsc's guest environment is in the OCI spec, not here). `envExempt` then holds only test fixtures (`tpmseal/swtpm`, `quota/quotatest`). Pin that: a test fails when an `envExempt` entry is in a package that any `cmd/` binary links (`go list -deps ./cmd/...`, run from the test). Tests: chronyc started while the parent's environment holds a synthetic `AGENTOS_OWNER` canary does not see it (a fake `chronyc` on `PATH` that dumps its environment; fails on main); the same for one audio tool; the existing chrony, gVisor and modem tests stay green, including the `machines` job's runsc tests.
2. **No `os.Environ()` in a child's environment** (3a-r7). `execWithoutEnv` accepts any `.Env =` assignment. Extend it: an `os.Environ()` or `syscall.Environ()` call anywhere inside an `Env` value (assignment or literal key) in non-test broker code fails the check, with no exemption list. Fix `cmd/agentos-guest-bridge/main.go:76` (`child.Env = append(os.Environ(), "OPENCLAW_GATEWAY_TOKEN="+token)`) to an explicit list: `PATH`, `HOME`, the token, and any variable the OpenClaw guest needs, named from its image. Tests: planted fixtures for both call forms fail the check; the OpenClaw guest test under gVisor (`machines` job, P1-7) still passes; a parent canary variable is absent from the bridge's child (unit test with a fake child).
3. **Every way of starting a child is checked** (4c-env). The check covers `exec.Cmd` only. Widen it to `os.StartProcess` (a nil `*os.ProcAttr`, or one without `Env`), `syscall.ForkExec` and `syscall.StartProcess` (a `*syscall.ProcAttr` without `Env`), under any import name. Fix `broker/machprobe/machprobe.go:102` (`os.StartProcess(o.Child[0], o.Child, &os.ProcAttr{})`) with an explicit empty or minimal `Env`. Tests: one planted fixture per shape fails the check (each fails against today's check); the tree passes; `machprobe`'s tests and the gVisor exhaustion test stay green.
4. **Records.** Update the Security README row's "Check" cell to the widened check and point its owner column at this package; agentosd ASSUMPTIONS L7-2 (exemptions are now test fixtures only); `broker/machprobe/ASSUMPTIONS.md` if it states the child's environment.

**Threat check:** the owner's number or a credential reaching a helper's environment (requirement 1); a refactor reintroducing inheritance through `append(os.Environ(), …)` or a lower-level call (requirements 2 and 3); a minimal environment that breaks a production child (the existing chrony, runsc, modem and OpenClaw tests).

## P3-4b-3r-confine

**Goal:** a fuzz child cannot take the broker down: it runs without root, without the network, in a cgroup leaf with its own memory and process limits, and its cache cannot fill the state disk.

**IDs:** LOOP-1 (fuzzing never starves the agent or the broker), LOOP-7, ARC-2. Tests carry `REQ: LOOP-1, LOOP-7`.

**Sources:** #560 Security 3 (comment 6076971513: children run as root with capabilities in agentosd's network namespace and cgroup; "put children in a cgroup leaf with `memory.max`, and use `CLONE_NEWNET` … and an unprivileged `Credential` once the target dirs are chowned") and 5 (cache unbounded on `/var/lib/agentos`, shared with the journal and state); #560 L3 point 2 (comment 6076986110: the `broker/` cgroup has no `memory.max`, `budget.go:138`; Go's fuzz engine has no RSS limit) and point 6; #560 UX/Potency (comment 6076984784, cache cap); loop7 F2, F7, F9, F12; agentosd ASSUMPTIONS L7-1 to L7-3; `agentosd.service` (no `User=`; `Delegate=yes`).

### Requirements (each with a failing test first)
1. **Own cgroup leaf with limits** (3a-r3). `agentosd` creates one leaf for fuzz children beside `broker/` under its delegated root (`broker/cgroup` `Child`), with `memory.max`, `pids.max` and a CPU weight below the broker's. Recommended starting values, checked against the HW-4 floor (4 cores, 8 GB) and recorded in agentosd ASSUMPTIONS: 1 GiB, 256 pids, the lowest weight in use. Children start inside it through `SysProcAttr.UseCgroupFD` and `CgroupFD`, so no child runs a moment in `broker/`. `loop7.Config` takes the leaf as a field the wiring sets; with none (tests, dev builds) the runner behaves as today. Tests (root, cgroup v2; skip without `AGENTOS_CGROUP_PARENT`): a child is in the leaf, not in the broker's group; a fake child that allocates past `memory.max` is killed in the leaf while the test process is unaffected; what the runner then reports follows F12 (a target finding or a runner error; the builder states which, with a test).
2. **No network, no root** (3a-r3). Children start with `Cloneflags: CLONE_NEWNET` (an empty network namespace) and an unprivileged `Credential` (a system user such as `agentos-fuzz`, created by a `sysusers.d` file in the image), with no ambient capabilities. The state directory `<state>/loop7` and its subdirectories belong to that user (a `tmpfiles.d` line, plus a chown when `Load` creates them), and the release's seeds stay read-only and root-owned. Tests (root): a child's uid is not 0 and its effective capability set is empty (read from `/proc/<pid>/status`); a child that dials a TCP or UDP address on the host fails; a target with a stored crash input still reports it through `Report` (the existing runner tests, run as root).
3. **The fuzz cache is bounded** (3a-r4). Before each fuzz step, the runner prunes `CacheDir/fuzz/<pkg>` to a per-package cap (recommended 64 MiB) and keeps the total under a box cap (recommended 512 MiB), removing the oldest generated entries first. It never prunes `<state>/targets/<pkg>/testdata`, which holds crash inputs and is evidence (F3, F9). Tests: a cache seeded past the cap is pruned to it before the step; crash inputs are never removed; a cache under the cap is untouched.
4. **CI runs the root tests.** Add `./loop7` (and the `cmd/agentosd` leaf test, by `-run`) to the `machines` job's "Machine tests as root" step, which already has `AGENTOS_CGROUP_PARENT`. The new tests skip elsewhere, and the PR shows them as RUN then PASS in that job.
5. **Records.** loop7 F2 and F7 (the leaf, the user, the network namespace), F9 (who owns the state directory), a new F row for the cache cap; agentosd ASSUMPTIONS L7-1 and L7-2.

**Threat check:** a fuzz input that blows memory bringing the OOM killer onto `agentosd` (requirement 1); a decoder bug becoming code running as root with the broker's network (requirement 2); the cache filling the disk the journal shares (requirement 3); a crash input pruned as cache, losing evidence (requirement 3); a child briefly in the broker's cgroup before it is moved (`CgroupFD` avoids the race).

**Scope:** `broker/loop7/loop7.go` (`run`, `Config`, `Load`'s directory ownership, the cache prune), its tests, `broker/loop7/ASSUMPTIONS.md`; `broker/cmd/agentosd/learn.go` (the leaf and the user), `main.go` only if the cgroup root is needed there, their tests, `ASSUMPTIONS.md`; `image/mkosi/mkosi.extra/usr/lib/sysusers.d/` (new file), `image/mkosi/mkosi.extra/usr/lib/tmpfiles.d/agentos.conf`, `tests/test_image.py` (the user and the directory line exist); `.github/workflows/ci.yml` (the `machines` job's package list only).

**Not here:** sweeping stale `run-*` directories (LATER P3-4b-3a l1).

**Estimate:** ~110k. Checkpoint at 60k: requirements 1 and 3 green.

## P3-4b-3r-fuzz

**Goal:** a fuzzed input that hangs a worker becomes a finding; a hang finding has a defined way to close; and what the owner and the records say about it is true.

**IDs:** LOOP-7, LOOP-9 (the owner is told, and told when it ends; a finding closes only on evidence). Tests carry `REQ: LOOP-7, LOOP-9`.

**Sources:** BOARD P3-4b-3h; #560 Security re-sign at ff1d55d point 1 (comment 6077323678: with Go 1.26.8, a target that loops on inputs longer than 3 bytes under `-test.fuzz -test.fuzztime=8s -test.parallel=1` prints `execs: 1 (0/sec)` until the deadline, then `PASS`, exits 0 and writes no input; proposal: a target finding when the step's last `fuzz: elapsed … execs: N` line shows no progress past the baseline; correct F12's wording); #560 L3 at 01cbe10 points 1 and 2 (comment 6077635344: nothing closes an overrun finding; F13, F10 and the code comment cite "P3-4b-3c's rules", which merged 3c does not have; an open overrun finding suppresses S39's cleared text for later crash fixes in the same target, because `clearedLinesLocked` keys on check and plain name; the owner text says "found a crash" for a hang; remedy: close an overrun finding once a new release's target binary completes a step in time, recorded as not a replay); #560 Security re-sign at 01cbe10 point 1 (comment 6077623141: define the closing evidence); #560 UX (comment 6076984784) for 3a-r6; #570 L3 nits 1 and 2 (comment 6077858108).

### Requirements (each with a failing test first)
1. **A stalled fuzz step is a finding** (3h). After a fuzz step, the runner reads the engine's progress lines (`fuzz: elapsed: …, execs: N …`, and the baseline line `gathering baseline coverage: K/K completed`). If the step exited 0 with a last `execs` count that never moved past the baseline count, it reports a target finding with a new detail, "a fuzzed input stopped the fuzz engine making progress". A step too short to print a progress line is not a stall. Tests: a fake target printing Go-shaped lines whose `execs` stays at the baseline and that exits 0 is reported (fails on main, where it is a clean step); one whose count rises is not; one that prints no progress line is not. One real-toolchain test builds a planted test-only fuzz target that loops forever on inputs longer than 3 bytes (`go test -c`, under the package's `testdata`) and runs it through the runner with a short `FuzzTime`: it is reported. If the real-toolchain test passes 60 s on CI, gate it behind `-short` and run it in the soak job.
2. **The closing evidence for a hang** (3h). A target finding for an overrun or a stall is never resolved by `Resolve` (it has no stored input; S30, S32). It closes only when a fuzz step of that target, run from a binary whose SHA-256 differs from the one that produced the finding, stops within its bound and moves its exec count past the baseline. loop7 records the producing binary's digest in its state directory (`<state>/targets/<pkg>/hang.json` or similar, restart-safe) when it reports. loops gains one narrow close path for this (for example `Guard.CloseTarget(ctx, id, Closure{Kind: "step", Binary: digest, Execs: n})`): it accepts only an open, reported, rule-less `fuzz` finding whose `Detail` is a target detail, never an input digest, saves the closure on the finding's evidence marked as not a replay, and sends the cleared text through S39's path. Tests: on the same binary, a good step leaves the finding open (pins today's behavior and the new rule); on a new binary, a good step closes it, saves a closure marked not a replay, and texts "Cleared" once if the finding was texted; a closure for an input-digest finding is refused; a restart between report and close keeps the digest.
3. **The owner text says hang, not crash** (3a-r6, 3h; `secure.go:1307`). `findingText`'s `CheckFuzz` case says "found a crash in" for every fuzz finding. A target finding for an overrun or a stall reads, suggested: "My self-test of <plain subject> stopped responding to a test input. The fix comes with an update." A no-input target finding keeps the crash wording. The identifier part of 3a-r6 was fixed by #558 (plain names, S41, and the lens test); this package adds one clause to `TestFindingTextsNameNoIdentifiersAndNeverAlarmWithoutAStep`: a fuzz target finding with a hang detail does not contain "crash". loops cannot import loop7, so the hang details move to exported constants in `broker/loops` that loop7 uses. Tests: the hang text for each hang detail; the crash text unchanged for an input finding.
4. **A hang finding does not hide another finding's cleared text** (3h). `clearedLinesLocked` keys on (check, plain name), so an open hang finding on target T suppresses the cleared line for a crash fix on T. Key a target-detail finding apart from input findings (add whether the detail is a target detail to the key). Test: with a hang finding open on T, a crash finding on T that resolves sends its cleared line (fails on main).
5. **The records say what is true** (3h; #570 nit 2). Correct F12 (it detects an engine that ignores `-test.fuzztime` and, after this package, a step that stalls; not every hang), F13 (name this package's close rule, not 3c's), F10 (a removed target's finding: nothing closes it; it stays open and STATUS shows it; point at LATER P3-4b-3 l8, since this package does not close it), the code comment at `loop7.go:353`, and the test comment at `runner_test.go:383`. No text in the tree says "P3-4b-3c's rules" afterwards (`grep` in the PR). loops S30 gains the new close path.

**Threat check:** a guest or a crafted binary forcing a false close (only a different release binary that completes a good step closes; the binary is release-listed, F7); a stall detector fooled by the engine's output format (it reads only the engine's own lines from the child's stdout, and a missing line is no finding, never a pass); a hang closed on the same release by luck (requirement 2 needs a new binary); a cleared text for a finding that did not clear (requirement 2's text goes through S39's dedupe).

**Scope:** `broker/loop7/loop7.go` (`Fuzz`, the target details, the hang state file), `loop7_test.go`, `runner_test.go`, a planted target under `broker/loop7/testdata/`, `broker/loop7/ASSUMPTIONS.md` (F10, F12, F13); `broker/loops/report.go` (the close path and `clearedLinesLocked`'s key), `broker/loops/secure.go` (`findingText`'s `CheckFuzz` case only), their tests, `broker/loops/ASSUMPTIONS.md` (S30, S39); `.github/workflows/soak.yml` only if requirement 1's real test is gated.

**Estimate:** ~110k. Checkpoint at 60k: requirements 1 and 2 green.

## P3-4b-3r-pass

**Goal:** `Pass` never says a finding cleared when its check did not run, tells the owner whenever a texted finding clears, and STATUS says when fuzzing has stopped making progress.

**IDs:** LOOP-9 (told per severity and told when it ends), LOOP-7, LOOP-1. Tests carry `REQ: LOOP-9` (add LOOP-7 on the digest-line tests).

**Sources:** #558 Security 4a point 2 (comment 6076792152: `check()` adds a failed check to `failed` and returns no findings for it; `Pass`'s close loop never reads `failed`, so every open finding of that check moves to Cleared; fix: skip open findings whose `Check` is in this pass's `failed`); #558 L3 point 3 (comment 6076810764: reproduced a false "Cleared: guest-image/openclaw. The agent machine stays paused…" with `Signed` erroring); #558 Potency (comment 6076778509: `Pass`'s clear path texts only paused findings; apply the `rec.Texted` test at the `later = append(later, clearedLine(rec))` line); #560 Potency (comment 6076984784) and L3 point 3 (comment 6076986110) for 3a-r5: a broken fuzz setup is visible only in the log; ask: one digest line when fuzzing is configured but has made no progress for longer than its recheck interval, and a log when `fuzzTargets` returns none on a box that should have a manifest; loops S39.

### Requirements (each with a failing test first)
1. **A check that failed closes nothing** (3c-r1). In `Pass` (`secure.go:416`), an open record whose `Check` is in this pass's `failed` stays open, unseen or not. Tests, each failing on main first: a paused, texted hash finding, then a pass where `Signed` errors: the finding stays open and no cleared text is sent; the next pass where the check runs clean closes it and sends the cleared line once. Same for an unpaused finding of another passive check.
2. **Cleared text for every texted finding** (3c-r2; S39). `Pass` sends the cleared line for every record with `Texted`, paused or not, through the same dedupe `clearedLinesLocked` (`report.go:274`) gives `Resolve` and `runProbe` (S39), never urgent; an untexted finding clears only in STATUS and the digest. Tests: texted and unpaused gives one "Cleared: … Nothing more is needed from you."; texted and paused gives today's line; untexted gives no text; two texted findings sharing a plain name send one line only when both have cleared.
3. **Fuzz progress in STATUS** (3a-r5). `loop7.Source.Digest` adds one plain line when fuzzing is configured (targets > 0) and no fuzz step has completed for longer than `Recheck()` (suggested: "Loop 2: my fuzz self-tests have not run for N days."), or when a target fails to run on every turn for a full cycle ("one of my fuzz self-tests cannot run"); no target name, path or identifier (the UX lens test applies). The time is taken when a step completes, not when it is offered. `learn.go` logs once when `fuzzTargets` returns none while the release directory exists (an image should always ship a manifest, L7-4). Tests: a source whose steps are all preempted or fail for longer than `Recheck()` shows the line; a source that completes steps does not; a target that errors every turn is named generically; the log fires on a release directory with no manifest.
4. **Records.** S39 (the `Pass` clear path), a loop7 F row for the digest line, agentosd ASSUMPTIONS L7-4.

**Threat check:** a false "Cleared" while a paused finding is still real (requirement 1); a cleared text for a finding that did not clear (requirement 2 sends only where `Pass` closes, after requirement 1); an owner who believes fuzzing protects the box while it silently does not run (requirement 3).

**Scope:** `broker/loops/secure.go` (`Pass` only), `secure_test.go` or `ownertext_test.go`, `broker/loops/ASSUMPTIONS.md` (S39); `broker/loop7/loop7.go` (`Digest`, the completion time), `loop7_test.go`, `broker/loop7/ASSUMPTIONS.md`; `broker/cmd/agentosd/learn.go` (`fuzzTargets`' log), its test, `ASSUMPTIONS.md` (L7-4).

**Estimate:** ~80k. Checkpoint at 45k: requirements 1 and 2 green.
