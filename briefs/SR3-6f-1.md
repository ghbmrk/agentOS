# SR3-6f-1: One attestor source for every update check (SR3-6-f1)

Release findings on #430 (SR3-6, merged 5ece9c3): Security 4a S1 and point 2 ([note](../reviews/security/2026-10-08-pr430.md)), also Potency later 1. Filed as SR3-6-f1. It also takes point 5 of SR3-6-f3 (wire `NoteAttestors`), since that is the same change. SPEC rows: UPD-8 (a narrowed attestor policy retires authority it granted), and U7 and U16 in `broker/update/ASSUMPTIONS.md`; acceptance A14.

**Why one package.** Two small changes, both about the attestor policy digest staying narrow:
- the wiring condition in `broker/maintain` (one source, read per check);
- a committed fail-closed test in `broker/update`.

About 120 lines of code and tests. No split.

**Order.** It is a W5b wiring condition, so it must land before W5b. It is independent of SR3-4f-1 and may build in parallel with it: it touches `broker/maintain` and `broker/update` tests, not `broker/apply`. Line references are from main at 99fa0fa.

**Today.**
- `Store.Check` calls `noteAttestors(o.Attestors, o.InterimAttestors)` and so rewrites `attestor_policy` from whatever list the caller passes (update/store.go, around line 489).
- Loop 3 passes the static `l.cfg.Attestors` and `l.cfg.InterimAttestors` (maintain/maintain.go:336). So an owner's narrowing through `NoteAttestors` lasts only until the next Loop 3 check, and a removed attestor counts again.
- Security reproduced it (keys {a, b}; `NoteAttestors({b})` makes `Security()` false; one `Check` with {a, b} makes it true again).
- Nothing calls `NoteAttestors` outside tests.
- The fail-closed behaviour on an unreadable `attestor_policy` is right, but only a probe showed it. The mutant `err == nil && cur != v.policy` (fail-open on a read error) survives the suite.

**Requirements** (local IDs under UPD-8 and U16):
- **SR3-6f-1a, one source, read per check.**
  - `maintain.Config` replaces the static `Attestors` and `InterimAttestors` slices with one source, read at the start of each Loop 3 check. Use an interface or func returning `(allow, interim []ed25519.PublicKey, err error)`.
  - If the read fails, the check fails closed: Loop 3 does not call `Check` with a stale or empty list as if it were current. It records the failure as for a failed mirror check, and authority already granted under an older digest stays retired.
  - Every place in `maintain` that reads `l.cfg.Attestors` (maintain.go:612, 620, 701) uses the list from that same read, so one check sees one policy.
  - A `Config` with no source keeps today's no-attestor behaviour, which only narrows.
- **SR3-6f-1b, NoteAttestors on change.**
  - The same source feeds `Store.NoteAttestors` whenever the owner's setting changes. Add a method on `Loop3` (for example `AttestorsChanged()`) that reads the source and calls `NoteAttestors`.
  - W5b wires it to the settings write. This package adds it and tests it; it does not wire `cmd/agentosd`.
  - First boot passes no attestors, which only narrows (Security S1): keep it so.
- **SR3-6f-1c, fail-closed test.**
  - Commit Security's point-2 probe in `broker/update/policy_test.go`. With `attestor_policy` replaced by a directory (or made unreadable), `Security()` and `InterimAttestation()` are false for a `Verified` from before, and `Stage` returns `ErrPolicyMoved`.

- A source read error never widens. It may only skip the check or narrow.
- One check uses one list: no second read in the middle of a check could mix two policies.
