# UX3-7: Keep a held text before pointing to it

Board row: #993 (class:release, tier A, lane:primary). It replaces the 2026-10-09 intake brief from Codex draft #405. That brief's gate, a LATER.md promotion through an L1 spec-diff, is met: SPEC v1.0 CH-19 states the requirement (D-079). Source: the potency finding on #3916 (comment 6505526001) and the triage on #993 (comment 6505585843). Start only after #3916 merges, and only while the agentosd serial slot is free (D-111). Usage estimate: 100k tokens.

**Why (facts).** When an agent text is withheld, the owner channel sends a pointer, but nothing keeps the withheld text. The CH-19 pointer `owner.Hidden` (broker/owner/disclose.go) says "Read it on my Wi-Fi page", but the page has nothing to show. After #3916, every CH-21 hold sends `owner.HeldCode`, which is the could-not-be-kept text, so the agent's result is lost. CH-21 says these holds will often be false ("I fixed the code"). agentosd's `keptReplies` (broker/cmd/agentosd/evidence.go) keeps only replies that are too long or could not be sent. It keeps at most 20 for 7 days, drops the oldest silently, swallows save errors, and no page reads it.

## Requirements (from SPEC.md v1.0)
- **CH-19:** the pointer is sent only after the content is kept for the owner page, durably across restarts, for a number of days the owner sets (default 30). It expires only by time. Reading never removes it, and an expired item says it has expired. If the content cannot be kept, the text says it could not be kept instead of pointing to the page (D-079).
- **CH-21:** the held text "I held back a message because it mentioned a code. Read it on my Wi-Fi page." is sent only once the output is kept as CH-19 requires. Otherwise a fixed text says it could not be kept.
- **CH-8:** reading content kept for the owner is a page step.
- **CH-12:** no text points to a page that lacks what it promises.

## Design
1. **The keep is the owner channel's.** Every agent path (Converse, Notify, NotifyAs, NotifyNow, and evidence.go's replies) passes `checkAgent` / `agentText`. The channel gets a `Keeper` (`Keep(kind, text string) error`), set by agentosd. When CH-19 or CH-21 withholds a text, the channel calls `Keep` first. On success it sends the pointer (`Hidden`, or CH-21's pointer wording). On error, or with no keeper set, it sends the matching could-not-be-kept text. There is one such text per kind, each one GSM-7 segment and naming no page. Nothing that is not kept is ever pointed to.
2. **The store is agentosd's `keptReplies`, grown, not a new package.** Each item carries a random id, a kind (`long`, `unsent`, `secret`, `code`), the text as the channel received it (stripped of controls) and its time. Items expire only by time, after `-kept-days` (default 30). An owner-page setting for that is out of scope; see Findings. The 20-item count cap goes, because it evicts by count. A byte cap (1 MiB in total) refuses a new item and never evicts an older one, so a flood gets the could-not-be-kept text, which is truthful. `keep` returns the store's error, and the save is atomic and fsynced (change.Store). An expired item leaves a stub (id, kind, time, no text) for another 30 days, so the page can say it has expired. A deletion's reach (`forget`) still drops everything, stubs included.
3. **The page reads it through the page socket, as passkeys do.** Add `localapi.OpHeld` ("page_held", token required), serve it in `localsrv`, and mount `/held/` in `localui` behind `signedIn`. The page lists unexpired items newest first, each with its date and kind, and the expired stubs as one line each ("A held message from 3 Oct has expired."). Text is HTML-escaped and shown as preformatted plain text, with no links made live. Reading changes nothing. STATUS's page-waiting count is untouched.
4. **No new redaction.** The kept text is what the clerks already returned, after their own CLK-4 redaction. The owner reads the withheld code on purpose, so the CH-19 patterns do not redact it. Record this as an assumption for the Security lens.
5. **Integration owner:** this package wires keep, store, socket op and page into the running agentosd and localui, and owns the matrix below.

## Lifecycle outcomes (test matrix: stage by outcome)
| Stage | Kept | Not kept |
|---|---|---|
| Withhold (secret, code) | pointer text, item listed on the page | could-not-be-kept text, nothing listed |
| Long or unsent reply | as today, plus the item has an id and kind | logged, and the owner is told it could not be kept |
| agentosd restart | item still listed, same id and text | — |
| Store full (byte cap) | — | could-not-be-kept text; older items unchanged |
| Expiry (day 30 + 1 s) | stub says expired; text gone from disk | — |
| Read on the page | still listed afterwards | — |
| Deletion's reach (`forget`) | items and stubs gone | — |

## Package IDs
- **HELD-1 Keep before the pointer.** Withheld text is kept, then pointed to. A keeper error sends the could-not-be-kept text (CH-19, CH-21).
- **HELD-2 Durable, time-only expiry.** Items survive restart and expire only by time, at the default of 30 days. A 21st item evicts nothing, and a full store refuses rather than evicts.
- **HELD-3 Readable on the page, not consumed.** A signed-in page shows the item verbatim and escaped. A second read shows it again, and an expired item says so.
- **HELD-4 Only the signed-in page.** The socket op refuses a missing or ended token. Nothing in the text, a log or the stub carries the held text.
