# W3-forget-b1-6: The restore entry checks the forget log safely

Board section: Integration: wiring merged packages into the box. Part of W3-forget-b1 (briefs/W3-forget-b1.md); SPEC REC-1, REC-2, CAP-3, A8, CH-12.

**Goal:** the forget-log check merged in #409/#436 runs only when a caller fills `recovery.Options` and `Layout` correctly, and no production caller exists yet: there is no restore command (that is W6, whose brief is a stub), and the vault process (`cmd/agentos-egress`) does not import `recovery`. This package delivers the one entry a restore command calls, so the command has no forget-log choice left to get wrong, and closes #409's release conditions and #436 Security point 2 in `broker/recovery/`.

**Requirement IDs:** REC-1 (restore onto new hardware), REC-2 (restricted mode until re-confirmed), CAP-3 and A8 as in W3-forget-b1; security C3 (authenticated forget log replayed over restores). Tests carry `REQ: REC-1, CAP-3, A8` (REC-2 on the restricted-state test, CH-12 on the hold-text test).

**Sources:** BOARD row W3-forget-b1-6; #409 Security R2, R3, R5 (a)–(d), L3 point 3 (PR comments, head f629664); `reviews/security/2026-10-08-pr436.md` point 2; #409 Security L2 (#487 handoff f4); #487 UX lens point 1 (`reviews/ux/2026-10-09-pr487.md`); the two L3 rounds on #519, a duplicate b1-6 brief that was stopped (comments 6073892933 and 6074078045), folded in by the coordinator.

## Design
A new `broker/recovery/restoreentry.go` exposes one function (name is the builder's; `RestoreBox` below). The W6 command calls it with the recovery key, the chosen backup, the destinations at hand and the box's learn dir; it fills `Options` and `Layout` itself and calls `Restore`/`RestoreDrive`. The vault process supplies its TPM counter (`tpmCounter`, `cmd/agentos-egress/trusted.go:403`) through a constructor that takes the counter as a required argument; nil is accepted only from a PC with no TPM and is logged. The W6 command itself, its UI and its vault-process endpoint stay in W6 (open question 2).

## Requirements (each with a test)
1. **(a) One forget-log path** (R5 a, L3 point 3). `RestoreBox` sets `Layout.ForgetLog` to the learn dir's `forget-log.json` (relative to the restore target), and `Restore` refuses an empty `Layout.ForgetLog` with an error before extracting anything. agentosd cannot import recovery (ARC-1, b1-4 Q6), so a testdata file read by both sides (as `recovery/testdata/confirm-v1.json` does) pins the file name and the `.pending`/`.confirm` suffixes; recovery's test checks `PendingSuffix`/`ConfirmSuffix` against it and agentosd's test checks `forgetLogFile` and its `".pending"` against it. Tests: empty layout is refused and nothing is written; a held restore through `RestoreBox` leaves its marker where agentosd's `restoreHold` finds it.
2. **(b) agentosd is stopped** (R5 b). The lock is agentosd's own: one lock file in its learn dir. agentosd takes it exclusive at start (held mode included) and holds it for its life; `RestoreBox` takes it exclusive without waiting, refuses ("stop the agent first") when it is held, and holds it until the rename into place is done. **It is never a lock shared with agentos-egress:** agentos-egress neither takes nor waits on it. agentosd and agentos-egress run together (agentosd's `-egress`, `-owner-verify` and `-routing` name agentos-egress sockets), so one exclusive lock over both would stop whichever starts second (#519 L3, point B). The vault process's side of the swap stays with its caller (see "Placed elsewhere"). #519's alternative (both services hold one lock file shared, the restore takes it exclusive and non-blocking) also meets that constraint, but it does not fit open question 2's ruling: `RestoreBox` runs inside agentos-egress, so the process would hold the shared lock it then needs exclusive, and holding it would not close the vault the swap replaces anyway. Tests: lock held → refusal, target unchanged; lock free → restore proceeds; agentosd's start fails cleanly when a restore holds the lock; agentosd starts while agentos-egress runs (agentos-egress takes no such lock). The lock-taking line in agentosd is its only change for this requirement.
3. **Every destination's copy** (row). `RestoreBox` reads the forget log copy from every destination at hand under one fixed name per destination (the builder picks it and records it in ASSUMPTIONS; b1-5 writes it). An unreachable destination or missing copy counts as absent, logged by destination name; it never fails the restore. It also fills `Options.Newer` from the backup log (b1-4's follow-up). Test with fake destinations: copies from all reach the check; one unreachable is skipped; `Newer` holds the verified newer backups only.
4. **Size cap** (R3). `decodeForgetLog` refuses input over 4 MiB, and `RestoreBox` reads each copy through a reader that stops at the cap plus one byte (refusing, not truncating). An over-cap copy counts as absent; an over-cap restored log is forged. Tests at cap and cap+1 for both.
5. **A corrupted copy doesn't forge the restore** (R2). A copy that fails to open after a valid first entry contributes its MAC-verified prefix (entries before the first bad one), then is treated like any other copy; the restored bundle's own log failing still gives `forget-log-forged`. Rationale for the threat check: anyone who can corrupt a destination copy can delete it, which already counts as absent, so this adds no power; no unverified entry is ever used.
   - **A copy cut below its anchor counts as absent** (#519 L3, point 1). The header MAC covers `Host`, `Base` and `AnchorSeq` but not the entry count, and `head()` returns `Base` whenever the last entry's `Seq <= AnchorSeq`. So a destination copy cut to fewer than `AnchorSeq` entries, by a flipped entry under this requirement or by deleting its tail today, reads as anchored at `Base`; if the vault's log is a prefix of it, it wins and the restore reads as checked, losing the forgets after the cut. Rule: a destination copy whose verified prefix holds fewer entries than its header's `AnchorSeq` is treated as absent and must not pass the counter check; `checkForgetLog` reports it so `RestoreBox` names it in its output. An honest copy always holds at least `AnchorSeq` entries (`anchorForgetLog` sets it to `len(Entries)`, and entries are only appended), so the rule never drops one. It does not apply to the restored bundle's own log.
   - Tests: corrupted copy + good copy → same result as the good copy alone; corrupted copy whose prefix is longer than the bundle's log → the prefix is used; corrupted bundle log → forged; **a log anchored on this PC at `AnchorSeq = A` with no forget since, restored from a backup made before the move (another `Host`), with one copy cut to k < A by deleting its tail and another by a flipped entry → each is dropped and named, the restore is not checked, and the result equals the copy being absent; a copy cut at exactly `AnchorSeq` entries → still usable.**
6. **The missing case opens the copies** (#436 Security point 2). When the bundle carries no forget log, `checkForgetLog` still opens the copies; the longest authentic one (same key, prefix rule as now) becomes the log the check continues with (anchored, or unanchored → the picker with that log's last date). Only when no authentic copy exists is the result `forget-log-missing`. Two authentic copies with different log IDs keep the restore held as forged. Tests: missing bundle log + authentic copy with forgets → not missing, and "Never" no longer releases; no copy → missing as before; two IDs → forged.
7. **(d) TPM anchor failure at `storeBackupKey`** (R5 d). Implements Mark's ruling on open question 1. **Pending Mark: this package does not start building until he has answered.**
8. **The hold text promises only what holds** (#487 UX point 1, CH-12; #519 L3, points 2 and A). For a held restore, `RestoreBox` returns the text the command prints verbatim, so W6 has no wording to get wrong: the reason, `PendingNotice(reason)`, and one line chosen by `recovery.Confirmable(reason)`. Neither line depends on agentosd's configuration: held mode texts only with `-modem-bridge` (`heldMode.Link` is nil otherwise) and an owner number (`heldOwner` errors with no `-owner` and setup unfinished), and the restore side can see neither, so **no line promises a text**.
   - Confirmable (`unanchored`, `missing`; held mode asks a question): "The agent stays on hold until the owner answers. It asks by text when it runs with its texting link and knows the owner's number; check both are set up."
   - Not confirmable (`forged`, `rolled_back`): `settleForgetLog` writes no question and no answer releases the hold, so **this line asks no question**: "The agent stays on hold. It texts the owner this notice when it runs with its texting link and knows the owner's number."
   - Recommended over printing a line only when the box will text: that needs the restore side to read agentosd's flags and setup record, which is more coupling for one line. Each line is GSM-7 and fits CH-12's bound.
   - Tests: each of the four reasons gives the notice and its own line exactly; `forged` and `rolled_back` never contain "until the owner answers" or any question; the text is the same with no bridge and no owner number (it takes no input from agentosd's configuration, and `restoreentry.go` reads no agentosd flag or setup record); a checked restore returns no hold text.
9. **agentosd trusts the learn dir only when it is private** (#409 Security L2, #487 handoff f4). `restoreHold` and `readRestoredForgets` trust the learn dir only when it is owned by agentosd's effective uid and is not group- or other-writable, and trust `forget-log.json`, `.pending` and `.confirm` only when each is owned by that uid with mode 0600. A refusal fails closed: the start holds, as for an unreadable marker, and the learning plane stays closed. `RestoreBox` writes those files 0600 in a 0700 dir; the owner is the caller's uid, and W6's endpoint must run as agentosd's uid or chown them (W6 precondition). Owner and mode, not a MAC: a MAC needs the forget key, which stays in the vault and out of agentosd; verifying against the vault's own log becomes possible in b1-5 (`ExportForgetLog`), which should then replace the file as the replay's source (b1-5 row). Tests: a group-writable learn dir → agentosd holds; a `forget-log.json` at 0644 → holds; one owned by another uid → holds (skipped when not root, with the mode-only test still run); files written by `RestoreBox` have mode 0600 in a 0700 dir.

## Open questions (flag in the PR; do not decide silently)
1. **(d) A failed TPM anchor when storing the recovery key. Pending Mark** (routed by the coordinator, 2026-10-09); the build waits for the answer. Today `ensureForgetLog` saves the key and the log, then the anchor's `Define`/`Read` error fails `storeBackupKey`, so Provision or rotation reports failure after half its writes.
   - (A, recommended) Fall back to anchoring at the first forget (as a nil `Box.Counter` already does), record that the anchor is missing, and show it on the local page; `AppendForget` retries the anchor. Cost: until a forget anchors it, a restore on this same PC is unanchored and goes to the owner's picker instead of passing silently. Recovery-key setup never fails on a TPM fault.
   - (B) Fail storing the recovery key, and make the failure atomic (remove the key and log written before the anchor). Strictest rollback check, but an owner with a faulty TPM cannot set up recovery at all, which REC-1 depends on.
2. **Where the restore entry lives. Ruled by the coordinator, 2026-10-09 on #503: option A.** (A, recommended) b1-6 delivers `RestoreBox` and the egress counter constructor; W6 builds the command and calls it (W6 row gains the precondition). (B) b1-6 also builds the command in the vault process, which pulls W6's UI and endpoint design into a tier-A forget-log package and pushes it past 150k.
3. **A read-only held page on `localui.sock`. Decided: no held page** (coordinator, 2026-10-09, adopting #519's L3, which judged it sound and not Mark's call; UX lens on #487, `reviews/ux/2026-10-09-pr487.md`; LATER `W3-forget-b1-7 a`). Held mode keeps serving only `owner.sock` (agentosd ASSUMPTIONS H1); the restore prints the hold instead (requirement 8). Why:
   - The owner at the PC right after a restore is the one who ran it, and sees the printed hold.
   - A page would be a second surface on a box that opens nothing restored (security C3), reachable from the local network.
   - The answer comes only over the owner's channel (#436 L3 point 4), so a page could not take it.
   - D-072 covers CRED-5 route control (the pinned-box notice pauses a broker-held route), not held restores; a held box has no live route to pause.
   LATER `W3-forget-b1-7 a` stays later. If the UX lens still wants a page, it is a new release row, not a blocker here.

## Assumptions to record (`broker/recovery/ASSUMPTIONS.md`, new section)
- 4 MiB holds the box's lifetime of forgets (an entry is well under 1 KiB; tens of thousands of forgets fit).
- An advisory file lock is enough to keep agentosd stopped: both sides are ours and run as root on the box; a hostile agentosd is out of scope for this check.
- A destination copy's verified prefix is as trustworthy as an intact copy's entries: each entry is MAC-chained under the recovery-key-derived key.
- Two authentic logs with different IDs do not arise from normal use (`ensureForgetLog` creates one log per vault), so holding is the safe reading.
- An honest destination copy holds at least `AnchorSeq` entries, so dropping one cut below it never drops an honest copy (requirement 5).
- Only agentosd's uid (root) writes the learn dir; localui, the modem bridge and the guest bridge run as other uids (agentosd ASSUMPTIONS, requirement 9).
