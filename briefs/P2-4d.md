# P2-4d: Vault rollback counter

Board section: Phase 2: real hardware (cloud parts).

Vault rollback counter: vault file format 2 with the vault ID and per-PC anchors sealed inside; a TPM NV counter per vault on each trusted PC (owner range, name tied to the vault ID, auth value held in the vault, salted sessions); the vault process refuses an old copy of the drive on the trusted-host, PIN and passphrase paths, and anchors before trusting a PC; the keys file's hash sealed in the vault so an old keys file is refused; `Rebase(recoveryKey)` for restores, dropping TPM slots, callable only from package `recovery`; `Vault.Reencrypt` moves the vault to a fresh data key, and the vault process moves it to a new policy key with fresh slots for this PC and, sealed from their recorded SRK, other trusted PCs; a missing counter fails loud (CRED-8, CRED-9, REC-1; V6, V7, recovery R10a; REC-2's restricted mode and REC-4's tier-4 rotation from the local UI are P2-8's, not covered here) ([assumptions](../broker/tpmseal/ASSUMPTIONS.md), T10–T11; [V6](../broker/egress/ASSUMPTIONS.md)).
