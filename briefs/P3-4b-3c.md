# P3-4b-3c: Owner text for LOOP-7 findings: cleared, plain words, urgent only with a step

Board section: Phase 3: the agentic loops. Part of P3-4b (briefs/P3-4b.md); SPEC LOOP-9, LOOP-7. Merges BOARD rows P3-4b-3c, 3d and 3e, and takes the owner-text items from P3-4b-4c, since all of them change the same functions in `broker/loops`.

**Goal:** what the owner reads about a fuzz, socket-probe, canary or corpus finding is true, plain and actionable. Four problems exist today:
- A finding that clears is texted only if it paused something (`Resolve` in `report.go`, `runProbe` in `probe.go`: `rec.Contained == "paused" && rec.Texted`), so an owner told of a finding never hears it end.
- `findingText` (`secure.go`) puts Go identifiers and paths in the text ("Fuzz test FuzzParseFrame …", the corpus file name) and says a corpus item "got past" a check, which is untrue for a replay.
- Every finding but an expiry is sent urgent (`tell`: `rec.Finding.Check != CheckExpiry`), even when nothing is paused and no step is offered.
- The wait line says "I recheck it every round", but loop7 rechecks a target only when its turn comes round: (targets + 1) × `Every`, 10 h as P3-4b-3a wires it (19 targets, `Every` 30 m), and bounded at 12 h by 3a's requirement 6.

**Requirement IDs:** LOOP-9 (the owner is told per severity and told when it ends), LOOP-7. Tests carry `REQ: LOOP-9, LOOP-7`.

**Sources:** BOARD rows P3-4b-3c, 3d, 3e and P3-4b-4c (its UX items and the owed lens check); `reviews/ux/2026-10-09-pr523.md` points 1–3; `reviews/ux/2026-10-09-pr515.md` points 1 and 2; the owed check `TestFindingTextsNameNoIdentifiersAndNeverAlarmWithoutAStep` (lens, second occurrence); `reviews/ux/README.md` "Checks that replaced findings".

## Requirements (each with a test)
1. **Cleared text for every texted finding** (#523 UX 1; row 3c). `Resolve` and `runProbe` send the cleared line for any record with `Texted`, paused or not. A paused record keeps today's sentence ("… stays paused until you resume it on my Wi-Fi page."). An unpaused one gets "Cleared: <plain subject>. Nothing more is needed from you." The cleared text is never urgent, and an untexted (digest-only) finding clears only in STATUS and the digest. Tests: texted and unpaused gives one cleared text; texted and paused gives today's line; untexted gives no text, for both `Resolve` (fuzz, probe) and `runProbe` (canary, corpus).
2. **Plain words, no identifiers** (#523 UX 2; #515 UX 1; row 3d). `findingText` for `fuzz`, `probe`, `canary` and `corpus` names what was tested in owner words through a fixed map from target or probe to a plain name ("the check that reads agent messages", "the agent's connection to me"), with a generic fallback ("one of my internal checks"). It never shows a Go identifier, file name, path or digest. The corpus text becomes UX #515's wording: "My self-test of the code filter failed: it missed a test code hidden inside a known attack text. Nothing real was exposed." (with the check's plain name in place of "code filter"). The fuzz and probe texts drop "on my current setup" and say the fix comes with an update. Tests: each check's text, for a subject with a Go-style name, a path and a digest in Detail, contains none of them; the map covers every target in loop7's target list and every probe check.
3. **Urgent only with a step** (#523 UX 2; #515 UX 2; row 3d). A finding's text is sent urgent only if its owner line names a pause that happened or a reply that works (PAUSE, STOP), or it is a canary leak. A canary leak always ends with "Reply STOP to pause everything." and is urgent. Any other finding is sent non-urgent and its line ends "Nothing is paused and nothing is needed from you." This holds however P3-4b-3b decides: if 3b makes a probe failure pause grants, the line names the pause and so becomes urgent through the same rule. Tests: a fuzz finding without containment is non-urgent and carries the sentence; a capped grant finding is urgent and names PAUSE; a canary leak is urgent and names STOP; `Pass`'s batch rule (`secure.go`, the `urgent ||` line) and `tell` use the same predicate.
4. **The wait line says the real cadence** (#523 UX 3; row 3e). `waitUpdate` becomes "one comes with an update; I check it again at least twice a day, and after each update." Behind it: P3-4b-3a's requirement 6 bounds the interval at 12 h (10 h as wired). If 3a has not merged, the wording is still true of the unwired code, since nothing runs it.
5. **The owed lens check** (lens, second occurrence). `TestFindingTextsNameNoIdentifiersAndNeverAlarmWithoutAStep` in `broker/loops` builds every check's owner line in each containment state (none, paused, failed, capped). It fails on a Go identifier (a word with an inner capital, or `Fuzz`/`Test` prefix), a `/` or `.go`, or a hex run of 8 or more. It also fails on any urgent line naming neither a pause nor a reply, and on a line not GSM-7 or longer than three segments. Add the row to `reviews/ux/README.md` "Checks that replaced findings".

## Acceptance criteria

- No change outside `broker/loops` and the UX README row.
