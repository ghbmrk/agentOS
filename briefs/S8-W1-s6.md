# S8-W1-s6: the plan route allows only the tools the pinned CLI declares

Board row: issue #1503. Class: release. Tier: A (`broker/egress`). Builder: strongest model. Usage estimate: 120k tokens, checkpoint at 90k.

**Why (facts, verified at main edcd59c).** `broker/egress/worker.go` holds a plan worker's model call to client-side tool *types* (`namespace`, `function`, `custom`), not to the tools the CLI declares. A CLI update, or a config layer below the image's managed config, can declare any client-side tool the image did not pin, and the route forwards it. And the pinned CLI's own code-mode request carries `client_metadata`, which `Codex()`'s body keys lack, so every code-mode turn is refused (captured from CLI 0.162.1 under `guest/codex/managed_config.toml`).

## Requirement (from SPEC.md)

- **CRED-5** (W1-W5): a plan worker's route lets the worker do only what its plan login is for, in the shape the pinned CLI sends.
- **CAP-11**: a model call to a cloud provider never has the provider run a tool for the box.

Package IDs:
- **TOOLS-DECL-1** `PlanRoute.Tools` lists the tools a model call may declare (namespace, name, type). A route with none, a type outside its `ToolTypes` or the client-side set, the `namespace` type itself, an unnamed tool or a repeated one does not validate.
- **TOOLS-DECL-2** A model call's tools (top level or the `additional_tools` item) pass only as declared namespaces holding declared tools of their declared type, or declared tools outside any namespace. A hosted tool anywhere, an undeclared tool or namespace, a namespace in a namespace, a tool carrying `tools` and a hosted `tool_choice` are refused with 403, journaled, and never reach the provider.
- **TOOLS-DECL-3** The pinned CLI's captured code-mode request passes with its declared tools unchanged; `client_metadata` passes only as an object of strings.

**Acceptance tests** (`broker/egress/codemode_test.go`, `REQ: CRED-5, CAP-11`):
- TOOLS-DECL-1: `TestPlanRouteDeclaresItsTools`.
- TOOLS-DECL-2: `TestCodeModeHostedToolRefused`.
- TOOLS-DECL-3: `TestCodeModeRequestPasses`.

## Design (recommendation)

`DeclaredTool{Namespace, Name, Type}` on `PlanRoute`; `Codex()` lists the 11 tools the capture declares. `checkTools` walks one namespace level and looks each tool up by (namespace, name). Function `parameters` stay unchecked for `tools` keys, since a schema may name a property `tools`. The fixture is the CLI's second code-mode turn with synthetic ids and long prompt text elided.

## Scope

`broker/egress/worker.go`, `broker/egress/codemode_test.go`, `broker/egress/testdata/codex-0.162.1-codemode.json`, `broker/egress/worker_test.go` (the "CLI request shape" case's top-level function becomes a declared namespace tool, since an undeclared one is now refused), `briefs/S8-W1-s6.md`.

## Out of scope

`broker/egress/ASSUMPTIONS.md`, `proxy.go`, `exchange.go` (open PRs #2037, #2015). Updating W1's text for the declared list follows those. Checking a `tool_choice` object's name against the declared list.
