# UX3-11: Keep critical controls readable on small phones

**Class:** proposed release (P2); primary lane, unclaimed. This is a cross-lane advisory handoff, not adopted design or implementation authorization. Recheck current main and concurrent PRs before claiming work. **Requirements/acceptance:** CH-12, CH-7, CH-3; A1, A14. **Dependencies/overlap:** Localui; preserve SR3-3 complete approval fields.

## Problem and evidence

Make full decision facts and controls readable at narrow widths and in both themes without truncating canonical approval data.

Evidence and fixed-main source anchors: [deep UX review, UX3-11](../reviews/ux/2026-10-08-deep-ux-review.md); [synthetic probes and limits](../reviews/ux/evidence/2026-10-08/README.md). Runtime remedies remain open after this brief is registered.

## Intended scope

broker/localui/pages.go and renderer/accessibility regression fixtures; no authorization changes. Coordinate with the existing package instead of building a competing flow. SPEC/DECISIONS are out of scope; any unresolved interaction or authority contract goes through an L1 spec-diff first. Record changed assumptions in the affected package.

## Acceptance evidence

1. Check normal 17px control/link text at least 4.5:1 against actual backgrounds in both themes using the WCAG 2.2 benchmark. Fix white-on-light dark-theme buttons and default dark-page links.
2. At 320 CSS pixels and zoom, render the 191-character filename fixture, long recipients, Unicode/look-alike warnings and multiple approvals. No horizontal scrolling is required to read ordinary decision text; all canonical characters remain inspectable and unchanged.
3. Provide visible keyboard focus, semantic page titles and context for repeated Approve/Deny/code inputs. Inspect accessibility names and perform a real screen-reader/keyboard pass before claiming accessible usability.
4. Retain code freshness, exact targets, escaping, canonical/look-alike cues, CSRF/session guards and local-only restrictions. Do not fix overflow by hiding, shortening or collapsing authority-bearing data by default.

## Security and potency constraints

This is decision readability, not a visual redesign. Browser fixture evidence establishes current contrast/overflow only, not complete WCAG conformance or hardware qualification.
