**What happens on main (a67d6eb).**
- **Ordinary releases ignore the policy.** `Verified.IndependentPasses` (`broker/update/attest.go:322`) does not check `policyCurrent`, while `SecurityAutoStage` does (`attest.go:367`, check at 371). `Store.Stage` (`broker/update/store.go:980-1012`) checks `policyCurrent` only `if v.security` (lines 997-1001).
- **What `decide` does with that.** `decide` (`broker/maintain/maintain.go:622`) gates an ordinary stable release on `listed && rel.IndependentPasses(atts, OwnKey) < MinPasses` (line 650), then proposes (line 657).
- **The probe that shows it.** Security ran the release under attestors `{a}` and then called `NoteAttestors(nil, nil)`. Afterwards `IndependentPasses` still returned 1 and `Stage` returned nil. A pass from an attestor the owner removed still counts toward an ordinary release's `MinPasses`, and nothing refuses it at the commit point.
- **The adopted claim outlives the narrowing.** `AttestorsChanged` (`maintain.go:718-727`) does not make a check due, and it leaves `TestedBy` and the `Adopted` state in place. So for up to one interval `Status` (`maintain.go:807-813`) keeps saying "Security update N is ready … An independent tester's report passed". Meanwhile `Stage` refuses with `ErrPolicyMoved`. `apply` already handles that refusal: `Applier.Execute` calls `Store.Stage`, and on `ErrPolicyMoved` it clears `Pending` and abandons the release (`broker/apply/apply.go:620-632` at a67d6eb), but the owner is told something false until then.
- **A fail-open mutant survives.** Changing `listed()` (`maintain.go:730-733`) to `_ = err; return len(allow) > 0` survives the whole `broker/maintain` suite. Re-run on a789f03 while this brief was written (a67d6eb changes no file in `broker/maintain` or `broker/update`): `ok github.com/ghbmrk/agentos/broker/maintain 4.900s`.

**Requirements** (local IDs):

- **SR3-6-f4a (ordinary passes are policy-bound):**
  - `IndependentPasses` returns 0 when `policyCurrent()` fails, the same as `SecurityAutoStage`.
  - `Stage` re-checks `policyCurrent` for any `Verified` whose admission counted attestor passes, not only `v.security`.
  - Suggested shape: `WithAttestations` (`store.go:325`) also records `attested = IndependentPasses(...) > 0`, and `Stage` checks `if v.security || v.attested`.
  - A release admitted with no attestors listed (`listed` false) still stages as today. Its admission never rested on a pass.
- **SR3-6-f4b (the adopted claim is retired):**
  - After `AttestorsChanged`, the next Loop 3 check is due at once (`Urgent()` true and `Next` offers a check, `maintain.go:274-296`), not one interval later.
  - For a release whose `TestedBy` claim rested on an attestor that is no longer listed, or on any pass once the policy moved, the claim is dropped: `TestedBy` is deleted, and the release is unproposed (`unproposeLocked`, `maintain.go:315-322`) or re-decided on that check.
  - `Status` stops saying "An independent tester's report passed" for it.
  - Write a text test on the exact STATUS line. `TestedBy` stores a class (`testedProject`/`testedIndependent`, `maintain.go:604`), not a tester name. So the test asserts that the independent-pass sentence is gone, not that a name is gone.
- **SR3-6-f4c (kill the `listed()` mutant):** extend `TestAttestorSourceErrorFailsClosed` (`broker/maintain/attestors_test.go:71`) with an assertion on `Status().Line`, or add a sibling test, so the mutant above fails.
- **SR3-6-f4d (record):**
  - U16 states that ordinary-release passes are bound to the policy at `Stage`.
  - M12 (the row SR3-6f-1 used for the attestor source) states that a narrowing makes a check due and retires the adopted claim.

- After a narrowing returns, can a removed attestor's pass still count anywhere? Check `decide`, `Stage`, `Evidence`, and the `Status` and `Digest` lines.
- Can a widening, or a read error in `AttestorsChanged` (which notes `nil, nil`, `maintain.go:724`), drop a claim that should stand, or stage something that should not? A narrowing must be narrow-only: it may retire claims and never grant one.
