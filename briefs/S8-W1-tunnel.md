The broker must therefore see each request, so this row is no longer a CONNECT/SNI tunnel. **Split 2026-10-14 (#1014 build).** Built here: (a) and (b), the route in `broker/egress/worker.go` (declared run and sign-in endpoints, the body check over every place the CLI declares tools, the swaps, the redirect rewrite, the auth-host check on the sign-in link, quota readings and metering), recorded in `broker/egress/ASSUMPTIONS.md` W1 to W7. #809's results folded in: with managed config the CLI sends tools in an `additional_tools` input item, and the code exchange's `redirect_uri` is rewritten from the forwarder's callback to the auth host's. The revert mutants and tests for those parts move with it.

**Why.** At current main a worker has no network and no broker socket (`broker/workers` package doc), and the guest-facing egress proxy refuses every `CONNECT` (`broker/egress/proxy.go`, ASSUMPTIONS E12). A Codex worker needs exactly one way out: to its declared OpenAI endpoints, through the swap in `broker/egress/exchange.go` (#426).

**Requirements:** CRED-5 broker-held (placeholders in the CLI; injection at declared endpoints only, including the refresh), CRED-1 (no real value in the worker), A14 ("a provider agent in a worker cannot reach any host but its provider's declared model endpoints"), CRED-5 W4's "provider-side fetch tools … off" carried over for Codex (a request body asking for a hosted tool is refused), W5's clean sign-in and auth-host check carried over for Codex sign-in, DEV-2 and E12 (no home-network or non-global address, also by rebinding), RES-5 and OP-8 (the run is metered and charged; in broker-held mode the broker reads the declared quota headers on its own connection, so they drive RES-5 admission against the owner's reserve; they never feed OP-8 spend), A3 (a plan route run as a provider-agent worker reaches its provider through this path).

**Ownership.** #807 owns the image, the pinned Codex CLI and its managed config, including the `base_url` and `CODEX_REFRESH_TOKEN_URL_OVERRIDE` that point at the forwarder this package adds. #1015 owns the vault entry and the placeholder `auth.json`. This package adds the worker's path out, the declared endpoint list (run and sign-in), the request-body check on the responses endpoint, and the auth-host check on the sign-in link. #1264 calls the sign-in path from the page.

**Change.**
- **Who serves it.** A new listener in the vault process (`broker/cmd/agentos-egress`), which already holds the netguard pins, the vault and the only outbound network. The guest-facing proxy is unchanged and keeps refusing `CONNECT`; a regression test pins that.
- **Endpoint.** One unix socket per provider worker, created only for a worker whose spec names a broker-held provider, bound into that worker. An in-worker forwarder on loopback relays the CLI's requests to it.
- **Declared endpoints only.** The listener forwards a request only when its method, host and path match the provider declaration (CAP-11-plan): for Codex, the responses endpoint, the models list and the token refresh (`auth.openai.com/oauth/token`, reached through the refresh override). Every other request is refused and journaled (host and path only). S8 measured about 20 side calls (analytics, plugins, update checks); they fail by absence, not by a deny list.
- **Request-body check (W4's carry-over).** Hosted tools (web search and any other tool OpenAI runs on its side) ride inside the body of the declared responses request, so a host-and-path match cannot stop them. The listener parses the body of each responses request against the declaration's body schema (ADP-10) and refuses the request, journaling host, path and the refused tool type only, if its `tools` array carries any type outside the declaration's client-side tool types. The allowed set is a list, not a deny list, so a hosted type added later fails by absence. A body that does not parse is refused the same way. #807 turns hosted tools off in the CLI's configuration; this check enforces it. #809 measures which tool types the pinned CLI sends, and the declaration's list comes from that measurement.
- **Sign-in endpoints (W5's carry-over; the owner of Codex sign-in).** For the page's "Use my plan" (#1264), this package declares the pinned CLI's device-auth endpoints and the authorization-code token exchange, on the declared auth host only. The first token response is swapped to placeholders all or none, and the vault entry (#1015) is written before the swapped response is released, as for a refresh. Sign-in runs in a fresh provider worker from the image, with placeholders only and no brief: only the login command. The verification URL and code the CLI prints are passed to the page only if the URL's host equals the declared auth host; otherwise sign-in stops and nothing is shown. The builder measures whether the pinned CLI's sign-in issuer can be pointed at the forwarder (as the refresh is, by `CODEX_REFRESH_TOKEN_URL_OVERRIDE`) and records it in `broker/egress/ASSUMPTIONS.md`. If it cannot, the Codex sign-in route waits. The sign-in worker never gets direct network.
- **Swap.** Each forwarded request goes through the existing `Swapper`: placeholders are replaced with the real values from the vault entry (#1015) at declared header positions, and refresh responses are swapped back to placeholders, all or none. This package wires it; it does not change the swap rules.
- **Plain HTTP or TLS to the forwarder.** The builder measures whether the pinned CLI accepts a plain-HTTP `base_url` and refresh override on loopback. If it does, no TLS terminates in the worker. If it does not, the forwarder terminates TLS with a per-box CA passed in `CODEX_CA_CERTIFICATE`, whose key never enters the worker. Record the finding in `broker/egress/ASSUMPTIONS.md`.
- **Broker resolution.** Upstream names resolve through the box's `netguard.Policy` dialer (E12), on every lookup; a non-global or home-prefix answer is refused, and the dial goes to the approved address.
- **Metering.** Each request is journaled as part of one run (provider ID, worker, endpoint, bytes, duration) and charged to the creator's reservation. The `x-codex-*` quota headers S8 found (`x-codex-primary`, the 300-minute window; `x-codex-secondary`, the 10080-minute window) are read by the broker on its own upstream connection and recorded per declared pool. In broker-held mode these readings are the broker's own, not CLI-reported, so they drive RES-5 admission against the owner's reserve (CAP-11-plan refuses a run past it) and the ONB-9 pool lines, without the worker-held best-effort caveat (that is W7's rule for worker-held mode only). They never feed OP-8 spend.
- **Tools have no network.** The forwarder's loopback and the socket path are unreachable from Codex's tool subprocesses (#807's sandbox). A tool holding the placeholder could otherwise spend the owner's plan.

**Simpler than the tunnel.** No ClientHello parsing, no SNI binding and no `SO_PEERCRED` question under gVisor, because the broker reads each request and the worker holds nothing worth stealing. The tool-network cut stays, since the placeholder still spends the plan through the proxy.

**Tests first.** A stub CLI's request to a declared endpoint reaches a stub upstream with the canary value injected, and the worker side sees only placeholders. A request to an undeclared host or path, a `CONNECT` and a declared host that rebinds to a private address are each refused and journaled without payload. A refresh through the stub swaps back to placeholders and updates the vault entry before release (#1015). The guest-facing proxy still refuses `CONNECT` (regression). A worker without a broker-held provider gets no socket. From a tool subprocess in the worker, loopback and the socket path are unreachable. Quota headers land as pool readings the admission check uses. A stub CLI's responses request whose `tools` carries a hosted type (`web_search`, and a made-up type not in the declaration's list) is refused and journaled without payload; one carrying only declared client-side types is forwarded; an unparseable body is refused. A stub sign-in through the device-auth endpoints leaves only placeholders in the worker's `auth.json`, and the vault entry is written before the swapped token response is released. A verification URL whose host differs from the declared auth host is never passed to the page. The sign-in worker has no brief and no direct network. The image test fails if `base_url` or the refresh override does not point at the forwarder.

**Revert mutants (each must turn a test red).** Forward an undeclared path. Skip the swap on a declared endpoint. Re-resolve the name at dial time. Let the guest-facing proxy accept `CONNECT`. Create the socket for a worker without a broker-held provider. Leave the socket reachable from tools. Skip the request-body check on the responses endpoint. Allow any tool type (turn the list into a deny list of `web_search`). Release the swapped sign-in token response before the vault write. Pass the verification URL to the page without the auth-host check.

**Threats Security must check.**
- An undeclared endpoint reached through a declared host (path confusion, encoded paths, a redirect the forwarder follows).
- Injection into a header or body position the declaration does not name.
- A hosted tool reaching OpenAI despite the body check: a tool type spelled differently, a tool nested in another field, a streaming or compressed body the check does not parse, or a request the CLI sends to an endpoint whose body the check does not read.
- Sign-in: a verification URL on a look-alike host, a token response that reaches the worker unswapped, and the sign-in worker reaching anything but the declared auth endpoints.
- The forwarder or the per-box CA key reachable from tools or visible in `/proc`.
- A refresh response that reaches the worker unswapped on an error path.
- Provider terms: Codex's terms were read in S8 (`spikes/S8-provider-workers/CODEX-TERMS.md`, #810); the route stays unconfirmed under D-061 until consent is recorded (CRED-5c).
