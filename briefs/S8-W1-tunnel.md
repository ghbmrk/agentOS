# S8-W1-tunnel: CONNECT-only tunnel for a worker-held provider CLI

Board section: Release rows carried from LATER.md (2026-10-10). Source: work item #1014 (from the S8-W1a inventory, #543; `docs/security/provider-worker-isolation.md` row "Provider inference tunnel"). Tier A (egress, vm). On G1's plan-login path (Mark chose "Plan login", 2026-10-13): fourth in the chain #808 → #807 → #1015 → this → CAP-11-plan (#1314) → #1264. No real login uses it before S8-live (#809) and the CRED-5 qualification pass (see CAP-11-plan).

**Why.** In worker-held mode the CLI holds its own login and talks TLS end to end to its provider, so the broker cannot inject or read the traffic; it can only decide where the bytes go. At current main the guest-facing egress proxy answers every `CONNECT` with a journaled denial (`broker/egress/proxy.go`, ASSUMPTIONS E12) and a worker has no network and no broker socket (`broker/workers` package doc), so a worker-held CLI has no way out.

**Requirements:** CRED-5 worker-held W4 (CONNECT host on the declared list, resolved by the broker, ClientHello SNI equal to that host; tool subprocesses have no network) and W3 (inference-scoped login only), A14 ("a provider agent in a worker cannot reach any host but its provider's declared model endpoints, and a tunnel whose SNI differs from its CONNECT host is refused"), DEV-2 and E12 (no home-network or non-global address, also by rebinding), OP-8 (the run is metered even though the stream is opaque: run count and wall clock, CRED-5 W7).

**Ownership.** #807 S8-W1 owns the provider image, the pinned CLI, the launcher and the managed settings (tool denies, auto-update and telemetry off). This package adds only network settings to that image (`HTTPS_PROXY` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, which S8 measured cut 6 direct tunnels) and the in-worker forwarder. The login reaches the CLI as `CLAUDE_CODE_OAUTH_TOKEN` through #807's launcher (see #1015's brief); the tunnel carries no credential of its own.

**Change.**
- **Who serves it.** The tunnel is a new listener in the vault process (`broker/cmd/agentos-egress`), which already holds the netguard pins and the only outbound network. The guest-facing proxy in `broker/egress/proxy.go` is unchanged and keeps refusing every `CONNECT`; a regression test pins that.
- **Tunnel endpoint.** One unix socket per provider worker, created only for a worker whose spec names a worker-held provider and bound into that worker. It accepts `CONNECT host:443` and nothing else: any other method, a port other than 443, an IP literal, or a host off the provider declaration's tunnel list is refused and journaled (host only).
- **Who can connect.** The property is that only the CLI process reaches the tunnel. Three parts, each tested: the socket path is absent from the tool subprocesses' mount namespace (#807's sandbox); the forwarder's loopback listener lives in the CLI's network namespace, which tools do not share; and the listener checks the peer's UID with `SO_PEERCRED` against the CLI's UID. Under gVisor the host side may see only the sandbox's host UID, so the builder verifies which UID is visible at each end, puts the `SO_PEERCRED` check where it distinguishes the CLI from tools (the in-sandbox forwarder if the host cannot), and records the finding in `broker/egress/ASSUMPTIONS.md`.
- **Broker resolution.** The listener resolves the host through the box's `netguard.Policy` dialer (E12); the worker's own DNS is never used (it has none). A name that resolves to a non-global or home-prefix address is refused, on every lookup, and the dial goes to the approved address, never the name again.
- **SNI binding.** The listener reads the first TLS record, parses the ClientHello, and requires its SNI to equal the CONNECT host exactly (case-folded, no trailing dot). Missing SNI, ECH outer names that differ, a first record that is not a ClientHello, or a ClientHello split past a size cap close the tunnel. Only then is the upstream dialed and bytes spliced. No TLS termination, no reading of later records.
- **Metering.** Each tunnel is journaled as one run segment (provider ID, worker, bytes each way, duration), charged to the creator's reservation under OP-8; per-run byte and wall-clock caps close it.
- **Declaration.** The tunnel list comes from the provider declaration (CAP-11-plan), data not code. For Claude: the inference hosts the pinned CLI uses with `CLAUDE_CODE_OAUTH_TOKEN` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`; the builder measures them against a stub and records them.

**Tests first.** CONNECT to a declared host with matching SNI splices to a stub upstream. Mismatched SNI, missing SNI, a non-ClientHello first record, an oversized split ClientHello, a declared host that rebinds to a private address, an IP literal, port 80, a host off the list and a plain `GET` are each refused and journaled without payload. The guest-facing proxy still refuses `CONNECT` (regression). A worker without a worker-held provider gets no socket. From a tool subprocess in the worker (stub CLI, #807's sandbox), loopback, the socket path and any address are unreachable, and a connection under a non-CLI UID is refused by the peer check. The image test (`tests/test_image.py` or the image's own test) fails when `HTTPS_PROXY` or `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is missing from the provider image. A stub CLI run with the image's settings opens no tunnel to an undeclared host.

**Revert mutants (each must turn a test red).** Drop the SNI comparison. Accept an IP literal. Re-resolve the name at dial time. Drop the `SO_PEERCRED` check. Let the guest-facing proxy accept `CONNECT`. Create the socket for a worker without a worker-held provider.

**Threats Security must check.**
- Provider terms: S8 found Anthropic's terms allow "an end user signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code", and require the Commercial Terms for running it in "hosted sandboxes or other agent infrastructure". Whether a self-hosted owner box is "a platform hosting Claude Code" is the open question S8 left for Mark. This package does not decide it; the verdict is owed in CAP-11-plan's qualification record.
- SNI/Host split (allowed SNI, then a foreign Host header inside TLS: W4 says qualification checks the provider edge refuses it; record the S8-live probe that does). Domain fronting via an allowed CDN name.
- ClientHello parsing as attack surface (bound sizes, fuzz target in `image/fuzz-targets.json`).
- An allowed host used as an exfiltration channel under an attacker's own key (W4's reason tools have no network: prove the socket and loopback are unreachable from tools).
- The forwarder or its env visible in `/proc` to tools.
- Upstream TLS downgrade is out of the broker's reach by design; say so in ASSUMPTIONS.

**Needs:** #807 S8-W1 (provider image, tool sandbox and managed policy; the tunnel must not ship before tools are cut off from loopback). #1015 S8-W1-volume (the worker spec field naming the provider). Can build against stubs in parallel with #1015 if the spec field is agreed first.
