# CI-race-scope: broker-race skips changes no broker test can see, backed by a read audit

Board section: Defects and later findings on surviving packages. Issue #6692 (follow-up from #6689).

**Why.** broker-race is 19% of ci minutes. Of the 239 first-parent merges from 2026-11-18 to 2026-11-25, 109 were full-scope but changed no file under `broker/`; they re-ran the race tests on code main's run already tested. Go tests read files outside `broker/` (`image/`, `guest/`, `evals/`, `SPEC.md`, `tools/canary.py` through exec, and more), so a guessed path list would be a false-pass route.

**Design.**
- `tools/ci_scope.py` gains `RACE_READ`, the measured set of tracked files outside `broker/` that the tests read, and `NEVER_BLIND` (`broker/`, `.github/`, the tools the job runs outside its traced steps). A change is `race-blind` when every path is a record or a modification (git status `M`) of a file outside both. An addition, deletion, type or mode change is never race-blind: it alters a directory listing or what a stat shows, which the audit does not trace. The base commit's copy decides, as for records.
- `.github/actions/scope` outputs `race=skip` on `records` or `race-blind`; broker-race's steps run unless it says exactly `skip`.
- Each broker-race run (PR and main) runs its `go test` steps with a bpftrace program on the kernel's LSM hooks (`tools/race_reads.py run`): `security_file_open` (every open, exec included), `security_inode_getattr` (every stat), `security_inode_readlink` and `security_inode_follow_link`, for the command's process tree (kept by `task_newtask`). Each probe walks `d_parent` to the workspace by inode and device (the runner kernel has no `bpf_d_path`) and logs paths outside `broker/`. `race_reads.py audit` fails on: a tracked file reached outside `RACE_READ`/`NEVER_BLIND`; any access of `.git/objects/`; a lost event, a trace not run start to end, or a full process map; a missing control access of any of the four kinds; a trace with no test binary exec. Only go's two VCS-stamp git commands are exempt (their output rests on no committed content), marked at their exec.

**Measured.** Full suite traced locally (go 1.26.11, no swtpm): reads outside `broker/` fall in `assurance/`, `evals/`, `guest/`, `image/`, `spikes/`, `SPEC.md`, `docs/owners-guide.md`, `tools/canary.py`, `tools/depaudit.py`, `tools/old_core.txt`; the runner added `tools/canary_controls.py` (canary sandbox). Tracing cost: none locally under strace (683 s plain, 678 s traced on `./owner/... ./kernel/...`), but on the 4-core runner strace's ptrace stops doubled the shards (15.8 min for shard 0 without stats; shard 2 timed out with them), so the trace runs in the kernel with no stop. `fexit:vfs_getattr` attached but saw no call (inlined), so the probes sit on the LSM hooks, which are called across compilation units. With that set, 53 of the 109 merges above would have skipped broker-race. The CI audit is the authority: a read seen only on the runner (swtpm, canary sandbox) fails it and is added to `RACE_READ`.

**Not chosen.** Go's test cache in place of `-count=1` (weaker: misses exec'd children and apt tool versions; needs Mark). strace, or strace less the stat family: too slow on the runner, and a stat shows a size a modification can change. Tracing on main pushes only: per-run auditing catches a new read on the PR that adds it, before a race-blind PR can rely on the set.

**Scope:** `tools/ci_scope.py`, `tools/race_reads.py` (new), `.github/actions/scope/action.yml`, `.github/workflows/ci.yml` (broker-race job), `tests/test_ci_scope.py`, `tests/test_race_reads.py` (new), `tests/test_workflows.py` (two guard strings), `tests/test_zz_classes_structural.py` (RACE_READ names a list file it does not read), `tools/risk_tier.py` (race_reads is tier A), `tools/ASSUMPTIONS.md`.

**Acceptance:** `tests/test_race_reads.py` (path reassembly from interleaved threads, each kind of access, the controls, the git object store, fail-closed cases, the program's walk and stamp exemption, the modify-only rule, `--raw` parsing); `tests/test_ci_scope.py` (the action prints `race=skip` with `records=true`, and broker-race's steps carry the race guard); the PR's own broker-race shards green with their audit step passing.

**Needs:** tier A; `.github/` and `tools/ci_scope.py` are gate files, so a separate Security accept.
