# P3-4b-3f: Socket probe on a machine whose journal is the probe's own

Board section: Phase 3: the agentic loops. Part of P3-4b (briefs/P3-4b.md); SPEC LOOP-7, LOOP-9. Merges BOARD rows P3-4b-3f and 3g: both are the same defect in `loop7.Journaled`, seen from the potency and L3 sides.

**Status: queued, owner decision.** The open question below is Mark's call. Do not start the build until it is answered; requirements 2–4 change with the option chosen.

**Goal:** the in-guest socket probe (`sockprobe`, run through `loop7.Config.Probe`) is wired, and its verdict is about the probe alone. Today `Journaled(machine, trail, start, end, window)` fails the round on any intent the machine journals after `start`. On a machine where the agent is working, the agent's own intents raise a false High, which is #523 Potency 3 (row 3f) and L3 point 2 (row 3g). The same function also accepts any socket-refusal note for the machine from up to `window` before `start`, so a refusal the agent itself caused can stand in for one the probe should have caused (false pass). P3-4b-3a wires loop7 with `Probe: nil`. This package sets it.

**Requirement IDs:** LOOP-7 (in-guest probes run off the shelf), LOOP-9 (a real probe failure is reported once, at its severity). Tests carry `REQ: LOOP-7, LOOP-9`.

**Sources:** BOARD rows P3-4b-3f and 3g; `reviews/potency/2026-10-09-pr523.md` points 1 (pick the probe machine) and 3 (false High; idle or dedicated machine; test a concurrent intent); #523 L3 release point 2 (live-agent intents in `Journaled`; overlaps L3 F7); `broker/loop7/loop7.go` (`ProbeRun`, `Journaled`); `broker/sockprobe/ASSUMPTIONS.md`.

## Open question (Mark's call)
**Where does the socket probe run?** The journal records effects per machine, and nothing in a record says which frame caused it.
- **(A, recommended) A dedicated probe machine.** It uses the same image and socket declaration as an agent machine, holds no grants or credentials, and runs no agent. It is started for the probe round (about every 7 h, in spare capacity) and stopped after it, so every record it journals in the round is the probe's. Cost: one extra short-lived machine per round (memory for its life, within HW-4's 8 GB because loop7 runs only in spare capacity). It tests the declaration, not a live machine's runtime state, so a defect that appears only under a running agent goes unseen.
- **(B) Live machines, only when idle.** The probe runs in an agent machine that has no open task. A round in which that machine journals an intent is void and retried next round, never reported. A machine that is never idle is never probed, and STATUS and the digest say so after 24 h. It tests the real machine, but on a busy box it may rarely run, and "idle" needs a reliable signal from the guest.
- **(C) Attribute each effect to the probe.** A probe token travels in each frame and lands in the refusal note and the intent. This changes the journal format and the guest channel, and puts frame-derived bytes into refusal notes, which B19 (`broker/daemon/ASSUMPTIONS.md`) rules out: a note carries no frame bytes, so a guest cannot write into the journal. It is larger and tier A in `sockets` and `journal`. Not recommended.

## Requirements (each with a test), written for option A; the build adjusts them if Mark picks B
1. **A probe machine** (Potency 1). agentosd can open a machine of kind "probe" from the release image with the agent socket declaration, no grants, no credentials, no learn-dir mounts and no network beyond the agent socket. It is opened only by loop7's `Probe` and closed when the round ends or fails. Tests: a probe machine has no grant and no credential path; it is closed after a round, after a failed round and after a preempted round.
2. **The probe runs there** (Potency 1). `learn.go` sets `loop7.Config.Probe` to a `ProbeRun` that opens the probe machine, runs `sockprobe` in it through the guest channel, and returns the machine's name. It sets `Trail` to the journal reader. Test: one round with the fake machine opener reports no finding when the broker refused every frame.
3. **The verdict is the probe's alone** (Potency 3, L3 point 2). `Journaled` counts only records from the probe machine (already keyed by machine). It no longer accepts refusal notes from before the probe machine opened, since that machine has no earlier records. Tests: a concurrent intent on a busy agent machine raises no finding; an intent journaled by the probe machine raises a High; a refusal note from another machine does not satisfy the probe's set; an agent machine's refusal in the window before `start` does not satisfy it.
4. **Findings and closure** (LOOP-9). A probe failure goes through `Report` as `probe` at High, with no containment until P3-4b-3b rules. A clean round resolves it through `Resolve` as loop7 does now. P3-4b-3c's owner text applies. Test: fail, then pass, gives one finding, then cleared.

## Acceptance criteria
