# S9: Local neural embedder for recall

Board section: Phase 0: harness and risk spikes.

Owner request 2026-10-08 (coordinator session), triggered by Google's EmbeddingGemma 2 (announced 2026-10-06; the coordinator did not verify these figures: Apache 2.0, 740M total of which a 270M text/code backbone, 768-d with Matryoshka truncation to 512/256/128, 8,192-token context, 100+ languages, about 1.49 GB of weights, huggingface.co/google/embeddinggemma-2). Not release-critical: it would class as `later` (LATER.md); it is started on the owner's explicit request. Question: does a small neural embedder beat `HashEmbedder` enough, on a frozen synthetic corpus and with BM25+facts fusion as the index uses it today, to be worth a local-inference service for recall? The gain threshold is declared in RESULT.md before any comparison runs; adoption must be earned by measurement (potency review 2026-10-08 P4: metadata filters and byte budgets first, no new RAG framework). Constraint: a neural embedder cannot link into agentosd (ARC-2, `TestAgentosdLinksNoInference`; SPEC §4 makes local inference an untrusted service), so any adoption is a separate process over a narrow socket with recall degrading to hash/BM25 when it is absent (DEP-1, OP-9); the reasoning and any SPEC change (drafted as `SPEC-DIFF.md`, Mark approves) are recorded in the spike. Also owed here: re-measure the int8 ranking floor (`TestInt8RankingAccuracy`, 0.85) for the new embedder (P3-3b). Spike first (tier C, `spikes/S9-local-embedder/`); a build package `S9b` is written only if the result is adopt.
