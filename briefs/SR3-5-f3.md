# SR3-5-f3: a test kills mutant M3 on Reconcile's pinned-alert clause

A release finding from the lens on #579 (release 1) and delta L3 on #579 (point 2), filed as #790 (parent SR3-5-f1). SPEC rows: ADP-2, OP-2, OP-3. Class release, tier A.

**Why one package.** It is one test, about 40 lines, and no production change unless the test finds a defect.

**Today.** `Reconcile` (exec.go) reports an organize whose reply was lost as unknown when it hides an alert, unless the attempt's kept pin judged that alert: `if o.Hides && pl.alert && !(pinned && pn.alert)`. Mutant M3 drops `pn.alert` (`!pinned`), so any pinned attempt reconciles an alert as done, even one whose pin judged no alert. No test fails under it. Dropping `pinned` instead is an equivalent mutant: an unpinned `pn` is the zero value, so `pn.alert` is false.

**Requirement SR3-5-f3.** A pinned non-alert attempt whose message reads as an alert at Reconcile, on the same Ref, reconciles as unknown, not succeeded.

| ID | Test | Why it fails under M3 |
|---|---|---|
| SR3-5-f3 | `TestReconcileDoesNotReportAnAlertTheAttemptDidNotJudge` (sr3f2_test.go): a DMARC-passing newsletter is judged a non-alert, archived through a store whose MOVE reply is lost (Unknown, pin kept); the owner then holds an account with the sender (`AccountSenders`), so the same message on the same Ref is an alert; `Reconcile` must answer unknown. Control subtest: without the account change it reconciles as succeeded. | M3 answers succeeded. The test passes at main; the PR quotes the failure with M3 applied. |

**Controls that must keep passing.** All `broker/mail/...` tests, including `TestReconcileJudgesThePinnedAttempt`.

**Threat check.** Under M3 an agent's archive of a newsletter could later hide a security alert and the journal would record it as a judged success. The test pins that path; no production code changes.
