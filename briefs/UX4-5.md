## Acceptance

1. Fresh view explains add AgentOS → return to this page → current 6-digit approval code. Label the setup key and current approval code by source/purpose; pairing, provider sign-in and approval codes are not interchangeable.
2. Returned/shown view offers Create replacement setup key with an adjacent warning that the previous unfinished key stops working. A normal wrong-code retry must not generate a new seed. Replacement invalidates the old seed and confirmation; preserve show-once and reset generation semantics.
3. Provide optional same-phone manual help when the authenticator link has no handler. A second device is not required. Keep ordinary user copy/paste and input assistance; no seed persistence, shared clipboard service, logs or URL leakage. Qualify actual mobile handler/autofill behavior.
4. Use the existing recovery explanation: restores onto new hardware or replaces a lost phone/number; keep the sheet apart from drive and approval grid. One actual-storage acknowledgment suffices; no mandatory quiz, photograph, retyping or backup account.
5. Host-trust choice wording identifies the PC using authoritative information and explains unattended restart versus next-start passphrase/code. Keep the trusted default and optional boot PIN policy; promise later correction only via a real guarded route.
6. Preserve wrong-code/send/enrollment limits and newest-seed acceptance. Report clock-not-ready distinctly under HOST-1b, not a misleading bad-code error; if a pause expiry is surfaced, source it from the authoritative bound rather than reset/extend it.
