# UX3-1-f1: show an ended setup sign-in without a click

Board section: Setup. Work item: #2328. Follow-up of UX3-1 (#991, `briefs/UX3-1.md`). **Tier A** (`broker/localui`, `broker/localapi`).

**Why.** UX3-1 acceptance 2: the page shows the real status of an expired, declined or failed challenge. Failure path: the device code expires or is declined; the setup page keeps showing it as current until the owner taps "Get a new code" (`/setup/ai-retry`, `broker/localui/pages.go:383`), because no sign-in state reaches the local UI. `provagent.Runner.SigningIn` (`signin.go:159`) is used only by agentosd's own page (`pagesignin.go:39`).

**Requirements:**
- UX3-F1: `localapi.SetupProvider` (`setup.go:316`) carries a read-only `SigningIn` field per provider, filled from the runner via `localsrv`. It holds state only: no code, no URL beyond what the page already shows.
- UX3-F2: `localui.Provider` (`setup.go:54`) carries it, and the device-code block shows an ended challenge (expired, declined, failed) as ended, with the retry control, with no click needed.
- UX3-F3: a live challenge still shows its code; a provider that never started shows neither.

**Acceptance tests (REQ: UX3-F1..F3):**
- `broker/localapi/setup_test.go::TestSetupProviderCarriesSigningIn` (F1; mutant: field left zero).
- `broker/localui/setup_test.go::TestEndedSignInShowsWithoutAClick` (F2; mutant: ignore the field).
- `::TestLiveSignInStillShowsCode`, `::TestIdleProviderShowsNoSignInBlock` (F3).

**Out of scope.** New sign-in flows; changing the runner's states.

**Scope:** `broker/localapi/setup.go` + test, `broker/localui/setup.go`, `pages.go` + test, the `localsrv` wiring file the builder names in the PR, this brief.

**Usage estimate:** 60k tokens; checkpoint at 45k.
