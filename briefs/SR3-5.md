## Finding and evidence

[Review finding F5](../reviews/security/2026-10-08-architecture-review.md#f5) at main `7b753eb87f606ea2268ca536d429d47989dba196`.

**Confidence:** Reproduced through the real IMAP adapter and the repository's loopback IMAP server.
**Exposure:** Mail package is merged but not connected by current agentosd. Requires a mailbox rebuild/reset between the guarded read and a subsequent mutation connection.

The adapter passes folder and UID from a prior connection into SetFlags and Move. Both open a new connection and SELECT the folder, but discard the returned UIDVALIDITY. Message and mutation signatures cannot carry the previously observed validity. A UID can identify a different message after a mailbox reset.

**Observed:** The guard authorized archiving a synthetic newsletter. The test server then recreated INBOX with UIDVALIDITY changing from 1 to 101 and reused the UID for a synthetic password-change alert. The executor moved the alert to Archive and returned success evidence naming the original newsletter.

**Impact:** The wrong message can be changed or moved without its guard/approval, while the journal records the previously checked identity. This is distinct from M9's accepted same-message flag-change race.

## Scope and intended change

`broker/mail/` (including `imapsmtp/`), tests/ASSUMPTIONS.md and the narrow journal identity integration if needed. No browser/desktop executor changes.

Represent remote message identity as mailbox + UIDVALIDITY + UID. On every new selected connection, compare the expected validity before any mutation; on mismatch, re-resolve and rerun the guard. Keep dependent reads and mutations in one selected session where practical. Carry the identity through undo and watcher fetches as well.

Do not expand authority or edit SPEC.md in this package. If the cited contract cannot decide a design choice, raise an L1 spec-diff proposal before implementation. Record changed assumptions in the affected package's ASSUMPTIONS.md.

## Acceptance tests

2. Carry mailbox + UIDVALIDITY + UID through message IDs, guarded reads, selected-session mutation APIs, watcher handoff and undo. On mismatch, re-resolve and rerun the guard or return a safe retry; never retry solely by the old numeric UID.
