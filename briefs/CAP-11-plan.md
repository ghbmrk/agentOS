# CAP-11-plan: provider-agent route for a worker-held plan (Claude Code first)

Board section: Release rows carried from LATER.md (2026-10-10). Source: work item #1314; the plan-login chain (Mark chose "Plan login" for the first box, 2026-10-13); CRED-5b's "CAP-11 plan-route code (S8)" dependency. Tier A (modelroute, vm, egress wiring). Fifth in the chain #808 → #807 → #1015 → #1014 → this → #1264. The route this package builds stays disabled until S8-live (#809) fills its qualification record.

**Why.** A guest can route single model calls over an API key (CAP-9) but cannot hand a whole subtask to the owner's plan. CAP-11 makes a provider's official agent CLI a route type, added by declaration, run headless inside a worker. Nothing at current main declares, starts or returns from a provider agent. The 2026-10-07 draft branch `pkg/cap-11-12-resources-draft` (commit fc2e31b, `broker/provagent/declare.go`; 5d2a29d, `broker/planquota/admit.go`) has a declaration schema and a pool gate with no merge base on main: reuse the schema where it still fits, credit the branch, and leave the resources tool to CAP-12a.

**Requirements:** CAP-11 (declaration, not router code; brief in and result out through broker tools; never reaches the guest, owner channel or an adapter; data label and reservation inherited; private use only on the owner's per-plan mark), CAP-9 (a plan route is a route kind; fallback over the remaining granted routes when it fails or is used up), CRED-5 worker-held qualification (a route ships only once W1-W9 are proven for the pinned CLI) plus W6 (one data label per provider account), W7 (CLI-reported quota is advisory; the run and wall-clock caps are the bound), W8 (only plans with overage billing off), and "slash and bang syntax in a brief MUST be inert", CRED-7 (result scanned for the provider's credential formats and withheld on a match), RES-5 (usage pools as declared, advisory in this mode), OP-8 (run metered and charged), A3 (a plan route run as a provider-agent worker), A14 (canary brief with slash and bang syntax is inert). A14's adversarial clause ("an adversarial brief surfaces no canary login") is not claimed here: a stub CLI cannot prove it, and under D-064 it belongs to #807 and S8-live, so no `REQ: A14` marker goes on it.

**How the login reaches the CLI.** One path, shared with #1015 and #1014: #807's launcher exports `CLAUDE_CODE_OAUTH_TOKEN` from the read-only login volume and execs the CLI. This package never handles the token.

**Change.**
- **Declaration** (`broker/provagent`): ID, CLI and pinned version, headless argv, how brief and result pass, custody mode, tunnel hosts (feeds #1014), token shape (feeds #1015), usage pools and where each is read, the used-up signal, task classes, and a **qualification record**: the pinned CLI version, a pointer to the W1-W5 evidence, and the provider terms URL, date read and verdict (`allowed`, `not-allowed` or `unclear`). Validated at load; carries no credential material. One built-in declaration: Claude Code, worker-held, shipped with an empty qualification record. No broker-held or Codex declaration ships here.
- **Qualification gate.** `provider_run` refuses with the closed reason `unqualified` unless the declaration's record is complete, its CLI version equals the image's pinned version, and the terms verdict is `allowed`. #809 S8-live fills the record after a supervised run. An `unclear` verdict means the route does not ship, and the question goes to Mark under D-107 / #1148 GRAY-sd (`gate:mark`).
- **Run.** A broker tool for the guest (name it in the style of `broker/workers` tools, e.g. `provider_run`) takes a provider ID, a brief and a task class. It also refuses unless the route is granted, the plan is signed in (login present and schema-valid), its overage-off answer is recorded (W8), and, for a private caller, the owner marked the plan private-allowed. It creates a fresh provider worker from the provider image with the login and tunnel, writes the brief to scratch, runs the headless argv with the brief on stdin as data (never as argv, never as a prompt prefix the CLI parses: a brief starting with `/` or `!` runs as text), enforces the run and wall-clock caps, collects the declared result file, scans it (CRED-7), returns it, and destroys the worker.
- **What leaves the worker.** Only the declared result file. The CLI's stdout and stderr are discarded (or kept as a bounded, CRED-7-scanned tail for a failure reason) and never journaled raw. The CLI's logs and transcripts live in per-worker scratch and are destroyed with the worker.
- **Provider workers are unreachable from worker tools.** The run's worker is broker-owned: it never appears in `Manager.Workers(lineage)` (built in #1015), and every worker tool (`exec`, `read`, `write`, `checkpoint`, `fork`, `diff`, `rollback`) refuses its ID. The provider agent has no broker socket and no guest path.
- **Routing.** CAP-9 sees a `plan` route kind per declaration. A used-up signal or a run failure falls back per CAP-9; a refused login stops the route and sets the ONB-9 sign-in line once, with no retry (CRED-5). Pool headroom from CLI events is recorded as advisory only and never promised on the page or in STATUS (W7).
- **Label.** The provider account carries one data label (W6): the first private run fixes it private; a public caller then cannot use it until the owner resets it.

**Tests first.** Declaration validation (missing fields, credential-shaped values, unknown custody, a malformed qualification record) refuses load. The built-in declaration refuses with `unqualified`; so do a record whose CLI version differs from the image's, and verdicts `unclear` and `not-allowed`. With a test-only qualified declaration, a granted, signed-in plan runs a stub CLI end to end and returns its result; ungranted, unsigned, overage-unknown and private-unmarked each refuse with a closed reason. A canary brief `/login` and `!cat ~/.claude/*` reaches the stub as plain text. A stub result carrying a canary credential format is withheld. A stub that echoes a canary to stdout and stderr and writes a canary transcript leaves no canary in the journal, the result, or the drive after the run. Each worker tool refuses the provider worker's ID. Caps stop a hung stub. A used-up signal and a refused login each fall back per CAP-9; a refused login does not retry. The run inherits the caller's label and reservation; the worker is gone afterwards. No test uses a real login.

**Revert mutants (each must turn a test red).** Skip the qualification check. Pass the brief as argv. Skip the CRED-7 result scan. Journal the CLI's stderr raw. Let `exec` accept a provider worker's ID. Retry after a refused login. Drop the W6 label check for a public caller.

**Threats Security must check.**
- Provider terms: S8 read Anthropic's terms on 2026-10-05 (`https://code.claude.com/docs/en/legal-and-compliance`). They allow an end user signing in to the unmodified binary with their own subscription, "including where a platform hosts Claude Code", forbid developers to "collect, store, or intermediate Claude.ai credentials", and require the Commercial Terms for "hosted sandboxes or other agent infrastructure". The verdict for a self-hosted owner box is owed by Mark (S8's open question) and is recorded in the qualification record, not decided in this package.
- Brief injection into the CLI's command surface (argv, stdin framing, slash and bang, `--` handling).
- Result channel carrying the login in an encoding the scan misses (scan is a tripwire, containment is W1).
- A guest choosing the provider ID or declaration path to reach another provider's login.
- Label laundering: private content reaching a plan account later used by a public caller (W6).
- A guest guessing a provider worker's ID and calling a worker tool on it.

**Spec dependency.** No SPEC change is needed to build this. Whether the route may ship depends on the terms verdict above: `allowed` ships under CRED-5 and CAP-11 as merged; `unclear` goes to Mark under D-107 and #1148 GRAY-sd (`gate:mark`), which would replace consent-at-connect with per-use or per-service owner approval. This package builds no consent flow.

**Needs:** #807, #1015, #1014 to build; #809 S8-live to enable (it fills the qualification record). #1264 c4e2 (page sign-in) comes after this and is what puts a real login in the vault; until then tests seed a synthetic canary login.

**Out of scope.** CAP-12a resources tool, the page's "Use my plan" sign-in (#1264), broker-held plan routes and their consent (CRED-5b, #1148), live qualification and A14's adversarial clause (S8-live, #807).

**Scope:** `broker/provagent/*` (new), `broker/modelroute/*` (route kind and fallback only), `broker/workers/*` (provider run path and tool ID refusal), `broker/workers/*_test.go`, `broker/vm/worker.go` (spec only), `broker/cmd/agentosd/main.go` (wiring), `broker/guest/mcp.go` (tool registration only), `broker/guest/tools_test.go`, the ASSUMPTIONS.md of each touched package, this brief.
