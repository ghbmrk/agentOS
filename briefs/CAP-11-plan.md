# CAP-11-plan: provider-agent route for a plan (Codex first, broker-held)

Board section: Release rows carried from LATER.md (2026-10-10). Source: work item #1314; the plan-login chain (Mark chose "Plan login" for the first box, 2026-10-13); CRED-5b's "CAP-11 plan-route code (S8)" dependency. Tier A (modelroute, vm, egress wiring). Fifth in the chain #808 → #807 → #1015 → #1014 → this → #1264. The route this package builds stays disabled until S8-live (#809) fills its qualification record.

**Re-scoped 2026-10-13 (D-114).** Mark's verdict on Claude's terms is `unclear`, so Codex (ChatGPT plan) is the first and default plan route. It is broker-held, unconfirmed (D-061): the CLI holds placeholders, the vault process injects the login (#1015, #1014), and the route needs the owner's recorded consent (CRED-5c) and CRED-5b's failure handling before it ships. The Claude declaration ships disabled, as an owner opt-in built in #1380. This removes the worker-held requirements (W1-W9) from this package for Codex; they apply to the Claude opt-in. Three of their aims carry over to Codex in other forms: W4's hosted tools off (#807's config, #1014's request-body check), W5's clean sign-in and auth-host check (#1014), and W8's money risk (the credits measurement below and on #809).

**Why.** A guest can route single model calls over an API key (CAP-9) but cannot hand a whole subtask to the owner's plan. CAP-11 makes a provider's official agent CLI a route type, added by declaration, run headless inside a worker. Nothing at current main declares, starts or returns from a provider agent. The 2026-10-07 draft branch `pkg/cap-11-12-resources-draft` (commit fc2e31b, `broker/provagent/declare.go`; 5d2a29d, `broker/planquota/admit.go`) has a declaration schema and a pool gate with no merge base on main: reuse the schema where it still fits, credit the branch, and leave the resources tool to CAP-12a.

**Requirements:** CAP-11 (declaration, not router code; brief in and result out through broker tools; never reaches the guest, owner channel or an adapter; data label and reservation inherited; private use only on the owner's per-plan mark), CAP-9 (a plan route is a route kind; fallback over the remaining granted routes when it fails or is used up), CRED-5 broker-held (placeholders in the CLI; injection at declared endpoints only) and the owner opt-in rule (a plan whose terms read is unclear is off until the owner opts in, D-114), plus "slash and bang syntax in a brief MUST be inert", CRED-7 (result scanned for the provider's credential formats and withheld on a match), RES-5 (usage pools as declared; broker-held, so the broker reads them on its own connection and refuses admission past the owner's reserve), OP-8 (run metered and charged), A3 (a plan route run as a provider-agent worker), A14 (canary brief with slash and bang syntax is inert). A14's adversarial clause ("an adversarial brief surfaces no canary login") is not claimed here: a stub CLI cannot prove it, so no `REQ: A14` marker goes on it; for Codex the worker holds only placeholders, and S8-live (#809) records the live check.

**How the login reaches the CLI.** It does not. The worker gets a placeholder `auth.json` at create (#1015), and the vault process injects the real login at the declared endpoints (#1014). This package never handles the login. The #1315 design, in which agentos-egress served a Claude token to a launcher, is dropped (D-114).

**Change.**
- **Declaration** (`broker/provagent`): ID, CLI and pinned version, headless argv, how brief and result pass, custody mode, declared endpoints and swap positions (feeds #1014), placeholder shape (feeds #1015), usage pools and where each is read, the used-up signal, task classes, and a **qualification record**: the pinned CLI version, a pointer to the W1-W5 evidence, and the provider terms URL, date read and verdict (`allowed`, `not-allowed` or `unclear`). The verdict also takes `unconfirmed`, for a broker-held route the terms do not plainly allow (D-061). Validated at load; carries no credential material. Two built-in declarations: Codex, broker-held, verdict `allowed` (#1377; D-117); and Claude Code, worker-held, verdict `unclear` (D-114), shipped disabled with an empty qualification record. Grok (xAI) and Muse (Meta) are added as data by #1378 and #1379 after their terms read.
- **Qualification gate.** `provider_run` refuses with the closed reason `unqualified` unless the declaration's record is complete, its CLI version equals the image's pinned version, and the terms verdict is `allowed`, or `unconfirmed` with the owner's recorded consent for that provider (CRED-5c). Verdict `unclear` refuses with `opt-in-required` until the owner's opt-in is recorded; #1380 builds the opt-in and its warning, so here it always refuses. #809 S8-live is the row that fills the record, after a supervised run. Neither `briefs/S8-live.md` nor #809 says so yet, so #809 must take it on (noted on #809 when this brief merged): it produces the pinned Codex CLI version, the measured declared endpoints and swap positions, the hosted tool types the pinned CLI sends (for #1014's body check), the credit behaviour after the plan's limit, and the terms URL, the date read and Mark's verdict (from #1377). The record lands as a change to the built-in declaration under tier A review. A `not-allowed` verdict means the provider gets the API key route only (D-114).
- **Run.** A broker tool for the guest (name it in the style of `broker/workers` tools, e.g. `provider_run`) takes a provider ID, a brief and a task class. It also refuses unless the route is granted, the plan is signed in (vault entry present, #1015), and, for a private caller, the owner marked the plan private-allowed. It creates a fresh provider worker from the provider image with its placeholders and egress socket, writes the brief to scratch, runs the headless argv with the brief on stdin as data (never as argv, never as a prompt prefix the CLI parses: a brief starting with `/` or `!` runs as text), enforces the run and wall-clock caps, collects the declared result file, scans it (CRED-7), returns it, and destroys the worker.
- **What leaves the worker.** Only the declared result file. The CLI's stdout and stderr are discarded (or kept as a bounded, CRED-7-scanned tail for a failure reason) and never journaled raw. The CLI's logs and transcripts live in per-worker scratch and are destroyed with the worker.
- **Provider workers are unreachable from worker tools.** The run's worker is broker-owned: it never appears in `Manager.Workers(lineage)` (built in #1015), and every worker tool refuses it. That is all 13 tools in `broker/workers`: `worker_create`, `worker_exec`, `worker_read_file`, `worker_write_file`, `worker_checkpoint`, `worker_fork`, `worker_diff`, `worker_rollback`, `worker_destroy`, `worker_list`, `worker_fit`, `worker_keep` and `worker_delete`. Each one that takes a worker name refuses a provider worker's name, `worker_list` omits it, `worker_keep` never keeps or destroys one, and `worker_create` refuses a spec naming a provider. The provider agent has no broker socket and no guest path.
- **Routing.** CAP-9 sees a `plan` route kind per declaration. A used-up signal or a run failure falls back per CAP-9; a refused login stops the route and sets the ONB-9 sign-in line once, with no retry (CRED-5). Pool headroom comes from the declared quota headers (`x-codex-*`), which the broker reads on its own upstream connection (#1014). In broker-held mode these are not CLI-reported, so `provider_run` refuses admission (closed reason: pool at reserve) when a pool is at or below the owner's reserve, and the readings feed the ONB-9 pool lines without the best-effort caveat. "Advisory, never promised" is W7's rule for worker-held mode and applies only to the Claude opt-in (#1380). The readings never feed OP-8 spend.
- **Concurrency.** Concurrent runs for one provider are safe: the token is read-only and needs no refresh (S8), and each run gets its own one-shot login socket (#1015), so runs share no writable state. RES-5's per-pool limit (default 2 provider-agent workers per pool) is the only bound on concurrency.
- **Overage and credits (W8's money risk, open measurement).** S8 left open whether Codex's `credits` fields matter (`spikes/S8-provider-workers/RESULT.md` §3). If a ChatGPT plan draws purchased credits after its limit, a broker-held run would spend owner money with no OP-8 meter. #809 measures this. Until it does, the Codex route stays disabled through the qualification record. If credits can be drawn, the declaration either treats the credit-draw signal as used-up (CAP-9 fallback, so the run never draws them), or the route refuses unless the account shows credits off, as W8 did; the measurement picks which. Either way no run draws credits unmetered. This is a measurement, not a SPEC change.
- **Label.** A run inherits the caller's data label; private use needs the owner's per-plan private mark (CAP-11).

**Tests first.** Declaration validation (missing fields, credential-shaped values, unknown custody, a malformed qualification record) refuses load. The built-in Codex declaration refuses with `unqualified` while its record is empty; so do a record whose CLI version differs from the image's and verdict `not-allowed`. Verdict `unconfirmed` refuses without consent and runs with it. The Claude declaration refuses with `opt-in-required`. With a test-only qualified declaration, a granted, signed-in plan runs a stub CLI end to end and returns its result; ungranted, unsigned and private-unmarked each refuse with a closed reason. A canary brief `/login` and `!cat ~/.codex/*` reaches the stub as plain text. A stub result carrying a canary credential format is withheld. A stub that echoes a canary to stdout and stderr and writes a canary transcript leaves no canary in the journal, the result, or the drive after the run. Each of the 13 worker tools refuses or omits the provider worker, one test per tool. Caps stop a hung stub. A used-up signal and a refused login each fall back per CAP-9; a refused login does not retry. A pool reading at or below the owner's reserve refuses admission with the closed reason. With a test declaration whose credit-draw signal is set, a stub response carrying it is treated as used-up and falls back. The run inherits the caller's label and reservation; the worker is gone afterwards. No test uses a real login.

**Revert mutants (each must turn a test red).** Skip the qualification check. Pass the brief as argv. Skip the CRED-7 result scan. Journal the CLI's stderr raw. Let `worker_exec` accept a provider worker's name. Let `worker_checkpoint` accept it. Let `worker_fork` accept it. Let `worker_rollback` accept it. Retry after a refused login. Admit a run while a pool is at the owner's reserve. Ignore the credit-draw signal. Accept `unconfirmed` without consent. Let the Claude declaration run without opt-in.

**Threats Security must check.**
- Provider terms: settled for this package by D-114. Claude's verdict is `unclear` (Mark, 2026-10-13), so its declaration ships disabled behind the opt-in (#1380). Codex is `allowed` (#1377; D-117); the `unconfirmed` consent path stays in the gate for other broker-held routes, so check it still refuses without consent.
- Brief injection into the CLI's command surface (argv, stdin framing, slash and bang, `--` handling).
- Result channel carrying the login in an encoding the scan misses (scan is a tripwire; the worker holds only placeholders).
- A guest choosing the provider ID or declaration path to reach another provider's login.
- Label laundering: private content reaching a plan account later used by a public caller.
- A guest guessing a provider worker's ID and calling a worker tool on it.
