# CAP-11-plan: provider-agent route for a worker-held plan (Claude Code first)

Board section: Release rows carried from LATER.md (2026-10-10). Source: work item #1314; the plan-login chain (Mark chose "Plan login" for the first box, 2026-10-13); CRED-5b's "CAP-11 plan-route code (S8)" dependency. Tier A (modelroute, vm, egress wiring). Fifth in the chain #808 → #807 → #1015 → #1014 → this → #1264.

**Why.** A guest can route single model calls over an API key (CAP-9) but cannot hand a whole subtask to the owner's plan. CAP-11 makes a provider's official agent CLI a route type, added by declaration, run headless inside a worker. Nothing at current main declares, starts or returns from a provider agent. The 2026-10-07 draft branch `pkg/cap-11-12-resources-draft` (commit fc2e31b, `broker/provagent/declare.go`; 5d2a29d, `broker/planquota/admit.go`) has a declaration schema and a pool gate with no merge base on main: reuse the schema where it still fits, credit the branch, and leave the resources tool to CAP-12a.

**Requirements:** CAP-11 (declaration, not router code; brief in and result out through broker tools; never reaches the guest, owner channel or an adapter; data label and reservation inherited; private use only on the owner's per-plan mark; auto-update and telemetry off), CAP-9 (a plan route is a route kind; fallback over the remaining granted routes when it fails or is used up), CRED-5 worker-held W1-W9 as built by #807, #1015 and #1014, plus W6 (one data label per provider account), W7 (CLI-reported quota is advisory; the run and wall-clock caps are the bound), W8 (only plans with overage billing off), and "slash and bang syntax in a brief MUST be inert", CRED-7 (result scanned for the provider's credential formats and withheld on a match), RES-5 (usage pools as declared, advisory in this mode), OP-8 (run metered and charged), A3 (a plan route run as a provider-agent worker), A14 (canary brief with slash and bang syntax is inert; adversarial brief surfaces no canary login).

**Change.**
- **Declaration** (`broker/provagent`): ID, CLI and qualified versions, headless argv, how brief and result pass, custody mode and terms note, tunnel and auth hosts (feeds #1014), login file path and schema (feeds #1015), usage pools and where each is read, the used-up signal, task classes. Validated at load; carries no credential material. One built-in declaration: Claude Code, worker-held. No broker-held or Codex declaration ships here.
- **Run.** A broker tool for the guest (name it in the CAP-11 style of `broker/workers` tools, e.g. `provider_run`) takes a provider ID, a brief and a task class. The broker refuses unless the route is granted, the plan is signed in (volume present and schema-valid), its overage-off answer is recorded (W8), and, for a private caller, the owner marked the plan private-allowed. It creates a fresh worker from the provider image with the login volume and tunnel, writes the brief to scratch, runs the headless argv with the brief on stdin as data (never as argv, never as a prompt prefix the CLI parses: a brief starting with `/` or `!` runs as text), enforces the run and wall-clock caps, collects the result file, scans it (CRED-7), returns it, and destroys the worker. The provider agent has no broker socket and no guest path.
- **Routing.** CAP-9 sees a `plan` route kind per declaration. A used-up signal or a run failure falls back per CAP-9; a refused login stops the route and sets the ONB-9 sign-in line once, with no retry (CRED-5). Pool headroom from CLI events is recorded as advisory only and never promised on the page or in STATUS (W7).
- **Label.** The provider account carries one data label (W6): the first private run fixes it private; a public caller then cannot use it until the owner resets it.

**Tests first.** Declaration validation (missing fields, credential-shaped values, unknown custody) refuses load. A granted, signed-in plan runs a stub CLI end to end and returns its result; ungranted, unsigned, overage-unknown and private-unmarked each refuse with a closed reason. A canary brief `/login` and `!cat ~/.claude/*` reaches the stub as plain text. A stub result carrying a canary credential format is withheld. Caps stop a hung stub. A used-up signal and a refused login each fall back per CAP-9; refused login does not retry. The run inherits the caller's label and reservation; the worker is gone afterwards. No test uses a real login.

**Threats Security must check.** Brief injection into the CLI's command surface (argv, stdin framing, slash and bang, `--` handling). Result channel carrying the login in an encoding the scan misses (scan is a tripwire, containment is W1). A guest choosing the provider ID or declaration path to reach another provider's volume. Label laundering: private content reaching a plan account later used by a public caller (W6). Concurrency: two runs sharing a writable login file (serialize per provider or prove the CLI's refresh is safe).

**Spec dependency.** This brief needs no SPEC change for the Claude worker-held route: CRED-5 and CAP-11 as merged cover it. #1148 GRAY-sd (unapproved L1 spec diff) would change only routes whose provider terms are **unconfirmed**, replacing CRED-5's consent-at-connect with per-use or per-service owner approval. This package therefore ships no unconfirmed-terms route and builds no consent flow; that work waits for Mark's decision on #1148.

**Needs:** #807, #1015, #1014. #1264 c4e2 (page sign-in) comes after this and is what puts a real login on the volume; until then tests seed a synthetic canary login.

**Out of scope.** CAP-12a resources tool, the page's "Use my plan" sign-in (#1264), broker-held plan routes and their consent (CRED-5b, #1148), live qualification (S8-live).

**Scope:** `broker/provagent/*` (new), `broker/modelroute/*` (route kind and fallback only), `broker/workers/*` (provider run path), `broker/vm/worker.go` (spec only), `broker/cmd/agentosd/main.go` (wiring), `broker/guest/mcp.go` (tool registration only), the ASSUMPTIONS.md of each touched package, this brief.

**Usage estimate:** 150k tokens. Split if past the checkpoint without green: (a) declaration and route kind, (b) run tool and result path. Builder model: Opus-class (tier A).
