## What to build

1. **Uplink.** agentosd's setup mode reads `/proc/net/route` and `/proc/net/ipv6_route` and counts the box as online when an up, non-reject default route exists on an interface other than `lo`. The access point's own subnet has no default route through the box.
2. **Progress.**
   - Online: phase `ready`, `Updated` and `Online` set. The first-boot update (UPD-3) is not wired into setup mode, so `Updated` follows `Online` and the AI step waits for an uplink.
   - Offline: phase `offline`.
3. **Never online.** When the last join answered `saved` and the box has had no uplink for 90 seconds since, progress sets `never_online`. A `joined` answer, or any uplink, clears it.
4. **The page.** While `NeverOnline` holds, every setup step shows a fixed CH-12 note.
   - Before pairing, the note asks the owner to check the Wi-Fi name and password and join again, or to plug in Ethernet. The number step then also shows the network form.
   - After pairing, the network step is over, so the note names Ethernet only.
   - Both notes say that setup can continue. The `offline` phase already lets setup continue.
5. **`agentos-localui`.** It gets `localui.AgentosdSetup{Owner: localui.Socket{Path: sock}}` and a `MemStore`. The page keeps nothing on disk (L18), so a page restart starts setup over. agentosd's newest-seed rule (L28) already covers a restart. `localui.New` checks only `ValidateServe`, since the page never reads the access point's SSID or password. The page waits up to 30 s for agentosd's socket before `New`, because `New` takes no answer as setup closed.

## Acceptance tests

1. `defaultRoute` cases:
   - true: an up IPv4 default on `wlan1`, and an IPv6 `::/0` on `eth0`;
   - false: the IPv6 reject default on `lo`, a non-default route, a down route, and empty files.
2. The uplink's `progress()`:
   - online gives `{ready, true, true, false}` and offline gives `{offline, false, false, false}`;
   - after a `saved` join and 89 s offline, `never_online` is false; at 90 s it is true;
   - an uplink, or a later `joined`, clears it.
   The joiner reports each code to it. Use a fake clock.
3. `AgentosdSetup.Progress` carries `never_online` across `InProcess` from `localsrv.Setup`.
4. The page:
   - with `NeverOnline` before pairing, the number step shows the note and the network form, and a join from it is accepted;
   - after pairing, the note names Ethernet and offers no form;
   - both notes pass `modem.Segments` as GSM-7 in at most three segments, and neither names an internal part.
5. With an empty network list, the network step takes a typed name, and the join hook receives it.
6. `cmd/agentos-localui`'s config has `AgentosdSetup` over the `-sock` path and a `MemStore`, and `localui.New` accepts it with no Wi-Fi password. `TestThePageLinksNoneOfAgentosd` and the unit test still pass unchanged.
7. CH-9: the diff touches none of localui's listener, source-subnet check or `NftRules`, and L5's tests pass.
