## Definitions (shared by all rows)

**Seed.** A seed is one entry in the seed catalog, `assurance/loop2-seeds/<seed-id>/`. The catalog is committed before the qualification freeze, and its SHA-256 is recorded in each run report. A seed has:
- `defect`: an edit to the box's change tree (`change.Tree`), only in namespaces a Loop 2 fix candidate may change: `procedures/`, `skills/`, `routing/`, `context/` or `config/` (`broker/change/tree.go`, `namespaces`). The defect makes a security property false, for example a routing rule that sends private-class work to a route allowed only public data. A defect in an authority or governance namespace (`grants/`, `checks/`, `suites/` and so on) can't be fixed by any candidate (LOOP-10, CHG-2), so it can't be a seed.
- `target`: the grant or executor the defect affects, which containment pauses.
- `test`: the **seeded failing test**, one security case in a closed, deterministic **tree-rule** form. It is a list of clauses `{path, pointer, op, value}` over tree files, with ops from a fixed set (`eq`, `absent`, `subset`, `le`). It is evaluated with no model and no inference (ARC-2). The test fails on the defective tree and passes on the reference fix. It carries at least two padding clauses that are irrelevant to the defect, so that minimization can be checked.
- `held`: one or more **held-back variants** under `held/`. Each tests the same property through a different surface (another task class, route name or file). Each must fail on the defective tree and pass on the reference fix. Neither loop 2 nor the fix author ever sees them.
- `fix`: the reference fix, a tree edit that restores the property.

**Tree-rule semantics.** A tree-rule test passes iff **every** clause holds (conjunction); the empty clause set passes. `path` is a tree path that `cleanPath` accepts. `pointer` is an RFC 6901 JSON Pointer into that file's JSON. An empty pointer means the whole document, and a file that isn't valid JSON makes every clause on it fail, except `absent` with an empty pointer. A missing file or pointer target makes the clause fail, except under `absent`, which holds iff the target is missing. `eq` holds iff the target equals `value` as canonical JSON. `subset` holds iff the target and `value` are both arrays and every target element is in `value`. `le` holds iff both are JSON numbers and the target ≤ `value`. A type mismatch makes `subset` and `le` fail. No other op exists, and an unknown op makes the whole test invalid, so it is rejected when added rather than counted as passing. Evaluation reads only the tree and is deterministic.

**Who seeds.** Only the qualification harness (P3-4b-2), never loop 2, a fixer or the guest. The harness picks the seed with its own random source and records the source's seed and the chosen seed ID in the run report (CHG-2: a change can't validate itself). The harness applies the defect to the active tree through its own owner-equivalent test path. The catalog lives in `assurance/`, which is never mounted in, or readable from, an agent machine or a fixer.

**What makes it a finding.** The harness passes the seed's `test` to loop 2 as a `loops.Finding`: `Check` `seeded`, `Contain` the seed's target, `Rule` the test's bytes, `Severity` High. It uses the new in-process entry point (P3-4b-1), and nothing else. A finding is the input to LOOP-9's pipeline. It is not something loop 2 discovered, and owner text must not say it was.

**Intended change:**

3. **Minimized regression.** A `seeded` finding's tree-rule test is reduced to a 1-minimal clause set: dropping any remaining clause makes it pass on the defective tree. 4. **Finding link.** A security case can name the finding ID it covers (a new optional field on `change.Case`). A fix candidate proposed for finding F qualifies only if **every** case linked to F passes on the candidate. That includes cases linked by someone other than loop 2, which is how held-back variants enter (P3-4b-2). This rule overrides PS1's no-regression grading for the cases linked to F. Other open findings keep PS1.
5. **Fix input.** `Fixer.Fix` receives only the finding. A test asserts that no suite content, and no other case's bytes, reach the fixer.
6. **LOOP-10 and anti-gaming.** A fix candidate must fail qualification, with a named reason, when it:
   - (a) edits the seeded regression or any case linked to F;
   - (b) deletes it;
   - (c) skips it, through `suites/`, `graders/`, `policy/` or `security/`, or through a `config/` key that turns loop 2, its checks, or fixture grading off or down;
   - (d) widens authority (`grants/`, `verbs/`, `egress/` and the like);
   - (e) disables a check (`checks/`, or a `config/` key that disables a check);
   - (f) reduces security-suite coverage by any path;
   - (g) passes the visible regression but fails a linked held-back case.

   Items (a), (b), (d) and (f) are expected to hold already through `classify.go`. Prove each one with a test. The `config/` keys in (c) and (e) are probably new: classify them as authority, a closed list kept in `tree.go`.
7. **LOOP-3.** Until loop 2 has carried at least one finding to containment since the daemon started, the scheduler reports loop 2's return as **unmeasured** (explore share), not as zero. That state appears in the digest and STATUS lines that show loop shares. Parking after clean passes (loops S3) is unchanged.
8. **Owner wording.** Owner-facing text (digest, STATUS, onboarding's LOOP-0 line, finding notices) describes loop 2 as checking the box against known problems and repairing findings. It never says loop 2 finds, hunts or detects vulnerabilities, or calls it a detector. A test scans loop 2's and onboarding's string tables for that vocabulary.

## P3-4b-2: A11 qualification harness

**IDs:** A11 (loop 2 clause), LOOP-9, LOOP-10, CHG-2.

**Scope:** `assurance/loop2-seeds/` (the catalog), `assurance/loop2/` (a Go test program or Python driver, whichever the existing A5 harness pattern favors), `assurance/README.md`, `tests/test_loop2_harness.py` (added after #490 used it; a brief-gap), and one CI job or an addition to an existing workflow, if the run fits CI time.

**Intended change:** at least three seeds in at least two namespaces (for example routing and context), each with at least one held-back variant. The harness:
- picks one seed per run with its own random source;
- applies the defect;
- links the held-back variants to the finding ID that `Report` returns, before any fix is proposed;
- runs a harness-provided fixer that returns, in order, the seven bad candidates of P3-4b-1 §6 (generated mechanically from the seed: edit, delete or skip the case, widen a grant, disable a check, drop a suite case, and a fix that special-cases the visible test's exact path or value) and then the reference fix;
- passes the finding to the fixer only through a harness fixer adapter that records every byte it hands the fixer (the fix-input audit). Paths and values the visible test shares, such as a file path or `true`, `1` or `"local"`, never match, so a clean run stays green;
- writes a JSON run report: catalog digest, random seed, seed ID, target paused (yes or no), regression ID and clause counts, each candidate's verdict and reason, suite size before and after.

The run passes only if the fix-input audit is clean, the target was paused, the regression is 1-minimal, all seven bad candidates were rejected for the expected reason, and the reference fix qualified.

## P3-4b-4: LOOP-7, canary rounds, corpora, tamper and exhaustion probes

**IDs:** LOOP-7 (bullets 1, 3, 4, 5), LOOP-9.

**Scope:** `tools/canary.py` (a scheduled mode), `assurance/canary-targets.json`, a Loop 2 source for each bullet, and vendored corpora under `assurance/corpora/`.

**Intended change:**
- **Canary rounds:** run the A5 harness on a schedule with fresh canaries. Any trace of a canary is a High finding.
- **Injection corpora:** published corpora only, with a compatible license, vendored with their source and digest. Replay their items as untrusted input to guests and collaborators, and check that the closed checks hold: CH-19's code filter, the commitment filter, alert patterns and labels. No item is written or generated by a model (D-067).
- **Tamper probes:** scripted writes from guest authority to evaluator, grader and snapshot paths. Each must be refused and journaled.
- **Exhaustion probes:** scripted CPU, memory, disk and process pressure inside the agent machine's cgroup. The broker must stay within its preemption and response targets.

**Acceptance:**
- Each source has a control that makes it report a finding: a planted leak, a corpus item the filter misses in a deliberately weakened copy, a writable snapshot in a test rig, a cgroup with no limit.
- Clean runs report nothing.
- Every finding goes through `Report`.
- No secret or canary value appears in a report (CLAUDE.md).
