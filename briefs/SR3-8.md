# SR3-8: Commit clean-room output durably before recording completion

**Owner:** primary lane (proposed by Codex at Mark's request; implementation is unclaimed).
**Priority:** P2. **Class:** release. **Implementation risk:** tier A.
**Requirements:** OSS-2; cleanroom assumptions C7/C8/C10.
**Acceptance:** A12.
**Dependencies:** P4-2 (merged).
**Needs / coordination:** Can start now; a release condition for W5c wiring. Confirm with a controlled fault regression first; physical power-loss behavior was not tested.

## Finding and evidence

[Review finding F8](../reviews/security/2026-10-08-architecture-review.md#f8) at main `7b753eb87f606ea2268ca536d429d47989dba196`.

**Confidence:** Source-level finding; physical power-loss behavior not exercised.
**Exposure:** Clean-room store/builder package, awaiting W5c live wiring. Actual loss depends on filesystem and storage behavior.

Artifact files use os.WriteFile without file Sync, and nested directories are not synced before the manifest, directory rename and job-completion state can become durable. On reopen, Get treats the manifest as completion evidence without validating all output files, and matching hints coalesce into that artifact.

**Observed:** Source inspection shows the missing persistence ordering and completed-artifact fast path. No physical power-cut or filesystem fault campaign ran in this review.

**Impact:** A power loss can leave a completed manifest with missing/damaged output that is never automatically rebuilt. Later hash checks fail closed, so this finding concerns stuck publication and lost work, not proof that corrupt artifacts are trusted or published.

**Source anchors:** [`broker/cleanroom/store.go:188`](https://github.com/ghbmrk/agentOS/blob/7b753eb87f606ea2268ca536d429d47989dba196/broker/cleanroom/store.go#L188); [`broker/cleanroom/store.go:209`](https://github.com/ghbmrk/agentOS/blob/7b753eb87f606ea2268ca536d429d47989dba196/broker/cleanroom/store.go#L209); [`broker/cleanroom/builder.go:260`](https://github.com/ghbmrk/agentOS/blob/7b753eb87f606ea2268ca536d429d47989dba196/broker/cleanroom/builder.go#L260); [`broker/cleanroom/intake.go:113`](https://github.com/ghbmrk/agentOS/blob/7b753eb87f606ea2268ca536d429d47989dba196/broker/cleanroom/intake.go#L113).

## Scope and intended change

`broker/cleanroom/`, tests and ASSUMPTIONS.md; artifact persistence order, reopened-job validation, quarantine and retry.

Sync output files and newly created directories bottom-up before committing the manifest. Validate the manifest's files before treating a restored job as complete; quarantine and requeue damaged artifacts. Preserve the queue entry until durable output is established.

Do not expand authority or edit SPEC.md in this package. If the cited contract cannot decide a design choice, raise an L1 spec-diff proposal before implementation. Record changed assumptions in the affected package's ASSUMPTIONS.md.

## Acceptance tests

1. Add file-operation fault injection around output writes/Sync, newly created nested directories, manifest persistence, rename, parent-directory Sync and queue completion. A completed job must always have durable, hash-valid outputs, or reopen must recognize and repair the incomplete state.
2. Reopen a completed manifest with a missing or truncated output. Get/intake must not indefinitely coalesce matching hints into that artifact; quarantine/requeue it and rebuild successfully.
3. Verify output files are synced and newly created directories persisted bottom-up before durable completion. Failed persistence must keep a retry obligation; avoid treating a successful rename alone as data durability.
4. Retain hash-based fail-closed reads and existing publication/privacy limits. Check nested output paths and repeated reopen/retry without duplicate publication. Record that simulated faults do not substitute for a hardware power-cut qualification.

Write the regression first and retain it in the repository. Link requirement markers to named passing tests; a marker alone is not completion evidence.
