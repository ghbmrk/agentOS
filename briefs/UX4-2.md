## Evidence and owner effect

After `/setup/number` sends a synthetic code, the current template nests `/setup/number-code` under closed details. In the 390px browser the code field is not visible; it stays hidden after a wrong code. With no valid box number, the exhausted-send response recommends a Text my box link that is absent. See UX4-2 and number-code-sent.html/number-no-box-number-limited.html.

## Bounded scope

localui phone-fallback view state, templates, error presentation and focused tests. Reuse the current server-rendered page and phone proof protocol. No new SMS service or automatic send loop.

## Acceptance

1. Successful fallback send renders the code input visible and reachable in keyboard/accessibility order, with a masked destination and one clear next action. Wrong-code and timeout responses keep the active fallback open.
2. Field labels identify the code source. Error text is discoverable, associated with the field and given a predictable focus/title strategy compatible with the page CSP; inspect the actual browser UI, not only HTML substring presence.
3. Keep the non-secret number edit path inside the same authorized context; changing it follows existing send/proof rules. Show only that context's destination.
4. Every error action exists and can work in the current state. Test missing/invalid BoxNumber, primary SMS available/unavailable, send limits, guess limits and delayed delivery. Add the CH-12 recurring-kind check for an unavailable next step.
5. Preserve all number normalization, possession proofs, send/guess budgets, duplicate-send protection and pairing binding. Opening help or reloading must not send again; no broader retry allowances.
6. Exercise keyboard and screen-reader operation on the supported phone/browser matrix when c4 is runnable; distinguish synthetic HTML visibility from physical SMS/app qualification.
