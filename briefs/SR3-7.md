## Finding and evidence

[Review finding F7](../reviews/security/2026-10-08-architecture-review.md#f7) at main `7b753eb87f606ea2268ca536d429d47989dba196`.

**Confidence:** Source-level finding only; no new reproduction or live provider call.
**Exposure:** Live model path: guest meter → forwarding handler → vault-process router. Consequence depends on a configured provider/model accepting multiple choices.

The meter rejects multiple choices only when its case-sensitive JSON map contains the exact key n. The router subsequently decodes into a Go struct, whose encoding/json decoder accepts field names case-insensitively, and re-encodes the choice count as canonical n. The OpenAI route does not independently enforce one choice; the Anthropic route does.

**Observed:** Code inspection establishes the parser mismatch and missing final one-choice check. The completed review did not measure provider acceptance, generated output or billing. The upstream-spend consequence therefore remains conditional.

**Impact:** A differently cased choice-count field can reach the provider despite the meter's one-choice contract. On a provider that honors multiple choices with a per-choice output limit, output can exceed the amount reserved at admission; charging actual usage afterward is too late to enforce the pre-call bound.
