# SR3-5-f4: each organize refusal and unknown gets its own words, not "changed since approval"

Board section: Security and architecture review (2026-10-08). Source: lens review on #579, release point 2. Class release, tier A.

**Why it matters.** `errChanged` ("mail: changed since approval", `broker/mail/exec.go:95`) is the evidence word for three different causes, and two of them say nothing changed. The owner reads a false cause in the journal and the digest (CH-19: fixed reason words, one per cause).

**What happens on main.** `errChanged` is returned at four sites, and two of them each cover two causes (checked against `guard.go:695-710` and `exec.go:84,178-186`):
- `Execute` (`exec.go:84`), `!agreed`: `takePin` returns false both when no `Escalate` ran (no pin) and when the judgements disagree in message or alert (`guard.go:700-707`). Only the second is a message that changed.
- `Execute` (`exec.go:84`), `pl.msg.Ref() != pn.ref` or it now hides an alert the approval did not escalate: the one case the words are true for.
- `Reconcile` (`exec.go:185`), `Hides && alert && !(pinned && pn.alert)`: with no pin (a restart lost it) nothing changed; with a pin whose approval did not escalate the alert, the alert appeared since approval, and "changed since approval" is true.
- `movedFrom` (`exec.go:207`, `:214`): the found message is not in the pinned target, or the pinned `Ref` still holds a message.

**Requirements:** CH-19 (fixed reason words, none from the server), ADP-2 (organize reversible only behind the adapter's guards). SR3-5-f1 is merged (dependency).

**Fix.** Replace the single sentinel by one fixed-wording error per cause, each starting `mail: ` so `reason` passes it through. `takePin` must tell the two false cases apart (a third result, or a reason), since the bool cannot:
1. `Execute`, no pin: "mail: no check ran for this message; ask again";
2. `Execute`, judgements disagree: its own word, e.g. "mail: the message changed between checks; ask again" (or keep "changed since approval", the builder's call, but distinct from 1);
3. `Execute` ref differs or newly hides an alert, and `Reconcile` with a pin whose approval did not escalate the alert: keep "mail: changed since approval" (true in both);
4. `Reconcile` with no pin: "mail: the check was lost on restart, so it cannot be confirmed";
5. `movedFrom` target mismatch and `movedFrom` pinned-Ref-still-present: two words, "the message is not where the move put it" and "the message is still where it was".
Final wording is the builder's within CH-12 (plain, no jargon, no server text); the contract is one distinct fixed string per cause above (seven causes, six strings).

**Acceptance tests:** (REQ: CH-19, ADP-2)
- T1 `TestOrganizeRefusalReasonsAreDistinct` (`broker/mail/`): drive each cause listed above (no pin, disagreeing pins, ref/alert changed, Reconcile no pin, Reconcile pinned-not-escalated, both `movedFrom` cases); assert `Outcome.Evidence` is the expected fixed string for each and that the strings for causes 1, 2, 4 and the two `movedFrom` words all differ from each other and from "changed since approval". Mutant: restore a shared sentinel; the test fails.
- T2 `TestChangedSinceApprovalOnlyWhenChanged`: "changed since approval" appears for cause 3 (Execute changed, and Reconcile with a pin that did not escalate) only; Execute with no pin or disagreeing pins, and Reconcile with no pin, never contain it.
- T3 results keep their classes: the Execute sites stay `ResultNotApplied`, the Reconcile and `movedFrom` sites stay `ResultUnknown` (no change to outcome semantics).
- Control: the existing `sr3f_test.go` and `sr3f2_test.go` checks on "changed since approval" stay green for cause 3; any that exercise the other causes move to the new words in the same commit.

**Out of scope.** The owner-voice words for the gate's own refusals (SR3-mail-w2-f1 part a), and the `UndoReport` text.

**Scope:** `broker/mail/exec.go`, `broker/mail/guard.go` (`takePin` only), a new `broker/mail/sr3f4_test.go`, edits to `sr3f_test.go` and `sr3f2_test.go` only where they match the old word on sites 1, 3 or 4, `broker/mail/ASSUMPTIONS.md` (the reason-word list), this brief.

**Dependencies:** SR3-5-f1 (merged). No open PR touches these files at writing (D-111: check again at start). SR3-mail-w2-f1 touches `broker/mail` too; do not run both at once.
