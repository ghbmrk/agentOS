# P2-2a-f4: Loop 3 learns how a release request closed, and STATUS says it (with SR3-4f-2-r1-f2)

Board rows: issue #922 (P2-2a-f4) and issue #779 (SR3-4f-2-r1-f2), built as one maintain batch (dispatch S2, 2026-10-17). Class: release. Tier: A (`broker/change/`, `broker/maintain/`). Builder: strongest model. Usage estimate: 120k tokens, checkpoint at 90k.

**Why (facts, verified at main 7afeb82).**
- `change.Pipeline.Decided` drops an upstream release proposal on the owner's NO, on "not chosen", on a lapse, and after a failed dispatch (`drive`: `Dispatch` error or `NotApplied`). Only a lapse is reported (`Lapsed`). So Loop 3 cannot tell the other closes apart.
- After a NO or a "not chosen", Loop 3 keeps `Proposed[v] == StateAwaitingOwner`. STATUS keeps saying "Update N has been waiting for your approval since …" (maintain.go `baseStatusLocked`), and `New` re-asks after a restart (L3 on #423 points 3 and 4, UX on #423 point 1).
- A release whose approved install failed is never offered again until a restart or a newer release (L3 on #423 point 4).
- After a lapse, STATUS says the release is waiting for approval until the next daily check, though no request is open.
- A staged adoption the applier dropped reads "Update N was not installed; I will offer it again.". That line has no cause and no time, says "offer" for a release that installs on its own, and repeats unchanged while the same release is dropped every day (#779; UX points 2 and 3, L3 point 2 and Security point 2 on #611; LATER A5-reask).

## Design

**change.** A memory-only `closed map[string]string` replaces `lapsed`. `Decided` records the kind for an upstream proposal:
- `lapse` records `lapsed`.
- "not chosen" records `left out`.
- After `Settle` drops the proposal, a `Denied` close records `declined`, and any other close that did not adopt records `failed`.

`Closed` reports the kind once. `Lapsed` reports and clears only `lapsed`.

**maintain.** The `Proposer` interface's `Lapsed` becomes `Closed`. `syncLocked` asks `Closed` for each version awaiting the owner. It runs under Loop 3's lock in `Next`, `Status`, `Digest` and `check`, and saves when anything changed.
- On `declined` or `left out`, it forgets the proposal and saves `Ended[v]` with the day. A check does not propose `v` again while it is there.
- On `lapsed` or `failed`, it forgets the proposal and saves `Ended[v]`. On `failed` it also counts a try in `Tries[v]`. The next daily check proposes `v` again and clears `Ended[v]`.
- A drop found at a check also counts a try.
- `Ended` and `Tries` are pruned with `Proposed`: for a version at or below the installed one, and on a source change.
