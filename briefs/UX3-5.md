# UX3-5: Preserve task composition across authentication

**Class:** proposed release (P2); primary lane, unclaimed. This is a cross-lane advisory handoff, not adopted design or implementation authorization. Recheck current main and concurrent PRs before claiming work. **Requirements/acceptance:** CH-11, CH-14, CH-7; A3, A14. **Dependencies/overlap:** L1 resolution of O5 versus CH-14; W5.

## Problem and evidence

Let an owner recover a naturally composed multi-message task without treating prior spoofable text as authenticated.

Evidence and fixed-main source anchors: [deep UX review, UX3-5](../reviews/ux/2026-10-08-deep-ux-review.md); [synthetic probes and limits](../reviews/ux/evidence/2026-10-08/README.md). Runtime remedies remain open after this brief is registered.

## Intended scope

L1 interaction proposal first; after adoption, bounded held-message state in broker/owner/ and related tests only. Coordinate with the existing package instead of building a competing flow. SPEC/DECISIONS are out of scope; any unresolved interaction or authority contract goes through an L1 spec-diff first. Record changed assumptions in the affected package.

## Acceptance evidence

1. Before implementation, record an L1 decision defining content selection and RUN binding, bounds on message count/size/rate/TTL, overflow, restart and expiry. Preserve the reason behind O5.
2. Test one, two and three bubbles; a mistyped code; expiry; delayed or spoofed interleaving; restart and overflow. Show exactly what was retained or discarded. No guest receives unselected pending text.
3. After strong authentication, explicitly inspect/select the intended bounded content and bind RUN to it. Only that content executes once; no automatic concatenation, replacement or execution based on sender proximity or a later valid code.
4. In an owner trial, target at least 7 of 8 participants choosing and running the intended text without retyping within 60 seconds. Record actual results and reject designs that silently accept injected fragments.

## Security and potency constraints

A quarantine plus explicit authenticated selection is a proposal, not authorization to relax O5 today. Inline codes authorize only their accompanying request under the existing contract. Stop at the L1 gate if these constraints cannot be reconciled.
