# Device image: assumptions

Built for PLAN P2-1 against SPEC v0.12, on the S7 host pick (DECISIONS 2026-10-04) and the
S1/S2 test kit (spikes/S1S2-testkit), which first booted this stack under Secure Boot. Each row
is a reading of the spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| I1 | Non-UKI boot: Debian's signed shim, systemd-boot and kernel; mkosi's initrd and the entry's command line are not covered by Secure Boot. The boot editor is off (`editor no`, `secure-boot-enroll off`), so a keyboard cannot edit the command line. On a trusted host their integrity rests on the TPM policy seal, which must cover the initrd and command line (PCR 9 or a signed PCR 11 policy), not PCR 7 alone (C1, for P2-4b). | HW-5, HW-5a | A UKI needs our own signing key and per-PC enrollment, which HW-5 rules out. |
| I2 | A release is the `/usr` verity root hash plus the boot entry that names it in `usrhash=`. The build verifies the split `/usr` partition and hash tree against that hash with `veritysetup` and writes `agentos_VERSION.release.json`. The updater (sysupdate transfer files, TUF metadata) comes with the update package and consumes these files. | UPD-1a, UPD-8 | Only the manifest shape. |
| I3 | Two `/usr` slots of 6 GiB plus 192 MiB verity each; slot B starts as `_empty`. This release's erofs `/usr` is about 1.1 GiB, most of it the OpenClaw guest. The slots are sized once, because repartitioning after drives ship is irreversible (Potency R1). Large, independently versioned payloads (model weights, executor images) live outside `/usr` as their own verified targets, not in the release. With releases staged into the idle slot, budget R9's 1280 MiB staging reserve may no longer be needed; the update package decides. | UPD-1 | Pick sizes before the first drive ships. |
| I4 | Boot counting: the one entry starts with 3 tries; `agentos-health` gates `boot-complete.target`, so an entry is blessed only after `/usr` is mounted read-only from the verity device whose root hash equals the entry's `usrhash=`, and the broker, runsc, the guest image and its launch.json start or exist. Secure Boot off is reported, not failed. This is a reliability gate, not a security control. A failed check, or one hung past 5 minutes, runs `agentos-fallback`, which reboots while the entry has tries left (`LoaderBootCountPath`), so the count reaches zero and the previous entry boots with no owner action; at zero it reboots once more if `LoaderEntries` lists another AgentOS entry (systemd-boot sorts the +0 entry last and `loader.conf` sets no default), and a single-entry drive at zero, or a blessed (uncounted) entry, stays up instead of looping. A try that never reaches the check also ends in a reboot: `panic=10`, and a `systemd.unit-dropin` credential on the command line that makes emergency and rescue mode run the fallback first in the host, or reboot in the initrd, which lacks it. So an initrd failure on a single-entry drive at zero, or on a blessed entry, reboot-loops; there it would otherwise hang with no usable shell. A hang with no panic and no failed unit still needs a hardware watchdog (LATER.md). CI shows the reboot on the two-drive boot, whose check fails. Fallback to the previous entry was shown by the S1/S2 kit with the same mechanism; a forced-fail CI boot on this image is a follow-up (BOARD IMG-3). | UPD-1, HW-5 | Add checks (broker socket answering, journal replay) once onboarding runs in CI. |
| I5 | The image holds no per-install state: `mkosi.finalize` fails the build on a machine ID, random seed, systemd credential secret or credstore, SSH host key, anything in `/etc/ssl/private`, private-key text (PEM, PGP, age) outside `/usr` in files up to 1 MiB, owner configuration (`/etc/agentos`) or broker state, and on any socket file anywhere (V15). After the entry swap, `finish_image.py` lists the final ESP and fails on any file outside an allowlist (shim and systemd-boot binaries, loader.conf, entries.srel, the AgentOS entry, and the kernel and initrd it names), so a `loader/random-seed` cannot ship. `mkosi.conf`'s `RemoveFiles` keeps the ESP inside that list: it drops the random seed `bootctl install` writes and Debian's `vmlinuz-`, `config-` and `System.map-` files in `/boot`, which `00-esp.conf` would otherwise copy. The OpenClaw guest copy under `/usr` is not content-scanned (I9). | HW-1 | — |
| I6 | The broker starts at every boot (#1249): with `/etc/agentos/agentosd.env` absent, `AGENTOS_OWNER` stays empty and `agentosd -owner ""` runs setup mode, which the setup page needs; once onboarding writes the file (mode 0600, in `/etc/agentos` 0700, values validated, C4), `agentosd.path` starts the broker if it is not running and a restart reads the owner. `${AGENTOS_OWNER}` is a whole word, so systemd passes it as one argument even when empty. `agentosd.service` has `Delegate=yes` and no cgroup flags, so `-cgroup-root` defaults to the service's own delegated group and the broker moves itself into `broker/` (RES-2, #124). Its int uid flags (`-modem-uid`, `-localui-uid`) are filled at start by `with-uids`, which replaces each whole `@uid:NAME` word with `id -u NAME` and refuses a missing user. | HW-1, RES-2 | Unit flags only. |
| I7 | Root is ext4, last on the drive, and grows to fill it on first boot (`systemd-repart` plus `GrowFileSystem`). It is not encrypted, so no drive goes to an owner before P2-4 encrypts owner state (C2); P2-4 may replace this root definition. | CRED-8 | P2-4 rewrites `50-root.conf`. |
| I8 | Reproducibility: the Debian main archive is pinned to a snapshot.debian.org timestamp; the build's apt sources (`mkosi.pkgmngr`) also read live `security.debian.org`, so a later rebuild can pick up newer security packages (the package manifest records versions). gVisor and Node are pinned by hash, OpenClaw by lockfile, Go builds use `-trimpath` and no build ID, file times clamp to the commit time, IDs derive from a fixed seed. CI builds on two runners and requires the same `/usr` root hash, boot entry and kernel; the initrd is compared and reported until it is reproducible (BOARD IMG-2). S1 flashes only images built from a push to main, or later a signed release, never a fork PR's artifact (C3). | OSS-8, OSS-9 | Pin security by snapshot too (`snapshot.debian.org/archive/debian-security`). |
| I9 | The OpenClaw guest rootfs is built by `guest/openclaw/build-rootfs.sh`, which copies the build host's shell and libraries. Builds are reproducible only on the same runner image; a Debian-package guest root is a follow-up. | ARC-3 | Build the guest root with mkosi as a second image. |
| I10 | Every drive is written from one image whose disk, ESP and root GUIDs derive from the fixed build seed (OSS-8), so two attached AgentOS drives would make the boot loader's ESP and gpt-auto's root ambiguous. `agentos-drive-id` gives each drive its own disk, ESP and root GUIDs once, after its first blessed boot (they apply from the next boot; the `/usr` slot GUIDs stay, since slot A's derives from its root hash), and on every boot `health` and the broker's `ExecStartPre` require that exactly one partition carries the booted ESP's GUID and that root is on that drive, so a boot with a second fresh drive attached is never blessed and the broker does not start. Root's ext4 filesystem UUID stays shared; nothing mounts by it. CI boots a copy twice and two copies together. The kernel's 11-minute RTC write is off: `systemd-timesyncd` is removed, and chrony with `rtcsync` off comes with HOST-1b. | HW-1, HW-5 | Per-drive GUIDs at flash time instead, if S1 writes drives with a tool that can. |
| I11 | Inbound firewall: `agentos-inbound.service` loads `/usr/lib/agentos/inbound.nft` (`nft -f`, atomic) before `network-pre.target`, so before any interface is configured. `systemd-networkd`, `systemd-resolved` and `agentosd` require it, so a failed load leaves the box with no network and no listener (fail closed). Debian's `nftables.service` is disabled, since it flushes the whole ruleset. `agentos-health` fails unless the `agentos_inbound` input chain ends in `drop`, so a release whose rules did not load is never blessed and the boot counter rolls back (I4). The boot test shows the rules loaded (`inbound=drop` in the health line); the reachability half of A14 runs the same file in network namespaces in CI (`tests/test_inbound_netns.py`), and since the wired uplink (I19) that test also runs real `systemd-networkd` on the image's `[Network]` section behind the drop: the box takes a DHCP lease and an IPv6 address from a stand-in router and no home host opens a box port at either. Gap: the booted image's first CI boot has a NIC (QEMU user networking) and shows the lease, but QEMU's user network cannot open connections into the guest, so the drop is not probed on the booted image. | DEV-2 | If CI boots the image on a bridged or tap network, probe the drop there. |
| I12 | Access point through the inbound drop, only while the access point runs (DEV-net-f, DEV-net-g; DEV-2, CH-7, CH-9): `agentos-ap-exempt@<if>.service` (`Requires=`/`After=agentos-inbound.service`, `BindsTo=` the interface's device) runs `/usr/lib/agentos/ap-exempt <if>`, which refuses `lo` and any name that is not a wireless interface (`/sys/class/net/<if>/phy80211`), then refuses unless `agentos_ap`'s input chain holds the line `iifname "<if>" drop` (the loader loads `agentos_ap` first, for the interface it created as the access point, so `agentos_ap` is the loader's record: a second radio, or the access point before its table loads, is refused), then `nft add element` into `inet agentos_inbound exempt` and reads it back. Its `ExecStop=` runs `ap-exempt --remove <if>`: one `add element; delete element` transaction (succeeds whether or not the element is there, touches no other element) and a check that the name is gone; the interface need not exist, so the device going (`BindsTo=`) removes it too. Removal closes the interface: it falls to `agentos_inbound`'s drop, which stays loaded, so removing never opens the drop (the DEV-net-f note that it would was wrong). Because systemd skips `ExecStop` for a unit whose start failed and can report a stop as done when `ExecStop` failed, `localui.BringUp`/`BringDown` also run the removal through nft themselves and unload `agentos_ap` only after it succeeds (broker/localui L34). Any failure exits 1 and nothing else is added, flushed or deleted. Rests on: the image runs systemd-networkd, not NetworkManager (test_image guards this, so DEV-net-e l3 stays inapplicable). P2-1's loader (`agentos-ap`, I16) drives the access point only through `localui.APLoader`, which calls `BringUp` and `BringDown` (broker/localui L34, DEV-net-h), and brings every radio down at its start. Tested in `tests/test_inbound_netns.py` (namespaces: stop, single radio rejoining a home network, second radio) and `tests/test_image.py`. | DEV-2, CH-7 | Hardware check of the stop path on the controller's radio (A1, A6). |
| I13 | No memory of the card-holding broker reaches disk (IMG-nodump; card C13: the Owner Card passphrase is a Go string that cannot be zeroed). Core dumps are discarded: `kernel.core_pattern=\|/usr/bin/false` and `fs.suid_dumpable=0` (sysctl.d, sorted last), systemd-coredump `Storage=none`, `DefaultLimitCORE=0` for every unit and `LimitCORE=0` on the three secret-holding units, `agentosd.service`, `agentos-egress.service` (vault keys) and `agentos-localui.service` (claim and card codes), which `mkosi.finalize` requires to exist. There is no swap at all: no swap partition, fstab entry, `.swap` unit, zram generator or swap file, and `systemd.swap=0` on the kernel command line so a swap partition added to the drive later is never used. Swap on per-boot-key encrypted cryptsetup is the alternative if the box ever needs it; it is not allowed now. `mkosi.finalize` checks the effective values across every drop-in, `finish_image.py` the partition table and the boot entry, and `agentos-health` the running box (`swap=off dumps=off`), so a release that swaps or keeps dumps is never blessed. | HW-1 | Encrypted swap only with a new row. |
| I14 | Setup services on a fresh image (#1249 P-3, #1270; ARC-6, CRED-8, CRED-9, HW-10). `agentos-egress.service` (user `agentos-egress`, sysusers `agentos-setup.conf`) runs `agentos-egress serve -broker-uid 0 -unlock-uid <agentos-localui> -rule /usr/lib/agentos/egress/rule.json`, ordered after `agentos-inbound` and before agentosd and the page; its sockets are in `/run/agentos-egress` (0711), its state in `/var/lib/agentos-egress` (0700, never shipped). The default rule routes only class `broker-default`, which the guest sends (guest/openclaw/build-rootfs.sh), to both providers (`anthropic`, `openai`); the model IDs are a starting pick to confirm before the G1 run. The agent machine name is `agent` on both sides: agentosd's and egress's `-agent-machine` defaults (#1280), so a key stored at setup grants that machine its provider. The vault's setup half exists only after the claim: `egress-setup` (as root, under a lock) copies the page's claim state through the page's own user (`setpriv`, bounded read) into a private temporary directory and runs `agentos-egress init -setup -claim` as the vault user; it does nothing when keys exist or the box is unclaimed, and `agentos-egress-setup.path` reruns it with `--restart` when the page writes the claim. `agentos-localui.service` (built into the image by build.sh from broker/cmd/agentos-localui) passes `-vault-sock`, `-claim-state` and `-card-latch` under its own `StateDirectory` (0700); `localui-claim` moves the seller's preloaded claim from `/var/lib/agentos` into it once, at its first start. The TPM resource manager is group `agentos-egress` (udev). The vault process is sandboxed at least as tightly as the page and modem units (empty capability set, `ProtectSystem=strict`, seccomp `@system-service` minus `@privileged @resources`, native arch only, `MemoryDenyWriteExecute`, `RestrictNamespaces`, `PrivateIPC`, `ProtectProc=invisible`, `UMask=0077`, `DevicePolicy=closed` with only `/dev/tpmrm0`); tests/test_image.py pins each setting. Neither it nor the page sets `ProcSubset=pid`, which would hide `/proc/net/route` (netguard's gateway) and `/proc/sys/kernel/random/boot_id` (the claim's boot id). Its two `+` ExecStartPre steps (`drive-id check`, `egress-setup`) run as root outside the namespace and seccomp sandbox, but the cgroup device policy binds them too; this rests on `drive-id check` reading partitions through lsblk, sysfs and the udev database rather than opening `/dev` block nodes, which is read from drive-id's code: the boot test runs drive-id in its own unit (agentos-drive-id.service) and does not check the unit's start under its device policy. `egress-setup --restart` drops its lock before `systemctl try-restart`, since the restarted unit's own `egress-setup` takes the same lock. The page unit keeps `TemporaryFileSystem=/var/lib/agentos:ro`, so it sees none of the broker's state; its one authority is the claim state and the Owner Card latch in its own state directory. Tested by tests/test_image.py and the two units' Go tests; the booted CI image does not yet assert each service is active. | ARC-6, CRED-9, HW-10 | An active-service check in the boot test. |
| I15 | Root ext4 has project quotas, so the broker can cap each agent machine's disk (RES-4) and never needs `-disk-quota=off`. `mkosi.conf` sets `SYSTEMD_REPART_MKFS_OPTIONS_EXT4=-Oquota,project` (mkosi passes `Environment=` to systemd-repart) and `rootflags=prjquota` on the kernel command line (gpt-auto mounts root with `rootflags=`). `finish_image.py` reads the built root's superblock and fails the build unless it is ext4 with the quota and project features and a project quota inode, and unless the entry's last `rootflags=` includes `prjquota`. Root grows on first boot (I7); `resize2fs` keeps the features. | RES-4 | Check `repquota -P /` on the booted image in the boot test. |
| I16 | **The access point loader (#825; DEV-net-h, CH-7, CH-9, HW-10).** `agentos-ap.service` runs as root after `agentos-inbound.service` (`Requires=`) and before the page. At start it lists every interface with `/sys/class/net/<if>/phy80211` and calls `APLoader.Start` with all of them, which stops each `agentos-ap-exempt@` and unloads a stale `agentos_ap`, before anything is brought up or joined. It then serves the sticker's setup network on `wlan0` (10.42.0.1/24, the page's `-iface` and `-addr`, which the image test holds equal) unless the Owner Card latch says confirmed or agentosd's owner state exists (a path it cannot stat counts as owned), when it burns the setup file (`firstboot.SetupNetwork`). A radio whose driver loads late is waited for (`-poll`, 2s) and brought down when it appears. While it serves, it reads the latch and the owner state every `-poll`: at the confirm, or once the box is owned, it brings the live access point down, then burns the setup file, and serves no network until #1185 (the card's network). Debian's hostapd and dnsmasq (`dnsmasq-base`, so no `dnsmasq.service`) do the radio and DHCP; `hostapd.service` is disabled in the preset; `10-agentos-wlan.link` keeps kernel `wlanN` names. dnsmasq keeps no lease file and logs no DHCP lines, and hostapd's module logger is off (`logger_syslog=0`, `logger_stdout=0`); all three name client MACs. A box with no radio (CI's QEMU boot) idles. The unit keeps root's network, firewall and child capabilities only (no `CAP_DAC_OVERRIDE`), a read-only system but `/var/lib/agentos` (the burn is a rename beside the setup file, so the directory stays writable) with the vault's state and agentosd's secret subtrees hidden (`InaccessiblePaths=`), no devices but `/dev/rfkill` (`DevicePolicy=closed`), no kernel tunables, `RestrictNamespaces`, `ProtectProc=invisible`, `PrivateIPC`, no core dumps, and `@system-service` without `~@privileged`, since dnsmasq drops to its own user. Rests on: the RZ616 (MT7922) radio supporting AP mode on Debian's `mt7921e`, which is unverified (#1113, needs the hardware), and on its firmware, which is in `firmware-mediatek` (non-free-firmware), a component this image does not yet enable. Not done: serving the card's network after the confirm (#1185), and ONB-5 passthrough (`SetPassthrough` refuses). Also rests on hostapd printing `AP-ENABLED` outside its module logger, which the hardware check confirms. | DEV-net-h, CH-7, CH-9, HW-10, ONB-5 | Hardware check on the M6 Ultra (#1113); the unit's hardening may need loosening there. |
| I17 | **The modem bridge and the home Wi-Fi helper ship (#1388).** `agentos-modem.service` and `agentos-netjoin.service` are enabled; sysusers creates `agentos-modem` and `agentos-netjoin`; agentosd gets `-netjoin-sock /run/agentos-netjoin/netjoin.sock` (the helper's `-dir` plus its socket name; the image test checks each flag against the binary's FlagSet and each socket path against its client's). The polkit rule and the modem udev rule are installed. `/usr/lib/agentos/modem.env` sets `COUNTRY_CODE=1` (#1292): G1 boxes ship to the US; an owner elsewhere needs onboarding to write `/etc/agentos/modem.env`, which the unit reads after it. No number is in the image. NetworkManager is **not** added: it would manage the uplink this image gives systemd-networkd (I11, I12), and with one radio serving the setup network the helper cannot join a home network until the loader hands the radio over (#936). Until NetworkManager and polkitd ship, the helper starts (it needs only the system bus) and each join answers `failed` (#936). The station decision (#1416): the home Wi-Fi station stays with NetworkManager under #936, which must set every interface but the station unmanaged (the wired uplink is networkd's, `Type=ether`, I19; the access point is the loader's) and keep `Requires=`/`After=agentos-inbound.service`; the image test fails if any `.network` file matches a radio. | CH-1, CH-12, ONB-3 | #936; a networkd station instead needs a `.network` naming the station interface only. |
| I18 | Codex provider worker (S8-W1, #807 defensive half): the managed-config key names that keep hosted tools off and pin the route to the forwarder, and the tool sandbox's reliance on bwrap in the worker, are recorded in guest/codex/ASSUMPTIONS.md (C1-C8). Not in the image yet: nothing installs the CLI or the config. | CRED-5, CAP-11 | #809 measures the pinned CLI against C1. |
| I19 | **The wired uplink (#1416).** `20-agentos-uplink.network` matches every physical Ethernet port (`Type=ether`, `Kind=!*`: no veth, bridge or other virtual link, and never the radio, `Type=wlan`) and takes DHCPv4 and IPv6 router advertisements, with DHCPv6 when the router asks for it (`DHCP=yes`); `systemd-networkd` is enabled by preset and starts after the inbound drop (I11). A USB tether in Ethernet mode (cdc_ether, rndis) is also an uplink, behind the same drop. Nothing waits for it: `agentos-egress` no longer orders on `network-online.target`, so an unplugged boot, or a cable with no lease, does not delay the setup page; the vault process learns the network from netlink and its poll. `systemd-networkd-wait-online.service` stays enabled and, on such a boot, fails after its 120 s timeout with nothing ordered after it (cosmetic, `later`). The boot report prints `agentos-uplink: <if> <address>` (up to 30 s for a lease while a cable is in, no wait otherwise); CI's first boot has a QEMU user-mode NIC and checks a lease, the reboot has none and checks `none`. **Hardware-only checks (M6 Ultra, not yet here), each a test plan:** (a) plug the M6 Ultra's Ethernet into a home router and boot: the console shows `agentos-uplink: <if> <router-pool address>`, `ip route` shows a default route via the router, and the setup page's "I plugged in an Ethernet cable" reports online; (b) boot with no cable: the setup page is served at the same point in boot as before this change (compare `systemd-analyze critical-chain agentos-localui.service` with and without the cable), and plugging the cable in afterwards brings the box online with no restart; (c) from another LAN host, `nmap -Pn -p- -sT` and `nmap -6 -Pn -p- -sT` against the box's leased addresses show every port filtered; (d) the M6 Ultra's NIC driver names its port and exposes `/sys/class/net/<if>/device` (a physical port), else the match and the boot report miss it. | ONB-3, DEV-2, DEV-net-e | A board with several ports or a managed switch may need a `Name=` or `Path=` match; a station on networkd changes I17. |
