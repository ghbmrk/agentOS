# Device image: assumptions

Built for PLAN P2-1 against SPEC v0.12, on the S7 host pick (DECISIONS 2026-10-04) and the
S1/S2 test kit (spikes/S1S2-testkit), which first booted this stack under Secure Boot. Each row
is a reading of the spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| I1 | Non-UKI boot: Debian's signed shim, systemd-boot and kernel; mkosi's initrd and the entry's command line are not covered by Secure Boot. Their integrity rests on the TPM policy seal (P2-4). | HW-5, HW-5a | A UKI needs our own signing key and per-PC enrollment, which HW-5 rules out. |
| I2 | A release is the `/usr` verity root hash plus the boot entry that names it in `usrhash=`. The build verifies the split `/usr` partition and hash tree against that hash with `veritysetup` and writes `agentos_VERSION.release.json`. The updater (sysupdate transfer files, TUF metadata) comes with the update package and consumes these files. | UPD-1a, UPD-8 | Only the manifest shape. |
| I3 | Two `/usr` slots of 4 GiB plus 128 MiB verity each (a full 4 GiB slot needs 75.5 MiB of hash tree); slot B starts as `_empty`. This release's erofs `/usr` is about 1.1 GiB, most of it the OpenClaw guest. | UPD-1 | Resizing slots after shipping needs a repartition; pick sizes before the first drive ships. |
| I4 | Boot counting: the one entry starts with 3 tries; `agentos-health` gates `boot-complete.target`, so an entry is blessed only after `/usr` is verity-mounted read-only and the broker, runsc and the guest image start. Secure Boot off is reported, not failed. Fallback to the previous entry was shown by the S1/S2 kit with the same mechanism; this image has one release, so it has nothing to fall back to yet. | UPD-1, HW-5 | Add checks (broker socket answering, journal replay) once onboarding runs in CI. |
| I5 | The image holds no per-install state: `mkosi.finalize` fails the build on a machine ID, random seed, systemd credential secret, SSH host key, anything in `/etc/ssl/private`, private-key text outside `/usr`, owner configuration (`/etc/agentos`) or broker state, and on any socket file anywhere (V15). The ESP's kernel and initrd are added after this check and are package content. | HW-1 | — |
| I6 | The broker starts only when `/etc/agentos/agentosd.env` exists (written by onboarding, P2-2). It runs with a delegated cgroup (`DelegateSubgroup=supervisor`) and puts agent machines under `agentosd.service/machines`. The vault process `agentos-egress` (P2-4a) ships in `/usr/lib/agentos` with no unit yet: P2-4 adds its unit and the broker's `-egress` socket. Not exercised in CI until onboarding exists. | HW-1 | Unit flags only. |
| I7 | Root is ext4, last on the drive, and grows to fill it on first boot (`systemd-repart` plus `GrowFileSystem`). Encryption of owner state belongs to the vault package (P2-4), which may replace this root definition. | CRED-8 | P2-4 rewrites `50-root.conf`. |
| I8 | Reproducibility: the Debian main archive is pinned to a snapshot.debian.org timestamp; mkosi always adds live `security.debian.org`, so a later rebuild can pick up newer security packages (the package manifest records versions). gVisor and Node are pinned by hash, OpenClaw by lockfile, Go builds use `-trimpath` and no build ID, file times clamp to the commit time, IDs derive from a fixed seed. CI builds on two runners and requires the same `/usr` root hash. | OSS-8, OSS-9 | Pin security by snapshot too, if mkosi gains a way. |
| I9 | The OpenClaw guest rootfs is built by `guest/openclaw/build-rootfs.sh`, which copies the build host's shell and libraries. Builds are reproducible only on the same runner image; a Debian-package guest root is a follow-up. | ARC-3 | Build the guest root with mkosi as a second image. |
