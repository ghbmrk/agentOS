# Device image: assumptions

Built for PLAN P2-1 against SPEC v0.12, on the S7 host pick (DECISIONS 2026-10-04) and the
S1/S2 test kit (spikes/S1S2-testkit), which first booted this stack under Secure Boot. Each row
is a reading of the spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| I1 | Non-UKI boot: Debian's signed shim, systemd-boot and kernel; mkosi's initrd and the entry's command line are not covered by Secure Boot. The boot editor is off (`editor no`, `secure-boot-enroll off`), so a keyboard cannot edit the command line. On a trusted host their integrity rests on the TPM policy seal, which must cover the initrd and command line (PCR 9 or a signed PCR 11 policy), not PCR 7 alone (C1, for P2-4b). | HW-5, HW-5a | A UKI needs our own signing key and per-PC enrollment, which HW-5 rules out. |
| I2 | A release is the `/usr` verity root hash plus the boot entry that names it in `usrhash=`. The build verifies the split `/usr` partition and hash tree against that hash with `veritysetup` and writes `agentos_VERSION.release.json`. The updater (sysupdate transfer files, TUF metadata) comes with the update package and consumes these files. | UPD-1a, UPD-8 | Only the manifest shape. |
| I3 | Two `/usr` slots of 6 GiB plus 192 MiB verity each; slot B starts as `_empty`. This release's erofs `/usr` is about 1.1 GiB, most of it the OpenClaw guest. The slots are sized once, because repartitioning after drives ship is irreversible (Potency R1). Large, independently versioned payloads (model weights, executor images) live outside `/usr` as their own verified targets, not in the release. With releases staged into the idle slot, budget R9's 1280 MiB staging reserve may no longer be needed; the update package decides. | UPD-1 | Pick sizes before the first drive ships. |
| I4 | Boot counting: the one entry starts with 3 tries; `agentos-health` gates `boot-complete.target`, so an entry is blessed only after `/usr` is mounted read-only from the verity device whose root hash equals the entry's `usrhash=`, and the broker, runsc, the guest image and its launch.json start or exist. Secure Boot off is reported, not failed. This is a reliability gate, not a security control. Fallback to the previous entry was shown by the S1/S2 kit with the same mechanism; a forced-fail CI boot on this image is a follow-up (BOARD IMG-3). | UPD-1, HW-5 | Add checks (broker socket answering, journal replay) once onboarding runs in CI. |
| I5 | The image holds no per-install state: `mkosi.finalize` fails the build on a machine ID, random seed, systemd credential secret or credstore, SSH host key, anything in `/etc/ssl/private`, private-key text (PEM, PGP, age) outside `/usr` in files up to 1 MiB, owner configuration (`/etc/agentos`) or broker state, on any socket file anywhere (V15), and on anything that could write the host's clock or assemble its disks (I11, I13). After the entry swap, `finish_image.py` lists the final ESP and fails on any file outside an allowlist (shim and systemd-boot binaries, loader.conf, entries.srel, the AgentOS entry, and the kernel and initrd it names), so a `loader/random-seed` cannot ship. The OpenClaw guest copy under `/usr` is not content-scanned (I9). | HW-1 | — |
| I6 | The broker starts when `/etc/agentos/agentosd.env` exists: at boot through `agentosd.service`, and as soon as onboarding (P2-2) writes it through `agentosd.path`. `agentosd.service` has `Delegate=yes` and no cgroup flags, so `-cgroup-root` defaults to the service's own delegated group and the broker moves itself into `broker/` (RES-2, #124). P2-2 writes `/etc/agentos` with mode 0700 and `agentosd.env` with mode 0600 and validates both values (C4). The vault process `agentos-egress` ships in `/usr/lib/agentos` with no unit yet: P2-4 adds it. Not exercised in CI until onboarding exists. | HW-1, RES-2 | Unit flags only. |
| I7 | Root is ext4, last on the drive, and grows to fill it on first boot (`systemd-repart` plus `GrowFileSystem`). It is not encrypted, so no drive goes to an owner before P2-4 encrypts owner state (C2); P2-4 may replace this root definition. | CRED-8 | P2-4 rewrites `50-root.conf`. |
| I8 | Reproducibility: the Debian main archive is pinned to a snapshot.debian.org timestamp; mkosi always adds live `security.debian.org`, so a later rebuild can pick up newer security packages (the package manifest records versions). gVisor and Node are pinned by hash, OpenClaw by lockfile, Go builds use `-trimpath` and no build ID, file times clamp to the commit time, IDs derive from a fixed seed (so every drive starts with the same IDs; I10). CI builds on two runners and requires the same `/usr` root hash, boot entry and kernel; the initrd is compared and reported until it is reproducible (BOARD IMG-2). S1 flashes only images built from a push to main, or later a signed release, never a fork PR's artifact (C3). | OSS-8, OSS-9 | Pin security by snapshot too, if mkosi gains a way. |
| I9 | The OpenClaw guest rootfs is built by `guest/openclaw/build-rootfs.sh`, which copies the build host's shell and libraries. Builds are reproducible only on the same runner image; a Debian-package guest root is a follow-up. | ARC-3 | Build the guest root with mkosi as a second image. |
| I10 | **Per-drive IDs** (Security MUST on #41). The fixed `Seed=` keeps `/usr` reproducible, so every drive is flashed with the same disk GUID, partition UUIDs and file-system IDs. `/usr` is chosen only by the entry's `usrhash=` and checked by dm-verity: the command line names no partition (`root=`, `mount.usr=`, `usr=`, `systemd.verity_usr_*` are refused by `finish_image.py`), so a same-ID `/usr` on another drive is the same verified release or fails to mount. In the initrd, `agentos-drive-ids` runs once the root device is found and before `sysroot.mount` (which `Requires=` it): the ESP the loader booted from (`LoaderDevicePartUUID`) must be the only partition with that ID, the root found for mounting must be on that ESP's disk, and no other disk may carry an ID of this disk's writable partitions; otherwise the box powers off (`FailureAction=poweroff`; a screenless box, so off is the signal). A fresh drive (root labelled `agentos-root-new`) gets random IDs: the disk GUID, every partition except the active release (labelled `agentos_*`, IDs from its root hash), the root ext4 UUID and the ESP volume ID, relabels root `agentos-root` last (an interrupted run repeats), and restarts once, since the loader still reports the old ESP ID for that boot. This uses one of the entry's 3 boot tries. CI boots two fresh copies (refused, A unchanged), A alone (new IDs, healthy, blessed), and A beside a fresh copy (boots, every mounted partition on A, no writable ID shared, the copy byte for byte unchanged). Residual: the check reads the disks once, so a drive carrying this drive's random IDs plugged in between the check and the mount (milliseconds) is not caught; copying a used drive's random IDs needs physical access to it, which already allows changing its unverified root (I7, C2). | HW-1, HW-5 | The ID set or the trigger label. |
| I11 | **Hardware clock** (HW-8, HOST-1b K1, K14). chrony replaces systemd-timesyncd, whose sync clears `STA_UNSYNC` and arms the kernel's 11-minute copy into the host's RTC. `/etc/chrony/chrony.conf` is HOST-1b's file (NTS first, no RTC directives, no DHCP sources), copied into `image/` until HOST-1b part 1 is on main; a test then requires the two to match. No `hwclock` or its udev rule (no `util-linux-extra`), and timedated is removed, so nothing serves `SetTime` or `SetLocalRTC`. `/dev/rtc*` is root 0600, and chrony runs with `DevicePolicy=closed` and no devices. `agentos-clock-boot` (HOST-1b K12) and the NTP-sync-then-RTC VM check (QEMU `-rtc base=localtime`, network needed) come with HOST-1b and HOST-1e. P2-9 K1's "enable systemd-timesyncd" is superseded. | HW-8, TIM-1 | Unit names only. |
| I12 | **Device policy** (HW-8; HOST-1a H11, security ruling (c) on #172: root can open a 0600 host-disk node). Every AgentOS service runs with `DevicePolicy=closed`: `agentosd` allows only `char-accel` and `char-drm` (broker/accel; the modem is the modem bridge's, gVisor runs on systrap), `agentos-health` only `/dev/mapper/control`, `agentos-boot-report` none. The initrd's `agentos-drive-ids` needs the drive's block device and is exempt. The CI boot lists every service unit's user and device policy, and fails on a root service with open device access that `image/device-policy.txt` does not list with a reason. `agentosd`'s policy is not exercised until onboarding runs in CI (IMG-4). | HW-8 | Add a `DeviceAllow=` line with its reason. |
| I13 | **No LVM or MD-RAID anywhere.** The HOST-1a rule that hides host disks runs only in the main system, so assembling in the initrd would also assemble a host's volumes, and an MD resync writes the host's disks (HW-8). The drive itself uses neither, so the initrd drops `lvm2` (and its udev rules) and has no `mdadm`, and the main system has neither, nor `udisks2`; `finish_image.py` lists the built initrd and fails on any of them. This reads HOST-1a H11's "the drive's own LVM or MD, if any, assembles in the initrd" as "if any": there is none. | HW-8, ONB-2 | If a later layout puts LVM or MD on the drive, assemble only the drive's own, matched by its IDs, in the initrd. |
