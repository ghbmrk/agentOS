# Device image: assumptions

Built for PLAN P2-1 against SPEC v0.12, on the S7 host pick (DECISIONS 2026-10-04) and the
S1/S2 test kit (spikes/S1S2-testkit), which first booted this stack under Secure Boot. Each row
is a reading of the spec, or a gap left for a later package, that a reviewer may want to change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| I1 | Non-UKI boot: Debian's signed shim, systemd-boot and kernel; mkosi's initrd and the entry's command line are not covered by Secure Boot. The boot editor is off (`editor no`, `secure-boot-enroll off`), so a keyboard cannot edit the command line. On a trusted host their integrity rests on the TPM policy seal, which must cover the initrd and command line (PCR 9 or a signed PCR 11 policy), not PCR 7 alone (C1, for P2-4b). | HW-5, HW-5a | A UKI needs our own signing key and per-PC enrollment, which HW-5 rules out. |
| I2 | A release is the `/usr` verity root hash plus the boot entry that names it in `usrhash=`. The build verifies the split `/usr` partition and hash tree against that hash with `veritysetup` and writes `agentos_VERSION.release.json`. The updater (sysupdate transfer files, TUF metadata) comes with the update package and consumes these files. | UPD-1a, UPD-8 | Only the manifest shape. |
| I3 | Two `/usr` slots of 6 GiB plus 192 MiB verity each; slot B starts as `_empty`. This release's erofs `/usr` is about 1.1 GiB, most of it the OpenClaw guest. The slots are sized once, because repartitioning after drives ship is irreversible (Potency R1). Large, independently versioned payloads (model weights, executor images) live outside `/usr` as their own verified targets, not in the release. With releases staged into the idle slot, budget R9's 1280 MiB staging reserve may no longer be needed; the update package decides. | UPD-1 | Pick sizes before the first drive ships. |
| I4 | Boot counting: the one entry starts with 3 tries; `agentos-health` gates `boot-complete.target`, so an entry is blessed only after `/usr` is mounted read-only from the verity device whose root hash equals the entry's `usrhash=`, and the broker, runsc, the guest image and its launch.json start or exist. Secure Boot off is reported, not failed. This is a reliability gate, not a security control. A failed check, or one hung past 5 minutes, runs `agentos-fallback`, which reboots while the entry has tries left (`LoaderBootCountPath`), so the count reaches zero and the previous entry boots with no owner action; at zero it reboots once more if `LoaderEntries` lists another agentOS entry (systemd-boot sorts the +0 entry last and `loader.conf` sets no default), and a single-entry drive at zero, or a blessed (uncounted) entry, stays up instead of looping. A try that never reaches the check also ends in a reboot: `panic=10`, and a `systemd.unit-dropin` credential on the command line that makes emergency and rescue mode run the fallback first in the host, or reboot in the initrd, which lacks it. So an initrd failure on a single-entry drive at zero, or on a blessed entry, reboot-loops; there it would otherwise hang with no usable shell. A hang with no panic and no failed unit still needs a hardware watchdog (LATER.md). CI shows the reboot on the two-drive boot, whose check fails. CI's forced-fail boot (IMG-3) shows the rest on this image: a fresh copy whose ESP also holds a previous release (the same entry as `agentos_0.conf`, version 0, no counter) boots with a `systemd.unit-dropin` credential that fails the health check whenever `LoaderBootCountPath` is set; the console shows the new entry's three tries at `+2-1`, `+1-2` and `+0-3`, each followed by the fallback's reboot, then the previous release passing (`bless=clean`), and the ESP afterwards holds the spent, unblessed `+0-3` entry beside the unchanged previous one. Gap: the previous release there shares slot A's `/usr`, so the boot of a slot-B `/usr` waits for the update package to write one; the single-entry-at-zero branch is covered by `tests/test_image.py` only. | UPD-1, HW-5 | Add checks (broker socket answering, journal replay) once onboarding runs in CI. |
| I5 | The image holds no per-install state: `mkosi.finalize` fails the build on a machine ID, random seed, systemd credential secret or credstore, SSH host key, anything in `/etc/ssl/private`, private-key text (PEM, PGP, age) outside `/usr` in files up to 1 MiB, owner configuration (`/etc/agentos`) or broker state, and on any socket file anywhere (V15). After the entry swap, `finish_image.py` lists the final ESP and fails on any file outside an allowlist (shim and systemd-boot binaries, loader.conf, entries.srel, the AgentOS entry, and the kernel and initrd it names), so a `loader/random-seed` cannot ship. `mkosi.conf`'s `RemoveFiles` keeps the ESP inside that list: it drops the random seed `bootctl install` writes and Debian's `vmlinuz-`, `config-` and `System.map-` files in `/boot`, which `00-esp.conf` would otherwise copy. The OpenClaw guest copy under `/usr` is not content-scanned (I9). | HW-1 | — |
| I6 | The broker starts at every boot (#1249): with `/etc/agentos/agentosd.env` absent, `AGENTOS_OWNER` stays empty and `agentosd -owner ""` runs setup mode, which the setup page needs; once onboarding writes the file (mode 0600, in `/etc/agentos` 0700, values validated, C4), `agentosd.path` starts the broker if it is not running and a restart reads the owner. `${AGENTOS_OWNER}` is a whole word, so systemd passes it as one argument even when empty. `agentosd.service` has `Delegate=yes` and no cgroup flags, so `-cgroup-root` defaults to the service's own delegated group and the broker moves itself into `broker/` (RES-2, #124). Its int uid flags (`-modem-uid`, `-localui-uid`) are filled at start by `with-uids`, which replaces each whole `@uid:NAME` word with `id -u NAME` and refuses a missing user. | HW-1, RES-2 | Unit flags only. |
| I7 | Root is ext4, last on the drive, and grows to fill it on first boot (`systemd-repart` plus `GrowFileSystem`). It is not encrypted, so no drive goes to an owner before P2-4 encrypts owner state (C2); P2-4 may replace this root definition. | CRED-8 | P2-4 rewrites `50-root.conf`. |
| I8 | Reproducibility: the Debian main and non-free-firmware archives are pinned to a snapshot.debian.org timestamp; the build's apt sources (`mkosi.pkgmngr`) also read live `security.debian.org`, so a later rebuild can pick up newer security packages (the package manifest records versions). gVisor and Node are pinned by hash, OpenClaw by lockfile, Go builds use `-trimpath` and no build ID, file times clamp to the commit time, IDs derive from a fixed seed. CI builds on two runners and requires the same `/usr` root hash, boot entry, kernel and both initrds (IMG-2, #2639); a differing initrd fails the build and is listed member by member (`compare_manifests.py --initrd`). S1 flashes only images built from a push to main, or later a signed release, never a fork PR's artifact (C3). | OSS-8, OSS-9 | Pin security by snapshot too (`snapshot.debian.org/archive/debian-security`). |
| I9 | The OpenClaw and Codex guest rootfs are built by `guest/openclaw/build-rootfs.sh` and `guest/codex/build-rootfs.sh` (#1721), and both copy the build host's shell, core tools (`/bin/sleep` among them) and their shared libraries unpinned: those bytes are whatever the runner image ships, not a snapshot or hash, so builds are reproducible only on the same runner image, and a runner update changes the worker's userland unreviewed. Only the Codex CLI itself is pinned (npm integrity hash, I18). A Debian-package guest root is a follow-up. | ARC-3, OSS-8 | Build both guest roots with mkosi as second images from the snapshot I8 pins. |
| I10 | Every drive is written from one image whose disk, ESP and root GUIDs derive from the fixed build seed (OSS-8), so two attached AgentOS drives would make the boot loader's ESP and gpt-auto's root ambiguous. `agentos-drive-id` gives each drive its own disk, ESP and root GUIDs once, after its first blessed boot (they apply from the next boot; the `/usr` slot GUIDs stay, since slot A's derives from its root hash), and on every boot `health` and the broker's `ExecStartPre` require that exactly one partition carries the booted ESP's GUID and that root is on that drive, so a boot with a second fresh drive attached is never blessed and the broker does not start. In the boot that assigns, udev shows the new GUIDs at once while the boot loader still names the old ESP GUID, so `assign` first records the old GUID, its partition and its disk in `/run/agentos-drive-id` (gone at the next boot), and `check` takes that record only when no partition carries the booted GUID and that partition is still on that disk; root must still be on it. Without it, a broker or vault start later in that boot failed until a power cycle (#1716), which the claim's vault restart hit on every first boot; the G1 e2e (#1688) claims after assign and so restarts the vault through it. Root's ext4 filesystem UUID stays shared; nothing mounts by it. CI boots a copy twice and two copies together. The kernel's 11-minute RTC write is off: `systemd-timesyncd` is removed, and chrony with `rtcsync` off comes with HOST-1b. | HW-1, HW-5 | Per-drive GUIDs at flash time instead, if S1 writes drives with a tool that can. |
| I11 | Inbound firewall: `agentos-inbound.service` loads `/usr/lib/agentos/inbound.nft` (`nft -f`, atomic) before `network-pre.target`, so before any interface is configured. `systemd-networkd`, `systemd-resolved`, `agentosd` and `NetworkManager.service` (a drop-in, #936) require it, so a failed load leaves the box with no network and no listener (fail closed). Debian's `nftables.service` is disabled, since it flushes the whole ruleset. `agentos-health` fails unless the `agentos_inbound` input chain ends in `drop`, so a release whose rules did not load is never blessed and the boot counter rolls back (I4). The boot test shows the rules loaded (`inbound=drop` in the health line); the reachability half of A14 runs the same file in network namespaces in CI (`tests/test_inbound_netns.py`), and since the wired uplink (I19) that test also runs real `systemd-networkd` on the image's `[Network]` section behind the drop: the box takes a DHCP lease and an IPv6 address from a stand-in router and no home host opens a box port at either, nor at the box's IPv6 link-local address, and each opens once the drop is deleted (the control). The booted image's first CI boot has a NIC (QEMU user networking) with host forwards to box ports 22, 80, 443, 18789 and 5355 (`systemd-resolved`'s LLMNR); `image/probe_inbound.py` connects through each and reads no answer, which is a dropped SYN (QEMU accepts the host's connection itself and closes it when the guest resets or answers; the probe's own test checks it tells a silent peer from one that closes). The test checks the lease is 10.0.2.15, the forwards' target, since a forward to nowhere would also read as dropped. The same boot has a second NIC whose other end is `image/probe_lan6.py` (QEMU's socket netdev, #1457): it plays a router advertising 2001:db8:6::/64, learns the box's link-local and SLAAC addresses from its duplicate-address checks, and first solicits each address, which the box must answer (the drop lets neighbour discovery through), the in-boot positive control that probe frames reach an address the box holds; only then does it send a SYN to each probed port at each address and read no answer (no reset, SYN-ACK or ICMPv6 error). `tests/test_boot_net.py` runs it against a stand-in box that drops, one that resets, and one that never answers neighbour discovery (no port is reported); `tests/test_inbound_netns.py` runs it from the home side of a tap into a namespace holding the drop and, as the control, without it. Gap: the in-boot control proves reachability, not a port that answers; an image without the drop would need a second build, so that half of the control stays with the netns test. | DEV-2 | |
| I12 | Access point through the inbound drop, only while the access point runs (DEV-net-f, DEV-net-g; DEV-2, CH-7, CH-9): `agentos-ap-exempt@<if>.service` (`Requires=`/`After=agentos-inbound.service`, `BindsTo=` the interface's device) runs `/usr/lib/agentos/ap-exempt <if>`, which refuses `lo` and any name that is not a wireless interface (`/sys/class/net/<if>/phy80211`), then refuses unless `agentos_ap`'s input chain holds the line `iifname "<if>" drop` (the loader loads `agentos_ap` first, for the interface it created as the access point, so `agentos_ap` is the loader's record: a second radio, or the access point before its table loads, is refused) and its forward chain holds `iifname "<if>" drop` and `oifname "<if>" drop` (the set also exempts the interface from `agentos_inbound`'s forward drop, #2824, so `agentos_ap` must drop all its forwarding but passthrough), then `nft add element` into `inet agentos_inbound exempt` and reads it back. Its `ExecStop=` runs `ap-exempt --remove <if>`: one `add element; delete element` transaction (succeeds whether or not the element is there, touches no other element) and a check that the name is gone; the interface need not exist, so the device going (`BindsTo=`) removes it too. Removal closes the interface: it falls to `agentos_inbound`'s drop, which stays loaded, so removing never opens the drop (the DEV-net-f note that it would was wrong). Because systemd skips `ExecStop` for a unit whose start failed and can report a stop as done when `ExecStop` failed, `localui.BringUp`/`BringDown` also run the removal through nft themselves and unload `agentos_ap` only after it succeeds (broker/localui L34). Any failure exits 1 and nothing else is added, flushed or deleted. Rests on: the image runs systemd-networkd, not NetworkManager (test_image guards this, so DEV-net-e l3 stays inapplicable). P2-1's loader (`agentos-ap`, I16) drives the access point only through `localui.APLoader`, which calls `BringUp` and `BringDown` (broker/localui L34, DEV-net-h), and brings every radio down at its start. Tested in `tests/test_inbound_netns.py` (namespaces: stop, single radio rejoining a home network, second radio) and `tests/test_image.py`. | DEV-2, CH-7 | Hardware check of the stop path on the controller's radio (A1, A6). |
| I13 | No memory of the card-holding broker reaches disk (IMG-nodump; card C13: the Owner Card passphrase is a Go string that cannot be zeroed). Core dumps are discarded: `kernel.core_pattern=\|/usr/bin/false` and `fs.suid_dumpable=0` (sysctl.d, sorted last), systemd-coredump `Storage=none`, `DefaultLimitCORE=0` for every unit and `LimitCORE=0` on the three secret-holding units, `agentosd.service`, `agentos-egress.service` (vault keys) and `agentos-localui.service` (claim and card codes), which `mkosi.finalize` requires to exist. There is no swap at all: no swap partition, fstab entry, `.swap` unit, zram generator or swap file, and `systemd.swap=0` on the kernel command line so a swap partition added to the drive later is never used. Swap on per-boot-key encrypted cryptsetup is the alternative if the box ever needs it; it is not allowed now. `mkosi.finalize` checks the effective values across every drop-in, `finish_image.py` the partition table and the boot entry, and `agentos-health` the running box (`swap=off dumps=off`), so a release that swaps or keeps dumps is never blessed. | HW-1 | Encrypted swap only with a new row. |

It cannot be a `+` ExecStartPre of the page: systemd applies the page's `TemporaryFileSystem=` to `+` commands too, and the step never saw the file (#1688). The TPM resource manager is group `agentos-egress` (udev). The vault process is sandboxed at least as tightly as the page and modem units (empty capability set, `ProtectSystem=strict`, seccomp `@system-service` minus `@privileged @resources`, native arch only, `MemoryDenyWriteExecute`, `RestrictNamespaces`, `PrivateIPC`, `ProtectProc=invisible`, `UMask=0077`, `DevicePolicy=closed` with only `/dev/tpmrm0`); tests/test_image.py pins each setting. Its two `+` ExecStartPre steps (`drive-id check`, `egress-setup`) run as root outside the namespace and seccomp sandbox, but the cgroup device policy binds them too; this rests on `drive-id check` reading partitions through lsblk, sysfs and the udev database rather than opening `/dev` block nodes, which is read from drive-id's code: the boot test runs drive-id in its own unit (agentos-drive-id.service) and does not check the unit's start under its device policy. `egress-setup --restart` drops its lock before `systemctl try-restart`, since the restarted unit's own `egress-setup` takes the same lock. The page unit keeps `TemporaryFileSystem=/var/lib/agentos:ro`, so it sees none of the broker's state; its one authority is the claim state and the Owner Card latch in its own state directory. Tested by tests/test_image.py and the two units' Go tests; the booted CI image does not yet assert each service is active. | ARC-6, CRED-9, HW-10 | An active-service check in the boot test. |
