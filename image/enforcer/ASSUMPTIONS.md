# Enforcer image assumptions (ENF-m-a, #3671)

Built against SPEC NET-2 Hardening and Channel, on D-229 (reuse the core's pipeline with an
enforcer-only key and feed) and briefs/ENF.md decisions 7 and 11. Each row is a reading a later change could overturn.

| ID | Assumption | Basis | Overturned by |
|---|---|---|---|
| ENF-m-1 | **The core's pipeline is reused, not copied, where it is generic**: the initrd settings (`../mkosi/initrd/`) and every finish check (`../finish_image.py`, imported). The core's 3,357-line `mkosi.finalize` is not: it checks agentOS units, users and keepers the enforcer does not have. The enforcer's own `mkosi.finalize` checks what is enforcer-specific. The apt sources, fstab, `/tmp` and root-growth files are copies of the core's. | D-229; #3671 split comment | A change to the core's finish step that breaks the enforcer shows in `enforcer-image.yml`, which watches it |
| ENF-m-2 | **Key separation compares keys, not signatures.** `finish_image.py` refuses a root, metadata signature or disk byte range that carries an agentOS key, matched by raw bytes (raw, hex, base64, PEM body) and TUF key id. It does not verify signatures: the box's update client does, against the key its root declares, so a signature whose key id lies does not verify. No agentOS release public key is committed to the repository, so the release build names them (`AGENTOS_RELEASE_KEYS`, PEM keys or root.json files); the build refuses to run with none. | NET-2 Channel; `broker/update` key format | Committed agentOS release public keys: then `build.sh` reads them by default |
| ENF-m-3 | **Watchdog.** PID 1 arms the first watchdog device (30 s). On the V1410 that is the chipset's TCO watchdog through `iTCO_wdt` [Inference: the V1410 is an Intel Jasper Lake board; not checked on the device]. The self-check fails a boot with no armed watchdog, so a box where the driver does not bind never blesses a release; the live run is a later row's. | NET-2 Hardening | A V1410 whose watchdog needs another driver |
| ENF-m-4 | **The state partition is not sealed to the TPM yet.** Writable state is the ext4 root partition, apart from both `/usr` slots and mounted noexec. Whether the V1410's TPM is usable was not checked: it needs the device, which a cloud session cannot reach. Sealing (an encrypted state partition bound to the TPM, as the core's sealed store binds its keys) is release item #4746. | Brief: "sealed to the TPM if the V1410's is usable; the builder checks and records it" | The device check |
| ENF-m-5 | **USB.** `usbcore.authorized_default=0`: the kernel authorises no USB device but root hubs, and no rule authorises one yet. ENF-t adds a udev rule naming its radios' USB IDs (decision 11); a radio behind an external hub then needs the hub's ID too. `usb-storage` and `uas` are not in the image (ENF-m-6), so no authorised device can use them. | NET-2 Hardening; decision 11 | ENF-t |
| ENF-m-6 | **Wi-Fi.** `cfg80211` and `mac80211`, which every Wi-Fi driver needs, the wireless drivers, the other modules that need `cfg80211` (staging Wi-Fi, batman-adv) and USB storage are left out of the image and the initrd (`KernelModulesExclude=`), and no Wi-Fi package or firmware is installed. The modprobe.d blocks stay as a second layer, but they are not enough alone: once a network card was present, `cfg80211` loaded despite its block (#4810, enforcer-image run 42499337177; the loader was not identified, and the kernel's request for nl80211's genetlink alias, `net-pf-16-proto-16-family-nl80211`, is the likely one). `mkosi.finalize` refuses a tree that still holds a blocked module. CI shows a forced load of the simulated radio driver refused and the self-check passing with a network card present. | NET-2 Hardening | — |
| ENF-m-7 | **Services.** The preset enables three units (self-check, boot report, the placeholder daemon) and disables everything else, and `mkosi.finalize` refuses any other enabled unit. No network is configured: no interface comes up until ENF-m-b adds the daemon and the open-port check. | NET-2 Hardening | ENF-m-b |
| ENF-m-8 | **Updates.** The image ships the enforcer feed's root and boots with counting and fallback, so a release that fails its self-check rolls back. Fetching a release from the enforcer feed, checking it against that root and writing it to slot B is the update client's work, which no slice built; it is release item #4745. The enforcer cannot import `broker/update` (decision 1), so the client uses go-tuf directly. | NET-2 Hardening; decision 1 | — |
| ENF-m-9 | **Not carried over from the core:** per-drive GUIDs (`drive-id`: the enforcer boots only its internal disk), the two-runner reproducibility comparison and the package vulnerability scan (EVL-5 names the core's image). The firmware password is set on the device at installation, not in the image. | Scope of ENF-m-a | A later row that needs any of them |
| ENF-m-10 | **No core dump reaches a file (#4459).** `sysctl.d/99-enforcer-nodump.conf` sets `kernel.core_pattern` to `\|/usr/bin/false` and `fs.suid_dumpable` to 0, as the core's image does (image I13). The kernel's default pattern, `core`, is relative, so a crashed radio stack would write its memory into its run directory, which its adapter sees; the stacks' `RLIMIT_CORE` 0 (radio ENF-k2-mnt-d) binds only a core file. `mkosi.finalize` reads sysctl.d as systemd-sysctl does for these two keys (directory precedence, name order, line ends at LF, CR or NUL, key normalisation, globs, `-key` unsets, last assignment wins) and refuses any link in sysctl.d; it is a smaller reader than the core's (no ownership walk), so the boot self-check, which reads `/proc/sys` and prints `dumps=off`, is the authority and `ci_boot.sh` requires it. `test_finalize.py` covers the reader. | NET-2 Confined radio stacks, NET-2 Hardening | A stack that needs a crash dump for debugging gets it from a lab image, never a release. |
| ENF-m-11 | **The kernel's reverse-path filter is off on every interface (#4810).** `sysctl.d/99-enforcer-rpfilter.conf` sets `net.ipv4.conf.all`, `.default` and `.*` `rp_filter` to 0. systemd's `50-default.conf` sets `default` and the `*` glob to 2 and leaves `all` alone; the later file's same keys replace those, and the glob reaches each interface as udev adds it. The kernel uses the larger of `all` and the interface's value, and on (1 or 2) it drops the WAN's DHCP answers before the ruleset's `rpf` chain, which replaces it, sees them (broker/enforcer/nft ENF-e-11), so the uplink never leases. `mkosi.finalize` refuses a tree whose final sysctl.d set leaves any key that names or globs an interface's `rp_filter` other than 0 (`test_finalize.py`); the self-check reads `/proc/sys/net/ipv4/conf/*/rp_filter` and fails a boot where any is not 0, and `ci_boot.sh` requires it to list `all`, `default` and a network card. Which interface is the WAN is ENF-m-b's; every interface is held at 0, so it needs no name. | NET-2 Fails safe, HW-16 | A ruleset without the `rpf` chain |
| ENF-m-12 | **No interface takes an ICMP redirect, before the daemon starts or while it is down (#5164 R3).** `sysctl.d/99-enforcer-redirects.conf` sets `accept_redirects` to 0 on `all`, `default` and `*`, IPv4 and IPv6. IPv4 takes a redirect when `all` or the interface's own value is on (when both are, with forwarding on); IPv6 reads only the interface's own value, which `default` starts. The glob reaches the interfaces up before systemd-sysctl runs and, through udev, each one added later, the WAN included: a redirect is never wanted there either, and no other key of the WAN is set (its `accept_ra` stays ENF-m-b's, broker/cmd/agentos-enforcer ENF-l-21). systemd's `50-default.conf` sets no `accept_redirects`. `mkosi.finalize` refuses a tree whose final sysctl.d set leaves any key that names or globs an interface's `accept_redirects`, in either family, other than 0 (`test_finalize.py`). The self-check reads `/proc/sys/net/ipv{4,6}/conf/*/accept_redirects` and fails a boot where any is not 0, and `ci_boot.sh` requires it to list `all`, `default` and a network card in both families; after that the daemon writes and reads back `default`, IPv4 `all` and each served interface at every reading (ENF-l-21). | NET-2 Segments, NET-2 Fails safe | A segment that needs redirects to route |
| ENF-m-13 | **The WAN's router-advertisement handling is checked at boot, and ENF-m-b sets it (#5189).** The daemon holds `default.accept_ra=0` and, with forwarding on, the kernel ignores `accept_ra=1` (broker/cmd/agentos-enforcer ENF-l-21), so the WAN takes router advertisements only when its link configuration says so: networkd's `IPv6AcceptRA=` in its `.network` file, or sysctl.d `accept_ra=2` on it. No interface is configured yet (ENF-m-7), so the image sets neither. `ci_boot.sh` runs `ci_wan.sh`'s probe before the boot report, which reads the first network card (the only one in CI, standing in for the WAN) for up to 60 s and prints its link state, `accept_ra`, forwarding and whether it holds an IPv6 default route; the check passes on `accept_ra=2` or a default route, and on a link left down only while `agentos-enforcer.service` is the placeholder, so ENF-m-b's unit cannot ship without one of them. The placeholder is the unit whose effective `ExecStart` (`systemctl show`, drop-ins applied) is the one command `/usr/bin/sleep infinity`, whatever its Description says (#5330). The default-route form takes any IPv6 default route on the card; requiring `proto ra` on it ships with the real unit (ENF-m-b, #3671; #5330 item 2). The default-route form rests on QEMU's user network sending router advertisements to the guest with `restrict=on` [Inference: libslirp answers a router solicitation itself; not checked on a real boot, since no image has a WAN up yet]. A WAN with no IPv6 loses function, not containment (NET-2 Fails safe). | NET-2 Fails safe | ENF-m-b's WAN link configuration, or a CI network without IPv6 |
| ENF-m-14 | **Boot-to-ruleset window, and what the self-check does not assert (#5120).** From kernel start until `systemd-sysctl` has read sysctl.d, interfaces carry the kernel's defaults (`rp_filter` 0, `accept_redirects` 1). From then until `agentos-enforcer` loads the ruleset, only the sysctl.d values (ENF-m-11, ENF-m-12) bound the box; ENF-m-7 configures no interface, so none is up and nothing is routed in that window [Inference: not measured on the device]. `mkosi.finalize` reads `/etc/sysctl.conf` after sysctl.d, as systemd-sysctl does, and refuses a link there. The self-check does not assert `accept_source_route`: systemd's `50-default.conf` sets `default` and `*` to 0 and the kernel's own default for `all` is 0 [Inference: from systemd's shipped file and kernel documentation, not read from the built tree]; with forwarding off and no interface up, a source-routed packet has no path, and with it on the ruleset's `rpf` chain is the control. Asserting it would add a boot failure for a key no ruleset or later row depends on. | NET-2 Hardening | A kernel or systemd default that sets `accept_source_route` above 0; an interface up before the ruleset loads |
