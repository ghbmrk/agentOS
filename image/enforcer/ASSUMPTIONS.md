# Enforcer image assumptions (ENF-m-a, #3671)

Built against SPEC NET-2 Hardening and Channel, on D-229 (reuse the core's pipeline with an
enforcer-only key and feed) and briefs/ENF.md decisions 7 and 11. Each row is a reading a later change could overturn.

| ID | Assumption | Basis | Overturned by |
|---|---|---|---|
| ENF-m-1 | **The core's pipeline is reused, not copied, where it is generic**: the initrd settings (`../mkosi/initrd/`) and every finish check (`../finish_image.py`, imported). The core's 3,357-line `mkosi.finalize` is not: it checks agentOS units, users and keepers the enforcer does not have. The enforcer's own `mkosi.finalize` checks what is enforcer-specific. The apt sources, fstab, `/tmp` and root-growth files are copies of the core's. | D-229; #3671 split comment | A change to the core's finish step that breaks the enforcer shows in `enforcer-image.yml`, which watches it |
| ENF-m-2 | **Key separation compares keys, not signatures.** `finish_image.py` refuses a root, metadata signature or disk byte range that carries an agentOS key, matched by raw bytes (raw, hex, base64, PEM body) and TUF key id. It does not verify signatures: the box's update client does, against the key its root declares, so a signature whose key id lies does not verify. No agentOS release public key is committed to the repository, so the release build names them (`AGENTOS_RELEASE_KEYS`, PEM keys or root.json files); the build refuses to run with none. | NET-2 Channel; `broker/update` key format | Committed agentOS release public keys: then `build.sh` reads them by default |
| ENF-m-3 | **Watchdog.** PID 1 arms the first watchdog device (30 s). On the V1410 that is the chipset's TCO watchdog through `iTCO_wdt` [Inference: the V1410 is an Intel Jasper Lake board; not checked on the device]. The self-check fails a boot with no armed watchdog, so a box where the driver does not bind never blesses a release; the live run is a later row's. | NET-2 Hardening | A V1410 whose watchdog needs another driver |
| ENF-m-4 | **The state partition is not sealed to the TPM yet.** Writable state is the ext4 root partition, apart from both `/usr` slots and mounted noexec. Whether the V1410's TPM is usable was not checked: it needs the device, which a cloud session cannot reach. Sealing (an encrypted state partition bound to the TPM, as the core's sealed store binds its keys) is release item #4746. | Brief: "sealed to the TPM if the V1410's is usable; the builder checks and records it" | The device check |
| ENF-m-5 | **USB.** `usbcore.authorized_default=0`: the kernel authorises no USB device but root hubs, and no rule authorises one yet. ENF-t adds a udev rule naming its radios' USB IDs (decision 11); a radio behind an external hub then needs the hub's ID too. `usb-storage` and `uas` are blocked even for an authorised device. | NET-2 Hardening; decision 11 | ENF-t |
| ENF-m-6 | **Wi-Fi.** `cfg80211` and `mac80211`, which every Wi-Fi driver needs, are blocked, the wireless drivers are left out of the initrd, and no Wi-Fi package or firmware is installed. CI shows a forced load of the simulated radio driver refused. | NET-2 Hardening | — |
| ENF-m-7 | **Services.** The preset enables three units (self-check, boot report, the placeholder daemon) and disables everything else, and `mkosi.finalize` refuses any other enabled unit. No network is configured: no interface comes up until ENF-m-b adds the daemon and the open-port check. | NET-2 Hardening | ENF-m-b |
| ENF-m-8 | **Updates.** The image ships the enforcer feed's root and boots with counting and fallback, so a release that fails its self-check rolls back. Fetching a release from the enforcer feed, checking it against that root and writing it to slot B is the update client's work, which no slice built; it is release item #4745. The enforcer cannot import `broker/update` (decision 1), so the client uses go-tuf directly. | NET-2 Hardening; decision 1 | — |
| ENF-m-9 | **Not carried over from the core:** per-drive GUIDs (`drive-id`: the enforcer boots only its internal disk), the two-runner reproducibility comparison and the package vulnerability scan (EVL-5 names the core's image). The firmware password is set on the device at installation, not in the image. | Scope of ENF-m-a | A later row that needs any of them |
