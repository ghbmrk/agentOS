# D-271: Root units are closed by construction: pinned commands and two closed key lists (#4493, KRN-2)

Date 2026-11-02. Source: Security reject on PR #4559 (comment 6573272343); the four review rounds on PR #4617, which this row replaces, ending in the L3 reject 6575404011 and the Security reject 6575434032, both `Next: step back`. Standing rule: Mark's structure-first rule of 2026-10-30.

**Decision.** The root-side lint in `broker/kernel/privfile` (`TestRootSidePathOpsGoThroughPrivfile`, #4493) closes every root unit by construction. Every check main makes today stays; this row only narrows further.

1. **Root unit.** A unit or drop-in under `image/` or `broker/` is a root unit unless its merged `User=` is a literal name that is not `root` or `0` and holds no `%` or `$`. `DynamicUser=` true does not exempt a unit by itself, since systemd reuses a static user of the same name, `root` included. A unit is a root unit too if it has a `+` or `!` line, or a merged `PermissionsStartOnly=` that is true; any other key that makes systemd run code as root for a `User=` unit makes it a root unit the same way. `PAMName=` fails on every unit, root or not, since PAM runs as root before the uid changes and its stack is outside any pin; no shipped unit sets it, and a shipped `pam.d` file is held to `exec.allow`. "Merged" means the unit plus every drop-in systemd 257 applies to it: each `-` prefix's directory, the template's, the type-wide one (`service.d`), in every unit directory, read as `mkosi.finalize` reads drop-ins. A `.socket` unit that hands a socket to a root unit is read as a root unit. A drop-in directory the lint cannot place fails.
2. **Two closed key lists.** Every key in every section of a merged root unit is on exactly one of two lists in the lint. A key on neither list fails, so a key systemd adds later, or one nobody thought of, is refused until a reviewed edit places it.
   - **Pinned keys** decide what a command runs, reads, receives or is named by. Each pinned key's merged value is pinned word for word with its unit and a reason in the units-only file, beside the commands (item 3). A changed value is a reviewed pin edit.
   - **Inert keys** can only narrow. For every value, a pinned command can run, read, write and receive nothing that a non-root uid or a file outside the pin controls and that it could not reach with the key absent. An inert key sets no environment variable, opens no file as the manager, runs nothing, and changes no unit name or drop-in set. Their values stay free, since no value of theirs reaches past main's baseline of the key being absent.
   - Placement: when in doubt, a key is pinned, which costs only a pin edit. The pinned list holds at least the command keys (item 3) and `ExecPaths`; `Environment`, `EnvironmentFile`, `PassEnvironment`, `UnsetEnvironment`; `User`, `Group`, `DynamicUser`; the path keys (`BindPaths`, `BindReadOnlyPaths`, `RootDirectory`, `RootImage`, `MountImages`, `Extension*`, `TemporaryFileSystem`, `WorkingDirectory`, `ExecSearchPath`); the input keys (`Standard*`, `TTYPath`, `OpenFile`, `LoadCredential*`, `SetCredential*`, `ImportCredential`); the `*Directory=` keys; `NetworkNamespacePath`, `IPCNamespacePath`, `BPFProgram`, `IPIngressFilterPath`, `IPEgressFilterPath` and `LogNamespace`; `Type`, `WatchdogSec` and `MemoryPressureWatch`, which set variables; the keys that start another unit (`Wants`, `Requires`, `BindsTo`, `Upholds`, `OnFailure`, `OnSuccess`, `Slice`, and `Unit=` on `.path` and `.timer` units); a `.path` unit's `Path*` and `MakeDirectory`; `JoinsNamespaceOf`; `Alias`, `DefaultInstance` and `Also`; and a handed socket's `Listen*`, `Socket*`, `Symlinks`, `Service` and `FileDescriptorName` keys.
   - The D-154 keys: `InaccessiblePaths` is inert, since it only removes access and `mkosi.finalize` still requires it. `PrivateTmp` is inert, since it swaps the world-writable `/tmp` and `/var/tmp` for private ones shared at most with units that join this one, which is still narrower than everyone who can write the global ones. `StateDirectory` is pinned, since it sets `$STATE_DIRECTORY` and makes the manager create and chown a path as root.
3. **Commands.** Every root command is pinned whole, word for word, with its unit and a reason, in the units-only file: the value of every command key (`ExecStart`, `ExecStartPre`, `ExecStartPost`, `ExecCondition`, `ExecReload`, `ExecStop`, `ExecStopPost`, and a socket's `ExecStartPre`, `ExecStartPost`, `ExecStopPre` and `ExecStopPost`), every `;`-joined command and every `+` or `!` line. `ExecPaths` and `ExecSearchPath` hold paths, not commands: they are pinned values (item 2) and count nothing, as on main. No argument is modelled, and a command not pinned fails. The list for udev, modprobe, sysctl and tmpfiles stays separate and unchanged, and never names a shell.
4. **Main's checks stay.** The pin matches literal text, so a substitution still has to clear main's rules: a plain absolute program; no `%` specifier; `$` only as a whole-word `${X}` that `unitVars` pins, with its sources checked across drop-ins; the mount, fstab and `.mount` `What=` rules. The live cases are `${AGENTOS_OWNER}` (`agentosd.service`) and `${AGENTOS_PAGE_IFACE}` (`agentos-localui.service`, a `+` line); the builder pins each as a `unitVars` entry or changes the unit.
5. **`$$` names.** A pinned script reads `$$NAME` or `$${NAME}` only for `SERVICE_RESULT`, `EXIT_CODE` or `EXIT_STATUS`, which systemd sets after the manager environment, and only when no `Environment` or `PassEnvironment` of the merged unit names it and the unit has no `EnvironmentFile`. Any other `$$` fails. An `EnvironmentFile`'s writer is reviewed with the pin, since its contents set `PATH` and `LD_*` for the command. The live case is `$$SERVICE_RESULT` in agentos-keeper-kernel's `ExecStopPost`.
6. **Manager level.** No shipped `system.conf` or `system.conf.d` drop-in, read as systemd 257 merges them, sets `DefaultEnvironment` or `ManagerEnvironment`, and no word of `mkosi.conf`'s `KernelCommandLine=` is `systemd.setenv=…`. Generators stay held by `exec.allow`, and the boot command line by `finish_image.py`'s allow-list, as on main.
7. **Counting.** A broker binary counts toward the root side wherever its name appears in a pinned command, bare or absolute, as a whole word, inside an `sh -c` script, after `=` or inside `$(…)`. A bare name extends main's count, which takes only tokens that start with `/`; the build adds a subtest for it. Over-counting is safe. The reason text is never a source for the count.
8. **Links and paths.** No absolute path in a pinned command or pinned value may have a component that is a link the repo ships under `image/` or `broker/`, or a `pathAliases` alias. A merged-usr `/bin` in the built image is not such a link, so `/bin/mkdir` and `/bin/false` stay. The lint refuses `.`, `..` and relative operands in any path word of a pin.
9. **Shells.** A shell runs as root only as a pinned whole command, with its script word for word. No shell is ever listed as a program. Moving the `sh -c` lines into script files was rejected: `mkosi.finalize` pins `KERNEL_REBOOT`, the exact `sh -c` text of agentos-keeper-kernel's `ExecStopPost`, and checks Exec values for `REBOOT_WORDS`, so a script file would hide `systemd-run` from that guard.

**Why this form.** Each round on #4617 found one more systemd key that a prose list missed, then a catch-all defined by a property ("remaps paths or the environment") over-refused hardening keys and under-caught input keys. Two closed lists end that: an unknown key fails. A pin of the whole merged unit would close the class too, but it would also pin hardening keys (`ProtectSystem`, `CapabilityBoundingSet` and the like) on about 30 units. That is roughly ten times the pin text, and every hardening edit would become a pin edit. The extra review would buy nothing, because an inert key cannot reach past the key being absent, which is main's baseline. No lens gets worse. Security gains a closed set, positive `$$` names and the manager clause, on top of main's count and refusals. Potency keeps main's subtests. UX costs nothing for today's units, which the two lists must place anyway.

**Review.** The reviewer checks four things: a root command is admitted only by an exact pin on top of main's checks; every key of a merged root unit is on one list; a key moved to or added on the inert list meets the inert test above; and a broker binary anywhere in a pinned command counts. In a new pin the reviewer also checks that the command and its pinned values read, write or run nothing in a world or magic tree, change no directory and root no tree there. A pinned script must build no program name through shell expansion or quoting, and no path with a component a non-root uid can write. Examples: `nft -f /tmp/x`, `sh -c 'cd /tmp && ./x'`, or a `rm` under a broker's `StateDirectory`.
