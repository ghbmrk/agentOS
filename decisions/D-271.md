# D-271: Root unit commands are pinned, on top of main's checks (#4493, KRN-2)

Date 2026-11-02. Source: Security reject on PR #4559 (comment 6573272343, fourth round); then the fix-lists on this row: L3 6574948903 and Security 6574962392 (round 1), L3 6575136747 and Security 6575146810 (round 2). Standing rule: Mark's structure-first rule of 2026-10-30.

**Decision.** The root-side lint in `broker/kernel/privfile` (`TestRootSidePathOpsGoThroughPrivfile`, #4493) gains a pin. The pin is added on top: every check main makes today stays, and the pin only narrows further.

1. **Root unit command.** Every `Exec*` value and every `;`-joined command, in any unit or drop-in with no `User=` or `DynamicUser=`, and on every `+` or `!` line in any unit, as main's lint reads it now. Units under `broker/` are read as well as those under `image/`.
2. **The pin.** Each root unit command is pinned whole, word for word, with its unit and a reason, in a units-only file. The list for udev, modprobe, sysctl and tmpfiles stays separate and unchanged, and never names a shell. No argument is modelled; any change to a root command is a reviewed edit of its pin. A command not pinned fails.
3. **Main's checks stay.** The pin matches literal text, so a substitution still has to clear main's rules:
   - a pinned program is a plain absolute path;
   - a pin holds no `%` specifier;
   - a pin holds `$` only as main allows it: a whole-word `${X}` that `unitVars` pins, with its `Environment=` and `EnvironmentFile=` sources checked across drop-ins;
   - the mount, fstab and `.mount` `What=` rules stay.
   The live cases are `${AGENTOS_OWNER}` (`agentosd.service:41`) and `${AGENTOS_PAGE_IFACE}` (`agentos-localui.service:41`, a `+` line, newly read under item 1); the builder pins each as a `unitVars` entry, or changes the unit.
4. **Counting.** A broker binary counts toward the root side wherever its name appears in a pin, bare or absolute, as main counts it today: a whole word, inside an `sh -c` script, after `=`, or inside `$(…)`. So `sh -c 'exec agentos-camnode'` is root-side. Over-counting is safe. The reason line is never a source for the count.
5. **Links.** No absolute path anywhere in a pin's text (scripts and `=` values included) may have a component that is a link the repo ships under its image trees, as #4559 reads them, or a `pathAliases` alias. A merged-usr `/bin` in the built image is not such a link, so `/bin/mkdir` and `/bin/false` stay.
6. **Shells.** A shell runs as root only as a pinned whole command, its script word for word. No shell is ever listed as a program. Moving the `sh -c` lines into script files was rejected: `mkosi.finalize` pins `KERNEL_REBOOT`, the exact `sh -c` text of agentos-keeper-kernel's `ExecStopPost`, and checks Exec values for `REBOOT_WORDS`, so a script file would hide `systemd-run` from that guard.

**Why.** A deny-list over argument spellings has false passes by construction. A pin fails closed: a new spelling, wrapper or argument is a different command that is not pinned. Because main's counting and refusals all stay, no lens gets worse: Potency keeps the subtests that pin them, and Security gains a reviewed pin on top of the mechanical count.

**Review.** The reviewer checks that a root unit command is admitted only by an exact pin on top of main's checks; that a broker binary anywhere in a pin's text counts; that a `$`, `%`, link or alias in a pinned path is refused as on main; and that a shell appears only inside a whole-command pin. In a new pin the reviewer also checks that the command reads, writes or runs nothing in a world or magic tree, changes no directory and roots no tree there, and that a pinned script builds no program name through shell expansion or quoting (for example `nft -f /tmp/x`, `rm -rf /tmp/d/x`, `sh -c 'cd /tmp && ./x'`).
