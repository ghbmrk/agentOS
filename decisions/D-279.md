# D-279: Trusted-core growth for #4805 (KRN-erase-plans, KRN-text-clerk-retry)

Date 2026-11-02. Source: issues #3870 (KRN-erase-plans, LOG-4, D-169) and #4760 (KRN-text-clerk-retry, KRN-1). Standing rule: D-159.

**Decision.** PR #4805 (issues #3870 and #4760, tier A) may grow the trusted core by +47 lines (`tools/trusted_base.py`, 41275 to 41322 against main 416e4dc, as measured by the builder), all in `broker/kernel` (`erase.go`, `state.go`, `log.go`, `kernel.go`, `trip.go`), with no new linked packages. The two changes are:

- `Submit` and the owner's key checks (`ownerKeys`) return the encoding's own wrapped error through one `asLogged` helper in `log.go`, instead of `ErrNotText` or a fixed string, so a caller learns why a value cannot be logged (#4760, KRN-1, fail closed). The model clerk's own change, so that a clerk given such text does not retry forever, is in `broker/clerk/model` and is outside the core.

**Review.** The reviewer re-measures against the base at merge (the baseline moves as other core rows land) and checks that every added core line belongs to one of the two changes as described above; growth beyond them is a finding, not a waiver.
