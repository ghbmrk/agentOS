# D-137: Gate-file PRs need a Security accept; nothing waits for Mark's line

Date 2026-10-19. Source: Mark, Decisions thread 2026-10-19 15:22:37Z ("Seeing as I'm just copying and pasting these without any understanding really, might as well just do them automatically", cmsg_01R63S2yrPkq32thy8WQCuvD1qFM6UGTNGC7QqB5oGG8X4); his tap of "Everything + extra" on the card "Merge which PRs automatically once reviews accept and CI is green?" (cmsg_01R63S2yrPkq32thy8WQCuvDAM8q9bDfofZtUAiTMbq9sm: "Everything merges without your line, but a PR that changes the gates also needs a separate security review to accept it"); then 16:04:17Z ("Build the D-137 gate change: gate-file PRs need a Security accept, everything else merges automatically", cmsg_01R63S2yrPkq32thy8WQCuvD8FjJwZJVYvWKZ28rvhKpXT). Supersedes D-125 and D-130. Procedure: docs/OPERATING.md §4, §7.

**Decision.**
1. **No PR waits for Mark's line.** SPEC.md PRs, interpretive or not, and gate-file PRs merge on their reviews' accepts and green CI, armed at the last accept like any other PR (D-120). The `Transcribes:` and `Mark-approved:` lines are retired.
2. **Gate-file PRs need a separate Security accept.** A PR for which `tools/premerge.py --needs-mark` prints `mark` (the D-125 list, unchanged) also needs a Security verdict of `accept`, from a fresh session that is neither its builder nor its L3/combined reviewer, posted in its own comment (marker `<!-- record: security -->` and no `l3` or `combined` marker), at a head whose diff equals the merging head's.

**Enforced.** `premerge.py --check` (the required `premerge` status) prints `needs-security <files>` for a gate-file PR until the newest trusted Security verdict comment accepts a head whose diff equals the current one; SPEC.md gets no extra check. Which session wrote a comment is not checkable from the comment, so the "fresh session" part stays procedure.

**Not changed.** The `--needs-mark` path list, the review tiers, the L3 accept the gate already requires, and the rule that an interpretive point a reviewer finds is a finding the review handles (it no longer goes to Mark by default; a real trade-off still goes to him on a card, per the auto-decide rule).

**Reasons.** Mark said his typed line adds no check: he pastes it without reading the diff. The risk it stood for is that a gate-file diff can weaken the reviews themselves, so the replacement is a second independent review that the gate counts, not a person's click.
