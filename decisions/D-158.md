# D-158: The readability rule

Date 2026-10-24. Source: Mark tapped "Readability rule" on the Decisions card cmsg_01R91wiieBzMSvPKFsAJVvuK9grKMJ2F1QEddQ56ZH4c1w (2026-10-24 18:33:45Z). Design: project file `answers/2026-10-24-frontier-plans-local-guard.html` (artifact https://claude.ai/artifact/NxbXon1o9NR1R3HFZfL6Br), "The design: one rule, one gate" and "The spec change".

**Decision.** A model call carrying private data goes only to a route nobody else can read (the box's own model, or an owner compute host granted private data) or to a route that a **class key** names for that call's task class (PLN-3, PLN-7). Reader values are private like everything else: D-141's reader-value exception is deleted, so a planner on a route others can read gets reader answers only under a class key. The kernel, never a planner, sets a call's class (KEY-2), so a planner cannot tag a suspended class's call with a keyed one. The box suspends a class key once routes nobody else can read score within noise of the keyed route on the class's held-out suite (HLD-3). Suspension is log state the key check reads, like a KEY-6 pause, not a caveat. If those routes fall behind, the box lifts its own suspension, with a notice to the owner; it never lifts an owner's pause or revoke. That returns to the grant the owner already signed, with the same caveats, expiry and caps, so it is not a widening (KEY-4). STATUS lists each key with what its route received.

**Switch-over.** D-115's yes on a plan's private-content question becomes one class key per task class that the plan route serves with private data. On adoption every such class gets its key, so no class gets worse on the day this lands; a live box's new keys are signed under KEY-4 like any other. A yes at onboarding (§8.1 step 6) makes the same keys. The per-route private-data question and its defaults (plan yes, private hosted no) are gone from PLN-7; a private hosted route receives private calls only under a class key.

**Supersedes.** D-115's plan private-content default part, and D-141's fallback route for the reader ("else on a route allowed private data") and its last clause ("its typed values may reach any planner route"). D-141's local-reader gate is unchanged.

**No kernel growth.** A class key is a key naming a destination, which PLN-3 already requires before a private value reaches a model route; deleting the exception removes a check.

**Not decided here.** Attested routes (a new route kind and risk for TEE.fail), decided separately once measurement shows the box's hardware keeps classes keyed. Exposure counting on the inbox eval set (#2527) runs in its own thread.
