# D-111: Drop the open-PR cap; add a conflict guard

Date 2026-10-13. Source: Mark, project Questions thread, 2026-10-13 ("Can more work be done in parallel - too slow", 19:17Z, cmsg_01R91wiieBzMSvPKFsAJVvuK2prLbArs9xuRcmPebpjYmB; then "No cap, as long as not wasteful of usage via merge conflicts", 19:19Z, cmsg_01R91wiieBzMSvPKFsAJVvuKMvMgh4vcRho4eRxnQAugPp).

**Decision.** The "about 10 open PRs per lane" cap of D-098 ends. D-098's scope freeze, and its 48-hour idle limit (no draft exempt), stay in force. The cap is replaced by a conflict guard: a build does not start while an open PR touches any file in the brief's declared scope, and two builds started together must have disjoint scopes. Shared append-only lists (BOARD.md, DECISIONS.md, ASSUMPTIONS.md files, and similar one-row-per-change lists) are exempt, as are files only generated by CI.

**Reasons.** The cap limited parallelism by count, but the cost Mark cares about is rework from merge conflicts, which scope overlap predicts and a count does not. With disjoint scopes any number of builds can run at once.

**Not changed.** The codex lane's own 3-PR limit (docs/LANES.md, D-110) is a lane rule and stays. `tools/metrics.py` still reports open PRs per lane against "about 10"; WIP-1 now drops that figure instead of enforcing it.
