# D-320: File overlap no longer blocks a build; hot files stay serial

Date 2026-11-16. Source: Mark, Questions 9 thread: "Elaborate on this one pr per file and if it's actually necessary" (cmsg_01R91wiieBzMSvPKFsAJVvuKTpHeV6scccG8EtBQztHifS), then, on the explanation that the D-111 guard blocks by file while conflicts happen by line, "Alter this so it makes more sense" (cmsg_01R91wiieBzMSvPKFsAJVvuKNPwBYGZ58cJuiWHrndnody).

**Decision.** This supersedes D-111's conflict-guard clause; D-111's end of the PR cap stays.
1. Overlap of files between an open PR and a brief's scope no longer blocks a build, and builds started together may share files.
2. Files on the hot list below take one open build at a time.
3. A build whose scope overlaps an armed PR branches from that PR's head, not from main.
4. A PR that conflicts after another merges rebases (or merges main). A result `tools/premerge.py` reads as `same` owes no delta review; a changed diff gets the usual delta review (OPERATING §7).
5. Each week METRICS counts the rebases that needed a delta review. If that count shows the rework Mark's D-111 condition guards against ("as long as not wasteful of usage via merge conflicts"), the coordinator brings it back to him.

**Hot list.** `broker/cmd/agentosd/main.go` (the daemon's main wiring). The hot-file measurement over 116 PRs merged in the 14 days to 2026-11-16 found no other file that qualifies. A later measurement adds files here, each with its measure, by a PR citing this decision.

**Brief scopes name files (coordinator's addition from that measurement, not Mark's text).** The measured collision source was briefs claiming whole directories (`image/`, `broker/kernel`, `broker/localui`), not shared files. A brief's scope names files, not directories, from the next time the brief is touched, so rules 2 and 3 compare real files.

**Reasons.** D-111 blocked by file, but git conflicts by line, so PRs editing different parts of one file were serialised for no rework saved. It also held builds behind armed PRs that merge unchanged. The cost D-111 targets is a delta review on a changed head, which `premerge.py`'s `same` reading already avoids for clean rebases; serialising only the files where edits collide often keeps that cost low, and the weekly count shows whether it does.

**Not changed.** Claim first (D-215), the codex lane's 3-PR limit (D-110), and one owner per directory from migration step 4 (OPERATING §5). Until METRICS has the count (its own work item), the coordinator tallies it by hand.
