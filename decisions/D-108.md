# D-108 (2026-10-13)

The broker takes `github.com/godbus/dbus/v5` v5.1.0, the D-Bus client `cmd/agentos-netjoin` uses to write the home Wi-Fi connection through NetworkManager (P2-2w c3; Security L8 on the P2-2w plan). Accepted against "near-zero dependencies" because:

- NetworkManager's D-Bus API is the only way to hand it a PSK without a command line, environment or file the helper would write (L8.5); `nmcli` with the PSK as an argument is ruled out.
- It is BSD-2-Clause, pure Go, has no dependencies of its own, and is vendored (`broker/vendor`), so builds never reach a module proxy (DEP-1).
- Only `cmd/agentos-netjoin` imports it; `broker/netjoin` sees NetworkManager through its own `NM` interface, so agentosd and the rest of the broker never link it.
- Its `os/exec` use is the session-bus autolaunch (`conn_other.go`) and macOS launchd lookup (`conn_darwin.go`); `ConnectSystemBus` reaches neither, and the helper's unit has no `DBUS_SESSION_BUS_ADDRESS`. The daemon's child-environment check names both in `vendorEnvExempt`, and a test pins that agentosd links neither.
- Its one URL literal is a comment citing the D-Bus specification, recorded as inert in `assurance/dependencies.json`.

Writing a D-Bus wire client in-tree was rejected: the marshalling and SASL auth are the bulk of the work and a new source of defects, for no gain over a small, stable, widely used module.

**Source:** P2-2w c3 brief (briefs/P2-2w-c3.md)
