# D-117: Grok and Muse join the plan route on the owner's plan login, no API key; terms reads default to allowed

Date 2026-10-14. Amends D-114. Source: Mark, project Questions thread. 00:36:10Z (cmsg_01R63S2yrPkq32thy8WQCuvDToGvZ2vEYNyb3st7AwrJwn): "Grok and muse don't need api either". 00:37:30Z (cmsg_01R63S2yrPkq32thy8WQCuvDYTgmCCEorhYYFX8R3HrbkN): "You have the terms - if not there then assume fine".

**Decision.**
- **Grok (#1378) and Muse (#1379) are plan routes.** Both use the owner's plan login, broker-held, with no API key. Terms verdict `allowed`. Grok source: x.ai/legal/terms-of-service, retrieved 2026-10-13; nothing in it prohibits automated or tool use, and section 2 Registration (no sharing credentials or making the account available to anyone else) does not reach the owner's own box acting for the owner. Muse source: Muse Supplemental ToS (muse.ai/terms, last updated 2026-09-08), retrieved 2026-10-13.
- **Terms-read rule.** A terms read gives verdict `allowed` unless the provided terms explicitly prohibit the use. Policies the terms cite but that were not provided (xAI AUP, Meta ToS, Meta AI ToS) are assumed fine.
- **Muse constraints (acceptance criteria on #1379).** Section 4(p) forbids hiding the automated nature of actions from affected parties, so outgoing actions made through Muse disclose that they are automated. Section 4(f) forbids using third-party credentials without authorization, so only the owner's own login is used. The arbitration section names "automated ways" only as an example of unauthorized use, not a rule against them.
- **Codex (#1377) is unchanged.** Its terms read is still pending Mark.
