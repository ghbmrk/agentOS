# D-114: Codex is the default plan route; Claude is an owner opt-in

Date 2026-10-13. Source: Mark, project Questions thread, 2026-10-13 (project message cmsg_01R63S2yrPkq32thy8WQCuvD17ibA5D3FyCLTBYAyU2Zud, 20:54:52Z, "Claude is unclear so default to codex with Claude as opt in with warning; also muse and grok"), after his read of https://code.claude.com/docs/en/legal-and-compliance fetched 2026-10-13 20:42Z. His earlier messages in the same exchange set the Claude shape: 20:49:04Z ("there may be a way to navigate it - if sign in is done via Claude's own flow etc; Claude code is not the only frontier plan, and more people would have OpenAI anyway"), 20:50:14Z ("Also if the user is doing it vs AgentOS itself somehow") and 20:52:32Z ("Claude is not preinstalled tho").

**Question.** Do Anthropic's consumer terms allow a self-hosted agentOS box to run Claude Code on the owner's Claude plan? Three clauses bear on it: "preinstalling or running Claude Code in your products or services", developers may not "collect, store, or intermediate… credentials or session tokens", and may not "route requests through… plan credentials on behalf of their users".

**Verdict.** `unclear`. This is the verdict briefs/CAP-11-plan.md (Threats, Spec dependency) left to Mark and the open question in L3 blocker 2 of reviews/l3/2026-10-13-pr1315.md.

**Decision.**
- Codex (ChatGPT plan) is the default plan route. It stays broker-held and unconfirmed, as D-061 set, so the owner's recorded consent (CRED-5) still applies.
- Claude is an owner opt-in. The route is off until the owner accepts a warning that quotes the three clauses and says Anthropic could restrict their account.
- The Claude route is worker-held and user-driven. Claude Code is not preinstalled; it is installed only after opt-in. The owner runs Claude's own sign-in flow in the unmodified CLI, and the CLI keeps its credential on its login volume. agentOS code never reads, copies or serves that credential. This replaces the #1315 design in which agentos-egress kept the token in the vault and served it to a launcher over a per-worker socket.
- Grok (xAI) and Muse (Meta; Mark, Questions thread, 2026-10-13 21:04:21Z, "Muse is from meta") are plan routes once a read of their terms sets the custody mode. Mark is pasting the OpenAI and xAI terms into the Questions thread for that read (#1377).
- A provider whose terms allow neither mode (verdict `not-allowed`) gets the API key route only. A read not yet done leaves the route off.

**Consequences for the plan-login chain.** Broker-held Codex needs no login volume, socket or tunnel: the egress proxy injects the login at declared endpoints and swaps refresh responses (CRED-5, ADP-10), which S8 proved mechanically. #807, #1015, #1014, #1314 and #1264 are re-scoped to Codex; the Claude opt-in is its own release row.

**Open points this decision leaves.** These are flagged on the PR, not settled here.
- CRED-5 W2 checks the login file's schema at every mount, which reads it, while the Claude opt-in says agentOS never reads that credential. The SPEC does not settle which gives way; the volume still needs CRED-8 encryption at rest without agentOS reading the file.
- CRED-5 W3 names `claude setup-token` as Claude's inference-only login. That token is printed for the user to supply, which a user-driven shape cannot pass on without agentOS handling it. The Claude opt-in row must show an inference-scoped login the CLI keeps itself, or W3 rules the route out.
- CAP-11 says CLI versions change only through image updates. A Claude CLI installed after opt-in must still be the release-qualified version.
- The Claude sign-in relay through the Wi-Fi page: how the owner drives Claude's sign-in in a headless worker without agentOS reading or intermediating the sign-in artifact (#1380).
