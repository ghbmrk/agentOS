# D-069 (2026-10-08)

Local devices as capabilities (SPEC §10B, DEV-1 to DEV-11; REV-5, ARC-5, ARC-6, CAP-2, CAP-12, ADP-2, CH-3, CH-10, CH-11, CH-18, §14, A14, A16, §17 risks 17 to 23).

**Problem.** SPEC v0.12 named "local network devices by explicit grant" in CAP-2 but defined no grant, executor, verb, or network rule for them. Meanwhile REV-5 left a `public` machine's uncredentialed egress "open", which on a home network reaches the router's admin page, printers, NAS shares, cameras, and any LAN service without authentication. The spec gave devices no capability and left the home network exposed.

**Decision.**

1. **The home network is untrusted** (DEV-2). No component reaches a non-global address, the box's own prefixes (global IPv6 widened to /56), or a learned router address, except a device executor to its pinned devices, the egress proxy to a compute host, the broker's resolver to the network-assigned resolver (DNS only), and a broker component to an owner-pinned backup target or private hosted route (an agent reaches the latter only as a routed model call); the host's own link configuration and the broker's NAT-PMP or PCP external-address query to the gateway are not connections. The check runs on the connected address, which defeats DNS rebinding. The box accepts no inbound connection from the home network except a connected device inside its authenticated session. Discovery is passive, and its results go to the owner only. This is release work (DEV-net-a, DEV-net-b, A14).
2. **Device executors** (DEV-1) are credentialed executors, one per credential domain (a hub, the box's Matter fabric, or one device). They run on mature stacks, are qualified through §11, and reach no internet host. The fabric root key stays in the vault.
3. **Identity is pinned** (DEV-3). An unverified device gets public content only and no `actuate-physical`.
4. **Classes come from physical consequence, not the adapter** (DEV-4, DEV-5).
   - `actuate` is reversible within owner bounds, with UNDO.
   - A device type missing from the table gets the strictest class: every write `actuate-physical` with no secure direction, media responses capture. A hub entity over a switch, plug, or relay is a generic switch whatever its hub domain, with no secure direction until its load is named.
   - Self-moving devices (robots, printer axes) are `actuate-physical`; stop, pause, cancel, and dock are secure.
   - `actuate-physical` lets the secure direction be pre-allowed, or approved by a texted code; a value outside `actuate` bounds stays high risk unless its secure direction is pre-allowed. Turning off a safety or access device is unsafe. The unsafe direction needs a code-generator code per action, unbatched.
   - Admin operations map to the existing verbs, and secret-creating ones to CRED-6.
   - Device credentials fall under Invariant C.
5. **Output is gated by audience** (DEV-6): owner, household (the default), or public. Private content goes freely only to owner devices.
6. **Capture is off until turned on locally** (DEV-7). It stays on the box or goes to an allowed compute host, never enters recall, and is deleted at task end.
7. **Events are untrusted and never urgent by themselves** (DEV-8). Urgency comes only from owner rules over verified devices.
8. **Cloud-visible devices count as disclosure** (DEV-9). From private machines they take enumerations and ranges only, under research-query bounds. Device reads are private, so device state is no private-to-public channel inside the box. `local-only` needs evidence (qualification or the owner's statement); a device's report of its own setting never counts by itself. Cutting a device off from its vendor cloud is a secure direction (a code-generator code for safety and access devices), offered as `BLOCK <id> <code>` beside the disclosure prompt where qualification shows the setting effective; BLOCK performs the action only where it is then low risk (a `household` audience), else it only cuts off. Turning it back on is tier 4.
9. **Grants** (DEV-10):
   - The broker prepares a connection plan (names, rooms, classes, bounds, audiences) and one tier-4 visit confirms it. A verified device that needs no secret can be connected read-only by `CONNECT <id>` and a code-generator code.
   - Capture, widening, re-pinning, turning a vendor cloud back on, and administrative grants (`change-account`, `delete-remote`, `reveal-or-create-secret`) need tier 4.
   - `actuate` or `present` on a device without a safety or access role, cutting such a device's vendor cloud off, private content on a `local-only` household device, and a secure-direction action take the texted low-tier code (CH-10). An `actuate-physical` grant, or a grant on a safety or access device, needs a code-generator code; an `actuate-physical` grant is never batched.
   - A digits-only reply matching no open code counts as a wrong code, so spoofed guesses are bounded.
   - Texted codes arrive as their own `Code <digits>` text, which the owner copies whole and sends back.
   - Revoking takes one text. An unused grant is offered for revocation in the digest.

**Tradeoffs.**
- *A per-class grant without the local page (UX over strictness).* A SIM swapper cannot obtain a code-generator code.
- *Texted codes for non-safety device grants (UX over SIM-swap resistance, risk 23).* Their worst case reaches no one outside the household and is bounded or undoable; locks, heat, valves, motion, capture, and connection keep the code generator or the local page. The owner can exclude these verbs from the low tier.
- *Phone code autofill not relied on.* Copying the whole code text works on any phone; keyboard suggestions are the phone's behaviour. Everything that widens exposure most (capture, bounds, audience, pins) still needs the local page.
- *Unverified devices kept usable for public content and reversible actions, not refused.* Many printers and cameras have no cryptographic identity.
- *Radios on the box excluded (§14).* The owner's hub or border router provides them without adding host attack surface.
- *Secure-direction pre-allowance accepted with risk 20.* Closing and turning off are not always harmless.

**Rejected.**
- *An agent-side LAN allowlist.* It turns any granted host into an unauthenticated control surface and keeps rebinding open.
- *Hub tokens injected by the egress proxy into HTTP requests alone.* Matter, IPP, SMB, and RTSP are not HTTP, and a token's scope is usually the whole hub.

**Phasing.** DEV-net-a and DEV-net-b are first-release blockers (A14, G2). Devices follow the first release (A16, G6): read-only sensors, storage, and printers first; then the device executor and events; then actuators, capture, and audience output.
