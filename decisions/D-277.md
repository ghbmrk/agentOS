# D-277: Trusted-core growth for #4720 (KRN-proc-print)

Date 2026-11-02. Source: issue #4719 (KRN-proc-print, tier A). Standing rule: D-159. Basis: DECOY-b-8's pointer-to-pointer rule and KRN-1's fail-closed rule, the same approval as the earlier release rows (D-267, D-268, D-270, D-273, D-274).

**Decision.** PR #4720 (issue #4719) may grow the trusted core by +19 lines (`tools/trusted_base.py`, 41238 to 41257, as measured by the builder), in `broker/kernel`, with no new linked packages. The added lines are of four kinds:
- (a) pointer-to-pointer fields (DECOY-b-8's rule), so that `proc.Kernel` and the keys it holds print no key value: the `proc.Kernel` head and link keys, the CounterAnchor signing key and the held recovery card;
- (b) one guard in `Log.Append` that refuses any text in an entry that the log would rewrite or that is not valid UTF-8. It covers Submit, Cancel, Undo, ReadPool and Reserve;
- (c) `Kernel.Submit` decides the plan in the form the log holds it, by a JSON round trip (about 4 core lines), so a non-UTF-8 plan ID is not checked for reuse under the wrong ID;
- (d) `Kernel.Answer` coerces a clerk's outcome and detail to valid UTF-8 before they are logged (about 3 core lines), so an in-process clerk's answer is not refused by the new guard.

**Review.** The reviewer re-measures against the base at merge (the baseline moves as other core rows land, for example D-273 and D-274) and checks that every added core line is one of the four kinds above; growth beyond them is a finding, not a waiver. The guard fails closed: a refused plan ID is an error, never a silent rewrite.
