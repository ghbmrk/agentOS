# D-131: Four guest options

Date 2026-10-19. Source: Mark, Questions thread, 2026-10-19 12:15:27Z (cmsg_01R63S2yrPkq32thy8WQCuvDJokSX4bBb42N24w3iZCASV): "Did this already - the four are the 3 frontier plan ones (codex, muse, groq) that have the right cli situation + openclaw".

**Decision.** agentOS has four guest options (ARC-3): the official CLIs of Codex (ChatGPT plan, the default guest), Grok (xAI) and Muse (Meta), and OpenClaw. "Groq" in Mark's line is read as Grok (xAI), the plan route in CRED-5 and #1378; Muse is Meta's, as in D-117 and #1379.

**Why** (Mark, 2026-10-19 12:18:55Z, cmsg_01R63S2yrPkq32thy8WQCuvDFF6wgNfyQbB7S7rK1TXwSE): OpenClaw on default hardware has no capable local model; the goal is a frontier plan orchestrating local resources for more efficiency on finite, expensive usage.

**Also (Mark, 2026-10-19 12:22:01Z, cmsg_01R63S2yrPkq32thy8WQCuvD9p95vszSRNhkYFbqkVCzv3).** Broker tools should make delegation effective; guest instructions are refined to do it without bloating per-request tokens; the guest, as main orchestrator, uses the smartest model without prohibitive latency by default and maximum capability on deeper tasks. 

**Decided (Mark, 2026-10-19 12:24:31Z, cmsg_01R63S2yrPkq32thy8WQCuvDLofbG8yW5gQESMdhTV2QQP: "Yes that’s fine. Codex should be default guest.").** Maximum capability on deep tasks is delegation to a CAP-11 worker at the plan's top model and effort. Codex is the default guest.

**Shape (proposed by the coordinator and adopted in SPEC; only point 5's no-fixed-limit clause is in Mark's words (12:47:13Z, cmsg_01R63S2yrPkq32thy8WQCuvD464vTL6nbne9biQuo7eG7T: "Standing instructions limit could be arbitrary and effect potency; there's probs a better way to get same outcome"), and every other point is a reading for his typed line).**
1. Each CLI guest runs only through ARC-6's interface; model calls go to the broker's provider endpoint with a placeholder credential.
2. Custody is broker-held only (D-117 sets all three to broker-held). Worker-held custody mounts the login only into that provider's workers (CRED-5), so a worker-held plan (Claude Code opt-in, D-114) is not a guest option.
3. Each CLI guest is qualified per version through §11 and LOOP-11 and appears in the owner's list only once qualified, so OpenClaw stays active until Codex qualifies. How owner messages enter its inbound API is a declaration and qualification item, not a blocker.
4. Codex is the default only where a ChatGPT plan is connected; OpenClaw is the guest for Local-only and API-key setups, and every requirement that applies to a setup passes with that setup's guest.
5. Acceptance for each CLI guest includes the CAP-13 handoff working and the plan usage saved being measured (A10). Broker tools make delegation cheap and effective; guest instructions' per-request cost is measured, and a leaner set replaces the current one only when the held-out suite shows no drop in success (no fixed limit, per Mark's 12:47:13Z line, cmsg_01R63S2yrPkq32thy8WQCuvD464vTL6nbne9biQuo7eG7T); tool detail loads on demand; the default turn's model has a latency bound set at qualification; the guest chooses when to delegate (no pre-task classifier).

**Open** (marked `[Open]` in ARC-3): whether connecting a plan after setup offers or makes the guest switch; what the Codex guest does when its route is paused, refused, unconfirmed or withdrawn (proposal: a broker-made switch to OpenClaw); the default for setups with only a Grok or Muse plan or only a private hosted model.

Antigravity and Gemini CLI stay excluded (#1409 amendment, Mark 2026-10-14 00:29Z). Builds on guest/codex (a CAP-11 worker today) and #1377 to #1379. The rest of #1409 (broker-held state, cross-provider check) is not part of this decision.
