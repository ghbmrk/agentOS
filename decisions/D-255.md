The recommendation, as approved:

1. Byte-cap overruns at the enforcer keep the KRN-12 trip. The kernel refuses any send that would pass a cap.
2. The same rule applies on the enforcer channel (NET-5). The kernel checks each command's format and rate before sending, and a malformed or excessive command at the enforcer trips.
3. False-trip safeguards: the kernel stops on the enforcer's own per-destination count read over the channel, plus a margin for in-flight bytes and retries; it uses the enforcer's day, so a clock difference cannot reset a cap early; it checks commands against the same format definition the enforcer enforces. The simulator tests each cap edge and a malformed command.

**The answer to his question (01:49:40Z, in the Questions thread):** accidental recovery is not needed from normal use. An honest core never reaches a cap or sends a bad command, so a trip means an attack. What is left is a bug where the kernel and the enforcer disagree; the three safeguards close the ways they could. After that, an accidental trip needs a bug in that one small check, which the simulator tests at each cap's edge. That residual risk is stated, not removed.
