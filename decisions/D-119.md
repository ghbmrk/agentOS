# D-119: ARC-1 lets hostapd's own user read the access point password

Date 2026-10-15. Source: Mark, Decisions card (approval message id added before merge). Work items #1648, #1312; from PR #1590 (#1426).

**Decision.** ARC-1's rule that only root-owned host processes read the host network secrets gets one exception: hostapd's dedicated unprivileged user (`agentos-hostapd`) may read the access point password from the runtime configuration it runs from (CH-7). That file sits in tmpfs (`/run/agentos-ap`), is readable by that user's group alone and is never written to the drive (IMG-nodump). The on-drive stores (`ap-net.json` and `setup-net.json`) stay root-only. The claim sticker's setup password (HW-10, D-112) falls under the same rule as the Owner Card's password.

**Reasons.** After #1590 hostapd, which faces the air before any auth, no longer runs as root, so a compromise cannot write the owner records. It cannot start without reading its own configuration, so ARC-1's text had to allow that read.

**Not changed.** CRED-1 and CRED-8, the journal, logs, snapshots and recall exclusions, and D-073's root-only store on the drive.
