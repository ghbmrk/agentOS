# D-120: records stay bot-only and the last accept arms the merge

Date 2026-10-15. Source: Mark, project message 2026-10-15 12:40:04Z ("Yes", cmsg_01R63S2yrPkq32thy8WQCuvDCVDGCf9kEBbZRpfxDeybYm). Work items #1816, #1819; part of #1691. Amends D-099 (who merges) and D-092 ("coordinator merges in its own turn").

**Decision.** (1) Records stay a bot job: `records.yml` runs once a day and is the only writer of `reviews/` files, so a feature PR carries no record commit and `tools/premerge.py` has no exemption. Target: records-only merges one a day or fewer. (2) The session that posts the last required accept arms auto-merge itself, only when the head equals the accepted head, CI is green and every review the tier requires accepted that head; it re-reads the head after arming and disarms if it changed (the arm call takes no head SHA). There is no merge worker. (3) After an accept, a push is allowed only to fix another review's finding: disarm first if armed, push, delta review, re-arm. (4) A PR touching a permission or review path (`premerge.py --needs-mark` prints `mark`; the list is `MARK_PATHS` there and OPERATING §7) is merged by Mark.

**Reasons.** Records-only PRs were 37% of merges in 48 hours. Writing them inline would rerun full CI on code PRs and need a premerge exemption that a modified or deleted record could pass. A separate merge worker is a cold start per merge once strict "up to date" is off.

**Not changed.** The reviews required by tier, the delta-review rule, the required checks. Follow-up: make premerge a required check.
