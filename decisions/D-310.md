# D-310: Ceilings only Mark raises

Date 2026-11-03. Source: Mark, "3 do it" in Decisions 8 (cmsg_01R91wiieBzMSvPKFsAJVvuK9RavMxoq8VhhMqyNb6RuYu, 2026-11-03 18:06:17Z), answering item 3 of cmsg_01R91wiieBzMSvPKFsAJVvuKJBxBzrPk3Ev4egaev3B8SD: "CI rejects any PR that pushes trusted lines (old and new core together, 58,895 today) or spec words above the current number. Adding means deleting as much elsewhere, and only you can raise either number."

**Decision.**
1. **Two ceilings** in `tools/ceilings.txt`, checked on every PR by `tools/trusted_base.py check` (the trusted-base workflow, base copy, on the PR head merged onto main):
   - `trusted-lines 58895`: the trusted core's lines as `tools/trusted_core.txt` measures them, plus every Go file under a `tools/old_core.txt` directory that is not a test or under testdata. 58,895 is the 2026-11-01 figure Mark approved; main measured 59,363 (core 41,472, old core 17,891) on 2026-11-03.
   - `spec-words 65725`: SPEC.md's words as `tools/word_budget.py` counts them, main's count on 2026-11-03.
2. **The rule.** A PR fails when a measure ends above its ceiling and above main's measure, and the failure names how many lines or words to cut. While main is over a ceiling a PR may not grow that measure; no PR crosses a ceiling upward. Main is about 468 trusted lines over today, so no PR may grow trusted lines until about 468 are cut. Each PR is measured against main at its last push, so two PRs that each fit the headroom can land together above a ceiling; main is then over it and the rule above stops further growth until cuts bring main back under. Old-core directories listed on either side count on both, and a head without the core file is measured by main's, so dropping a list line sheds no lines.
3. **Only Mark raises.** Any PR may lower a number and is then held to it. To raise one, Mark answers a decision card; a DECISIONS.md row recording the answer and naming the PR merges first, and the PR body carries `Ceiling: <that row's ID>`. Deleting the file needs the same line. The row must be active on main and name the PR. The file and the tool are gate files (Security accept, D-137).
4. **What ends.** D-159 rule 2: core lines no longer take a per-PR `Trusted-core:` waiver, so no growth decision is written per PR; a new import, an allow line or a dropped root still needs a `Trusted-core:` decision. The D-152 `Word-budget:` waiver no longer lifts SPEC.md above its ceiling.
