# D-115: Private covers content only; the plan private-content question defaults to yes; the reserve is a setting

Date 2026-10-13. Source: Mark, project Questions thread. 21:44:59Z: "Private needs to be defined + made clear doesn't include credentials etc; the part of each limit shouldn't be a q in onboarding but a setting in whatever settings." 21:53:58Z (cmsg_01R63S2yrPkq32thy8WQCuvD8jdrsfYMbMP4cCL8bVArRs): "Assume local model is very dumb so guest should be as thin as possible - default yes on private for plan".

**Decision.**
- **Private is content only.** REV-6 gains: credentials (passwords, plan logins, API keys, tokens, keys) are never private data to share, and no setting sends them to any model or provider (CRED-1, Invariant C).
- **Plan routes default yes.** The SPEC section 8.1 step 6 question is "Let this plan see your private content: mail, documents, chats, and anything made from them? Passwords and keys are never shared." Its default is yes for plan routes.
- **Private hosted keeps no.** CAP-9 states the private-hosted default (no) explicitly, apart from plan routes.
- **The reserve is a setting.** "Keep part of each limit for your own use?" leaves onboarding. Each ONB-9 pool line carries "Kept for your own use: 0%", changeable on the page or by text. RES-5's default of 0% is unchanged; the worker-held best-effort note (CRED-5 W7) moves with it.

**Not in this decision.** Pre-checking the setup page's box is a separate row (#1403). Guest declarations are #1409. Issue #1384.
