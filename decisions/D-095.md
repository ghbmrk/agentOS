# D-095: Simplification: one gate, one log, one objective

Date 2026-10-10. Source: Mark, simplification thread ("Plan to implement this, then implement"; "Stop any work that becomes redundant after this").

**Decision.** Build toward SPEC §9 taken literally: the journal is the only durable state, every other store is a projection rebuilt from it, owner messages are intents rechecked at dispatch (OP-3), one revisable outcome record per goal (OP-7), FORGET erases once in the journal (CAP-3), and the trusted core is a named package list. Packages: BOARD section "Simplification (2026-10-10)", brief `briefs/SIM.md`. The spec change itself goes through SIM-sd, which Mark approves; wave 0 (SIM-gate, SIM-fs, SIM-bound) and SIM-check, SIM-proj, SIM-core need no spec change.

**Redundant work stopped.** Rows that harden a mechanism SIM-owner or SIM-erase deletes are `dropped (superseded by SIM-x, D-095)`: the digest queue's own lint gates, Failed-batch compaction and forget-test gaps (W5-Dc-r18, r19, r21, r22) and the per-store forget follow-ups (W3-forget-reach-r1 to r5, W3-forget-b2c-f1-r2 to r4, W3-forget-b2c-f2). Their cases become tests in the SIM package. Rows that state an owner-facing requirement stay queued and are built inside SIM-owner or SIM-erase (W5-Dc-r5, r13, r15, r16, r17, r20). Open PRs are not closed: W5-D drafts stay as reference (CONV-3 parts bin). The forget log over backups (W3-forget-b1-5, b1-6, b1-7) and the spec diffs W5-Dc-r2, r3, r14 keep their rows. W5-Db and W5-Dc are corrected to merged (#573, #592) with the rows folded into them.

**Not decided here.** Scope freeze of off-gate subsystems and a WIP cap per lane (separate cards); main branch protection (a GitHub setting only Mark can change); how gain is measured and whether a tie may adopt (policy, SIM-outcome only makes it legible).

**Reasons.** About 25 self-persisting stores, 11+ forget implementations and four outcome vocabularies each need their own correctness argument; one log needs one. Most open defects and follow-up chains in W5-D and W3-forget are symptoms of that drift, so patching them one by one keeps the cost. Later ideas (crypto-shredding, policy as data, capability grants, deterministic simulation, pull-first, repo as log) are LATER rows `SIM l1` to `l6`, tagged recheck.
