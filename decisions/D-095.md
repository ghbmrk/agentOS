# D-095: Simplification: one gate, one log, one objective

Date 2026-10-10. Source: Mark, simplification thread ("Plan to implement this, then implement"; "Stop any work that becomes redundant after this").

**Decision.** Build toward SPEC §9 taken literally: the journal is the only durable state, every other store is a projection rebuilt from it, owner messages are intents rechecked at dispatch (OP-3), one revisable outcome record per goal (OP-7), FORGET erases once in the journal (CAP-3), and the trusted core is a named package list. Packages: BOARD section "Simplification (2026-10-10)", brief `briefs/SIM.md`. The spec change itself goes through SIM-sd, which Mark approves; wave 0 (SIM-gate, SIM-fs, SIM-bound) and SIM-check, SIM-proj, SIM-cases, SIM-core need no spec change.

**Redundant work stopped.** Rows that harden a mechanism a SIM package deletes are `dropped (superseded by SIM-x, D-095)`, and their case is named in that package's acceptance: the digest queue's Failed-batch compaction and its gate (W5-Dc-r18, r21, r22; SIM-owner-digest deletes `digestqueue` whole, `Sender`, `Batch` and the gate included) and the digest and retry forget follow-ups (W5-Dc-r19, W3-forget-b2c-f1-r3, W3-forget-b2c-f2; SIM-erase). Rows that state an owner-facing requirement stay queued and are built inside SIM-owner-hold (W5-Dc-r13, r15, r16, r17), SIM-owner-digest (r20) or SIM-erase (r5). Recall's take-back (W3-forget-reach-r1 to r5) is not a projection and keeps its rows; the restore-path rows W3-forget-b2c-f1-r2 and r4 stay queued with the forget log over backups (W3-forget-b1-5, b1-6, b1-7). The spec diffs W5-Dc-r2, r3, r14 keep their rows. W5-Db and W5-Dc are corrected to merged (#573, #592) with the rows folded into them.

**W5-D drafts.** Mark chose yes on "journal as the only durable state" (Decisions card, 2026-10-10): W5 building stops and the W5-D draft PRs stay open as reference. SIM-cases owns extracting their crash, acknowledgement and forget cases as tests against main; a case main fails is assigned to SIM-owner-hold, SIM-owner-digest or SIM-erase, never skipped.

**Not decided here.** Scope freeze of off-gate subsystems and a WIP cap per lane (separate cards); main branch protection (a GitHub setting only Mark can change); how gain is measured and whether a tie may adopt (policy, SIM-outcome only makes it legible).

**Reasons.** About 25 self-persisting stores, 11+ forget implementations and four outcome vocabularies each need their own correctness argument; one log needs one. Most open defects and follow-up chains in W5-D and W3-forget are symptoms of that drift, so patching them one by one keeps the cost. Later ideas (crypto-shredding, policy as data, capability grants, deterministic simulation, pull-first, repo as log) are LATER rows `SIM l1` to `l6`, tagged recheck.
