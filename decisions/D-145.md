# D-145: Root children carry a limit

Date 2026-10-21. Source: Mark, tap "Require a limit" on the Decisions card cmsg_01R63S2yrPkq32thy8WQCuvD3jz5qCbo7yXFH3AK5VgvY1, 2026-10-21 12:27:20Z (#2631 item 3).

**Decision.** Every key derived from the root carries at least one caveat (spend, bounds, expiry, hold window, verbs or the like), so full power stays with the owner's root (the phone passkey) and a leaked or misused child key is always capped; enforced in the key chain check, which refuses an uncaveated first link (`key.ErrUncaveated`) in `Derive`, `Verify` and `Chain`. A loose caveat still passes, so issuing points set sensible defaults. Supersedes nothing

**Narrowed by D-146.** A key off the root must carry both an expiry and a daily spend cap, and the root is the passkey's own, not "the phone passkey" alone: the owner's hardware keys anchor it.
