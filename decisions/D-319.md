# D-319: mutgate maps a changed helper line to the tests that reach it

Date 2026-11-15. Source: auto-decided by the coordinator, option A; Lens's fix-list on #5827 (comment 6892769898). Context: #5770 widens a package's mutgate targets to every covered line when a changed test line sits outside a test function. #5757's new `chrony_test.go` imports and helpers trip that rule, so the gate fails on about 290 survivors in code the PR never touched.

**Decision.** Option A: a changed test line outside any test function (an import or helper) maps to the tests that reach it, not to the whole package. The fix keeps both holes closed, each with its own test:
- #5753: a changed helper plus a comment line targets the lines covered by every test that reaches the helper, transitively;
- #5762: a skipped or deleted test plus a comment line targets that test's base coverage;
- a change to anything every test runs (`TestMain`, `init`, a package-level var initializer) still targets every covered line, since nothing calls those by reference.

**Rejected.**
- B, a baseline of about 290 survivors: worsens Potency.
- C, kill every survivor first: neutral on every lens, but blocks #5757 for a long time; the survivors stay valid as separate rows.
- D, no test code outside a test function: keeps #5757's 189 test-only client lines in `kernelsock.go`, because `tools/trusted_base.py` counts no `_test.go`, and so breaks the D-310 ceiling.
