# D-123: bot PRs get CI through a bot token

Date 2026-10-16. Source: Mark, Decisions card 2026-10-16 12:14Z (cmsg_01R91wiieBzMSvPKFsAJVvuK9ots49DuPohRxXLpoaJUhY). Work item #1769.

**Decision.** Option A, bot token. Mark creates `BOT_PR_TOKEN` himself, a token limited to this repository, and stores it as a secret in a `bot` environment limited to main. #1770 (merged) already reads it. Once the secret exists, the bot workflows are re-run so #739, #741 and #1893 get real CI.

**Reasons.** GitHub does not run CI on pushes made with the default token, so bot PRs stall. One setup removes the stall; the merge queue likely still needs a token, and approving by hand stalls whenever Mark is away.

**Not changed.** No merge queue; no per-push manual approval.
