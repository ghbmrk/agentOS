**Decision.**
1. **Two PRs.** #2996 (setup-only kernel start, STO-2c) and #3001 (TPM slot capped after unlock, STO-2c-cap) may grow the trusted core over tools/trusted_core.txt. Each names D-159 in its `Trusted-core:` line.
2. **Standing rule.** Core growth that implements a design Mark already approved needs no card. It proceeds when every review its tier requires accepts, citing that approval. Growth with no approved design behind it still goes to Mark as a card.
3. **How a later PR cites it.** `tools/trusted_base.py` accepts a `Trusted-core:` line only when it names an active row of the base branch's DECISIONS.md whose text names the growth PR's own number, so a row the PR adds itself does not count (#2945). A later growth PR therefore first gets a one-row DECISIONS.md PR with its own ID: status `active`; decision text "Trusted-core growth for #<PR>, implementing <the approved design> (D-159)"; source the message id of Mark's approval. That row merges on its own reviews, then the growth PR names it in its `Trusted-core:` line.
4. **Review still checks each line.** The reviewer confirms the cited approval covers the design the code implements; growth beyond it is a finding, not a waiver.
