**Security: does default-yes widen exposure without saying so?** It does widen exposure. By default, a connected plan's provider (Codex/OpenAI first) receives private content. The SPEC says so where it matters:
- Step 6 shows the question with its default beside **Use the defaults**, so the owner sees what is shared, and with which plan, before step 6 completes.
- REV-6's existing rule ("only where the owner allowed private data for that route") holds, because pressing the button is that allowance.
- Credentials stay excluded whatever the answer.

The two gaps are wording and a cross-row dependency (findings 1 and 2). Neither leaves the exposure unstated.

**Findings**
1. **release: the credential sentence is too absolute.** REV-6's "no setting sends them to any model or provider" and the question's "Passwords and keys are never shared" are both true as content rules. Read literally, they contradict the designed path, in which a provider's own credential reaches that provider's declared endpoints as authentication:
   - CRED-5: the broker-held Codex login is injected by the egress proxy.
   - CAP-9: the private-hosted key is "injected only there".
   - API keys reach their own provider the same way.

   Suggested wording, at the next SPEC touch or with the #1367/#1403 copy follow-up: "never sent to any model as content; a credential reaches only its own provider's declared endpoints, as authentication (CRED-5, ADP-10)". Keep the owner-facing line short, for example "Your passwords and keys are never shown to it."
2. **later: the Claude opt-in route inherits default-yes.** As written, the Claude plan route (worker-held, opt-in, D-114) also defaults private to yes. #1409 says Claude "gets only owner text plus cleared input". #1409 must state that exception in CAP-9 or §8.1, or the opt-in warning must cover private content, so the two rows do not conflict. This PR is correct to leave it out (#1409 is out of scope), but the dependency is not recorded anywhere yet.
3. **later: name the provider in the copy.** "Let this plan see your private content" does not say the content leaves the box for the provider's servers under the provider's terms. The plan name next to it implies that, which is adequate for the SPEC. For #1403 copy, prefer naming the provider ("Let ChatGPT see...").
4. **later: changelog order.** The changelog row for D-115 sits above the D-114 row (SPEC.md line 735). Newer entries go last, so move it below D-114.
5. **later: missing message id.** The D-115 row and record cite a message id only for 21:53:58Z. Add the 21:44:59Z message's id when it is available.

**Potency/UX.** Dropping the reserve question shortens first-run setup. One question with a sensible default suits a thin guest, as Mark intended. The reserve stays visible and editable per pool where the owner already looks (ONB-9).
