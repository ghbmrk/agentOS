## Security

Question: does the password value stay out of what an agent sees, by mechanism, when the page is hostile?

- **blocker (CRED-4, defect).** The decoy fix works only at column 0. `roleRE` is anchored `^- `, so on an indented line `nameEnd` returns 0 and the first `[ref=…]` token in the page-controlled name wins. Reproduced at the head: `  - textbox "foo [ref=e1]" [ref=e5]: hunter2` with refs `{e5}` comes back unchanged, so the value leaks. This is the same attack the commit claims to fix. Real aria snapshots nest by indentation [Inference: the spike's own tests use flat lines, so nothing in the repo shows a nested one]; any login form inside a list or form node is nested. Fix: accept leading whitespace in `roleRE`, and add the indented decoy lines to `TestCRED4PasswordValueOmittedDespiteDecoyRefInName`.
- Same blocker, second half: `nameEnd` fails open. An unterminated quote returns `len(line)`, no ref is found and the value passes (`- textbox "unterminated [ref=e1] [ref=e5]: hunter2` leaks). Fix: when the name cannot be parsed, treat the line as the password line if any ref token on it is in `refs`. Over-redacting a field whose name mentions a password ref costs nothing.
- **blocker (CRED-4, CRED-10; CLAUDE.md reuse rule).** `broker/browser` is on main (tier A, `Parse`, `NewOrigins`/`Declared`, the output filter, the gate). #211 adds a second `Parse`, origin check and `Request` type in `broker/browseract`, and its PR says "Reuse: None". Two parsers of one closed protocol can drift (this one already differs: it accepts a trailing `}`). It also puts tier-A protocol code under a tier-B path, so it gets a lighter review. Parse and origin code in `browseract` are not compared line by line with `broker/browser` here. Fix: drop the duplicate `Parse` and origin code and add `OmitValues` to `broker/browser` (tier A, which then needs the strongest model and a Security section), or state in the PR why reuse fails.
- release (CRED-4; invariant "a password value never reaches an agent"; failure path: the untrusted driver sends an empty or short `refs` set and `OmitValues` passes everything). Nothing in the Go code derives which refs are password fields; the spike does it in the driver from DOM attributes (RESULT.md finding 1). The broker must either get refs from a trusted source or treat textbox values as omitted by default. Fits the CRED-4b part 2 brief.
- later (`recheck`): `Parse` accepts a trailing `}` or `]` (reproduced on `{"v":0,"verb":"snapshot"}}`). Not a false pass for the returned `Request`, which comes from the first object. It becomes one if any caller forwards `raw`; `broker/browser` forwards a canonical re-encoding, so the duplicate is the only path.
- Pass: verb list and argument allow-list refuse evaluate, cookie, storage, header and extra arguments; refs must match the snapshot pattern; navigate refuses non-http(s) and userinfo, including the backslash-userinfo and backslash-host forms (Go's parser rejects both); `v` accepts only the number 0.
