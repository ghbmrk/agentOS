## Security

Question: does each protection hold by mechanism, with Invariant C and REV-2 intact?

- Pass (CH-14, CH-11, D-080): held text is never passed to a guest or model, is bounded by size (readback plus 2 `MORE` pages, 9 segments), and runs only on `RUN` except a lone inline-coded message. A spoofed `RUN` after an unlock can do only what a spoofed task message could in an unlocked session (CH-3), so `RUN` taking no code adds no path. A coded message is always kept, so a spoofer cannot displace it.
- Pass (CH-19, D-079): the pointer is sent only after the content is kept, CRED-7-redacted, and "could not be kept" is the fail-safe text; nothing leaks on a keep failure.
- Pass (CRED-2, CH-20, §11B, D-082): the trusted base now names the credential readers and says scanning is a tripwire, and summaries and hints are called bounded channels, not zero leakage. Claims shrink to what the mechanism gives.
- Pass (OSS-7, OSS-5, OSS-6, LOOP-0, UPD-4, D-088): the switch is local-UI only, never by text, never at setup; items made while it is off are never sent; the embargoed report and the `fast` attestation feed are gated on it; a new kind, field or option asks again. Default-off removes the exposure, so the Tor path need not run while off.
- **release (OSS-7, §11B principle; D-082).** The text bounds one channel (hints: 5 a day, about 57 bits), but OSS-7 opens three, and the cap does not cover hardware records or attestations. Failure path: attestation pass/fail is one bit per reproduced candidate with no daily count, so a compromised reproduction harness could carry more than 57 bits a day through the opt-in. Name a count bound for records and attestations or state them as unbounded in the consent screen. Fold into the D-088 release row with the PR's carried "consent screen states the record and attestation channel".
- later (recheck): CH-19 keeps results by time only (default 30 days) with no size bound. A runaway agent that emits outputs containing "code" could fill the store, after which legitimate pointers say "could not be kept". It fails safe (nothing leaks), and the existing disk quota may already cover it.

The offer to publish appears once, with examples drawn from the box's own log, and again only when something new would leave.
