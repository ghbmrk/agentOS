## Decision (c): lens view

Decision (c) asks whether the security notice only notifies or also pauses the route. It is not open: Mark ruled yes on 2026-10-09. That ruling is D-072, which sits on the unmerged branch `records/mark-rulings-2026-10-09`, and b6954ae implements it. What is still open is Mark's approval of the exact SPEC text. This lens recommends that the ruling stand.

- **UX:** a notice that only notifies relies on the owner reading a digest line and texting a pause. Owners on a pinned box (UPD-4) are the ones least likely to be watching for updates, so they would keep running a prohibited route. Pausing on arrival takes that step out of the owner's hands.
- **Potency:** the cost is that pinned boxes lose the plan route a release earlier than they would have. A prohibited route is lost either way. Work moves to the CAP-9 fallback, so it costs money but no capability. A forged or mistaken notice can only pause, which costs availability and grants no authority (the Security view at cb554f9).

## UX

Verdict: fix-list

1. **blocker (CRED-5, CH-12; defect).** The notice text contradicts the automatic pause.
   - **What it says.** The clause reads: "The same notice, naming how to pause the route, goes out as a security notice that pauses the route on arrival".
   - **Why that is a defect.** The notice is told to name how to pause a route that it has already paused. CH-12 says a problem text never suggests a step that cannot fix the cause.
   - **Class.** The builder and the coordinator recheck classed this as later. It is a blocker here because it is SPEC text inside a cited ID, it is a one-clause edit, and Mark has still to approve the exact text. Fixing it now means he approves wording that is consistent.
   - **Fix.** Drop "naming how to pause the route,". The sentence before it already makes the notice say which plan stopped, why, and what runs instead. If a phrase must stay, use "saying the route is paused".
2. **release (CRED-5c; spec gap).** CRED-5 does not say whether the owner can resume a route the notice paused.
   - **What the text says now.** The resume command covers three cases: a route the owner paused, one whose consent was withdrawn, and one whose login was refused. A route paused by the notice fits none of them. So it can be read as not resumable, but only by implication.
   - **Recommendation.** Say so explicitly. A route paused by the notice is withdrawn on that box, just as the release would withdraw it. It is not resumable by the owner, and its STATUS line says that only an update brings the plan back.
   - **Tradeoff.** Letting the owner resume it would mean the box knowingly runs a route the provider prohibits. That trades the owner's account risk for plan savings, which is a question for Mark and not something this lens decides.
   - **Where it belongs.** CRED-5c already names the resume command, so this fits there. It also links to LATER `CRED-5t-msg`, the "stays down until you change channel" line on a pinned box.
3. **release (CRED-5b; notice cadence).** A box that is not pinned will hear the same withdrawal twice: first from the security notice, then from the release.
   - **Risk.** As written, each could produce its own STATUS and digest line.
   - **Fix.** CRED-5b's notice item should treat them as one event per route and owner, so the release adds no second line when the notice has already told the owner. This sits with the item's existing rule of "one STATUS line plus one digest line per withdrawal".
