## 1. `-r` is unconditional

`_unshare_flags()` now returns `["-r", "-n", "-m"] + pid` with no euid branch. As real root, `unshare -r` maps the caller's uid 0 to 0 with a count of 1 (`0 0 1`). `-r` and `-m` are in one `unshare` call, so the user namespace is created first and owns the new mount, network and PID namespaces. `_inner`, strace and the scenario all run inside it. This is the same path CI's unprivileged `runner` already took at ac61b7c, so the sandbox's namespace layout in CI is unchanged.

## 2. The control is not vacuous and runs unskipped

- **Body.** `own-user-namespace` reads `/proc/self/uid_map`, sends the loopback datagram that `must_log` requires (so a body that never ran fails), and exits nonzero on an empty map or on exactly `0 0 4294967295`.
- **Mutation, local (real root, initial user namespace).** At 811b35f, `test_the_scenario_runs_in_its_own_user_namespace` and the ptrace-ancestors test pass. With `_unshare_flags()` reverted to the ac61b7c euid branch, the new test fails with `uid_map is '0 0 4294967295': the scenario runs in the initial user namespace`.
- **CI at 811b35f** (run 37890428886, dependency-audit job, success, read from the log tail): `PASS control-own-user-namespace control (pass; 1 socket events, 0 violation(s); 1 attempt(s) …)`, `PASS control-no-ptrace-ancestors …`, `PASS control-kept-read-only …`, `Ran 84 tests … OK` (83 at 8eff3cc plus the new test, none skipped).
- **Fails closed on a root run.** `cmd_run` runs every built-in control before the product targets, so a regression of `-r` on a root run fails that run, not just a test.

## 4. No init-namespace cap path remains; B1 still holds

- **Kept caps are scoped to the user namespace.** Every process from `unshare` down is in a non-initial user namespace, so `capable()` checks against the initial namespace fail for all of them. `open_by_handle_at` needs CAP_DAC_READ_SEARCH in the initial namespace or CAP_SYS_ADMIN over the mount, and the scenario has neither. CAP_SYS_MODULE and CAP_SYS_RAWIO are checked only in the initial namespace. A device node made under CAP_MKNOD in a user namespace is refused. The B2 routes are closed.
- **Kept DAC caps.** CAP_DAC_OVERRIDE and CAP_FOWNER still apply to inodes owned by mapped kuid 0. Those caps only matter on writable mounts; kept paths stay behind the `ro` binds, and SYS_ADMIN is still dropped. This is the same position CI was already in, not a new route.
- **B1 holds.** `DROP_CAPS` is unchanged. `_inner` and strace now hold CAP_SYS_ADMIN only in the sandbox's user namespace, not the initial one, so the ptrace prize is smaller than before. `cap_ptrace_access_check` and Yama still deny the attach, and `control-no-ptrace-ancestors` passes in CI and locally.
- **Nothing else changed.** No change to `TRACED`, the mounts, the evidence pipes or verdict logic.

## Findings

- **B2: closed.** Code, local mutation and CI evidence are in points 1, 2 and 4.
- **N1, release (into the existing DEP-3 row, no new row).** Two things for DEP-3's brief, neither a route today:
  - **The control checks "not the initial namespace", not "our own namespace".** Under a runtime that already puts the runner in a user namespace, it would pass without `-r`. Pinning the expected map shape (`0 <euid> 1`) makes it exact.
  - **The single-uid map limits DEP-3's own fix.** `-r` maps one uid, so DEP-3's plan to run the scenario under a uid distinct from `_inner` needs a wider map (`--map-users` and subordinate ids). Without one, the `setuid` fails.
  - **Why release, not later.** This is security hardening on a tier-A path (OPERATING §2), and DEP-3 rewrites this code anyway.
