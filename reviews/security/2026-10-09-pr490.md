## Controls fail closed

## Findings

1. **release** (CHG-2, A11) — **A raw leak of a held clause whose fields all appear in the visible test passes the audit, and the leak control would not notice.** The whole-clause match needs canonical layout; the field match skips any `path`, `pointer` or `value` the visible test has anywhere. Reproduced: visible `{/x le 1, /y le 2}` on one file, held `{"path": …, "pointer": "/x", "op": "le", "value": 2}` as the file's raw bytes: `clean=true`. The current catalog is unaffected (every held clause has a field the test lacks, and the control caught seed 0), but `validate` does not refuse such a seed and `leaking-adapter` runs only on the first valid seed. Proposal: run `leaking-adapter` on every valid seed, and either have `validate` refuse a held clause with no unshared field or match whole clauses against the record's compacted JSON too. UX cost none; potency cost a few ms per run. New BOARD row (next package touching `assurance/loop2`).
2. **release** (CHG-2, into P3-4b-5) — **Bare tokens followed by a full stop are missed.** `.` counts as a word character on both sides, so `confirm over 20.` and `keep /confirm_over_eur.` are `clean=true` (reproduced). No exposure today (the fixer gets structured `Finding` bytes, no prose), but H-4 carries these rules to P3-4b-5's prompt, which is prose. Proposal: P3-4b-5's audit treats a trailing `.` followed by space or end as a boundary (keeping `2.205` unmatched), with a test. UX cost none; potency cost none.
3. **later** — Element-level leaks of a held array value (`"search"` alone from `["pages","search"]`) and non-canonical JSON escapes (`\/`, `c`) are not detected; within H-4's documented limit (verbatim and canonical only). One LATER line.
