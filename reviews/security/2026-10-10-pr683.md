# Security 4a, PR #683 (CRED-4)

Record: PR #683 · package CRED-4b · head b6fa419

**Security section (stage 4a), tier A by path (`broker/browser/`).** Assigned at `3f5687d`; the PR moved to `b6fa419` (canonical-shape parsing, fail closed on every other line) before the review finished, so this record reviews `b6fa419` and covers `3f5687d` too. Supersedes nothing: #211 had no Security 4a.

**Threat check.** Adversary: the agent, which must never see a password value (CRED-4 "password fields omitted"); the page is untrusted and controls accessible names, placeholders and layout. Asset: a password held in a field of a logged-in browser (owner-entered, CH-8). Path: page → Playwright `_snapshotForAI` → driver → gate → agent. Today nothing reaches the agent through this path: the gate does not call `OmitValues` and part 1 holds no sessions (K2, K14). The review therefore asks whether `OmitValues`, once part 2 wires it as K14 requires, removes every copy of the value from a real snapshot.

**Method.** Real snapshots, not hand-written ones: Playwright 1.56.1 (`page._snapshotForAI()`, the `mode="ai"` form S5 uses) on headless Chromium, each page holding `<input type=password value=hunter2>` in one layout, then `OmitValues` with that input's ref, at `b6fa419`. `go vet` and `go test ./browser` pass on this head.

| Layout (real HTML) | Playwright output (abridged) | Value after `OmitValues` |
|---|---|---|
| `<label>Password <input type=password>` | `textbox "Password" [ref=e3]: hunter2` | omitted |
| decoy name `aria-label='x [ref=e1]: "y'` | `'textbox "x [ref=e1]: \"y" [ref=e7]': hunter2` | omitted |
| `aria-label="Password" placeholder="Enter password"` | `textbox "Password" [ref=e5]:` / `- /placeholder: Enter password` / `- text: hunter2` | **leaks** (child line) |
| input inside a table cell | `row "Pass hunter2"`, `cell "hunter2"` | **leaks** (ancestor names) |
| input inside `<a>` or `<button>` | `link "hunter2"`, `button "Show hunter2"` | **leaks** (ancestor name) |
| another element `aria-labelledby` the input | `button "hunter2"` | **leaks** (labelled element's name) |

Encodings: the field's own line is replaced from the ref to the end, so YAML quoting or JSON escaping of the value (`"hun\"ter: #2"`) does not matter there. Partial matches and split writes: `OmitValues` takes the whole snapshot and splits on `\n` only, so a CRLF snapshot works; a snapshot split on bare `\r` is driver-made, not page-made (Playwright escapes control characters in names and values), and falls under K14's untrusted driver.

**Findings**
1. **blocker** (CRED-4, defect): a password node with children keeps its value. A native password input whose placeholder differs from its accessible name renders the value as a child line, `- text: hunter2`, and `OmitValues` keeps every child line (it rewrites the head to `…[ref=e5]:`). This is the common "label plus placeholder" login form. LATER `CRED-4 l1` (added at `b6fa419`) classes it later on the premise that "a native password input has no children"; that premise is measured false above, so the LATER line should go and the fix land here. Fix: when a password ref's line ends with `:`, replace the value of every deeper-indented line under it (keep `/placeholder`), or drop those lines; test with the measured layout as a fixture.
2. **blocker** (CRED-4, defect): the value escapes through other elements' accessible names. The accessible-name computation includes an embedded control's value, so any ancestor named from content (row, cell, link, button, listitem) and any element `aria-labelledby` the field carries the password in its name, outside the field's own line. Fix: collect each omitted value (decoded from its YAML form), then replace every occurrence of it elsewhere in the snapshot in both the raw and the name-escaped form (`\"`, `\\`) and with whitespace collapsed as accname does, the way the vault's exact-value redactor treats a vault value; a short value over-redacts, which fails closed. Test with the four measured layouts.
3. **later** (no new row): a driver that splits lines on bare `\r` or reports no password refs defeats `OmitValues`; both are the untrusted-driver case already held by K14 (release).

S5's `protocol.py` `omit_values` has the same two gaps; K11's shared positive/negative corpus should carry these layouts so both sides are checked against one set.

Findings: blocker 2 (child-line value; value in other elements' names); release 0 new (K14 stands); later 1 (driver-made line splits, under K14).
