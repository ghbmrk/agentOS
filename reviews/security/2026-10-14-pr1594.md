## Threat check
Assets: deleted content (CAP-3 erasure), live notes, other items' text. Adversary: a fault after the rename (dir sync or reopen failure), a crash in that window, and a retry that filters on stale offsets.

- **Erasure.** `ErrReplaced` is returned only after the rename (`durable.WriteFile` yields `ErrDirSync` only after `rename`; reopen failure follows a completed write). The new file already lacks the deleted lines, and `rewriteSegs` keeps the segment in `unerased`, so prune refuses to drop tombstones until a clean retry (test: "repeatedly" subtests). A crash before the dir sync can restore the old file; the durable tombstone and `Open`'s erase remove it (R6, unchanged). Structural.
- **Cross-item disclosure through stale offsets.** On main a dir-sync failure left memory on old offsets over the new file. Reads were already guarded: `segment.go:147` rejects a line whose ID is not the entry's, so the old bug was loss, not disclosure. With this PR memory and the handle follow the new file; on a failed reopen `broken[n]` makes `ReadAt` and `Append` fail closed while `ReadSegment` (uncached) lets the retry run, and a successful retry clears `broken`.
- **Append cut-back path** (`segment.go:187`). An `ErrReplaced` there moves memory to the cut file, advances `active` and keeps the segment marked for erase. Lines memory never knew are gone from the live file; the crash case is R6's existing "loads as ingested" note. Not widened.
- **Seams.** `writeSegment`/`openSegment` are unexported package vars, swapped only in tests under `t.Cleanup`; no `t.Parallel` in the package. No production reach.
- **Data.** Canary `quokkacanary` is synthetic; no credentials or personal data.
