## Evidence

- [Fact] **Containment.** `--pid --fork --kill-child --mount-proc` makes `_inner` the namespace's PID 1; when it returns, or unshare is SIGKILLed (`--kill-child` → child dies), the kernel kills every process in the namespace, setsid or not. `_run_sandboxed` kills the session group before `wait()`, so the group ID cannot have been reused. `_mask_host_sockets` uses `/proc/<getpid()>/fd/…`; with `--mount-proc`, `getpid()` (1) and `/proc` agree. `sandbox_available()` probes the same flags, so a runner without PID namespaces fails with exit 2 (D2).
- [Fact] **Forging a fault cannot make a pass.** A scenario that prints `strace: …PTRACE_…` only gets `error` (and up to 3 runs); product scenarios must expect `pass`, controls have fixed expectations.
- [Fact] **Faults do not drop violations** (HK-1c): `carried` collects every faulted attempt's violations; a clean rerun becomes `violation`, three faults give `error` carrying all of them.
- [Fact] **Logs.** `detail` on a fault carries the scenario's stderr tail, the same data `stderr_tail` carried before. No new host data or secrets are exposed.
- [Fact, reproduced] **A traced process can erase its own trace.** `open`/`truncate` are not in `TRACED`, and `net.strace` and `stderr` sit in the work dir the scenario can find (`TMPDIR=<work>/tmp`). Locally: `strace -f -qq -e trace=connect -o tr -- python3 -c '…connect(("192.0.2.10",80)); open("tr","r+").truncate(0)'` leaves `tr` empty. Predates this PR.

## Threat check

Asset: DEP-2's guarantee that a shipped dependency does not phone home (detection in CI; the namespace blocks the call itself in the sandbox only). Adversary: **D**, a malicious or compromised dependency running inside a scenario.

| Path | Stop | Kind |
|---|---|---|
| D's child calls setsid() to outlive the run and write later | PID namespace kill | Structural (new) |
| D prints a fake strace fault | Outcome `error`, not `pass` | Structural |

| D truncates `net.strace` or rewrites `stderr` (untraced opens) | None | **Not stopped**, predates the PR: point 2 |

## Points

1. **blocker (HK-1b, defect)**: `STRACE_FAULT` is anchored at line start, so a fault that follows a partial line of scenario stderr reads as no fault. HK-1b says faulting is `error`, never `pass`. Fix: drop the anchor, e.g. `rb"strace: [^\n]*(?:Input/output error|PTRACE_)"`. Over-matching can only produce `error`. Add a test with a fault after a partial line, such as `b"partial" + b"strace: ptrace(PTRACE_LISTEN,pid:4,sig:0): Input/output error\n"` with exit 0, expected `error`. UX cost: none. Potency cost: none.
2. **release (new BOARD row, DEP-2)**: the evidence files can be edited from inside the sandbox. A traced process can truncate `net.strace` (reproduced above) or remove strace's fault line from `stderr`, and the audit then reads `pass`. Proposal: keep strace's trace and stderr out of reach of the scenario. Write the trace to a pipe or file descriptor owned by `_inner` (e.g. `-o /proc/self/fd/N`), or to a directory outside the sandbox's bind set; read strace's stderr through a pipe `_inner` holds; trace `open*`/`truncate`/`unlink*` on the work dir's evidence files as violations. UX cost: none. Potency cost: none (CI only).
3. **later**: `_scratch_dir` uses plain `shutil.rmtree`, which, unlike `TemporaryDirectory`, does not reset read-only permissions. A scenario that leaves a read-only tree (a Go module cache under `HOME=<work>/home`, e.g. a GOTOOLCHAIN download) would then fail cleanup with EACCES, as a non-root runner. The shipped scenarios do not do this today (CI green). Fix when touched: use `TemporaryDirectory(ignore_cleanup_errors=False)` semantics or an `onexc` that chmods, keeping the ENOTEMPTY retry.
