## 1. Blocker 4a: closed

- The scenario now runs as `strace … -- setpriv --bounding-set -sys_admin --inh-caps -sys_admin -- <cmd>` (`DROP_SYS_ADMIN`). On the setpriv exec, root's new permitted set is `bounding | (inheritable & fI)`; with sys_admin out of both, CAP_SYS_ADMIN is absent from permitted and effective; it is gone from bounding and inheritable by construction; ambient is cleared on a privileged exec and must stay a subset of inheritable. All five sets lack it, and no descendant can regain it (bounding is one-way).
- Other routes back to it: a nested user namespace gets `MNT_LOCK_READONLY` mounts (`lock_mnt_tree`) and cannot clear `ro`; a `mount(2)` remount is in `TRACED` and counted as a violation.
- `sandbox_available()` now requires `setpriv`; without it `depaudit run` prints `FAIL sandbox unavailable` instead of running unconfined.
- `tools/ASSUMPTIONS.md` D8 is corrected to match (the `ro` flag was not locked inside the sandbox's own mount namespace; the drop is what holds it).

## Threat check

Attacker: the audited dependency's install or test scenario running inside the sandbox, aiming to forge or hide evidence or write a kept path.
- Clear `ro` with `mount_setattr`/`open_tree_attr`: denied, CAP_SYS_ADMIN absent (point 1); exercised by the control.
- Remount via `mount(2)`: traced → violation.
- New user namespace: locked mounts.
- Borrow CAP_SYS_ADMIN from a more-privileged process: possible by inference via ptrace (finding R1).
- Run without the drop: fails loudly (`sandbox unavailable`).

## Findings

- **R1, release (fold into DEP-3).** The drop removes only sys_admin, so the scenario keeps CAP_SYS_PTRACE. `cap_ptrace_access_check` then lets it attach to `_inner` (PID 1 of the sandbox, which still holds CAP_SYS_ADMIN) or to strace, and inject `mount_setattr` to clear `ro` and rewrite a kept path. This is the D9 ptrace channel with a DEP-2b consequence. Fix: `--bounding-set -sys_admin,-sys_ptrace --inh-caps -sys_admin,-sys_ptrace`, which also denies the `/proc/1/fd` reopen (`ptrace_may_access` READ_FSCREDS) and narrows D9. Inferred from code; not reproduced here (the live probe was blocked by this environment's permission policy).
- **L1, later.** `open_tree_attr` (467) needs Linux 6.15+; on older CI kernels it returns ENOSYS, so only the `mount_setattr` half of the control bites there. setpriv still covers both.
- **L2, later.** No test covers the nested-userns claim in D8.
- **L3, later.** `probe =os.path.join(...)` spacing in `_control`.
