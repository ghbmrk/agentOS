## L6: setup's authority lives in agentosd, never in the page process

[Fact] As built in #189 (localui L26) and #367 (localui L28, `localsrv.Setup`):

1. `agentos-localui` holds no setup authority: no hooks, no store, no seed and no AP Wi-Fi password. Each setup op is a call over `localui.sock`, and agentosd treats the page process as compromised (L25).
2. agentosd serves setup's ops only in setup mode: no finish recorded in `-setup-record` and no owner-state file. Finish closes setup for good, across restarts. An unreadable record keeps setup closed. An owner-state file with no record is a hard failure.
3. Finish needs a code that agentosd saw confirmed from the newest seed, then the vault's seal (egress K17).
4. [Decision, new; not yet built] **Binding on every later setup op (c3, c4):** a new setup op is served by `localsrv.Setup` under conditions 2 and 3, as a fixed-shape request with fixed refusal codes. It is refused once setup is closed. Its effect runs in agentosd or a narrower process, never in the page.

## L7: the code seed is made in the vault and handed out once

[Fact] As built in #320 and #367. Egress K17 is the full statement and governs. This summary leaves nothing of it out on purpose:

1. **Made in the vault.** `POST /enroll` on `verify.sock` (agentosd only) puts a fresh 20-byte seed in the vault as `owner-totp-pending` and answers its `otpauth://` link once.
2. **Each link once.** Each enroll makes a new seed, so no seed goes out twice. A replaced seed no longer confirms. `POST /enroll` also deletes the confirmed marker, so a restarted setup's new pairing must confirm its own seed.
3. **Confirm.** `POST /enroll/confirm` takes one code. A match spends its step (the shared last step, egress K7), moves the seed to `owner-totp-seed`, writes the `owner-totp-confirmed` marker and deletes the pending copy. It does not seal. Wrong codes count with the channel's counted codes (`MaxWrongCounted` per `VerifyWindow`).
4. **Seal at finish only.** `POST /enroll/seal`, which agentosd calls at finish, works only while the confirmed marker is there and no pending seed is. It writes `owner-totp-enrolled` and deletes `owner-totp-setup-open` and the confirmed marker. The seal notifies the owner over the channel that earlier code generators stopped working.
5. **Closed by default.** Both enroll ops answer 410 unless the vault holds `owner-totp-setup-open`. Only `agentos-egress init -setup` writes it (the image's setup path, which prints no seed), and the seal deletes it. Boxes made by plain `init`, by REC-3's `recovery.ReEnroll`, or before c1 never open it, so a taken-over agentosd cannot swap the owner's seed for one it holds. Both entries are in the vault, so editing the drive's state file cannot reopen enrollment.
6. **The page keeps a "shown" flag and never a seed.** Setup's link is the only hand-out.
7. Accepted residual: during the setup window agentosd and the page see the seed while it is shown (lens bundle b). The window closes at finish's seal.

## L8: `agentos-netjoin` (proposed; binds P2-2w c3)

**Purpose.** On the image, joining a home network means writing a NetworkManager system connection (S7: NetworkManager runs the box's Wi-Fi). The right to do that would let a process rewrite or delete any connection. L8 keeps that right out of agentosd and out of the page process. It gives the right to a helper that can do exactly one thing.

**What the radio does.** [Fact] CH-7 keeps the box's access point up for the box's whole life, not only during setup: status, STOP, unlock and sign-in are served on it. So nothing takes the access point down at finish, and the home connection has to run beside it. That needs a second Wi-Fi device: either a station interface on the same radio, which needs the radio and driver to support an access point and a station at the same time, or a second adapter. [Inference] NetworkManager autoconnects a connection only on a device that is not already active, so the access point's own device never takes `agentos-home`. Making that station device is the image's job (P2-1, row P2-2w c3 r4): it is created at boot, before any helper runs. No component in this package holds `network-control`, takes the access point down or activates a connection. Until P2-1 shows a station device on the target hardware, the helper answers `saved` (condition 4), and the owner learns whether the box got online from setup's real progress (P2-2w c4, `Online`).

Conditions:

1. **Own user, no root.**
   - `agentos-netjoin` runs as a dedicated system user, from its own systemd unit.
   - The unit has an empty `CapabilityBoundingSet=` and no `AmbientCapabilities=`, `NoNewPrivileges=yes`, `RestrictAddressFamilies=AF_UNIX`, and `IPAddressDeny=any`.
   - The filesystem is read-only apart from the socket directory: `ProtectSystem=strict`, `ProtectHome=yes`, and one `ReadWritePaths=` (or `RuntimeDirectory=`) for the socket directory.
   - There is no `EnvironmentFile=` and no `Environment=` carrying input.
2. **Privilege through NetworkManager and polkit only.**
   - The helper talks to NetworkManager over the system D-Bus.
   - A polkit rule returns `polkit.Result.YES` only when `subject.user` is the helper's user and `action.id` is `org.freedesktop.NetworkManager.settings.modify.system`. Every other subject and action falls through (`polkit.Result.NOT_HANDLED`). So the helper gets no `network-control`, no `enable-disable-*` and no `wifi.share.*`.
   - The connection activates by autoconnect, never by an explicit activate call.
   - Residual: see "What a compromised helper reaches" below.
3. **One caller.**
   - The helper listens on one unix socket and serves only agentosd's uid, checked with `SO_PEERCRED` on each connection.
   - It refuses other peers before reading a request.
   - It caps request size, connections and idle time. It reuses `sockets.Server`, as `verify.sock` and `localui.sock` do.
4. **One op, one connection, found by a fixed UUID.**
   - The only request is `{ssid, psk}`. It writes the one fixed connection whose UUID is the constant `8907ba39-4053-4e84-9cbf-931587303e08` (id `agentos-home`).
   - It finds that connection with `Settings.GetConnectionByUuid`. It creates the connection with `Settings.AddConnection2` the first time, and changes it with `Settings.Connection.Update2` on that connection's path only after that.
   - It never calls `ListConnections`, and never calls `GetSettings`, `GetSecrets`, `ClearSecrets`, `Update`, `Update2` or `Delete` on any other connection path. It calls no method on a device and no activate or deactivate method.
   - Its only other reads are D-Bus property reads (`org.freedesktop.DBus.Properties`): NetworkManager's `ActiveConnections`, each active connection's `Uuid` and `State`, and the Wi-Fi devices' `DeviceType` and `State`. They are used to report the outcome.
   - **The settings are exactly this set and nothing else:**
     - `connection.type=802-11-wireless`
     - `connection.id=agentos-home`
     - `connection.uuid` = the constant
     - `connection.autoconnect=yes`
     - `802-11-wireless.mode=infrastructure`
     - `802-11-wireless.ssid` = the request's SSID
     - `802-11-wireless.hidden=no`
     - `802-11-wireless-security.key-mgmt=wpa-psk`
     - `802-11-wireless-security.psk` = the request's PSK
     - `802-11-wireless-security.psk-flags=0`
     - `ipv4.method=auto`
     - `ipv6.method=auto`
   - The caller can set nothing else: no DNS, address, route, interface, MAC, autoconnect priority, proxy, 802.1X or connection permissions. [Inference] `wpa-psk` joins WPA2 and WPA2/WPA3-transition networks, but not SAE-only ones (LATER P2-2w c3 f2). `hidden=no` means a network that does not broadcast its name is not joined (LATER P2-2w c3 f3). No interface name is set, so NetworkManager uses whichever free Wi-Fi device can take it.
   - **Answers are fixed codes**, decided within a fixed wait of at most 40 seconds after the write:
     - `joined`: an active connection with the fixed UUID reached `ACTIVATED`.
     - `not_joined`: an active connection with the fixed UUID appeared and then reached `DEACTIVATED` or went away (wrong password, or no such network in range).
     - `saved`: the connection was written, but no active connection with the fixed UUID appeared within the wait (no free Wi-Fi device to try it on). This is the answer whenever the join cannot be tested.
     - `refused`: the request failed condition 5 or was malformed. Nothing was written.
     - `busy`: another join is still running. The helper serves one join at a time.
     - `failed`: a D-Bus or NetworkManager error, including polkit refusing the write.
   - agentosd maps `joined` and `saved` to success for the page, and every other code to the page's one existing error ("Could not join that Wi-Fi. Check the password and try again."). agentosd's call timeout is longer than the helper's fixed wait.
5. **Input bounds, checked before any D-Bus call.**
   - SSID: 1 to 32 bytes.
   - PSK: 8 to 63 printable ASCII characters, or exactly 64 hex digits.
   - Anything else is refused. Neither value ever reaches a command line, an environment or a file the helper writes.
6. **The password is never logged or kept.**
   - The PSK goes only to NetworkManager, as a system-owned secret (`psk-flags=0`) in its root-only connection store.
   - It is not written to agentosd's state, the setup record, the journal, any log line, error text or crash output, in agentosd, the page or the helper.
   - Tests prove this with a synthetic canary.
   - [Open, for P2-1: row P2-2w c3 r3] whether NetworkManager's connection store sits on an encrypted volume. If it does not, a lost drive gives away the home Wi-Fi password, against CRED-8.
7. **Setup mode only.**
   - agentosd serves the page's join op only under L6 conditions 2 and 4, at most 6 tries a minute.
   - Once setup is closed it is refused, like every setup op.
   - Changing the home Wi-Fi after setup is not served. It is LATER P2-2w c3 f1 and needs its own owner authentication. If P2-1 chooses in-memory connections (row P2-2w c3 r3), agentosd's re-add at boot is a separate, non-page call, and this condition is amended to say so.
8. **Carry (accepted residuals).**
   - Before finish, the page process still sees the home password as the owner types it, as it sees every setup field (L28 carry). agentosd checks shape only.
   - [Inference] Anyone who has the box's access-point password (on the Owner Card) can, during setup, point the box at a network they control. The uplink carries only TLS-protected and signed traffic (updates and provider calls), so this gains them availability and traffic metadata, not custody. Because the home network cannot be changed after setup (LATER P2-2w c3 f1), such a join lasts past finish until a reset.

## What a compromised helper reaches (the polkit residual)

[Inference, to verify in c3] polkit cannot narrow `settings.modify.system` to one connection, so the narrowing to `agentos-home` is the helper's code. A process running as the helper's user can, through NetworkManager:

- rewrite the access point's connection: make it open, or change its password;
- add system connections with an attacker's DNS servers, routes or addresses;
- read the access point's password and the home PSK with `GetSecrets` ([Inference] NetworkManager gates secrets of system connections on the same action);
- delete any system connection, the access point's included.

This is accepted. It is still narrower than agentosd holding the right, and the helper's input is two bounded strings from one peer. A D-Bus busconfig policy that lets the helper's uid send only `AddConnection2`, `GetConnectionByUuid` and `Update2`, plus the property reads in condition 4, would take away the `GetSecrets` and `Delete` lines above. It would not take away rewriting the access point. That is row P2-2w c3 r1 (release).

Rejected alternatives (L3 on #422):

- `connection.permissions=user:<helper>` with only `settings.modify.own`: [Inference] such a connection is visible only to a user with a logind session, so it would not autoconnect on a headless box.
- A keyfile drop directory read by a root path unit: this moves the parse of attacker-shaped input into a root process, a wider surface.

## Threat check (L3 on #422)

| Adversary | Path | Stopped by |
|---|---|---|
| Compromised page (L25) | Calls the join op | L6.2 setup mode, 6 tries a minute, input bounds. Remaining: the page sees the PSK (L8.8). |
| Compromised page or another local uid | Dials the helper's socket | `SO_PEERCRED` uid check before any read. |
| Compromised agentosd | Asks the helper to join an attacker's network | Not stopped. agentosd already holds more than this. Availability only. |
| Holder of the access-point password | Points the box at their network before finish | Needs the card. Availability and traffic metadata, lasting until a reset (L8.8). |
| Compromised helper | The list above | Accepted residual; busconfig narrowing is row P2-2w c3 r1. |
| Any user with an active local session | `settings.modify.system` through NetworkManager's default `allow_active=yes` ([Inference]) | No seat or console session on the image: row P2-2w c3 r4. |

**Cost.** UX: none; the page and its wording are unchanged. A box whose radio cannot run a station beside the access point answers `saved`, and the owner learns about a bad password from setup's progress step instead of the network step. Potency: none in MVP; changing the home Wi-Fi after setup waits for the LATER row.
