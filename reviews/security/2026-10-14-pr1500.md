## Threat check
| Concern | Result | How |
|---|---|---|
| Measured size equals wire size | yes | `writeTree` measures the exact `[]byte` it writes (`encodeRPC` output, newline and echoed request ID included; the ID is capped by maxMCPBody). HTTP/1.1 runs over the unix socket with no content encoding, and chunked framing is removed before the LimitReader. |
| Off-by-one | correct | `len(b) > MaxTreeAnswer`: an answer of exactly the bound goes, one byte over is refused. The bridge's `LimitReader(MaxTreeAnswer)` reads the full bound. An answer whose only extra byte is the newline is refused, which is conservative. |
| Memory | no regression | The answer is built before the check, but its size is bounded upstream by agentosd's 4 MiB raw cap (at most about 7x after two encodings), and concurrency by MaxConns. |
| Log | clean | The log line carries the machine ID and the sizes, never the tree's content. |
| managed_tree by name | by design | The plane cannot tell the bridge from the agent (same socket; the bridge proxies the agent's /mcp). The agent gets only its own skills, liveTree.Call has no side effects, and REV-5 holds. This is the remedy #1488 L-1 chose. |
| Step note | correct | The note never rides on a tree answer, success or error, and still goes on every other tool result through `m.result` and `m.whole`. `TestATreePollLeavesTheStepNoteForTheAgent` shows the agent still gets it. |
| Fail-closed | yes | A refused or oversize answer is an `isError` result. The bridge keeps its version and directory, and nothing is mirrored. A cut-short body is a decode error, which also fails closed. |
| Races | none | `writeTree` touches no shared state, and `takeNote` is no longer called on this path. |
