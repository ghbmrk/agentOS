# Security lens: #1068, IMG-nodump (no core dumps, no swap), head 548908b

Record: PR #1068 · package IMG-nodump · head 548908b

Scope: the PR at 548908b. Tier A (`risk_tier.py`: image/). It closes S1 from #1060. The Owner Card passphrase is a Go string that cannot be zeroed (card C13), so neither a crash nor a swap-out may write the broker's memory to disk. `tests/test_image.py` passes, and the image builds and boot test are green.

Question: can any path still write agentosd's memory to disk?

Threat check:
- Core files: `kernel.core_pattern=|/usr/bin/false` makes the kernel pipe each dump to a helper that discards it, and a pipe pattern ignores `RLIMIT_CORE`. A unit that raises `LimitCORE` therefore still writes nothing. `DefaultLimitCORE=0` and `LimitCORE=0` on agentosd are extra layers on top. `fs.suid_dumpable=0` is set too. Mutants that drop each setting are killed.
- Overrides: `mkosi.finalize` works out the value systemd actually uses after reading every drop-in, with /etc taking precedence and the last value winning. A later sysctl file, a file of the same name in /etc, or a unit or manager drop-in that turns dumps back on each fails the build. systemd-coredump is not in `Packages=`. Even if it ships one day, its `50-coredump.conf` sorts before `99-agentos-nodump.conf` (tested).
- Swap: no swap-type partition (checked in repart and in the built partition table), no fstab swap line, no `.swap` unit, no zram generator and no swap file. `systemd.swap=0` means a swap partition added to the drive later is never activated. Hibernation has no target.
- Running box: `health` fails on any active swap or a non-discarding `core_pattern`, so a release that keeps dumps or swaps is never blessed. The CI boot shows `swap=off dumps=off`.
- Not covered, and not needed for HW-1 now: a root `swapon` after boot (root can already read the memory), and kdump. kdump has no package and no `crashkernel=` today, and nothing checks for it (LATER IMG-nodump l4, recheck). pstore holds only the kernel log.

Findings: blocker 0; release 0; later 0 (the L3's l1–l4 are filed as LATER IMG-nodump l1–l4).

Arbitration: no tension with Potency or UX.
