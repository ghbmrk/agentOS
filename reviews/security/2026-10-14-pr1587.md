- **Classification order.** `dispatchable` checks the fence before `duplicateOf`, so a fenced account always yields the plain `ErrUnreconciled` wrap, never a `HeldError`; a `HeldError` means no fence. `settingFailed` checks `HeldError` first because its `Is` matches `ErrUnreconciled` (engine.go:400). The mapping is exact both ways.
- **No disclosure.** Both replies are fixed constants; no error text, intent ID, account or address reaches the SMS. Error detail stays in `e.logf` as before (the `HeldError` text carries intent IDs only).
- **Who can see the distinction.** Held vs fenced is only revealed after the `unlocked` check (evidence.go:443); a sender without owner authentication still gets no reply. The owner already sees fenced intents on STATUS, so no new oracle.
- **Fail closed.** `settingFailed(nil)` (OFF with `err == nil` but a non-Succeeded state) returns the old generic refusal, never a success text.
- **Adversaries (run 1 model):** guest agent, spoofed SMS sender, hostile mail. None gains a path: the diff adds no input parsing, no effect and no destination.
