## Evidence

- [Fact] **The bound holds at every dispatch.** `Engine.Dispatch` reads `e.seq`, runs the policy check without the lock, and commits `dispatched` only if `e.seq` is unchanged; otherwise it checks again (up to 16 times, then `ErrBusy`, no dispatch). At `PhaseDispatch`, `matches` counts the other intents that are `in_flight` or `outcome_unknown` (any age) or `succeeded` with their latest dispatch in the window. So a rule-allowed effect starts only if fewer than `PerDay` (and `PerRecord`) started effects lie in the 24 h ending at that instant. Since a window's count only rises at a dispatch, no 24 h window holds more rule-allowed starts than the bound. The commit sits under the lock with the seq check, so nothing can dispatch between the count and the journal write.
- [Fact] **Past the bound at dispatch is a refusal.** The rule no longer matches, `evaluateEffect` returns `ask`, and `Check` with no held owner decision returns "needs the owner's approval"; the engine journals `recheck_failed` (Denied). Nothing at dispatch falls through to allow.
- [Fact] **Queue, resume, retry, restart.** A queued (`authorized`) intent holds a place at authorization whatever its age, so a STOP-held queue cannot grow past the bound; the rest are asked (ADP-9). `not_applied` and `denied` release; a retry is counted again at its own recheck. `dispatched` is set from the record's `At` in `apply`, so replay restores every place (OP-4); a crash after `dispatched` replays as `in_flight` → `outcome_unknown`, held until `Resolve` (OP-2).
- [Fact] **Splitting.** A `Rule` covers one `Action` on one account; places are counted per (account, action) across all rules, so two rules on the same operation share one count (conservative). Splitting across accounts needs a rule per account, each an owner grant (CH-3).
- [Fact] **Error paths.** `InUse` reads memory and cannot fail; a broken engine refuses every commit, so no dispatch follows a failed write. `DeliveryCap` uses the same `inUse`, filtered to evidence origin.
- [Fact] **Authorize is not serialized like dispatch.** `Authorize` drops the lock for the policy check and commits without a seq check, so two concurrent authorizations under a bound of 1 can both be authorized. The dispatch recheck then refuses the second (Denied, never asked). This fails closed, but GR7's new sentence "under a bound of 1 the second is asked" holds only for sequential authorizations: point 2.
- [Fact] **Erasure drops the record key.** `apply(RecErased)` sets `Params` to nil, so an erased `succeeded` intent still counts toward `PerDay` but no longer toward its record's `PerRecord`. Erasure is the owner's (recall's deletion reach, CAP-3), not a guest's. This predates the PR: `AuthorizedSince` returned the same erased intent. Point 3.
- [Fact] **Clock.** The engine stamps records with `time.Now().UTC()` and the gate uses `cfg.Now` (default `time.Now`). A forward jump ages `succeeded` places out early; a backward jump keeps them longer. Queued and unresolved places are now age-independent, so the clock exposure is smaller than before the PR. Neither guest nor agent sets the box clock; the HOST-1b guard covers that.

## Threat check

Assets: the owner's ADP-9 scope bounds (`PerDay`, `PerRecord`) and the evidence `DeliveryCap`, i.e. how many irreversible effects run unasked. Adversaries: **G**, a guest or agent submitting intents; **C**, a confused deputy (the broker itself across STOP, restart, retry).

| Path | Stop | Kind |
|---|---|---|
| G queues rule-matching intents across days under STOP, then the owner RESUMEs (F2) | Authorization counts queued places of any age; the rest are asked | Structural (new) |
| G races two dispatches for the last place | Seq-checked commit; the loser rechecks against the winner's start | Structural |
| G races two authorizations for the last place | Both may be authorized; the dispatch recheck refuses one | Structural, fails closed (point 2 is wording) |
| C crashes between the count and the `dispatched` write | Nothing dispatched; the intent stays authorized | Structural |

| G makes an attempt end not applied, then retries past a later send | Retry counts started effects at its own recheck | Structural |
| G leaves an attempt unknown so it ages out | Unknown holds a place at any age | Structural (new) |
| G splits across accounts or operations | One rule per (account, action), each an owner grant | Structural |

## Points

1. **release** (agrees with the PR's class). Mail `DailyLimit` (`broker/mail`, M8) still counts by authorization time through `AuthorizedSince`, and its in-memory `reserved` map is lost on restart, so an organize queue older than 24 h can run past 200 at RESUME. A queue can outlive the window behind an unreconciled-account fence or a duplicate hold too, not only STOP. Release is the right class, not blocker: organize is a reversible verb (ADP-2, undo window), the bound is a guard on mass reversible change rather than the gate on an irreversible effect, and the mail adapter is not wired on main. It should not be later: unattended organize on a real mailbox will rely on it, and the fix (count with `Engine.InUse`) now exists. No BOARD row exists yet on the head; the coordinator should register one and make mail wiring for unattended organize depend on it.
2. **later.** GR7 ("Concurrent intents fail closed: each one's authorize check counts the others already queued or started, so under a bound of 1 the second is asked") overstates: concurrent `Authorize` calls are not seq-checked, so both can be authorized and the second is refused at dispatch, not asked (evidence above). Behaviour is safe. Fix the wording the next time GR7 changes, e.g. "…so under a bound of 1 the second is asked, or, if both are authorized at once, refused at the recheck".
3. **later.** An erased intent's record key is gone, so it stops counting toward `PerRecord` (`PerDay` still holds). Count an erased intent in the window against every record (conservative), or keep the record key among the fields erasure keeps (CAP-3, A12). Predates this PR; owner-triggered.
