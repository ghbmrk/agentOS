## Threat check

Adversaries: a hostile guest, a hostile or tampered corpus or harness output, a local process on the host. Assets: the integrity of the Loop 2 finding chain (a probe finding closes only on a clean run of its own subject, S24), pauses of grants and executors, the daemon's environment and credentials, ARC-2's process boundary.

### ARC-2 (os/exec reach)

- [Fact] `probecmd` imports `os/exec`; `loops` and `corpus` import neither `os/exec` nor `probecmd` (`loops` reaches it only from `probecmd_test.go`, an external test package). `go list -deps ./cmd/agentosd` contains neither `probecmd` nor `broker/corpus`; no `escapeOK` entry is added (`daemon/inference_test.go` is not in the diff), so linking `probecmd` into the daemon fails `TestARC2ControlPathCannotReachInference` until a reviewed entry exists. S28 and BOARD row P3-4b-4c say the same.

### Command construction (`probecmd.CommandProbe`)

- [Fact] argv only, no shell: `exec.CommandContext(ctx, Cmd[0], Cmd[1:]..., "--out", <path>)`. `Cmd` is daemon configuration; the only appended value is a path under a fresh `os.MkdirTemp` (0700). No corpus text or guest data reaches argv. Stdout and stderr are discarded; the output file is read with a 1 MiB cap, `DisallowUnknownFields`, and must name the probe's own check; a nonzero exit, a timeout, a missing or malformed file or an `errors` entry is an error, so the run closes nothing (fails closed, S26).
- [Fact] **The timeout kills only the direct child.** Reproduced: `Cmd = sh -c "sleep 4242 & wait"`, `Timeout = 1s`: `Run` returns `context deadline exceeded`, and the `sleep` is still alive afterwards. For `canary.py round` that leaves its target (`go test ./e2e`) running past the bound and overlapping the next round (finding 1).
- [Fact] `cmd.Env` is nil, so the harness inherits the daemon's whole environment, and `canary.py run_target` passes `os.environ` on to each target. Not live (S28: not wired). Second occurrence of #523 finding 3 (finding 2).

### Findings from probes (`Report`, `runProbe`)

- [Fact] `Guard.Report` has no caller outside `loops`; no guest, socket or local API path reaches it. `reportable` takes `canary`/`corpus` without a rule only with a subject; a probe finding's `Contain` is limited to grant/executor and is counted against `MaxPausesPerDay`. A probe cannot report another check's finding (`runProbe` rejects it as an error). Owner text passes subject and detail through `safeName`.
- [Fact] Closure needs a whole clean run: any error from `Run`, from a `Report`, or a foreign check sets `failed`, and then nothing is closed. Only open, reported, rule-less findings of the probe's own check whose subject is in `Checked` and not found again are closed; a probe finding that carries a rule is never closed by a probe.
- [Fact] **#523 kind (a), a never-run replay counted as passed: not present.** `CorpusProbe` adds an item to `Checked` only after every check ran on it, and returns an error (no `Checked`) on cancellation or a check that misses its bare payload. `canary.py round` adds a target to `checked` only after `run_target` returned a non-error outcome, and checks no product target when a control fails; an empty registry checks nothing.
- [Fact] **#523 kind (b), a verdict from guest-supplied rows: not present.** The corpus probe calls the closed checks' functions directly (S27); no guest is involved. A canary verdict is the host harness's scan of the target's stdout, stderr and surface directory; the A14 target's surface includes broker-side journal and meter state, and an empty surface or missing ack is an error. The guest in that target is a scripted test rig, not a production guest. Wiring a production guest into a round (P3-4b-4b/4c) must keep the verdict broker-side.
- [Fact] A target whose round has both hits and an error is reported as an error only, so its leak never becomes a finding; the owner sees "leak tests, failed" in STATUS and the digest each time, so it is not silent (finding 5).
- [Fact] `loops`, `probecmd` and `corpus` are tier B, yet `runProbe` decides closure and `probecmd`'s parse decides what is reported and paused. Second occurrence of #523 finding 5 (finding 4).

## Findings

1. **release** (LOOP-7, S26; defect) — **A probe's timeout leaves its grandchildren running.** `broker/probecmd/command.go` `Run` kills only `cmd.Process`. Fix: `cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}` and `cmd.Cancel = func() error { return syscall.Kill(-cmd.Process.Pid, syscall.SIGKILL) }`, with a test that a backgrounded grandchild is gone after the timeout. Belongs to P3-4b-4c (wiring); small enough to fold into this PR if the builder prefers. UX cost none; potency cost none.
2. **release** (LOOP-7, S28; recurring kind) — **Child processes inherit the daemon's environment.** `CommandProbe` leaves `cmd.Env` nil; `canary.py` hands `os.environ` to targets. Fix in P3-4b-4c: an explicit minimal environment (`PATH`, `HOME`, `TMPDIR`, plus what a target needs by name). Second PR with this kind (#523 finding 3), so per CLAUDE.md the next package touching the area (P3-4b-4c) adds a check: a broker test, next to the ARC-2 AST walk in `daemon/inference_test.go`, that fails when non-test broker code builds an `exec.Cmd` in a function that never assigns its `Env`; listed under "Checks that replaced findings" once merged. UX cost none; potency cost none.
3. **release** (LOOP-7, D-067) — **The corpus is not verified when the broker loads it.** Fix in P3-4b-4c: `//go:embed` `items.json` in `broker/corpus` so no drive file is read (the signed binary is the digest), or pin its SHA-256 in the binary and refuse a mismatch in `LoadCorpus`. UX cost none; potency cost none.
4. **release** (LOOP-9, OPERATING §3; recurring kind) — **Code that decides finding closure sits outside tier A.** `loops` (now `runProbe`), `probecmd` and `corpus` are tier B, so a later delta to them gets no Security re-sign. Second PR with this kind (#523 finding 5, `loop7`). Fix: add `loops`, `probecmd`, `corpus` (and `loop7` if it keeps `Resolve`) to `TIER_A_BROKER` with `tests/test_risk_tier.py` pins, in the next package touching them (P3-4b-4b). Stricter of release/later chosen because it is the second occurrence. UX cost none; potency cost none.
5. **release** (LOOP-7, A5) — **A leak in an errored round is not reported.** `tools/canary.py cmd_round` drops a target's hits when the same target also errored (`outcome` "error" wins). Fix: when `kinds_hit` is non-empty, emit the finding as well as the error (the run still closes nothing). Fold into P3-4b-4b or 4c. UX cost none; potency cost none.
