## What changes for an attacker
Before this PR, a hostile or compromised mail host could end the vault process. A malformed response such as a bare `* 1 FETCH` panics in go-imap's reader goroutine, where no recover runs, and the owner then has to unlock the vault again (CRED-8). `broker/go.mod` now replaces go-imap v1.2.1 with an in-repo copy, `broker/third_party/go-imap`. Its `Client.reader` recovers the panic, closes the connection and ends, so the in-flight command fails with `errClosed` and mail.sock answers `failed`.

| Path | Stop | How |
|---|---|---|
| A server response panics a response handler on the reader goroutine | structural | The `recover` in `reader` covers parsing and every handler. With upstream `client.go` overlaid, T1 and mailsock T3 fail with `index out of range [1] with length 1`; with the patch they pass. |
| A partial FETCH result is used after the guarded panic | structural, unchanged | `imapsmtp.fetch` returns the messages it has so far together with the error, but `mailsock.answer` replaces the whole reply with an error code whenever err != nil. Only mailsock consumes `imapsmtp.Store` (egress `mailaccount.go`). |
| A command is reported successful after the guarded panic | structural | `defer`s run in LIFO order: the recover closes the conn first, then `close(loggedOut)` runs, so `execute` returns `errClosed`. A command whose tagged OK was already delivered really did complete on the server. |
| Stale mailbox or UIDVALIDITY state is reused | structural, unchanged | `session` dials a new client for each call, and `selectAt` checks validity in that same session. |
| Server bytes reach logs | structural | The recover logs fixed text without the panic value, and `ErrorLog` is `quiet{}` once `client.New` returns. |
| The handler lock is left held after the panic | partly | `handlersLocker` is now released by `defer`. `c.locker` is still held if the panic happens inside its critical section (point 3). |
| A fatal runtime error from the server's bytes (stack overflow, out of memory) | none | `recover` cannot catch these. Unbounded `(` nesting recurses in `ReadFields`/`ReadList` (point 1). |
| Supply chain: the fork differs from upstream in ways the record does not show | structural, verified here | See Runs below. LICENSE is identical to upstream's. |
| ARC-2 | structural, unchanged | The PR adds no imports. The daemon ARC-2 tests and `TestDaemonAndVaultProcessLinkNoScanner` pass. |

## Findings
1. **blocker** (CRED-8, defect). egress K18, mail M20, agentosd MW8 ("Closed") and `PATCH.md` claim a hostile server's bytes "cost one call, never the process". A deeply nested FETCH response (about 5 MB) still ends the vault through a fatal stack overflow. `MaxLiteralSize` is unset, so a `{4294967295}` literal is allocated up front without any bound. Fix in this PR: scope the text to panics, name these residuals, and point to the release issue from point 2.
2. **release** (CRED-8 / K18). Bound parse depth and literal size on the IMAP read path, either by patching the fork's `read.go` or with a bounding conn. Failure path: a hostile or compromised mail host answers a UID FETCH with deep nesting, the vault exits, and the owner has to unlock again.
3. **release** (K18 "costs one call"). After a SELECT fails, the server sends the tagged NO and then `* n EXISTS` (or `RECENT`). If the caller sets `c.mailbox = nil` between the reader's `Mailbox()` check and `c.locker.Lock()`, the reader dereferences nil while holding `c.locker`. The guard recovers, but `c.locker` stays held, so the session's deferred `Logout` blocks in `State()` forever and the `ServeConn` goroutine and the mail.sock conn leak with no answer. This is a narrow race, reasoned from the code and not reproduced. Upstream the same race crashed the process; with the guard it hangs. Fix: skip `Logout` once `c.LoggedOut()` is closed, or defer the unlock in those handlers.
4. **later** (wording). No test fails when the `handle` `defer` edit is reverted, and the reason M20 and `PATCH.md` give for it is inaccurate. Keep the defer as a defensive change and correct the reason.
5. **later** `recheck` (tooling). `tools/risk_tier.py` classes `broker/third_party/` as tier B, while `broker/vendor/` is tier A, and no CI step checks `vendor/` against `go mod vendor`. A change to third_party alone drifts unnoticed; it does not reach the binary, because builds use `vendor/`. Suggested fix: add the prefix to the tier-A list and add a vendor-drift step.
