Threat check. The adversary is a guest or hostile device on the box's Wi-Fi (the CH-9 subnet), a cross-site page open in the owner's phone browser, or a phone whose session is stale or locked. The questions are whether any of them can read the task list, submit a forget, forget without the owner's code, or get task words into logs.

## Facts

- [Fact] **Reach and sign-in (CH-7, CH-8).** `/forget/` is registered with `Mount`, so it sits behind `signedIn`. That check asks agentosd (`OpSession`) on every request. Below it, both new socket ops (`page_forget_tasks`, `page_forget`) check the token again with `liveStatus`. A missing token, an expired session, or a session minted under an earlier lock count (#444's LocalSignIn lock and wrong-code locks raise `Locks`) is deleted and refused `unauthorized`. An unsigned guest gets a redirect to `/unlock` and no list. The CH-9 subnet check, the Host check against DNS rebinding, `Cache-Control: no-store`, the CSP and `X-Frame-Options: DENY` all apply to the new page from `ServeHTTP` unchanged.
- [Fact] **One read of lock and unlock (SR3-1).** `liveStatus` takes a single `Owner.LocalStatus()`. It checks the session's lock generation against that snapshot and hands the same snapshot's `Unlocked` to `ForgetTasks` and `Forget`. A lock that lands between two reads therefore cannot pair an old session with "unlocked". Mutant: passing a second `LocalStatus().Unlocked` read to `Forget` fails `TestAForgetOpReadsTheLockAndTheUnlockTogether`, so the mutant is killed.
- [Fact] **Same unlock signal as `Text` (brief work 4).** `LocalStatus().Unlocked` and the owner channel's `unlocked` (the value `Settings`/`Text` receives) are both `codes.unlocked(now)` under `Channel.mu`. A session that is signed in but whose unlock has since lapsed (no lock, so the session stays live) gets `Locked: true` and an empty list, and `PageForget` refuses with fixed text. Mutant: removing `!unlocked` in `PageForget` fails `TestALockedSessionListsNothingAndAsksNothing`, so the mutant is killed.
- [Fact] **CSRF and origin.** Every POST passes through `sameOrigin` in `ServeHTTP`, which checks `Sec-Fetch-Site` and `Origin`. Cookies are SameSite=Strict. `/forget/ask` is wrapped in `s.post`, which allows POST only and caps the body at 16 KiB. A GET or HEAD to `/forget/` only lists, and a GET to `/forget/ask` gets 405. The form also carries `forgetToken = HMAC(formKey, "forget"‖session key‖goal)`, compared with `hmac.Equal`, under a domain label kept apart from `formToken` and `resumeToken`. A form lifted from one phone, or minted for a different goal, is stale on any other session. Tests cover a cross-site POST, a signed-out POST, and a GET.
- [Fact] **No new forget path (CAP-3).** `PageForget` takes `f.mu` and then calls FORGET's own `ask`, so it has no direct route to `forgetTask`. It asks only for a goal that `tasks.recent(forgetList)` returns under that lock, which is the set a texted `FORGET` lists. `ask` submits and authorizes a Pending intent: the owner must approve it with a code before `Execute` runs. The page answers only "Asked…", never "forgotten". `TestAPageAskIsOneRequestAndForgetsOnlyOnceApproved` drives the route through approval and confirms the owed entry is saved before the tombstone, and that a failed save texts "Not forgotten".
- [Fact] **Replay and races.** Replaying a captured form within the same session submits one more owner request. The effect is the same as texting `FORGET n` twice: nothing is deleted without a code, and an approved second request finds the goal gone. Across sessions or after sign-out the token no longer matches. `ask`'s `seq++` runs under `f.mu` on both paths. `TestPageAndTextAsksRunConcurrently` passes under `-race` with distinct intent IDs. Lock order is unchanged: `f.mu` is held across the gate calls exactly as `Text` holds it, and `Item` (the gate's callback) takes no `f.mu`.
- [Fact] **What the list exposes.** Each task is listed by goal ID, date, and `shown(t, true)`, the same label a texted `FORGET` shows. That is the clipped words for an SMS task, "(a task, when)" otherwise (security C2), and runs of 4 or more digits become `####`. The label is rendered through `html/template` inside `<bdi>`. Nothing is shown before sign-in or while the session is locked. No new log line carries a goal ID or task words; `ask` logs only gate errors, as before. Both `TestThePageLogsNoTaskWords` and `TestTheForgetPageLogsNoTaskWords` assert that a synthetic canary never reaches the log.
- [Fact] **W3-forget-b4 (#528, merged).** #528 changes `Execute`, `retry` and the owed file. This PR adds only new methods and calls `ask`, and #528 changes neither `ask` nor `recent`. A page ask therefore reaches #528's owed order through `Execute`, like any other ask.
- [Fact] **Merge resolution at 0227eae** (`git show --remerge-diff 0227eae`). The resolution keeps `OpSIM` alongside `OpForgetTasks` and `OpForget` in `Ops`, and `AdoptSIM` alongside the forget config fields. In the op table, `OpForgetTasks` moves from `s.authed(...)` to its own `liveStatus` check. It also introduces `liveStatus` so that `live` keeps its old behaviour for #444's ops. The resolution drops no auth check.
- [Fact] **Pending merge of main (#528, #523).** A trial merge of origin/main (cd82296) into 0227eae conflicts in BOARD.md and `main.go:622`. Resolving it with both lines, `caps.learning(lp)` followed by `lp.forgetOwner.wirePage(&cfg)`, builds and passes `go vet` and `go test -race -count=1` on `./cmd/agentosd ./localsrv ./localui ./localapi ./daemon` (go1.26.8). `go test -race -count=30 -run 'Owed|Forget|Page' ./cmd/agentosd` also passes, so the `forget_owed_test.go:110` flake that L3 noted did not reproduce on the merged tree.
- [Fact] The tests use synthetic goals and texts only; there are no credentials or personal data.

## Points

1. **later.** `localapi.ForgetTask.Date` crosses the socket, but the page never renders it. The label already carries the time, so the field is a dead copy of task metadata. Drop it or show it. This matches L3 point 1 on #534, so no new LATER line is added.
2. **later.** Re-posting the same form (a double tap, or back and resubmit) submits a second owner request for the same goal. It is harmless, since the owner needs a code for each request, but the owner gets a duplicate request. Texting `FORGET n` twice already has this behaviour. A later page package could show "already asked" for a goal with a Pending forget.

No blockers and no release points.
