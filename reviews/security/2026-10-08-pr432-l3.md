## Blockers from the previous fix-list

**1. Requeue before quarantine: resolved.**
- `openStore` now returns damaged artifacts still in place. `New` runs `rebuild` and then `quarantine`. `finish` runs `renew` and then `quarantine`, and `settle` no longer quarantines.
- Mutation checks, each run on the head with only the fix reverted:
  - Swapping the order in `New` fails `TestQuarantineCrashAtOpenKeepsJob` and `TestRepairsAreBounded`.
  - Swapping the order in `finish` fails `TestQuarantineCrashInFinishKeepsJob`.
- Crash windows, checked with reviewer probes that were run and not committed:
  - **Between renew and the rename, at the bound, three times in a row:** each crash leaves the queue entry with its attempts spent and no copy added. The fourth open then logs `failed`, starts no machine, and leaves exactly `maxRepairs`+1 copies. The step is idempotent, and repeating the crash neither adds nor loses anything.
  - **After the rename and before `.quarantine` is synced:** on reopen there is one queued entry and one copy, and the job is rebuilt to the same artifact ID.
  - **New repair entry:** `rebuild` creates `repair-<job>/`, `writeJSON` syncs the file and its directory, and then the queue directory is synced. The entry is therefore durable before the rename, across both directories.

**2. The bound holds across restarts: resolved.**
- `renew` counts `.quarantine/<id>-<12 hex>` copies, and the `Repairs` field is gone.
- Forcing `n < maxRepairs` true fails `TestRepairsAreBounded`, and so does making `losses` return 0. That test runs damage, reopen and run for `maxRepairs`+1 cycles.
- Ways the count could be fooled:
  - **Name collisions:** job IDs are fixed-length 12-hex `newID` values, and a copy's name is matched by exact prefix `<id>-` plus `^[0-9a-f]{12}$`. A probe placed `<id>-zz`, `<id>x-<hex>`, `<id>-<hex>-<hex>` and uppercase hex in `.quarantine`. None of them counted.
  - **Two copies with the same random suffix:** a 48-bit collision makes the rename fail, which fails closed.
  - **A missing directory** counts as 0, which is correct for a first loss. A `.quarantine` that is a file makes `New` fail, which fails closed.
  - **Pruning:** nothing in the package removes `.quarantine` entries today. The `.stage-*` glob and the dot-skip in `openStore` leave it alone. Point 1 below records the constraint this places on any future pruning.

## Threat check (tier A)

| Adversary | What was checked | Result |
|---|---|---|
| Hostile clean-room guest | Controls result bytes and paths | Holds. The broker hashes the bytes it writes itself, so the guest cannot cause a mismatch, a quarantine or a repair loop. The new code changes nothing on this surface. |
| Malicious hint source | Schema values only | Holds. A repaired entry's hint is re-checked by `parseCanonical` in `runJob`. A new matching hint after the bound is a new job under normal intake limits, not a way around the bound. |
| Storage loss or crash | Every step between renew, rename and the syncs | Holds (above). A job is never silently lost, and rebuilds are bounded at `maxRepairs` per artifact ID across restarts. |
| Actor who can write broker state | Deleting or planting entries in `.quarantine` | Out of model: this actor can already edit the queue. Planted foreign names do not count, and a malformed directory fails closed. |
| Concurrent intake | `quarantine` now takes `s.mu`. Between `renew` and `quarantine`, a `Send` can coalesce into the still-listed artifact. | Holds. Below the bound the rebuild yields the same artifact ID. At the bound, the effect is the existing loss of work, which fails closed. |

Damaged output is never served or published. `ReadFile` stays hash-checked on nested paths (`TestNestedReadStaysFailClosed`).
