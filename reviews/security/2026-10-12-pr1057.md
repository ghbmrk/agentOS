# Security lens: #1057, SIM-split-b (CH-4 checker), head b3d3ef5

Record: PR #1057 · package SIM-split · head b3d3ef5

Scope: the PR at b3d3ef5 (second SIM-split PR). Tier A (`risk_tier.py`: new core `checker` and `procguard`, new wiring `cmd/agentos-checker`, holder, sockets, core.txt). `go test -race` on go1.26.8 passes for `./checker ./procguard ./holder ./sockets ./cmd/agentos-checker ./cmd/agentos-holder ./core ./daemon ./egress`. Nothing constructs a checker in production yet: wiring is SIM-split-wire, so the broker still verifies codes as before.

Question: can a high-risk act get a login without an owner code the checker verified for that exact request?

Threat check:
- Replay and expiry: `Redeem` deletes the approval before checking expiry, so an approval spends once; approvals expire after 15 minutes and live in memory only (restart drops them, fail closed). Mutants dropping the delete or the expiry check are killed.
- Forgery: approvals come only from `Verify` on a matching TOTP after `max(after, last spent step)`; the step is written durably before approvals are recorded. Mutants that approve on a wrong code, ignore the durable step, skip the state write or drop the pause are killed.
- Binding: `Act` is SHA-256 over length-prefixed host, method, escaped wire path and body; the holder computes it from `a.Host`, `op.Method`, `r.URL.EscapedPath()` and the bytes it forwards, matching the upstream URL. Mutants dropping body, method, host or the length prefixes are killed. Not bound: the account (S1) and the forwarded headers (later).
- Isolation and IPC: three sockets with separate `SO_PEERCRED` allow-lists (`sockets.ListenPeers`; admit-any mutant killed); the binary refuses one uid on two sides and running as any peer uid (mutants killed for both binaries); `PR_SET_DUMPABLE 0` is set before any listener opens and before a seed or login can arrive (mutant killed). No socket reads the seed back; the state file holds only the last step.
- Fail closed: no checker configured refuses every non-read; redeem transport error gives 503 `unapproved`; draft, organize and unknown verbs stay refused (mutants killed). The daemon inference import check (`daemon/inference_test.go`) is unchanged and passes; `procguard` sits outside `sockets` so agentosd links no prctl.
- Secrets: tests use random seeds and `example.invalid` canaries; no log line carries a code, seed or login.

C-5 decision: not a blocker. CH-4 codes are time-bound by SPEC; CH-10 lets one code cover a batch. Today the broker alone verifies and acts, so moving verification out narrows trust (a compromised egress or holder can no longer act without a code) and leaves the broker's content-substitution power where it was. The PR states the gap; the paper grid closes it.

Findings:
- **S1 release** (CH-10, acceptance "an approval covers one exact request once"). Failure path: two accounts at one provider host both run holders; a compromised egress takes the owner's approval for account A's send and forwards the same bytes to account B's holder, which redeems it, since `Act` names no account and every holder uid shares `redeem.sock`. Folded into SIM-split-fix item 3.
- **S2 release** (CH-10 fail closed). Failure path: `Redeemer` mapping an unexpected status (400, 500) to approved passes CI (mutant survives); the code is correct today. Folded into SIM-split-fix item 4.
- **Later**, in LATER.md: forwarded headers not in the act (SIM-split-b l1, `recheck`); fixed 15-minute TTL vs the owner-set CH-10 lifetime (l2); `procguard` is Linux-only while its test is untagged (l3).

Findings: blocker 0; release 2 (SIM-split-fix items 3-4); later 3.

Arbitration: no tension with Potency or UX.
