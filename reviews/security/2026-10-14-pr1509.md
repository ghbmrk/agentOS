## Bypass analysis

- Module naming and compression: every in-tree HCI driver (drivers/bluetooth, toshiba_bluetooth, btrsi) depends on `net/bluetooth/bluetooth.ko`. mkosi adds a dependency back, and the case-insensitive `bluetooth` pattern always matches that path, whatever the suffix (.ko, .ko.xz, .ko.zst). A renamed or DKMS BT module outside these paths (probe: `updates/dkms/hci_uart.ko.zst`, `drivers/net/foo/btintel.ko` not matched by name) still drags bluetooth.ko in, so the module gate is complete while CONFIG_BT=m (Debian). Aliases: `modules.alias` names btusb, but there is no file to load.
- Firmware: only MediaTek BT_RAM_CODE, Realtek rtl_bt, Intel ibt-, Broadcom .hcd are matched. QCA, TI, Atheros ar3k, NXP and MediaTek mt7622/mt7668 BT firmware are not (probe). It is inert without bluetooth.ko, but I20 overclaims (R3).
- Units, daemons: `bluetooth` matches bluetooth.service, bluetoothd, udev rules. Only the two exact `bluetooth.target` paths are allowed (an /etc copy fails). btattach/hciattach are not matched but are useless without hci_uart + bluetooth.ko.
- Other initrds: the entry's `initrd` lines are all checked, and the ESP allowlist forbids any other file. Type #1 entries take no addons.
- Main image: out of scope here. It still carries every BT module. Only btusb and btmtk are blocked (I20, #1450), which covers the RZ616 (USB BT).
- Parser fail-closed probes: unknown leading bytes, bzip2, junk after a raw cpio, a truncated cpio, a missing trailer and a bad magic all raise. gzip followed by a raw cpio raises (BadGzipFile). **xz followed by a raw cpio, or by junk, passes, and the appended archive is never listed** (R1). zstd was not probed locally (no zstd binary; host left unchanged). The zstd CLI rejects unknown trailing data.

## Findings

- R1 (release): `cpio_names` ignores data after an xz segment (Python's `lzma.decompress` drops trailing non-xz data). The kernel's initramfs unpacker continues after a compressed segment, so an archive appended there would boot unchecked. It is not reachable with the pinned mkosi (zstd initrds), but it is a fail-open in a fail-closed check.
- R2 (release): I20 step (1) and the #1113 comment say to check "at rd.break". The default initrd is systemd 257 (mkosi-initrd), which ignores dracut's `rd.break`. v257's debug-generator has no `systemd.break=` (checked in source). Forcing emergency mode reboots by the image's own emergency.service credential drop-in. So the initrd-stage check cannot be run as written.
- R3 (release): I20 says the build fails on "any Bluetooth ... firmware". The patterns cover MediaTek, Intel, Realtek and Broadcom only.
