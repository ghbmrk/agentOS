**Threat check.** Assets: owner STOP (CH-2), broker memory under an untrusted guest, OP-1 idempotency, CAP-3 erasure, grants and scope bounds. Adversaries: a hostile or looping guest that controls `request_id`, `action` and params; a crash or a failed journal read; a false pass.

| Path | Stopped | How |
|---|---|---|
| Guest re-enters a denied id to get a fresh decision | structurally | `Submit` checks `intents`, then `cold`, before any commit; an evicted id answers idempotent or `ErrConflict`. A 128-bit id or fingerprint-prefix collision reads as the old denial (fails closed) and costs about 2^64 hashes |
| Detached cold entry is committed | structurally | state checks return `ErrState`; `validate` refuses records for ids not in `intents` |
| Guest stalls STOP through journal reads | structurally | guest-reachable `Get` and `Submit` never read the journal (`TestSIMBoundEvictedLookupsReadNoJournal`); journal reads are owner-only (`SIM-bound l1`) |
| Guest grows broker memory | reduced, not bounded | 36 B plus one interned shape per evicted denial; a guest-chosen `action` mints about 0.5 KiB per denial. Linear and rate-limited (`SubmitBurst`/`SubmitEvery`), far below main |
| Scope bounds or grants rebuilt from a smaller view | structurally | `InUse` counts authorized and started intents, which are never evicted; `grants.Attach` gets no grants from a failed `Trail` (fails closed) |
| Erasure of an evicted denial (CAP-3) | structurally | `Erase` rehydrates and pins; `rewriteErased`/`unerased` read the erased set from the journal; a failed read there returns an error |
| Recall deletion reads as complete after a failed read | not at all, fault-only | `Between` falls back to memory when `ReadAll` fails, so evicted denials miss `Erase(ids)` while the rewrite's read succeeds. No adversary can induce it (host-side journal; a full disk fails appends, not reads) |
| False pass | structurally | `readCounter` wraps the store's only read method; L3 showed the zero-read test cannot pass on 95e6438 |
