## Round 1 at 2cc2101 (request changes)

Head 2cc2101d652f38b5c6cfe06845b3de1ce2f50af2 on base dfabba435ae0b6c81d4c865bc96f94211d450c45.

### What changes for an attacker
This PR is the first time the image puts a radio on the air.

`agentos-ap.service` runs as root at boot after the inbound drop. It does the following:
- brings every phy80211 interface down through `APLoader.Start`
- reads the page's card latch and agentosd's `owner.json`
- serves the seller's sticker network on wlan0 at 10.42.0.1/24, using hostapd (WPA3-SAE, MFP required) and dnsmasq (DNS answers every name with the box)
- burns the setup file instead if the card is confirmed or the box is owned

The PR also enables the modem bridge and the netjoin helper. The bridge parses texts from any sender. The helper has a polkit grant for NetworkManager, which is absent from the image.

### Findings
- **B1, blocker** (HW-10, CH-7, D-112, D-105). The sticker network is served past the Owner Card confirm and past ownership until the loader restarts. On an always-on box that can be indefinite. It widens D-105's accepted residual ("until the confirm") and CH-7's "claim and setup pages only".
  - Fix: watch the latch and owner state while serving, then Down and burn.
  - Test: confirm or own during serving, and assert Stop ran and the file is empty.
- **R1, release** (ARC-1, CRED-1). The ap unit and its root hostapd, which is pre-auth over-the-air attack surface, need:
  - DevicePolicy=closed with only /dev/rfkill
  - ProtectKernelTunables
  - write access narrowed to the setup file's directory
  - InaccessiblePaths for the vault state
  - RestrictNamespaces, ProtectProc and PrivateIPC
  - no CAP_DAC_OVERRIDE
- **R2, release** (privacy, I16). Add `logger_syslog=0` and `logger_stdout=0` to HostapdConf.
- **R3, release**. Add tests that kill M7 (loader Up is SAE only) and M13 (an Lstat error counts as owned).
- **R4, release** (DEV-net-h b, #936). Station joins through netjoin bypass `APLoader.Station`. This must be mediated before NetworkManager ships.
- **R5, release** (#1385 family). A page-forged `card_confirmed:true` burns the setup network, which is a DoS. Move the confirm witness with #1385's fix.

## Delta round at 1af4001 (accept)

Head 1af40016ee08edb2d38f8b772ffbf72bfc4deb40 on base 075eb0ec720215ca15cbd1f4d53eda8e50d70cc5. Reviewed fix commit 454e5708; merge 1af40016 has an empty `--remerge-diff`. 0 blockers, 2 new release findings, 2 carried release items.

### The earlier findings
- **S-B1 (blocker): fixed.** I found no race, and no path where the AP stays up or comes back after the burn.
  - While serving, the loader re-reads the latch and owner state every `-poll` (2 s).
  - At the confirm or at ownership, `firstboot.SetupNetwork` burns through `downFirst`, whose `Save` runs `l.Down` before the file store's `Save`.
  - `Down` holds the loader's lock. `Hostapd.teardown` waits for each child to exit (SIGTERM, then SIGKILL) and returns an error if one does not. In that case `Save` never runs, so the file is never emptied while hostapd is alive.
  - A failed `Down` or a failed burn fails the run. `Restart=always` then re-enters at the start-time check, which burns before any `Up`. So a burn that keeps failing keeps the radio down; it never serves.
  - After a burn the run idles and does not return, so the unit does not restart it. The only `Up` needs a non-nil network, which needs the latch unconfirmed, the box not owned and the file non-empty. Once the file is empty, no latch content brings the AP back.
  - The file can also be emptied by something other than the loader's burn (`Begin` in agentos-localui burns on a confirmed latch). That case still runs `Down` through the `n == nil && !down` branch, but no test covers it (S-D2).
  - The test records the setup file's size at each `Stop` and asserts it was non-zero at the first one. That pins down-before-burn.
- **Forgery: the page cannot forge state to keep the AP up past ownership.**
  - `owner.json` is root's, its `Lstat` cannot be steered by the page uid, and ownership skips parsing the latch.
  - A latch that is a link, a FIFO, oversized or unparsable makes the poll fail. The run then brings the AP down and exits, and the restart serves nothing. `O_NONBLOCK` means a FIFO cannot stall the poll loop.
  - Mutant M37, a latch read error treated as "no latch", also leaves the AP down: the start serves nothing and the poll returns n == nil and runs Down. So it fails closed too.
  - What remains is the known page-written confirm (S-R5, #1385). A page that writes the latch can revert or withhold the confirm, but it decided the confirm in the first place.
- **"An owner state the loader can't read counts as owned": right.**
  - The only errors other than not-exist (ENOTDIR, EACCES, EIO) come from root-side faults, and the loader also holds CAP_DAC_READ_SEARCH.
  - So the page cannot use this to keep the network up. Failing closed burns the file, which costs at worst a re-seal on a broken root filesystem.
  - Failing open would keep the sticker password on air on a box whose ownership can't be checked.
  - Mutant M13/M19 (`owned := err == nil`) is now killed through ENOTDIR. The EACCES case only runs when the tests are not root.
- **P-1 (late radio): the wait loops cleanly.**
  - `waitForIface` lists `/sys/class/net` once per `-poll` using `select` on `ctx.Done()` and `time.After(c.Poll)`, so it does not busy-spin at the default.
  - `down` grows only by distinct interface names.
  - Two edge cases are not security findings and are left to Potency (later):
    - `-poll` ≤ 0 is not refused. With it, `time.After(0)` spins and `time.NewTicker` panics. Only the unit file sets this flag, and it doesn't set it.
    - A radio that appears after serving begins is not brought down. A new netdev starts down and nothing in the image brings it up.
- **S-R1 (hardening): the new settings are real, a test pins each one (a mutant dropping it is killed), and DevicePolicy works.**
  - The changes: CAP_DAC_OVERRIDE gone, `DevicePolicy=closed` with `DeviceAllow=/dev/rfkill rw`, ProtectKernelTunables, RestrictNamespaces, `ProtectProc=invisible`, PrivateIPC, and the vault and egress hidden.
  - From the hostapd 2.11 source:
    - hostapd opens `/dev/rfkill` O_RDONLY, and if the open fails it logs "RFKILL status not available" and carries on (driver_nl80211.c, rfkill.c). So a `/dev/rfkill` that is missing when the unit starts doesn't break bring-up.
    - hostapd writes `/proc/sys` only for bridge, proxy ARP and DGAF filters, and this config uses none of them.
    - nft, ip and systemctl use netlink and D-Bus and need no device node.
  - The write set is still a denylist: see S-D1.
- **S-R2: `logger_syslog=0` and `logger_stdout=0` do not break AP-ENABLED. Not a G1 blocker.** Traced through the hostapd 2.11 source:
  - AP-ENABLED is `wpa_msg(..., MSG_INFO, AP_EVENT_ENABLED)` (src/ap/hostapd.c).
  - `wpa_msg` calls `wpa_printf(level, …)` (src/utils/wpa_debug.c).
  - `wpa_printf` `vprintf`s to stdout when `level >= wpa_debug_level`. That level defaults to MSG_INFO, and `wpa_debug_syslog` defaults to 0 unless `-s` is passed. The loader runs `hostapd <conf>` with no `-s`, `-q` or `-f`.
  - `logger_syslog` and `logger_stdout` gate only `hostapd_logger_cb` (hostapd/main.c), the module logger that `hostapd_logger()` feeds.
  - So `Hostapd.start` still reads AP-ENABLED from the stdout pipe.
  - The remaining MAC-bearing lines (`AP-STA-CONNECTED <mac>` via `wpa_msg`) also go to that pipe, which is drained unread. Nothing reaches the journal.
  - The I16 hardware check is still worth running on #1113.
- **S-R3: fixed.** M7 (loader Up with WPA2) is killed by `TestServesWPA3Only`. M13 is killed as above.

### Findings
- **S-D1 (release; ARC-1, CRED-1; residual of S-R1).** The pre-auth-reachable root hostapd can still write agentosd's owner records.
  - `ReadWritePaths=/var/lib/agentos` plus a 13-entry `InaccessiblePaths` denylist leaves these writable:
    - `setup.json`: setup's record of the owner's number. Writing it before setup finishes lets an attacker plant their own number as the owner.
    - `owner.json`, `meter.json`, `spare-meter.json`, `clock.json`, `guest-inbox.json`, `kept-replies.json` and `digest`.
    - any state file added later.
  - Only 2 of the 13 hidden paths are pinned (M27 and M28 survive).
  - It takes a hostapd RCE from radio range, and it is narrower than at 2cc2101, so it is release rather than blocker.
  - Done when one of the following holds:
    - The setup file moves into its own directory and that directory is the only `ReadWritePaths`.
    - Or the burn truncates in place with fsync, and `ReadWritePaths` names the file alone.
    - Or, preferred, hostapd runs as its own user with ambient NET_ADMIN and NET_RAW.
  - In each case the test pins the write set as an allowlist.
- **S-D2 (release; CTRL-claim-ap).** Two fail-closed `Down`s in the new serving loop are untested (M21 and M22 survive).
  - **Emptied underneath.** The setup file is emptied by something else while serving, for example `Begin` on a confirmed latch. Then `SetupNetwork` returns nil without calling `Save`, and only the `n == nil && !down` branch takes the AP off the air. Without that branch the sticker network stays up indefinitely.
  - **Poll error.** The latch turns unparsable, or the setup file corrupt, mid-serve. The run should bring the AP down before it fails, and not leave `agentos-ap-exempt@wlan0` and the address up until the restart.
  - Done when a test covers each case and asserts Stop ran: an emptied file means Stop ran and the run idles; a garbage latch means Stop ran and the run returns an error.
- **Carried (release; filed at merge, see Filed):**
  - S-R4: netjoin station joins bypass `APLoader.Station`, before NetworkManager ships (#936).
  - S-R5: the page-written confirm witness; comment on #1385.
