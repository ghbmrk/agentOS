## Evidence

- [Fact] **No outside path to `Report`.** It has no caller outside tests; the daemon wires only `FixturesLiveFor` (`loop2Live`). Nothing on a socket or the local API reaches it.
- [Fact] **The fixer cannot widen its own grading.** `Guard.fix` overwrites `Source`, `Origin`, `Public` and `Finding` after `Fixer.Fix` returns. Security cases live in pipeline state, not in the tree, so no candidate edit can add, edit, delete or relink one; `suites/`, `graders/`, `policy/`, `security/` are governance and `checks/`, `grants/` authority, forbidden by `classify`. Any other proposer setting `Finding` only moves that finding's linked cases from PS1's "open" to "must pass", so it can only tighten.
- [Fact] **Linked cases cannot be dodged by making them unevaluable.** In `evaluate`, a linked case the candidate side declines is counted as a fail before the PS1 branch, and the frozen set carries every security case regardless of class (`freezeLocked`). A preempted, held candidate is re-graded against the cases linked at the time of the next `Propose`.
- [Fact] **The suite only grows, crash or not.** `addCase` saves or rolls back; `SecurityCount` is checked across the A11 and LOOP-10 tests; `Loop2Passed` is persisted, so once the active tree passes a linked case a later change that re-breaks it is a regression.
- [Fact] **Tree rules are closed and deterministic.** `ParseTreeRule` rejects extra keys and unknown fields, `valid` rejects unknown ops, and `holds` re-validates each clause; `AnswerTreeRule` answers from the tree passed in, with no machine or model.
- [Fact] **No secret or personal data reaches owner text or logs.** The new owner strings are fixed wording plus `safeName(Subject)`; regression bytes go to the evidence store only; error strings carry check, kind and severity names.

## Points

1. **blocker** (LOOP-9, LOOP-10 "reduces coverage"; brief-gap: the code follows the brief's definition of 1-minimal). `Minimize` keeps removing clauses while the rest still fails, so a test with two failing clauses is cut to one of them. Reproduced: rule {padding, padding, `/private` subset `["local"]`, `/fallback` absent} on the defective seed tree minimizes to `/fallback` absent alone; the candidate `{"private":["local","cloud"],"name":"r"}` (removes the fallback, still lets private work use the cloud route) is adopted, the finding closes as fixed, and the finding's own test still fails on the active tree. A finding is marked fixed without a fix to what it reported, and the permanent regression covers less than the finding did. Proposal: the regression keeps every clause that fails on the defective tree, dropping only the clauses that hold there (unique, deterministic, and dropping any kept clause loses a failure); or add one 1-minimal case per failing clause, all linked to the finding. Add a test with two failing clauses. UX cost: none. Potency cost: none.
2. **blocker** (LOOP-9, LOOP-10; defect). A reported finding's request is opened (`Fix` pending) even when its regression case was never added: `AddSecurityCase` failed, or the check's fixtures are deferred because `FixturesLiveFor` lacks it. The fix candidate then has no linked case, `Linked == 0` passes the new check, and any candidate that keeps the held-out suite qualifies. Reproduced: with `AddSecurityCase` failing once ("disk full"), a candidate that only edits `skills/greet` is adopted, the finding is closed and cleared, and the active tree is still the defective one. Proposal: in `proposeInner`, reject a candidate with `Finding` set and `Linked == 0` ("no security case is linked to the finding"); in `handle`, do not record `FixPending` for a reported finding until its case is in the suite, and retry the add on the next `Pass` (`ErrDuplicate` already makes it idempotent). UX cost: none. Potency cost: none.
3. **release** (LOOP-9). `handle` saves the record (`Reported`, `Fix` empty, no fixture) before adding the case; `Report` saves again only at its end, after the owner text. A crash in between leaves a record no path advances: `Pass` skips reported records, `retry` is false for an empty `Fix`, STATUS and the digest say nothing, and a second `Report` of the same finding returns the stale open record. Reproduced by restarting from the first save. The target stays paused, so this fails closed, but the fix request and possibly the owner's text are lost. Proposal: `Report` and `Pass` resume an open reported record whose case or request is missing (add the case, open the request, send a text not yet sent). Fold into the fix for point 2. UX cost: none. Potency cost: none.
4. **release** (CHG-2; pre-existing, not in this diff). `Guard.fix` stamps four fields but keeps the fixer's `Goals` and `Claim`. A fixer that sets `Goals` ties the fix's adoption to an owner goal, so forgetting that goal undoes the fix through `ForgetGoal`. Harmless with today's scripted fixers; it matters once P3-4b-5's model-backed fixer answers the request. Proposal: loop 2 clears `Goals` and `Claim` along with the fields it already stamps; put it in P3-4b-5's acceptance. UX cost: none. Potency cost: none.
5. **later** (LOOP-10 (c), (e)). `loopKeys` lists exact paths that no tree file or reader uses yet. When a reader of `config/loops.json` or `config/loop2.json` lands, it should read exactly those paths and keys, with a test tying the list to the reader, so a renamed key cannot slip past the list.
