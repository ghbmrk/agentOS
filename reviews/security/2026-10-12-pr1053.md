# Security lens: #1053, SIM-split-a (key holders), head 54bbace

Record: PR #1053 · package SIM-split · head 54bbace

Scope: the PR at 54bbace (first of two SIM-split PRs; the CH-4 checker and CH-10 are PR 2). Tier A (`risk_tier.py`: vault, egress, core.txt, new core `holder`, new wiring `cmd/agentos-holder`). `go test -race` on go1.26.8 passes for `./holder/... ./cmd/agentos-holder/... ./vault/... ./core/... ./egress/...`. Production code does not yet construct `Holders`, `Redaction` or a `HashRedactor` (grep of non-test code), so nothing here changes what runs today: the vault still lives in `agentos-egress` (H-1).

Question: can a login leave its account's holder, or can a request outside the declared shape get one?

Threat check:
- Key custody per account: `holder.New` refuses adapters with different credentials, so one process keeps one login; `Hand` copies and zeroes the previous value; the hand socket has `GET /state` and `PUT /secret` only, neither reads the secret back. Pass. Mutation: dropping the holder's own redaction makes `TestEgressHoldsNoLoginAcrossProcesses` fail (the `/proc/self/mem` scan of egress finds the login), and its control must match, so the scan is not vacuous.
- IPC: `Listen` admits one peer uid by `SO_PEERCRED` and closes others unread (mutant killed by `TestHandAdmitsOnlyItsUID`); the binary refuses equal request and hand uids and a run dir not owned by its uid. Provider answers cannot forge `Agentos-Holder-Drop` or `-Error`: the holder forwards only declared headers, and `forbiddenHeader` now rejects any declared `agentos` header.
- What the holder refuses: unknown host, query string, undeclared method/path, any verb but read, undeclared request header or non-identity encoding, an oversize body, no secret held (503), an encoded response, a netguard-denied destination. Mutants on the header, verb and no-secret checks are killed; the query-string check survives its mutant (R4).
- Failure modes: holder down or restarted empty fails closed (503 / unreachable) until the keeper re-hands; an unswappable exchange stops the route (`TestHolderDropStopsTheRoute`, mutant killed); egress refuses `Vault` beside holders and an adapter without a holder (mutants killed).
- Egress redaction (CRED-7): `HashRedactor` keeps HMAC-SHA-256 of head and tail windows plus the whole form, behind a secret-base rolling prefilter; streaming is split-independent (`TestHashStreamingAtEverySplit`); mutants removing the whole-form or tail match are killed.

H-4 decision: not a blocker. The hash redactor is an oracle by construction (egress must be able to test spans), so moving the key would not help; it meets CRED-7 as the brief specifies, and it is not wired, so no live path exposes a short secret today (the plaintext vault in egress is strictly more exposure). It is a tier-A security finding, so `release`, not `later` (OPERATING §2).

Findings:
- **R1 release** (H-4). Invariant: SIM-check's predicate "no secret appears in any process except its account's holder" (briefs/SIM.md SIM-split item 3) and the SIM-split acceptance "egress memory holds only keyed hashes of it, never the value". Failure path: once production wiring hands egress a `HashRedactor` over a vault holding a short or user-chosen value (a mail or SIP password), a compromised egress runs `Redact` over a dictionary and recovers it. Settle before the production-wiring row lands (an entropy floor for values hashed in egress, or a DECISIONS row accepting it per value class).
- **R2 release** (H-3). Invariant: ADP-10 at the holder (acceptance "a request the holder's shape rejects never gets a login"). Failure path: a compromised egress sends `chat.completions` with `mcp_servers` or `web_search_options`; the holder injects the owner's key and the provider fetches from a guest-chosen address. The holder re-applies the op's `BodyRule`.
- **R3 release**. Invariant: SIM-split acceptance "readable only in its account's holder (checked by process)". Failure path: a unit that runs the holder under egress's uid lets egress read `/proc/<holder>/mem`. The binary refuses running as `-request-uid` and sets itself non-dumpable.
- **R4 release**. Invariant: ADP-10 at the holder. Failure path: dropping `r.URL.RawQuery != ""` passes CI (mutant survives), and a compromised egress then adds query parameters to a declared op with the login. Add the test.
- Builder's release rows 1-5 (production wiring, mail/SMS/SIP holders, refreshed-token persistence, SIM-check predicate, PR 2 checker) stand; H-7 (no compute-host pins in the holder's netguard) joins row 1.
- **Later**, in LATER.md: `Hand` zeroes the old secret while an in-flight request may read it (rotation race; the keeper hands only to an empty holder); holder peer-uid tests carry no ARC-1 marker; the `agentos` forbidden-header rule has no test.

Findings: blocker 0; release 4 (R1-R4, one follow-up brief with builder rows 1-5); later 3.
