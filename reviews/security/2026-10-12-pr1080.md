# Security lens: #1080, CTRL-claim-wire (claim wired into first boot; owner reserve; reinstall route), head fea0207

Record: PR #1080 · package CTRL-claim-wire · head fea0207

Scope: the PR at fea0207. Tier A (claim, firstboot, localui, cmd/agentosd, tools/risk_tier). `go test -race -count=1 ./claim ./firstboot ./localui ./cmd/agentosd` passes on go1.26.8. The L3 verdict is PR comment 6122674748.

Question: can a client without the sticker claim the box, lock the owner out or reach setup, and can losing or forging state route a box wrongly?

Threat check:
- Admission: `/claim` sits behind the AP-subnet, Host and same-origin checks. A foreign Host never reaches the counter, which is tested through agentosd.
- Lockout denial (R3): codes that do not match the 40-bit prefix go to the shared count only, so a client without the sticker cannot spend the owner's per-boot reserve of 3. The reserve is counted under the mutex, saved before the answer and fail-closed.
- Offline: the prefix verifier splits the 80-bit code into two independently searchable 40-bit halves (about 2^41 SHA-256 from a disk read). That breaks claim K2. Blocker B1.
- R4 marker: it is written only after a sealed `claim.Open`, before anything is shown, and it survives the confirm. Forging or deleting it needs partition write access, and that attacker already wins. Losing both files resets the unconfirmed vault.
- Reinstall route: no claimant, no card, Hold refuses, no vault reset. Tested.
- Mutants: 11 tried, 10 killed. M9 (the reserve never refills on a new boot) survived. Blocker B2.
- Secrets in tests: per-run codes only. The journal holds counts, and a test checks that it holds no prefix.

Findings:
- **B1 blocker** (HW-10 R3, claim K2). The full prefix hash is stored, so the code falls offline in about 2^41. Store a 2-byte tag instead, test its length, and correct K9 and K2.
- **B2 blocker** (HW-10 R3). The reserve refill on a new boot is untested. Assert `Reserve == ReserveTries` after the boot changes.
- **B3 blocker** (HW-10 R4). The reinstall page also says "Setup continues on the phone that claimed me". It should say only "already claimed, reinstall me".
- **Later l1**: routes outside setup are not claim-gated. They are inert without an owner, and test 1 does not sweep them.

Findings: blocker 3; release 0; later 1.

Arbitration: no tension with Potency or UX (B3 is shared with UX).
