## Threat check (a stale or concurrent session must not act under a lock it no longer holds)

Asset: the page session token, and code-free RESUME through it. Generation = `State.Locks`, raised under `c.mu` by every lock (`codes.lock` for `RequireUnlock`, the `WrongToLock` crossing in `checkStrong`).

- **Sign-in overlapped by a lock (F1).** Stopped. `LocalSignIn` reads `UnlockedUntil` and `Locks` in the critical section that accepted the code, before the texts go out, and `signIn` mints with that count, not a later `LocalStatus()`. A lock during the texts makes `live()` drop the token on first use.
- **Code-free RESUME racing a lock.** Stopped at the commit point: `LocalResume(locks)` compares under `c.mu`, which also covers the stop/resume itself, so no lock can land between the check and the commit.
- **Refresh RESUME (stale session plus code) overlapped by a lock.** Stopped. A lock during the refresh's texts leaves the returned count equal to the session's, so the commit-point check is what refuses it. A lock before the code is checked is refused twice: once by the new `locks != ses.locks` branch, and again by the commit-point check.
- **The count is recaptured anywhere.** No. The only reads after the critical section are `live()`'s check, which can only kill sessions, and `LocalStatus` for display.
- **A dead token revived.** No. Every refusal drops the session (`drop`). `refresh` only touches a session still in the map, and `live()` re-checks the count on each use.
- **Other tokened ops.** Read ops check only at the token check, which leaves a window of microseconds of read access. Approving takes its own fresh code. Deny only narrows. Follow and ask-resume only open a request that needs a code. This matches the builder's LATER SR3-1 f1, and I agree it is later.
- **Authority.** Unchanged. There is no new op, input or code path. A refresh code accepted under a later count still unlocks the owner session (the O4 local unlock, texted to the owner) but mints nothing. A fresh sign-in would have the same effect.

## Points

1. **later (test coverage): the refresh branch's count check (`localsrv.go` resume, `case locks != ses.locks`) has no test that fails without it.** With it disabled, the commit-point check in `LocalResume` still refuses and drops the session, so nothing is exposed. The branch is defence in depth that no test covers. Either add a test where the lock lands before the refresh code is checked, or drop the branch.
2. **later (agree, no new row): LATER SR3-1 f1 and f2 as the builder recorded them.** Deny, follow and ask-resume gain no authority from the race. An overlapped sign-in returning a dead token costs only a round trip.
