## Round 1 at bfe2b94 (fix-list)

### What changes for an attacker
Setup's AI step is now live on a deployed box. The page lists the vault's built-in providers (OpenAI, Anthropic) through agentosd. It stores an API key in the vault and records the owner's private-data answer as a `private-ok-<adapter>` marker entry. The model router reads that marker on every private call (`route.Config.PrivateAllowed`). Device-code sign-in is still not served (c4e2).

| Path | Stop | How |
|---|---|---|
| Key in logs, errors or answers | structural | `localapi.APIKey` and `modelroute.SetupKeyRequest` both redact in `String`/`GoString`. agentosd and the vault process return fixed errors, the list carries only `connected`, and no code on the path logs. |
| Key overwrites seed, recovery or card entries | structural | `setupKey` uses `putKeyLocked`, the code `put` uses: adapter credential names only, never over another kind. |
| Key injected elsewhere | structural, unchanged | It is stored as `KindAPIKey`, and `apiKeysOnly` injects it only into the adapter's declared endpoints. |
| Provider ops after finish | structural | `localsrv.Setup.open` answers setup closed. The vault's `setupOpen` gives 503 locked, 410 sealed and 412 never opened (K17). Both mutations are killed. |
| Another uid drives the ops | structural, unchanged | `verify.sock` takes agentosd only, and `localui.sock` takes the page uid only. |
| Key before card or claim | structural, unchanged | The page's `aiReady` comes after Host, which comes after Recovery and the card hold, so the key lands in the card's vault (K21) and never in a setup vault that `setup.key` can open. |
| Header injection or oversize key | structural | Both agentosd and the vault process require 1 to 512 bytes of printable ASCII with no space. Bodies are capped (2 KiB / 1 KiB) and the key op is limited to 10/min. |
| Private call while the vault is locked or before custody exists | structural | `privateHook` with nil custody is false, and `privateAllowed` is false unless the vault is open. Both mutations are killed. |
| Private data by default | **open (S-B1)**; fixed in round 2 | The box is pre-ticked and labelled "Recommended" (`localui/pages.go:264`). This PR makes the answer effective. |
| Plan logins | n/a | Not served (c4e2), and `device_code: false`. |
| Key not checked with the provider | accepted | It avoids setup-time egress, and a wrong key fails later as a 401. |

### Findings
- **S-B1 (blocker; CAP-9, REV-6).** The private-data checkbox on the AI step is `checked` and says "Recommended." (`broker/localui/pages.go:264`). This PR wires it through `setuphooks.go:146` and `localsrv/setupproviders.go:61` to the vault marker (`providers.go:87`), which `route.privateOK` honours.
  - Failure path: the owner pastes a key and saves, and their mail and files become routable to OpenAI or Anthropic without the owner ever marking the provider.
  - The answer cannot be changed after setup (out of the brief's scope).
  - CAP-9: private-class calls go only to providers the owner marked. §8.1 step 6 sets default no.
  - Fix in this PR: remove `checked` and "Recommended.", and flip `localui_test.go:399`.
