## Findings

- **B1 (blocker).** Up after a failed Stop, then Rekey, still returns nil while `l.failed` holds the access point's interface.
  - Review probe (not committed), using the PR's own `fakeAP.stopErr`:
    1. `Rekey(rotatedPW)` returns "did not come down".
    2. `Up(cfg with rotatedPW)` on wlan0 returns `<nil>`. `upLocked` only refuses failed interfaces other than `cfg.Iface`. After this, `l.up=wlan0` and `failed[wlan0]` is still set.
    3. `Rekey(rotatedPW)` returns `<nil>` through the same-password short-circuit.
  - Requirement. #1193 says "while `l.failed` holds the access point's interface, `Rekey` returns an error instead of nil". The PR closes #1193.
  - Failure path. hostapd refuses to stop. The loader recovers with `Up` and the stored new password and is told success. A retried Rekey is also told success. If the driver's `Start` does not replace the stuck instance, the lost card still joins. The `AccessPoint` contract (`ap.go`) does not say whether Start fails or replaces an instance that is still running.
  - Fix:
    - (a) `Rekey` checks `stuck()` (or `failed[l.up]`) before the same-password nil.
    - (b) Either `upLocked` refuses `cfg.Iface` while its last BringDown failed, until a Down succeeds, or the `AccessPoint` contract says Start fails while a previous instance still runs and the fake models it. In an experiment, the refusal changed only `TestUnreadableAPTableIsKept`'s expected message.
    - (c) The test gains the Up-after-failed-Stop step.
    - L40 is updated to match.
