## Threat check

- [Fact] **ARC-2 holds.** `capoff.go` imports `errors fmt log os regexp strings sync sync/atomic time unicode/utf8` plus `daemon` and `loops`; no `net`, no `modelroute`, no new dial. The probe is one `os.Stat` (capoff.go `modelProbe.Line`). agentosd's only path to the model socket is still `modelroute.Forward` in `openGuestPlane`, unchanged.
- [Fact] **The stat leaks one bit and nothing else.** Its result picks between "" and the constant `modelUnreachable`; neither the path, the error nor the mode reaches STATUS or the log. `os.Stat` follows a symlink; the socket's directory belongs to the vault process, which is more trusted than agentosd, and a planted link can only flip that one bit. `Lstat` would make a legitimately linked socket read "not reachable", so Stat is the right call. Nothing acts on the result, so there is no TOCTOU to exploit; staleness is bounded to a minute (`modelProbeEvery`) and recorded as S12.
- [Fact] **No attacker-controlled text reaches the lines.** Every registry line is a package constant (`capLineTexts`); no line formats a note, capability name, guest string, path or error. `logCapLines` logs only those constants. The guest-facing question tools (`question.Tools` via `Call`) are unchanged and never write a capability line.
- [Fact] **Answering is unchanged.** `questions.start` only wraps `open` and sets `questionsOff`; `cfg.Answer` is still the owner channel's hook (`control.Handler.answer`, unlocked, non-PUBLIC task chat). Guests reach only the ask and status tools, so a guest cannot forge an answer.
- [Fact] **C9 tells the truth about the time check.** `q.g` is stored only after both `clock.New` and `question.New` succeed, so on any `open` failure `restricted()` is false and STATUS now says "the time check is off". That is more honest than before (silent fail-open of TIM-1 restriction).
- [Fact] **C11 is a true "off".** No `maintain.Loop3` is constructed; `updateChecks` is never called, so "Update checks: not running" stands on every box, which is accurate.
- [Fact] **False "on" for the model route (S8/S12).** agentos-egress opens `model.sock` at serve start for every socket in `serve` (cmd/agentos-egress/main.go:413–420), before any unlock and whatever the grants; a locked vault answers 503 (server.go:66, 194). So a box with no grant, or with its vault locked, has the socket and shows **no** C2 line. ASSUMPTIONS S8 says such a box "reads 'Model: not reachable, …'"; it reads nothing. The A11 test's third case (`no_model_route`) removes the socket, which models neither no-grant nor a locked vault, so A11's "no model grant" cause has no passing test though the file claims `REQ: A11`.

## Findings

1. **blocker** (OP-9, A11; defect) — **S8 states the opposite of what the box does.** With no grant, or the vault locked, the model socket exists and STATUS shows no model line; S8 says it shows "Model: not reachable". Fix: correct S8 to say both cases read as on (no line), name the locked vault beside no-grant, and say the A11 "no model grant" cause is not met by this PR (its test covers a missing socket only), keeping the release finding against CRED-5f. Optionally rename the subtest `no_model_socket`. Text-only; no code change. UX cost none; potency cost none.

Proposal: `modelroute` gains a status call (it may dial the vault socket), CRED-5f's brief carries the no-grant line, and C2 reads it. This is the release row the brief already asks for; finding 1 makes its scope accurate. UX cost: one more vault round trip per minute; potency none.
