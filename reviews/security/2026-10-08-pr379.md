## Evidence

- [Fact] **Verify before apply.** `ScheduleFirstBoot` takes `*update.Verified`; `schedule` returns `ErrNotChecked` unless `v.OK()`. The gate gets that value only from `update.Store.Check` on the stable channel, which applies signatures, thresholds, rollback floors and expiry (UPD-a).
- [Fact] **Downgrade.** `schedule` refuses `m.Version <= installed` with `ErrRollback`; `Check` refuses metadata older than stored. The gate opens only when a verified, fresh check finds nothing newer *and* the installed release's freshness is confirmed (`FreshnessFailed`, `UnconfirmedFreshness`). Mutation: dropping that freshness test fails `TestWithdrawnDriveReleaseKeepsGateHeld`.
- [Fact] **Rollback (A/B fallback).** A fallen-back version is recorded in the applier and refused by `ScheduleFirstBoot` (`ErrFellBack`); the gate stays held. Mutation: disabling the check fails `TestFirstBootFallbackIsRememberedAndNotRetried`.
- [Fact] **Offline.** No mirror is contacted; the gate stays held with the "offline" text; the local page's AI step is refused with offline wording.
- [Fact] **Fail closed.** Every non-success (no mirror, unreachable, unverified, installing, fell back) leaves `Trusted` false. The latch is the only persisted state; losing it costs one more check.
- [Fact] **Not wired.** No package outside `broker/firstboot` imports it; `Hold()` has no caller at this head (F7, UPD-b2). The AI step on the local page still uses the pre-existing `Hooks.Progress`.
- [Fact] `go test ./firstboot/ ./apply/ ./localui/ ./update/...` passes; CI green on the head.

## Threat check

Asset: the owner's AI and account credentials, which UPD-3 says never touch an outdated image. Adversaries: **N**, on the network path or controlling a mirror; **S**, holding old validly signed metadata or releases.

| Path | Stop | Kind |
|---|---|---|
| N serves unsigned or under-threshold metadata | `Check` refuses; gate held ("unverified") | Structural |
| S serves an older release, or metadata older than stored | Rollback floor in `Check`; version floor in `schedule` | Structural |
| N blocks every mirror | Gate held ("unreached"); only setup is delayed | Structural (fail closed) |
| A release that fails to boot is retried in a loop | `FellBack` record, refused | Structural |
| **N replays a frozen mirror (old but unexpired-looking timestamp) while the box's clock is behind** | Online expiry trusts `Options.Now` (`update/store.go:477,516`), which the gate passes through from `Config.Now = time.Now`. A first-boot box has never synced, so a clock near the image build date makes stale metadata look fresh; the gate latches `Trusted` on an outdated image, permanently (F5) | **Not stopped in the gate**; procedurally bound to UPD-b2 (F7, BOARD) |
| Some connect path skips `Hold()` | No caller yet; UPD-b2 acceptance test (F7) | Procedural (UPD-b2) |

## The clock gap (L3 point 1): release, not blocker

Decision boundary: is there, at this head, any path by which a credential reaches an outdated image because of the gap? No. The gate is a library with no caller; nothing reads `Hold()` or `Trusted()`, and no latch file is written in production. UPD-3 is not claimed end to end by this PR: the BOARD splits it into UPD-b (gate), UPD-b2 (wiring) and UPD-b3 (image), and UPD-3 holds only when all three land. The guard's input is also not available here: a trusted time comes from the HOST-1b clock guard (`broker/clock`, chrony with NTS), which is agentosd wiring, UPD-b2's scope.

What would make it a blocker: wiring `Hold()` into any connect path, or a release, without the guard. So the condition on UPD-b2 is hard, and it should be structural rather than a note:

1. **release (UPD-b2, first commit)** — make the clock fallible and required in `firstboot.Config` (`Now func() (time.Time, error)` or `ClockReady func() bool`, `New` refusing nil), feed it from the clock guard's `Latest`, and have `Step` stay held while the guard has not synced. A test: with the clock set before a replayed timestamp's expiry and the guard unsynced, the gate stays held. This turns the F7 note into a type the wiring cannot skip.
2. **release (UPD-b2)** — the "no connect path skips `Hold()`" test already on the row.
3. **release (UPD-b2)** — add `firstboot` to `TIER_A_BROKER` in `tools/risk_tier.py`. OPERATING §3 asks for it in the PR that creates a package that gates effects; it is outside UPD-3, so not a blocker here. Without it, a later firstboot-only change (for example to the latch) would be tier B and skip this Security section, which weakens the very procedural binding the clock gap relies on. It belongs in the same commit as point 1.

Costs: point 1 delays setup on a box that cannot reach NTS (UX cost; the offline/unverified wording already covers it). Potency: none.
