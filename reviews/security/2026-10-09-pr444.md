Threat check. Asset: the owner channel. Adopting a SIM sends approvals and texts over that SIM's line. Adversaries: a SIM swapper who holds the owner's number and a texted code (CH-19); someone on the Wi-Fi with a signed-in page but no code (CH-7); a compromised local UI process; a compromised modem bridge feeding `state`; a race between the page and a SIM change.

- [Fact] Adopting always takes a strong code, also within `FreshFor`. `localsrv.adoptSIM` checks the token first, then refuses an empty code with `RefusedCodeNeeded`, then runs `owner.LocalSignIn`, which accepts only a code-generator code or the asked grid cell (`checkStrong`), never a texted code. The vault unlock's proof (`UnlockProofPrefix`) is refused in localsrv before `LocalSignIn`, which would otherwise accept it, and again in localui. Wrong codes go through the same per-socket limiter (`takeTry`/`endTry`) and `LocalSignIn`'s daily tries as RESUME. Mutants M1, M2, M3, M10 and M11 are killed. A swapper with a fresh session but no code cannot adopt (CH-19).
- [Fact] A compromised local UI cannot pick the SIM. The page gets a 16-hex tag (SHA-256 prefix) and the last four digits. `modemlink.Adopt` records only the SIM the bridge reports right now, while the line is swapped or unbound, and only if the tag matches it. Any other tag gets `ErrStale`, mapped to `RefusedChanged`, and nothing is written (M4, M13 killed). The tag does not hide the serial from a determined UI: an ICCID with a known issuer prefix and last four digits is brute-forceable from a 64-bit prefix. That is harmless here, because the serial is not a secret (the roles file is 0644) and knowing it grants nothing.
- [Fact] A page/SIM race fails safe. `Adopt` reads the SIM under the lock, then writes outside it. If the bridge reports another SIM in between, the recorded serial is still the one the owner confirmed with a code. The bridge then finds a mismatch at its next open and reports swapped again. `adopted` is set only if the SIM did not change.
- [Fact] Bridge input stays bounded. `setState` refuses the whole call if `iccid` is not 1–22 characters of 0-9/A-F (M5 killed). It keeps a serial only while the line is swapped or unbound (M6 killed). A compromised bridge can offer any serial, but it already controls the modem and the roles check it runs, so adoption gives it nothing new. The bridge still only reads the roles file, and its read-only bind (L3 on #170) is kept.
- [Fact] Roles file integrity. agentosd writes a temp file in the same directory, chmods it 0644, fsyncs it, renames it and fsyncs the directory. It keeps other keys (M9 killed) and refuses a file that is not JSON rather than overwriting it (M8 killed). No serial or number is logged on any new path.
- [Fact] ARC-2: localsrv still does not import modemlink. `ErrStaleSIM` is localsrv's, and agentosd maps `modemlink.ErrStale` to it. The daemon's control-path guard test passes.
- [Fact] A successful adoption counts as a local sign-in, so the existing coalesced "A phone signed in on my Wi-Fi" text reaches the owner over the adopted line once the bridge reopens.
- [Fact] `go test -race -count=1` passes on bridgeproto, modemlink, modem/bridge, localsrv, localui, cmd/agentosd, daemon and localapi, and `go vet` is clean. The tests use synthetic serials and codes; no credentials or personal data appear.

## Points

- S1 (release; fold into the PR's proposed P2-1 row on `/var/lib/agentos/modem` permissions; not a blocker because no unit exists yet and #444 does not set the mode): `recordOwnerSIM` reads the roles file with `os.ReadFile`, which follows a symlink. It then copies every JSON key it finds into a 0644 file. If the image ever makes the directory writable by `agentos-modem` (the hostile-PDU parser), the bridge could plant `roles.json` as a symlink to a JSON file only agentosd can read and get its keys back world-readable. The rename replaces the link rather than its target, so integrity holds; only disclosure is at risk. The P2-1 row should say: the directory is owned by and writable only by agentosd's user, and `agentos-modem` gets read-only access. Optionally, open with `O_NOFOLLOW`.
- S2 (release, BOARD row with the next package touching modemlink or the bridge; a test gap on a tier-A path, so not `later`; not a blocker because the code is correct at this head and both mutants fail closed or are filtered downstream): two claims are unpinned.
  - M7: no test reports a different SIM, or an ok line, after an adoption and checks that `adopted` clears. Without the clear, the page keeps "Setting up the SIM ending in …" and refuses every later adoption until agentosd restarts. That fails closed, but it is wrong.
  - M12: no bridge test checks that `state` carries no serial while the line is ok. modemlink drops it then (M6), so it does not reach the page.
