## Facts

- [Fact] **Order.** `agentDone` saves `{"agent":true}` under item 2's ID only after `takeBack` returned nil, then sends through `done`, which drops it only on a successful send and re-owes and retries with backoff otherwise. On `ErrCarried` the entry is dropped and only the promise is said; recall's `Retry` owns `TakenBack`. `Handled` is read nowhere on this path. The tests cover the brief's list, including the on-disk-at-send check and the `Handled`-true, not-done case (`recorded` in `fakeWork`).
- [Fact] **Restart.** `finishOwed` matches `Agent` first and sends `forgetAgentDone` through `done` without reading `f.agent`, recall or the forget log. `resumeAgent` skips a goal recall reports handled, so a restart after a done take-back does not run it again; the only repeat is a crash between send and drop (F15), the lesser harm.
- [Fact] **Key.** Owed keys are now three disjoint forms: item 1 goal IDs `owner:<msg>` (`guest.GoalID`), item 2 IDs `forget-agent/<nonce>/<goal>`, and `!lost`. The nonce carries `UnixNano`, a per-boot sequence and the task time, so two asks never share a key. The brief's key `grants.ForgetAgentGoal(id)` would have been item 1's key: item 1's owe would overwrite the `Agent` entry and either item's `paid` would drop the other's (mutant M5 below fails three tests). Item 2's ID is the safer key; the brief-gap note and F14 record it.
- [Fact] **Replay and tamper.** A replayed entry (same key) gives at most one repeated text. `forgetAgentDone` names no task, so no entry can make it describe the wrong item. A forged `{"<any key>":{"agent":true}}` produces one "taken back" text with no corroboration, unlike item 1, whose entries need a tombstone (F10); writing it needs the daemon's uid (point L1).
- [Fact] **No task words.** The entry is the `Agent` flag under an ID that holds a nonce and a goal ID; the canary test checks the file. Logs added name errors only.

## Points

- **P1 · release (CH-12-lint coverage).** The lint matches identifiers in `inform`'s argument only. It misses `f.inform(recalltool.TakenBack)` (the same text as `forgetAgentDone`, reached by selector), a done text passed through a local variable, and a done text sent through `promise` or `say`, which send once and owe nothing (M2: the lint passes; only the runtime tests catch it). No requirement is broken at this head: every done text goes through `done`. Fix: in the next package that edits `forget.go` (W3-forget-b2c-f1), flag a done text in any call but `done`, add `TakenBack` to the names, and add these three mutants.
- **P2 · release (outside the cited IDs; CAP-3 wording vs recall).** `forgetAgentDone` says the agent "no longer holds it" whenever `takeBack` returns nil. `Reach.TakeBack` also returns nil when the reset is recorded but its deletion reach is unfinished (Retry finishes it, across a restart), and on `errUnrecorded`, where "its reach is left undone (logged)". In the second case the owner can be told "done" while the reach the deletion should finish is still held. This is not new: before this PR `inform` sent the same text at the same point. The PR makes the text durable but does not move it. Fix in recalltool: carry it into the W3-forget-reach brief, so the done-or-owed signal that row exposes counts a take-back as done only once its reach is finished too, not only when it is "in `TakenBackFrom` and not in `TakeBacksOwed`" (`errUnrecorded` marks it done with its reach undone).
- **L1 · later.** An `Agent` entry is told without corroboration. A forged one (daemon uid only) gives a false "taken back" text, which F10's sanitizing gives item 1 entries no way to do. Cheap check without reading recall: tell an `Agent` entry only if the journal holds a `Succeeded` intent with that ID. One line for LATER.md.
