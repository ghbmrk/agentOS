## What changes for an attacker
Before this PR a preloaded box had no Wi-Fi a phone could join before the claim. After it, the box holds a per-box WPA3 password, also printed on the sticker. That network is served from first boot until the Owner Card is confirmed.

| Path | Stop | How |
|---|---|---|
| Someone guesses the setup password | structural | `claim.NewCode` reads `crypto/rand` (the seller passes nil in production): 16 symbols, `byte%32` over 32 symbols, no bias, 80 bits. It is drawn separately from the code and the SSID. SAE allows online guesses only. |
| The network falls back to WPA2-PSK | structural once wired | `SetupNet` has no WPA2 field, and `HostapdConf` gives `SAE` and `ieee80211w=2` unless `WPA2` is set. No setup-network `APConfig` is built yet (S-R1). |
| The password leaks through logs, argv, env or errors | structural | debugfs reads it from a 0600 temp file and gets only file names. `logf` prints the directory. Parse and validate errors are fixed strings or json errors that carry no values. The claim state never holds it (tested). |
| The password is read from disk | structural | root:root 0600 under 0700, read back and checked with `e2fsck`. Seller copies are 0600. CRED-1 holds: no model-directed process reads `/var/lib/agentos`. |
| A forged file brings up a network nobody printed | structural | `ParseSetupNet` is strict, and a bad or unreadable file stops the start. |
| The setup network outlives the confirm | structural in firstboot, wiring owed | `Network()` serves only while `Card.Hold()` is non-nil, then burns the file. A failed burn serves nothing. `Begin` burns the file on a confirmed box, and a failed burn stops the start. Wiring is #1185 (and S-R3). |
| The seller knows the password | accepted (K10) | The seller already holds the claim code. |
| A look-alike network run by someone who read the sticker | residual (S-l2) | SAE does not authenticate the access point to password holders. |

## Findings
- **S-R1 (release; CH-7, A1). Onto #1185.** The setup network's `APConfig` is always `WPA2=false`, with a test that the hostapd config made from `Network()` reads `wpa_key_mgmt=SAE` and `ieee80211w=2`. Switch with `Down`/`Up` using the card's SSID, never with `Rekey` (which keeps the SSID). Decide whether ONB-5 passthrough applies on the setup network: the home Wi-Fi join comes before the card step, so an uplink can exist while it is up.
- **S-R2 (release; HW-10, CH-7). Onto #1184.** The spec diff states the exception: a seller-made setup password that opens only the claim and setup pages and dies at the card confirm.
- **S-R3 (release; HW-10, A1). Onto #1185, flag on #1226.** #1226's `localui.CardBox` (broker/localui/firstboot.go:56-58 at 9d48672) builds `BoxConfig` without `SetupNet`. Once both land, the file is never served or burned. Whichever lands later wires a store for `claim.SetupNetPath` that the `Begin` process can read and write, with a test.
- **S-l1 (later; onto #1185).** The owned-box start removes a leftover `SetupNetPath` file.
- **S-l2 (later; K10 residual).** A look-alike network run by someone who read the sticker relays more than the card: the claim, the home Wi-Fi password, the pairing code, the `otpauth://` seed and the Owner Card (plain HTTP; card step is the fourth §8.1 setup sub-step). This is not a blocker (D-105 trust root, an open network is worse). K10 should state the residual (CTRL-claim-ap l1, #1258). Later option: WPA3 SAE-PK, after a phone-support spike.
- **S-l3 (later; test gap; CTRL-claim-ap l1, #1258).** Pin the SSID and the password as separate draws (broker/claim/setupnet.go:40-48).
