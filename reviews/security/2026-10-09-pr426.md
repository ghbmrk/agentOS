## Evidence

- [Fact] **Nothing from an exchange reaches the guest unless it is in the declared shape.** `ResponseRule.swap` requires status 200, media type `application/json`, at most 64 KiB, exactly one JSON object with no trailing data, every required field present, and no undeclared field. Field names are matched exactly; Go's map decode is case-sensitive. Each value must match its declared kind. The CLI gets the proxy's re-encoding, never the upstream bytes. If a key appears twice, only the last value survives, and that is also the value that gets swapped, so the first value is never forwarded. Upstream response headers are not copied on this branch; only `Content-Type` is set. The forwarded body still passes `red.Writer`.
- [Fact] **No partial store.** `Swap` gets every credential of one response in one call. The proxy checks that the placeholder count matches, that no placeholder is empty and that no placeholder contains any of the response's credentials. Only then does it call `commit`. A `Swap` error, a nil `commit` or a `commit` error drops the response (`TestFailedSwapFailsClosed`, `TestFailedCommitFailsClosed`, `TestPartialSwapStoresNothing`).
- [Fact] **Trigger a fails closed.** An exchange response below 400 that fails the shape check is dropped (502), and the route stops with the fixed `ReasonUnswappable`. An error status is dropped without stopping. In both cases the body is not forwarded (`TestUnswappableRefreshFailsClosed` uses a synthetic canary in an undeclared shape, per the brief). The transport is `RoundTrip`, which does not follow redirects, so a 3xx `Location` is dropped like any other undeclared shape.
- [Fact] **Trigger b stops retries before they reach the provider.** A declared `Refused` status on any operation stops the adapter's route, and the response is not forwarded. On later requests, the `stopped` check runs after the operation match and before the verb check, the body read, the vault `Secret` lookup and injection. So a stopped route never reveals the credential and never reaches the provider, for every machine (`TestRefusedLoginStopsRetrying`, `TestStoppedRouteIsStoppedForEveryMachine`). `validate` keeps refusal statuses within 400–599, so a 2xx cannot be declared a refusal.
- [Fact] **Declarations cannot leave the hooks unset.** `New` refuses an exchange without a `Swapper`, and refuses an exchange or a refusal list without `RouteFailed`. It compiles each rule on a copy. A text field must have an anchored pattern, and a rule must declare at least one credential field (`TestNewRefusesUnsafeExchangeDeclarations`).
- [Fact] **The journal and notices get fixed text only.** `ev.Reason` and the deny bodies are `ReasonUnswappable`, `ReasonLoginRefused` or a fixed "answered with an error" literal. `Event` has no body or header fields. No response bytes reach the audit record.
- [Fact] **Resume gains no authority.** `Resume` reopens only a `ReasonLoginRefused` stop and returns `ErrRequalify` for an unswappable stop (`TestUnswappableStopIsNotResumed`). Nothing in `broker/` outside the egress package calls `Resume`, `Swapper` or `RouteFailed` yet. The ASSUMPTIONS row E11 records the wiring and the CH-10 owner check as release work, so this diff exposes no new caller to a guest.

## Threat check

Assets: plan credentials issued by a refresh (CRED-1, CRED-5 broker-held), and the owner's plan account standing with the provider. Adversaries: **G**, a guest or agent that controls the CLI's requests on a broker-held route; **P**, a provider or path that answers a refresh in a shape the declaration does not foresee (format change, extra token); **R**, a hostile or compromised upstream response.

| Path | Stop | Kind |
|---|---|---|
| P adds a new credential field (e.g. `id_token`) to a refresh response | Undeclared field fails the whole response; dropped; route stops | Structural |
| P/R nests a credential inside an object or array, or under a renamed key | Kinds admit only string/number/bool; exact field set | Structural |
| R puts a credential in a declared text field | Anchored declared pattern, at most 256 bytes | Procedural (pattern quality is declaration review; point 3) |
| R puts a credential in response headers (`Set-Cookie`, custom) | Exchange branch copies no upstream headers | Structural |
| A refresh is half-stored and the CLI holds a placeholder for a missing token | Swap then check then commit; drop on any failure | Structural (given the `Swapper` honours all-or-none; vault side not built) |
| G retries a refused login and makes a restriction worse | Stop is per adapter and checked before injection and forwarding | Structural, until restart (memory only; CRED-5b) |
| G provokes a stop (a declared refusal status, or a request that draws a different 200 shape) | Availability only: route falls back, no credential reaches G | Accepted DoS (point 1) |
| G reopens a stopped route | `Resume` has no guest-reachable caller; caller must check the owner (CH-10) | Structural now; procedural once wired (release, E11) |

## Points

1. **later.** G can make an unswappable stop happen: for example, a refresh request whose parameters draw a 200 with an extra field. That keeps the plan route on the API-key fallback until a release or a restart, and the owner cannot `Resume` it. E11 records the refusal-status DoS but not this one. It fails closed, and once the vault injects the refresh request body (release work in E11), G controls less of the request. When a built-in plan adapter arrives, declare a `BodyRule` for the exchange request so that G cannot choose its parameters.
2. **release (already listed under CRED-5b on the PR).** An exchange or refusal response that carries a non-identity `Content-Encoding` hits the existing `encoded` check before the new branches. It is dropped with a 502, but the route does not stop, so a compressed refusal does not end the retries (trigger b), and a compressed 200 refresh is dropped without a stop (trigger a). It is still fail closed, and the proxy sends `Accept-Encoding: identity`. Suggested fix for CRED-5b: move the `op.refused` and exchange checks ahead of `encoded`, or stop the route on an encoded exchange response.
3. **later.** `compile` accepts any `FieldText` pattern, `.*` included, so a careless declaration would let a credential through as text. Pattern quality depends on declaration review, as the `Field.Pattern` comment says. A check in `New` that rejects a pattern that matches a long random token (for example, a 40-character base64 canary) would make this structural.
4. **later.** The first stop's reason wins (`stop` ignores later reasons). Suppose a refusal on an inference request stops the route while a refresh is in flight, and the refresh then comes back unswappable. The stop stays `ReasonLoginRefused`, and the owner's `Resume` reopens it. The next refresh in the same shape is dropped and stops the route again, so no credential leaks; only the notice and the requalify rule are skipped once. If it is ever wired, an unswappable stop could overwrite a refused one.
5. **release (already listed under CRED-5b on the PR).** A transient `commit` failure, such as a vault write error, on a 200 counts as unswappable and keeps the route stopped until a restart or a release. It fails closed. When the vault `Swapper` is built, consider a distinct reason for a commit failure.
