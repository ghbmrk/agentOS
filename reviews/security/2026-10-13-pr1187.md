This is the tier A Security section (stage 4a). It ran in a fresh session, from the diff against main 297f7e0, issues #1176 (S-R1) and #1177 (U-R1), REC-4, CRED-1, and the #1175 Security record. It did not use the builder's reasoning. `risk_tier.py --git origin/main pr1187` prints A.

Threat model. The assets are the same as for #1175:
- the typed current vault passphrase held in a waiting `Pending`;
- the new card's parts in transit to commit;
- the replaced code-generator seed.

The new surface is:
- a rotation ID on begin, commit and cancel;
- a bounded memory of cancelled IDs;
- `POST /rotate/status`;
- a start-page offer that reuses `/rotate/show`.

The adversaries are a late or stale request from the page itself, a device on the AP or a signed-out phone, a cross-site page, a compromised agentosd (ARC-2), and any other local process.

| Path | Stop | How |
|---|---|---|
| A late commit lands under a newer rotation (S-R1) | structural | `commitRotation` → `mine(id)`: a waiting `Pending`, a well-formed ID and a constant-time match. Otherwise it answers 410 and the `Pending` is left untouched. Tested on the real socket: `TestAStaleRotationsOpsCannotTouchTheNewerOne`. Handler-level test: `TestRotateOpsCarryTheirRotationID` |
| A stale cancel drops a newer rotation (S-R1) | structural | `cancelRotation(id)` drops only on `mine(id)`. Otherwise it answers 410 and remembers the ID. The display's `Discarded` closure carries its own ID. Tested: same two tests, plus `localui` `TestRotationOpsCarryTheBegunID` |
| A begin with no answer keeps a passphrase, or lands late and drops a newer rotation (S-R1 follow-up) | structural, with a bound | Start cancels by ID on no answer, a 5xx, or a mismatched echo. The vault process checks the dead list under `rotation.mu` before `r.drop()` and before `approvedLocked`, so a refused late begin drops nothing, spends no code and holds no passphrase. A begin still in flight holds `rotation.mu` through `BeginRotate`, and its cancel then drops it by `mine(id)`. Tested on the real socket: `TestABeginWithNoAnswerIsCancelledByItsID` (only the case where the cancel arrives first). Bound: S-n1 |
| Someone forges or replays an ID | structural | 128 bits from crypto/rand, so collisions are negligible. The ID stays in agentos-localui's closures and is never in HTML, a cookie or a URL. The socket's `peerListener` (`-unlock-uid`, SO_PEERCRED) is unchanged and remains the access control. The ID is a guard against races, not a credential (K20). The only peer that can send an ID could already drive every op |
| `/rotate/status` leaks the seed | structural | It answers only `{enrollment_pending: bool}`. The page reads it on `GET /rotate/` behind `signedIn` |
| Showing the generator again with weaker proof, or after it is confirmed | structural | The offer reuses `/rotate/show` → `recovery.ShowEnrollment`. That needs the current recovery key: the new card's, since only `refresh` (a recovery-key or lost-card rotation) replaces the seed. A wrong key texts the owner. It answers `ErrNoEnrollment` once `ConfirmEnrollment` deletes the marker. The page is no-store |
| Secrets in logs | structural | The diff adds no logging. Replies are the fixed `uerr` texts (`errRotationID`, `errRotationGone`) |

## Findings

None blocker, release or later.

- **S-n1 (not a finding; a bounded residual within the #1175 R2 bound).** `rotation.dead` keeps the last 16 IDs that were cancelled while not waiting, and drops the oldest first. `bury` and `beginRotation` both run under `rotation.mu`, so eviction cannot race.
  - Review probe on the real handler (not committed): begin C, cancel ID X, cancel 16 more fresh IDs, then begin with X. The begin answers 200, and X replaces C.
  - Reaching this needs 16 cancels naming IDs that are not waiting, all reaching the vault process while one begin is stuck. Only agentos-localui can send them, and its normal flows bury at most one ID per Start, with Start serialized.
  - The outcome is safe. C's display commits, gets 410 and maps to `card.ErrDiscard` ("nothing changed", which is true). X's `Pending` and its passphrase are dropped by lock or the 30-min `PendingTTL` timer. That is the R2 bound the #1175 Security accepted.
  - The missing eviction test is L3's L-l1.
