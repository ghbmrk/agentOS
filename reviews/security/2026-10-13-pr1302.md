## Blockers
**B1. The vault process's unit has the weakest sandbox of the three setup services (CRED-9, ARC-1, cited).**
`agentos-egress.service` holds every API key and the vault passphrase, and it is the only path out to the internet. Yet it lacks controls the page (localui L26) and the modem bridge (bridge B7) already carry:
- `RestrictNamespaces`
- `SystemCallFilter=@system-service ~@privileged @resources`
- `SystemCallArchitectures=native`
- `MemoryDenyWriteExecute`
- an empty `CapabilityBoundingSet`
- `ProtectKernelLogs`, `ProtectClock`, `ProtectHostname`, `RestrictRealtime`
- `ProtectProc=invisible`
- `PrivateIPC`/`RemoveIPC`
- a device policy: `DevicePolicy=closed` plus `DeviceAllow=/dev/tpmrm0 rw` keeps the TPM.

Failure path: code execution in the process can create user namespaces and use the full syscall surface, so a kernel bug becomes root, and root reaches the TPM, the vault and the broker.

Four mutations survive every test:
- deleting `ProtectSystem=strict`
- deleting `UMask=0077`
- deleting `RestrictAddressFamilies`
- deleting the `drive-id check` ExecStartPre

The unsure-between-blocker-and-release rule (OPERATING §2) applies, and the fix is in scope and small.

**Fix:** add the lines, and pin every sandbox line and the drive-id ExecStartPre in `test_image.py`.

**B2. The page's `TemporaryFileSystem=/var/lib/agentos:ro` is removed on a wrong premise, and `TestTheUnitWiresTheSetupFiles` forbids restoring it.**
- The page's state is in the sibling `/var/lib/agentos-localui`, which the tmpfs does not cover.
- `localui-claim` runs with `+`, so it gets no namespacing.
- With the layer gone, only DAC keeps a compromised page out of the broker's state: root 0700, plus the agentos-fuzz ACL.
- The unit's header still says "no secret and no authority", which is no longer true.

**Fix:**
- Restore the line.
- Make the test assert both of these:
  - `/var/lib/agentos` is hidden;
  - nothing hides `/var/lib/agentos-localui` or `/run/agentos-egress`.
- Correct the header.

## Release (drafted below)
- **S-R1 (builder's release 2, confirmed release, not blocker): the page can forge "claimed".** Probe: `agentos-egress init -setup -claim` on a 16-byte `{"claimed":true}` made `setup.key`, `vault` and `vault.keys`. Egress K22, the only claim check outside the page, reads a page-writable file.
  - **Why release:**
    - Before the claim, only the sticker's setup network reaches the page, and its password is printed beside the code (claim K10). Whoever can exploit the page can claim legitimately.
    - After the claim, `vault.keys` exists and `egress-setup` does nothing.
    - A download box serves no page before pairing.
    - The fix (taking the claim decision out of the page) is Go work outside this PR. The page must save its try counts (K9), so the file cannot be read-only.
  - **G1-gating:** it must land before an owner box ships, and before the access-point loader (P2-1) or #1272 serves any pre-claim network that someone without the sticker can join.
- **S-R2 (builder's release 1, confirmed): prjquota.** This fails closed. The fix must enable project quota on root and must never be `-disk-quota off` (RES-4).
- **S-R3: the root-run helpers' guards are untested, and the root oneshot has no sandbox (recurring kind: root follows a lower uid's link).** These mutations survive:
  - `localui-claim` without its `-L "$src"` check
  - `localui-claim` without its `-L "$dst"` check
  - `egress-setup` with an unbounded read (`cat`)
  - `egress-setup` without `flock`

### Blocker
**B3 (new in the delta): `ProcSubset=pid` on egress hides `/proc/net`.** The cause and probe:
- `netguard.Sources.ReadLocal` reads no gateway, with no error.
- `Read` never asks NAT-PMP, so the router's external address is never refused (DEV-2; netguard N4, N9).
- Probe: full `/proc` gives `gateway=192.0.2.1`; `subset=pid` gives `invalid IP`, `err=<nil>`. `/proc/self/net/route` still works.

**Fix:** drop `ProcSubset=pid` (pin its absence with a reason), or read `/proc/self/net/*` with a test.

### For L3 (availability, not Security)

With `-vault-sock` now wired, `prepare` → `firstboot.Begin` fails on every box that is not set up, so the page crash-loops and the image has no setup page. It fails closed. **Fix:** drop `ProcSubset=pid` from the page.

A further gap: I14's "the boot test shows" drive-id works under `DevicePolicy=closed` is unverified, because `ci_boot.sh` never checks that egress is active.
