## Threat check

Adversary: a release that once carried attestation authority (interim test-box pass, or an allow-listed attestor later removed) trying to keep it, through rollback of the policy state, a read or parse error, or a race with the narrowing. Asset: the automatic security-update path (CHG-3 standing policy, applier `Security` scheduling, `Store.Stage`).

- [Fact] Binding. `noteAttestors` writes `outside_attestor_listed` (if any outside key), then `attestor_policy`, then sets `v.policy = s.policy()`, all under the store flock that `Check` holds for its whole run. `WithAttestations` copies the struct, so `policy` carries over. Every authority read (`Security`, `InterimAttestation`, `SecurityAutoStage`) re-reads the digest, and `Stage` re-reads it under the same flock for any `v.security` release, after `trustUnchanged`.
- [Fact] Interim rollback is closed. The sticky flag is in the digest, and no code path removes it, so `outside=false` can't come back short of deleting the store directory (U7/U16; P2-4b TPM NV anchor). FollowRoot also writes the flag (U13), so a fork switch retires interim authority too.
- [Fact] Fail-closed on read errors holds. Probe test, run and deleted (not committed): with `attestor_policy` replaced by a directory, `Security()` and `InterimAttestation()` are false and `Stage` fails. A missing `attestor_policy` gives `"|outside=…"`, which never equals a recorded digest, because `noteAttestors` writes the file before `v.policy` is computed. So deleting it retires authority and doesn't revive it. A store or `Verified` with no digest (`policy == ""`) also mismatches. A write failure in `noteAttestors` fails `Check`.
- [Fact] Torn reads during a concurrent narrowing (`Security()` reads two files without the lock) can only show the old policy or the new one, never a state that matches an older `Verified` after the narrowing has returned. `Stage`, the commit point, reads under the lock. `TestSR36NarrowingConcurrentWithStage` covers that.
- [Fact] Downgrade isn't widened. `CommitStaged` still requires a version newer than installed, and `trustUnchanged` is unchanged. The diff only removes authority. The owner path (`!v.security`) skips the check, as acceptance 4 allows.
- [Fact] `go test -race -count=1` passes on update, apply, change and maintain at 84c9efc, and `go vet` is clean.

## Release points re-checked for exploitability now

None is exploitable at this head. The applier (apply A7) and `NoteAttestors` are not wired into `agentosd`, and Loop 3 passes a static `Config.Attestors`.

1. **U16 / TPM NV anchoring** (deleting the store directory revives interim): the U7 class, needs root write on the store, bound to P2-4b. Not new. **later** (already recorded as U16).
2. **No committed test for fail-closed on a read error**: the behaviour is correct (probe above). The gap is regression protection only. **release**: add the probe as a test in the next package that touches `broker/update/store.go`.
3. **Apply drop paths leave the adoption `Staged`**: `Staged` is bookkeeping (digest text, `ConfirmStaged`/`StageFailed`). It grants nothing, and any re-activation goes through `Schedule` → `Store.Stage`, which re-checks. **release** (with SR3-4).
4. **Narrowing between Install and reboot is not caught**: `Stage` is the authority commit point, the same design as `ErrTrustMoved` (U15). After it, the signed, threshold-verified image is in the slot, and `CommitStaged` keeps anti-rollback. The window is a policy that changed after authorization, not a forged or older release. **release**.
5. **`NoteAttestors` not wired**: see S1. **release** (W5b).

## Points

- **S1 (release, wiring condition for W5b, UPD-8).** [Fact] Each `Check` rewrites `attestor_policy` from its own `Options.Attestors`. Probe: a release attested by keys {a, b}, `NoteAttestors({b})` → `Security()` false; then one `Check` with the old static list {a, b} → `Security()` true again. So an owner's narrowing through `NoteAttestors` holds only until the next Loop 3 check, unless Loop 3's list comes from the same source. [Inference] This doesn't break SR3-6's own claim: the revived authority equals what a fresh check under the stale list would grant, and the cause is pre-existing. But it is the path by which a removed (for example compromised) attestor would keep counting once wired. Condition: the wiring must take `Options.Attestors` for every `Check` (Loop 3; first boot passes none, which only narrows) and the `NoteAttestors` argument from one owner-setting source, read per check, with a test that a removal through the owner's setting survives the next Loop 3 check. UX cost: none. Potency cost: none.
- **S2 (later).** `policy()` treats a missing `attestor_policy` as the empty list rather than an error. That is safe today (it only retires authority, as above). A future change that computes `v.policy` before the file is written would turn it fail-open, and U16's "Security re-check if the digest's inputs change" already covers that.

No blockers.
