**`--host-uds=open` (point handed over from the lens screen).** It does not undermine A14's no-direct-dial claim. The flag lets the sandbox connect to host Unix sockets reachable through its own mounts. It is not an IP path, and it is the ARC-6 channel itself: broker services, including egress, reach the guest through the per-machine services directory mounted read-only at `/run/agentos` (ASSUMPTIONS V15). Off-allowlist reach through those sockets is the broker's egress policy (ARC-6(d), REV-5), not this test's claim. What bounds the flag is the set of host paths in the guest's mount tree. The bundle binds nothing from the host but the services directory (`TestRES3NoHostDevicesReachAMachine`), and a socket planted in the image is unreachable (`TestIntegrationHostSocketInImageIsUnreachable`, an integration test; not run here). `/proc` and `/tmp` are the sandbox's own. Read from the code; no live probe was run.

**Findings**
1. **release** (A14, A6; outside the cited IDs, so not a blocker): the only guard on what `--host-uds=open` can reach, `TestRES3NoHostDevicesReachAMachine`, flags a host bind only when `Type == "bind"`. The OCI runtime spec also lets a bind be declared by an `options` entry `bind` or `rbind` under another type (e.g. `"type":"none"`); that reading is inferred from the spec, and runsc's handling was not probed. Failure path: a later bundle change mounting a host directory that holds a daemon socket (e.g. `/var/run`) as `{"type":"none","options":["rbind"]}` passes CI, and the guest can then connect to that host daemon around the broker. Fix: treat any mount whose type is `bind` or whose options contain `bind`/`rbind` as a bind, and add `--host-uds` to the flags the test pins (only `open` is allowed).
