## Evidence

- [Fact] **Only the two ruled reasons open a way out.** `Confirmable` is true for `forget-log-unanchored` and `forget-log-missing` only; `rolled-back` and `forged` remove any stale `.confirm` and stay held with no question (`settleForgetLog`). agentosd's `loadHeld` independently refuses any other reason, an unknown field, an unsorted or unparsable date, and an answer index that is negative, out of range, or "Later" (never right). A question that does not read keeps the hold.
- [Fact] **Fail closed on every wrong path.** A wrong letter sets `Closed` and every later reply returns the wrong-answer text; only `c == q.Answer` writes the log and removes the marker. The marker is removed before the question, so a crash between them leaves a held-free state with no stray question that `loadHeld` would read (it checks `.pending` first). A reply that is no single letter asks again and changes nothing.
- [Fact] **The vault only gains forgets while held.** Unanchored, `checkForgetLog` now returns the longest authentic copy (chain and MACs checked under the card's key; any non-prefix copy with the same ID is still `forged`), and `settleForgetLog` saves it to the vault before the question is asked. Adding authentic entries cannot bring anything back, so saving it before the answer is safe.
- [Fact] **No forgotten content in the texts.** `askText` and `wrongText` carry dates, fixed strings and a destination name passed through `plainName` (ASCII letters, digits, ` -._`, 24 characters), so a hostile destination name cannot inject text or break GSM-7. The newer-backup entries reach the file with `Key` blanked.
- [Fact] **No new privilege path.** The `.confirm` file (with its plaintext answer index and log) sits in the state dir beside the marker. Anyone who can write it can already delete `forget-log.json.pending` and write `forget-log.json` directly, and agentosd's `readRestoredForgets` already reads that file without a MAC check (unchanged here). agentosd still does not import recovery.
- [Fact] **Decoys.** They come from `crypto/rand` (an injectable reader for tests only, unexported), sit at least 45 days apart (the clamp keeps at least `decoyGap` per remaining decoy, so no gap falls under 45), and every date has the same format.

## Threat check

Assets: CAP-3 (a forget stays forgotten across a restore); the owner's forgotten content. Adversaries: **O**, the honest owner restoring a backup older than their last forget (the one the check exists for, per ASSUMPTIONS Q1 and REC-1); **L**, a local process with write access to the state dir; **D**, a hostile or corrupt backup destination.

| Path | Stop | Kind |
|---|---|---|
| O restores a stale backup on a new PC and answers from memory | Their real last forget is after every listed date → "Later" or a decoy → held | Procedural (rests on the owner's memory, as ruled in D-065) |
| O restores a stale backup on a new PC twice and picks the date that repeats | Nothing: the real date is fixed and the decoys are fresh each time | **Not stopped**: point 1 |
| O restores a stale backup whose last forget falls on the same calendar day as the real last forget | Nothing: dates are whole days | **Not stopped** (precision of the ruling): point 3 |
| O restores a pre-log backup (`missing`) while an authentic log holding forgets is at hand, and answers "Never" | Nothing: copies are not opened in the missing case | **Not stopped**: point 2 |
| O on the same PC with a working counter restores a rolled-back log | `rolled-back`, no question | Structural |
| D supplies a forged or diverging log copy | `forged`, no question | Structural |
| D supplies a hostile destination name for the wrong-answer text | `plainName` filter | Structural |
| L edits `.confirm` to set the answer or log | Same privilege already lifts the hold by deleting the marker | Not a new path |
| Forgotten content reaches a text | Texts hold dates and fixed strings only | Structural |

## Points

1. **release** (CAP-3, C3; ASSUMPTIONS Q1 is inaccurate). Q1 says a guess is right one time in six and that the owner retries by restoring again "with new decoys". The real date is the same in every question and the decoys change, so two restores of the same backup show the answer as the one repeating date (and in the "never" case, no repeating date points to "Never"). An owner unsure of their last forget can pass the check by pattern instead of memory, which is the case the check exists for. Proposal: derive the decoys from the restored log itself (e.g. seed them from an HMAC under the forget key over the log head, plus the reason), so the same backup always shows the same question; then Q1's 1-in-6 holds per backup. UX cost: none. Potency cost: none. Not a blocker: Q1 places the card holder outside the threat model, and the stop is procedural either way.
2. **release** (CAP-3, C3; brief gap, the builder followed the brief). In the `missing` case `checkForgetLog` returns before opening any copy, so the right answer is always "Never", even when a copy at hand (a destination's log under the same recovery key) proves forgets exist. An owner who answers "Never" releases the restore with no log, and those forgets are not replayed. Proposal: in the missing case, open the copies under the card's key; if an authentic one has entries, carry the longest as the unanchored case does (its date becomes the answer), or hold without a question. UX cost: none for owners with no log anywhere. Potency cost: none.
3. **later** (D-065 precision). Dates are calendar days, so a backup made between two forgets on the same day confirms with the day of the later forget, and the later forget comes back. Proposal: record the residual in ASSUMPTIONS Q4; a finer answer would need a new ruling.

No blocker. Signed for W3-forget-b1-4 at 1c0e4c2 by the Security lens; a later tier-A delta needs a re-sign (OPERATING §3).
