## First pass

- [Fact] **No new path from guest to host.** The guest runs fixed scripts (`machprobe.Tamper`, `Press`) with guest authority and gets no new socket, mount, credential or network. Tamper verdicts come from a broker-side `treeDigest` that does not follow links. Exhaustion limits are read broker-side from the cgroup and the quota. The guest's count and output are only logged.
- [Fact] **No spoofing or flooding.** A finding's `Subject` comes from broker configuration or the fixed kind list, and `Detail` is a constant, so no guest string reaches a finding or the owner's text. `runProbe` rejects a finding with the wrong check. A failed round stays in STATUS and the digest until a round succeeds.
- [Fact] **Pressure is bounded.** Every kind stops after `hold+5s`. Memory, processes and disk are capped by the machine's cgroup and quota, and `ExhaustProbe.Run` preempts the pressed machine on every path after `Press` returns an ID. CPU is limited only by `cpu.weight`, so idle host CPU can be used during the hold, which an agent can already do.
- [Fact] **The helper ships only in the test guest.** The only importer of `machprobe` is `broker/vm/gvisor/testdata/guest`; no production image or binary links it (M3).

Points:
