## Review
- **Who can trigger the switch.** `page_rotate_ap_net` needs only a live agentosd session and a card-shaped network under the current SSID; nothing binds it to a vault commit. The actor is a compromised page process. Binding to the commit raises the bar to one owner tier-4 entry during the compromise. Under CH-7 an attacker-chosen password reaches only the pre-sign-in pages, so release is the right class (R1).
- **409 and no answer.** The access point and the vault can disagree when the vault never committed; the owner holds the new card and is not locked out. A failed hand-off on 409 or no answer is silent (R2).
- **Atomic write.** `durable.WriteFile` matches the #1465 rule. An `ErrDirSync` after the rename misreports "still uses your old card's password" (R2). Neither the atomic write nor the uncancellable context is pinned by a test (R3).
- **Restart.** agentos-ap brings wireless Down then serves `ap-net.json`, and never falls back to the old password.
- **Leaks.** None found; `RotateAPNet` redacts in String and GoString, both tested.
- **Done-when.** #1459 R1 and the widened #1191 items are met. The switch lands within one 2 s poll of the hand-off, before the reply reaches the phone; that is the safe direction and the confirm page warns. #1191's "fixed CH-12 text if recovery keeps failing" is not built (R4).

## Findings
- **R1 (release; REC-4, CH-3, CH-7).** The op takes the access point password from the page with session authority only; a compromised page can lock the owner out, set a known password, or flap the access point, and the change outlives the compromise. Filed #1522.
- **R2 (release; REC-4, CH-12).** A failed hand-off on 409 or no answer is not told to the owner, and `ErrDirSync` is misreported. Filed #1523.
- **R3 (release; tier-A test gap).** Wiring, atomic write and context are untested. Filed #1524.
- **R4 (release; CH-12, REC-4).** No owner text when the rotated access point keeps failing to come up. Filed #1525.
