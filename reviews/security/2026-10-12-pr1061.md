# Security lens: #1061, SIM-split-fix, head 339b352

Record: PR #1061 · package SIM-split-fix · head 339b352

Scope: the PR at 339b352, which fixes #1053 R1/R2 and #1057 S1/S2. `risk_tier.py` puts it in tier A: core `checker` and `holder`, wiring `cmd/agentos-holder`, and `egress`. On go1.26.8, `go test -race` passes for `./checker ./holder ./egress ./sockets ./cmd/agentos-holder ./cmd/agentos-checker`. SPEC.md is untouched.

Question: after this PR, can a compromised egress or holder send a gated act or a provider-side tool body with a real login that the owner did not approve?

Threat check:
- Account binding (S1): `checker.Act` length-prefixes the account (the credential name). The holder uses its own `Adapters[0].Credential`, which `New` keeps single and `Validate` keeps non-empty. A's approval is a different act from B's for the same bytes, and the account never comes from the request. Residual: on the shared `redeem.sock`, one holder can spend (and so deny) another account's act, but cannot use it (LATER SIM-split-fix l1).
- Fail closed (S2): only 204 approves and only 403 refuses. Any other status, a timeout (10 s) or a dial error is an error, and the holder then answers 503 `unapproved` without reaching the provider, even if `true` came back alongside the error. A 3xx can only be followed back to the checker's own socket.
- Body rule (R2): the holder runs egress's own `BodyRule.apply` and sends its own encoding, so the act covers the exact bytes it sends. It uses the public form only when `-public-fetch` is set (off by default) and egress says `public`, so egress's label alone loosens nothing. Deny keys stay refused in public mode, and the label header is never sent upstream. Residual: on a login opened with `-public-fetch`, a compromised egress gets what a public machine gets (LATER SIM-split-fix l2, `recheck`).
- Short secrets (R1, D-103): I confirm the class acceptance. The brief allows it. Today egress holds plaintext, so a keyed hash is less exposure, and dropping these passwords from the redactor would lose CRED-7. D-103 binds SIM-split-wire to give egress the hash redactor only. D-103 collides with no D-number on main or in any open PR.
- Mutants (all killed unless noted): empty account in the holder; `Act` without the account; non-204 read as approved; holder ignoring a redeem error; label alone enabling public mode; holder always public; holder skipping the rule; proxy labelling every machine public. **The `-public-fetch` default flipped to true survives** (no test parses the default). Dropping the proxy's `Header.Del(LabelHeader)` survives but is equivalent, because egress copies only allowlisted headers.
- Secrets: tests use random `sk-canary-` values and `example.invalid` only.

Findings:
- **P1 release** (ADP-10, REV-5; acceptance "a body carrying `mcp_servers` is refused by the holder even when egress forwards it"). Failure path: the flag default flips to true with CI green, and a compromised egress then gets the public form on every login. Folded into SIM-split-wire, which sets the flag from the owner's choice per login and pins the default-off with a test.
- **Later**, in LATER.md: SIM-split-fix l1 and l2 (filed by the builder) and l3 (H-10 wording).

Findings: blocker 0; release 1 (P1, SIM-split-wire); later 3.
