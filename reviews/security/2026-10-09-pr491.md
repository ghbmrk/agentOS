## Evidence

- [Fact] **Test-only.** The diff touches only `broker/change/env_test.go`; `testSplitKey` lives in a `_test.go` file and is not compiled into any binary.
- [Fact] **Production split stays random.** `New` reads `Config.Rand` once, only when no state is persisted, and defaults it to `crypto/rand` (`pipeline.go:416-417`, `443-446`). The two non-test `change.New` callers, `broker/cmd/agentosd/learn.go:139` and `assurance/loop2/rig.go:150`, do not set `Rand`. A persisted key must be 32 bytes or `New` fails closed (`pipeline.go:428`).
- [Fact] **The pinned key cannot be read short silently.** `testSplitKey` is exactly 32 bytes. Every later `New` in `change/` tests restarts over an existing store (`cascade_test`, `loop2_test`, `pe5b_test`, `pipeline_test:553`), so the drained reader is never read; if one were, `io.ReadFull` would return EOF and the test would fail, not pass.
- [Fact] **Owner-gate (ErrNeedsOwner) tests do not depend on the split.** The tests that drive a candidate to the owner force it with `MinHeldOut = 100` (`pe5`, `pe5b`, `pe7`, `resume` tests) or call `Check` directly (`env_test.go:44`, `pipeline_test.go:510`), so no split key can make them skip the owner path. The flake ran the other way: a random key sometimes sent an adoption test to the owner.
- [Fact] **Held-out leakage tests still exercise both sides.** `TestSplitKeepsGoalTogether` asserts dev and held-out are disjoint per goal and that both sides are non-empty, so it fails if a pinned key ever collapses the split; `TestSplitKeepsLegacySide` checks sides against `splitOf(e.p.key, ...)`, whatever the key. `TestSplitIgnoresCallerGoal` (security C2) does not depend on the key.
- [Judgement] Pinning trades per-run variation of the split (a weak, accidental property test of CHG-1 over one random key per run) for determinism. The invariants these tests check are key-independent, so nothing tested before is untested now.

## Threat check

Assets: the held-out set's secrecy from the candidate builder (CHG-1); the owner gate on under-evidenced adoptions. Adversaries: **B**, a proposer that games the split; **T**, a test suite that passes while the property is broken.
