# Security, PR #463 (SR2-3q, SR2-3p: classify runsc exec failures before the command ran)

Record: PR #463 · package SR2-3q · head 6770714

Stage 4a, tier A (`tools/risk_tier.py` prints A: broker/vm, broker/workers). Reviewed from the diff and CAP-8, RES-4 only; CI green on 6770714; `go test ./vm/... ./workers/` passes locally. Covers SR2-3p too (same PR).

## Threat check

Asset: the owner's worker state, which a duplicated command can change twice; the invariant is that the guest is told "did not start; retry it" only when the command cannot have run. Adversaries: a guest choosing argv; runsc failing at any point; a runsc upgrade.

Read against gVisor `release-20260928.0` (the pin in V32/V33): `runsc/cmd/exec.go`, `runsc/container/container.go`, `runsc/sandbox/sandbox.go`, `runsc/boot/controller.go`, `runsc/boot/loader.go`, `pkg/sentry/control/proc.go`, `pkg/urpc/urpc.go`.

| Path | Result |
|---|---|
| `loading container failed`, `parsing process spec` (Fatalf) | before `c.Execute`; NotStarted is correct |
| `executing processes for container:` + `requireStatus`, `configureStdios`, `sandboxConnect` error | before the call is sent; NotStarted correct |
| + marshal/write error in `urpc.Client.Call` | request incomplete, the server cannot decode or dispatch it; NotStarted correct |
| + `urpc method %q failed` (reply lost after send) | command may have started; matched by `notRun` → ErrExecFailed. Structural |
| + `RemoteError` (sentry answered failure) | every error in `executeAsync`/`control.ExecAsync` returns before `Kernel.StartProcess`; nothing errors after it. NotStarted/NoProgram correct |
| `writing internal pid file` / no line / runsc panic or kill | ErrExecFailed. Structural (default is fail-safe) |
| ctx ended | context error, unchanged |
| guest argv imitating runsc text | argv appears only after runsc's prefix, inside `%q` of `ExecArgs`, quotes escaped; `urpc method "` needs a raw quote, so a guest can only cause a false *match* toward ErrExecFailed; NoProgram match is anchored at the line end, where the sentry's error is. Tested (spoof cases). Either way the outcome among NotStarted/NoProgram changes advice only, never safety |
| runsc text reaching the guest | none; the three guest texts are fixed (`guesterr.go`), match by sentinel identity |
| `--log` read | per-exec 0600 file in the broker-held state dir, outside the sandbox; first JSON value, 1 MiB bound |

## Points

1. **later** (concrete defect class: drift, fail-open direction). Every changed runsc/sentry text fails safe to ErrExecFailed, except one: if a runsc upgrade rewords urpc's `urpc method %q failed` wrapper, a lost reply under `executing processes for container:` reads as ErrExecNotStarted ("retry it") and a command that ran can be retried. The fixture (`fakerunsc.sh`) copies the text, so CI would not notice. V33's re-read-on-pin-change action (V20) covers it procedurally only. Proposal: when the pin next changes, add a check that greps the vendored or fetched `pkg/urpc/urpc.go` at the pinned tag for the exact format string. UX cost none; potency cost none.

No blockers; nothing in release.
