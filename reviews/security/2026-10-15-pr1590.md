## Review (63434765, round 1, Security record)

Verdict: REQUEST CHANGES. Comment: https://github.com/ghbmrk/agentOS/pull/1590#issuecomment-6170031972

#### Security review (tier A, A1 option 1) at 6343476

**Verdict: REQUEST CHANGES.** There is one blocker (B1) and two release items (R1, R2).

**What holds.** I re-ran the probe locally under the CI `setpriv` line (no_new_privs, the unit's bounding set, the group), inside `unshare -n -u`.
- hostapd's child runs with Uid and Gid 61426 ×4 and no groups.
- Its Inh, Prm, Eff and Amb sets are all 0x3000, which is NET_ADMIN and NET_RAW.
- `--clear-groups` fails at chown, as the PR says.
- The AP uid cannot reach verify.sock or any other broker socket, on first boot or steady state:
  - egress filters by SO_PEERCRED: uid 0 and localui;
  - `sockets.Server` sockets are 0600, or 0660 to the peer's group;
  - `/var/lib/agentos` is 0700 root from sysinit tmpfiles;
  - the egress and localui state dirs are 0700.
- egress trusts no AP uid.
- `systemd-sysusers --root` creates `agentos-hostapd` with its own group.

**B1: the production wiring is unpinned, and a nil `User` runs hostapd as root.** main.go:96, hostapd.go:46-47 and :132.
- I put main.go:96 back to `ap := &localui.Hostapd{Dir: dir}` and every test still passed: the cmd/agentos-ap tests, the unit pin, `TestNewHostapdRunsHostapdAsItsUser`, and the CI probe, which builds its own `Hostapd`. That mutant is the exact A1 failure.
- Fix: make `Hostapd.Start` refuse `User == nil` when euid is 0, or add an explicit test-only opt-in. Then have a test assert that main's construction path sets `User`, for example through a `newLoader` helper, or by having the unit test refuse a `localui.Hostapd{` literal in main.go.

**R1: the child's bounding set is 0x34e4** (dac_read_search, kill, setgid, setuid, net_bind_service, net_admin, net_raw). hostapd.go:140-143, hostapd_user_test.go:84-92.
- Measured without no_new_privs: as the hostapd uid, a `cap_setuid+ep` binary reached uid 0. With no_new_privs it gets EPERM and CapPrm 0, and sudo is refused.
- `NoNewPrivileges=yes` is pinned, so nothing can be gained today. But A1 says "without SETUID or DAC_READ_SEARCH", and the probe does not check the bounding set.
- Fix: assert `NoNewPrivs: 1` in the probe. Preferably also drop the child's bounding set to NET_ADMIN and NET_RAW (a `setpriv --bounding-set` wrapper or a PR_CAPBSET_DROP helper) and pin `CapBnd` at 0x3000.

**R2: the first-boot skip of the `-/var/lib/agentos-egress` mask is still there.** agentos-ap.service:60.
- It is moot for hostapd: no DAC capabilities, and the dir is 0700 agentos-egress.
- But the root loader keeps CAP_DAC_READ_SEARCH and has no ordering against agentos-egress. On first boot the mask is skipped, and the vault state written after the claim is readable to it. The same holds for the `-/var/lib/agentos/*` masks.
- A1 listed this as its own point.
- Fix: add `After=agentos-egress.service` (and agentosd) and pin it in `TestTheUnitIsBounded`, or record it as a residual in I16 for the owner to accept.

**Not findings:**
- writeConf, which uses O_EXCL|O_NOFOLLOW, then fchown and fchmod, in a 0710 root dir, is sound.
- dnsmasq's implicit drop user (no `user=`) is pre-existing and out of scope.
- NET_ADMIN and NET_RAW in the host netns are A1's approved set.

CI's machines, broker and checks jobs were still running when I read the head.

##### Verified
- **B1.**
  - `Start` refuses a nil `User` without `AsCaller` (`broker/localui/hostapd.go:104`), pinned by `TestHostapdRefusesNoUser`.
  - M14 (main.go:96 put back to `&localui.Hostapd{Dir: dir}`) is killed by `TestMainBuildsHostapdOnlyThroughNewHostapd`. So is building a literal after the `newHostapd` call.

- **R1.** I re-ran the probe under the CI `setpriv` line inside `unshare -n -u`. The child reports:

  - Inh, Prm, Eff, **Bnd** and Amb all `0x3000` (`capsh`: cap_net_admin,cap_net_raw; it was 0x34e4).
  - **NoNewPrivs 1**.
  - Without `--no-new-privs` the child still reports NNP 1, so the code sets the flag itself.
  - Without `+setpcap` it fails closed: "capability bounding set: drop 0: operation not permitted".
- **CAP_SETPCAP on the loader: not a net loss.** On a file-caps kernel it can only:
  - drop from the bounding set;
  - add bounding-set caps to the inheritable set, which a uid-0 process already holds as permitted;
  - set securebits, which give nothing beyond the bounding set to a process that already has SETUID.
  - Nothing it allows raises a capability past the bounding set, which is pinned exactly with `NoNewPrivileges=yes`. dnsmasq and `ip` had the full root set before anyway.
  - `@system-service` admits prctl and capset.
- **Other threads.** In a scratch test (20 confined starts, plus goroutines that force new Ms), only the main thread (m0) carries the confinement, and it is wedged for good by `runtime.mexit`. No working thread is tainted.
- **R2.**
  - `systemd-analyze --root verify multi-user.target` on a scratch root with the preset's units reports no cycle. A planted `Before=agentos-egress.service` is reported, so the check would see one.
  - egress's `StateDirectory` exists before its start completes, so the vault mask now applies on first boot.
  - agentosd is `Type=simple` and creates its subtrees later. I16 records that residual.
- **test_image's last-`After=` reading** (`ini()` with `strict=False`, tests/test_image.py:2392) checks only inbound and passes the After-revert mutant. The ordering is pinned instead by Go `TestTheUnitIsBounded`, which compares every After line exactly and kills the revert. Nothing is hidden.
- **Local runs.** `go test -race ./localui/... ./cmd/agentos-ap/...` passes as root. `python3 -m unittest tests.test_image` passes 161 tests.
- **Mutants killed:**
  - M14 and M14b;
  - the bounding-set drop removed;
  - `startConfined` bypassed;
  - the After revert;
  - SETPCAP removed from the unit;
  - M8 (no Remove, `O_TRUNC`);
  - the nil-User refusal removed.

##### Security: required
- **S-R1. `Hostapd.AsCaller` is exported, so production code can still run hostapd as root with green CI.**
  - Sites: `broker/localui/hostapd.go:50-51`, `:104`; `broker/cmd/agentos-ap/user_test.go:51`, which parses main.go only.

- **L3-L1.** "it ends with its goroutine" is false on the main thread, which is wedged instead (hostapd.go:229-230, L51, the PR body). loop7's F2 row words this correctly.
- **L3-L2.** I16's "so the secret paths it hides exist when it starts" holds for egress's state directory, not for agentosd's later paths. Its own next clause states that residual.
- **L3-L3.** The body says dnsmasq.conf is "pinned by `TestWriteConfRefusesALink`". Only `writeConf` is pinned (P-L2).
- **L3-B1 resolved.** `Closes #1426` is present, and the L51 collision note now names #1241.
