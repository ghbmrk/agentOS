# Security lens: #1060, CTRL-card (first-boot Owner Card display and confirm), head 94cc904

Record: PR #1060 · package CTRL-card · head 94cc904

Scope: the PR at 94cc904. Tier A (`risk_tier.py`: broker/card). `go test -race` on go1.26.8 passes for `./card ./firstboot`; `./localui ./recovery` still pass. Nothing is wired yet: agentosd and the setup page do not build a `CardStep` (release finding on the PR).

Question: can any per-owner secret on the Owner Card reach disk, logs, the journal, an error or a traceback, or survive the confirm on the box, and can setup finish without the owner holding the card?

Threat check:
- Disk and logs: nothing is written before the confirm. Journal events are fixed strings. `Card` and `Display` format as placeholders. Error bodies are fixed and never echo the answer. AT1 test scans the whole partition (journal, `log`, `slog`, vault files) with the A8 scanner. Mutant: journal carries the recovery key, killed.
- Confirm gate: it needs the word and the group (constant-time compare after normalisation). Empty, partial and swapped inputs are refused. A provision runs only after a match, and the erase only after provision and latch succeed. A panic leaves the hold held. Mutants for skipping the compare, dropping the group, provisioning before the compare, erasing on provision failure, ignoring a latch error, a `Hold` that never holds, and a latch ignored on restart are all killed. No attempt limit, by design: only the paired phone can try, and it can read the card anyway.
- Randomness: `crypto/rand` by default, for the values and the asked positions. Mutant: fixed `math/rand` seed, killed by both two-boot tests.
- Erasure: the sheet and grid seed are zeroed and the card dropped. Mutants that skip the erase or skip the zeroing are killed. Go strings stay in freed heap (C13), which holds only with no core dumps and no plaintext swap (S1).
- Transport: pairing is checked first. Headers set: `no-store`, CSP, `frame-ancestors 'none'`. Cross-site POSTs are refused. Mutants that turn off the Origin or pairing check are killed. DNS rebinding relies on localui's Host check, so the display must be mounted inside that server (wiring condition).
- Secrets in tests: values generated per run, no real credentials.

Findings:
- **S1 release** (HW-1 AT1, A1). The image disables core dumps and keeps swap off or encrypted, with an image check. Failure path: a crash or swap-out of the card-holding process after generation writes the unzeroable passphrase string to `/var/lib/systemd/coredump` or a swap partition.
- Conditions added to the builder's wiring release finding: mount behind localui's Host check and pairing, and reset a half-made vault after a restart between provision and latch.

Findings: blocker 0; release 1 (plus the builder's 2); later 0.

Arbitration: no tension with Potency or UX.
