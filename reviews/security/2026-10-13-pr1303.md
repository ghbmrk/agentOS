## Round 1 (9647904)

### What changes for an attacker
The required `checks` job gains a lane-gate step. On `pull_request` it adds a detached worktree of `HEAD^1` and runs that copy of `risk_tier.py` with `--pr-branch`/`--pr-title`. If the base copy lacks the flag, it runs the PR's copy instead. A PR in the codex lane (branch `pkg/codex-` or title `CX-`) whose diff is above tier C fails. LANES.md adds a fresh Claude L3 for Codex PRs that touch `tools/*.py`. The adversary is a lane agent, whether careless or reward-hacking, that pushes as Mark's login and wants a PR above tier C merged.

| Path | Stop | How |
|---|---|---|
| PR loosens the classifier or the gate code | structural | The base's `risk_tier.py` and `core.txt` run (`-I`, and `CORE_LIST` from `__file__`). |
| PR deletes or disables the gate step in ci.yml | none (B1) | `pull_request` takes the workflow from the PR merge. No other check enforces tier: premerge.py does not check it, and a Codex L3 alone is enough off `tools/*.py`. |
| PR code earlier in `checks` tampers with the step | none (B2) | Unit tests, trace.py, doclint.py, board.py and the PR's risk_tier.py run first. Any of them can prepend `$GITHUB_PATH` (fake python3/git/grep), rewrite refs or occupy `$RUNNER_TEMP/base`. |
| Script injection by branch or title | structural | They pass through `env:` and are quoted. A `-`-leading one-word title makes argparse exit 2, which fails closed. |
| Fails open on error | structural | bash `-eo pipefail`. worktree, `git diff` (`check=True`) and core-list errors each exit non-zero. |
| Token or permission widening | none added | `checks` stays read-only, with `persist-credentials: false`. |
| `workflow_dispatch` run on a codex branch, or a commit status named `checks` | procedural (R1) | The gate is `pull_request`-only, and the ruleset's required contexts have no `integration_id`. |
| Codex PR on a non-codex stem with a non-CX title, or a title edited after the run | procedural (R2, D26) | Names only, and there is no `edited` trigger. |
| Fork PRs | not a lane path | Codex pushes to the repo, and only the shared login merges. |
| `merge_group` | structural | The gate is skipped there. The strict policy means the PR run already gated the same diff. |

### Findings
- **B1 (blocker):** the gate lives in the PR-controlled workflow. Fix with (a) a `pull_request_target` gate workflow that runs the base definition and base script on the diff names only, with no PR code and `contents: read`, and types including `edited`. Mark makes it required through a decision issue. Or fix with (b), at minimum: record in D26 that the Codex credential lacks the `workflow` scope, and state the guarantee as conditional.
- **B2 (blocker):** PR code runs before the gate in the same job. Fix: make the gate the first step after checkout and call `/usr/bin/python3 -I` and `/usr/bin/git`. Fix (a) of B1 also covers it.
- **R1 (release):** a `checks` result can reach the head SHA without the gate, through a dispatch run or a status named `checks`.
- **R2 (release):** D26's name key, with no `edited` trigger. Acceptable as a recorded gap until a separate Codex identity exists.
- **R3 (release):** no test covers the CI wiring, and the grep fallback to the PR copy should be removed once the gate is on main.

The ci.yml comment and D26's "a PR cannot loosen it" are false until B1 and B2 are fixed.

Next: the builder fixes B1 and B2, then Security re-signs the delta; owed: Security re-sign, L3.

## Round 2 delta (e2aaaf4)

The delta from 9647904: `.github/workflows/lane-gate.yml` is new (job `lane-gate`, on `pull_request_target`), and the gate step is removed from `ci.yml`, leaving only the advisory summary. `tests/test_workflows.py::test_lane_gate_runs_only_the_base_copy` is new, and LANES.md and D26 are reworded.

| Path | Stop | How |
|---|---|---|
| PR deletes, skips or edits the gate (B1) | structural | `pull_request_target` runs the base branch's workflow file. |
| PR code runs before or beside the gate (B2) | structural | The only checkout is of `base.sha`, with `persist-credentials: false`. The head is fetched as objects (`refs/pull/N/head`) and checked with `git cat-file -e`, and the base's `python3 -I tools/risk_tier.py` runs `git diff --name-only -z --no-renames BASE...HEAD`, which runs no diff drivers. |
| Injection by branch or title | structural | They pass through `env:` and are quoted. A title starting with `-` or `--` makes argparse exit 2, which fails closed. |
| Token or secrets | structural | `contents: read` at both workflow and job level, and no `secrets.*`. |
| Title edited after the run | structural | `edited` is a trigger. |
| Fork PRs | structural | Same path: base code only, read-only token. |
| Fails open | structural | Exit codes: main's current copy without the flags gives 2, a codex branch at tier A gives 1, a non-lane PR gives 0, title `-x` gives 2. A fetch, cat-file or diff error, or the head moving during a run, also fails the job. |
| Status named `lane-gate` from the shared login | procedural (R1) | Needs the integration pin when the check is made required. |
| Duplicate `lane-gate` check run from a PR's `pull_request` workflow, or from a base retargeted to a branch whose `lane-gate.yml` passes | not reproduced (R4) | Same app, so the integration pin does not help. The repo is user-owned, so there is no required-workflows rule. |
| Not in force | procedural | `main-checks` requires only `checks`, `broker`, `machines` and `hostcheck`. `lane-gate` did not run on this PR because main has no such workflow yet. |
