## 1. B1 is closed (in the mode CI runs)

`DROP_CAPS` = `setpriv --bounding-set -sys_admin,-sys_ptrace --inh-caps -sys_admin,-sys_ptrace`. The previous re-sign's exec-transition argument holds for both caps. The scenario's **effective bounding set** is the full set minus CAP_SYS_ADMIN and CAP_SYS_PTRACE. Its permitted and effective sets are the same and its inheritable and ambient sets are empty. In CI's mode (`-r`, non-root runner) every one of those caps is scoped to the sandbox's user namespace.

These are the routes to `_inner` (PID 1) or strace, both of which still hold CAP_SYS_ADMIN:
- `PTRACE_ATTACH`/`SEIZE`, `/proc/<pid>/mem`, `process_vm_writev`, `pidfd_getfd`: each goes through `ptrace_may_access` in attach mode. `cap_ptrace_access_check` denies it because the target's permitted set is not a subset of the caller's and the caller lacks CAP_SYS_PTRACE in the target's user namespace. Yama scope 1 (Ubuntu's default) also denies an ancestor.
- `/proc/1/fd/*`, `/proc/1/root`, `/proc/1/cwd`, `/proc/1/environ`: read mode, same capability check, denied. This narrows D9 as the builder says.
- A nested user namespace has full caps only in the new namespace. That does not count against `_inner`'s namespace, and the mounts it copies are locked (`MNT_LOCK_READONLY`).
- Kept caps: in the user namespace, none of them clears `ro` or reaches another process's memory without SYS_ADMIN or SYS_PTRACE. Real root is different: see B2.

## Threat check

Attacker: the audited dependency's install or test scenario inside the sandbox, aiming to write a kept path or to forge or erase evidence.

## Findings

- **B1: closed.** Code, local mutation and CI evidence are in points 1 and 2.

- **B2, blocker (DEP-2b, defect).** The setpriv drop is a denylist of two caps, and it holds only because CI runs the scenario in a user namespace.
  - **The gap.** When `depaudit run` runs as real root, `_unshare_flags()` omits `-r`. The scenario is then init-namespace root holding every other cap.
  - **Example route.** CAP_DAC_READ_SEARCH allows `open_by_handle_at`. A handle from `name_to_handle_at` on a kept file, opened against an fd on a writable mount of the same filesystem (`/` is not made read-only), gives a writable fd to the kept file. That bypasses the `ro` bind mount, and `open_by_handle_at` is untraced.
  - **Other routes.** CAP_SYS_MODULE, CAP_MKNOD with a block device, and CAP_SYS_RAWIO lead to the same result.
  - **Basis.** This was traced from code. A live probe was not run, under this review's no-live-probe instruction. The gap predates this delta; the previous re-sign did not list it.
  - **Why blocker.** It breaks DEP-2b in a mode the code supports and that D8 claims holds ("checked as root"). Per OPERATING §2, the stricter class is chosen.
  - **Decision boundary.** If the coordinator rules real-root runs unsupported, the same one-line fix below still closes the gap, so the cost of the stricter class is small.
  - **Fix.**
    - Always enter a user namespace: `-r` regardless of euid. As root that maps 0→0, and every kept cap becomes namespace-scoped. The alternative is to make `sandbox_available()` false at euid 0.
    - Add a control that fails unless the scenario's `/proc/self/uid_map` is not the identity map `0 0 4294967295`.
    - Correct D8's "real root on CI".
