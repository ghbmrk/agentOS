## Findings
- **B1, blocker (round 1; fixed in delta 2).** `forward_key` took components from the raw key, so `/net/ipv4/ip_forward=1`, `net.ipv4.ip_forward.=1`, `/net/ipv*/conf/*/forwarding=1` and four similar lines passed while systemd-sysctl applied them. Keys are now normalised as `sysctl_normalize` does, with all seven pinned.
- **R1, release (round 1; fixed in delta 2).** sysctl lines were split with `splitlines()`; systemd ends a line at NUL and keeps `\x0b`, `\x1c`, U+2028. `sysctl_byte_violations` now refuses those bytes in every sysctl file, covering `kernel.core_pattern` too.
- **B2, blocker (delta 2; fixed in delta 3).** `sysctl_files` was not systemd-sysctl's list: it appended `/etc/sysctl.conf` last, read hidden names and sorted Python `str`. The listing is now a port of 257.13's `conf_files`, checked against `cat-config` in CI.
- **R2, R3, release (delta 2; fixed in delta 3).** A 1 MiB line stops systemd's read of the file; an absolute link was read against the build host. Both are refused and pinned.
- **R5, release (delta 2; fixed in delta 3).** The unreadable path of `sysctl_byte_violations` is pinned. `byte_violations`' unreadable path is not (round-1 L1): filed in #1529.
- **R4, release (delta 2 and 3; filed #1530).** tmpfiles.d, the kernel command line and credentials can set forwarding outside sysctl.d.
- **R6, release (delta 3; filed #1528).** The modprobe.d listing matches kmod 34, but the line parser does not (K1-K5).
- Incident (round 1): a first probe run changed the review VM's `kernel.domainname`; the probe was fixed to use `-u` and a per-netns key.
