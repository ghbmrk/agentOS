#### Findings
- **S1 (release, A11/K10, tier A).** egress/proxy.go:384 asks `Granted(grantsOf, adapter)`, and replay is served by `HandlerWithGrantsOf(machine, ev.From, …)` (cmd/agentos-egress/server.go:215). Probe: proxy alone, `HandlerWithGrantsOf("eval-1", "agent")`, no `-grant` and a stored key gave **200**, and the provider received the key. End to end it is refused only because the eval router is built flag-only (`newRouter`, no stored callback). So "replay keeps only `-eval-from`'s flag grants" (K24) holds at one layer, not two. `prices.within` also checks only the flag-only `ev.Grants`, so the LOOP-5 price ceiling relies on the same router gate. Failure path: #1279 or any new `HandlerWithGrantsOf` caller gives replay the owner's key with no second check and outside the ceiling. Fix: ask with the calling `machine` (mutation M10, `granted(machine, …)`, keeps every egress and agentos-egress test green), plus a proxy-level `eval-`/`lb-` test. Not exploitable at this head, so this is not a blocker. It can be fixed here cheaply or carried by #1279.
- **S2 (release, recheck, A11/CAP-11, tier A).** cmd/agentos-egress/main.go:133-141: `checkAgentMachine` accepts `wk-` (vm.WorkerPrefix) and `cr-` (cleanroom.Prefix) names. The flag is root-set, so this takes a configuration error. Failure path: a unit or image setting `-agent-machine` to a worker or clean-room name gives that machine the owner's stored keys. Fix: refuse every broker-reserved prefix from one shared list.
- I agree with the builder's `later` on the stale `keyed` mark (L1, #1200). Display only: M9 and M1 show it never grants.
