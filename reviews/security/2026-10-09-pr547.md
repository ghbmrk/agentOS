# Security 4a, PR #547 (P1-4-flake, Exec's deadline panic classification)

Record: PR #547 · package P1-4-flake · head a8e28f20

Tier A (`broker/vm/gvisor`). Fresh session, from the diff `origin/main...pr547` and the cited IDs CAP-8, RES-4 and LOOP-7, with reviews/security/README.md and V32 applied. Merged as c0eb06e.

Threat check: `crashed := ExitError && runscErr non-empty && (exit 2 || ctx.Err() != nil)`.

## Facts

- [Fact] **Guest cannot write runsc's stderr.** The guest's fd 2 is runsc's fd 3 (`--pass-fd 3:2`, SR2-3n); runsc's own fd 2 goes only to `runscErr`. The new disjunct does not change that.
- [Fact] **Deadline as "crash".** A guest can end its own exec's context only by running past the timeout, which it already could. Making runsc write stderr as well would withhold its own partial output: loss, not leak (V34).
- [Fact] **Timing hiding a panic.** Before this PR a trace written before the kill gave exit -1, `crashed` was false, partial output was returned and the trace reached no log. Now that case withholds output and goes through `logExec`. `TestRunscPanicKilledAtTheDeadlineAnswersNoOutput` and `wantPanicLogged` pin both. os/exec 1.26 returns `*ExitError` (-1) for a `Cancel` kill, so `errors.As` holds.
- [Fact] **Late `ctx.Err()`.** A context ending after `Wait` flips a normal exit to `crashed` only if runsc's stderr is non-empty, which per V32 already means runsc failed.
- [Fact] Tests cancel at a mark the fake creates, not at a wall clock. `go test ./vm/gvisor -run 'Panic|Deadline' -count=50 -race` passed.

## Points

1. **release**: CI's fuzz count is one figure for five targets. "600000x is about what 20s ran" holds for `modemlink:FuzzInbound` (18 s locally, 4 cores), but `sockets:FuzzFrames` ran 600000x in 6 s and now gets about a third of its per-PR fuzzing. Fix: per-target counts in the loop, from CI's exec/s, or a log line with the rates. UX and potency cost: none. Not a blocker: LOOP-7 sets no budget and seeds plus planted-decoder controls still run in the race step. BOARD row P1-4-flake-counts.
2. **release**: the exit-code gate is redundant and leaves one gap. If runsc is killed by something other than the context (a cgroup OOM kill after it began a trace), it exits -1 with `ctx.Err() == nil`: output returned as a result and nothing in `exec.log`. `crashed := err != nil && len(runscErr.bytes()) > 0` is simpler and closes it. Not a regression; no guest path found. BOARD row P1-4-flake-crashed.
3. **later**: a runsc failure at the deadline reaches callers as `TimedOut`, not `ErrExecFailed`; the failure is visible only in `exec.log` (since #391). A monitor wanting "runsc panicked" as a security signal must read that log. LATER.md.

Lens README: neither recurring kind applies (no new `exec.Cmd`; `broker/vm/gvisor` is already tier A). No new check warranted.
