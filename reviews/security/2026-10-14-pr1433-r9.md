### Release
- **R25. The SPEC sentence and the code define "identical" differently.**
  - `SPEC.md:380` defines an identical repeat as "the same record to the same recipients by the same action". The code also requires the same body (`gate.go:974-978`, D-116).
  - So a reply with new text to the same message within 24h still auto-replies under ADP-11. This is pinned by `repeat_confirm_test.go:365`.
  - It is not a double send, but the normative text and the code disagree.
  - **Fix:** add a qualifying sentence after Mark's verbatim one, citing D-116. That needs the coordinator's or Mark's ack. The other option is to drop the body comparison.
- **R26. R23 overclaims after an erase.**
  - `gate.go:968` treats an erased rival as matching any record, body and recipients.
  - **Probe:** s1 (inv-1042 to sam) is erased after it went. A pre-allowed send of a different invoice to a different person is then asked, with "already sent 09:00 Oct 5; send it again?". The same happens 23h later.
  - **Effect:**
    - the owner's line states a false fact;
    - ADP-9 and ADP-11 are suspended on that account and action for 24h after any CAP-3 erase, which runs on any owner source deletion;
    - it teaches the owner to ignore the warning at the moment a real repeat is most likely.
  - **Fix:** the journal keeps an erased intent's recipients and EFP. Require the same recipients, or match the EFP, and give the line its own wording instead of "already sent".
