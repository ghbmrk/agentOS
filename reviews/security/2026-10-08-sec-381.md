## Evidence (resume path, end to end)

- [Fact] **Page form.** `/paused/` is mounted through `Mount`, so `signedIn` covers it. Every POST passes the global `sameOrigin` check (`server.go:266`), and the cookie is `SameSite=Strict`, `HttpOnly`. The form carries `resumeToken` = HMAC(formKey, "resume"‖session‖grant‖pause), compared with `hmac.Equal`. The "resume" prefix keeps it apart from `formToken`. The body is capped at 16 KiB, and fields given more than once count as absent. Mutation: replacing the HMAC check with `true` fails `TestThePausedPageAsksToResumeAGrant`.
- [Fact] **Socket.** `page_paused` is `authed`; `page_ask_resume` checks the token before anything else, bounds grant ≤ `MaxID` and pause ≤ `MaxPause` (128), and turns every agentosd error into `errFailed`. `TestEveryOpButTheOpenOnesNeedsAToken` covers both new ops.
- [Fact] **Gate, origin binding.** `evaluateBroker` denies a `resume` spec unless `Origin == "local"` and `Spec.Pause` is set (`gate.go:894`). Guest origins were already refused at the top of `evaluateBroker`; owner-text and Loop 2 origins are now refused too. The only code that submits a `local` resume is `Gate.AskResume`, which agentosd reaches only from the page socket. Mutation: removing the check fails `TestAResumeComesOnlyFromThePageNamingItsPause`.
- [Fact] **Binding to the pause.** A pause now records its intent ID and origin on the grant (`applyLocked`). A second pause replaces both. `validateLocked` refuses a resume whose `Pause` differs from the grant's current one, at evaluate and again at apply. The item's `Detail` (description, who paused it, pause ID) is inside `owner.ItemSum`, so the code the owner enters is bound to this grant and this pause, and `sameItem` at dispatch refuses a pause that changed after approval. Two independent layers: with the apply-time check removed, `TestAResumeDoesNotEndALaterPause` still passes because of the sum.
- [Fact] **Approval code.** The verdict is `ask, local: true` with `Kind: GrantChange`: high tier, no texted YES (`RequestLocal`), a code-generator code on the page, and `isConfirmed` required before dispatch. A code is spent across page and texts (D2 on #165); `TestAResumeTakesAFreshPageCode` covers a reused code and an empty one. The channel texts the page's answer (`LocalAnswer`). This is the same machinery #165 and #169 signed, unchanged here.
- [Fact] **Apply.** On resume, apply clears `Paused`, `Pause` and `PausedBy`, fires `Unpaused` (Loop 2 drops its line), and texts "Resumed G…". A resume recorded before this package has no `Pause`; it still replays, and the gate refuses any new one without a pause.
- [Fact] **Escaping.** The page renders with `html/template`, with no `template.HTML`. `What` goes through `showField`, so odd runes show as `[U+…]` with a warning. Grant IDs are `G<n>` from the gate; pause IDs are `owner/pause/<G…>/<ns>.<n>` or `loop2/pause/<hex>`, all broker-made. Approvals shows `Detail` through `show`.
- [Fact] **Gate-reason leaks.** `AskResume`'s errors (which may carry `Permission.Reason`) stop at `daemon.askResume`. Only `ErrPauseChanged` becomes text, and that text is fixed; everything else becomes `errFailed`, and the page shows its own fixed sentence. The test fake returns a path-like error and checks that the page does not show it.
- [Fact] `go test ./grants/ ./localui/ ./localsrv/ ./localapi/ ./daemon/ ./loops/ ./owner/` passes at c05f2fd.

## Threat check

Asset: a paused grant's authority, which a resume restores. Adversaries: **A**, the agent (guest); **S**, a SIM swapper or spoofer holding or forging the owner's number; **W**, an unsigned Wi-Fi client; **X**, a cross-site page in the owner's phone browser; **P**, a second signed-in phone that holds an old page.

| Path | Stop | Kind |
|---|---|---|
| A submits a resume grant change | `guest:` origins are denied on broker actions; resume needs origin `local` | Structural |
| S resumes by text | Resume from any non-`local` origin is denied; a texted YES is refused for a local item | Structural |
| S, holding the phone, approves the page's ask | Needs a code-generator code on the page, bound to the item's sum | Structural |
| W calls `page_ask_resume` or `page_paused` | Both need a live session token | Structural |
| X posts the form cross-site | `sameOrigin`, a SameSite=Strict cookie, and an HMAC bound to the session | Structural |
| P replays another phone's form | The HMAC binds the session; a mismatch is stale | Structural |
| A stale ask (from before a re-pause) ends the later pause | `Spec.Pause` is checked at evaluate and apply; the sum and `sameItem` catch it at dispatch | Structural (two layers) |
| A code for another request, or a reused code, approves the resume | Codes are bound to the sum and spent once (D1/D2 on #165) | Structural (inherited) |
| A-controlled text reaches the page through `What` | `What` comes from an owner-approved spec, through `showField` and `html/template` | Structural |
| Gate reasons or paths leak to the page | Only fixed texts cross agentosd → socket → page | Structural |
| A signed-in phone floods asks | Each ask needs the session, an open ask for the same pause is returned again, and nothing widens without a code | Accepted (asks are harmless; LATER `W5a-resume-dedupe`) |

No path widens a grant without the page, a session, and a fresh code bound to that grant and pause.

## Points

None blocking.
1. **later** — `localsrv.askResume` checks the token inline instead of through `s.authed`. The two are equivalent today (both use `s.valid`, and the ops-need-a-token test covers it). If `authed` gains a check later, this op would silently miss it. Fold it into `authed` when the file is next touched.
2. **later (already LATER `W5a-resume-dedupe`)** — two asks made at the same moment can file two requests. Approving one resumes the grant; the other then fails validation. Nothing widens twice, so the class is correct.
