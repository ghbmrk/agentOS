## Threat check

Adversaries: a hostile guest (agent machine with guest authority), a fuzz input, a local process on the host. Assets: the integrity of the Loop 2 finding chain (a finding closes only on a passing replay of its own stored input, S24), the journal (content and capacity), credentials and live machines.

### Finding closure (S24, LOOP-9)

- [Fact] `Guard.Resolve` refuses anything but an open, reported `fuzz`/`probe` finding, and anything but `Passed` with `Evidence == Detail`; `Pass` never clears a rule-less finding; a tree-rule finding cannot be closed through `Resolve`; `reportable` refuses `/original` IDs and a rule on a rule-less check. These checks are sound, but `Resolve` trusts its caller's word that the replay ran and passed, so S24 holds only if `loop7` builds `Replay` honestly. It does not in two cases (findings 1 and 2).
- [Fact] **Fuzz: inputs that never ran count as passed.** `replay` marks every corpus file not in `failing` as passed. A seed that panics aborts the test binary, so later seeds never run and print nothing. Reproduced: corpus `a1` (panics), `b1`, `c1`, `z1` (`t.Fatal`) under `-test.run=^FuzzX$ -test.v` prints only `=== RUN FuzzX/a1` and `--- FAIL: FuzzX/a1`; `b1`, `c1`, `z1` never run. With open findings for `z1`, a new panicking input sorting before it resolves `z1`'s finding without any replay of `z1`.
- [Fact] **Probe: a guest's report alone can close a finding.** `Journaled` derives the refusals it must find in the journal from `res.Sent` rows the guest reports with `Got == Want`. A guest that returns `Result{}` (no `Sent`, no `Failures`) makes `fails` empty, and `probe` resolves every open `socket.<machine>` finding, including one raised by the broker-side check itself (a refusal the broker failed to journal). The package doc says the journal check is broker-side "since the guest cannot read the journal", but its expectations come from the guest. Not wired in production yet (F7).
- [Fact] A guest can also suppress a probe finding by returning a clean result, and can provoke one (F4: `Contain` nil, notice only). That is inherent to an in-guest probe and accepted; closing a broker-raised finding is not.

### Refusal journal (B19)

- [Fact] The note holds only the broker's machine ID (from `cfg.Machines`, not the peer's claim; the `Peer` argument is ignored), the fixed adapter `socket-refusal`, the code token and a fixed reason. No frame bytes, op name or peer-supplied text reaches it, so a guest cannot inject into it.
- [Fact] Flood: `EgressGate.Admit` keys on (machine, reason class); reasons are six fixed strings without quotes, so at most six notes per machine per minute, and the table is bounded (4096 keys, per-machine overflow). The gate is a fresh instance, separate from the egress-denial gate. `refused` runs synchronously on the serving goroutine, but `Admit` is a short mutex section and `RecordEgress` is the existing journal path.
- [Fact] Owner sockets set no `Refused`; only the six protocol codes are told, not an op's own answers.

### Harness reach and corpora

- [Fact] The fuzz targets run in-process against handlers, `httptest` recorders and `fakeMachines`/`MemStore` rigs; the probe tests listen on a temp-dir Unix socket. No dial to a real host, no real machine, no env or credential read. The single "secret" string (`open /secret: permission denied`) is a planted refusal text in a control.
- [Fact] All 57 added corpus files are Go fuzz v1 encodings of synthetic bytes (`example.test` URLs, placeholder accounts such as `zther`); no credential, token or personal data.
- [Fact] `loop7.command` passes the broker's whole environment to the fuzz binaries. `agentosd` reads no secret from its environment today, so this is not live.

### CI and soak

- [Fact] `ci.yml` adds a 20 s fuzz step per new target that fails the job on any failure (`|| exit 1`); no existing step, condition or permission is changed. `soak.yml` adds five matrix rows; `fail-fast`, `max-parallel` and the timeout are unchanged. `tools/risk_tier.py` adds `sockprobe` to tier A, and the test pins `sockprobe` A and `loop7` B. No gate is weakened.

## Findings

1. **blocker** (S24, LOOP-9; defect) — **A fuzz finding closes without its input being replayed.** `broker/loop7/loop7.go` `replay`: `passed` includes every corpus file not seen in a `--- FAIL:` line, which includes files that never ran after an earlier seed panicked. Fix: build `passed` only from `--- PASS: <Target>/<file>` lines in the `-test.v` output, and add a test with two stored crash inputs, the first a panic, asserting the second's finding stays open. UX cost none; potency cost none.
2. **blocker** (S24, LOOP-9, LOOP-7; defect) — **A guest's empty probe result closes probe findings, including broker-raised ones.** `Journaled` takes the refusal codes to look for from guest-reported `Sent` rows. Fix: take them from `sockprobe.Frames` (every fixed frame's `Want` must have a `socket-refusal` note for the machine in the window, whatever the guest reports), and fail the round when `Sent` lacks any frame. A guest that really sends the frames then produces the broker-observed refusals, which is a genuine replay. Add a test where `Probe` returns `Result{}` on a machine with an open finding and the finding stays open. UX cost none; potency cost none.
3. **later** — `loop7.command` hands the fuzz binaries `os.Environ()`. Proposal: a minimal environment (`PATH`, `HOME`, `TMPDIR`, `GOFLAGS=`) when F7 wires the source. UX cost none; potency cost none.
4. **later** — `ErrPeer` on a guest socket is journaled under that machine's ID, though the peer was by definition not that machine (another host process). Coalesced, so harmless; proposal: note the attribution in B19's row. UX cost none; potency cost none.
5. **later** — `loop7` decides which findings `Resolve` closes, yet is tier B. Proposal: if it keeps that role once wired (F7), move it to `TIER_A_BROKER` so later deltas get a Security re-sign. UX cost none; potency cost none.

### Threat check

- [Fact] **Finding 1 fixed.** `replay` now builds `passed` only from `--- PASS: <Target>/<file>` lines whose function name matches the target, and hashes the file as it is on disk now, so a file changed since its finding does not match the stored `Detail`. A seed that never ran, after an earlier panic, prints no PASS line and resolves nothing; `TestASeedThatNeverRanResolvesNothing` pins this with two panicking seeds sorting first. A PASS line could be forged only by target output: none of the five fuzz targets logs or prints, and the inputs come from the repository corpus or Go's mutator, never from a guest.
- [Fact] **Finding 2 fixed.** `Journaled` no longer takes the `Result`. Its expected codes are every `Want` in `sockprobe.Frames` (malformed, unknown-op, too-large), so a guest cannot shrink the set; the test with `Result{}` and no journal notes fails the round and keeps the finding open. To close a finding, a guest must make the broker itself journal a refusal note for each code within the window. The guest cannot write the journal, and making the broker refuse the frames is the replay.
- [Fact] **No other closure path.** The only callers of `loops.Guard.Resolve` are the two in `loop7`. `journal.Engine.Resolve` at `engine.go:409` is a different method. No socket or local API reaches it, so S26's trust in the in-process caller holds.
- [Inference] **Residual, accepted.** The broker check works per code, not per frame: "not JSON" and "wrong field type" both expect `malformed`. If one of them were wrongly accepted, a guest could skip it, send the other, and pass the round. Refusal notes carry no frame identity by design (B19: no frame bytes), and a guest can already suppress or provoke probe findings (F4, no containment). Per-frame evidence would need a frame identity in the note, so this is not a blocker.
