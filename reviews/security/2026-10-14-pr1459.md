### Threat check

- **Reach.** The new op `page_setup_ap_net` is on agentosd's localui.sock only. The socket is peer-UID/GID-pinned to agentos-localui, the op is served only during setup mode with the page's card step (pageCard), and it is gone after finish. Nothing new listens on the network. A Wi-Fi neighbour or a hostile page in the phone's browser reaches the op only through the card confirm, which needs the paired, claimed phone. That is unchanged.
- **Forgery (#1385, #1420/#1421).** A compromised page can (a) forge the latch, which burns the setup network early and serves whatever network the page reported, and (b) rewrite ap-net.json at any time until finish, which agentos-ap applies at the next poll with Down then Up. Neither adds capability: the page generates the card, so it already knows the card's network, and the box's only exposure is DoS, which a compromised page already has. #1385 is not widened. Apnet N3 states this.
- **Injection into hostapd.** `apnet.Validate` limits the SSID to `AgentOS-` plus 4 card symbols and the password to 16 card symbols in groups of 4. Newlines, `|`, spaces and lowercase are all refused. The parser refuses unknown fields and trailing data, and it validates on both write (agentosd) and read (agentos-ap).
- **Secret handling.** The file is root-only 0600 in the root 0700 `/var/lib/agentos` and written with a durable rename. agentosd runs as root, and agentos-localui cannot read the directory. Logs carry only the network kind. `String`/`GoString` redact on `Network` and `SetupAPNet`. JSON errors do not quote values. The file is not in any snapshot path. This meets ARC-1/CRED-1.
- **Fail-closed.** A failed report fails the provision before the vault provisions or the latch saves. A malformed ap-net.json, or a latch that cannot be read, takes the AP down and exits, and the unit retries. A confirmed box with no file serves nothing. The card network is never served before the confirm or ownership (killed mutants M14/M15). WPA3-SAE only with ieee80211w=2 and ap_isolate on the card network, which is asserted.
- **Races.** The report is durable before the latch saves, and agentos-ap reads the latch before ap-net. At the confirm, downFirst brings the setup network down before the burn, and the card network comes up only after that (tested). On a card-to-card change, `APLoader.Up` refuses while up, so even with the explicit Down removed (M16) the loader exits and restarts rather than running two networks.

### Findings

#### blocker
- **B1 (ARC-2).** The required `broker` check is red at the head. The ARC-2 control-path guard (`broker/daemon/arc2_test.go`) fails because agentosd now imports `broker/apnet`, which is not in `controlPath`. Fix: add `"apnet": {}` to `controlPath`, which holds apnet to the control path's import rules (it imports only bytes, encoding/json, errors, fmt, io, strings), and add `apnet` to the `daemon` entry or to wherever cmd/agentosd's allowed imports are listed. Do not weaken the test. The PR's Trace row ARC-2 "pass" is therefore wrong. Also rebase onto main (40 behind) before review of the delta.

#### release
- **R1 (ARC-1, REC-4, CH-7).** This is already on the PR's Findings line, and the security lens confirms it is a release item, not a later one. A Wi-Fi rotation does not rewrite ap-net.json and `APLoader.Rekey` is unwired. Failure path: the owner suspects the card is lost and rotates. The box keeps serving the old password at every start, so whoever holds the lost card stays on the box's Wi-Fi. That defeats ARC-1's "the owner rotates it under REC-4 after a suspected loss".

#### later
