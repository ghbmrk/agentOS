## Blocker
**B1. The PR opens setup on a preloaded box with no claim gate in the configuration it ships (HW-10, cited; #1115 "a preloaded box keeps the claim gate").**
- `cmd/agentosd/main.go:511` now always hands setup mode `Card: pageCardStep`. On main, `m.Card == nil` made setup mode `log.Fatal`, so setup never opened. After this PR, agentosd serves every setup op to the page.
- `cmd/agentos-localui/main.go:124` runs `firstboot.Begin`, and with it `Config.Claim`, only when `-vault-sock` is set. That flag defaults to `""` (`main.go:52`), and the unit this package ships (`agentos-localui.service:14`) does not pass it.
- On a box whose seller sealed the claim state, the page as shipped therefore serves `/setup` to anyone on the access point with no claim gate. Network join, number pairing and enroll attempts are all open. Only finish stays held (card pending), and K22 stops the vault.
- The claim gate fails open when a dependency is missing, while the card hold fails closed.
- Mutation probes: removing the `run` block (`if false && …`) **survives**. Dropping `!cfg.Hooks.AlreadySetUp()`, which lets an owned box run Begin and its reset, also **survives**. Nothing tests `run`'s gating, because `TestThePageRunsTheFirstBoot` calls `withFirstBoot` directly.

**Fix:**
1. In `run`, when setup is open and `-vault-sock` is empty, return an error rather than serve setup, so the unit restarts and no setup step is served. Alternatively, open the claim state and set `Config.Claim` without the vault. The point is that the claim gate never depends on the card wiring.
2. Add a `run`-level test, or factor `run`'s gate into a tested function, covering three cases:
   - a sealed claim state at `-claim-state` with open setup gates `/setup` with a redirect to `/claim`;
   - open setup with no `-vault-sock` serves no setup step;
   - an owned box (`AlreadySetUp` true) never calls `Reset`.

This ran in a fresh session.

**Scope.** `git diff 00e9e9a 9d48672` is one commit and contains no merge. It touches only `cmd/agentos-localui/main.go` (`prepare`, `errNoVault`) and `main_test.go` (`TestRunGatesSetupOnTheClaim`).

**B1: fixed.** With setup open and `-vault-sock` unset, `run()` exits with `errNoVault`. `TestRunGatesSetupOnTheClaim` covers three cases: a sealed claim state redirects `/setup` to 303 `/claim`, a missing vault socket gives `errNoVault` from both `prepare` and `run`, and an owned box sends the vault no request.

**Probes.** There were 7 mutation probes, none committed; 6 were killed (D1–D5, D7).
- **D6 survived.** It checks the vault before the owned check, which would make the shipped unit's owned boxes exit. This is availability, not a fail-open, and is added to l3.

**New: S-R3 (release, folded into s1).** `AlreadySetUp` is asked twice, once in `prepare` and once in `New`'s `adopt`, and any error counts as "set up".
- A transient first error skips the first boot and the vault check. A second answer of "open" then serves ungated setup.
- A probe confirmed it: `/setup` answered 200 with no vault socket.
- The damage is bounded by agentosd's `card pending` and egress K22, and the next restart decides again. The pattern was already there at 00e9e9a.
- Fix: decide once, using `Wait` and telling a refusal apart from a transport error.

**Other paths checked.**
- An unreadable claim state (EACCES) makes the page exit.
- A missing claim state (ENOENT) is S-R1, which is unchanged and now unreachable on the shipped unit, because the page exits first.

**Shipped unit.** The unit has no `-vault-sock` and `Restart=always`, so the page exits every 5 s while setup is open. That fails closed, but setup is blocked until s1 lands.

**SetupNet (#1186 S-R3).** This is not a blocker: the field does not exist on main or in #1226. It is release work for whichever of #1186 and #1226 lands second (draft s4, conditional).

**Runs.** `go test -race -count=1` over `./cmd/agentos-localui ./localui ./firstboot` is ok. `risk_tier` prints A. CI at 9d48672 is all green: checks, broker, machines, hostcheck, canary, dependency-audit and scope.
