##### Findings (non-blocking)

**P9. class:release: the systemd-order test does not model a mid-poll hang-up (mutant L survives).**
- **Why it matters.** The real bridge is always long-polling, so on a systemd stop its poll is cut off mid-flight. The "polled, then stopped first" subtest (`drain_test.go:321-326`) uses a poll that completed, with `PollWait` at 100 ms.
- **Effect.** If `HangupOps` ever stopped covering owner ops, the drain would stall about 25 s on every restart with an alert queued, and every test would still pass. My ad-hoc test fails under L ("held the stop 4s"), and passes at 0.9 s on the head.
- **Ask.** Add a subtest with the default `PollWait` and the poll's client ctx cancelled before the stop. This is the same item as Security S8.

**P10. class:release: `BridgeGap` (1 s) equals the bridge's 1 s back-off after a failed poll (`bridge.go:328-333`).**
- **Effect.** A single transient poll error during a drain with a live bridge reads as "gone", and the alert is lost.
- **Not a regression.** This is no worse than main, and it never arises under the shipped units.
- **Ask.** Widen the gap when #1772 lands. This is the same item as Security S9.

**P11. class:release, for #1772: the bridge's final `sent` uses the cancelled ctx (`bridge.go:341`).** A text sent at SIGTERM therefore has no heard result, and agentosd waits out its bound. (a1) should report it with `context.WithoutCancel`, bounded.

**P12. class:later: stale test name in a comment.** `drain_test.go:68-69` still points to `TestShutdownDrainWaitsTheBoundWhenTheBridgeNeverPolls`, which was renamed to `TestShutdownDrainWaitsTheBoundWhileTheBridgeHoldsAText`.
