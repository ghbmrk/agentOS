## Fix list
1. **blocker (defect, OP-3).** `policy.Check` in `world.go` runs `interleave` *before* it reads `p.grants`. A revoke nested in the check is therefore seen by the check itself, and the window this is meant to reach (grant read, then revoke, then the dispatched record committed) is never entered. A4 and the trace row both claim this window is covered; it is not, so the OP-3 race guard can be deleted with the sweep still green.
   - Fix: read `held := p.grants[in.Account]` before `interleave`, and return `errNoGrant` on `!held`.
   - I checked this fix. The correct engine still passes the full `./sim` run, and with the seq recheck removed the sweep catches it: `seed 16 step 171: OP-3: e12#2 ran on mail with no grant held`.
   - Note this mutant check in the PR. A sim-side mutant for it would need an engine hook, so no new test is required.

## Not blocking
2. **later.** The three PR mutants live in the fakes (policy, disk), so they show that the oracles are sensitive, not that the sweep finds engine bugs. The engine-level mutants above cover that for now. The brief's DEL-1 and stale "Cleared" mutants stay with the second half.
3. **later.** `checkErased` checks only the IDs that the *current* engine reports as erased. It keeps no record of acknowledged erasures across reboots. Under today's disk model, the check made right after the ack is enough.
4. **later.** The Rewrite dirsync crash is thin (3 hits in 100 seeds). A power cut never persists an unsynced truncate. OpenFile's own dirsync is not a crash point, but a crash there is equivalent to a crash just before Open.
5. **later, recheck.** No oracle compares the settled results in the journal with the service's truth. A wrong reconcile result is caught only when it leads to a second effect (OP-2).
