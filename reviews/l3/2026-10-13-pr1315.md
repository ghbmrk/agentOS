### Points


1. **blocker (CRED-5 worker-held, CAP-11 "qualified per provider and CLI version", §17 risk 3): CAP-11-plan has no qualification gate.** CRED-5 allows a worker-held login "only for a provider agent whose qualification meets" W1-W5. The brief ships a built-in Claude declaration that runs as soon as a plan is signed in, and it puts S8-live (#809) out of scope without listing it as a dependency. #1264, the next row, is what puts a real login on the volume. As written, a real worker-held route could go live with nothing but stub evidence behind it. Fix: the declaration carries a qualification record (pinned CLI version, a pointer to the W1-W5 evidence, and the terms re-read with its date and verdict). `provider_run` refuses with a closed reason until that record is present. Add a test that an unqualified declaration refuses. Make #809 a dependency of enabling the route, or of #1264.
2. **blocker (CRED-5 "chosen per provider by its published terms", §17 risk 3): none of the three threat lists covers Anthropic's terms, and CAP-11-plan treats them as settled.** S8's terms read (`RESULT.md`, 2026-10-05) quotes Anthropic's page on two points: "products or services (e.g. in hosted sandboxes or other agent infrastructure)" need the Commercial Terms, and the page permits "a platform hosting Claude Code". It also leaves open one question that only Mark can take to Anthropic: does a self-hosted owner box count as "a platform hosting Claude Code"? The "Spec dependency" paragraph should cite that read and that open question. The declaration's terms note should record its source URL, the date read and the verdict. The brief should also state that if the re-read at qualification finds this use unclear, the worker-held route does not ship and the question moves to D-107 / #1148 (`gate:mark`). Add a threats bullet saying the same.
3. **blocker (A14 "absent from every snapshot", CRED-1 snapshots): S8-W1-volume excludes only files, but worker snapshots also capture memory.** `Manager.Park` takes a `Full` snapshot (`broker/vm/worker.go:271-316`), and a full snapshot runs `runsc checkpoint` (`broker/vm/gvisor/gvisor.go:236-239`), which saves the sandbox's memory and kernel state. The CLI's token, both in its memory and in its environment (`CLAUDE_CODE_OAUTH_TOKEN`), would land in that image even though the volume sits outside the overlay. Fix: a worker with a login mounted never takes a memory checkpoint. Park stops it without a snapshot, and checkpoint, fork and rollback refuse it. Test with a canary placed in a stub CLI's env and heap, then search the checkpoint image.
4. **blocker (CRED-5 W1, A14): the provider worker can still be named by the guest's worker tools.** `broker/workers` lets the lineage that made a worker name it with exec, read, write, checkpoint, fork and diff. CAP-11 requires the provider worker to inherit its creator's label and reservation, yet neither brief takes it out of the guest's namespace. The volume brief guards only `read` and `write` paths. A guest `exec` in the provider worker runs outside the CLI's tool sandbox and can read the login directly. Fix (CAP-11-plan, and the volume brief's "never mounted" list): provider workers are broker-owned, left out of `Workers(lineage)`, and every worker tool refuses their IDs. Test each tool.
5. **blocker (CRED-5 W1/W2): the briefs disagree on how the login reaches the CLI.** The volume brief assumes "the file the CLI reads after `claude setup-token`", with a writable login file for refresh. The tunnel brief and S8 (`RESULT.md` line 21) use the `CLAUDE_CODE_OAUTH_TOKEN` environment variable, and S8 records that the setup token "is valid for a year and needs no refresh". The difference decides several things: whether the volume can be fully read-only, which process reads the volume and exports the token (a root-owned launcher whose `/proc/<pid>/environ` is exactly the W1 surface), and the fact that `setup-token` prints the token to stdout (#1264's path, which must not pass through `Exec` output or the journal). Fix: the volume brief states the mechanism and makes the volume read-only when no refresh is needed. The builder still measures the details against the pinned CLI.
6. **blocker (CRED-8, ARC-1 "subject to CRED-1 and CRED-8"): "under the encrypted data area (CRED-8)" names something that does not exist.** CRED-8 encrypts only the vault, and `vm.Config.StateDir` is a plain directory. A login valid for a year would sit on the drive in clear text, which breaks CRED-8's "a lost drive is ciphertext". Fix: name a mechanism. For example, store the login encrypted under a key from the open vault and decrypt it only into memory-backed storage at mount time, so a locked vault means no plan route. Test that the drive holds no canary.
7. **blocker (CRED-5 W4 "no network at all", A14; Security recurring kind "a confinement brief lists the namespaces instead of the property"): the tunnel brief gives the wrong reason the socket is safe.** It says tool subprocesses "with their own empty network namespace … see neither loopback nor the socket". A network namespace does not hide a pathname Unix socket; only mount-namespace hiding or a peer check does. Fix: state the property, that only the CLI process can connect. Get it from the path being absent in the tools' mount namespace and from a broker-side `SO_PEERCRED` check of the CLI's UID. The existing test should stay.
8. **blocker (E12, A14 "proxy requests … are denied"): the tunnel brief's scope includes `broker/egress/proxy.go` "(CONNECT dispatch only)".** That is the guest-facing proxy in the vault process (`broker/cmd/agentos-egress`), and it must keep refusing every CONNECT. The tunnel is a separate per-worker listener. The brief also wires it in `broker/cmd/agentosd/main.go` without saying which process serves it. Fix: leave proxy.go's CONNECT denial unchanged and add a regression test that a guest CONNECT is still denied. Name the serving process and put its `main.go` in scope.
9. **blocker (dependency order): the tunnel brief and #807 both claim the provider image and managed settings.** The S8-W1 brief is "image fix … managed-policy deny". The tunnel brief lists #807 as providing "tool sandbox and managed policy", yet its own Change builds the provider worker image, the pinned CLI, and the managed settings that deny WebFetch, WebSearch, remote sessions and MCP. Fix: give each item one owner. Either #807 owns the image and managed settings and the tunnel adds only the network settings and the forwarder, or the reverse. Update both briefs' Needs lines to match.
10. **blocker (A14, D-064): CAP-11-plan cites A14's adversarial-brief clause but has no test for it.** "Adversarial brief surfaces no canary login" is listed under Requirements, but Tests first has nothing that proves it, and a stub CLI cannot prove it. A `REQ: A14` marker would be a false pass. Fix: either drop the clause from this package (S8-W1 and S8-live own it, and D-064 governs any real-CLI probe), or add the probe under D-064.
11. **blocker (CRED-1, CRED-5 "results leaving the worker"): CAP-11-plan's threat list does not cover the CLI's other outputs.** These include stdout and stderr, exit messages, and transcripts and logs the CLI writes to scratch. All of them can carry the token or its prefix into the `Exec` result, the journal or the guest. Fix: only the declared result file leaves the worker, and stdout and stderr are discarded or scanned and never journaled raw. Add a test with a stub CLI that echoes a canary to stderr.
12. **blocker (Potency recurring kind: "a brief's declared scope omits the test files the change forces"): the Tests-first lists need files outside the declared scopes.** The volume brief's journal, recall and backup proofs need `broker/journal`, `broker/recall` and the BAK-1 code. The tunnel brief's image-build failure test needs a home (`tests/` or an image test). CAP-11-plan's tool registration needs `broker/guest/tools_test.go`. Fix: add these paths to each brief's Scope.
13. **release (Potency recurring kind "a defence can be reverted and the suite still passes"): no brief names a revert mutant per defence.** Examples: the SNI check, the schema check, memory-checkpoint refusal, the worker-tool ID refusal and the result scan. Add them before the builds start.
14. **release (CLAUDE.md "linked from its BOARD.md row"): the board rows do not link the new briefs.** The #1015 and #1014 rows do not link their briefs, and their dependency cells still say "S8-W1 scheduled" rather than `#807` / `#1015`. #1314's cell names the brief as plain text where #807 uses a link. Update the issue bodies when this PR merges.
15. **later: CAP-11-plan's "serialize per provider" conflicts with RES-5's default of 2 concurrent provider-agent workers per pool.** With a read-only token (point 5), concurrent runs are safe. Say so.
16. **later (OP-8, RES-5): the tunnel brief says each tunnel is "charged … under OP-8".** OP-8 meters calls and tokens, which an opaque tunnel cannot see, and RES-5 says CLI events never count as OP-8 spend. State that the wall-clock and run caps (W7) are what is charged. Separately, #1014's title cites A3 but the brief does not.
