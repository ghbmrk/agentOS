#### S1 (blocker, tier-A security): Preempt and ResumeFromCheckpoint act through a retired handle on a same-ID successor
- **S1a: Preempt, vm.go:1893-1915.**
  - Probe: the `afterGet` hook destroys `exp`, creates a new `exp`, and holds the old handle's mu as a stale reader (for example Prune, which holds a listed mc's lock across snapshot unpublishes, prune.go:82-131).
  - Result: Preempt takes the no-lock branch, and `kill(old)` killed the successor's guest. The successor's record still says `running`, and Preempt returned nil to admission.
  - Reach: availability and accounting only, with no label crossing. The window between get and TryLock is nanoseconds wide, and the race also needs a concurrent holder of the stale lock.
- **S1b: ResumeFromCheckpoint, sleep.go:106-150.**
  - Probe: the `afterGet` hook destroys `exp` and creates a new, preempted `exp` (a fresh lineage, because Create mints one per creation, OP-1).
  - Result: ResumeFromCheckpoint answered `Restored: true`. The successor's layer and memory were replaced by the predecessor's sleep checkpoint, and the successor's file was gone.
  - Root cause: inLineage (vm.go:1311) accepts any snapshot whose `Machine` equals the ID. A direct `Rollback(successor, predecessorSnap)` also succeeds. That part is pre-existing on main. Guest tools block it for workers because `snapshot()` checks `s.Lineage == c.lineage` (workers/workers.go:716), but this path has no such check.
  - Reach today: only agentosd's sleeper calls this (cmd/agentosd/sleeper.go:341, 418), and agentosd never Destroys an agent machine. So the race is not reachable as wired. The label still rises (Rollback raises it), so there is no REV-5 break; the breach is across lineages and incarnations (OP-1).
- **Why a blocker:** the PR's stated invariant (V38 "A handle is good for one machine's life" and the body's "Any operation on a handle taken before the Destroy returns ErrUnknown and leaves a same-ID successor alone") is false for these two paths. Tier-A security findings are not deferred.
- **Fix (small):**
  - Preempt: refuse a retired handle before `kill`. Add an atomic mirror of `gone`, set together with `gone` in destroy, and check it in Preempt's no-lock branch; preemptLocked already no-ops on a Stopped machine.
  - ResumeFromCheckpoint: use `lockLive` at sleep.go:111, and either require `s.Lineage == mc.Lineage` or tighten inLineage to require a matching Lineage when the snapshot has one. The latter also closes the pre-existing direct-Rollback case.
