## Findings

- Blockers: none.

**Release** (shared with Potency, filed as #1514)
- **R1: the `rd.break` half of the hardware check cannot run on a release image.** It appears in I20's step (1) and in [the comment on #1113](https://github.com/ghbmrk/agentOS/issues/1113#issuecomment-6162706030). There are three obstacles:
  - The loader is written with `editor no` and `timeout 0`, so the command line cannot be edited at boot.
  - `rd.break` is a dracut option. mkosi's systemd initrd ignores it, and systemd 257 has no `rd.systemd.break=`.
  - `mkosi.conf` replaces `emergency.service` and `rescue.service` with the fallback or a reboot.

  #1475 said "if reachable". Fix: I20 and #1113 should say the stage is not reachable on a release image, and swap in a check that also covers the initrd stage. After a normal boot, `journalctl -b -k | grep -iE 'bluetooth|btusb|btmtk'` should print nothing, because the kernel log includes the initrd stage and `bluetooth.ko` logs `Bluetooth: Core ver` when it loads. That check runs alongside `lsmod` and `/sys/class/bluetooth`.

**Later** (L1-L5 filed as #1515; L6 folded into #1514)
- **L1:** Pin the real zstd path in a unit test. Either assert `finish.ZSTD == b"\x28\xb5\x2f\xfd"`, or run a real round trip when `zstd` is on PATH.
- **L2:** Add tests for a zero `namesize`, a package differing only in architecture, and `brcm/*.hcd.zst`.
- **L3:** `BT_PATTERNS` misses some Bluetooth firmware: Qualcomm `qca/` rampatch and nvm, TI `TIInit_`, and Marvell. This is harmless while no module that loads them is in the initrd, but it is worth adding.
- **L4:** A `ValueError` from `cpio_names`, or a zstd `CalledProcessError`, escapes `main` as a traceback that does not name the initrd. Wrap `check_initrd` so the message reads `initrd <path> unreadable: …`.
- **L5:** An empty initrd reports `could bring up Bluetooth (#1475): ['no files']`. Say `initrd <path> lists no files`. Also add a hint to the Bluetooth failure: `add a KernelModulesInitrdExclude= regex in image/mkosi/mkosi.conf, and check modinfo -F depends for the kept module that pulls it in`.
- **L6:** I20 says the build fails on "any Bluetooth … firmware". The patterns cover MediaTek, Realtek, Intel and Broadcom, plus any path containing "bluetooth". Narrow the wording or extend the patterns (L3).
