**Potency**
- **The tests fail on main.** I put main's `approvals.go` back under the PR's tests, and both fail (`codes "000000" and "000000", want 000000 redrawn to 065793` and `second request Q9 opened with a colliding code`). At the head, both pass under `go test -race -count=1 ./owner/`.
- The injected `codeRand` is a sound design. Short reads (request IDs) use the real source, and 3-byte-plus reads (code draws) are scripted, so the test pins the redraw exactly. Fill byte 1 gives 0x010101 = 65793, which is < 10^6, so `rand.Int` accepts it on the first read.
- Mutants: `codeDraws=1` is killed. `codeDraws=2` survives, because the bound is not pinned; that is acceptable. A draw moved after the `Pending` commit survives (see Security finding 1).

**UX: what each party sees on a refusal**
- **The owner:** nothing. No text is sent, which is correct, because no request exists.
- **The agent (gate path):** `failReason` passes on `owner: no free approval code`, and retrying the request_id asks again (grants/gate.go:2243-2257). The message is truthful. It is terse but actionable through the existing retry contract.
- **The owner's RETRY text:** this falls through to "Could not ask about every retry now. Text RETRY again later for the rest." (channel.go:1066-1068), which is truthful and actionable.
- In practice, a refusal is unreachable with a working source.

**L3 and structure**
- This is the simplest structure that works: a bounded loop over `c.open` under the lock the caller already holds, with no new state and no persisted field. A set or index would be over-engineering at `MaxOpen`=50.
- **O33 is accurate.** The redraw, the bound, the refusal and the ID-less `YES` claim all match the code. Queued auto-replies carry UNDO IDs and no code, and retired requests are out of `c.open`. The one gap is in finding 3.
