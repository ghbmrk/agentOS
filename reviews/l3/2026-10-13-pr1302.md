## Cited requirements, traced against each binary's real flags

- **ARC-6, CAP-9 (P-3).**
  - `agentos-egress.service` runs `serve -broker-uid 0 -unlock-uid @uid:agentos-localui -rule /usr/lib/agentos/egress/rule.json`. Every flag is defined on serve's FlagSet (broker/cmd/agentos-egress/main.go:304-324).
  - The rule has one class, `broker-default`, which is the guest's `MODEL` default (guest/openclaw/build-rootfs.sh). It routes to `anthropic` (`claude-sonnet-5-5`, a current Anthropic model ID) and `openai` (`gpt-5`, still to confirm: the builder's release item 3).
  - A smoke run of the built binary with these flags, as root with a distinct broker uid and the image's rule, comes up as "vault process up, vault locked" and serves its sockets with no vault on disk.
- **-agent-machine.** At this head neither egress nor main defines `-agent-machine` on serve. Passing it now would stop the vault process at boot ("flag provided but not defined", exit 2), so leaving it out is correct.
  - agentosd's default is `agent` (cmd/agentosd/main.go:398), and #1280 adds egress's flag with the same default.
  - `test_the_machine_names_agree` checks that the two match as soon as egress defines the flag.
  - So the builder's release item 4 needs no separate row.
- **CRED-9 (#1249).**
  - The page passes `-vault-sock /run/agentos-egress/unlock.sock`, which is egress's `RuntimeDirectory` plus `UnlockSocket`.
  - egress makes that directory 0711 itself (`runDir`).
  - agentosd's `-egress`, `-owner-verify` and `-routing` defaults all point into the same directory.
- **HW-10, HW-1 (#1270).**
  - `-claim-state` and `-card-latch` sit under the page's `StateDirectory` (0700).
  - `localui-claim` moves the seller's `claim.json` across once.
  - `LimitCORE=0` is set, and `mkosi.finalize` refuses the build without it.
  - Nothing else reads `claim.StatePath` on the box: agentosd does not, and egress `init` gets `-claim` from `egress-setup`.
- **Setup mode.**
  - `Environment=AGENTOS_OWNER=` plus `EnvironmentFile=-` gives `-owner ""` as one argument. `with-uids` was run here and keeps the empty word.
  - `-localui-uid` makes agentosd serve `localui.sock` with a group socket, and its directory turns 0711 (sockets.go:187-195), so the page's user can reach it.
- **Ordering.**
  - egress runs before agentosd and the page.
  - The page has `Wants=` egress.
  - agentosd has `Wants=` and `After=` egress.

## Points

- **B1 (blocker, ARC-6/CAP-9 test; the PR does not build on main).**
  - broker/cmd/agentos-egress/imagerule_test.go:28 calls `modelRouting(rule, grants{...}, nil, "", "")` with 5 arguments.
  - #1242 (merged as c17b5a9) added `allowed func(string) bool`, so main's `modelRouting` takes 6.
  - After merging origin/main, `go vet ./cmd/agentos-egress/` fails: `not enough arguments in call to modelRouting`. The PR is `behind`, and premerge needs a head that contains main.
  - Fix: merge main and pass `nil` for `allowed`.
  - With only that change, the merged tree passes the egress, localui and agentosd Go tests and test_image (90/90).
- **R1 (release, A1/G1 model task; ARC-3, RES-4): the image root has no `prjquota`.** The builder's release item 1 is right, but its failure path is not.
  - agentosd does not fail at the first `machine create`. At start, `openMachineDisk` gets `quota.ErrUnsupported` and agentosd logs "agent machines disabled" (cmd/agentosd/main.go:764). No agent machine is ever created, so the guest never sends a `broker-default` call.
  - It is not filed yet. A drafted issue is below. The minimal fix and the G1 analysis are in the Potency record.
- **R2 (release, A1 §8.1 step 5, ONB-3; the builder classed it later).** The modem bridge and netjoin units are not in the image, and agentosd gets no `-netjoin-sock`.
  - "Text my box" needs a running `agentos-modem`. The home Wi-Fi step needs `agentos-netjoin`; without it, that step answers "not joined".
  - #1269 ships no unit, and #1292 covers only `modem.env`'s country code.
  - A drafted issue is in the UX record.
- **R3 (release, A1 §8.1 steps 3-4, ONB-4/ONB-5; already tracked).** Nothing in the image brings up the box's own Wi-Fi.
  - mkosi.conf installs no Wi-Fi stack (no hostapd, wpa_supplicant, iwd or NetworkManager), and the P2-1 loader has not landed.
  - The page listens only on 10.42.0.1 with `IPAddressAllow=10.42.0.0/24`. So it restarts every 5 s, and no phone can reach it, even with the router cable in.
  - This is tracked by #825 (P2-1), which has no class label, and #936. Ask: label #825 `class:release` and cite A1. No new issue is needed.
- **L1 (later, recheck).** `agentos-egress.service` has `Wants=`/`After=network-online.target`.
  - Through egress, agentosd and the page now wait for network-online on every boot.
  - The image ships no `.network` file. If wait-online is enabled, both may start only after wait-online's timeout, which is 120 s by default.
  - egress needs no network at start: netguard follows the routes over netlink.
  - Fix: drop network-online from egress and from `SetupServicesTest`. It is marked recheck because whether wait-online runs in the built image was not confirmed (CI logs were unreachable from this session).
- **L2 (later, recheck).** `tests/test_image.py:flags()` takes the union of every subcommand's flags.
  - So an `init`-only flag on serve's line passes. Probe S1 (`-claim` added to serve) survives, yet the binary exits 2 at boot.
  - Fix: check serve's flags against serve's FlagSet only.
- **L3 (later).** `egress-setup` prints "no setup vault yet (the box is not claimed)" for any `init` failure, which hides a full disk, a TPM error and other real causes.
- **Findings line.** The PR names four release items but no issue for any of them. OPERATING §2 needs a `work-item` issue for each. The drafted bodies here, in the Potency record and in the UX record are for the coordinator to file as one follow-up brief.
