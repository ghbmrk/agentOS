## Requirements

- **CAP-3: the same path as a texted forget. Met.** `PageForget` takes `f.mu` and calls the same `f.ask(ctx, goal, f.now())` that `Text` calls for `FORGET n`. That submits one `ActionLearnForget` intent, then `Authorize`, and the result is a pending owner request. The page has no path to `forgetTask` and no second forget implementation. Approval runs the existing `Execute`, unchanged, so the order is owe the text, then the tombstone, then tell. `TestAPageAskIsOneRequestAndForgetsOnlyOnceApproved` drives that order through `PageForget` in three steps:
  - Before approval, nothing is forgotten, no text is sent and nothing is saved.
  - On approval, the tombstone hook asserts that the owed entry is already saved.
  - When the tombstone fails, the owner gets "Not forgotten".
- **Brief Work 4: the locked vault. Met, on the same signal.** `Text` is given `unlocked` from `control.Handler`, which comes from `Channel.SessionUnlocked(now)`, which is `codes.unlocked(now)`. The page passes `Owner.LocalStatus().Unlocked`, which is the same `codes.unlocked(now)` under the same `c.mu`. While locked, `PageTasks` returns `{Locked:true}` without reading tasks, and `PageForget` returns fixed text before taking the lock.
- **Brief Work 5: locking. Met.** Both new methods hold `f.mu` for their whole path. `ask` and `inform` do not take `f.mu` themselves, because `Text` already calls `ask` under it, so there is no self-deadlock. `TestPageAndTextAsksRunConcurrently` passes under `-race`: 40 concurrent asks gave 40 distinct intent IDs.
- **Brief Work 1: the list is `tasks.recent(forgetList)` only. Met.** The label is `shown(t, true)`, the same string a texted `FORGET` shows. `PageForget` re-checks that the goal is still in `recent(forgetList)` before asking. A task that is unlisted, older than the list, already forgotten or malformed submits nothing (`TestAnIDNotListedAsksNothing`).
- **CH-7 and CH-8: sign-in. Met.** The page is mounted with `Mount`, so it sits behind `signedIn`. Both socket ops need a live token: `page_forget_tasks` through `authed`, and `page_forget` through `valid(in.Token)`, which is checked before args are used. Signed-out requests redirect to `/unlock`, and none of them lists or asks anything (localui and localsrv tests).

## Threat check (tier A)

1. **Who can reach the route.** Only a device on the box's access point that holds a live sign-in cookie. localui is treated as untrusted, so agentosd re-checks three things on the socket: the token, the unlocked state, and that the goal is listed. A compromised localui with a stolen live token can do no more than the owner's signed-in phone can, which is file a request. Deleting still needs the owner's code through the gate.
2. **CSRF and same origin.** Every POST passes the server's top-level `sameOrigin` check: `Sec-Fetch-Site` must be `same-origin` or `none`, and `Origin`, when present, must equal `http://<host>`. Cookies are SameSite=Strict. `/forget/ask` is wrapped in `s.post`, so it is POST-only with a 16 KiB cap. `/forget/` is GET/HEAD-only and never asks. The form also carries an HMAC over the session key and the goal ID, so a form from another phone, or one with an edited task, is stale. A same-phone replay only files another request that still needs a code. A cross-origin POST returns 403 with no ask (localui test).
3. **Task data exposed.** Nothing is exposed before sign-in, and nothing while locked. After sign-in, the page shows FORGET's own label: the clipped words of a task the owner texted, with digit runs masked to `####`, or "(a task, <time>)" for any other task (security C2). Labels are HTML-escaped by `html/template` and isolated with `<bdi>`. No task words are logged; the canary tests cover both localui and agentosd.
4. **A forget the owner never approved.** This is not possible from the page. It can only submit a pending request for a task the signed-in, unlocked owner picked. It cannot reach `Execute`.
