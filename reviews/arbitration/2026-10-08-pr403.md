# Arbitration: #403, DEV-2 home-network exceptions

Record: PR #403 · package D-069 (spec-diff) · head a15ee45

**Conflict.** DEV-2 Out allows exactly two exceptions to the home-network boundary: a device executor to its pinned devices, and the egress proxy to a compute host. Security wants the list closed, because an agent-side LAN allowlist turns any granted host into an unauthenticated control surface (D-069, rejected options). Potency loses three things the spec still promises: the broker resolver's upstream when the network assigns the router as DNS, BAK-1 backups to a NAS the owner already has, and a CAP-9 private hosted route on a home-network machine ([combined pass](../combined/2026-10-08-pr403.md), P1).

**Resolution.** Keep the list closed to agents and add broker-only exceptions, each fixed by the owner or the network:

1. The broker's resolver to the resolver the network assigns (DHCP or RDNSS), DNS only. Answers are still checked on the connected address, so rebinding still fails.
2. A broker component to an endpoint the owner pinned on the local page (tier 4): an off-box backup target (BAK-1) or a private hosted route (CAP-9), over TLS or a pinned key.
3. The host's own link configuration (DHCP, router and neighbour discovery) is not a connection under the rule.

A14 adds that an agent machine reaches neither the assigned resolver nor a pinned endpoint.

**Why it dominates.**
- Security: agents gain no reach. Each new endpoint is used only by a broker component, pinned, and owner-confirmed at tier 4. A router serving DNS can already see and route all traffic, so querying it exposes nothing new.
- Potency: the resolver works on an ordinary home network, and BAK-1 and CAP-9 keep their present meaning.
- UX: no new step; backup and hosted routes are already set up on the local page.

Neither a midpoint (a time-limited LAN allowlist) nor the current text (lose the three capabilities) beats it on any lens.

**Escalated.** Nothing. Mark approves the folded text as part of the spec diff.
