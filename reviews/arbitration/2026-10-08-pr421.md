# Arbitration, PR #421 (CRED-5 L1 spec diff)

Record: PR #421 · package L1 · head cb554f944709cdac93fe0a2b7a6ce2ec206b7dfc

One tension: how strictly a broker-held route's response must match its "declared shape" before the route is withdrawn (CRED-5 (d)). Security wants a strict match, because an undeclared field could carry a credential to the model (CRED-1, Invariant C). Potency loses if strict matching takes a route down until a release whenever a provider adds a harmless field.

- Cross-check: strict matching makes both a credential leak and a provider's routine change look the same. Loose matching gives up CRED-1. No setting of a single threshold keeps both.
- Redesign lever (scope by verified data): project the response. The broker forwards only the declared fields to the CLI and drops undeclared ones, so an unknown field never reaches the model whatever it holds. The route fails, and (d) applies, only when a required declared field is missing or malformed.
- Decision: projection, as a release point on CRED-5b's brief. It dominates both options. CRED-1 holds by construction, and an added field costs nothing. Not a fork for Mark.
