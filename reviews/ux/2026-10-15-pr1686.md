## Review (6f237ef8, delta 1, Potency, UX and L3 combined record)

Verdict: ACCEPT. Comment: https://github.com/ghbmrk/agentOS/pull/1686#issuecomment-6176766642

P/UX/L3 delta (tier A): ACCEPT

Head reviewed: 6f237ef (delta over the ACCEPTed head, 7ce5ed95, through 6f237ef8). This review does not repeat the Security delta review, which is running separately.

**What I checked**
- **Clock read under the lock (B1).** `reserve`, `NotifyNow`, `postHeld` and both `releasePaced` reads now call `Now()` after `c.mu.Lock()`. `reserveLocked`'s only callers (pacer.go:232, 278, 340, 468) all pass a `now` read in the same hold. That holds.
- **Restamp at return (R3), edge cases.**
  - *Send returns after the hour boundary:* the stamp moves later, so the text counts for longer. That is the safe direction. The one exception is finding 1.
  - *Crash between reserve and restamp:* the early stamp, saved before the send, survives the crash, so the text stays counted with an end up to the queue wait early. O32 states this ("A crash before the move leaves the early stamp"), and it is no worse than the previous head.
  - *Clock step back:* the default `Now` is `time.Now`, and `at` and `now` both carry monotonic readings in-process, so `now.After(at)` compares monotonic time. The restamp still happens and takes the stepped-back wall time, which fixes the "future stamp is uncounted" case for in-flight texts. With a clock that has no monotonic reading, the `!now.After(at)` guard (pacer.go:318) leaves the stamp as it is, which is O22's existing step-back rule.
  - `Sent` is no longer sorted after a restamp, but nothing relies on its order: `recentSends`, `unreserve` and `settle` all scan by value.
- **modemlink change does not alter other callers.** `modem.ErrNotSent` wraps `ErrDown`, so every `errors.Is(err, modem.ErrDown)` keeps its behavior: `owner.LineDown`, which gives grants' `failReason` its "line is down" reason, and the digest queue. No caller in the tree compares `== modem.ErrDown` or matches the error string. `Link.Send`, `SendRequest` and `SendReceipt` change only in which sentinel they return, and only for `ReceiptNotSent`. The Unknown outcomes still return bare `ErrDown`, and the receipt tests now assert `!errors.Is(err, ErrNotSent)` for them. `SetupLine` keeps its own `modemlink.ErrNotSent` and is not affected. `go build ./...` is clean. I ran `-race` tests on owner, modem/..., modemlink, grants and localsrv, plus cmd/agentosd, cmd/agentos-localui, daemon, e2e, localui, recovery, smsapi and vm/gvisor: all green. loops and loop7 fail only on sandbox setup (`getfacl` missing, no subuid), which has nothing to do with this change. CI at 6f237ef is all green.
- **Mutations (each reverted afterwards):**
  - M1: `settle` refunds on any error → `TestOnlyUnsentTextIsUncounted` and `TestCountRunsFromTheSend` fail.
  - M2: restamp disabled → `TestCountRunsFromTheSend` fails.
  - M3: `reserve` reads `Now()` before the lock → `TestConcurrentCountsAreAllKept` fails.
  - M4: `Receipt.err` returns `ErrDown` for NotSent → three `TestSendReceipt*NotSent` tests fail.
  - M5: simulator `Line.Send` returns `ErrDown` → nothing fails (finding 2).
- **ASSUMPTIONS.** The O31→O32 renumber is complete. O22 and O28 now cite O32. No `O31` is left anywhere in the PR tree, and no Go comment cites O31 or O32. #1433 (open) adds O31 = RETRY right after O30, so the two rows no longer collide and the "renumber at merge" note was correctly dropped. O32's test list names all seven tests that exist.
- **Trace to CH-15.** All seven tests in `pacer_race_test.go` carry `REQ: CH-15 (#1638)`. The renamed `TestFailedOrDroppedSendIsUncounted` is referenced nowhere, and `tools/trace.py --gate CH-15` passes. TRACE.md is regenerated on main and is not a PR concern.
- **UX: what the owner experiences.** The owner now gets the allowance back an hour after a text actually went, not an hour after the box queued it. That matches what the owner sees on their phone: a queued text that arrives at 10:04 no longer frees a slot at 11:00. A text whose fate is unknown (bridge timeout after hand-off) now spends a slot even if it never arrived. That is the right trade for CH-15, since one missing text is better than a burst, and the owner sees nothing new: no new wording and no extra text. The only change the owner can notice is that during a slow bridge, the next paced text waits up to the queue delay longer.

**Findings**
1. **later**: owner/pacer.go:318-330 with modemlink/modemlink.go:318. A send can sit in the modemlink queue for up to `(ahead+1)*SendWait` before hand-off, about 3m40s per text ahead and up to 64 ahead, so it can exceed an hour. Its stamp then ages out of the hour while the text is still in flight: the allowance refills before the text goes, which is the #1638 race in the long-queue case. Any `reserveLocked` after that point also prunes the stamp, so `settle` finds no match and the text is never counted at its return. This needs a badly degraded bridge with roughly 16+ texts queued. Suggested fix: in `settle`, append `now` when no stamp equals `at` and the error is not `ErrNotSent`. The in-flight refill could be pinned by keeping in-flight stamps out of the pruning. Record it in O32 or file it as a follow-up.
2. **later**: modem/modem.go:144. The simulator's switch to `ErrNotSent` is not pinned by any test: mutating it back to `ErrDown` passes modem, owner and the race tests. A one-line assertion in modem's tests (`errors.Is(err, ErrNotSent)` on a downed line) would close it.
3. **later**: modem/at/driver.go:316, 563. The direct AT driver still returns bare `ErrDown`, including for texts it provably never wrote, such as a closed port before the write. On a box using it directly, a line-down send now spends an allowance slot it did not use. This fails safe and is not a regression for CH-15, but it is a small UX cost. Classifying AT errors is a follow-up if that path ships.

There are no blockers and no release-class findings. The B1 and R2 fixes and the restamp are correct, they are covered by tests that fail without them, and the change to modemlink's sentinel does not change any other caller.
