# Synthetic onboarding flow evidence

Source base: `e19274c36f7c2d81ad72d01b796aaa1eb36ba549` (2026-10-08). This is advisory evidence for the setup interface in that source, before its remaining runtime hooks are wired.

The probe calls public `localui.New`, `Server.ServeHTTP`, `Server.OfferText` and `MemStore` interfaces. Hooks, SSIDs, phone numbers, enrollment seed, code values and provider credentials are synthetic. It injects recoverable network/host/provider failures and changes the setup cookie while keeping the source address fixed. The fixed six-digit confirmation is a fake Hook boundary. There is no real phone, SMS carrier, authenticator, provider, physical network, host-trust change or hardware effect. It does not establish authentication correctness or mobile captive-portal behavior.

## Run

From this directory, against an AgentOS checkout at the source base:

```sh
GO_BINARY=/absolute/path/to/go sh run.sh /absolute/path/to/agentos /tmp/onboarding-flow-output
```

`GO_BINARY` defaults to `go`. Native Linux and Darwin are supported. The runner copies `probe.go.txt` to a temporary `.go` file, creates an external isolated Go build cache, and changes no repository runtime files. On Darwin it uses panic-only listener/socket build shims through an external Go overlay; none of those shim functions run. Linux does not use shims. The shims are reused from the preceding 2026-10-08 UX evidence.

The runner executes **14 Python assertions** over `results.json` and **four existing Go tests**: `TestSetupMinimumPath`, `TestSetupResumesAfterRestart`, `TestOnlyThePairedPhoneContinuesSetup`, and `TestCardCodePairingIsClaimedWithThePageCode`. These checks pass at the source base. They demonstrate the measured response/effect-call observations and reuse the existing success/security-boundary tests; they are not comprehensive onboarding or security validation.

## Recorded observations

- A failed host opt-out receives an unchecked “This is not my PC” form. Retrying the rendered default changes synthetic `TrustHost` calls from false to true.
- A failed API-key connection after privacy opt-out receives a checked private-data checkbox. Retrying that default changes synthetic `SetPrivateOK` calls from false to true. The synthetic key is never echoed.
- A network error after selecting Synthetic Home renders Neighbor as the first/default SSID. The selection is not restored.
- The number fallback sends a code, but its confirmation remains inside a closed `details` element, including after a wrong-code response.
- A changed cookie context is correctly refused, even at the same source address. The page describes another phone and offers only the reset-secret restart path. Physical captive-portal/browser cookie loss remains an inference to test on real devices.

`results.json` contains the probe's mechanical observations. Selected HTML files are the actual source template output. `setup-tests.txt` records the four existing tests. `browser-observations.json` manually records a separate static-fixture inspection in the Codex in-app browser at a 390 × 844 CSS-pixel viewport; it is **not** a browser rerunner. That inspection observed the hidden code field, checked privacy retry, unchecked host opt-out retry, and the shared `AgentOS` title.

Pairing codes are randomly generated by the production page. Repeated runs can therefore differ in those synthetic tokens in the number-step HTML. Results JSON and non-random HTML should agree; number-step comparison should normalize only the `PAIR` token. Test timings can vary. No absolute overlay or cache path is checked in.
