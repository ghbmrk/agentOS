This is the tier A lens screen, UX pass.

- **Normal path (G1).** It is unchanged for the owner. The page finishes only once its card step's `Hold()` clears, which happens after `/card/provision` has put the card's entry in the vault. The seal then succeeds. See the Potency record, M12.
- **What the owner sees in the new `card pending` state.**
  - How the box gets there: the vault is remade while the page's latch still says confirmed (K22). The owner is sent back to step 3 by the existing not-confirmed path, then confirms a new code. Finish then reaches the new refusal.
  - agentosd answers `card pending`. The page's `AgentosdSetup.Finish` (broker/localui/setuphooks.go:111) maps only `enrollment unavailable`. So `maybeFinish` (broker/localui/setup.go:1074) shows the generic "Could not finish setup. Try again."
  - Retrying never helps:
    - The latch stays confirmed, so `Hold()` stays nil and the page re-reports the card.
    - `Display()` is nil, so `/card` redirects to `/setup`.
    - `ResetUnlatched` runs only when the latch is unset.
  - The owner has no step on the page that gets out of this state.
- **R1 (release, A1 and HW-1).** On `card pending` from finish, the page should say what is happening and lead the owner out of it.
  - Failure path: after a keys-file loss under a set latch, every finish attempt shows "Could not finish setup. Try again.", and nothing the owner can do on the page finishes setup.
  - Fix, in localui (outside this PR's scope): map `localapi.ErrCardPending` from finish to a fixed message, then clear the latch and rerun the card step (reset, then a new card). A suggested text: "I need to make your Owner Card again. Any card I showed you before will not work."
  - Before this PR the same path finished silently with a useless card. The PR makes the owner strictly better off (stopped, not misled), so this is not a blocker on the cited IDs.
- **No finding.**
  - The refusal changes nothing in the vault, so repeated tries are harmless (the test checks this).
  - An unconfirmed seed still gets the step-3 route first, as before.

Owed: none from UX. R1 goes into the follow-up brief.
