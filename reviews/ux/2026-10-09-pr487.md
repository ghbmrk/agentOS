# UX, PR #487 (W3-forget-b1-7, text the owner a held restore and take their answer)

Tier A, UX lens only; Security is stage 4a. Reviewed from the diff against its merge-base with main (682486e), the brief, security C3's "tells the owner", CAP-3, A8, CH-2, CH-11 and CH-12, and #436 UX points 1 and 2. Question: while a restore is held, does the owner hear why, what to do, and nothing that cannot work?

- Yes. A held box no longer exits silently: it texts the question (or the closed or no-question notice) once the bridge reports the owner line up, answers each owner reply, and says "Restore confirmed. Your agent starts again shortly." before it starts. #409 U2 is closed.
- #436 UX point 1 is done: "this PC" replaces "this new PC". Point 2 is done: with no newer backup, the wrong-answer text adds "If you picked by mistake, restore this backup again to answer again.", and that step works, since every restore of a backup asks the same open question (recovery `TestEveryRestoreOfABackupAsksTheSameQuestion`; ASSUMPTIONS H10).
- The CH-12 recurring-kind check (`TestHeldOwnerTextsNameOnlyStepsThatWork`) covers every text held mode can send: GSM-7, three segments at most, the replies listed last and each one parsed as its choice, and no named step outside the state's allowed set. It passes locally at this head. The README row scopes it honestly to held-restore texts.
- STOP, STATUS and HELP getting the held text is acceptable under CH-2 and CH-11: the agent is not running, and the held text says what the owner can do.

Points:
1. **release (security C3 "tells the owner", CH-12)**: a held box serves no local page (ASSUMPTIONS H1, LATER W3-forget-b1-7 a). The owner is most likely at the PC right after a restore, and the page then simply fails, with no reason given; the reason arrives only on the phone. Proposal: when W3-forget-b1-6 briefs the restore flow, decide whether the restore is started from the local page; if it is, held mode serves a read-only page on localui.sock showing the same held text (no answers taken there, nothing restored opened). Cost to security: one more socket in held mode, read-only. Raise LATER W3-forget-b1-7 a to this condition on the W3-forget-b1-6 row.
2. **later (CH-12)**: the held box texts once per start and then only answers. An owner who misses that text hears nothing more until a restart. A reminder after a day (at most a few) would close it.
3. **later (CH-11, CH-2)**: STOP and STATUS get the question back, which does not say the agent is stopped. Prefixing "Your agent is stopped." to replies that are control words fits within the segment budget.
4. **later (wording)**: "restore this backup again to answer again" repeats "again"; "restore this backup again and answer once more" reads better.
5. **later (lens README)**: the check matches steps against a fixed list of phrasings (`heldSteps`); a new phrasing of an unworkable step outside that list passes. The README row could say "from a fixed list of step phrasings", and the recurring-kind bullet could note that held-restore texts are now covered.
