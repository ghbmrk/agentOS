##### Findings

**B1 (release; Potency + L3): tmpfiles.d can create a sysctl file under `/etc/sysctl.d` on the writable root, and the build passes.**
- The PR body says "tmpfiles.d writes to /proc/sys or a sysctl.d directory ... fail the build". The code only guards `/proc` and `/run/sysctl.d` (`image/mkosi/mkosi.finalize:715`).
- `tests/test_image.py:2217` even pins `f /etc/sysctl.d/x.conf` as a passing line.
- Root is a writable ext4 partition (`mkosi.repart/30-root.conf`), and systemd-sysctl reads `/etc/sysctl.d` first. So `f /etc/sysctl.d/zz.conf - - - - net.ipv4.ip_forward=1` in `/usr/lib/tmpfiles.d` passes `violations()`. Real `systemd-tmpfiles --root` creates that file, and it is in place before systemd-sysctl on every boot after the first.
- `L /etc/sysctl.d/zz.conf - - - - <file>` and `C /etc/sysctl.d - - - - <dir>` pass too. The same applies to `/etc/sysctl.conf` wherever Debian's `99-sysctl.conf` link exists.
- The boot health snapshot (`forward=off`) is then the only guard.
- Fix: count every sysctl.d directory systemd-sysctl reads that the box can write (`/etc/sysctl.d`, plus `/etc/sysctl.conf`) as a TMPFILES_TARGETS path. Pin `f`, `L` and `C` lines into each.
- The same mechanism reaches the other directories the tree check reads (`/etc/modprobe.d`, `/etc/systemd/network`, `/run/systemd/network`, the `*.conf.d` directories). I leave that to the Security lens, but the general fix is a single rule: refuse any tmpfiles.d line that can create a file in a directory the tree check lists.

**B2 (release; Potency, #1530 case 1): `C+` on an ancestor of `/run/sysctl.d` copies a `sysctl.d/` tree in, and the build passes.**
- `tmpfiles_hits(root, path)` matches a line's *path* only at or below a target (`mkosi.finalize:780`, `ancestor=False` at `:856`).
- The `C+` lines `C+ /run - - - - /usr/share/seed`, `C+ /var/run ...` and `C+ %t ...` all pass, where `/usr/share/seed/sysctl.d/99-x.conf` holds `net.ipv4.ip_forward=1`.
- On systemd 255, `systemd-tmpfiles --root=T --create` creates `T/run/sysctl.d/99-x.conf` from exactly that line. In tmpfiles.d(5), `C+` descends into a destination directory that already exists.
- This is the "creates /run/sysctl.d/*.conf" case the issue names, and its done-when says case 1 fails the build.
- Fix: for copy types (`C`, `C+`), check the path with `ancestor=True`. Pin `C+ /run`, `C+ %t` and `C+ /`.

**R1 (release; L3): I21 still says the conf-list diff is "skipped only where `systemd-analyze` is missing"** (`image/ASSUMPTIONS.md:29`). After #1531, CI sets `AGENTOS_REQUIRE_REFERENCE_TOOLS=1`, and both `SystemdDiffTest` and the new `KmodDiffTest` fail rather than skip. Say so, as the row already does for `AGENTOS_REQUIRE_IPV6`.

**R2 (later; UX): the tmpfiles refusal does not say which target matched or how to fix a stock line.**
- The message is `mkosi.finalize:858`: `<file>: line N: <line>; it could set a sysctl outside sysctl.d (#1530)`. When a Debian systemd update changes a link line, whoever maintains the image has to read the code to find `TMPFILES_LINKS`.
- Name the matched target (`/proc`, `/run/sysctl.d`, via link X) and add "set it in sysctl.d, or if this is a stock link line, add its exact pair to TMPFILES_LINKS".
- The command-line message at `finish_image.py:104` could likewise say "move it to a sysctl.d file".

**R3 (later; UX): the reference-tool failure does not name the package or the local escape.** `tests/test_image.py:2330` says `AGENTOS_REQUIRE_REFERENCE_TOOLS=1 but modprobe is not installed`. Add "(apt-get install kmod / systemd; unset the flag to skip locally)".
