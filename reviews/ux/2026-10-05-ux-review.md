## Findings

### 1. Problem texts must name a step that can work (CH-12)
[Fact] Per-PR reviews kept finding the same defect:
- #124: "needs an update or a restart" for missing cgroup delegation, which a restart can't fix.
- #126: no STATUS line at all when the builder failed to start.
- #132: "isn't connected right now" for a missing setting that never clears on its own.
- #133: "ready to install", which leaves the owner wondering whether to act.
- #134: "the builder isn't set up", a setting the owner has no way to reach.
Each was fixed in its PR, but nothing written stops the next one.

Proposal (CH-12): every text that reports a problem or a wait says what the owner can do, or that nothing is needed. It never suggests a step that cannot fix the cause.
- Potency: neutral.
- UX: better. Fewer dead-end steps, and the owner learns to trust the advice.
- Security: neutral.

### 2. One name for the local UI (CH-12)
[Fact] Broker owner texts say "the local page" or "the box's local page" 35 times, and "the box's Wi-Fi page" or "Wi-Fi page" 24 times. The spec mostly says "local UI".
[Inference] The owner reaches the page by joining the box's Wi-Fi, which the Owner Card names (ONB-7), so "the box's Wi-Fi page" is the name they can recognise. "Local page" means nothing to someone who isn't technical.
- This reverses R2 on #132, which recommended "local page".

Proposal (CH-12): owner texts use one name for it, built on the Wi-Fi, and never name internal parts (such as "the builder" or "the vault process"). The exact words wait for the first-person voice rule Mark set on 2026-10-05 (owned by the "Box's own email address" thread), which would make it "my Wi-Fi page". A BOARD row renames the strings in one pass, before P2-2 ships the page.
- Potency: neutral.
- UX: better.
- Security: neutral.

### 3. STATUS shows only exceptions (CH-12)
[Fact] The per-PR rulings on #98, #99, #114, #126 and #133 all applied an unwritten rule:
- STATUS gives the agent's line, then only lines for something not running, something waiting on the owner, or something different from what the owner set.
- A finished event, such as an installed update, goes to the digest once.

Proposal: write that rule into CH-12.
- Potency: neutral.
- UX: better. STATUS stays short enough to scan in one text, within CH-12's three-segment limit.
- Security: neutral.

### 4. The locked prompt should name RUN (owner channel)
[Fact] A locked message gets "Locked. Your message is held for 15 minutes. Send a code from your code generator." After a code-only unlock the owner then gets "Held: "…". Reply RUN to send it." (CH-14, O5). The prompt doesn't warn about that second step. This is UX-57 R4, carried over.

Proposal: the prompt names both forms, for example "Locked. Your message is held for 15 minutes. Send a code from your code generator, then RUN to send it." Check the length when a grid cell is offered. This is a code change for the owner-channel package.
- Potency: neutral.
- UX: better. There is no surprise step.
- Security: neutral. RUN stays.

### 5. Silence while the agent is down
Already a BOARD condition on W5 (UX-56-2): one receipt per outage. No change.
