## Owner-facing failure modes traced

- **The vault process is down** (for example, `with-uids` finds no user, or the rule is unreadable). The page still runs, because it only `Wants=` egress. The unlock and host steps then answer through the page's existing "Could not save" error. That is acceptable.
- **The page restarts after the claim.** `egress-setup --restart` restarts egress once, so for a few seconds the page may see the vault as unavailable. I agree with the builder's later item 2.
- **A fresh box with no prjquota.** STATUS shows two lines together:
  - "Agent and worker tools: off, their machines did not start; restart me."
  - "Agent machines are off: my disk can't limit what each one writes."

  A restart never fixes this, so the first line sends the owner round a loop. See L1. R1 in the Potency record removes the cause.
- **No AP on the image.** The page is unreachable. See L3 R3.

## Points

- **R1 (release, A1 §8.1 step 5, ONB-3; the builder classed it later).** The image ships neither `agentos-modem` nor `agentos-netjoin`, and agentosd gets no `-netjoin-sock`.
  - Failure path: on the G1 run the owner taps "Text my box", and nothing on the box reads the modem, so no reply arrives and setup cannot learn the owner's number.
  - The home Wi-Fi step answers "not joined" for any network.
  - #1269 ships no unit, and #1292 covers only `modem.env`'s country code. A drafted issue is below.
- **L1 (later, recheck).** When agent machines are off because the disk has no project quotas (`quota.ErrUnsupported`), the agent line should say `fixUpdate` ("nothing to do; a later box version adds it"), not `fixRestart`. It is marked recheck because it becomes moot once Potency R1 lands on every image.
- **L2 (later, recheck).** egress's `network-online.target` ordering can delay the page and agentosd by up to wait-online's timeout on a box with no configured uplink. ONB-4 sets a frozen target for the box's Wi-Fi and page. See L3 L1.
- **L3 (later).** The `egress-setup` log blames "not claimed" for every `init` failure. See L3 L3.
- **No finding.**
  - The unit and helper comments are plain.
  - `with-uids` refuses a missing user with a message that names it.
  - Claim and vault state never ship (finalize).

Owed: none from UX. A delta re-check is needed only if the B1 fix touches more than the test.

## Drafted issue (R1, release)

Title: P2-2w c4g: the image ships agentos-modem and agentos-netjoin units, and agentosd's unit passes -netjoin-sock (A1 §8.1 steps 5 and network)

Body: Serves A1 (§8.1 step 5, "Text my box"; the home-network step) and ONB-3.

Failure path: on the G1 M6 Ultra, the setup page runs (PR #1302), but no unit starts the modem bridge or the netjoin helper. The owner's pairing text gets no reply, so setup never learns the owner's number. The network step answers "not joined" for every network.

Acceptance:
1. Both units ship in the image and are enabled in the preset, with their users in sysusers and their uids passed through `with-uids`.
2. agentosd's unit passes `-netjoin-sock` at the helper's socket.
3. `modem.env` supplies what the bridge requires (#1292).
4. `SetupServicesTest` checks each flag against the binary's FlagSet, and each socket path against its client's.

Tier A. (release; UX R1 and L3 R2 on PR #1302, upgrading the builder's later item 1.)
