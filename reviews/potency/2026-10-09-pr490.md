Reviewed from `git diff origin/main...pr490` against A11, LOOP-9, LOOP-10 and CHG-2 (briefs/P3-4b.md, P3-4b-2), and ran `assurance/loop2/run.py --all` at the head: all three seeds pass (each 1-minimal regression from 3 clauses to 1, (a)–(g) rejected for the expected reason, the reference fix adopted, suite 1 → 5), and both controls are caught. Question: does this turn A11's loop 2 clause into evidence at a cost in proportion, and does it cap anything it need not?

- It is a real gain. The harness drives the product's own chain (`loops.Guard.Report`, `change.Pipeline.Propose`, the journal), not a model of it, and its evaluator answers tree rules through `change.AnswerTreeRule`, the same call `replay.Evaluator` makes first (replay.go:245). So H-1 does not weaken the evidence. A green run means a seeded defect really gets contained, minimized, fixed, and kept from being gamed.
- The controls make it falsifiable, as A5's do: a held variant that already holds is refused as an invalid seed, and a leaking adapter fails the audit. The validation step "at least one held variant fails the gamed fix (g)" stops a catalog from passing (g) vacuously.
- The adapter wraps any `loops.Fixer`, so P3-4b-5 can put its model-backed fixer behind the same audit without new plumbing (A-1).
- Cost: two CI steps of about 25 s each in the existing canary job, stdlib Python plus one `go run`. In proportion for a permanent A11 gate.

Points:
1. **later (A11, owner P3-4b-5)**: the scripted fixer ignores the `Finding` it is given, so the harness shows that bad candidates are rejected and a correct one adopted, but not that a `Finding` carries enough for a fixer to build that fix. When P3-4b-5 runs its fixer behind this adapter (A-1), it needs a mode where the model's own candidate is graded against the linked and held cases and the run passes only if it is adopted, alongside the scripted (a)–(g) set. Otherwise A11 for the real fixer stays unshown.
2. **later (A11, catalog breadth)**: the three seeds cover `config/`, `context/` and `procedures/`; none is in `routing/` or `skills/`, though the brief's own example defect is a routing rule. The ≥3 seeds in ≥2 namespaces bar is met; add a routing seed when the catalog is next extended.
3. **later (CI cost)**: `--all` and `--pick` each rebuild the harness and rerun both controls, and `--pick` repeats one of the seeds `--all` just ran. One invocation that runs `--all` and records a random pick in the same report would halve the step, if CI time ever matters.
