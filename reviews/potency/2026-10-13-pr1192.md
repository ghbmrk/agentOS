# Potency: PR #1192 (CTRL-card-rot-ap)

Record: PR #1192 · package CTRL-card-rot-ap · head 11b2504efdb0d945cf08161ff0caf32fc8dc5c16

Verdict: accept

This is the tier A lens screen, Potency pass. The question was whether the change caps what the owner or the box can do without buying matching security or UX.

- **Gain.** The loader can now restart a running access point with a rotated Wi-Fi password, on the same interface and SSID. That is the mechanism REC-4 needs for a Wi-Fi rotation to take effect without a reboot. It is not yet reachable: #1191 wires it once P2-1 and P2-4 land.
- **No cap.** Dropping WPA2 on a rekey follows CH-7 as amended by D-081 (WPA3-only for the first release), so no owner option is lost. A same-password rekey or an invalid one leaves the access point untouched, so phones are not dropped for nothing.
- **Proportionate.** It reuses BringUp, BringDown and the loader's checks, and adds no new component.

Considered, not proposed: restoring the old password when the new bring-up fails. The builder's choice holds. A rotation presumes the old password lost, and the next `Up` (a retry or a reboot) starts the access point with the stored new one.

Next: merge on green CI once L3, UX and Security accept this head. Owed: none from Potency.
