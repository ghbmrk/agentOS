# Potency, PR #426 (CRED-5t, broker-held route failure)

Record: PR #426 · package CRED-5t · head 0bba6a7f2b3d7be2a163093740ff609c63bd4054

Verdict: accept

Tier A, Potency lens; Security is stage 4a. Reviewed from `git diff origin/main...0bba6a7`, egress E11, CRED-5, CRED-1, ADP-10 and D-061. Question: where does the route stop cost the owner a plan route more often or for longer than the security gain requires?

Error statuses that are not declared refusals do not stop the route, so a provider outage costs nothing beyond the failed call. That is the right line.

Points:
1. **release (CRED-5; fold into CRED-5b, which already lists "an encoded refusal does not stop the route" as a classing question).** `Refused` matches the status alone. Providers commonly answer both a malformed refresh and a revoked or restricted login with 400 or 401 (OAuth `invalid_request` vs `invalid_grant`). Declaring that status would let any malformed request, including one the guest provokes, stop the plan route for every machine until the owner resumes. Not declaring it means a real restriction is retried. Letting a `Refused` entry also name the error code in the body (an anchored pattern on one top-level field, as `FieldText` already does) removes both costs. Security cost: none (a stop is still fail-closed; matching is narrower). UX cost: none (fewer false notices, UX point 2).
2. **later.** An unswappable stop holds until a release requalifies the declaration. A provider that adds one harmless field to its refresh response therefore stops the route on every box at once until a release ships. This is the cost of CRED-1 and is accepted, but the release path should be fast: once a built-in plan adapter exists, a qualification test against the live refresh shape belongs in the release checks, so a shape change is caught before boxes see it.

Considered, not proposed: admitting undeclared response fields, or journaling their names, to speed requalification. A field name or value is provider-chosen and could carry a credential, so either would weaken CRED-1 (hard constraint).
