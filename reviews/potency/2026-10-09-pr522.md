- Potency R2 is met: the owner taps a task instead of retyping its words, and the page shares `recent`, `shown`, `ask` and `f.mu` with texted `FORGET`, so there is one forget path to maintain and no second approval rule. Owner-minutes per forget fall for a texted task and stay the same for others.

Points:

The R2 title says "older tasks" and the cap is where the reach stops. Lifting it means a deeper `recent(n)` and a paged list, with the ask check (P2) and the texted `FORGET n` list kept equal (a task the owner could not forget by text must not appear, per the brief). No cited ID needs it. Security cost: a longer label list on shared Wi-Fi after sign-in. UX cost: none. LATER.md line to add: `W3-forget-b3r-deeper`.

This limits R2 for those tasks. Any richer label is a security-lens change (agentosd P4), not a page change; a UX-side proposal is a later fixed label by origin (for example "(a voice task, <time>)"), if the task records its channel.
