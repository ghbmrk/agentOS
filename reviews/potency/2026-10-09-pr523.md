# Potency, PR #523 (P3-4b-3, LOOP-7 fuzz targets and in-guest socket probe)

Record: PR #523 · package P3-4b-3 · head 0a7e68b81842a7e998f4ddb02c0743ec21b4ff69

Verdict: accept

Tier A, Potency lens only. Reviewed from `git diff origin/main...pr523` against LOOP-7 (bullet 2), LOOP-9, LOOP-1 and the brief's acceptance lines (briefs/P3-4b.md, P3-4b-3). The question: do the fuzz targets and the probe exercise what they claim, and what stops that reaching the owner? The diff builds and tests the pieces well. Nothing runs them on a box yet. That is the gap, and the builder has already proposed it as a release row.

What exercises its claim:
- **Fuzz targets check properties, with a planted control each** (`sockets/fuzz_test.go`): no panic, a response is ok or a fixed code, a bad line or unknown op reaches no handler, and the frame reader splits exactly at `MaxRequest`. The controls show a panicking, a leaking and a lenient decoder are caught. Twelve to fourteen committed seeds per target, and CI fuzzes each for 20 s, with the long runs in `soak.yml`. This meets the brief's acceptance lines.
- **The probe checks real behaviour**: undeclared sockets are not dialable, each fixed bad frame gets its fixed code, and the broker answers as the same peer after each frame. Controls cover a lenient server, a missing socket and a server that stops answering.
- **The broker side checks the journal**: each refusal the probe saw must have a note for that machine and code. Any intent from the machine in the round fails the probe.

Points:
1. **release (builder's item, confirmed)**: production wiring. No package outside `loop7` and `sockprobe` references either one, and the daemon builds no `loop7.Source`, no fuzz binaries (`go test -c`) and no `ProbeRun`. LOOP-7's "continuous" testing and the brief line "a Loop 2 source that runs bounded fuzz time in spare capacity" are exercised only by tests today. The brief's acceptance lines (CI fuzz, controls, journaled refusals, a fuzz failure becomes a finding, yield within the preemption target) are met, so this is not a blocker. It needs its own BOARD row: build the binaries at update time, pick the probe machine, pass `Report`. The row should also state what the box needs (disk, build time) against the floor (HW-4).
2. **release (builder's item, adjusted)**: pauses. Both `Report` calls pass no `Contain`, so A-6 (probe findings may pause the affected grant) is unused and LOOP-9's "contain first" has nothing to contain. Split the decision. A probe failure on machine M can pause M's grants, which narrows authority only (A-6), so it goes in the wiring row. A fuzz crash in a decoder has no natural grant or executor, so recording "noticed, not contained" in DECISIONS.md is the cheaper choice than inventing a pause. Say so in the owner text (UX 2).
3. **release (new, wiring row)**: false probe failures on a busy machine. `Journaled` fails the round for any intent from the machine since the round started, but the probe cannot tell its own effects from the agent's concurrent work. A probe run against a live agent can raise a High, urgent text with no fault. `ProbeRun` must pick an idle machine or a dedicated probe machine, and the row should test it with a concurrent intent.
4. **release (owner message for a resolved finding, builder's item, confirmed)**: see UX 1. Class unchanged.
5. **later**: `Resolve`'s replay gate is tautological for probes. The source builds `Replay{Evidence: f.Detail, Passed: true}` from the open finding itself, and a clean round resolves any open finding for that machine, so the gate protects only against other callers. That is fine while the source is the only caller. If another caller appears, add a probe digest or round ID to the evidence.
6. **later**: a probe finding for a machine that is never probed again (retired, renamed) stays open. Add a staleness line to the digest when the source is wired.
7. **later (P3-4b-4)**: the probe sends four fixed frames per socket and does not test connection limits, rapid reconnects or half-open frames. Exhaustion is P3-4b-4's. Fuzz time in production is 30 s per target per cycle, against hours in `soak.yml`, which is fine for spare capacity. The engine's generated corpus stays in `CacheDir`, and only crashing inputs are kept as evidence; promoting good inputs to seeds is a later choice.

Cost to security: none. The only new broker behaviour is a journal note per refusal, coalesced per machine and code. Cost to UX: see the UX record, points 1–3.
