Tier A lens screen, Potency pass.

- **Value.** The check adds real value. It closes #1265's failure path: a wrong, truncated or revoked key let setup finish and say "connected", every model-backed task then failed, and only a fresh setup could fix it.
  - It costs one cheap, free, read-only GET per save (`/v1/models` on both built-in adapters). It is not an `Operation`, so guests gain no new reach (E2, `TestKeyCheckIsNotAnOperation`).
  - It uses the existing transport, netguard and injection, and adds no new component.
- **P1 (later, recheck).** A key that authenticates is not the same as a key that can do work. The models list answers 200 for a valid key on an account with no credit or billing. On a new OpenAI or Anthropic account that is the most common first-day failure: every task then fails with "insufficient quota" or "credit balance too low".
  - Catching it needs a billed call: a tiny completion, with a model choice and some cost. That is not proposed here.
  - Proposal: when the first model-backed task fails that way, send one STATUS line with the step to take ("Your OpenAI account has no credit. Add credit on platform.openai.com.").
  - Recheck: if A1's first-task path counts this failure, it becomes release.
- **P2 (later, recheck).** OpenAI restricted (scoped) keys can be created without the "Models: Read" permission. As I understand it, OpenAI answers such a key's `/v1/models` call with an insufficient-permissions error (status 401 or 403; I have not checked this live). The page then says "The provider did not accept that key." for a key that can run completions. That penalises the owners who follow least-privilege advice.
  - Proposal: read the bounded body for OpenAI's missing-scope error and answer a distinct text ("That key may not list models. Allow 'Models: Read' for it, or use an unrestricted key."), or name the permission in the refused text.
  - Recheck: confirm OpenAI's live status and body first.
- **Considered, not proposed.** Storing a key that could not be checked, with a warning. It would remove the outage block, but it brings back the unrecoverable path, since no step past setup replaces a key.

Security cost of P1 and P2: none. UX cost: one line of text each.
