# Potency, PR #429 (SR3-7, one validated request for model reservation and routing)

Record: PR #429 · package SR3-7 · head 80a15ac78ed7c0421084443f7080327e02ff6b3e

Verdict: accept

Tier A, Potency lens only. Reviewed from `git diff origin/main...pr429`, OP-8, ARC-7 and the L3 threat table. Question: does a single canonical request cap what an agent can do through the model route?

- No capability is lost. `n>1` was already outside the meter's contract (OP-8); this PR closes the case-variant bypass and refuses it at the router for every provider. What is newly refused is only ambiguous bodies (repeated or case-colliding keys) and `n` written as `1.0` or `"1"`.
- One small gain: a chat request carrying only `max_output_tokens` now gets `max_completion_tokens` inserted at `DefaultReserve`, so the forwarded ceiling matches the reservation instead of the router's own ceiling. Spend stays bounded and predictable.
- Considered, not proposed: allowing `n>1` with a reservation of `n × limit`. It would let one call fan out samples, but agents get the same result from N metered calls in parallel (RES-2), and it would reopen the bound this package closes. Security cost outweighs the gain.

Points: none.
