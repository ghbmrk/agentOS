Tier A, Potency lens only. Reviewed from the diff against its merge-base with main, OP-8 and ARC-7. Question: does a model call an agent could usefully make now fail?

- Only non-canonical requests are refused: a repeated top-level key, two keys that differ only in case, or `n` or a limit key in another case. Ordinary SDK clients send none of these. Unknown keys still pass the meter and are dropped by the router as before. `n` other than 1 was already refused by the meter, so the router check adds no new refusal on the metered path.
- A chat call that carries only another API's limit key (`max_output_tokens`) is now reserved and capped at DefaultReserve under the key the API reads. Before, it reserved the smaller stated limit while the provider applied its own default. That is a correct bound, not a loss: the reservation can be larger, and the cap is DefaultReserve.
- Refusal texts name the canonical spelling, so an agent can correct itself in one retry.
