This is the tier A lens screen, Potency pass.

- **Gain.** The setup page stops sending the owner round a rejoin loop that cannot succeed. Each retry only restarted agentosd's 90 s never-online wait. The page now points to the one fix that works (Ethernet). The cost is small: a stdlib sysfs read, run only while never_online holds.
- **G1 (M6 Ultra, built-in RZ616).** The RZ616 is one radio, and the access point holds it as `wlan0` (unit `-iface wlan0`).
  - Until #936 makes a station vif beside the access point, `/sys/class/net` lists no other wireless interface. So the no-station path fires for every A1 owner who relies on Wi-Fi alone, about 90 s after the join.
  - Once #936 makes the vif at boot, it shows up as a second netdev with `phy80211` and the path stops firing. The test case "ap and station vif" covers that shape.
  - A USB adapter is the other way out of the path, and it is picked up on the next page load.
  - Interface naming cannot cause a wrong answer here: if the access point were not on `-iface`, the page's SO_BINDTODEVICE would already fail.
  - On G1 the PR is correct, but it is a stopgap. Before #936, an A1 run with Wi-Fi alone still never gets online, so the model-backed task in A1 can run only over Ethernet. The PR does not change that dependency, and should not.
