## #391 SR2-3m (cbbf80e): accept
- [Fact] The cost the brief accepted is real and narrower than "rare": any exec that exits 2 with `panic: ` or `fatal error: ` followed by a goroutine header on stderr loses all its output and answers a ref. That is exactly what a compiled Go binary prints on an unrecovered panic (`./app`, `./pkg.test`), so an agent running its own Go program in a worker cannot see why it crashed. `go run` and `go test` exit 1 and are unaffected; stdout is not watched.
- [Fact] The security bought is matching: the trace this guards against can carry host paths and the container ID (362-1), and the guest cannot tell a runsc panic from its own (they share fd 2), so withholding is the only fail-closed answer at this layer.
- [Inference] Throughput cost is negligible: the watch runs an RE2 scan over each stderr write plus a 256-byte carry, and holds at most 16 KiB.

### P1 (release): the ref gives the agent no route to its own crash output
- **Point:** when `panicked` withholds output, the agent gets the generic ref and cannot learn that its own Go panic is the likely cause, nor the workaround (send its stderr to stdout with `2>&1`, or wrap the exit code, either of which the watch then does not match; neither touches runsc's own fd 2, so neither weakens SR2-3m).
- **Cheapest lift:** a `vm` sentinel for "withheld: stderr looked like a Go crash trace and the exit was 2", which workers map to fixed text naming the `2>&1` route. This is the pathless-sentinel shape SR2-3j already carries for 362-2, so fold it into SR2-3j's brief rather than a new row.
- **Class:** release (stricter of release/later: Go builds in workers are a core worker use, and the cost is silent). Not a blocker: outside the cited RES-4/CAP-8.

No cross-lens tension beyond P1's tradeoff, which the brief already accepted; nothing goes to Mark.
