# Potency, PR #381 (W5a-resume, per-grant resume on the local page)

Verdict: accept

Reviewed at c05f2fd. Fresh session, from the diff, the brief and the cited IDs (CH-3, CH-10, LOOP-9, OP-5).

- **Gain.** Before this PR a grant that Loop 2 paused had no resume path; the only way back was to revoke it and approve a new grant. Now one paused grant resumes on its own, with no STOP and no other grant affected. That is the precondition W5a's lens set before any Box input lands (BOARD: "a hard condition before the first Box input lands"), so Loop 2 can now be wired to real inputs without risking that an automatic pause strands a grant.
- **No safety given up.** A resume widens access again, so it costs the same as a new grant: the page, a fresh code-generator code bound to this grant and this pause, and the answer texted (CH-3, CH-10). Pausing is unchanged and stays cheap (PAUSE by text, Loop 2). The asymmetry is correct: narrowing is easy, widening is gated.
- **Loop 2 bookkeeping follows.** A page resume fires the existing `Config.Unpaused` hook, so the guard drops the paused line from its digest (`resume_test.go:76`).

Points:
1. **later (already LATER `W5a-resume-pace`)** — the ask waits for the gate's CH-15 batch before it shows under Approvals, so the owner standing at the page may have to reload. That adds owner-minutes to each resume. An ask made on the page could skip the batch, since the owner is already present; worth doing when CH-15 pacing is next touched.
2. **considered, not proposed** — resume by text, without the page. It would let an owner who is away resume a Loop 2 pause, but it widens access from a channel CH-3 and CH-10 hold insufficient for widening (a SIM swapper holds the phone). The owner's remote option is still revoke plus a new grant later, or leave it paused.
