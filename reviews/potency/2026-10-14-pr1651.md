Tier A. Cited: A14, ARC-6, RES-3.

## Potency
- Cap lifted or lowered: none. The guard allows exactly one bind, the machine's services directory at `vm.ServicesMount`, and pins `--host-uds=open`; ARC-6 already says the guest reaches the broker's services "and nothing else", so the tests now enforce a cap the spec already sets rather than adding one. Product code is unchanged.
- Deliberate friction: a future feature that needs another host path in a guest (a shared folder, a device) now fails both bundle tests. That is the intended structural floor (ARC-6, RES-3); such a feature needs a spec change first, not a test edit.
- Structural simplicity: one guard (`isBind`, `foreignBinds`, `hostUDSOpen`) replaces two divergent inline checks, and `TestAGuestCannotDial`'s `/proc` and `/tmp` allowances now refuse a bind option too. Fewer places to drift.
- Mutants (the recurring kind in this README): reverted `isBind` to `Type == "bind"` only, and `hostUDSOpen` to ignore the flag; each fails `TestA14HostBindGuardSeesOptionBinds` / `TestA14HostUDSGuardSeesWidening` (4 cases each). The builder's bundle and argv mutants (PR body) fail both bundle tests.
- Cost to security: none (tightens). Cost to UX: none.

## Findings
- Blockers: none. Release: none.
- **P1, later, no issue.** The bind guard runs in tests over the bundle `writeBundle` builds, not at start time in product code. A14-r2 (BOARD) already moves the no-network check into the launch path; the package that builds A14-r2 can apply `foreignBinds` there too at little cost. Nothing to act on in this PR.
