## R1 (release, A1/G1 model task; ARC-3, RES-4): prjquota. Does it block G1?

**Yes, it blocks G1's model task.**
- G1's model-backed task runs in the owner's agent machine: the OpenClaw guest sends `broker-default` through agentosd to model.sock.
- agentosd runs with `-runsc` and the default `-disk-quota=on`. At start, `quota.Open(/var/lib/agentos/machines)` fails on an ext4 root mounted without project quotas (mkosi.repart/30-root.conf `Format=ext4`; KernelCommandLine has no `rootflags`).
- So `md.err` is set, and agentosd logs "agent machines disabled" and never creates the `agent` machine (cmd/agentosd/main.go:764).
- Nothing else in the chain matters until this is fixed. The setup page and the vault are not affected.

**Minimal fix, one small tier-A image package:**
1. Give the root ext4 the project-quota feature at build time. Use `tune2fs -O quota,project -Q prjquota` on the unmounted root partition in the build's post-step. `SYSTEMD_REPART_MKFS_OPTIONS_EXT4="-O quota,project"` also works if mkosi passes it to repart. `GrowFileSystem` keeps the feature.
2. Add `rootflags=prjquota` to `KernelCommandLine` in mkosi.conf, so the kernel enforces limits, not only accounting, when gpt-auto mounts root.
3. Add a check: `finish_image.py` asserts the feature on the root partition, and the CI boot asserts that agentosd did not log "agent machines disabled". `agentos-health` could also print `quota=on`.

Not `-disk-quota=off`: that is RES-4's explicit opt-out, it lets a guest fill the journal's disk, and choosing it is Security's call, not a G1 shortcut.

**What else G1's model task needs after this PR, in order.** prjquota alone is not enough.
1. This R1 (new).
2. #1280 (CRED-5f-mr-grant). The image grants no machine a model (no `-grant`, by CAP-9), so until stored keys grant `agent`, every model call is refused and STATUS reads "no AI plan or key connected".
3. The phone has to reach setup at all: the box's own Wi-Fi (#825, #936; L3 R3) and the modem and netjoin units (UX R1).
4. The model IDs, confirmed before the run (the builder's release item 3).
5. The private-data box ticked at setup until #1266 (the builder's later item 5).

## Drafted issue (R1, release)

Title: IMG-prjquota: the image's root file system has project quotas, so agentosd runs agent machines on the M6 Ultra (G1)

Body: Serves A1 (G1: one useful model-backed task) and RES-4 (vm V31: "P2-1 image: state file system with `prjquota`, or a machines volume").

Failure path: on every image box, agentosd starts with `-runsc` and `-disk-quota=on`. `quota.Open(/var/lib/agentos/machines)` returns `ErrUnsupported`, because root is ext4 with no project-quota feature and is mounted without `prjquota`. agentosd logs "agent machines disabled" (cmd/agentosd/main.go:764), the owner's agent machine is never created, and no model-backed task can run.

Acceptance:
1. The root partition is made with ext4 `quota,project` (tune2fs on the unmounted partition after mkosi, or repart mkfs options), and `KernelCommandLine` carries `rootflags=prjquota`.
2. `finish_image.py` fails the build without the feature.
3. The CI boot shows agentosd did not disable agent machines (journal check or a health field).
4. `-disk-quota` stays `on`.
