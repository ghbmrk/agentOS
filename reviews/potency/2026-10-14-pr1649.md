## Potency
- Cap lifted or lowered: daily assurance coverage is unchanged. The matrix still runs all 18 fuzz targets at the same `fuzztime` and both soak shards for the same minutes, so fuzz-hours and soak-hours per day are the same. What changes is latency: a crasher found in wave 6 surfaces about 18 h (worst case about 21 h, per `fuzzrun.py`'s budget plus one chunk cap) after the run starts instead of about 9 h.
- What it buys: peak hosted runners go from 8 to 4, so required PR checks (lane-gate, ci) are no longer starved. That raises build throughput, which is the cap the PR lifts; the latency cost is smaller than the hours PRs were waiting.
- Fit in the day: with the defaults the run ends before the next scheduled run is created (cron fires 07:35–09:23Z per the PR body; even at 02:17 a 21 h run ends before the next fire). Held-back jobs wait inside the run and do not consume their 345 min timeout. Only a `fuzztime` dispatch above about 3h45 pushes the next daily run to pending, and the one-pending-per-group rule means at most one day is skipped (#1665, later).
- Failure as pass: `report` still runs on `failure()` of any job; throttling cannot skip a job or mark one green. No path lets a failure read as a pass.
- Cost to security: none (permissions, triggers and steps unchanged; Security 4a accepts). Cost to UX: none to the owner.
