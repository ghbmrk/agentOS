# Potency, PR #670 (ARC-6 tool-result stand-in, lens screen)

Record: PR #670 · package ARC-6 · head 71168ff

Verdict: fix-list
Cause: defect

Tier A, Potency lens, on the PR's diff. Cited ID: ARC-6. The change saves guest context by holding back results over 8 KiB; it adds no capability, credential or egress, and cost to security and UX is nil apart from the points below. Both defects were reproduced on 71168ff with a throwaway test (not committed).

Points:
1. **blocker** (ARC-6; the PR's claim that `result_read` returns the original): a result larger than `totalBytes` (4 MiB) is evicted by its own `Hand` call (`evict` pops from the front until under the cap, including the new entry). The guest gets a stand-in whose id can never be read, the original is gone, and the code comment tells the guest to call the tool again, which repeats any side effect. Reproduced: `Hand("m", 4MiB+1)` then `Read` returns false. Fix: return the body unchanged when it exceeds `totalBytes` (or cap it lower), and add a test; no test covers `totalBytes`, so this defence can be reverted and the suite still passes.
2. **release** (ARC-6, A6 parallel machines; failure path: machine B stores 33 oversized results and machine A's held result is dropped): `evict` pops the global oldest entry, so one machine's volume drops another machine's results. Reproduced: A's entry is unreadable after B stores `perMachine+1` results. Read isolation holds; availability across machines does not. Fix: evict the oldest of the calling machine first, then global only for `totalBytes`. Can ride the fix for point 1.
3. **later** (`recheck`): `result_read` returns the whole text, so reading a fold back re-spends the context the stand-in saved (a 1 MiB result is 1 MiB of guest context). Offset and length arguments would let a guest page or sample.

Verdict follows the blocker; accept once point 1 is fixed and tested.
