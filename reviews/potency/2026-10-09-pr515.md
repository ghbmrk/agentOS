Security cost of any proposal below: none (no probe writes or generates an attack, D-067). UX cost: see the UX record, points 1 and 2. No point cites a brief requirement ID that makes it a blocker.

What the corpus probe does: it tests that each closed check (code filter, commitment filter, alert patterns, label check) still hits its own fixed payload when a published attack text surrounds it. It does not test whether the attack succeeds, and the checks are deterministic substring and pattern matchers. So the probe is a robustness regression for "an attack wrapper does not hide a payload", which is what the brief's LOOP-7 line needs and no more. Its power is bounded by how different the wrappers are from each other.

Points:
1. **later (builder's item, adjusted: what to vendor next)**: the 10 items are five goal-hijack and five prompt-leak strings, with case variants of two. All are ASCII English prefixes, so for a substring or pattern check they are near-equivalent wrappers. The gap left by deferring Hugging Face is not volume; it is shape: obfuscated payloads (Unicode lookalikes, zero-width splits, base64 or spaced digits), multilingual text, and indirect injection in long mail bodies. A larger set of the same shape adds little. When LATER's row is taken, pick for shape, not size, and say so in the row. Adjust the row text accordingly.
2. **release (fold into P3-4b-4c)**: the probe is credited only if the product targets exist. `canary.py round` runs the built-in controls and two registry targets, both `go test` scripts. S28 records that `agentosd` runs none and the daily CI assurance job is the only runner, so on a box today the corpus and canary protect nothing between updates. This is the builder's 4c row; confirmed. The row should state its acceptance as "a probe ran on the box and its run is visible in STATUS", not "wired".
3. **release (fold into P3-4b-4b)**: replay is direct (the checks' functions), not through a guest or a collaborator channel (S27). A regression where the guest's path bypasses a check cannot show up. The builder's tamper and exhaustion row is the place to add a path-level replay of the same items through the in-machine rig. Confirmed as a release row.
4. **later**: the `label check` takes the whole attack text as a label with an empty payload, so it tests refusal of a long string, not refusal of a payload inside one. It is a real check, and a different one from the others, but a label rule that refuses by length alone would pass. Add one attack-shaped near-miss label (a valid label name plus an attack suffix) next time `checks.go` is touched.
5. **later (builder's item, confirmed)**: the open question about rule-less findings. The pause holds the risk and the probe's next clean run closes it. No Loop 2 fix is proposed, which is right until a probe can say what to change.

Checked and fine: the probe fails closed (an unhittable payload, a malformed or oversized output, a nonzero exit all make an error, never a clean run); the canary round runs controls first and skips product targets if any control fails; a probe that fails is named in STATUS and the digest.
