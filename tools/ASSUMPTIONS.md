# Harness tools: assumptions

Rows for `tools/depaudit.py`, written for HK-1 (a defect fix in P1-6's harness;
local IDs HK-1a–c in `briefs/HK-1.md`, no SPEC row) and DEP-2 (D7–D11; local
IDs DEP-2a–c in `briefs/DEP-2.md`, no SPEC row). Each row is something the
fix rests on that a reviewer may want to check or change.

| # | Assumption | Spec basis | If it changes |
|---|---|---|---|
| D1 | **The #391 straggler was a process still writing after the run.** Verified from run 37824851327 (PR #391, head 7e81122, job `dependency-audit`): `test_shipped_registry_passes` raised `OSError: [Errno 39] Directory not empty: 'go-build2650989805'` from `TemporaryDirectory.__exit__` in `run_target`. That a Go build child outlived strace is an inference from the go-build name; the log does not show the process. | HK-1a | If a straggler is seen with the PID namespace in place, the kill is not total: investigate before raising the retry bound. |
| D2 | **Killing the PID namespace kills everything the scenario started.** The sandbox runs under `unshare --pid --fork --kill-child --mount-proc`; when unshare is killed or its child (namespace init) exits, the kernel kills every process in the namespace, including one that called `setsid()` (which `killpg` alone misses: `test_a_process_that_escaped_strace_and_its_group_is_killed_with_the_run`). The work directory is removed only after that, so the ENOTEMPTY retry (50 × 0.2 s, then raise) covers writes already in flight, not a live process. Checked as root and as an unprivileged user locally; CI's runner is authoritative. | HK-1a | If a runner refuses a PID namespace or a `proc` mount, `sandbox_available()` (same flags) is false and `depaudit run` fails with exit 2, loudly, not by skipping. |
| D3 | **A strace fault is recognized by strace's own message on the scenario's stderr**, `^strace: .*Input/output error` or `^strace: .*PTRACE_`. The #378 log (PTRACE_LISTEN EIO) and the #372 log were not retrievable, so the message text is **inferred**, from strace's `ptrace_restart`, which prints `strace: ptrace(PTRACE_LISTEN,pid:N,sig:S): Input/output error`. Exit status is not part of the test: strace exits with the main tracee's status, so a fault on a child it let go of can end 0 with a partial trace. | HK-1b | A scenario that prints such a line itself only makes its own result `error`, never `pass`. If strace changes its wording, a fault reads as `scenario-failed` or `pass` again: update the pattern and its test. |
| D4 | **Each attempt runs in a fresh work directory** (`tmp/`, `home/`, build caches). Since DEP-2 the kept paths (`ROOT`, the repo and `tools/depaudit.py` included; `sys.prefix`; the target's `keep`) are mounted read-only, so they cannot carry state from attempt 1 to the rerun (L3 on #401 passed a marker that way). Paths a target names in `writes` stay writable and persist; only controls use `writes`. | HK-1b, DEP-2b | If a product scenario needs a writable path outside its work directory, add `writes` to the registry schema with its own review: that path again carries state across attempts. |
| D5 | **What a faulted attempt saw is kept.** Its violations are added to the final result whatever the last attempt's outcome: a clean rerun becomes `violation`, a sandbox error keeps them, and three faults give `error` with each attempt's violations. A scenario that fails on its own is not rerun. | HK-1b, HK-1c | — |
| D6 | **A timeout is not a fault.** A scenario that outlives its timeout is `scenario-failed` and not rerun; a sandbox that outlives timeout + 60 s still raises out of `run_target` (as before HK-1), after the kill. | HK-1a, HK-1b | — |
| D7 | **The evidence never touches the filesystem.** strace writes its trace to a pipe it opens as `/proc/<_inner pid>/fd/N`; that fd is close-on-exec in `_inner`, so the traced command does not inherit it. strace's stderr is a pipe the tracee shares; through that shared write end it can only append, and appended text can only add a fault (`error`) or nothing. The result leaves on a private dup of `_inner`'s stdout, and anything but exactly one JSON object line with the expected keys makes the attempt `error`. Checked against origin/main's harness: the tamper control passed there. | DEP-2a | This holds only against the inherited fds. Any tracee can reopen either pipe's read end through `/proc/1/fd/…` and drain it, erasing connect lines or a fault line, or ptrace `_inner` (neither is in `TRACED`): see D9. |
| D8 | **Read-only means `remount,bind,ro` on every kept path, parents first.** Kept paths are bound in sorted order, so a parent is made read-only before a path inside it; a `writes` path inside a read-only parent is bound again and left writable. Checked as root and as an unprivileged user (`unshare -r`), where a remount that drops `ro` is refused by the kernel (locked mount flags). | DEP-2b | Submounts carried by `--rbind` keep their own flags and stay writable (none under the kept paths on CI today): see D10. |
| D9 | **Residual, release (DEP-3): every tracee can erase or forge the evidence through `_inner`.** The tracee always has `_inner`'s uid (root on CI, uid 0 of the user namespace under `-r`) and CAP_SYS_PTRACE in that namespace, so this is not limited to a root or hostile-by-privilege scenario. It can `open("/proc/1/fd/<trace_r or err_r>", O_RDONLY)` and drain the pipe, which erases connect lines or a strace fault line (racing `_inner`'s reader); `PTRACE_ATTACH` to each thread in `/proc/1/task` first freezes `_inner` and makes the drain deterministic, and writing `_inner`'s memory forges the result. Neither syscall is in `TRACED`, so the attempt shows nothing. DEP-2a's invariant (a tracee can at most append a line, never erase one) therefore does not hold while `_inner` shares the tracee's uid. Inferred from Linux semantics (`/proc/<pid>/fd` reopen, `ptrace_may_access`); not reproduced by experiment (L3 on #437). `depaudit run` exists to run unreviewed dependency code, so the trigger for raising this is already met. | DEP-2a | DEP-3 closes it: run the scenario under a uid distinct from `_inner` and strace (or keep the read ends outside the PID namespace and deny ptrace by seccomp), with a planted control that drains `/proc/1/fd` and ptrace-attaches after a connect and expects `violation`. |
| D10 | **Residual, release (DEP-4): rbind submounts stay writable.** `remount,bind,ro` applies to the top mount only, so a submount under `ROOT`, `sys.prefix` or a keep entry is a kept path the scenario can write, which breaks DEP-2b. None exist under the kept paths on CI today. Classed release, not later: OPERATING §2 bars `later` for a tier-A security finding (L3 on #437). | DEP-2b | DEP-4 closes it: fail closed by making every mount under a kept path read-only (`mount_setattr` with `AT_RECURSIVE`, or a remount per `/proc/self/mountinfo` entry), or refuse to run. |
| D11 | **Counts are per target and cover every attempt.** `attempts`, `faults` (attempts that ended with a strace fault) and `cleanup_retries` (ENOTEMPTY retries removing work directories) are kept in each result and summed on the `depaudit run` line. | DEP-2c | — |
